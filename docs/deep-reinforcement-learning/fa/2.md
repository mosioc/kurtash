# خلاصه کامل فصل دوم کتاب Grokking Deep Reinforcement Learning

فصل دوم به مفاهیم بنیادی محیط در یادگیری تقویتی (Reinforcement Learning)، نحوه تعامل Agent با Environment و مدل‌سازی ریاضی این تعامل با استفاده از **Markov Decision Processes (MDPs)** می‌پردازد.

هدف اصلی فصل این است که یاد بگیریم یک مسئله واقعی را چگونه به مجموعه‌ای از Stateها، Actionها، Transitionها و Rewardها تبدیل کنیم تا بتوانیم آن را با الگوریتم‌های Reinforcement Learning حل کنیم.

# 1. Reinforcement Learning چیست؟

یادگیری تقویتی روشی از یادگیری ماشین است که در آن یک عامل (Agent) با تعامل با محیط (Environment)، یاد می‌گیرد چه اقداماتی انجام دهد تا در بلندمدت بیشترین پاداش (Reward) را به دست آورد.

برخلاف روش‌های مبتنی بر قوانین از پیش تعریف‌شده، در RL عامل از طریق تجربه، آزمون و خطا و دریافت بازخورد یاد می‌گیرد.

**مثال‌ها:**

- آموزش یک سگ برای انجام دستورات.
- آموزش ربات برای راه رفتن.
- آموزش خودرو خودران برای رانندگی.
- یادگیری استراتژی مناسب در بازی‌ها.
- تصمیم‌گیری برای خرید و فروش سهام.

## اجزای اصلی RL

| مفهوم | تعریف |
| --- | --- |
| Agent | عامل تصمیم‌گیرنده |
| Environment | محیطی که عامل با آن تعامل می‌کند |
| Action | اقدامی که عامل انجام می‌دهد |
| Observation | اطلاعاتی که عامل از محیط دریافت می‌کند |
| Reward | بازخورد عددی محیط به عامل |
| Goal | هدفی که عامل برای دستیابی به آن تلاش می‌کند |

## چرخه اصلی Agent

تعامل Agent با Environment را می‌توان در سه مرحله اصلی خلاصه کرد:

**1. Observe**

دریافت اطلاعات از محیط.

**2. Act**

انتخاب و اجرای یک Action.

**3. Evaluate**

ارزیابی نتیجه و دریافت Reward.

این چرخه به‌صورت مداوم تکرار می‌شود و باعث می‌شود Agent با توجه به نتایج اقدامات قبلی، رفتار آینده خود را بهبود دهد.

**نمودار چرخه تعامل Agent و Environment:**

```text
                 Action (a_t)
        +---------------------------+
        |                           |
        v                           |
   +---------+                 +-------------+
   |  Agent  |                 | Environment |
   +---------+                 +-------------+
        ^                           |
        |                           |
        +---------------------------+
             Observation (o_t)
                Reward (r_t)
```

در این چرخه:

- Agent اطلاعات محیط را دریافت می‌کند.
- بر اساس اطلاعات دریافتی، Action انتخاب می‌کند.
- Environment به Action واکنش نشان می‌دهد.
- محیط State جدید و Reward مربوط به آن را ایجاد می‌کند.
- این اطلاعات برای تصمیم‌گیری بعدی در اختیار Agent قرار می‌گیرند.

# 2. Environment چیست؟

Environment تمام عوامل و متغیرهایی است که خارج از Agent قرار دارند و بر نتیجه تصمیم‌های آن تأثیر می‌گذارند.

برای مثال، در یک بازی:

- موقعیت فعلی بازیکن
- موقعیت دشمنان
- موانع
- وضعیت بازی
- قوانین حرکت

همگی بخشی از Environment هستند.

در RL، محیط را با استفاده از چند مؤلفه ریاضی مدل‌سازی می‌کنیم.

## State Space

State Space مجموعه تمام Stateهای ممکن محیط است.

**State:** وضعیت مشخص محیط در یک لحظه از زمان.

مثال: در بازی Checkers، هر چیدمان ممکن از مهره‌ها روی صفحه می‌تواند یک State باشد.

اگر مجموعه تمام Stateهای ممکن را در نظر بگیریم، به State Space می‌رسیم.

نکته مهم: تعداد متغیرهای توصیف‌کننده هر State می‌تواند ثابت و محدود باشد، اما تعداد ترکیب‌های ممکن این متغیرها بسیار زیاد باشد.

## Observation Space

Observation Space مجموعه تمام اطلاعاتی است که Agent ممکن است از محیط مشاهده کند.

تفاوت State و Observation:

- State: وضعیت واقعی محیط.
- Observation: اطلاعاتی که Agent از آن وضعیت دریافت می‌کند.

این دو همیشه یکسان نیستند.

مثلاً در یک بازی، ممکن است Agent موقعیت مهره‌ها را ببیند، اما از اطلاعات پنهان بازی مطلع نباشد.

## Action Space

Action Space مجموعه تمام اقداماتی است که Agent می‌تواند انجام دهد.

مثال در Frozen Lake:

- Up
- Down
- Left
- Right

نکته مهم: Actionهای قابل انتخاب ممکن است به State فعلی وابسته باشند. مثلاً در گوشه یک Grid، تعداد حرکت‌های ممکن محدودتر است.

## Transition Function

Transition Function مشخص می‌کند که پس از اجرای یک Action، محیط چگونه از State فعلی به State بعدی منتقل می‌شود.

فرمول:

\[
P(s'|s,a)
\]

که در آن:

- \(s\): وضعیت فعلی
- \(a\): اقدام انجام‌شده
- \(s'\): وضعیت بعدی

این تابع می‌تواند قطعی یا احتمالاتی باشد.

## Reward Function

Reward Function مشخص می‌کند که Agent پس از انجام یک Action و ایجاد یک Transition چه پاداشی دریافت می‌کند.

فرم عمومی:

\[
R(s,a,s')
\]

یعنی پاداش به State فعلی، Action و State بعدی وابسته است.

Reward می‌تواند مثبت، منفی یا صفر باشد.

# 3. Deterministic vs Stochastic Environments

یکی از مهم‌ترین تفاوت‌های محیط‌ها در RL، میزان قطعیت نتیجه اقدامات است.

## Deterministic Environment

محیط قطعی است؛ یعنی هر Action در یک State مشخص، همیشه نتیجه یکسانی دارد.

مثال:

اگر Agent در خانه شماره 2 باشد و به سمت راست حرکت کند، همیشه به خانه شماره 3 می‌رود.

برای State بعدی موردنظر:

\[
P(s'|s,a)=1
\]

## Stochastic Environment

محیط احتمالاتی است؛ یعنی یک Action می‌تواند نتایج متفاوتی داشته باشد.

مثلاً در یک محیط لغزنده:

- احتمال 80٪ حرکت به سمت موردنظر
- احتمال 20٪ لغزش و حرکت به سمت عقب

برای حرکت موردنظر:

\[
P(s'|s,a)=0.8
\]

و احتمال باقی‌مانده مربوط به سایر نتایج ممکن است.

| ویژگی | Deterministic | Stochastic |
| --- | --- | --- |
| نتیجه Action | قطعی | احتمالاتی |
| عدم قطعیت | ندارد | دارد |
| Transition | یک نتیجه مشخص | چند نتیجه ممکن |
| مثال | حرکت در Grid ساده | حرکت روی سطح یخی |

نکته: در محیط Stochastic، حتی اگر Agent یک Action مشخص انتخاب کند، نتیجه الزاماً قابل پیش‌بینی نیست.

# 4. انواع Reward

Reward سیگنالی است که محیط به Agent می‌دهد تا کیفیت نتیجه اقدامات را مشخص کند.

## Positive Reward

پاداش مثبت برای تشویق رفتار مطلوب.

مثال: رسیدن به هدف در بازی.

## Negative Reward

پاداش منفی برای جریمه رفتار نامطلوب.

مثال: برخورد ربات با مانع یا صرف زمان بیش از حد.

## Zero Reward

پاداش صفر زمانی که اقدام انجام‌شده پاداش یا جریمه خاصی ندارد.

## Dense vs Sparse Rewards

| نوع | توضیح |
| --- | --- |
| Dense Reward | Agent در مراحل مختلف بازخورد دریافت می‌کند. |
| Sparse Reward | Agent فقط در موقعیت‌های محدودی Reward دریافت می‌کند. |

**Dense Reward:**

- بازخورد بیشتر
- امکان یادگیری سریع‌تر
- هدایت بیشتر Agent توسط Reward

**Sparse Reward:**

- بازخورد کمتر
- نیاز بیشتر به Exploration
- امکان کشف راهکارهای غیرمنتظره

مثال: در یک بازی، اگر برای هر حرکت امتیاز بدهیم Dense Reward داریم؛ اگر فقط برای برنده شدن امتیاز بدهیم Sparse Reward داریم.

# 5. Time Steps, Experiences and Episodes

## Time Step

Time Step واحد زمانی در تعامل Agent و Environment است.

در هر Time Step، Agent اطلاعات دریافت می‌کند، اقدامی انجام می‌دهد و بازخورد می‌گیرد.

این واحد می‌تواند یک میلی‌ثانیه، یک ثانیه یا حتی یک روز باشد.

## Experience

Experience ثبت اطلاعات مربوط به یک مرحله تعامل Agent با محیط است.

\[
(s_t,a_t,r_{t+1},s_{t+1})
\]

یعنی:

- State فعلی
- Action انتخاب‌شده
- Reward دریافت‌شده
- State بعدی

## Episode

Episode مجموعه‌ای از Time Stepها از شروع تا پایان یک وظیفه است.

### Episodic Tasks

وظایفی که شروع و پایان مشخص دارند.

مثال:

- تمام کردن یک بازی
- حل یک Maze
- رسیدن به هدف در Frozen Lake

### Continuing Tasks

وظایفی که به‌صورت طبیعی پایان مشخصی ندارند.

مثال:

- کنترل مداوم یک خودرو
- کنترل سیستم‌های صنعتی

نکته: می‌توان با تعیین یک Time Step Limit برای یک وظیفه Continuing، آن را به یک وظیفه محدود و اپیزودیک تبدیل کرد.

# 6. Return

Return مجموع پاداش‌هایی است که Agent در طول یک Episode دریافت می‌کند.

هدف اصلی Agent در RL، بیشینه‌سازی Return است.

در ساده‌ترین حالت:

\[
G_t=\sum_{k=0}^{T-t-1}r_{t+k+1}
\]

یعنی مجموع Rewardهای آینده از زمان فعلی تا پایان Episode.

در ادامه فصل، نسخه Discounted Return نیز معرفی می‌شود.

# 7. سه مفهوم اصلی در Agent

سه ابزار مهم برای تصمیم‌گیری و یادگیری Agent عبارت‌اند از:

| مفهوم | وظیفه |
| --- | --- |
| Policy | انتخاب Action |
| Model | پیش‌بینی وضعیت و Reward آینده |
| Value Function | تخمین پاداش آینده |

## Policy

Policy مشخص می‌کند Agent در یک وضعیت چه اقدامی انجام دهد.

\[
\pi(a|s)
\]

Policy می‌تواند:

- Deterministic: برای هر State یک Action مشخص انتخاب کند.
- Stochastic: برای هر State یک توزیع احتمال روی Actionها داشته باشد.

## Model

Model رفتار Environment را پیش‌بینی می‌کند.

به عبارت دیگر، مشخص می‌کند اگر Agent اقدامی انجام دهد، چه State و Reward احتمالی در آینده ایجاد می‌شود.

## Value Function

Value Function میزان مطلوبیت یک State یا وضعیت را بر اساس Rewardهای مورد انتظار آینده تخمین می‌زند.

نکته: در این فصل این سه مفهوم معرفی می‌شوند؛ جزئیات محاسباتی و الگوریتم‌های آن‌ها موضوع مباحث بعدی هستند.

# 8. Markov Decision Process (MDP)

مهم‌ترین مفهوم فصل

MDP یا Markov Decision Process یک مدل ریاضی برای توصیف محیط‌های تصمیم‌گیری در Reinforcement Learning است.

با استفاده از MDP می‌توانیم مشخص کنیم:

1. چه وضعیت‌هایی در محیط وجود دارند؟
2. Agent چه اقداماتی می‌تواند انجام دهد؟
3. هر Action چه تأثیری بر محیط دارد؟
4. Agent چه Rewardای دریافت می‌کند؟
5. پاداش‌های آینده چگونه ارزش‌گذاری می‌شوند؟

## اجزای اصلی MDP

در این فصل MDP با مؤلفه‌های زیر معرفی می‌شود:

| مؤلفه | مفهوم |
| --- | --- |
| State Space | تمام وضعیت‌های ممکن |
| Action Space | اقدامات ممکن |
| Transition Function | احتمال انتقال بین وضعیت‌ها |
| Reward Function | پاداش حاصل از اقدامات و انتقال‌ها |
| Initial State Distribution | توزیع احتمالات وضعیت‌های شروع |
| Discount Factor | میزان اهمیت پاداش‌های آینده |
| Planning Horizon | بازه زمانی برنامه‌ریزی |

نمایش متداول MDP:

\[
MDP=(S,A,P,R,\gamma)
\]

این نمایش، اجزای اصلی را نشان می‌دهد؛ Initial State Distribution و Horizon نیز از مشخصات مسئله هستند که در مدل‌سازی کامل باید در نظر گرفته شوند.

## Markov Property

خاصیت مارکوف یکی از مهم‌ترین ویژگی‌های MDP است.

طبق این خاصیت، وضعیت آینده فقط به State فعلی و Action فعلی وابسته است، نه کل تاریخچه قبلی.

\[
P(S_{t+1}|S_t,A_t,\ldots,S_0,A_0)
=

P(S_{t+1}|S_t,A_t)
\]

**مثال:**

فرض کن یک ربات در یک محیط Grid قرار دارد.

اگر State فعلی ربات موقعیت آن باشد، برای پیش‌بینی موقعیت بعدی کافی است موقعیت فعلی و Action را بدانیم.

اما اگر حرکت ربات به سرعت آن نیز وابسته باشد، باید سرعت را هم به State اضافه کنیم.

بنابراین، انتخاب متغیرهای مناسب برای تعریف State بسیار مهم است.

## Stationary Environment

محیط Stationary محیطی است که قوانین Transition و Reward آن در طول فرآیند یادگیری تغییر نمی‌کنند.

یعنی:

- احتمالات انتقال ثابت می‌مانند.
- قوانین دریافت Reward ثابت می‌مانند.

اگر محیط در حین آموزش تغییر کند، Policy یادگرفته‌شده ممکن است دیگر مناسب نباشد.

# 9. Terminal States

Terminal State وضعیت پایانی یک Episode است؛ یعنی Agent با رسیدن به آن، تعامل جاری خود را به پایان می‌رساند.

مثال‌ها:

- برنده شدن در بازی
- باختن در بازی
- رسیدن به مقصد
- افتادن در یک Hole در Frozen Lake

در MDP، برای Terminal State معمولاً یک Transition با احتمال ۱ به خودش تعریف می‌شود:

\[
P(s'=s|s,a)=1
\]

و Reward آن در این Transition برابر صفر در نظر گرفته می‌شود.

این یک قرارداد مدل‌سازی است که باعث می‌شود تعریف Transitionها کامل باشد.

نکته مهم: Terminal State با Initial State متفاوت است. وضعیت شروع و وضعیت‌های پایانی بخشی از تعریف محیط و MDP هستند، نه ویژگی‌هایی که Agent در طول آموزش به‌صورت دلخواه تعیین کند.

# 10. Action Space و انواع Policy

Action Space الزاماً در تمام Stateها یکسان نیست.

مثلاً در یک محیط Grid:

- در مرکز Grid ممکن است چهار حرکت داشته باشیم.
- در گوشه Grid تعداد حرکت‌های مجاز کمتر است.
- در Terminal State، حرکت مؤثری برای خروج وجود ندارد.

بنابراین می‌توان مجموعه Actionهای مجاز را تابعی از State در نظر گرفت:

\[
A(s)
\]

## No-op Action

No-op مخفف No Operation است.

یعنی اقدامی که هیچ تغییر مؤثری در محیط ایجاد نمی‌کند.

این Action می‌تواند برای نمایش شرایطی استفاده شود که Agent عملاً کاری انجام نمی‌دهد.

## Deterministic Policy

در این نوع Policy، برای هر State یک Action مشخص انتخاب می‌شود.

\[
a=\pi(s)
\]

مثلاً:

اگر Agent در خانه شماره 2 باشد، همیشه حرکت به راست را انتخاب می‌کند.

## Stochastic Policy

در این نوع Policy، Agent برای انتخاب Action از یک توزیع احتمال استفاده می‌کند.

\[
\pi(a|s)=P(A_t=a|S_t=s)
\]

مثلاً:

| Action | Probability |
| --- | --- |
| Up | 0.5 |
| Down | 0.2 |
| Left | 0.2 |
| Right | 0.1 |

تفاوت مهم:

- Deterministic و Stochastic در اینجا درباره نحوه انتخاب Action توسط Agent هستند.
- Deterministic و Stochastic Environment درباره نحوه واکنش محیط به Action هستند.

این دو موضوع مستقل از یکدیگرند.

# 11. Planning Horizon

Planning Horizon مشخص می‌کند Agent برای چه بازه زمانی به آینده نگاه می‌کند و پاداش‌ها و اقدامات آینده را در نظر می‌گیرد.

## Finite Horizon

Agent می‌داند که وظیفه پس از تعداد مشخصی Time Step به پایان می‌رسد.

مثال: حل یک Puzzle در حداکثر ۱۵ حرکت.

## Greedy Horizon

نوع خاصی از Finite Horizon است که Agent فقط یک مرحله جلوتر را در نظر می‌گیرد.

یعنی تصمیم‌گیری بر اساس Reward فوری انجام می‌شود و پاداش‌های مراحل بعدی در نظر گرفته نمی‌شوند.

این مفهوم در مسائل Bandit اهمیت دارد.

## Infinite Horizon

Agent فرض می‌کند که تعامل با محیط می‌تواند تا بی‌نهایت ادامه پیدا کند.

مثال: کنترل مداوم یک ربات در انبار.

البته ممکن است محیط در عمل در هر زمانی متوقف شود.

## Hard Time Step Limit

گاهی برای جلوگیری از ادامه بی‌نهایت یک Episode، محدودیت زمانی مشخصی تعریف می‌کنیم.

در این صورت، پس از رسیدن به تعداد مشخصی Time Step، Episode خاتمه پیدا می‌کند.

این موضوع در محیط‌هایی مانند CartPole کاربرد دارد.

تفاوت مهم: محدودیت زمانی مصنوعی با رسیدن طبیعی به Terminal State یکسان نیست.

# 12. Discount Factor (γ)

مفهوم بسیار مهم

Discount Factor یا ضریب تنزیل مشخص می‌کند پاداش‌های آینده در مقایسه با پاداش‌های فعلی چه ارزشی دارند.

با نماد یونانی Gamma یعنی \(\gamma\) نشان داده می‌شود.

\[
0\leq\gamma\leq1
\]

ایده اصلی:

هرچه Reward در آینده دورتر باشد، ارزش آن می‌تواند کمتر در نظر گرفته شود.

## مقادیر Gamma

| مقدار | مفهوم |
| --- | --- |
| \(\gamma=0\) | فقط Reward فوری اهمیت دارد. |
| \(\gamma=0.5\) | پاداش‌های آینده با شدت بیشتری کاهش ارزش پیدا می‌کنند. |
| \(\gamma=0.99\) | پاداش‌های آینده اهمیت زیادی دارند. |
| \(\gamma=1\) | هیچ Discounting انجام نمی‌شود. |

## Discounted Return

فرمول محاسبه Return با در نظر گرفتن Discount Factor:

\[
G_t=\sum_{k=0}^{T-t-1}\gamma^k r_{t+k+1}
\]

در این فرمول:

- \(G_t\): Return از زمان فعلی
- \(\gamma\): ضریب تنزیل
- \(k\): فاصله زمانی Reward از زمان فعلی
- \(r_{t+k+1}\): Reward آینده

### مثال

فرض کنیم Agent در سه مرحله آینده Rewardهای زیر را دریافت کند:

\[
r_1=10,\quad r_2=10,\quad r_3=10
\]

اگر:

\[
\gamma=0.5
\]

آنگاه:

\[
G=10+(0.5)(10)+(0.5^2)(10)
\]

\[
G=17.5
\]

اما اگر:

\[
\gamma=1
\]

آنگاه:

\[
G=10+10+10=30
\]

بنابراین Gamma مشخص می‌کند Agent چقدر به پاداش‌های دورتر اهمیت بدهد.

## چرا Discount Factor مهم است؟

1. کاهش تأثیر پاداش‌های بسیار دور و نامطمئن.
2. کمک به کنترل و پایداری محاسبات Return.
3. تنظیم تعادل میان Reward فوری و Reward آینده.
4. تأثیرگذاری بر استراتژی بلندمدت Agent.

**نکته مهم:** مقدار مناسب Gamma برای تمام محیط‌ها یکسان نیست. این مقدار به ساختار محیط، Rewardها و طول مسیر موفقیت وابسته است.

در مثال‌های فصل:

- Bandit Walk و Bandit Slippery Walk می‌توانند از Gamma برابر ۱ استفاده کنند.
- Frozen Lake معمولاً با Gamma برابر ۰٫۹۹ بررسی می‌شود.

Gamma در تعریف MDP نقش دارد و در برخی تنظیمات، به‌عنوان Hyperparameter نیز تنظیم می‌شود.

# 13. انواع MDP و توسعه‌های آن

MDP پایه برای مدل‌سازی بسیاری از مسائل مناسب است؛ اما تمام محیط‌های واقعی ساختار یکسانی ندارند.

برای همین، نسخه‌های توسعه‌یافته‌ای از MDP معرفی شده‌اند.

| نوع | نام کامل | کاربرد |
| --- | --- | --- |
| MDP | Markov Decision Process | محیط با State قابل مشاهده |
| POMDP | Partially Observable Markov Decision Process | محیط با اطلاعات ناقص |
| FMDP | Factored Markov Decision Process | نمایش فشرده محیط‌های بزرگ |
| Continuous MDP | Continuous Markov Decision Process | State یا Action پیوسته |
| Relational MDP | Relational Markov Decision Process | مدل‌سازی روابط بین اشیا |
| SMDP | Semi-Markov Decision Process | اقداماتی با مدت‌زمان متفاوت |
| MMDP | Multi-Agent Markov Decision Process | تعامل چند Agent |
| Decentralized MDP | Decentralized Markov Decision Process | همکاری Agentهای توزیع‌شده |

## POMDP

در MDP معمولی، فرض می‌شود Agent به State واقعی محیط دسترسی دارد.

اما در POMDP، Agent فقط Observation دریافت می‌کند و لزوماً State واقعی را نمی‌داند.

مثال: رباتی که تنها بخشی از یک اتاق را با سنسورهای خود مشاهده می‌کند.

تفاوت:

- MDP: دسترسی به State
- POMDP: دسترسی به Observation ناقص

در POMDP علاوه بر Observation Space، مفهوم Emission Probability نیز مطرح می‌شود:

\[
P(o|s)
\]

این احتمال نشان می‌دهد با قرار داشتن محیط در State مشخص، مشاهده یک Observation خاص چقدر محتمل است.

## FMDP

Factored MDP برای نمایش فشرده محیط‌هایی با تعداد بسیار زیاد State استفاده می‌شود.

به‌جای نمایش تمام Stateها به‌صورت جداگانه، از ساختار متغیرها و روابط میان آن‌ها استفاده می‌کند.

## Continuous MDP

در این نوع MDP، متغیرهای State یا Action می‌توانند مقادیر پیوسته داشته باشند.

مثال: کنترل بازوی رباتیک در فضای سه‌بعدی.

موقعیت و زاویه بازو می‌توانند مقادیر پیوسته داشته باشند.

## Relational MDP

برای مدل‌سازی اشیا و روابط میان آن‌ها استفاده می‌شود.

مثال: Agent باید درک کند که یک شیء نسبت به شیء دیگر کجا قرار دارد و اقدامات چگونه این روابط را تغییر می‌دهند.

## SMDP

Semi-Markov Decision Process امکان مدل‌سازی Actionهایی را فراهم می‌کند که ممکن است چند Time Step طول بکشند.

مثال: یک فرآیند چندمرحله‌ای برای مونتاژ یک قطعه.

## MMDP

Multi-Agent MDP برای محیط‌هایی استفاده می‌شود که چند Agent به‌صورت هم‌زمان با یکدیگر تعامل دارند.

مثال: چند ربات که برای انجام یک مأموریت مشترک همکاری می‌کنند.

## Decentralized MDP

در این مدل، چند Agent می‌توانند برای دستیابی به یک Reward مشترک همکاری کنند، بدون اینکه لزوماً به تمام State محیط دسترسی داشته باشند.

# 14. نحوه تعریف MDP و POMDP در عمل

در دنیای واقعی، همیشه تمام اجزای یک MDP به‌صورت کامل در اختیار ما قرار نمی‌گیرند.

ممکن است فقط این دو مورد را داشته باشیم:

- Transition Function
- Reward Function

و اطلاعات دیگری مانند موارد زیر مشخص نشده باشند:

- Initial State Distribution
- Discount Factor
- Planning Horizon

در چنین شرایطی، باید مشخص کنیم چه فرض‌هایی برای محیط در نظر گرفته‌ایم.

در مثال‌های آموزشی این فصل، برای ساده‌سازی، تمرکز اصلی روی Transition Function و Reward Function است و برخی پارامترها از پیش فرض یا تعیین می‌شوند.

## تفاوت MDP و POMDP از نظر مدل‌سازی

| ویژگی | MDP | POMDP |
| --- | --- | --- |
| State Space | دارد | دارد |
| Action Space | دارد | دارد |
| Transition Function | دارد | دارد |
| Reward Function | دارد | دارد |
| Observation Space | در حالت کامل، همان State | جداگانه تعریف می‌شود |
| Emission Probability | لازم نیست | دارد |
| مشاهده State واقعی | بله | لزوماً خیر |

# 15. محیط‌های نمونه در فصل دوم

فصل دوم برای توضیح مفاهیم، چند محیط ساده را معرفی می‌کند.

## 15.1. Bandit Walk (BW)

یک محیط بسیار ساده با سه State که فقط یکی از آن‌ها Non-terminal است.

ویژگی‌ها:

- Agent از State میانی شروع می‌کند.
- می‌تواند به چپ یا راست حرکت کند.
- رسیدن به انتهای سمت راست Reward برابر +1 دارد.
- سایر انتقال‌ها Reward برابر صفر دارند.
- انتقال‌ها Deterministic هستند.

**نمودار Bandit Walk:**

```text
          Left                 Right
     +-------------+       +-------------+
     |             |       |             |
     v             |       v             |
+----------+   +----------+   +----------+
|    S0    |<->|    S1    |<->|    S2    |
| Terminal |   |  Start   |   | Terminal |
| Reward 0 |   |          |   | Reward +1|
+----------+   +----------+   +----------+
```

در این نمایش:

- \(S_1\) وضعیت شروع و تنها State غیرپایانی است.
- \(S_0\) و \(S_2\) وضعیت‌های پایانی هستند.
- رسیدن به سمت راست پاداش +1 دارد.
- رسیدن به سمت چپ پاداشی ایجاد نمی‌کند.

هدف: بررسی ساده نحوه یادگیری Agent در محیطی با گزینه‌های محدود.

## 15.2. Bandit Slippery Walk (BSW)

این محیط نسخه Stochastic محیط قبلی است.

ویژگی‌ها:

- Agent در محیط مشابه BW قرار دارد.
- حرکت همیشه مطابق Action انتخابی نیست.
- احتمال حرکت به جهت موردنظر ۸۰٪ است.
- احتمال لغزش به عقب ۲۰٪ است.
- رسیدن به هدف Reward برابر +1 دارد.
- سایر انتقال‌ها Reward برابر صفر دارند.

**نمودار انتقال احتمالاتی:**

فرض کنیم Agent در \(S_1\) قرار دارد و Action حرکت به راست را انتخاب می‌کند:

```text
                         Action: Right
                              |
                              v
                         +----------+
                         |    S1    |
                         +----------+
                           /      \
                          /        \
                    20%  /          \  80%
                        v            v
                  +----------+  +----------+
                  |    S0    |  |    S2    |
                  | Terminal |  | Terminal |
                  | Reward 0 |  | Reward +1|
                  +----------+  +----------+
```

در این مثال:

- با احتمال ۸۰٪ حرکت موردنظر انجام می‌شود.
- با احتمال ۲۰٪ حرکت به عقب اتفاق می‌افتد.

هدف: بررسی تأثیر عدم قطعیت در Transitionها.

## 15.3. Frozen Lake (FL)

Frozen Lake یک محیط Grid World با ابعاد 4×4 است.

Agent باید به مقصد برسد و از افتادن در Holeها جلوگیری کند.

ویژگی‌ها:

- ۱۶ خانه در Grid وجود دارد.
- چهار Action اصلی دارد: Up، Down، Left و Right.
- حرکت‌ها Stochastic هستند.
- احتمال حرکت در جهت موردنظر یک‌سوم است.
- احتمال حرکت به هر یک از دو جهت جانبی نیز یک‌سوم است.
- رسیدن به Goal پاداش +1 دارد.
- سایر حالت‌ها Reward برابر صفر دارند.
- افتادن در Hole باعث پایان Episode می‌شود.

**نقشه Frozen Lake:**

```text
+---+---+---+---+
| S | F | F | F |
+---+---+---+---+
| F | H | F | H |
+---+---+---+---+
| F | F | F | H |
+---+---+---+---+
| H | F | F | G |
+---+---+---+---+
```

راهنمای نقشه:

```text
S = Start
F = Frozen / Safe tile
H = Hole (Terminal state)
G = Goal (Reward = +1)
```

**نحوه حرکت در Frozen Lake:**

عامل چهار Action ممکن دارد:

```text
              Up
               ^
               |
               |
      Left <-- S --> Right
               |
               |
               v
             Down
```

اما چون محیط Stochastic است، انتخاب یک جهت لزوماً به حرکت در همان جهت منجر نمی‌شود.

برای مثال، اگر Agent حرکت به سمت راست را انتخاب کند:

```text
                 Intended: Right
                     1/3
                      |
                      v
                 +---------+
                 | Current |
                 |  State  |
                 +---------+
                   /     \
                  /       \
             1/3 /         \ 1/3
                v           v
              Up           Down
```

بنابراین:

- احتمال حرکت به جهت انتخاب‌شده: \(1/3\)
- احتمال حرکت به یک جهت جانبی: \(1/3\)
- احتمال حرکت به جهت جانبی دیگر: \(1/3\)

این محیط برای یادگیری نحوه مدل‌سازی محیط‌های احتمالاتی و طراحی MDP کاربرد دارد.

## 15.4. CartPole

CartPole محیطی است که Agent باید با حرکت دادن یک واگن، میله متصل به آن را در حالت تعادل نگه دارد.

در فصل، این محیط برای توضیح Hard Time Step Limit و محدودیت طول Episode مطرح می‌شود.

نمایش مفهومی ساده:

```text
             |
             |   Pole
             |
             |
        _____|_____
       |           |
       |   Cart    |
       +-----------+
   =====================
          Track
```

Agent با حرکت دادن واگن به چپ یا راست تلاش می‌کند میله را متعادل نگه دارد.

# 16. جزئیات مهم State Space

یکی از نکات مهم فصل، تفاوت بین تعداد متغیرهای یک State و تعداد Stateهای ممکن است.

مثلاً در بازی Checkers:

- تعداد مهره‌ها و متغیرهای توصیف‌کننده صفحه محدود است.
- اما ترکیب‌های مختلف قرارگیری مهره‌ها می‌توانند تعداد بسیار زیادی State ایجاد کنند.

بنابراین:

**تعداد متغیرهای هر State لزوماً نشان‌دهنده تعداد Stateهای ممکن نیست.**

یک State می‌تواند با تعداد محدودی متغیر توصیف شود، اما State Space بسیار بزرگی داشته باشد.

این موضوع در طراحی الگوریتم‌های RL اهمیت زیادی دارد؛ زیرا افزایش تعداد Stateهای ممکن، محاسبات و یادگیری را دشوارتر می‌کند.

## Finite vs Infinite State Space

- Finite State Space: تعداد وضعیت‌های ممکن محدود است.
- Infinite State Space: تعداد وضعیت‌های ممکن نامحدود است.

در محیط‌های پیوسته، مثلاً موقعیت یک ربات در فضای سه‌بعدی، State Space می‌تواند نامتناهی باشد.

بااین‌حال، ممکن است هر State تنها با تعداد محدودی متغیر توصیف شود.

# 17. Corner States

Corner State به وضعیت‌هایی در Grid World گفته می‌شود که در گوشه محیط قرار دارند.

در این وضعیت‌ها، تعداد Actionهای مجاز کمتر است.

مثلاً در یک Grid:

- خانه مرکزی: چهار حرکت ممکن.
- خانه کناری: سه حرکت ممکن.
- خانه گوشه: دو حرکت ممکن.

**نمایش مفهومی محدودیت حرکت در Grid:**

```text
+-----+-----+-----+
|     |     |     |
+-----+-----+-----+
|     |  C  |     |
+-----+-----+-----+
|     |     |     |
+-----+-----+-----+
```

در خانه مرکزی \(C\)، چهار جهت حرکت وجود دارد:

```text
              Up
               ^
               |
       Left <--C--> Right
               |
               v
             Down
```

اما در گوشه Grid:

```text
+-----+-----+
|  C  |     |
+-----+-----+
|     |     |
+-----+-----+
```

تنها دو جهت حرکت داخل Grid باقی می‌مانند:

```text
              Down
               |
               v
       Right -> C
```

اگر Agent بخواهد از محیط خارج شود، ممکن است به دیوار برخورد کند و در همان موقعیت باقی بماند.

بنابراین، Transition Function باید محدودیت حرکت در گوشه‌ها و کناره‌ها را در نظر بگیرد.

# 18. Reward Expectation

Reward Expectation یا Expected Reward به میانگین پاداش مورد انتظاری اشاره دارد که با در نظر گرفتن تمام نتایج احتمالی یک اقدام محاسبه می‌شود.

در محیط Stochastic، یک Action ممکن است چند نتیجه متفاوت داشته باشد.

بنابراین نمی‌توان فقط یک نتیجه را در محاسبه Reward در نظر گرفت.

فرمول کلی:

\[
\mathbb{E}[R] = \sum_{s'}P(s'|s,a)R(s,a,s')
\]

مثال:

فرض کن یک ربات سه مسیر برای رسیدن به هدف دارد و هر مسیر احتمال موفقیت متفاوتی دارد.

برای محاسبه Reward مورد انتظار، پاداش هر نتیجه را در احتمال وقوع آن ضرب کرده و نتایج را با هم جمع می‌کنیم.

این مفهوم در محیط‌های احتمالاتی اهمیت زیادی دارد.

# 19. Environment Feedback و Filtering

محیط پس از دریافت Action از Agent، وضعیت داخلی خود را به‌روزرسانی می‌کند.

**چرخه تعامل:**

```text
       +------------------+
       |      Agent       |
       +------------------+
                |
                | Action
                v
       +------------------+
       |   Environment    |
       +------------------+
                |
                | Transition
                v
       +------------------+
       |    New State     |
       +------------------+
                |
                | Reward + Observation
                v
       +------------------+
       |      Agent       |
       +------------------+
                |
                v
         Next Time Step
```

مراحل تعامل:

1. Agent یک Action انتخاب می‌کند.
2. Environment آن Action را دریافت می‌کند.
3. Transition اتفاق می‌افتد.
4. State جدید ایجاد می‌شود.
5. Environment یک Reward ارائه می‌دهد.
6. اطلاعات لازم به Agent منتقل می‌شود.

## Filtering

در برخی محیط‌ها، تمام اطلاعات داخلی Environment در اختیار Agent قرار نمی‌گیرد.

در نتیجه، اطلاعاتی که Agent دریافت می‌کند می‌تواند نسخه‌ای محدود یا فیلترشده از وضعیت واقعی محیط باشد.

مثال: یک خودروی خودران نمی‌تواند تمام اطلاعات جاده و رفتار سایر رانندگان را بداند، اما می‌تواند از سنسورها اطلاعات مهمی درباره اطراف خود دریافت کند.

این موضوع یکی از دلایل اهمیت Observation و POMDP است.

# 20. مقایسه مفاهیم مهم فصل

این جدول برای مرور سریع تفاوت مفاهیمی که احتمال اشتباه گرفتن آن‌ها وجود دارد، بسیار کاربردی است.

| مفهوم اول | مفهوم دوم | تفاوت |
| --- | --- | --- |
| State | Observation | وضعیت واقعی در برابر اطلاعات مشاهده‌شده |
| Action | Reward | اقدام عامل در برابر بازخورد محیط |
| State Space | Action Space | وضعیت‌های ممکن در برابر اقدامات ممکن |
| Deterministic Environment | Stochastic Environment | نتیجه قطعی در برابر نتیجه احتمالاتی |
| Deterministic Policy | Stochastic Policy | انتخاب قطعی در برابر انتخاب احتمالاتی |
| Episodic Task | Continuing Task | وظیفه با پایان مشخص در برابر وظیفه ادامه‌دار |
| Dense Reward | Sparse Reward | بازخورد مکرر در برابر بازخورد محدود |
| MDP | POMDP | مشاهده State در برابر مشاهده ناقص |
| Finite Horizon | Infinite Horizon | افق برنامه‌ریزی محدود در برابر نامحدود |
| Terminal State | Non-terminal State | وضعیت پایانی در برابر وضعیت ادامه‌دار |
| Policy | Model | انتخاب Action در برابر پیش‌بینی رفتار محیط |
| Reward | Return | پاداش یک مرحله در برابر مجموع پاداش‌ها |
| Reward | Value Function | بازخورد فوری در برابر تخمین پاداش آینده |

# 22. مهم‌ترین نکات فصل دوم

اگر بخواهیم تمام فصل را به مفاهیم کلیدی تقلیل دهیم، این موارد مهم‌ترین نکات آن هستند:

1. **Reinforcement Learning:** عامل از طریق تعامل با محیط و دریافت Reward یاد می‌گیرد.
2. **Agent و Environment:** Agent تصمیم می‌گیرد و Environment به تصمیم‌های آن واکنش نشان می‌دهد.
3. **State:** وضعیت فعلی محیط است.
4. **Observation:** اطلاعاتی است که Agent از محیط دریافت می‌کند.
5. **Action:** اقدامی است که Agent می‌تواند انجام دهد.
6. **Transition Function:** نحوه انتقال از State فعلی به State بعدی را مشخص می‌کند.
7. **Reward Function:** کیفیت نتیجه اقدامات را به‌صورت عددی مشخص می‌کند.
8. **Deterministic و Stochastic:** مشخص می‌کنند نتایج اقدامات قطعی هستند یا احتمالاتی.
9. **Episode و Time Step:** واحدهای اصلی توصیف تعامل Agent با محیط هستند.
10. **Return:** مجموع پاداش‌های دریافتی در طول یک وظیفه است.
11. **Policy:** مشخص می‌کند Agent چه Actionای انتخاب کند.
12. **Model:** رفتار آینده Environment را پیش‌بینی می‌کند.
13. **Value Function:** ارزش بلندمدت یک State را تخمین می‌زند.
14. **MDP:** چارچوب ریاضی مدل‌سازی محیط‌های تصمیم‌گیری است.
15. **Markov Property:** آینده به State و Action فعلی وابسته است، نه کل تاریخچه.
16. **Terminal State:** وضعیت پایان Episode است.
17. **Planning Horizon:** افق زمانی تصمیم‌گیری Agent را مشخص می‌کند.
18. **Discount Factor:** اهمیت Rewardهای آینده را تعیین می‌کند.
19. **POMDP:** برای محیط‌هایی استفاده می‌شود که Agent اطلاعات کامل از State ندارد.
20. **Reward Expectation:** میانگین پاداش مورد انتظار را با توجه به احتمالات محاسبه می‌کند.

**نکته مهم:** درک تفاوت‌های MDP و POMDP، State و Observation، Policy و Value Function و همچنین Transition و Reward Function پیش از مطالعه فصل سوم بسیار مهم هستند. این مفاهیم پایه درک الگوریتم‌های Deep Reinforcement Learning محسوب می‌شوند.
