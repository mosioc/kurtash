# خلاصه جامع فصل سوم کتاب Grokking Deep Reinforcement Learning

**موضوع اصلی فصل: حل مسائل تصمیم‌گیری مارکوف (MDP) با استفاده از برنامه‌ریزی پویا (Dynamic Programming)**

این فصل یکی از بنیادی‌ترین فصل‌های یادگیری تقویتی است. هدف آن آشنایی با نحوه ارزیابی سیاست‌ها، محاسبه ارزش حالت‌ها و اقدامات و پیدا کردن سیاست بهینه در محیط‌هایی است که قوانین و پویایی آن‌ها از قبل مشخص هستند.

در این فصل، مفاهیمی معرفی می‌شوند که پایه بسیاری از الگوریتم‌های بعدی یادگیری تقویتی، به‌خصوص Deep Reinforcement Learning، هستند.

# ۱. مبانی و پیش‌نیازهای فصل

## ۱.۱. Markov Decision Process (MDP)

**مفهوم بنیادی**

فرآیند تصمیم‌گیری مارکوف (MDP) چارچوبی ریاضی برای مدل‌سازی مسائل تصمیم‌گیری متوالی در یادگیری تقویتی است.

در یک MDP، عامل (Agent) در محیط (Environment) قرار دارد و با انتخاب اقدامات مختلف، وضعیت محیط را تغییر می‌دهد و پاداش دریافت می‌کند.

MDP قوانین اصلی محیط را مشخص می‌کند؛ یعنی:

- چه حالت‌هایی (States) وجود دارند.
- چه اقداماتی (Actions) قابل انجام هستند.
- احتمال انتقال از یک حالت به حالت دیگر چقدر است.
- هر انتقال چه پاداشی به همراه دارد.

### چرخه تعامل Agent و Environment

در هر مرحله، عامل وضعیت فعلی را دریافت می‌کند، یک Action انتخاب می‌کند و محیط در پاسخ، وضعیت بعدی و پاداش را برمی‌گرداند.

```text
             Action (A_t)
       +----------------------+
       |                      v
+-------------+         +-------------+
|    Agent    |         | Environment |
+-------------+         +-------------+
       ^                      |
       |                      |
       +----------------------+
          State (S_t+1)
          Reward (R_t+1)
```

**مشکل اصلی:** الگوریتم‌هایی مانند Value Iteration و Policy Iteration برای محاسبات خود به شناخت کامل مدل محیط نیاز دارند.

یعنی باید اطلاعات مربوط به موارد زیر در اختیارشان باشد:

- Transition Probabilities
- Reward Function

در دنیای واقعی، همیشه چنین اطلاعاتی در دسترس نیست و ممکن است محیط پیچیده یا متغیر باشد.

## ۱.۲. Dynamic Programming (DP)

برنامه‌ریزی پویا مجموعه‌ای از روش‌های محاسباتی برای حل مسائل تصمیم‌گیری با استفاده از تجزیه مسئله به مسائل کوچک‌تر است.

در Reinforcement Learning، از Dynamic Programming برای ارزیابی و بهینه‌سازی سیاست‌ها در MDP استفاده می‌شود.

دو الگوریتم مهم این حوزه عبارت‌اند از:

1. Policy Iteration
2. Value Iteration

ویژگی مهم Dynamic Programming این است که از مدل شناخته‌شده محیط استفاده می‌کند.

**نکته:** این روش‌ها برای درک اصول RL بسیار مهم هستند، حتی اگر در بسیاری از محیط‌های واقعی نتوان مستقیماً از آن‌ها استفاده کرد.

## ۱.۳. تفاوت Dynamic Programming با Reinforcement Learning واقعی

در مثال‌های ساده این فصل، فرض می‌کنیم عامل به اطلاعات کامل محیط دسترسی دارد.

بنابراین:

- نیازی به Exploration برای کشف قوانین محیط ندارد.
- احتمال انتقال بین حالت‌ها را می‌داند.
- پاداش‌های مربوط به انتقال‌ها را می‌داند.
- می‌تواند با محاسبات ریاضی سیاست مناسب را پیدا کند.

این شرایط با محیط‌های واقعی تفاوت دارد؛ زیرا در مسائل واقعی معمولاً عامل باید از طریق تعامل با محیط، اطلاعات لازم را به دست بیاورد.

# ۲. Reward و Return

## ۲.۱. Reward

پاداش (Reward) مقداری عددی است که عامل پس از انجام یک اقدام یا وقوع یک انتقال از محیط دریافت می‌کند.

هدف عامل در Reinforcement Learning، بیشینه‌سازی پاداش مورد انتظار در طول زمان است.

برای مثال، در یک بازی:

- رسیدن به هدف: پاداش مثبت
- برخورد با مانع: پاداش منفی
- انجام یک اقدام نامناسب: احتمالاً پاداش منفی

پاداش‌ها مشخص می‌کنند چه رفتارهایی از نظر طراحی محیط مطلوب هستند.

## ۲.۲. Return

**مفهوم مهم**

بازده (Return) مجموع پاداش‌هایی است که عامل از یک نقطه زمانی تا پایان مسیر دریافت می‌کند.

به عبارت دیگر، برخلاف Reward که پاداش یک مرحله را نشان می‌دهد، Return به مجموع پاداش‌های آینده توجه دارد.

فرمول Return با در نظر گرفتن Discount Factor:

\[
G_t=\sum_{k=0}^{T-t-1}\gamma^k R_{t+k+1}
\]

در این فرمول:

- \(G_t\): بازده از زمان \(t\)
- \(R_{t+k+1}\): پاداش دریافتی در آینده
- \(\gamma\): ضریب تنزیل (Discount Factor)
- \(T\): زمان پایان یک اپیزود

## ۲.۳. Discount Factor یا Gamma

**مفهوم مهم**

ضریب تنزیل (Discount Factor) مشخص می‌کند پاداش‌های آینده در مقایسه با پاداش‌های نزدیک چقدر اهمیت دارند.

مقدار Gamma معمولاً بین صفر و یک قرار دارد:

\[
0\leq\gamma\leq1
\]

تفسیر مقادیر مختلف:

| مقدار Gamma | مفهوم |
| --- | --- |
| نزدیک به 0 | اهمیت بیشتر پاداش‌های فوری |
| نزدیک به 1 | اهمیت بیشتر پاداش‌های آینده |
| برابر با 1 | بدون تنزیل پاداش‌های آینده |

برای مثال، اگر:

\[
\gamma=0.5
\]

باشد، وزن پاداش مرحله اول برابر با ۱، مرحله دوم برابر با ۰٫۵ و مرحله سوم برابر با ۰٫۲۵ خواهد بود.

بنابراین هرچه پاداش در آینده دورتر باشد، سهم کمتری در Return خواهد داشت.

### نمایش تأثیر Discount Factor بر Return

```text
Time:       t        t+1        t+2        t+3
            |          |          |          |
Reward:     R1         R2         R3         R4
            |          |          |          |
Weight:     1          γ          γ²         γ³
            |          |          |          |
            +----------+----------+----------+
                       |
                       v
              Discounted Return

G_t = R1 + γR2 + γ²R3 + γ³R4 + ...
```

## ۲.۴. Reward-to-Go

Reward-to-Go به مجموع پاداش‌هایی اشاره دارد که عامل از زمان فعلی به بعد می‌تواند دریافت کند.

این مفهوم نگاه رو به آینده دارد و مشخص می‌کند از وضعیت فعلی به بعد چه میزان پاداش قابل دستیابی است.

تفاوت مهم:

- Reward: پاداش یک مرحله
- Return: مجموع پاداش‌های آینده با در نظر گرفتن تنزیل
- Reward-to-Go: مجموع پاداش‌های باقی‌مانده از زمان فعلی به بعد

# ۳. Stochastic Environment

## ۳.۱. محیط تصادفی

محیط تصادفی (Stochastic Environment) محیطی است که در آن نتیجه یک اقدام همیشه قابل پیش‌بینی نیست.

برای مثال، فرض کن عامل قصد دارد در یک محیط شبکه‌ای به سمت راست حرکت کند.

ممکن است:

- به سمت راست حرکت کند.
- به سمت چپ منحرف شود.
- به دلیل تصادفی بودن محیط، نتیجه متفاوتی دریافت کند.

بنابراین یک Action مشخص الزاماً همیشه به یک State مشخص منتهی نمی‌شود.

این ویژگی باعث می‌شود عامل به جای انتخاب ساده یک مسیر، احتمال نتایج مختلف را در نظر بگیرد.

## ۳.۲. مثال Frozen Lake

Frozen Lake یک محیط ساده برای بررسی تصمیم‌گیری در شرایط عدم قطعیت است.

در این محیط:

- برخی خانه‌ها امن هستند.
- برخی خانه‌ها دارای حفره (Hole) هستند.
- یک خانه به عنوان نقطه شروع وجود دارد.
- یک خانه به عنوان هدف (Goal) مشخص شده است.

هدف عامل رسیدن به نقطه هدف بدون افتادن در حفره‌ها است.

اما مشکل اینجاست که اقدامات عامل ممکن است به دلیل تصادفی بودن محیط، نتیجه مورد انتظار را نداشته باشند.

بنابراین عامل باید سیاستی داشته باشد که احتمال نتایج مختلف را در نظر بگیرد.

## ۳.۳. مثال Slippery Walk 5

Slippery Walk 5 نمونه دیگری از محیط‌های تصادفی است که در متن فصل معرفی شده است.

در این محیط، حرکت به یک جهت مشخص همیشه به معنای رسیدن به همان جهت نیست؛ ممکن است عامل به دلیل لغزش در جهت دیگری حرکت کند.

این مثال برای درک تأثیر تصادفی بودن محیط بر محاسبه Return و انتخاب سیاست مناسب استفاده می‌شود.

# ۴. Policy

**مفهوم بنیادی**

سیاست (Policy) استراتژی یا قانونی است که مشخص می‌کند عامل در هر حالت چه اقدامی انجام دهد.

به زبان ساده، Policy مشخص می‌کند:

«اگر در این State قرار گرفتی، چه Action انجام بده.»

سیاست می‌تواند به شکل‌های مختلفی تعریف شود:

- Deterministic Policy: برای هر حالت، یک اقدام مشخص انتخاب می‌کند.
- Stochastic Policy: برای هر حالت، احتمال انتخاب اقدامات مختلف را مشخص می‌کند.

در یک محیط ممکن است چندین Policy متفاوت وجود داشته باشد.

حتی ممکن است چند Policy مختلف عملکرد بهینه و یکسانی داشته باشند.

مثلاً در یک محیط شبکه‌ای، دو مسیر متفاوت ممکن است هر دو به هدف برسند و Return یکسانی تولید کنند.

# ۵. Value Functions

توابع ارزش یکی از مهم‌ترین مفاهیم فصل سوم هستند.

هدف آن‌ها تخمین میزان پاداشی است که عامل می‌تواند از یک وضعیت یا اقدام به دست بیاورد.

در این فصل سه مفهوم اصلی بررسی می‌شوند:

1. State-Value Function
2. Action-Value Function
3. Action-Advantage Function

## ۵.۱. State-Value Function (V Function)

**مفهوم مهم**

تابع ارزش حالت (State-Value Function) نشان می‌دهد قرار گرفتن در یک State، با در نظر گرفتن یک Policy مشخص، چه میزان Return مورد انتظاری برای عامل به همراه خواهد داشت.

فرمول:

\[
V^\pi(s)=\mathbb{E}_\pi[G_t\mid S_t=s]
\]

در این فرمول:

- \(V^\pi(s)\): ارزش حالت \(s\) تحت سیاست \(\pi\)
- \(G_t\): Return
- \(\mathbb{E}\): امید ریاضی (Expected Value)
- \(\pi\): سیاست عامل

به زبان ساده، این تابع به ما می‌گوید:

«اگر عامل در این وضعیت قرار بگیرد و طبق سیاست فعلی خود عمل کند، انتظار داریم در آینده چه میزان پاداش دریافت کند؟»

مثال:

در Frozen Lake، ممکن است دو State متفاوت داشته باشیم:

- State A: نزدیک به هدف و دور از حفره‌ها
- State B: نزدیک به حفره و دور از هدف

احتمالاً State A ارزش بیشتری خواهد داشت.

**نکته:** ارزش یک State به Policy مورد استفاده وابسته است. یک وضعیت ممکن است تحت یک سیاست ارزشمند و تحت سیاست دیگری کم‌ارزش باشد.

## ۵.۲. Action-Value Function (Q Function)

**مفهوم بسیار مهم**

تابع ارزش اقدام (Action-Value Function) مشخص می‌کند انجام یک Action مشخص در یک State مشخص، چه میزان Return مورد انتظار ایجاد می‌کند.

فرمول:

\[
Q^\pi(s,a)=\mathbb{E}_\pi[G_t\mid S_t=s,A_t=a]
\]

این تابع برخلاف V Function فقط ارزش یک State را بررسی نمی‌کند، بلکه اقدام مشخصی را نیز در نظر می‌گیرد.

برای مثال، فرض کن عامل در یک State قرار دارد و دو انتخاب دارد:

- حرکت به چپ
- حرکت به راست

V Function ارزش کلی قرار گرفتن در آن State را نشان می‌دهد؛ اما Q Function مشخص می‌کند انتخاب حرکت به چپ یا راست چه نتیجه‌ای خواهد داشت.

بنابراین Q Function ابزار دقیق‌تری برای مقایسه اقدامات مختلف است.

### تفاوت V و Q Function

| ویژگی | V Function | Q Function |
| --- | --- | --- |
| ورودی | State | State و Action |
| هدف | ارزیابی یک حالت | ارزیابی یک اقدام در یک حالت |
| خروجی | ارزش مورد انتظار حالت | ارزش مورد انتظار اقدام |
| کاربرد | ارزیابی وضعیت | مقایسه اقدامات |

## ۵.۳. Bellman Equation

**مفهوم بنیادی**

معادله بلمن (Bellman Equation) یکی از مهم‌ترین مبانی ریاضی در Reinforcement Learning است.

این معادله ارزش یک State یا Action را بر اساس پاداش فوری و ارزش مورد انتظار وضعیت‌های آینده محاسبه می‌کند.

ایده اصلی:

ارزش یک تصمیم فقط به پاداشی که همین الان دریافت می‌کنیم وابسته نیست؛ بلکه باید ارزش وضعیت‌هایی را هم در نظر بگیریم که در آینده به آن‌ها منتقل می‌شویم.

فرمول Bellman برای Q Function:

\[
Q^\pi(s,a)=
\sum_{s',r}p(s',r\mid s,a)
\left[
r+\gamma\sum_{a'}\pi(a'\mid s')Q^\pi(s',a')
\right]
\]

اجزای فرمول:

- \(s\): وضعیت فعلی
- \(a\): اقدام فعلی
- \(s'\): وضعیت بعدی
- \(r\): پاداش انتقال
- \(p(s',r\mid s,a)\): احتمال انتقال و دریافت پاداش
- \(\gamma\): ضریب تنزیل
- \(\pi\): سیاست عامل

معنای این معادله:

ارزش یک Action برابر است با پاداش فوری به‌علاوه ارزش تنزیل‌شده آینده، با در نظر گرفتن احتمال رخ دادن نتایج مختلف.

**کاربرد:** Bellman Equation پایه محاسباتی بسیاری از الگوریتم‌های یادگیری تقویتی است.

## ۵.۴. Action-Advantage Function (A Function)

**مفهوم مهم**

تابع مزیت اقدام (Action-Advantage Function) مشخص می‌کند یک اقدام مشخص چقدر بهتر یا بدتر از ارزش مورد انتظار خود State است.

فرمول:

\[
A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s)
\]

تفسیر:

- Advantage مثبت: اقدام موردنظر بهتر از عملکرد مورد انتظار سیاست در آن State است.
- Advantage منفی: اقدام موردنظر بدتر از عملکرد مورد انتظار سیاست است.
- Advantage صفر: اقدام موردنظر به اندازه عملکرد مورد انتظار سیاست ارزش دارد.

مثال:

فرض کن سیاست فعلی عامل معمولاً حرکت به چپ را انتخاب می‌کند؛ اما در یک وضعیت خاص، حرکت به راست بهتر است.

Advantage Function مشخص می‌کند حرکت به راست چه میزان بهتر از ارزش کلی مورد انتظار آن State است.

### تفاوت Q و Advantage

Q Function ارزش انجام یک Action مشخص را نشان می‌دهد.

Advantage Function نشان می‌دهد آن Action نسبت به ارزش کلی State چقدر بهتر یا بدتر است.

### ارتباط V Function، Q Function و Advantage

```text
             State (s)
                 |
          +------+------+
          |             |
          v             v
       V(s)           Q(s,a)
    State Value     Action Value
                        |
                        |
              A(s,a) = Q(s,a) - V(s)
                        |
                        v
                  Advantage
```

# ۶. Optimality در Reinforcement Learning

**مفهوم بنیادی**

Optimality به معنای پیدا کردن بهترین رفتار ممکن برای بیشینه‌سازی Expected Return است.

در این بخش، تفاوت میان Policy بهینه و Value Function بهینه بررسی می‌شود.

## ۶.۱. Optimal Policy

سیاست بهینه (Optimal Policy) سیاستی است که بیشترین Return مورد انتظار را در اختیار عامل قرار می‌دهد.

با نماد:

\[
\pi^*
\]

ممکن است یک محیط چندین Optimal Policy داشته باشد.

یعنی چند سیاست متفاوت بتوانند دقیقاً عملکرد بهینه یکسانی داشته باشند.

## ۶.۲. Optimal State-Value Function

تابع ارزش حالت بهینه با نماد زیر نمایش داده می‌شود:

\[
V^*(s)
\]

این تابع بیشترین ارزش قابل دستیابی برای هر State را نشان می‌دهد.

فرمول:

\[
V^*(s)=\max_\pi V^\pi(s)
\]

یعنی از میان تمام سیاست‌های ممکن، بیشترین ارزش قابل دستیابی برای آن State انتخاب می‌شود.

## ۶.۳. Optimal Action-Value Function

تابع ارزش اقدام بهینه با نماد زیر نمایش داده می‌شود:

\[
Q^*(s,a)
\]

این تابع بیشترین Return مورد انتظار را برای یک جفت State و Action نشان می‌دهد، با فرض اینکه پس از اقدام فعلی، عامل بهینه عمل کند.

رابطه مهم:

\[
V^*(s)=\max_a Q^*(s,a)
\]

یعنی برای محاسبه ارزش بهینه یک State، کافی است بیشترین Q Value اقدامات ممکن در آن State را پیدا کنیم.

## ۶.۴. Optimal Advantage Function

تابع مزیت بهینه مشخص می‌کند یک Action نسبت به بهترین ارزش قابل دستیابی در همان State چه وضعیتی دارد.

فرمول:

\[
A^*(s,a)=Q^*(s,a)-V^*(s)
\]

از آنجا که:

\[
V^*(s)=\max_a Q^*(s,a)
\]

بنابراین:

\[
A^*(s,a)\leq 0
\]

یعنی Advantage در حالت بهینه نمی‌تواند مثبت باشد.

اگر Advantage یک Action مثبت باشد، نشان می‌دهد ارزش آن اقدام از ارزش بهینه State بیشتر است که با تعریف Optimality تناقض دارد.

## ۶.۵. رابطه بین V، Q و Policy بهینه

این سه مفهوم ارتباط مستقیمی با یکدیگر دارند:

**Optimal Q Function**

\[
Q^*(s,a)
\]

ارزش بهینه هر جفت State و Action را نشان می‌دهد.

**Optimal V Function**

\[
V^*(s)=\max_a Q^*(s,a)
\]

بیشترین ارزش قابل دستیابی در هر State را نشان می‌دهد.

**Optimal Policy**

\[
\pi^*(s)\in\arg\max_a Q^*(s,a)
\]

اقدامی را انتخاب می‌کند که بیشترین ارزش را دارد. اگر چند اقدام ارزش یکسان و بهینه داشته باشند، هرکدام می‌توانند در یک سیاست بهینه انتخاب شوند.

### ارتباط Optimal Q، Optimal V و Optimal Policy

```text
             Optimal Q Function
                  Q*(s,a)
                     |
          +----------+----------+
          |                     |
          v                     v
    max over actions       argmax over actions
          |                     |
          v                     v
    Optimal V Function    Optimal Policy
         V*(s)               π*(s)
```

نکات مهم:

- اگر Optimal Q Function را داشته باشیم، می‌توانیم Optimal Policy را استخراج کنیم.
- اگر Optimal V Function را داشته باشیم، با استفاده از مدل محیط و بررسی یک مرحله آینده می‌توانیم Optimal Q Function را محاسبه کنیم.
- ممکن است چند Optimal Policy وجود داشته باشد، اما در چارچوب MDPهای مورد بحث، Optimal V و Optimal Q یکتا هستند.

# ۷. Iterative Policy Evaluation

**مفهوم بسیار مهم**

ارزیابی تکرارشونده سیاست (Iterative Policy Evaluation) روشی برای تخمین ارزش حالت‌های مختلف تحت یک Policy مشخص است.

هدف این روش پیدا کردن بهترین Policy نیست؛ بلکه ابتدا می‌خواهیم بفهمیم Policy فعلی چقدر خوب عمل می‌کند.

## ۷.۱. چرا به Iterative Policy Evaluation نیاز داریم؟

در محیط‌هایی با State Space بزرگ، محاسبه مستقیم ارزش تمام حالت‌ها می‌تواند دشوار باشد.

بنابراین به جای محاسبه مستقیم، از تخمین‌های اولیه استفاده می‌کنیم و آن‌ها را به‌صورت تکراری بهبود می‌دهیم.

## ۷.۲. نحوه عملکرد

فرآیند به شکل زیر انجام می‌شود:

1. برای تمام Stateها یک مقدار اولیه در نظر می‌گیریم.
2. Policy موردنظر را مشخص می‌کنیم.
3. ارزش هر State را بر اساس پاداش مورد انتظار و ارزش Stateهای بعدی به‌روزرسانی می‌کنیم.
4. این فرآیند را بارها تکرار می‌کنیم.
5. زمانی که تغییرات مقادیر بسیار کوچک شوند، فرآیند متوقف می‌شود.

فرمول اصلی برای یک Policy قطعی:

\[
V_{k+1}(s)=
\sum_{s',r}p(s',r\mid s,\pi(s))
\left[r+\gamma V_k(s')\right]
\]

برای سیاست تصادفی نیز باید روی اقدامات ممکن با احتمال انتخاب آن‌ها میانگین‌گیری کنیم.

در این فرمول:

- \(V_k(s)\): تخمین ارزش State در تکرار فعلی
- \(V_{k+1}(s)\): تخمین ارزش در تکرار بعدی
- \(r\): پاداش
- \(\gamma\): Discount Factor
- \(p\): احتمال انتقال به State بعدی

## ۷.۳. Convergence

Convergence به معنای همگرایی مقادیر تخمینی به مقادیر پایدار است.

در Iterative Policy Evaluation، با تکرار محاسبات، ارزش Stateها به‌تدریج به مقدار واقعی خود تحت Policy موردنظر نزدیک می‌شود.

برای تشخیص همگرایی، می‌توان تغییرات ارزش Stateها را بررسی کرد.

مثلاً:

\[
\Delta=\max_s|V_{k+1}(s)-V_k(s)|
\]

اگر:

\[
\Delta<\theta
\]

باشد، می‌توان محاسبات را متوقف کرد.

در اینجا \(\theta\) یک مقدار آستانه یا Tolerance است.

نکته مهم: لازم نیست همیشه به دقت ریاضی کامل برسیم؛ گاهی یک تقریب به‌اندازه کافی دقیق برای هدف ما مناسب است.

## ۷.۴. تأثیر Gamma در Policy Evaluation

مقدار Gamma روی نحوه ارزیابی ارزش حالت‌ها تأثیر می‌گذارد.

- Gamma پایین: پاداش‌های فوری اهمیت بیشتری دارند.
- Gamma بالا: پاداش‌های آینده اهمیت بیشتری دارند.

در متن فصل، نمونه‌ای با:

\[
\gamma=0.99
\]

بررسی شده است.

این مقدار نشان می‌دهد پاداش‌های آینده نیز اهمیت زیادی دارند.

## ۷.۵. مثال ارزیابی Policy

در مثال کتاب، ارزش Stateهای مختلف در یک محیط با استفاده از Iterative Policy Evaluation محاسبه می‌شود.

در این مثال:

- یک Policy تصادفی بررسی می‌شود.
- ارزش اولیه Stateها تخمین زده می‌شود.
- با تکرار محاسبات، ارزش‌ها به‌روزرسانی می‌شوند.
- پس از حدود هشت تکرار، تخمین‌های مناسبی به دست می‌آیند.

همچنین یک Policy دیگر با نام GoGetIt بررسی می‌شود که برخلاف انتظار، عملکرد چندان خوبی ندارد و فقط درصد کمی از مواقع به هدف می‌رسد.

**نتیجه مهم:** عملکرد یک Policy به ویژگی‌های محیط و ساختار پاداش آن وابسته است. یک سیاست لزوماً در همه محیط‌ها عملکرد خوبی ندارد.

# ۸. Multiple Optimal Policies و Tie-Breaking

در یک محیط ممکن است چند Policy بهینه وجود داشته باشند.

برای مثال، در یک محیط شبکه‌ای ممکن است دو مسیر متفاوت دقیقاً Return یکسانی داشته باشند.

در متن فصل، مثال State شماره ۶ مطرح می‌شود که در آن دو Action، یعنی حرکت به چپ و راست، ارزش یکسانی دارند.

به این وضعیت Tie گفته می‌شود.

## ۸.۱. مشکل Tie-Breaking

اگر دو Action دارای Q Value یکسان باشند، الگوریتم باید مشخص کند کدام‌یک را انتخاب کند.

انتخاب تصادفی و بدون مدیریت مناسب Tieها ممکن است باعث شود الگوریتم بین چند Policy مختلف جابه‌جا شود و پیشرفت مشخصی نداشته باشد.

## ۸.۲. Tie-Breaking Strategy

برای جلوگیری از این مشکل باید هنگام انتخاب Actionهای هم‌ارزش، از یک روش انتخاب مشخص و سازگار استفاده کرد.

هدف این است که الگوریتم در چرخه‌های غیرضروری گرفتار نشود و بتواند به یک Policy بهینه و پایدار برسد.

# ۹. Policy Iteration

**الگوریتم اصلی فصل**

Policy Iteration الگوریتمی برای پیدا کردن Optimal Policy در یک MDP با استفاده از تکرار دو مرحله اصلی است:

1. Policy Evaluation
2. Policy Improvement

ایده اصلی این است که ابتدا عملکرد Policy فعلی را ارزیابی کنیم و سپس با استفاده از اطلاعات به‌دست‌آمده، آن را بهبود دهیم.

## ۹.۱. Policy Evaluation

در این مرحله، ارزش Stateهای مختلف تحت Policy فعلی محاسبه می‌شود.

یعنی می‌خواهیم بدانیم سیاست فعلی در هر وضعیت چه میزان Return مورد انتظاری ایجاد می‌کند.

این کار با استفاده از Iterative Policy Evaluation انجام می‌شود.

## ۹.۲. Policy Improvement

پس از ارزیابی Policy، نوبت به بهبود آن می‌رسد.

در این مرحله، با استفاده از Value Function یا Q Function، اقدامات بهتر برای هر State انتخاب می‌شوند.

به عبارت دیگر، Policy جدید تلاش می‌کند در هر State اقدامی را انتخاب کند که ارزش بیشتری داشته باشد.

فرمول کلی بهبود سیاست:

\[
\pi'(s)=
\arg\max_a
\sum_{s',r}p(s',r\mid s,a)
[r+\gamma V^\pi(s')]
\]

## ۹.۳. چرخه Policy Iteration

```text
       +------------------+
       |  Initial Policy  |
       +------------------+
                |
                v
       +------------------+
       | Policy Evaluation|
       +------------------+
                |
                v
       +-------------------+
       | Policy Improvement|
       +-------------------+
                |
                v
       +------------------+
       | Policy Changed?  |
       +------------------+
           |          |
          Yes         No
           |          |
           |          v
           |    +----------------+
           |    | Optimal Policy |
           |    +----------------+
           |
           +------> Repeat
```

مراحل الگوریتم:

1. **Initial Policy**
   - شروع با یک Policy اولیه

2. **Policy Evaluation**
   - محاسبه ارزش Stateها تحت سیاست فعلی

3. **Policy Improvement**
   - انتخاب اقدامات بهتر و به‌روزرسانی Policy

4. **بررسی همگرایی (Convergence)**
   - آیا Policy دیگر تغییر نمی‌کند؟
   - **خیر:** تکرار مراحل Policy Evaluation و Policy Improvement
   - **بله:** دستیابی به Optimal Policy

## ۹.۴. ویژگی‌های Policy Iteration

- به‌صورت مستقیم Policy را بهبود می‌دهد.
- از Policy Evaluation برای تخمین ارزش Stateها استفاده می‌کند.
- با Policy Improvement اقدامات بهتر را انتخاب می‌کند.
- در MDPهای متناهی با شرایط استاندارد، به Policy بهینه همگرا می‌شود.
- ممکن است چند Policy بهینه وجود داشته باشد.

# ۱۰. Value Iteration

Value Iteration یکی دیگر از الگوریتم‌های مهم Dynamic Programming برای پیدا کردن Optimal Value Function و Optimal Policy است.

این الگوریتم در ابتدای متن فصل به‌عنوان یکی از دو روش بنیادی حل MDP معرفی شده است.

تفاوت کلی آن با Policy Iteration در نحوه انجام محاسبات است:

- Policy Iteration دو مرحله ارزیابی و بهبود سیاست را تکرار می‌کند.
- Value Iteration ارزش حالت‌ها را با استفاده از بیشینه‌سازی ارزش اقدامات ممکن به‌روزرسانی می‌کند.

فرمول استاندارد Value Iteration:

\[
V_{k+1}(s)=
\max_a\sum_{s',r}p(s',r\mid s,a)
[r+\gamma V_k(s')]
\]

### مقایسه ساختار Policy Iteration و Value Iteration

```text
       Dynamic Programming
                |
        +-------+-------+
        |               |
        v               v
 Policy Iteration   Value Iteration
        |               |
        v               v
 Policy Evaluation  Value Update
        |               |
        v               v
 Policy Improvement  Max over Actions
        |               |
        v               v
 Optimal Policy     Optimal Value
```

**نکته مهم درباره منبع:** متن صوتی ارسالی، Value Iteration را معرفی می‌کند اما وارد مراحل اجرایی و مثال محاسباتی آن نمی‌شود. بنابراین توضیح فرمول بالا برای تکمیل ارتباط مفهومی آن با مطالب فصل است و جزئیات الگوریتم از متن صوتی استخراج نشده‌اند.

# ۱۴. نکات کلیدی فصل

1. MDP چارچوب ریاضی مدل‌سازی مسائل تصمیم‌گیری متوالی در RL است.
2. Dynamic Programming برای حل MDPهایی استفاده می‌شود که مدل محیط آن‌ها مشخص است.
3. Reward پاداش یک مرحله و Return مجموع پاداش‌های آینده است.
4. Discount Factor با نماد Gamma اهمیت پاداش‌های آینده را مشخص می‌کند.
5. Policy تعیین می‌کند عامل در هر State چه Action انجام دهد.
6. Stochastic Environment به این معناست که نتیجه اقدامات همیشه قابل پیش‌بینی نیست.
7. V Function ارزش مورد انتظار یک State را نشان می‌دهد.
8. Q Function ارزش مورد انتظار یک Action مشخص در یک State را نشان می‌دهد.
9. Advantage Function تفاوت ارزش یک Action با ارزش State را مشخص می‌کند.
10. Bellman Equation ارزش فعلی را به پاداش فوری و ارزش آینده مرتبط می‌کند.
11. Optimal Policy بهترین استراتژی برای بیشینه‌سازی Expected Return است.
12. Optimal V و Optimal Q به‌ترتیب بیشترین ارزش حالت و اقدام را نشان می‌دهند.
13. Iterative Policy Evaluation عملکرد یک Policy مشخص را با به‌روزرسانی تکراری ارزش Stateها تخمین می‌زند.
14. Policy Iteration از دو مرحله Policy Evaluation و Policy Improvement تشکیل شده است.
15. Value Iteration مستقیماً ارزش Stateها را با استفاده از بیشینه‌سازی روی اقدامات به‌روزرسانی می‌کند.
16. ممکن است چند Policy بهینه وجود داشته باشند؛ بنابراین مدیریت Tieها اهمیت دارد.
17. در MDPهای متناهی با شرایط استاندارد، Policy Iteration و Value Iteration به جواب بهینه همگرا می‌شوند.

# ۱۵. جمع‌بندی نهایی فصل

اگر بخواهیم کل فصل سوم را در یک مسیر منطقی خلاصه کنیم:

ابتدا محیط را با استفاده از MDP مدل‌سازی می‌کنیم. سپس با استفاده از Reward و Return، عملکرد تصمیم‌های عامل را اندازه‌گیری می‌کنیم. Policy مشخص می‌کند عامل چه اقداماتی انجام دهد و Value Function مشخص می‌کند این تصمیم‌ها چقدر ارزشمند هستند.

با استفاده از Bellman Equation، ارزش وضعیت‌های فعلی را بر اساس پاداش و ارزش وضعیت‌های آینده محاسبه می‌کنیم.

در ادامه، با استفاده از Policy Evaluation عملکرد سیاست فعلی را تخمین می‌زنیم و با Policy Improvement آن را بهبود می‌دهیم. این فرآیند در Policy Iteration تکرار می‌شود تا به یک Policy بهینه برسیم.

**مهم‌ترین پیام فصل:** برای تصمیم‌گیری هوشمندانه، صرفاً دانستن وضعیت فعلی کافی نیست؛ باید ارزش بلندمدت اقدامات و پیامدهای احتمالی آن‌ها را نیز ارزیابی کنیم.

## پیشنهاد برای تسلط بر فصل

- تفاوت Reward، Return و Discount Factor
- تفاوت V Function، Q Function و Advantage Function
- درک Bellman Equation و ارتباط آن با Value Functions
- تفاوت Policy Evaluation و Policy Improvement
- درک چرخه Policy Iteration و تفاوت آن با Value Iteration
- درک نمودار تعامل Agent و Environment
- توانایی توضیح ارتباط Optimal Q، Optimal V و Optimal Policy
- توانایی تشریح چرخه Policy Iteration بدون مراجعه به متن
