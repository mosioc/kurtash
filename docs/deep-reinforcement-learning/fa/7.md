# **بخش اول: استفاده بهتر از تجربه‌ها**

## **۲. چرا به روش‌های بهتر برای Policy Evaluation نیاز داریم؟**

در فصل‌های قبل با الگوریتم‌های زیر آشنا شدیم:

- Monte Carlo
- TD Learning
- N-Step TD
- SARSA
- Q-Learning

یکی از مشکلات روش‌های معمول این است که ممکن است اطلاعات مربوط به یک Reward دیرهنگام، به‌آرامی به Stateها و State-Action Pairهای قبلی منتقل شود.

برای مثال، فرض کن Agent در یک بازی ۱۰ حرکت انجام می‌دهد و فقط در حرکت دهم به هدف می‌رسد و Reward دریافت می‌کند.

```
S1 → S2 → S3 → S4 → ... → S10 → Goal
                                      |
                                   Reward +10
```

اگر از روش One-Step TD استفاده کنیم، اطلاعات Reward ابتدا فقط به State قبلی منتقل می‌شود و سپس در مراحل بعدی به Stateهای قبلی‌تر می‌رسد.

این فرایند ممکن است به تعداد زیادی به‌روزرسانی نیاز داشته باشد.

**هدف روش‌های این فصل:** انتقال مؤثرتر اطلاعات Reward به Stateها و Actionهای قبلی، بدون اینکه مجبور باشیم برای هر به‌روزرسانی تا پایان Episode صبر کنیم.

## **۳. On-Policy و Off-Policy**

قبل از بررسی الگوریتم‌های فصل، باید تفاوت این دو مفهوم را بدانیم.

### **۳.۱. On-Policy Learning**

در روش On-Policy، Agent رفتار و ارزش همان Policy را که برای تعامل با محیط استفاده می‌کند، یاد می‌گیرد.

به بیان دیگر:

- Policy مورد استفاده برای انتخاب Actionها همان Policy مورد ارزیابی و بهبود است.
- Agent از تجربه‌هایی یاد می‌گیرد که با Policy رفتاری خودش تولید کرده است.

مثال: SARSA و SARSA(λ).

### **۳.۲. Off-Policy Learning**

در روش Off-Policy، Policy مورد استفاده برای جمع‌آوری تجربه می‌تواند با Policy مورد استفاده برای یادگیری متفاوت باشد.

دو Policy مهم داریم:

- Behavior Policy: سیاستی که Agent با آن Action انتخاب می‌کند.
- Target Policy: سیاستی که Agent می‌خواهد ارزش آن را یاد بگیرد یا به سمت آن بهبود پیدا کند.

مثال: Q-Learning و Watkins's Q(λ).

### **مقایسه**

| ویژگی             | On-Policy            | Off-Policy             |
| ----------------- | -------------------- | ---------------------- |
| Behavior Policy   | همان Target Policy   | می‌تواند متفاوت باشد   |
| یادگیری           | از رفتار Policy فعلی | مستقل‌تر از رفتار فعلی |
| الگوریتم نمونه    | SARSA                | Q-Learning             |
| نمونه توسعه‌یافته | SARSA(λ)             | Watkins's Q(λ)         |

نکته مهم: Off-Policy به این معنی نیست که Agent بدون Policy رفتار می‌کند؛ بلکه رفتار جمع‌آوری تجربه از Policy مورد یادگیری متمایز است.

## **۴. λ-Return**

مفهوم کلیدی فصل

`λ-Return` روشی برای ترکیب اطلاعات حاصل از بازگشت‌های چندمرحله‌ای مختلف است.

برای درک آن، ابتدا باید سه مفهوم را بشناسیم:

### **۴.۱. One-Step Return**

در One-Step TD، فقط Reward یک مرحله آینده را در نظر می‌گیریم و سپس از تخمین Value در State بعدی استفاده می‌کنیم.

\\[ G_t^{(1)}=R\_{t+1}+\gamma V(S\_{t+1}) \\]

ویژگی‌ها:

- یک Reward واقعی.
- یک تخمین از آینده.
- استفاده از Bootstrapping.
- به‌روزرسانی سریع، اما وابسته به تخمین Value مرحله بعد.

### **۴.۲. N-Step Return**

در N-Step TD، به‌جای یک Reward، چند Reward متوالی را در نظر می‌گیریم و سپس از Value تخمینی State نهایی استفاده می‌کنیم.

\\[ G_t^{(n)} = \sum\_{k=1}^{n}\gamma^{k-1}R\_{t+k} +\gamma^n V(S\_{t+n}) \\]

ویژگی‌ها:

- استفاده از چند Reward واقعی.
- استفاده از تخمین Value در انتهای بازه.
- انتقال اطلاعات در چند مرحله.
- کاهش وابستگی به تخمین‌های نزدیک.

### **۴.۳. Monte Carlo Return**

در Monte Carlo، Return واقعی تا پایان Episode محاسبه می‌شود.

\\[ G_t = \sum\_{k=1}^{T-t}\gamma^{k-1}R\_{t+k} \\]

ویژگی‌ها:

- استفاده از Rewardهای واقعی تا پایان Episode.
- بدون Bootstrapping.
- نیازمند مشاهده ادامه Episode تا پایان آن.
- معمولاً Variance بیشتری نسبت به روش‌های TD دارد.

### **۴.۴. ایده اصلی λ-Return**

به‌جای انتخاب فقط یک N-Step Return، می‌توان Returnهای چندمرحله‌ای مختلف را با وزن‌های مشخص ترکیب کرد.

\\[ G_t^\lambda = (1-\lambda) \sum\_{n=1}^{\infty} \lambda^{n-1}G_t^{(n)} \\]

این فرمول شکل مفهومی برای Episodeهای ادامه‌دار است؛ در Episodeهای محدود، نسخه مناسب باید با درنظرگرفتن پایان Episode محاسبه شود.

پارامتر λ بین صفر و یک قرار دارد:

\\[ 0 \leq \lambda \leq 1 \\]

- λ نزدیک صفر: وزن بیشتر به Returnهای کوتاه‌مدت.
- λ نزدیک یک: وزن بیشتر به Returnهای بلندمدت.

در نتیجه، λ امکان کنترل میزان استفاده از اطلاعات آینده را فراهم می‌کند.

### **رفتار λ در دو حالت حدی**

| مقدار λ | رفتار                    |
| ------- | ------------------------ |
| λ = 0   | معادل One-Step TD        |
| λ → 1   | نزدیک‌شدن به Monte Carlo |

**طیف مفهومی λ-Return**

```
λ = 0                                      λ = 1
  |------------------------------------------|
  v                                          v
One-Step TD                              Monte Carlo

       λ افزایش پیدا می‌کند  →
       سهم Returnهای چندمرحله‌ای بلندتر بیشتر می‌شود.
```

**نکته:**

- λ = 0 → معادل One-Step TD
- λ = 1 → معادل Monte Carlo (در حالت Episodic و با شرایط مناسب)

**نکته مهم:** λ همان Learning Rate نیست.

- α (Alpha): میزان تغییر Value در هر به‌روزرسانی.
- γ (Gamma): میزان اهمیت Rewardهای آینده.
- λ (Lambda): میزان اهمیت Returnهای چندمرحله‌ای مختلف.

## **۵. Eligibility Traces**

مفهوم کلیدی فصل

Eligibility Traces مکانیزمی برای نگهداری اطلاعاتی درباره Stateها یا State-Action Pairهایی است که Agent اخیراً از آن‌ها بازدید کرده است.

هدف این مکانیزم این است که هنگام دریافت TD Error، مشخص شود کدام Stateها یا Actionهای قبلی باید در به‌روزرسانی Value Function مشارکت کنند.

به زبان ساده، Eligibility Trace نوعی حافظه کوتاه‌مدت از تجربه‌های Agent است.

### **۵.۱. چرا Eligibility Traces اهمیت دارند؟**

فرض کن Agent در یک بازی مسیر زیر را طی می‌کند:

```
S1 → S2 → S3 → S4 → S5 → Goal
                                  |
                               Reward +10
```

هنگامی که Agent به Goal می‌رسد، اطلاعات مربوط به Reward باید به تجربه‌های قبلی منتقل شود.

بدون Eligibility Traces، روش One-Step TD اطلاعات را به‌صورت تدریجی منتقل می‌کند.

اما با Eligibility Traces، Stateهای قبلی هنوز ردپایی از حضور خود دارند و می‌توانند با دریافت TD Error به‌روزرسانی شوند.

### **۵.۲. دو نوع Eligibility Traces**

دو نوع اصلی که در این فصل بررسی می‌شوند:

1. Accumulating Traces
2. Replacing Traces

### **۵.۳. Accumulating Traces**

در این روش، هر بار که Agent از یک State یا State-Action Pair بازدید می‌کند، مقدار Eligibility آن افزایش می‌یابد.

فرمول:

\\[ e_t(s,a)= \begin{cases} \gamma\lambda e\_{t-1}(s,a)+1 & (s,a)=(S_t,A_t)\\\ \gamma\lambda e\_{t-1}(s,a) & \text{otherwise} \end{cases} \\]

یعنی:

- با هر بازدید، مقدار Trace افزایش می‌یابد.
- Traceهای قدیمی به‌مرور کاهش پیدا می‌کنند.
- بازدیدهای تکراری باعث افزایش اهمیت آن State-Action Pair می‌شوند.

**مثال:**

فرض کن Agent چند بار از یک State-Action Pair مشخص بازدید کند.

```
Visit 1 → Eligibility = 1
Visit 2 → Eligibility = 1 + γλ
Visit 3 → Eligibility = 1 + γλ + (γλ)²
```

در نتیجه، مقدار Eligibility می‌تواند از ۱ بیشتر شود.

مزیت: تعداد دفعات بازدید نیز در میزان تأثیر تجربه نقش دارد.

محدودیت: اگر Agent در یک Loop بارها یک State-Action Pair را تکرار کند، مقدار Eligibility آن ممکن است بیش از حد افزایش یابد.

### **۵.۴. Replacing Traces**

در این روش، هنگام بازدید مجدد از یک State-Action Pair، مقدار Trace آن به ۱ تنظیم می‌شود، نه اینکه به مقدار قبلی اضافه شود.

فرمول:

\\[ e_t(s,a)= \begin{cases} 1 & (s,a)=(S_t,A_t)\\\ \gamma\lambda e\_{t-1}(s,a) & \text{otherwise} \end{cases} \\]

ویژگی‌ها:

- مقدار Trace مربوط به Pair فعلی برابر ۱ می‌شود.
- Traceهای سایر Pairها کاهش پیدا می‌کنند.
- بازدیدهای تکراری باعث انباشته‌شدن مقدار Trace نمی‌شوند.
- مقدار Trace از ۱ بیشتر نمی‌شود.

### **۵.۵. مقایسه Accumulating و Replacing Traces**

| ویژگی           | Accumulating            | Replacing       |
| --------------- | ----------------------- | --------------- |
| بازدید مجدد     | افزایش مقدار            | تنظیم مجدد به ۱ |
| حداکثر مقدار    | ممکن است بیشتر از ۱ شود | حداکثر ۱        |
| تأثیر تکرار     | قوی‌تر می‌شود           | انباشته نمی‌شود |
| رفتار در Loop   | احتمال انباشت زیاد      | کنترل‌شده‌تر    |
| اهمیت Frequency | بیشتر                   | کمتر            |

### **مثال مفهومی: Frequency در مقابل Recency**

فرض کن Agent در یک محیط مرتباً از یک مسیر تکراری عبور می‌کند، اما در نهایت یک State جدید را تجربه می‌کند که به دریافت Reward منجر می‌شود.

- Accumulating Traces به بازدیدهای مکرر گذشته اهمیت بیشتری می‌دهد.
- Replacing Traces اجازه نمی‌دهد صرفاً به دلیل تکرار زیاد، یک State-Action Pair بیش از حد تأثیرگذار شود.

بنابراین:

**Accumulating Traces بیشتر Frequency و Recency را ترکیب می‌کند، درحالی‌که Replacing Traces از انباشته‌شدن اثر بازدیدهای تکراری جلوگیری می‌کند.**

نکته: Replacing Traces الزاماً همیشه بهتر یا پایدارتر نیست؛ انتخاب آن‌ها به الگوریتم، محیط و نوع مسئله بستگی دارد.

### **۵.۶. تأثیر Eligibility Traces بر Q-Function**

Eligibility Traces فقط یک حافظه مستقل نیستند؛ مستقیماً در به‌روزرسانی Value Function مشارکت می‌کنند.

در Q-Learning با Eligibility Traces، فرمول به‌روزرسانی به شکل زیر است:

\\[ Q(s,a)\leftarrow Q(s,a)+ \alpha\delta_t e_t(s,a) \\]

که در آن:

- \\(Q(s,a)\\): مقدار فعلی State-Action Pair.
- \\(\alpha\\): Learning Rate.
- \\(\delta_t\\): TD Error.
- \\(e_t(s,a)\\): Eligibility Trace.

بنابراین، مقدار تغییر Q به دو عامل وابسته است:

1. میزان خطای پیش‌بینی (TD Error).
2. میزان Eligibility آن State-Action Pair.

برای مثال، اگر یک State-Action Pair مقدار Eligibility بالایی داشته باشد، TD Error می‌تواند تأثیر بیشتری روی Q آن بگذارد.

### **۵.۷. تفاوت Eligibility Trace و TD Error**

این دو مفهوم را نباید با یکدیگر اشتباه گرفت.

| مفهوم             | وظیفه                                                        |
| ----------------- | ------------------------------------------------------------ |
| TD Error          | مشخص می‌کند پیش‌بینی Value چقدر اشتباه بوده است              |
| Eligibility Trace | مشخص می‌کند کدام State یا Action باید از این خطا تأثیر بگیرد |

به بیان ساده:

- TD Error می‌گوید چقدر باید یاد بگیریم.
- Eligibility Trace می‌گوید کجا باید یاد بگیریم.

## **۶. SARSA(λ)**

On-Policy Control

SARSA(λ) نسخه توسعه‌یافته SARSA است که از λ-Return و Eligibility Traces استفاده می‌کند.

در SARSA معمولی، هر بار تنها یک مرحله از آینده برای محاسبه TD Target در نظر گرفته می‌شود.

اما SARSA(λ) امکان انتقال اطلاعات حاصل از چندین مرحله آینده به State-Action Pairهای قبلی را فراهم می‌کند.

### **۶.۱. یادآوری SARSA معمولی**

SARSA مخفف پنج عنصر زیر است:

```
S → A → R → S' → A'
```

فرمول TD Target:

\\[ Target=R\_{t+1}+\gamma Q(S\_{t+1},A\_{t+1}) \\]

فرمول TD Error:

\\[ \delta_t= R\_{t+1} +\gamma Q(S\_{t+1},A\_{t+1}) -Q(S_t,A_t) \\]

و به‌روزرسانی:

\\[ Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha\delta_t \\]

### **۶.۲. SARSA(λ) چگونه کار می‌کند؟**

SARSA(λ) به‌جای به‌روزرسانی صرفاً State-Action Pair فعلی، از Eligibility Traces برای به‌روزرسانی Pairهای قبلی نیز استفاده می‌کند.

در هر Time Step:

1. Agent یک State و Action را تجربه می‌کند.
2. Reward و State بعدی را دریافت می‌کند.
3. TD Error محاسبه می‌شود.
4. Eligibility Traces به‌روزرسانی می‌شوند.
5. Q-Value تمام State-Action Pairهای دارای Eligibility به‌روزرسانی می‌شوند.
6. Agent به تعامل با محیط ادامه می‌دهد.

فرمول به‌روزرسانی:

\\[ Q(s,a)\leftarrow Q(s,a)+\alpha\delta_t e_t(s,a) \\]

### **۶.۳. ویژگی‌های SARSA(λ)**

- On-Policy است.
- از Eligibility Traces استفاده می‌کند.
- می‌تواند از تجربه‌های چندین مرحله قبل استفاده کند.
- برای مسائل دارای Delayed Rewards مفید است.
- به‌روزرسانی‌های آن می‌توانند سریع‌تر از SARSA معمولی اطلاعات Reward را منتقل کنند.

### **۶.۴. تفاوت SARSA و SARSA(λ)**

| ویژگی              | SARSA           | SARSA(λ)                 |
| ------------------ | --------------- | ------------------------ |
| نوع یادگیری        | On-Policy       | On-Policy                |
| TD Target          | One-Step        | λ-Return در Forward View |
| Eligibility Traces | ندارد           | دارد                     |
| انتقال اعتبار      | عمدتاً یک مرحله | چندین مرحله              |
| Delayed Rewards    | محدودتر         | مناسب‌تر                 |

نکته مهم: SARSA(λ) با λ=0 به SARSA معمولی تبدیل می‌شود.

## **۷. Watkins's Q(λ)**

Off-Policy Control

Watkins's Q(λ) نسخه توسعه‌یافته Q-Learning است که از Eligibility Traces برای انتقال اطلاعات Reward به تجربه‌های قبلی استفاده می‌کند.

برای درک آن باید ابتدا تفاوت Q-Learning و SARSA را به یاد بیاوریم.

### **۷.۱. یادآوری Q-Learning**

Q-Learning یک الگوریتم Off-Policy است.

فرمول TD Target:

\\[ Target= R\_{t+1}+ \gamma\max_a Q(S\_{t+1},a) \\]

فرمول TD Error:

\\[ \delta_t= R\_{t+1} +\gamma\max_a Q(S\_{t+1},a) -Q(S_t,A_t) \\]

نکته اصلی:

Q-Learning برای محاسبه Target از بهترین Action ممکن طبق Q-Function استفاده می‌کند، نه لزوماً Action انتخاب‌شده توسط Behavior Policy.

### **۷.۲. ایده Watkins's Q(λ)**

Watkins's Q(λ) این ویژگی Q-Learning را حفظ می‌کند و Eligibility Traces را به آن اضافه می‌کند.

یعنی:

- همچنان Off-Policy باقی می‌ماند.
- از TD Error برای اصلاح Q-Values استفاده می‌کند.
- اطلاعات را به State-Action Pairهای قبلی منتقل می‌کند.
- از Eligibility Traces برای مشخص‌کردن میزان تأثیر تجربه‌های قبلی استفاده می‌کند.

### **۷.۳. تفاوت مهم Watkins's Q(λ) و SARSA(λ)**

در SARSA(λ)، Agent از Action انتخاب‌شده توسط Policy برای محاسبه TD Target استفاده می‌کند.

اما Watkins's Q(λ) از بیشترین Q-Value در State بعدی استفاده می‌کند.

با این حال، یک مسئله مهم وجود دارد:

اگر Agent در State بعدی یک Action غیرحریصانه (Non-Greedy) انتخاب کند، دیگر نمی‌توان به همان شکل قبلی Eligibility Traces را حفظ کرد.

به همین دلیل Watkins's Q(λ) از مکانیزم خاصی استفاده می‌کند.

### **۷.۴. Clearing Eligibility Traces**

در Watkins's Q(λ)، اگر Action انتخاب‌شده توسط Behavior Policy در State جدید، Greedy نباشد، Eligibility Traces پاک می‌شوند.

چرا؟

چون الگوریتم در حال یادگیری ارزش Policy حریصانه است، اما Agent در عمل یک Action غیرحریصانه انتخاب کرده است.

اگر ردپای تجربه‌های قبلی حفظ شود، ممکن است اطلاعات حاصل از رفتار Exploratory به‌صورت نامناسب در Target Policy منتشر شود.

بنابراین، در صورت انتخاب Action غیرحریصانه:

```
Non-Greedy Action
       |
       v
Clear Eligibility Traces
       |
       v
Continue Learning
```

در صورت انتخاب Action حریصانه، Traceهای قبلی طبق قاعده معمول کاهش پیدا می‌کنند.

### **۷.۵. تفاوت SARSA(λ) و Watkins's Q(λ)**

| ویژگی                       | SARSA(λ)            | Watkins's Q(λ)         |
| --------------------------- | ------------------- | ---------------------- |
| نوع                         | On-Policy           | Off-Policy             |
| TD Target                   | Action انتخاب‌شده   | Max Q                  |
| Eligibility Traces          | دارد                | دارد                   |
| برخورد با Non-Greedy Action | ادامه Traceها       | پاک‌کردن Traceها       |
| هدف                         | بهبود Policy رفتاری | یادگیری Policy حریصانه |

### **۷.۶. Peng's Q(λ)**

در کنار Watkins's Q(λ)، روش دیگری به نام Peng's Q(λ) نیز وجود دارد.

تفاوت مهم این دو روش در نحوه برخورد با تجربه‌های غیرحریصانه و حفظ Eligibility Traces است.

- Watkins's Q(λ): پس از انتخاب Action غیرحریصانه، Traceها را پاک می‌کند.
- Peng's Q(λ): از یک روش متفاوت برای ترکیب اطلاعات On-Policy و Off-Policy استفاده می‌کند و Traceها را به همان شکل Watkins قطع نمی‌کند.

در نتیجه، Peng's Q(λ) می‌تواند اطلاعات بیشتری از دنباله رفتار Agent حفظ کند.

البته این دو الگوریتم را نباید صرفاً دو پیاده‌سازی متفاوت از یک فرمول یکسان دانست؛ Targetهای مورد استفاده آن‌ها نیز تفاوت دارند.

## **۸. مقایسه الگوریتم‌های بخش اول**

| الگوریتم       | On/Off-Policy | Eligibility Traces | ویژگی مهم                               |
| -------------- | ------------- | ------------------ | --------------------------------------- |
| SARSA          | On-Policy     | خیر                | One-Step Update                         |
| SARSA(λ)       | On-Policy     | بله                | Multi-Step Credit Assignment            |
| Q-Learning     | Off-Policy    | خیر                | Greedy TD Target                        |
| Watkins's Q(λ) | Off-Policy    | بله                | پاک‌کردن Trace پس از Non-Greedy Action  |
| Peng's Q(λ)    | Off-Policy    | بله                | حفظ متفاوت اطلاعات تجربه‌های غیرحریصانه |

**ارتباط مفهومی:**

```
             TD Control
                 |
        +--------+--------+
        |                 |
     On-Policy         Off-Policy
        |                 |
      SARSA            Q-Learning
        |                 |
    SARSA(λ)       Watkins's Q(λ)
                          |
                     Peng's Q(λ)
```

# **بخش دوم: Model-Based Reinforcement Learning**

## **۹. Model-Free در مقابل Model-Based RL**

در بخش دوم فصل، از بهبود الگوریتم‌های مبتنی بر تجربه مستقیم فراتر می‌رویم.

اینجا دو رویکرد اصلی Reinforcement Learning مطرح می‌شوند.

### **۹.۱. Model-Free Reinforcement Learning**

در Model-Free RL، Agent برای یادگیری Policy یا Value Function نیازی به ساخت مدل صریح از محیط ندارد.

Agent:

1. با Environment تعامل می‌کند.
2. Action انتخاب می‌کند.
3. Reward دریافت می‌کند.
4. State جدید را مشاهده می‌کند.
5. با استفاده از تجربه‌ها Value Function یا Policy را بهبود می‌دهد.

مثال:

- SARSA
- Q-Learning
- DQN

مزایا:

- نیاز نداشتن به مدل صریح محیط.
- پیاده‌سازی نسبتاً ساده‌تر.
- مناسب برای محیط‌هایی که مدل دقیق آن‌ها در دسترس نیست.

معایب:

- نیاز احتمالی به تجربه‌های زیاد.
- وابستگی به تعامل مستقیم با Environment.
- استفاده‌نکردن مستقیم از شبیه‌سازی مدل برای Planning.

### **۹.۲. Model-Based Reinforcement Learning**

در Model-Based RL، Agent یک مدل از رفتار محیط یاد می‌گیرد یا از مدلی که از قبل در اختیار دارد استفاده می‌کند.

این مدل به Agent کمک می‌کند بفهمد:

- با انتخاب یک Action چه Stateهایی ممکن است ایجاد شوند؟
- احتمال وقوع هر Transition چقدر است؟
- چه Rewardی ممکن است دریافت شود؟

Agent می‌تواند با استفاده از این مدل، بدون انجام مجدد تمام تعاملات در محیط واقعی، آینده را شبیه‌سازی کند.

### **مقایسه**

| ویژگی             | Model-Free             | Model-Based                          |
| ----------------- | ---------------------- | ------------------------------------ |
| مدل محیط          | نیاز ندارد             | دارد یا یاد می‌گیرد                  |
| منبع تجربه        | تعامل واقعی            | تعامل واقعی و شبیه‌سازی              |
| Planning          | از مدل استفاده نمی‌کند | از مدل برای Planning استفاده می‌کند  |
| Sample Efficiency | ممکن است پایین‌تر باشد | در صورت دقت مدل می‌تواند بالاتر باشد |
| مشکل اصلی         | نیاز به تجربه زیاد     | خطای مدل                             |

### **مثال ساده**

فرض کن می‌خواهی یک بازی را یاد بگیری.

**Model-Free:**

```
Try Action
    |
    v
Observe Result
    |
    v
Update Q-Value
    |
    v
Try Again
```

**Model-Based:**

```
Interact with Environment
          |
          v
     Learn Model
          |
          v
  Simulate Possible Actions
          |
          v
        Planning
          |
          v
     Improve Policy
```

نکته مهم: Model-Based الزاماً به معنی داشتن مدل از قبل نیست. مدل می‌تواند از تجربه‌های Agent یاد گرفته شود.

## **۱۰. Environment Model**

برای اینکه Agent بتواند آینده را شبیه‌سازی کند، به یک Environment Model نیاز دارد.

در یک MDP، مدل معمولاً دو مؤلفه مهم دارد:

### **۱۰.۱. Transition Model**

تابع Transition مشخص می‌کند با انتخاب Action در یک State، احتمال رسیدن به State بعدی چقدر است.

\\[ P(s'|s,a) \\]

یعنی:

احتمال اینکه Agent از State فعلی \\(s\\)، با انتخاب Action برابر \\(a\\)، به State بعدی \\(s'\\) برسد.

### **۱۰.۲. Reward Model**

تابع Reward مشخص می‌کند با انجام یک Transition چه Rewardی دریافت می‌شود.

\\[ R(s,a,s') \\]

بنابراین، یک مدل کامل محیط می‌تواند شامل این دو مؤلفه باشد:

```
Environment Model
       |
       +-------------------+
       |                   |
       v                   v
Transition Model      Reward Model
       |                   |
       v                   v
Next State          Expected Reward
       |                   |
       +---------+---------+
                 |
                 v
          Planning
```

## **۱۱. Sampling Models و Distribution Models**

در متن ارسالی، به دو نوع مدل اشاره شده که باید تفاوت آن‌ها را دقیق بدانیم.

### **۱۱.۱. Sampling Model**

Sampling Model با دریافت State و Action، یک نمونه از نتیجه احتمالی محیط تولید می‌کند.

\\[ (s',r)\sim \hat{P}(\cdot,\cdot|s,a) \\]

مثلاً اگر Agent یک Action انجام دهد، مدل یک نتیجه ممکن را نمونه‌گیری می‌کند.

### **۱۱.۲. Distribution Model**

Distribution Model به‌جای تولید فقط یک نتیجه، توزیع احتمال نتایج ممکن را ارائه می‌دهد.

مثلاً:

```
Current State + Action
          |
          v
    Possible Outcomes
          |
      +---+---+
      |       |
      v       v
    Heads    Tails
      |       |
      0.5     0.5
```

### **مقایسه**

| ویژگی     | Sampling Model            | Distribution Model              |
| --------- | ------------------------- | ------------------------------- |
| خروجی     | یک نمونه                  | توزیع احتمالات                  |
| اطلاعات   | یک نتیجه احتمالی          | تمام نتایج مدل‌شده              |
| کاربرد    | شبیه‌سازی                 | محاسبه توزیعی و برنامه‌ریزی     |
| عدم قطعیت | از نمونه‌گیری مشخص می‌شود | به‌صورت توزیع نمایش داده می‌شود |

نکته: Distribution Model لزوماً از نظر واقعی دقیق‌تر نیست. فقط اطلاعات توزیعی بیشتری ارائه می‌کند؛ کیفیت آن همچنان به دقت مدل یادگرفته‌شده بستگی دارد.

## **۱۲. Dyna-Q**

Model-Based RL

Dyna-Q یکی از مهم‌ترین الگوریتم‌های این فصل است.

ایده اصلی آن ترکیب سه فعالیت در یک Agent است:

1. Interaction: تعامل با محیط واقعی.
2. Learning: یادگیری مدل محیط و به‌روزرسانی Q-Function.
3. Planning: استفاده از مدل یادگرفته‌شده برای شبیه‌سازی تجربه‌های جدید.

در Q-Learning معمولی، Agent برای یادگیری عمدتاً به تجربه‌هایی وابسته است که مستقیماً از Environment دریافت می‌کند.

اما در Dyna-Q، Agent علاوه بر تجربه واقعی، از تجربه‌های شبیه‌سازی‌شده توسط مدل خودش نیز استفاده می‌کند.

### **۱۲.۱. ساختار Dyna-Q**

```
                Real Environment
                       |
                       v
                  Interaction
                       |
                 (S, A, R, S')
                       |
             +---------+---------+
             |                   |
             v                   v
        Q-Learning          Model Learning
             |                   |
             v                   v
        Update Q-Table       Update Model
                                 |
                                 v
                              Planning
                                 |
                         Simulated Experience
                                 |
                                 v
                            Update Q-Table
```

نکته مهم این است که هر دو مسیر Real Experience و Simulated Experience می‌توانند Q-Function را بهبود دهند.

### **۱۲.۲. Dyna-Q چگونه کار می‌کند؟**

در هر مرحله، Agent ابتدا با محیط واقعی تعامل می‌کند.

مراحل:

**مرحله اول: انتخاب Action**

Agent با استفاده از Policy خود، Action انتخاب می‌کند.

**مرحله دوم: دریافت تجربه واقعی**

Environment اطلاعات زیر را ارائه می‌دهد:

\\[ (S_t,A_t,R\_{t+1},S\_{t+1}) \\]

**مرحله سوم: به‌روزرسانی Q-Function**

با استفاده از Q-Learning:

\\[ Q(S_t,A_t)\leftarrow Q(S_t,A_t) +\alpha\delta_t \\]

که در آن:

\\[ \delta_t = R\_{t+1} +\gamma\max_a Q(S\_{t+1},a) -Q(S_t,A_t) \\]

**مرحله چهارم: یادگیری مدل**

Agent اطلاعات مربوط به Transition را در مدل خود ذخیره می‌کند.

**مرحله پنجم: Planning**

Agent چند State-Action Pair را از مدل انتخاب می‌کند و با استفاده از مدل، تجربه‌های شبیه‌سازی‌شده تولید می‌کند.

**مرحله ششم: به‌روزرسانی مجدد Q-Function**

تجربه‌های شبیه‌سازی‌شده نیز برای اصلاح Q-Values استفاده می‌شوند.

### **۱۲.۳. Model در Dyna-Q چه اطلاعاتی نگهداری می‌کند؟**

در پیاده‌سازی مورد بحث کتاب، مدل از اطلاعات مربوط به Transitionها استفاده می‌کند.

برای مثال:

- State فعلی
- Action انتخاب‌شده
- State بعدی
- Reward حاصل از Transition

مدل برای ثبت Transitionهای مشاهده‌شده از ساختارهای داده چندبعدی (Tensors) استفاده می‌کند.

در پیاده‌سازی کتاب، اطلاعات احتمال Transition و Reward متوسط حاصل از Transitionها نگهداری می‌شوند.

به شکل مفهومی:

```
Model
  |
  +-- Transition Probabilities
  |       P(s' | s, a)
  |
  +-- Expected Rewards
          R(s, a, s')
```

چرا Reward متوسط اهمیت دارد؟

فرض کن Agent یک Transition مشخص را چندین بار تجربه کرده و هر بار Reward متفاوتی دریافت کرده است.

می‌توان از میانگین Rewardهای مشاهده‌شده برای تخمین Reward آن Transition استفاده کرد.

### **۱۲.۴. Planning در Dyna-Q**

Planning یعنی استفاده از مدل یادگرفته‌شده برای تولید تجربه‌های مصنوعی.

فرض کن Agent قبلاً این تجربه را داشته است:

```
S1 --Action A--> S2
Reward = +5
```

Agent می‌تواند این Transition را از مدل خود بازیابی کند و بدون مراجعه مجدد به محیط واقعی، از آن برای به‌روزرسانی Q-Function استفاده کند.

فرمول Update همچنان همان Q-Learning است:

\\[ Q(s,a)\leftarrow Q(s,a)+ \alpha \left[ r+\gamma\max\_{a'}Q(s',a')-Q(s,a) \right] \\]

تفاوت در این است که این بار \\(s,a,r,s'\\) از مدل به دست آمده‌اند، نه از تعامل جدید با Environment.

### **۱۲.۵. Planning Steps**

یکی از پارامترهای مهم Dyna-Q تعداد دفعات Planning در هر تعامل واقعی است.

به این تعداد معمولاً `n` یا `planning_steps` گفته می‌شود.

برای مثال:

```
One Real Interaction
        |
        v
   Update Model
        |
        v
   Planning Step 1
        |
        v
   Planning Step 2
        |
        v
   Planning Step 3
        |
        v
   Update Q-Function
```

هرچه تعداد Planning Steps بیشتر باشد، Agent می‌تواند از تجربه‌های شبیه‌سازی‌شده بیشتری استفاده کند.

اما افزایش آن هزینه محاسباتی بیشتری نیز دارد.

### **۱۲.۶. مزایای Dyna-Q**

- استفاده بهتر از تجربه‌های واقعی.
- یادگیری سریع‌تر در بسیاری از محیط‌ها.
- کاهش نیاز به تعامل مستقیم و مکرر با Environment.
- امکان بهبود Q-Function با Simulated Experience.
- ترکیب یادگیری و برنامه‌ریزی در یک الگوریتم.

### **۱۲.۷. محدودیت‌های Dyna-Q**

مهم‌ترین مشکل Dyna-Q وابستگی به دقت مدل است.

اگر مدل اشتباه باشد، Agent ممکن است از تجربه‌های شبیه‌سازی‌شده اشتباه یاد بگیرد.

مثلاً:

```
Real Environment:
S1 → S2 → Reward +5

Incorrect Model:
S1 → S3 → Reward +10
```

اگر Agent بارها از مدل اشتباه استفاده کند، Q-Values آن نیز ممکن است به‌سمت نتایج اشتباه منحرف شوند.

این موضوع به‌خصوص در محیط‌های Dynamic که قوانین یا Transitionها تغییر می‌کنند اهمیت دارد.

## **۱۳. Trajectory Sampling**

Model-Based Planning

Trajectory Sampling روش دیگری برای Planning در Model-Based RL است که در این فصل معرفی می‌شود.

تفاوت اصلی آن با Dyna-Q در نحوه انتخاب Stateها و Actionهایی است که برای Planning استفاده می‌شوند.

### **۱۳.۱. مشکل روش Planning در Dyna-Q**

در Dyna-Q، Planning معمولاً با انتخاب تصادفی State-Action Pairهای مشاهده‌شده انجام می‌شود.

به بیان دیگر، Agent ممکن است یک State را برای Planning انتخاب کند که ارتباط مستقیمی با State فعلی یا مسیر احتمالی رسیدن به هدف نداشته باشد.

مثال:

```
Dyna-Q Planning:

Random State-Action Pair
          |
          v
    Simulate Transition
          |
          v
       Update Q
```

این روش از تمام بخش‌های مدل فرصت یادگیری ایجاد می‌کند، اما لزوماً روی تجربه‌هایی که برای رفتار فعلی Agent مهم‌تر هستند تمرکز نمی‌کند.

### **۱۳.۲. ایده اصلی Trajectory Sampling**

در Trajectory Sampling، به‌جای انتخاب تصادفی Stateها، Agent یک مسیر شبیه‌سازی‌شده را از State فعلی خود آغاز می‌کند.

سپس با استفاده از Policy فعلی، Action انتخاب می‌کند و Transitionهای احتمالی را از مدل دریافت می‌کند.

این روند چند مرحله ادامه پیدا می‌کند.

```
Current State
      |
      v
Select Action using Current Policy
      |
      v
Sample Next State from Model
      |
      v
Select Next Action
      |
      v
Sample Another Transition
      |
      v
Continue for a Limited Depth
```

به این ترتیب، Agent مسیرهایی را بررسی می‌کند که با رفتار فعلی و Policy یادگرفته‌شده آن ارتباط دارند.

### **۱۳.۳. مثال**

فرض کن Agent در یک بازی در State شماره ۳ قرار دارد و هدف رسیدن به State شماره ۸ است.

```
S3 → S4 → S5 → S6 → S7 → S8
                                  |
                               Reward +1
```

در Trajectory Sampling:

1. Agent از S3 شروع می‌کند.
2. با Policy فعلی، Action مناسب را انتخاب می‌کند.
3. مدل محیط State بعدی را شبیه‌سازی می‌کند.
4. این روند تا رسیدن به حداکثر عمق تعیین‌شده ادامه پیدا می‌کند.
5. تجربه‌های شبیه‌سازی‌شده برای بهبود Value Function استفاده می‌شوند.

بنابراین، Agent به‌جای نمونه‌گیری تصادفی از کل مدل، روی مسیرهای محتمل آینده تمرکز می‌کند.

### **۱۳.۴. Max Core Trajectory Depth**

در کد کتاب، پارامتری با نام `max_core_trajectory_depth` مطرح می‌شود.

این پارامتر حداکثر طول مسیر شبیه‌سازی‌شده را مشخص می‌کند.

به بیان ساده:

- Depth کوچک: بررسی تعداد کمتری از مراحل آینده.
- Depth بزرگ: بررسی مراحل بیشتری از آینده.

مثلاً:

```
Depth = 2

S1 → S2 → S3

Depth = 5

S1 → S2 → S3 → S4 → S5 → S6
```

افزایش Depth باعث می‌شود اطلاعات بیشتری از آینده وارد Planning شود، اما هزینه محاسباتی نیز افزایش پیدا می‌کند.

### **۱۳.۵. مزایای Trajectory Sampling**

- تمرکز روی Stateهای مرتبط با وضعیت فعلی Agent.
- استفاده هدفمندتر از مدل محیط.
- تمرکز بیشتر روی مسیرهای منتهی به Goal.
- امکان کاهش اتلاف Planning روی Stateهای کم‌ارتباط.
- استفاده مؤثر از اطلاعات Policy فعلی.

### **۱۳.۶. محدودیت‌های Trajectory Sampling**

این روش نیز محدودیت‌هایی دارد:

- ممکن است تمام State-Action Pairها بررسی نشوند.
- ممکن است مسیرهای مهمی که Policy فعلی هنوز کشف نکرده، نادیده گرفته شوند.
- به دقت مدل محیط وابسته است.
- نتایج آن به Policy فعلی و عمق شبیه‌سازی وابسته هستند.

بنابراین، اگر Policy فعلی اطلاعات کافی نداشته باشد، Trajectory Sampling نیز ممکن است مسیرهای ارزشمند را از دست بدهد.

## **۱۴. تفاوت Dyna-Q و Trajectory Sampling**

این دو روش هر دو Model-Based هستند و از مدل یادگرفته‌شده برای Planning استفاده می‌کنند.

اما تفاوت آن‌ها در استراتژی انتخاب تجربه‌های شبیه‌سازی‌شده است.

| ویژگی           | Dyna-Q                              | Trajectory Sampling                  |
| --------------- | ----------------------------------- | ------------------------------------ |
| نوع             | Model-Based                         | Model-Based                          |
| مدل محیط        | دارد                                | دارد                                 |
| انتخاب State    | تصادفی از Stateهای مشاهده‌شده       | شروع از State فعلی                   |
| انتخاب Action   | تصادفی در Planning                  | طبق Policy فعلی                      |
| ساختار Planning | نمونه‌گیری مستقل                    | شبیه‌سازی یک مسیر                    |
| تمرکز           | تجربه‌های مختلف مدل                 | مسیرهای محتمل آینده                  |
| مزیت            | پوشش عمومی‌تر مدل                   | تمرکز روی مسیرهای مرتبط              |
| محدودیت         | اتلاف Planning روی Pairهای کم‌اهمیت | احتمال نادیده‌گرفتن مسیرهای کشف‌نشده |

## **۱۹. نکات مهم و اشتباهات رایج**

1. λ با α تفاوت دارد. λ میزان ترکیب Returnهای چندمرحله‌ای را کنترل می‌کند، اما α میزان تغییر Value Function را مشخص می‌کند.
2. λ=0 در SARSA(λ) معادل SARSA معمولی است.
3. λ-Return ترکیبی از N-Step Returnهای مختلف است.
4. Eligibility Traces مشخص می‌کنند TD Error چگونه روی تجربه‌های قبلی اثر بگذارد.
5. Accumulating Traces با بازدید مجدد افزایش پیدا می‌کنند و می‌توانند از یک بیشتر شوند.
6. Replacing Traces هنگام بازدید مجدد، مقدار Trace را به یک تنظیم می‌کنند.
7. SARSA(λ) یک روش On-Policy است.
8. Watkins's Q(λ) یک روش Off-Policy است.
9. Watkins's Q(λ) هنگام انتخاب Action غیرحریصانه، Eligibility Traces را پاک می‌کند.
10. Model-Free برای یادگیری به مدل صریح محیط نیاز ندارد.
11. Model-Based از مدل محیط برای شبیه‌سازی و Planning استفاده می‌کند.
12. Dyna-Q هم از تجربه واقعی و هم از تجربه شبیه‌سازی‌شده استفاده می‌کند.
13. Dyna-Q برای Planning از نمونه‌گیری State-Action Pairهای مشاهده‌شده استفاده می‌کند.
14. Trajectory Sampling از State فعلی شروع می‌کند و مسیر را با Policy فعلی ادامه می‌دهد.
15. افزایش Planning Steps یا Trajectory Depth می‌تواند هزینه محاسباتی را افزایش دهد.
16. مدل اشتباه می‌تواند باعث یادگیری اشتباه و به‌روزرسانی نامناسب Q-Values شود.
