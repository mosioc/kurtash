# **خلاصهٔ جامع فصل چهارم کتاب Grokking Deep Reinforcement Learning**

**Chapter 4: Balancing the Gathering and Use of Information**

موضوع اصلی این فصل، یکی از مهم‌ترین چالش‌های Reinforcement Learning است: عامل (Agent) چگونه میان جمع‌آوری اطلاعات جدید (Exploration) و استفاده از دانش فعلی برای دریافت پاداش (Exploitation) تعادل برقرار کند؟

برای بررسی این مسئله، ابتدا با Multi-Armed Bandit آشنا می‌شویم و سپس الگوریتم‌های مختلف Exploration را بررسی می‌کنیم؛ از روش‌های ساده‌ای مانند Greedy و Epsilon-Greedy گرفته تا روش‌های پیشرفته‌تری مانند Softmax، UCB و Thompson Sampling.

## **۱. مسئلهٔ اصلی فصل: Exploration vs. Exploitation**

یکی از بنیادی‌ترین چالش‌های Reinforcement Learning این است که Agent باید تصمیم بگیرد چه زمانی از دانش فعلی خود استفاده کند و چه زمانی برای به‌دست‌آوردن اطلاعات جدید، اقداماتی را امتحان کند که هنوز دربارهٔ آن‌ها اطلاعات کافی ندارد.

این مسئله را **Exploration–Exploitation Dilemma** می‌نامیم.

### **۱.۱. Exploration (اکتشاف)**

Exploration یعنی Agent اقداماتی را امتحان کند تا دربارهٔ محیط اطلاعات بیشتری به دست آورد.

برای مثال، فرض کن یک Agent سه انتخاب دارد و هنوز نمی‌داند کدام‌یک بیشترین Reward را تولید می‌کند. اگر همیشه گزینه‌ای را انتخاب کند که تاکنون بهترین نتیجه را داده، ممکن است هرگز متوجه نشود که گزینهٔ دیگری در واقع بهتر است.

اهداف Exploration:

- کشف گزینه‌های بهتر
- کاهش عدم‌قطعیت دربارهٔ Rewardها
- بهبود تخمین Action Valueها
- جمع‌آوری اطلاعات برای تصمیم‌گیری‌های آینده

### **۱.۲. Exploitation (بهره‌برداری)**

Exploitation یعنی Agent از اطلاعات و تجربه‌های قبلی خود استفاده کند و اقدامی را انتخاب کند که طبق تخمین فعلی، بیشترین Reward را دارد.

مثلاً اگر Agent تخمین زده باشد:

| Action | Estimated Value |
| ------ | --------------- |
| A      | 2               |
| B      | 5               |
| C      | 3               |

در حالت Exploitation، گزینهٔ B را انتخاب می‌کند.

هدف Exploitation، استفاده از دانش موجود برای کسب بیشترین پاداش است.

### **۱.۳. تعارض Exploration و Exploitation**

مشکل اینجاست که این دو هدف همیشه با یکدیگر سازگار نیستند.

- اگر Agent بیش از حد Explore کند، زمان زیادی را صرف انتخاب اقداماتی می‌کند که ممکن است Reward کمتری داشته باشند.
- اگر بیش از حد Exploit کند، ممکن است فرصت کشف اقدام بهتر را از دست بدهد.

بنابراین Agent باید میان این دو تعادل برقرار کند.

### **رابطهٔ مفهومی Exploration و Exploitation**

```
                Agent
                  |
        Current Knowledge
                  |
          Decision Making
                  |
          +-------+-------+
          |               |
     Exploration      Exploitation
          |               |
    Try new Actions   Choose best-known
          |               |
    Gather Information  Obtain Reward
          |               |
    Reduce Uncertainty   Use Current Knowledge
          |               |
          +-------+-------+
                  |
          Better Decisions
```

### Exploration (اکتشاف)

- هدف: کسب اطلاعات جدید
- کاربرد: یادگیری دربارهٔ گزینه‌های ناشناخته
- نتیجه: کاهش عدم‌قطعیت دربارهٔ محیط و Actionها

### Exploitation (بهره‌برداری)

- هدف: کسب پاداش
- کاربرد: استفاده از دانش و تجربهٔ فعلی برای انتخاب بهترین Action تخمینی
- نتیجه: استفاده از اطلاعات موجود برای دریافت Reward بیشتر

هدف، ایجاد تعادل میان Exploration و Exploitation متناسب با میزان اطلاعات و شرایط محیط است.

**مثال روزمره:** فرض کن در یک رستوران غذای موردعلاقه‌ات را می‌شناسی. سفارش دوبارهٔ آن Exploitation است؛ امتحان‌کردن غذای جدید Exploration است. غذای جدید ممکن است بهتر باشد، اما برای فهمیدن آن باید ریسک کنی و اطلاعات جمع‌آوری کنی.

نکتهٔ مهم: Exploration هدف نهایی نیست؛ هدف آن فراهم‌کردن اطلاعات لازم برای Exploitation مؤثرتر است.

## **۲. The Challenge of Interpreting Evaluative Feedback**

این عنوان، بخش اول فصل است.

### **۲.۱. Evaluative Feedback چیست؟**

در Reinforcement Learning، Agent معمولاً تمام جزئیات محیط و پیامدهای هر Action را از ابتدا نمی‌داند. در عوض، اقدام می‌کند و سپس از محیط Reward دریافت می‌کند.

این Reward نوعی **Evaluative Feedback** است؛ یعنی بازخوردی که به Agent می‌گوید نتیجهٔ اقدامش چقدر خوب یا بد بوده است.

اما یک مشکل اساسی وجود دارد:

دریافت Reward مثبت لزوماً به این معنی نیست که بهترین Action ممکن را انتخاب کرده‌ایم.

مثلاً:

- انتخاب A، پاداش ۵ تولید کرده است.
- انتخاب B، پاداش ۳ تولید کرده است.

آیا A قطعاً بهتر از B است؟ خیر. ممکن است Reward مورد انتظار B بیشتر باشد، اما Agent هنوز به‌اندازهٔ کافی آن را امتحان نکرده باشد.

بنابراین Agent نمی‌تواند فقط بر اساس Rewardهای مشاهده‌شده دربارهٔ کیفیت واقعی اقدامات قضاوت قطعی کند.

### **۲.۲. تفاوت Evaluative Feedback و مدل کامل محیط**

اگر Agent مدل محیط را از ابتدا بداند، ممکن است بتواند با استفاده از Transition Function و Reward Function پیامد اقدامات را پیش‌بینی کند.

اما در یادگیری مبتنی بر تجربه، Agent این اطلاعات را به‌طور کامل ندارد و باید از تعامل با محیط یاد بگیرد.

این وضعیت باعث ایجاد عدم‌قطعیت می‌شود.

**نکتهٔ کلیدی:** Agent از Reward یاد می‌گیرد، اما Reward به‌تنهایی مشخص نمی‌کند که بهترین اقدام ممکن چه بوده است.

## **۳. Multi-Armed Bandits (MAB)**

برای بررسی Exploration و Exploitation، کتاب از مسئله‌ای به نام Multi-Armed Bandit استفاده می‌کند.

### **۳.۱. تعریف Multi-Armed Bandit**

Multi-Armed Bandit یک مسئلهٔ تصمیم‌گیری است که در آن Agent از میان چند Action انتخاب می‌کند و هر Action دارای یک توزیع Reward ناشناخته است.

نام این مسئله از دستگاه‌های قمار چنداهرم‌دار گرفته شده است.

تصور کن دستگاهی با چند اهرم وجود دارد. هر اهرم احتمال متفاوتی برای پرداخت جایزه دارد، اما تو این احتمالات را نمی‌دانی.

وظیفهٔ تو این است که با امتحان‌کردن اهرم‌ها، بهترین گزینه را پیدا کنی.

### **ساختار مفهومی Multi-Armed Bandit**

```
                   Agent
                     |
              Select an Action
                     |
          +----------+----------+
          |          |          |
       Action A   Action B   Action C
          |          |          |
          v          v          v
      Reward A   Reward B   Reward C
          |          |          |
          +----------+----------+
                     |
                Observe Reward
                     |
              Update Action Value
                     |
              Select Next Action
```

این نمودار نشان می‌دهد که Agent با انتخاب Action، دریافت Reward و به‌روزرسانی تخمین خود، به‌تدریج دربارهٔ گزینه‌ها اطلاعات جمع‌آوری می‌کند.

### **۳.۲. ویژگی‌های اصلی MAB**

یک Multi-Armed Bandit ساده دارای ویژگی‌های زیر است:

- فقط یک State دارد.
- چند Action مختلف دارد.
- Agent در هر مرحله یکی از Actionها را انتخاب می‌کند.
- محیط پس از انتخاب Action، Reward تولید می‌کند.
- Agent از Rewardهای مشاهده‌شده برای تخمین ارزش Actionها استفاده می‌کند.

### **۳.۳. تفاوت MAB و MDP**

| ویژگی         | Multi-Armed Bandit             | MDP                                 |
| ------------- | ------------------------------ | ----------------------------------- |
| تعداد Stateها | یک State                       | یک یا چند State                     |
| Actionها      | چند انتخاب                     | چند انتخاب در هر State              |
| Transition    | معمولاً بدون تغییر State       | انتقال بین Stateها                  |
| Horizon       | معمولاً یک تصمیم در هر Episode | می‌تواند چندین Time Step داشته باشد |
| مسئلهٔ اصلی   | انتخاب بهترین Action           | انتخاب دنباله‌ای از Actionها        |

در MAB، هر تصمیم معمولاً شامل انتخاب یک Action و دریافت یک Reward است. برخلاف MDPهای معمول، مسئلهٔ اصلی این نیست که Agent چگونه در Stateهای مختلف حرکت کند؛ بلکه این است که چگونه ارزش گزینه‌های موجود را تخمین بزند و بهترین گزینه را پیدا کند.

### **۳.۴. Action Value در MAB**

برای هر Action، یک مقدار تخمینی داریم که نشان می‌دهد انتظار داریم انتخاب آن Action چه Rewardی تولید کند.

این مقدار را Action Value می‌نامیم.

\\[ Q(a)=\mathbb{E}[R\mid A=a] \\]

در این رابطه:

- \\(Q(a)\\): ارزش مورد انتظار Action
- \\(R\\): Reward
- \\(A=a\\): انتخاب Action موردنظر
- \\(\mathbb{E}\\): Expected Value یا امید ریاضی

در عمل، Agent مقدار واقعی \\(Q(a)\\) را نمی‌داند و باید آن را از تجربه تخمین بزند.

### **۳.۵. تخمین Action Value با Sample Average**

یکی از روش‌های ساده برای تخمین ارزش یک Action، میانگین Rewardهایی است که تاکنون از انتخاب آن Action دریافت کرده‌ایم.

\\[ Q_n(a)=\frac{1}{n}\sum\_{i=1}^{n}R_i \\]

در این رابطه:

- \\(Q_n(a)\\): تخمین ارزش Action پس از \\(n\\) بار انتخاب
- \\(n\\): تعداد دفعات انتخاب Action
- \\(R_i\\): Reward مشاهده‌شده در تجربهٔ شمارهٔ \\(i\\)

**مثال:**

فرض کن Action A سه بار انتخاب شده و Rewardهای زیر را تولید کرده است:

\\[ R=[2,4,6] \\]

در نتیجه:

\\[ Q(A)=\frac{2+4+6}{3}=4 \\]

بنابراین تخمین Agent از ارزش Action A برابر ۴ است.

### **۳.۶. Incremental Update**

به‌جای محاسبهٔ مجدد تمام میانگین‌ها، می‌توان Action Value را به‌صورت تدریجی به‌روزرسانی کرد.

\\[ Q\_{n+1}(a)=Q_n(a)+\frac{1}{n+1}[R\_{n+1}-Q_n(a)] \\]

فرم عمومی‌تر این رابطه:

\\[ Q\_{\text{new}}=Q\_{\text{old}}+\alpha(R-Q\_{\text{old}}) \\]

که در آن:

- \\(\alpha\\): Learning Rate
- \\(R\\): Reward جدید
- \\(Q\_{\text{old}}\\): تخمین قبلی

در Sample Average، مقدار Learning Rate به تعداد دفعات انتخاب Action وابسته است؛ یعنی برای به‌روزرسانی پس از دریافت Reward شمارهٔ \\(n+1\\)، نرخ یادگیری برابر \\(1/(n+1)\\) است.

## **۴. Regret: The Cost of Exploration**

یکی از مفاهیم مهم این فصل Regret است.

### **۴.۱. تعریف Regret**

Regret میزان هزینه یا فرصت ازدست‌رفته‌ای است که به‌دلیل انتخاب یک Action غیربهینه ایجاد می‌شود.

به زبان ساده، Regret نشان می‌دهد Agent به‌خاطر انتخاب‌هایی که انجام داده، چه مقدار Reward را نسبت به انتخاب همیشگی بهترین Action از دست داده است.

اگر بهترین Action دارای ارزش واقعی \\(Q^\\\*\\) باشد و Agent در زمان \\(t\\)، اقدام \\(A_t\\) را انتخاب کند:

\\[ r_t=Q^\\\*-Q(A_t) \\]

این مقدار، Regret مورد انتظار در آن مرحله است.

Regret تجمعی:

\\[ R_T=\sum\_{t=1}^{T}[Q^\\\*-Q(A_t)] \\]

در این رابطه:

- \\(Q^\\\*\\): ارزش واقعی بهترین Action
- \\(Q(A_t)\\): ارزش واقعی Action انتخاب‌شده
- \\(r_t\\): Regret در یک مرحله
- \\(R_T\\): Total Cumulative Regret تا زمان \\(T\\)

توجه کن که در این فرمول، منظور از \\(Q(A_t)\\) ارزش واقعی مورد انتظار Action انتخاب‌شده است، نه الزاماً Reward تصادفی مشاهده‌شده در آن مرحله.

### **۴.۲. چرا Exploration باعث Regret می‌شود؟**

فرض کن بهترین Action دارای Reward مورد انتظار ۱۰ است.

Agent برای کشف گزینه‌های دیگر، Actionی را انتخاب می‌کند که Reward مورد انتظار آن ۶ است.

در این مرحله:

\\[ Regret=10-6=4 \\]

اگر Agent این انتخاب را چندین بار تکرار کند، Regret تجمعی افزایش پیدا می‌کند.

اما این به معنی بدبودن Exploration نیست؛ زیرا ممکن است این تجربه‌ها در آینده به کشف Action بهتری منجر شوند.

### **۴.۳. هدف الگوریتم‌های Exploration**

هدف این نیست که Agent هیچ‌وقت Regret نداشته باشد؛ بلکه باید در طول زمان، Regret را تا حد ممکن کاهش دهد.

به همین دلیل، الگوریتم‌های Exploration باید بین دو موضوع تعادل ایجاد کنند:

1. کسب اطلاعات جدید (Exploration)
2. جلوگیری از انتخاب‌های غیربهینهٔ بیش از حد (Regret Reduction)

### **مثال مفهومی Regret**

فرض کن بهترین Action همیشه Reward مورد انتظار ۱۰ دارد.

| Action | Reward مورد انتظار | Regret |
| ------ | ------------------ | ------ |
| A      | 10                 | 0      |
| B      | 7                  | 3      |
| C      | 4                  | 6      |

فرمول محاسبه:

```
Regret = Optimal Expected Reward - Selected Action's Expected Reward
```

مثلاً برای Action B:

```
Regret = 10 - 7 = 3
```

اعداد صرفاً مثال آموزشی هستند؛ بهترین Action در این مثال A است.

## **۵. Approaches to Solving MAB Environments**

برای حل Multi-Armed Bandit چند رویکرد مختلف وجود دارد.

در این فصل، ابتدا روش‌های ساده بررسی می‌شوند و سپس الگوریتم‌هایی معرفی می‌شوند که به شکل هوشمندانه‌تری Exploration را مدیریت می‌کنند.

سه رویکرد پایه‌ای برای درک مسئله:

1. Greedy: فقط بهره‌برداری
2. Random: فقط اکتشاف
3. ترکیب Exploration و Exploitation، مانند Epsilon-Greedy

سپس روش‌های مبتنی بر تخمین و عدم‌قطعیت بررسی می‌شوند.

### **۵.۱. Greedy: Always Exploit**

در روش Greedy، Agent همیشه Actionی را انتخاب می‌کند که بالاترین Action Value تخمینی را دارد.

\\[ A_t=\arg\max_a Q_t(a) \\]

مثلاً:

| Action | Estimated Value |
| ------ | --------------- |
| A      | 4               |
| B      | 7               |
| C      | 5               |

Agent همیشه Action B را انتخاب می‌کند.

**مزایا:**

- ساده و سریع
- استفاده از بهترین دانش موجود
- عدم نیاز به پارامتر Exploration

**معایب:**

- ممکن است خیلی زود به یک Action وابسته شود.
- گزینه‌های ناشناخته را بررسی نمی‌کند.
- ممکن است در یک جواب غیربهینه گیر کند.

مثلاً اگر Action B در ابتدا Reward خوبی داشته باشد، Agent ممکن است آن را دائماً انتخاب کند، حتی اگر Action A در واقع بهتر باشد.

این مشکل را می‌توان با مفهوم Premature Convergence یا همگرایی زودهنگام توصیف کرد.

### **۵.۲. Random: Always Explore**

در روش Random، Agent بدون توجه به تخمین Action Value، به‌صورت تصادفی Action انتخاب می‌کند.

\\[ P(A_t=a)=\frac{1}{|\mathcal{A}|} \\]

یعنی احتمال انتخاب هر Action یکسان است.

مثلاً اگر سه Action داشته باشیم:

\\[ P(A)=P(B)=P(C)=\frac{1}{3} \\]

**مزایا:**

- تمام Actionها فرصت انتخاب دارند.
- به تخمین‌های اولیه وابسته نیست.
- احتمال کشف گزینه‌های ناشناخته وجود دارد.

**معایب:**

- از دانش قبلی استفاده نمی‌کند.
- حتی پس از شناسایی بهترین Action هم تصادفی انتخاب می‌کند.
- ممکن است Regret زیادی تولید کند.

**نتیجه:** Greedy و Random دو نقطهٔ مقابل یکدیگر هستند؛ یکی فقط از دانش فعلی استفاده می‌کند و دیگری تقریباً آن را نادیده می‌گیرد.

## **۶. Epsilon-Greedy**

یکی از معروف‌ترین روش‌های Exploration در Reinforcement Learning است.

### **۶.۱. ایدهٔ اصلی**

Epsilon-Greedy ترکیبی از Greedy و Random است.

Agent در بیشتر مواقع بهترین Action تخمینی را انتخاب می‌کند، اما گاهی نیز به‌صورت تصادفی یک Action انتخاب می‌کند.

پارامتر اصلی این الگوریتم:

\\[ \epsilon\in[0,1] \\]

که Epsilon نام دارد.

قانون انتخاب Action:

- با احتمال \\(1-\epsilon\\): انتخاب Greedy Action
- با احتمال \\(\epsilon\\): انتخاب تصادفی Action

### **ساختار تصمیم‌گیری Epsilon-Greedy**

```
                Start
                  |
           Generate Random
              Number
                  |
             Is random
             < epsilon?
              /     \
            Yes      No
             |        |
             v        v
        Random     Greedy
        Action     Action
             |        |
             +---+----+
                 |
             Observe
              Reward
                 |
          Update Q-Value
                 |
              Repeat
```

### **۶.۲. فرمول Epsilon-Greedy**

\\[ A_t= \begin{cases} \text{Random Action} & \text{with probability }\epsilon\\\ \arg\max_a Q_t(a) & \text{with probability }1-\epsilon \end{cases} \\]

**مثال:**

فرض کن:

\\[ \epsilon=0.1 \\]

در نتیجه:

- ۹۰ درصد مواقع Agent به‌صورت Greedy عمل می‌کند.
- ۱۰ درصد مواقع Agent وارد مرحلهٔ Random Selection می‌شود.

### **۶.۳. نکتهٔ مهم دربارهٔ Epsilon**

یک اشتباه رایج این است که تصور کنیم اگر \\(\epsilon=0.5\\) باشد، Agent دقیقاً ۵۰ درصد مواقع Action غیربهینه انتخاب می‌کند.

این برداشت صحیح نیست.

در مرحلهٔ Exploration، Agent از میان تمام Actionها به‌صورت تصادفی انتخاب می‌کند؛ بنابراین ممکن است همان Action Greedy نیز انتخاب شود.

اگر \\(k\\) تعداد Actionها باشد و فقط یک Action را Greedy در نظر بگیریم، در حالت بدون Tie:

\\[ P(\text{Non-greedy})= \epsilon\left(1-\frac{1}{k}\right) \\]

برای مثال، اگر دو Action داشته باشیم و \\(\epsilon=0.5\\) باشد:

\\[ P(\text{Non-greedy})=0.5(1-0.5)=0.25 \\]

پس احتمال انتخاب Action غیربهینه برابر ۲۵ درصد است، نه ۵۰ درصد.

### **۶.۴. انتخاب مقدار مناسب Epsilon**

- Epsilon بزرگ: Exploration بیشتر
- Epsilon کوچک: Exploitation بیشتر
- Epsilon برابر صفر: رفتار Greedy
- Epsilon برابر یک: انتخاب تصادفی (Random)

مقدار Epsilon باید متناسب با مسئله و میزان اطلاعات Agent تنظیم شود.

## **۷. Decaying Epsilon-Greedy**

یکی از مشکلات Epsilon-Greedy ثابت این است که مقدار Exploration در طول زمان تغییر نمی‌کند.

اما معمولاً Agent در ابتدای یادگیری اطلاعات کمی دارد و باید بیشتر Explore کند. پس از کسب تجربه، می‌تواند بیشتر Exploit کند.

اینجاست که Decaying Epsilon-Greedy مطرح می‌شود.

### **۷.۱. ایدهٔ اصلی**

در این روش مقدار Epsilon به‌تدریج کاهش می‌یابد.

\\[ \epsilon_t\downarrow \\]

در ابتدای آموزش:

- Exploration زیاد است.
- Agent گزینه‌های مختلف را امتحان می‌کند.

در ادامه:

- Exploration کمتر می‌شود.
- Agent بیشتر از اطلاعات جمع‌آوری‌شده استفاده می‌کند.

### **۷.۲. Linear Decay**

در کاهش خطی، Epsilon با نرخ ثابت کاهش می‌یابد.

یک فرمول رایج:

\\[ \epsilon_t=\max(\epsilon\_{\min},\epsilon_0-kt) \\]

که در آن:

- \\(\epsilon_0\\): مقدار اولیه
- \\(k\\): نرخ کاهش
- \\(\epsilon\_{\min}\\): حداقل مقدار مجاز
- \\(t\\): زمان یا شمارهٔ Episode

**مثال:**

فرض کن:

\\[ \epsilon_0=1 \\]

\\[ \epsilon\_{\min}=0.1 \\]

با گذشت زمان، مقدار Epsilon به‌صورت خطی کاهش می‌یابد و پس از رسیدن به ۰.۱ در همان مقدار باقی می‌ماند.

### **۷.۳. Exponential Decay**

در کاهش نمایی، مقدار Epsilon به‌صورت نمایی کاهش می‌یابد.

\\[ \epsilon_t=\max(\epsilon\_{\min},\epsilon_0e^{-kt}) \\]

در این رابطه:

- \\(e\\): عدد نپر
- \\(k\\): نرخ کاهش
- \\(t\\): زمان

در این روش، کاهش Epsilon در ابتدا سریع‌تر است و سپس به‌تدریج آهسته‌تر می‌شود.

### **مقایسهٔ Linear و Exponential Epsilon Decay**

در روش Linear Decay، مقدار Epsilon با نرخ ثابت کاهش می‌یابد.

در روش Exponential Decay، مقدار Epsilon در ابتدا سریع‌تر کاهش پیدا می‌کند و سپس به‌تدریج آهسته‌تر می‌شود.

**Linear Decay:**

```
Epsilon
  1.0 |\
      | \
      |  \
      |   \
      |    \
      |     \
  0.1 |______\____________
      |
      +--------------------> Time
```

**Exponential Decay:**

```
Epsilon
  1.0 |\
      | \
      |  \
      |   \__
      |      \____
      |           \____
  0.1 |____________________
      |
      +--------------------> Time
```

این نمودارها شماتیک هستند و شکل دقیق منحنی به پارامترهای کاهش بستگی دارد.

### **فرمول‌ها**

Linear Decay:

```
ε(t) = max(ε_min, ε_0 - k × t)
```

ویژگی‌ها:

- کاهش با نرخ ثابت
- قابل پیش‌بینی بودن روند کاهش
- کنترل سادهٔ میزان Exploration

Exponential Decay:

```
ε(t) = max(ε_min, ε_0 × e^(-k × t))
```

ویژگی‌ها:

- کاهش سریع‌تر در ابتدای یادگیری
- کاهش آهسته‌تر در ادامه
- نزدیک‌شدن تدریجی به حداقل Epsilon

### **مقایسهٔ نمونه**

| Episode | Linear Decay | Exponential Decay |
| ------- | ------------ | ----------------- |
| ۰       | ۱٫۰۰         | ۱٫۰۰              |
| ۱       | ۰٫۹۰         | ۰٫۷۴              |
| ۲       | ۰٫۸۰         | ۰٫۵۵              |
| ۳       | ۰٫۷۰         | ۰٫۴۱              |
| ۴       | ۰٫۶۰         | ۰٫۳۰              |
| ۵       | ۰٫۵۰         | ۰٫۲۲              |
| ۶       | ۰٫۴۰         | ۰٫۱۷              |
| ۷       | ۰٫۳۰         | ۰٫۱۳              |
| ۸       | ۰٫۲۰         | ۰٫۱۰              |
| ۹       | ۰٫۱۰         | ۰٫۱۰              |

این اعداد یک مثال نمایشی هستند و شکل واقعی نمودار به پارامترهای کاهش بستگی دارد.

### **۷.۴. مزایا و محدودیت‌ها**

**مزایا:**

- Exploration در ابتدای آموزش بیشتر است.
- در ادامه Agent به سمت Exploitation می‌رود.
- پیاده‌سازی ساده‌ای دارد.

**محدودیت‌ها:**

- انتخاب نرخ کاهش مناسب اهمیت زیادی دارد.
- کاهش سریع ممکن است باعث شود Agent گزینه‌های بهتر را کشف نکند.
- کاهش بیش از حد Epsilon ممکن است Exploration را تقریباً متوقف کند.

نکته: کاهش Epsilon لزوماً به معنی بهترشدن تخمین‌ها نیست؛ فقط احتمال انتخاب تصادفی را تغییر می‌دهد.

## **۸. Optimistic Initialization**

### **۸.۱. ایدهٔ اصلی**

Optimistic Initialization یک روش ساده برای تشویق Exploration است.

در این روش، Agent در ابتدای کار Action Valueها را با مقادیر خوش‌بینانه و نسبتاً بزرگ مقداردهی می‌کند.

یعنی فرض می‌کند تمام Actionها در ابتدا پتانسیل بالایی دارند.

چرا این کار باعث Exploration می‌شود؟

چون Agent در ابتدا اطلاعات واقعی ندارد. اگر مقدار تخمینی تمام Actionها بالا باشد، پس از انتخاب و دریافت Reward، ارزش تخمینی آن Action ممکن است کاهش پیدا کند.

در نتیجه Actionهای دیگری که هنوز امتحان نشده‌اند، همچنان مقدار تخمینی بالایی خواهند داشت و احتمال انتخاب آن‌ها بیشتر می‌شود.

### **۸.۲. مثال**

فرض کن سه Action داریم:

| Action | مقدار اولیه |
| ------ | ----------- |
| A      | 10          |
| B      | 10          |
| C      | 10          |

Agent ابتدا A را انتخاب می‌کند و Reward برابر ۳ دریافت می‌کند.

با فرض استفاده از به‌روزرسانی Sample Average و یک مشاهده، تخمین A برابر ۳ می‌شود:

\\[ Q(A)=3 \\]

اما تخمین B و C همچنان ۱۰ است.

بنابراین Agent به‌احتمال زیاد سراغ B یا C می‌رود.

### **روند Optimistic Initialization**

```
Initial Q-Values
       |
       v
+------+------+------+
| Q(A) | Q(B) | Q(C) |
|  10  |  10  |  10  |
+------+------+------+
       |
       v
   Select A
       |
       v
   Observe R = 3
       |
       v
   Update Q(A)
       |
       v
+------+------+------+
| Q(A) | Q(B) | Q(C) |
|   3  |  10  |  10  |
+------+------+------+
       |
       v
 Select B or C
```

به این ترتیب، مقداردهی اولیهٔ خوش‌بینانه می‌تواند Exploration ایجاد کند.

### **۸.۳. مزایا**

- ساده و قابل پیاده‌سازی
- بدون نیاز به Random Exploration دائمی
- تشویق Agent به امتحان‌کردن Actionهای مختلف

### **۸.۴. محدودیت‌ها**

- به مقداردهی اولیه وابسته است.
- اگر مقادیر اولیه بیش از حد بزرگ باشند، یادگیری ممکن است نامتوازن شود.
- در محیط‌های Non-stationary یا محیط‌هایی که ارزش Actionها تغییر می‌کند، به‌تنهایی راهکار کاملی نیست.

**نکتهٔ مهم:** Optimistic Initialization یک روش مبتنی بر خوش‌بینی در تخمین‌های اولیه است؛ نباید آن را با UCB یکسان بدانیم. UCB عدم‌قطعیت و تعداد دفعات انتخاب Action را به‌صورت پویا در تصمیم‌گیری لحاظ می‌کند.

## **۹. Strategic Exploration**

تا اینجا روش‌هایی را بررسی کردیم که عمدتاً با استفاده از تصادفی‌بودن، Exploration را انجام می‌دادند.

اما یک سؤال مهم باقی می‌ماند:

آیا بهتر نیست Agent هنگام انتخاب تصادفی، به کیفیت تخمین‌هایش نیز توجه کند؟

مثلاً اگر Action A تخمین ۹ و Action B تخمین ۱ داشته باشد، منطقی نیست که احتمال انتخاب هر دو کاملاً برابر باشد.

در بخش دوم فصل، سه روش مهم‌تر برای Exploration بررسی می‌شوند:

1. Softmax
2. Upper Confidence Bound (UCB)
3. Thompson Sampling

تفاوت مهم این روش‌ها در نحوهٔ استفاده از تخمین Action Value و اطلاعات مربوط به عدم‌قطعیت است.

### **۹.۱. Softmax: Select Actions Randomly in Proportion to Their Estimates**

#### **ایدهٔ اصلی**

در Epsilon-Greedy، Agent در مرحلهٔ Exploration به‌صورت تصادفی از بین Actionها انتخاب می‌کند.

اما Softmax احتمال انتخاب هر Action را متناسب با تخمین ارزش آن تعیین می‌کند.

یعنی:

- Action با تخمین بالاتر، احتمال انتخاب بیشتری دارد.
- Action با تخمین پایین‌تر، احتمال انتخاب کمتری دارد.
- برخلاف Greedy، Actionهای دیگر نیز همچنان شانس انتخاب دارند.

#### **فرمول Softmax**

\\[ P(A_t=a)= \frac{\exp(Q_t(a)/\tau)} {\sum\_{b\in\mathcal{A}}\exp(Q_t(b)/\tau)} \\]

در این فرمول:

- \\(P(A_t=a)\\): احتمال انتخاب Action موردنظر
- \\(Q_t(a)\\): تخمین ارزش Action
- \\(\exp\\): تابع نمایی
- \\(\tau\\): Temperature
- \\(\mathcal{A}\\): مجموعهٔ تمام Actionها

#### **Temperature چیست؟**

Temperature پارامتری است که میزان تصادفی‌بودن انتخاب Actionها را کنترل می‌کند.

**Temperature بالا:**

- احتمال انتخاب Actionها به یکدیگر نزدیک‌تر می‌شود.
- Exploration افزایش می‌یابد.
- تفاوت ارزش تخمینی Actionها تأثیر کمتری بر انتخاب دارد.

**Temperature پایین:**

- احتمال انتخاب Action با ارزش تخمینی بالاتر افزایش می‌یابد.
- انتخاب‌ها بیشتر به سمت Greedy می‌روند.
- Exploitation افزایش می‌یابد.

### **تأثیر Temperature بر احتمال انتخاب در Softmax**

Temperature با نماد `τ` مشخص می‌شود و میزان تصادفی‌بودن انتخاب Actionها را کنترل می‌کند.

فرمول Softmax:

`P(A=a) = exp(Q(a)/τ) / Σ exp(Q(b)/τ)`

فرض کن سه Action با مقادیر زیر داریم:

- Action A: Q = 1
- Action B: Q = 2
- Action C: Q = 3

با Temperature برابر ۱:

| Action | Action Value | Probability |
| ------ | ------------ | ----------- |
| A      | ۱            | ۹٫۰٪        |
| B      | ۲            | ۲۴٫۵٪       |
| C      | ۳            | ۶۶٫۵٪       |

### **نمایش مفهومی تأثیر Temperature**

```
Temperature پایین (τ کوچک)
--------------------------------
Action A  | *
Action B  | ***
Action C  | ***************

تمرکز بیشتر روی Action با Q بالاتر


Temperature بالا (τ بزرگ)
--------------------------------
Action A  | ********
Action B  | **********
Action C  | ************

احتمال‌های نزدیک‌تر به یکدیگر
```

این نمودار صرفاً شماتیک است و طول میله‌ها مقدار احتمال واقعی را نشان نمی‌دهد.

- Temperature پایین: احتمال انتخاب Action دارای بیشترین ارزش افزایش می‌یابد و رفتار به Greedy نزدیک می‌شود.
- Temperature بالا: احتمال انتخاب Actionها به یکدیگر نزدیک‌تر می‌شود و Exploration افزایش می‌یابد.

به‌طور خلاصه:

- \\(\tau\rightarrow 0\\): انتخاب به سمت Greedy نزدیک می‌شود.
- \\(\tau\\) کوچک: تمرکز بیشتر بر Actionهای با ارزش بالا.
- \\(\tau\\) بزرگ: انتخاب تصادفی‌تر.
- \\(\tau\rightarrow\infty\\): احتمال انتخاب Actionها تقریباً برابر می‌شود.

#### **مزایا**

- استفاده از Action Value در انتخاب تصادفی
- امکان انتخاب Actionهای غیربهینه با احتمال کنترل‌شده
- ایجاد تعادل میان Exploration و Exploitation

#### **محدودیت‌ها**

- انتخاب Temperature مناسب اهمیت زیادی دارد.
- Softmax به‌خودی‌خود عدم‌قطعیت تخمین‌ها را مدل نمی‌کند.
- مقدار Action Valueها می‌تواند روی رفتار احتمالاتی اثر بگذارد.

**نکتهٔ مهم:** Softmax بر اساس مقدار تخمینی Actionها تصمیم می‌گیرد، نه بر اساس میزان اطمینان Agent به آن تخمین‌ها.

### **۹.۲. Upper Confidence Bound (UCB)**

#### **ایدهٔ اصلی**

UCB یکی از روش‌های مهم Strategic Exploration است.

در روش‌های قبلی، Agent عمدتاً از تخمین Action Value استفاده می‌کرد. اما مشکل این است که تخمین یک Action ممکن است هنوز دقیق نباشد.

مثلاً:

- Action A: تخمین ۸، با ۱۰۰ بار تجربه
- Action B: تخمین ۷، با ۲ بار تجربه

اگر فقط به تخمین ارزش نگاه کنیم، A بهتر به نظر می‌رسد.

اما دربارهٔ B اطلاعات بسیار کمتری داریم. شاید B در واقع بهتر از A باشد.

UCB برای حل این مسئله، علاوه بر مقدار تخمینی، میزان عدم‌قطعیت را نیز در نظر می‌گیرد.

#### **Confidence Bound چیست؟**

Confidence Bound به محدوده‌ای اشاره دارد که با توجه به داده‌های مشاهده‌شده، انتظار داریم مقدار واقعی در آن قرار بگیرد.

در UCB، به‌جای انتخاب صرفاً بر اساس تخمین فعلی، یک Bonus به تخمین Action اضافه می‌شود.

این Bonus به Actionهایی تعلق می‌گیرد که کمتر امتحان شده‌اند.

#### **فرمول UCB**

فرمول متداول UCB1:

\\[ UCB_t(a)=Q_t(a)+c\sqrt{\frac{\ln t}{N_t(a)}} \\]

در این رابطه:

- \\(Q_t(a)\\): ارزش تخمینی Action
- \\(c\\): پارامتر کنترل‌کنندهٔ میزان Exploration
- \\(t\\): تعداد کل انتخاب‌ها تا زمان فعلی
- \\(N_t(a)\\): تعداد دفعات انتخاب Action
- \\(\ln\\): لگاریتم طبیعی

دو بخش اصلی داریم:

\\[ \underbrace{Q_t(a)}\_{\text{Exploitation}} + \underbrace{c\sqrt{\frac{\ln t}{N_t(a)}}}\_{\text{Exploration Bonus}} \\]

#### **ساختار تصمیم‌گیری UCB**

```
              For Each Action
                     |
          +----------+----------+
          |                     |
          v                     v
   Estimated Value        Exploration Bonus
       Q(a)               c × √(ln(t)/N(a))
          |                     |
          +----------+----------+
                     |
                     v
                  UCB Score
                     |
                     v
             Compare All Actions
                     |
                     v
             Select Highest UCB
                     |
                     v
              Observe Reward
                     |
                     v
               Update Q-Value
                     |
                     v
                   Repeat
```

این نمودار نشان می‌دهد UCB چگونه دو مؤلفهٔ Exploitation و Exploration را ترکیب می‌کند.

#### **Exploration Bonus چگونه کار می‌کند؟**

به فرمول توجه کن:

\\[ c\sqrt{\frac{\ln t}{N_t(a)}} \\]

اگر Action کمتر انتخاب شده باشد، \\(N_t(a)\\) کوچک‌تر است و Exploration Bonus بزرگ‌تر می‌شود.

در نتیجه:

- Actionهای کمتر امتحان‌شده جذاب‌تر می‌شوند.
- Actionهای بیشتر امتحان‌شده Bonus کمتری می‌گیرند.
- Agent به‌مرور اطلاعات بیشتری دربارهٔ گزینه‌های مختلف جمع‌آوری می‌کند.

#### **مثال**

فرض کن دو Action داریم:

| ویژگی             | Action A | Action B |
| ----------------- | -------- | -------- |
| Estimated Value   | 8        | 7        |
| تعداد انتخاب      | 100      | 2        |
| Exploration Bonus | 0.2      | 2        |
| UCB Score         | 8.2      | 9        |

با اینکه تخمین ارزش A بیشتر است، امتیاز UCB برای B بالاتر می‌شود.

پس Agent ممکن است B را انتخاب کند؛ چون هنوز دربارهٔ آن اطلاعات کافی ندارد.

این مقادیر یک مثال عددی ساده‌شده هستند؛ Bonus واقعی باید با استفاده از فرمول و پارامترهای الگوریتم محاسبه شود.

الگوریتم Upper Confidence Bound (UCB) برای انتخاب Action از دو مؤلفه استفاده می‌کند:

### ۱. Estimated Action Value

`Q(a)`

نشان‌دهندهٔ Reward مورد انتظار از انتخاب Action است.

این بخش مربوط به Exploitation است؛ یعنی استفاده از دانش فعلی Agent.

### ۲. Exploration Bonus

`Exploration Bonus`

مقداری اضافی است که به Actionهای کمتر بررسی‌شده اختصاص داده می‌شود.

این بخش مربوط به Exploration است؛ یعنی تشویق Agent به بررسی گزینه‌هایی که دربارهٔ آن‌ها اطلاعات کمتری دارد.

### ۳. UCB Score

فرمول:

`UCB(a) = Q(a) + Exploration Bonus`

فرمول متداول UCB1:

`UCB_t(a) = Q_t(a) + c × √(ln(t) / N_t(a))`

Agent در هر مرحله Action دارای بالاترین UCB Score را انتخاب می‌کند.

بنابراین:

- Estimated Action Value بالاتر، Exploitation را تقویت می‌کند.
- Exploration Bonus بالاتر، Exploration را تقویت می‌کند.
- مجموع این دو، امتیاز نهایی UCB را مشخص می‌کند.

#### **تفاوت UCB و Optimistic Initialization**

این دو روش شباهت مفهومی دارند؛ چون هر دو از خوش‌بینی برای تشویق Exploration استفاده می‌کنند.

اما تفاوت آن‌ها مهم است:

| Optimistic Initialization               | UCB                                                |
| --------------------------------------- | -------------------------------------------------- |
| تخمین اولیه را خوش‌بینانه تعیین می‌کند. | در هر مرحله Bonus اکتشاف محاسبه می‌کند.            |
| خوش‌بینی در مقداردهی اولیه است.         | خوش‌بینی بر اساس تعداد انتخاب و زمان تغییر می‌کند. |
| روش ساده‌تری است.                       | از اطلاعات تجربه‌ها به شکل پویا استفاده می‌کند.    |

**مزایا:**

- استفاده از تخمین ارزش و عدم‌قطعیت
- تشویق انتخاب Actionهای کمتر بررسی‌شده
- ایجاد تعادل سیستماتیک میان Exploration و Exploitation

**محدودیت‌ها:**

- نیازمند تنظیم پارامتر \\(c\\)
- وابستگی به فرضیات ریاضی و شرایط مسئله
- در محیط‌های غیرایستا، نسخهٔ پایه ممکن است مناسب نباشد.

### **۹.۳. Thompson Sampling: Balancing Reward and Risk**

#### **ایدهٔ اصلی**

Thompson Sampling یک روش Bayesian برای Exploration است.

در این روش، Agent به‌جای اینکه فقط یک تخمین ثابت برای ارزش هر Action داشته باشد، یک توزیع احتمالاتی از باور خود دربارهٔ ارزش آن Action نگه می‌دارد.

سپس از این توزیع‌ها نمونه‌گیری می‌کند و Actionی را انتخاب می‌کند که نمونهٔ به‌دست‌آمدهٔ آن بیشترین مقدار را دارد.

به زبان ساده:

Agent به‌جای اینکه فقط بپرسد «کدام Action بهترین است؟»، می‌پرسد:

«اگر ارزش واقعی Actionها مطابق باور فعلی من باشد، کدام Action را باید انتخاب کنم؟»

#### **Bayesian Inference چیست؟**

در روش Bayesian، Agent باور اولیه‌ای دربارهٔ یک پارامتر دارد و با مشاهدهٔ داده‌های جدید، باور خود را به‌روزرسانی می‌کند.

دو مفهوم اصلی:

- Prior: باور اولیه دربارهٔ پارامتر
- Posterior: باور به‌روزشده پس از مشاهدهٔ داده‌ها

فرمول Bayes:

\\[ P(\theta\mid D)= \frac{P(D\mid\theta)P(\theta)}{P(D)} \\]

که در آن:

- \\(\theta\\): پارامتر ناشناخته
- \\(D\\): داده‌های مشاهده‌شده
- \\(P(\theta)\\): Prior
- \\(P(\theta\mid D)\\): Posterior
- \\(P(D\mid\theta)\\): Likelihood

#### **مراحل Thompson Sampling**

1. برای هر Action یک توزیع احتمالاتی دربارهٔ Reward آن نگه می‌داریم.
2. از توزیع هر Action یک نمونه می‌گیریم.
3. Actionی را انتخاب می‌کنیم که نمونهٔ بزرگ‌تری دارد.
4. Reward واقعی را از محیط دریافت می‌کنیم.
5. توزیع مربوط به Action انتخاب‌شده را با استفاده از دادهٔ جدید به‌روزرسانی می‌کنیم.
6. این فرایند را تکرار می‌کنیم.

### **چرخهٔ Thompson Sampling**

```
        Maintain Beliefs
               |
               v
        Sample from Each
        Action Distribution
               |
               v
        Compare Samples
               |
               v
        Select Highest Sample
               |
               v
        Execute Selected Action
               |
               v
        Observe Reward
               |
               v
        Update Posterior
               |
               v
          Repeat Cycle
```

1. **Maintain Beliefs**

   نگهداری توزیع باور برای هر Action
2. **Sample**

   نمونه‌گیری از توزیع هر Action
3. **Select**

   انتخاب Action با بزرگ‌ترین نمونه
4. **Observe Reward**

   دریافت Reward از محیط
5. **Update Posterior**

   به‌روزرسانی باور با استفاده از تجربهٔ جدید
6. **Repeat**

   تکرار فرایند

#### **مثال ساده**

فرض کن دو Action داریم:

- Action A: احتمال موفقیت نامشخص
- Action B: احتمال موفقیت نامشخص

Agent برای هر Action یک توزیع احتمالاتی دارد.

ممکن است در یک مرحله، نمونهٔ Action A برابر ۰.۸ و نمونهٔ Action B برابر ۰.۶ باشد.

پس A انتخاب می‌شود.

اما در مرحلهٔ بعد، با نمونه‌گیری جدید ممکن است B مقدار بالاتری بگیرد و انتخاب شود.

این تغییر انتخاب‌ها به Agent اجازه می‌دهد هم از گزینه‌های امیدوارکننده استفاده کند و هم گزینه‌های دیگر را بررسی کند.

#### **Gaussian Distribution**

در توضیح کتاب، از توزیع Gaussian برای نمونه‌گیری در مثال‌های Thompson Sampling استفاده می‌شود.

\\[ X\sim\mathcal{N}(\mu,\sigma^2) \\]

در این رابطه:

- \\(\mu\\): میانگین توزیع
- \\(\sigma^2\\): واریانس
- \\(\sigma\\): انحراف معیار

اگر عدم‌قطعیت دربارهٔ یک Action بیشتر باشد، توزیع آن می‌تواند گسترده‌تر باشد.

در نتیجه نمونه‌های مختلف‌تری تولید می‌کند و احتمال انتخاب آن Action نیز می‌تواند تغییر کند.

#### **Beta Distribution**

توزیع Beta برای مسئله‌های Bernoulli Bandit انتخاب رایجی است.

\\[ X\sim Beta(\alpha,\beta) \\]

در این توزیع:

- \\(\alpha\\): پارامتر مرتبط با شواهد موفقیت
- \\(\beta\\): پارامتر مرتبط با شواهد شکست

در حالت سادهٔ Bernoulli Bandit، اگر Prior برابر \\(Beta(\alpha_0,\beta_0)\\) باشد و \\(s\\) موفقیت و \\(f\\) شکست مشاهده کنیم:

\\[ \alpha=\alpha_0+s \\]

\\[ \beta=\beta_0+f \\]

این به‌روزرسانی باعث می‌شود توزیع باور Agent با تجربه‌های جدید تغییر کند.

**نکتهٔ مهم دربارهٔ کتاب:** نویسنده در مثال آموزشی خود از Gaussian استفاده می‌کند، اما Beta Distribution برای بسیاری از مسائل Bernoulli Bandit رایج‌تر است. پس نباید تصور کنیم Thompson Sampling فقط با Gaussian کار می‌کند.

#### **مزایا**

- استفاده از عدم‌قطعیت در تصمیم‌گیری
- ایجاد Exploration بدون نیاز به Epsilon ثابت
- به‌روزرسانی باور با تجربه‌های جدید
- توانایی انتخاب گزینه‌های ناشناخته اما امیدوارکننده

#### **محدودیت‌ها**

- نیاز به انتخاب Prior مناسب
- نیاز به نگهداری و به‌روزرسانی توزیع‌های احتمالاتی
- پیچیدگی بیشتر نسبت به Epsilon-Greedy
- وابستگی به مدل احتمالاتی انتخاب‌شده

## **۱۱. آزمایش‌ها و ارزیابی الگوریتم‌ها**

در فصل چهارم، الگوریتم‌ها صرفاً به‌صورت تئوری معرفی نمی‌شوند؛ عملکرد آن‌ها در محیط‌های مختلف Multi-Armed Bandit نیز بررسی می‌شود.

هدف از این آزمایش‌ها بررسی این موضوع است که آیا یک روش Exploration در شرایط مختلف عملکرد مناسبی دارد یا خیر.

دو نوع محیط مهم در آزمایش‌های کتاب:

### **۱۱.۱. Two-Armed Bernoulli Bandit**

در این محیط دو Action داریم.

هر Action با احتمال مشخصی Reward برابر ۱ تولید می‌کند و در غیر این صورت Reward برابر ۰ خواهد بود.

\\[ R\sim Bernoulli(p) \\]

که \\(p\\) احتمال دریافت Reward مثبت است.

مثلاً:

- Action A: احتمال موفقیت ۰.۴
- Action B: احتمال موفقیت ۰.۷

بنابراین B به‌طور میانگین بهتر است، اما Agent از ابتدا این موضوع را نمی‌داند.

ساختار مفهومی:

```
             Two-Armed Bandit
                     |
              +------+------+
              |             |
              v             v
           Action A      Action B
              |             |
          Bernoulli      Bernoulli
           p = 0.4        p = 0.7
              |             |
              v             v
          Reward 0/1     Reward 0/1
```

### **۱۱.۲. Ten-Armed Gaussian Bandit**

در این محیط ده Action مختلف وجود دارد و Reward هر Action از یک توزیع Gaussian تولید می‌شود.

\\[ R_a\sim\mathcal{N}(\mu_a,\sigma_a^2) \\]

در اینجا:

- هر Action میانگین Reward متفاوتی دارد.
- Rewardها می‌توانند حول میانگین نوسان داشته باشند.
- Agent باید با تجربه ارزش گزینه‌ها را تخمین بزند.

ساختار مفهومی:

```
                 Ten-Armed Bandit
                         |
       +------+------+------+------+------+
       |      |      |      |      |      |
       v      v      v      v      v      v
      A1     A2     A3     A4     A5    ...
       |      |      |      |      |      |
       v      v      v      v      v      v
   Gaussian distributions with different means
                         |
                         v
                 Observed Rewards
```

### **۱۱.۳. معیارهای ارزیابی**

برای بررسی عملکرد الگوریتم‌ها می‌توان از معیارهای زیر استفاده کرد:

**Average Reward**

میانگین Reward دریافتی Agent:

\\[ \bar{R}=\frac{1}{T}\sum\_{t=1}^{T}R_t \\]

هرچه این مقدار بیشتر باشد، Agent به‌طور متوسط پاداش بیشتری دریافت کرده است.

**Cumulative Reward**

مجموع Rewardها در طول اجرا:

\\[ G_T=\sum\_{t=1}^{T}R_t \\]

**Cumulative Regret**

مجموع فرصت‌های ازدست‌رفته در مقایسه با بهترین Action:

\\[ R_T=\sum\_{t=1}^{T}[Q^\\\*-Q(A_t)] \\]

هرچه Regret کمتر باشد، Agent از نظر انتخاب Actionهای نزدیک به بهینه عملکرد بهتری داشته است.

### **۱۱.۴. نکتهٔ مهم نتایج آزمایش‌ها**

یک نتیجهٔ مهم در بررسی‌های این فصل این است که الگوریتم‌های پیچیده‌تر همیشه از روش‌های ساده‌تر بهتر نیستند.

برای مثال، در بعضی از محیط‌های آزمایش‌شده، Epsilon-Greedy با تنظیم مناسب می‌تواند عملکرد بسیار خوبی داشته باشد.

بنابراین:

- پیچیدگی بیشتر الزاماً به معنی عملکرد بهتر نیست.
- انتخاب الگوریتم به نوع محیط بستگی دارد.
- Hyperparameterها نقش مهمی در عملکرد دارند.
- یک الگوریتم ممکن است در یک محیط عالی و در محیط دیگر ضعیف باشد.

این موضوع یکی از دلایل اهمیت آزمایش و ارزیابی تجربی در Reinforcement Learning است.

## **۱۲. جمع‌بندی نهایی فصل**

پیام اصلی فصل چهارم این است که Agent برای رسیدن به عملکرد بهتر، باید یاد بگیرد چه زمانی اطلاعات جدید جمع‌آوری کند و چه زمانی از اطلاعات فعلی خود برای کسب Reward استفاده کند.

این مسئله از آنجا به وجود می‌آید که Agent در محیط‌های ناشناخته، مدل کامل محیط و ارزش واقعی Actionها را نمی‌داند.

بنابراین باید از طریق تعامل و دریافت Reward، ارزش گزینه‌ها را تخمین بزند.

**گروه اول: روش‌های پایه**

- Greedy
- Random
- Epsilon-Greedy

این روش‌ها پایهٔ درک Exploration و Exploitation هستند.

**گروه دوم: روش‌های بهبود Exploration**

- Decaying Epsilon-Greedy
- Optimistic Initialization

این روش‌ها تلاش می‌کنند Exploration را متناسب با مرحلهٔ یادگیری یا تخمین‌های اولیه مدیریت کنند.

**گروه سوم: Strategic Exploration**

- Softmax
- UCB
- Thompson Sampling

این روش‌ها از اطلاعات مربوط به Action Value، عدم‌قطعیت یا توزیع باور برای تصمیم‌گیری بهتر استفاده می‌کنند.

### ۱. Reinforcement Learning

یادگیری از طریق تعامل با محیط و دریافت Reward.

### ۲. Evaluative Feedback

Agent از محیط بازخورد دریافت می‌کند، اما مدل کامل محیط و ارزش واقعی Actionها را از ابتدا نمی‌داند.

### ۳. Exploration–Exploitation Dilemma

Agent باید میان دو هدف تعادل برقرار کند:

- Exploration: کسب اطلاعات جدید
- Exploitation: استفاده از دانش فعلی برای دریافت Reward

### ۴. Multi-Armed Bandit (MAB)

محیطی تک‌حالته با چند Action و Rewardهای ناشناخته که مسئلهٔ Exploration–Exploitation را بررسی می‌کند.

### ۵. Basic Strategies

**Greedy**

- همیشه انتخاب Action با بالاترین Action Value تخمینی
- تمرکز بر Exploitation

**Random**

- انتخاب تصادفی Actionها
- تمرکز بر Exploration

**Epsilon-Greedy**

- انتخاب Greedy با احتمال `1 - ε`
- انتخاب تصادفی با احتمال `ε`

### ۶. Improved Strategies

**Decaying Epsilon-Greedy**

- کاهش تدریجی Epsilon
- Exploration بیشتر در ابتدای یادگیری
- Exploitation بیشتر در ادامه

**Optimistic Initialization**

- شروع با تخمین‌های اولیهٔ خوش‌بینانه
- تشویق Agent به امتحان‌کردن Actionهای مختلف

### ۷. Strategic Exploration

روش‌هایی که از اطلاعات ارزش Actionها و عدم‌قطعیت برای تصمیم‌گیری استفاده می‌کنند.

**Softmax**

- انتخاب احتمالی Actionها بر اساس Action Value
- کنترل میزان تصادفی‌بودن با Temperature

**Upper Confidence Bound (UCB)**

- ترکیب Action Value و Exploration Bonus
- تشویق انتخاب Actionهای کمتر بررسی‌شده

**Thompson Sampling**

- استفاده از Bayesian Inference
- نمونه‌گیری از توزیع باور دربارهٔ Reward هر Action
- به‌روزرسانی باور با تجربه‌های جدید

### ۸. Goal: Low Regret + High Expected Reward

## **۱۴. فرمول‌های مهم فصل چهارم**

برگهٔ ارجاع سریع:

| مفهوم                 | فرمول                                                           |
| --------------------- | --------------------------------------------------------------- |
| Expected Action Value | \\(Q(a)=\mathbb{E}[R\mid A=a]\\)                                |
| Sample Average        | \\(Q_n(a)=\frac{1}{n}\sum\_{i=1}^{n}R_i\\)                      |
| Incremental Update    | \\(Q\_{\text{new}}=Q\_{\text{old}}+\alpha(R-Q\_{\text{old}})\\) |
| Epsilon-Greedy        | \\(P(\text{Random})=\epsilon\\)                                 |
| Linear Decay          | \\(\epsilon_t=\max(\epsilon\_{\min},\epsilon_0-kt)\\)           |
| Exponential Decay     | \\(\epsilon_t=\max(\epsilon\_{\min},\epsilon_0e^{-kt})\\)       |
| Softmax               | \\(P(a)=\frac{e^{Q(a)/\tau}}{\sum_b e^{Q(b)/\tau}}\\)           |
| UCB                   | \\(Q_t(a)+c\sqrt{\frac{\ln t}{N_t(a)}}\\)                       |
| Instantaneous Regret  | \\(r_t=Q^\\\*-Q(A_t)\\)                                         |
| Cumulative Regret     | \\(R_T=\sum\_{t=1}^{T}[Q^\\\*-Q(A_t)]\\)                        |
| Gaussian              | \\(X\sim\mathcal{N}(\mu,\sigma^2)\\)                            |
| Beta                  | \\(X\sim Beta(\alpha,\beta)\\)                                  |

## **۱۵. نکات مهم و امتحانی**

1. Exploration یعنی جمع‌آوری اطلاعات جدید و Exploitation یعنی استفاده از دانش فعلی برای کسب Reward.
2. مهم‌ترین دلیل نیاز به Exploration، ناشناخته‌بودن مدل محیط و ارزش واقعی Actionهاست.
3. Multi-Armed Bandit یک مسئلهٔ تک‌حالته با چند Action و Reward ناشناخته است.
4. Greedy همیشه Action با بالاترین تخمین ارزش را انتخاب می‌کند.
5. Random تمام Actionها را با احتمال برابر انتخاب می‌کند.
6. Epsilon-Greedy در بیشتر مواقع Greedy است و گاهی تصادفی انتخاب می‌کند.
7. Epsilon بزرگ‌تر به معنی Exploration بیشتر است.
8. در Epsilon-Greedy، احتمال انتخاب Action غیربهینه لزوماً برابر Epsilon نیست؛ چون انتخاب تصادفی ممکن است به انتخاب همان Action بهینه منجر شود.
9. Decaying Epsilon-Greedy در ابتدا بیشتر Explore می‌کند و به‌تدریج به سمت Exploitation می‌رود.
10. Linear Decay کاهش با نرخ ثابت دارد، در حالی که Exponential Decay معمولاً در ابتدا سریع‌تر کاهش پیدا می‌کند.
11. Optimistic Initialization با تخمین‌های اولیهٔ خوش‌بینانه، Agent را به بررسی Actionهای مختلف تشویق می‌کند.
12. Softmax احتمال انتخاب Action را بر اساس ارزش تخمینی و Temperature تعیین می‌کند.
13. Temperature پایین، انتخاب‌ها را به Greedy نزدیک می‌کند.
14. Temperature بالا باعث نزدیک‌ترشدن احتمال انتخاب Actionهای مختلف می‌شود.
15. UCB علاوه بر تخمین ارزش، Exploration Bonus را نیز در نظر می‌گیرد.
16. در UCB، Actionهایی که کمتر انتخاب شده‌اند معمولاً Exploration Bonus بیشتری دارند.
17. Thompson Sampling از توزیع باور دربارهٔ ارزش Actionها نمونه‌گیری می‌کند.
18. در Thompson Sampling، Prior با مشاهدهٔ داده‌های جدید به Posterior تبدیل می‌شود.
19. Thompson Sampling می‌تواند از توزیع‌های مختلفی مانند Gaussian یا Beta استفاده کند.
20. Regret نشان‌دهندهٔ هزینهٔ انتخاب Actionهای غیربهینه نسبت به بهترین Action است.
21. پیچیده‌تر بودن یک الگوریتم لزوماً به معنی عملکرد بهتر آن نیست.
22. انتخاب Exploration Strategy مناسب به محیط و Hyperparameterها بستگی دارد.

## **۱۷. جمع‌بندی یک‌خطی فصل**

در Reinforcement Learning، برای رسیدن به بهترین تصمیم‌ها کافی نیست از دانش فعلی استفاده کنیم؛ باید بدانیم چه زمانی برای کشف گزینه‌های بهتر، ریسک Exploration را بپذیریم و چگونه این ریسک را با روش‌هایی مانند Epsilon-Greedy، Softmax، UCB و Thompson Sampling مدیریت کنیم.

## **۱۸. چک‌لیست تسلط بر فصل**

- تفاوت Exploration و Exploitation چیست و چرا میان آن‌ها تعارض وجود دارد؟
- چرا Reward مشاهده‌شده لزوماً نشان‌دهندهٔ ارزش واقعی یک Action نیست؟
- Multi-Armed Bandit چیست و چه تفاوتی با MDP دارد؟
- Action Value چگونه با Sample Average تخمین زده می‌شود؟
- Incremental Update چه مزیتی نسبت به محاسبهٔ مجدد میانگین دارد؟
- Regret چیست و چگونه محاسبه می‌شود؟
- چرا Greedy ممکن است در یک Action غیربهینه گیر کند؟
- Epsilon-Greedy چگونه Exploration را مدیریت می‌کند؟
- تفاوت Linear و Exponential Epsilon Decay چیست؟
- Optimistic Initialization چگونه Exploration ایجاد می‌کند؟
- Temperature در Softmax چه تأثیری بر احتمال انتخاب Action دارد؟
- UCB چگونه Action Value و Exploration Bonus را ترکیب می‌کند؟
- تفاوت UCB و Optimistic Initialization چیست؟
- Thompson Sampling چگونه از Prior و Posterior استفاده می‌کند؟
- چه تفاوتی میان Gaussian و Beta Distribution در مثال‌های Thompson Sampling وجود دارد؟
- چرا عملکرد الگوریتم‌ها باید در محیط‌های مختلف ارزیابی شود؟
