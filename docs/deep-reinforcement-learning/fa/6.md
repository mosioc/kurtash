## **۲. تفاوت Prediction و Control**

یکی از مهم‌ترین مفاهیم فصل ششم، تفاوت دو مسئله Prediction و Control است.

در فصل پنجم بیشتر با Prediction سروکار داشتیم؛ اما در فصل ششم هدف ما حل Control Problem است.

### **۲.۱. Prediction Problem**

هدف Prediction، ارزیابی یک Policy مشخص است.

یعنی می‌خواهیم بدانیم اگر Agent از یک Policy مشخص پیروی کند، عملکرد آن چقدر خوب خواهد بود.

در این مسئله، هدف پیدا کردن Policy بهتر نیست؛ بلکه می‌خواهیم ارزش Policy موجود را تخمین بزنیم.

ابزار اصلی:

- State-Value Function: \\(V^\pi(s)\\)
- Action-Value Function: \\(Q^\pi(s,a)\\)

### **۲.۲. Control Problem**

هدف Control، پیدا کردن بهترین Policy ممکن است.

در اینجا فقط نمی‌خواهیم بدانیم یک Policy چقدر خوب است؛ بلکه می‌خواهیم آن را بهبود دهیم تا بیشترین Return ممکن را به دست آوریم.

برای این کار دو فرآیند داریم:

1. Policy Evaluation: ارزیابی Policy فعلی
2. Policy Improvement: بهبود Policy بر اساس اطلاعات به‌دست‌آمده

### **مقایسه Prediction و Control**

| ویژگی  | Prediction              | Control                                 |
| ------ | ----------------------- | --------------------------------------- |
| هدف    | ارزیابی Policy          | بهینه‌سازی Policy                       |
| تمرکز  | تخمین Value             | یافتن بهترین رفتار                      |
| Policy | مشخص و ثابت یا داده‌شده | به‌صورت تدریجی بهبود می‌یابد            |
| خروجی  | Value Function          | Optimal Policy و Optimal Value Function |

**رابطه مفهومی:**

```
Prediction Problem
       |
       v
Policy Evaluation
       |
       v
Estimate Value Function


Control Problem
       |
       v
Policy Evaluation
       |
       v
Policy Improvement
       |
       v
Better Policy
       |
       v
Repeat
       |
       v
Optimal Policy
```

نکته کلیدی:

Prediction به ما می‌گوید یک Policy چقدر خوب است؛ Control تلاش می‌کند Policy بهتری پیدا کند.

## **۳. چرا به Action-Value Function یا Q-Function نیاز داریم؟**

در فصل‌های قبل با State-Value Function آشنا شدیم.

اما یک مشکل وجود دارد: دانستن ارزش یک State لزوماً به ما نمی‌گوید کدام Action را باید انتخاب کنیم.

### **۳.۱. State-Value Function**

تابع \\(V^\pi(s)\\) نشان می‌دهد اگر در State مشخصی قرار بگیریم و از Policy مشخصی پیروی کنیم، Return مورد انتظار چقدر خواهد بود.

\\[ V^\pi(s)= \mathbb{E}\_\pi[G_t\mid S_t=s] \\]

### **۳.۲. Action-Value Function**

تابع \\(Q^\pi(s,a)\\) ارزش انتخاب یک Action مشخص در یک State مشخص را نشان می‌دهد.

\\[ Q^\pi(s,a)= \mathbb{E}\_\pi[G_t\mid S_t=s,A_t=a] \\]

تفاوت اصلی:

- \\(V(s)\\): ارزش قرار داشتن در یک State
- \\(Q(s,a)\\): ارزش انتخاب یک Action در یک State

### **مثال: بازی شطرنج**

فرض کن Agent در یک موقعیت مشخص از صفحه شطرنج قرار دارد.

- \\(V(s)\\) نشان می‌دهد این موقعیت به‌طور کلی چقدر مطلوب است.
- \\(Q(s,a)\\) نشان می‌دهد انجام یک حرکت مشخص از آن موقعیت چقدر ارزشمند است.

برای انتخاب بهترین حرکت، دانستن ارزش Actionها بسیار کاربردی‌تر است.

### **۳.۳. چرا Q-Function در Control اهمیت دارد؟**

برای بهبود Policy باید بتوانیم Actionهای مختلف را با یکدیگر مقایسه کنیم.

اگر Q-Function را داشته باشیم، می‌توانیم Action دارای بیشترین ارزش تخمینی را انتخاب کنیم:

\\[ \pi(s)=\arg\max_a Q(s,a) \\]

این Policy را Greedy Policy می‌نامیم.

نکته مهم:

برای استفاده از Q-Function و انتخاب Action، لزوماً نیازی نیست مدل کامل MDP را در اختیار داشته باشیم. می‌توانیم Q-Valueها را مستقیماً از تجربه‌های Agent یاد بگیریم.

به همین دلیل Q-Function در Model-Free Reinforcement Learning اهمیت زیادی دارد.

## **۴. آناتومی یک Reinforcement Learning Agent**

کتاب در بخش 6.1 ساختار کلی یک RL Agent را به سه وظیفه اصلی تقسیم می‌کند.

هر Agent معمولاً سه کار انجام می‌دهد:

1. Gather Experience: جمع‌آوری تجربه
2. Estimate Something: تخمین یک معیار یا تابع ارزش
3. Improve a Policy: بهبود Policy

### **۴.۱. Gather Experience**

Agent باید از محیط تجربه جمع‌آوری کند.

هر تجربه معمولاً شامل اطلاعات زیر است:

\\[ (S_t,A_t,R\_{t+1},S\_{t+1}) \\]

یعنی:

- \\(S_t\\): وضعیت فعلی
- \\(A_t\\): اقدام انتخاب‌شده
- \\(R\_{t+1}\\): پاداش دریافتی
- \\(S\_{t+1}\\): وضعیت بعدی

این اطلاعات به Agent کمک می‌کنند بفهمد اقداماتش چه نتایجی داشته‌اند.

تجربه می‌تواند از راه‌های مختلف به دست آید:

- تعامل مستقیم با محیط واقعی
- شبیه‌سازی محیط (Simulation)
- استفاده از یک مدل یادگرفته‌شده از محیط

مثلاً برای آموزش یک Robot، می‌توان ابتدا از Simulation استفاده کرد تا Agent بدون آسیب زدن به ربات واقعی یاد بگیرد.

### **۴.۲. Estimate Something**

Agent پس از جمع‌آوری تجربه باید چیزی را تخمین بزند.

این تخمین می‌تواند شامل موارد زیر باشد:

- Value Function
- Action-Value Function یا Q-Function
- ارزش مورد انتظار تصمیم‌های مختلف

در این فصل تمرکز اصلی روی تخمین Q-Function است؛ زیرا برای انتخاب و بهبود Actionها به آن نیاز داریم.

### **۴.۳. Improve a Policy**

در نهایت Agent از اطلاعات تخمین‌زده‌شده برای بهبود Policy استفاده می‌کند.

Policy مشخص می‌کند Agent در هر State چه Actionی انتخاب کند.

\\[ \pi(a\mid s) \\]

یک Policy می‌تواند قطعی (Deterministic) یا احتمالاتی (Stochastic) باشد.

در Policy قطعی، برای هر State یک Action مشخص انتخاب می‌شود.

در Policy احتمالاتی، احتمال انتخاب Actionهای مختلف مشخص می‌شود.

### **چرخه اصلی یک RL Agent**

این نمودار را می‌توان مستقیماً در Markdown کپی کرد:

```
       Environment
            |
            v
    Gather Experience
            |
            v
     Estimate Values
            |
            v
     Improve Policy
            |
            v
    Better Decisions
            |
            v
       Environment
            |
            v
          Repeat
```

این سه وظیفه با یکدیگر ارتباط دارند:

- بدون Experience، اطلاعاتی برای یادگیری وجود ندارد.
- بدون Estimation، Agent نمی‌تواند ارزش تصمیم‌های خود را به‌درستی مقایسه کند.
- بدون Policy Improvement، یادگیری لزوماً به رفتار بهتر منجر نمی‌شود.

### **۴.۴. تفاوت Reinforcement Learning و Supervised Learning**

در Supervised Learning، معمولاً یک Dataset آماده داریم که شامل Input و Target است.

مدل یاد می‌گیرد رابطه میان ورودی و خروجی را پیدا کند.

اما در Reinforcement Learning، Agent باید در فرآیند یادگیری، تجربه‌های موردنیاز خود را نیز جمع‌آوری کند.

| Supervised Learning          | Reinforcement Learning                 |
| ---------------------------- | -------------------------------------- |
| Dataset از قبل فراهم شده است | Agent تجربه جمع‌آوری می‌کند            |
| داده‌ها معمولاً ثابت هستند   | تجربه‌ها به تصمیم‌های Agent وابسته‌اند |
| Target مشخص است              | بازخورد از طریق Reward دریافت می‌شود   |
| یادگیری از نمونه‌ها          | یادگیری از تعامل و تجربه               |

**نکته مهم:**

در RL، جمع‌آوری داده (Experience Gathering) و یادگیری از داده (Learning) دو مسئله متفاوت هستند.

ممکن است یک Agent در انتخاب تجربه‌های مفید عملکرد خوبی داشته باشد، اما در یادگیری از آن‌ها ضعیف باشد؛ یا برعکس.

### **۴.۵. تفاوت Reinforcement Learning و Dynamic Programming**

Dynamic Programming معمولاً برای حل مسئله به مدل محیط نیاز دارد.

این مدل شامل اطلاعاتی مانند موارد زیر است:

- Transition Probability
- Reward Function

اما در بسیاری از الگوریتم‌های Model-Free RL، Agent مدل کامل محیط را در اختیار ندارد و از تجربه‌های نمونه‌برداری‌شده یاد می‌گیرد.

بنابراین:

- Dynamic Programming: استفاده از مدل محیط برای محاسبه و برنامه‌ریزی
- Model-Free RL: یادگیری از تجربه بدون نیاز به مدل کامل محیط

البته RL همیشه به معنی تعامل مستقیم با دنیای واقعی نیست؛ Simulation و تجربه‌های تولیدشده از مدل نیز می‌توانند استفاده شوند.

## **۵. Generalized Policy Iteration (GPI)**

مفهوم محوری فصل ششم

Generalized Policy Iteration یکی از مهم‌ترین مفاهیم این فصل است.

GPI یک چارچوب کلی برای درک ساختار الگوریتم‌های Reinforcement Learning است.

ایده اصلی آن تعامل مداوم دو فرآیند است:

1. Policy Evaluation
2. Policy Improvement

### **۵.۱. Policy Evaluation**

در این مرحله، عملکرد Policy فعلی را ارزیابی می‌کنیم.

هدف، تخمین Value Function مربوط به Policy است.

\\[ V^\pi(s) \\]

یا در الگوریتم‌های مبتنی بر Action-Value:

\\[ Q^\pi(s,a) \\]

### **۵.۲. Policy Improvement**

در این مرحله از اطلاعات Value Function برای بهبود Policy استفاده می‌کنیم.

برای مثال، اگر یک Action در State مشخصی ارزش بیشتری داشته باشد، می‌توانیم احتمال انتخاب آن را افزایش دهیم.

در حالت Greedy:

\\[ \pi'(s)=\arg\max_a Q^\pi(s,a) \\]

### **۵.۳. چرخه GPI**

```
       Initial Policy
             |
             v
      Policy Evaluation
             |
             v
      Estimate Value Function
             |
             v
      Policy Improvement
             |
             v
        Better Policy
             |
             v
      Policy Evaluation
             |
             v
           Repeat
             |
             v
       Optimal Policy
```

### **۵.۴. ارتباط GPI با Policy Iteration و Value Iteration**

GPI یک چارچوب عمومی‌تر از یک الگوریتم مشخص است.

**Policy Iteration:**

- ابتدا Policy را ارزیابی می‌کند.
- سپس Policy را بهبود می‌دهد.
- این فرآیند را تکرار می‌کند.
- در نسخه کلاسیک، Policy Evaluation به‌صورت کامل انجام می‌شود.

**Value Iteration:**

- از یک به‌روزرسانی مبتنی بر Bellman Optimality استفاده می‌کند.
- به جای ارزیابی کامل Policy در هر تکرار، تخمین ارزش‌ها را به‌صورت تدریجی به‌روزرسانی می‌کند.
- بهبود Policy در این فرآیند به‌صورت ضمنی اتفاق می‌افتد.

### **۵.۵. چرا Policy Evaluation همیشه کامل انجام نمی‌شود؟**

در محیط‌های پیچیده، محاسبه دقیق Value Function می‌تواند بسیار پرهزینه باشد.

بنابراین گاهی به جای ارزیابی کامل، از Partial Evaluation استفاده می‌کنیم.

در این روش، Policy تنها تا حدی ارزیابی می‌شود و سپس بهبود پیدا می‌کند.

مزایا:

- کاهش محاسبات
- سرعت بیشتر در بهبود Policy
- امکان یادگیری تدریجی
- مناسب‌تر بودن برای محیط‌های پیچیده

### **۵.۶. تعادل میان Evaluation و Improvement**

در GPI دو فرآیند با یکدیگر تعامل دارند:

- Evaluation تلاش می‌کند Value Function با Policy فعلی سازگار شود.
- Improvement از Value Function برای تولید Policy بهتر استفاده می‌کند.

بهبود Policy ممکن است باعث شود Value Function قبلی دیگر با Policy جدید سازگار نباشد.

بنابراین باید دوباره Evaluation انجام شود.

این تعامل مداوم، اساس GPI است.

**نکته مهم:** GPI الزاماً به معنی انجام کامل Evaluation و سپس Improvement نیست. این دو فرآیند می‌توانند به شکل تدریجی و هم‌زمان نیز پیش بروند.

## **۶. Exploration و Exploitation در Control**

در Control Problem، Agent باید علاوه بر استفاده از اطلاعات فعلی، گزینه‌های ناشناخته را نیز بررسی کند.

این مسئله همان Exploration و Exploitation است.

### **۶.۱. Exploration**

Exploration یعنی امتحان کردن Actionهای مختلف برای جمع‌آوری اطلاعات بیشتر.

هدف، کشف گزینه‌هایی است که ممکن است ارزش بیشتری داشته باشند.

### **۶.۲. Exploitation**

Exploitation یعنی استفاده از اطلاعات فعلی برای انتخاب بهترین Action شناخته‌شده.

هدف، دریافت بیشترین Reward بر اساس دانش موجود است.

### **۶.۳. چرا Exploration ضروری است؟**

فرض کن Agent در یک Maze قرار دارد.

اگر همیشه کوتاه‌ترین مسیر شناخته‌شده را انتخاب کند، ممکن است هرگز متوجه نشود مسیر دیگری وجود دارد که Reward بیشتری تولید می‌کند.

پس Agent نباید همیشه Greedy باشد.

### **۶.۴. Epsilon-Greedy**

یکی از روش‌های ساده و پرکاربرد برای ایجاد تعادل میان Exploration و Exploitation، الگوریتم Epsilon-Greedy است.

در این روش:

- با احتمال \\(1-\epsilon\\)، بهترین Action شناخته‌شده انتخاب می‌شود.
- با احتمال \\(\epsilon\\)، یک Action به‌صورت تصادفی انتخاب می‌شود.

\\[ a_t = \begin{cases} \text{Random Action} & \text{with probability } \epsilon\\\ \arg\max_a Q(s_t,a) & \text{with probability } 1-\epsilon \end{cases} \\]

مثلاً اگر:

\\[ \epsilon=0.2 \\]

باشد:

- ۲۰٪ احتمال Exploration
- ۸۰٪ احتمال Exploitation

### **۶.۵. Decaying Epsilon**

در ابتدای آموزش، Agent اطلاعات کمی دارد؛ بنابراین Exploration بیشتر مفید است.

با افزایش تجربه، می‌توان احتمال Exploration را کاهش داد.

به این روش Decaying Epsilon می‌گوییم.

```
Training Progress
       |
       v
Early Training
High Epsilon
More Exploration
       |
       v
Middle Training
Lower Epsilon
Balanced Behavior
       |
       v
Late Training
Low Epsilon
More Exploitation
```

البته کاهش Epsilon نباید بدون توجه به شرایط محیط انجام شود؛ زیرا کاهش بیش از حد آن می‌تواند باعث شود Agent فرصت کشف Actionهای بهتر را از دست بدهد.

## **۷. Control Agents و Model-Free Learning**

در این فصل با Agentهایی آشنا می‌شویم که می‌توانند مستقیماً از تجربه‌های خود Policy را بهبود دهند.

### **۷.۱. تفاوت Model-Based و Model-Free**

**Model-Based RL**

Agent از یک مدل محیط برای پیش‌بینی نتایج Actionها استفاده می‌کند.

این مدل می‌تواند Transition و Reward را توصیف کند.

**Model-Free RL**

Agent مستقیماً از تجربه‌های خود برای یادگیری ارزش Actionها یا Policy استفاده می‌کند.

لزومی ندارد احتمال انتقال به تمام Stateهای بعدی را بداند.

### **۷.۲. چرا Model-Free Learning اهمیت دارد؟**

در بسیاری از مسائل واقعی، ساختن مدل دقیق محیط بسیار دشوار است.

برای مثال:

- Robot Navigation
- Game Playing
- Resource Management
- Traffic Optimization

در چنین شرایطی می‌توان Agent را با تجربه‌های حاصل از تعامل یا Simulation آموزش داد.

### **۷.۳. Decoupling Learning from Behavior**

یکی از ایده‌های مهم فصل، جدا کردن فرآیند یادگیری از رفتار Agent است.

این موضوع در Q-Learning اهمیت ویژه‌ای پیدا می‌کند.

Agent می‌تواند با یک Policy برای جمع‌آوری تجربه عمل کند، اما از آن تجربه‌ها برای یادگیری یک Policy متفاوت و بهتر استفاده کند.

در مقابل، روش‌های On-Policy مانند SARSA از رفتار واقعی خود Agent برای به‌روزرسانی تخمین‌ها استفاده می‌کنند.

در بخش‌های بعدی این تفاوت را دقیق‌تر بررسی می‌کنیم.

## **۸. Monte Carlo Control**

On-Policy

Episode-Based

Monte Carlo Control اولین الگوریتم اصلی برای حل Control Problem در این فصل است.

هدف آن بهبود Policy از طریق تجربه‌های جمع‌آوری‌شده در Episodeها است.

### **۸.۱. ایده اصلی Monte Carlo Control**

در Monte Carlo Control:

1. Agent با استفاده از Policy فعلی در محیط حرکت می‌کند.
2. یک Episode کامل اجرا می‌شود.
3. Return واقعی محاسبه می‌شود.
4. Q-Valueهای State-Actionهای بازدیدشده به‌روزرسانی می‌شوند.
5. Policy بهبود پیدا می‌کند.
6. Episode بعدی آغاز می‌شود.

تفاوت مهم با Prediction این است که در اینجا از تخمین Q-Function برای بهبود Policy استفاده می‌کنیم.

### **۸.۲. چرا از Q-Function استفاده می‌کنیم؟**

همان‌طور که گفتیم، برای انتخاب بهترین Action باید ارزش Actionهای مختلف را مقایسه کنیم.

\\[ \pi(s)=\arg\max_a Q(s,a) \\]

بنابراین Monte Carlo Control به جای اینکه فقط State Value را تخمین بزند، Action Value را یاد می‌گیرد.

### **۸.۳. First-Visit Monte Carlo Control**

در First-Visit Monte Carlo، هر State-Action Pair در هر Episode فقط در اولین باری که بازدید می‌شود، برای به‌روزرسانی در نظر گرفته می‌شود.

یعنی:

\\[ (S_t,A_t) \\]

فقط زمانی Update می‌شود که اولین وقوع آن در Episode باشد.

هدف این کار، استفاده از اولین بازدید هر State-Action Pair در محاسبه Return است.

توجه: First-Visit بودن به‌خودی‌خود به معنای جلوگیری قطعی از Overestimation نیست؛ بلکه یکی از روش‌های تعریف تخمین Monte Carlo است.

### **۸.۴. Every-Visit Monte Carlo**

در Every-Visit Monte Carlo، تمام بازدیدهای یک State-Action Pair در Episode برای محاسبه تخمین استفاده می‌شوند.

| First-Visit MC                        | Every-Visit MC                         |
| ------------------------------------- | -------------------------------------- |
| اولین بازدید در Episode               | تمام بازدیدها                          |
| هر Pair یک بار در هر Episode          | هر Pair ممکن است چند بار Update شود    |
| از Return اولین بازدید استفاده می‌کند | از Return تمام بازدیدها استفاده می‌کند |

### **۸.۵. فرمول به‌روزرسانی Q-Function**

می‌توان Q-Value را با میانگین Returnهای مشاهده‌شده تخمین زد:

\\[ Q(s,a)=\frac{1}{N(s,a)} \sum\_{i=1}^{N(s,a)}G_i \\]

که در آن:

- \\(N(s,a)\\): تعداد نمونه‌های مورد استفاده
- \\(G_i\\): Return مشاهده‌شده در نمونه شماره \\(i\\)

همچنین می‌توان از Incremental Update استفاده کرد:

\\[ Q\_{\text{new}}(s,a)= Q\_{\text{old}}(s,a)+ \alpha[G_t-Q\_{\text{old}}(s,a)] \\]

در این فرمول:

- \\(\alpha\\): Learning Rate
- \\(G_t\\): Return واقعی
- اختلاف میان Return واقعی و تخمین قبلی، مقدار اصلاح را تعیین می‌کند.

### **۸.۶. Policy Improvement در Monte Carlo Control**

بعد از تخمین Q-Valueها، Policy را بهبود می‌دهیم.

اما برای حفظ Exploration، معمولاً از Epsilon-Greedy استفاده می‌کنیم.

یعنی Agent همیشه بهترین Action شناخته‌شده را انتخاب نمی‌کند و همچنان احتمال انتخاب Action تصادفی وجود دارد.

### **۸.۷. چرخه Monte Carlo Control**

```
        Initialize Q
             |
             v
      Initialize Policy
             |
             v
      Start New Episode
             |
             v
       Collect Experience
             |
             v
       Episode Finished?
             |
             v
       Calculate Returns
             |
             v
       Update Q-Values
             |
             v
       Improve Policy
             |
             v
         Next Episode
             |
             v
            Repeat
```

### **۸.۸. محدودیت Monte Carlo Control**

مهم‌ترین محدودیت Monte Carlo این است که برای محاسبه Return واقعی باید منتظر پایان Episode بمانیم.

این موضوع در محیط‌هایی که Episodeهای طولانی دارند یا پایان مشخصی ندارند، مشکل‌ساز است.

برای مثال، در کنترل یک Robot ممکن است بخواهیم بعد از هر Action، تخمین خود را اصلاح کنیم؛ نه اینکه تا پایان یک مسیر طولانی منتظر بمانیم.

این مسئله انگیزه استفاده از Temporal Difference Learning و الگوریتم SARSA است.

## **۹. SARSA: Improving Policies After Each Step**

On-Policy

Temporal Difference

SARSA یکی از مهم‌ترین الگوریتم‌های فصل ششم است.

برخلاف Monte Carlo که برای Update کردن تخمین‌ها منتظر پایان Episode می‌ماند، SARSA می‌تواند بعد از هر Time Step یادگیری خود را به‌روزرسانی کند.

### **۹.۱. SARSA چیست؟**

SARSA مخفف پنج مؤلفه زیر است:

- S: State
- A: Action
- R: Reward
- S: Next State
- A: Next Action

این پنج مؤلفه دقیقاً اطلاعاتی هستند که برای به‌روزرسانی Q-Function در SARSA استفاده می‌شوند.

### **۹.۲. نحوه عملکرد SARSA**

فرض کن Agent در State فعلی قرار دارد.

مراحل کار:

1. State فعلی \\(S_t\\) را مشاهده می‌کند.
2. Action فعلی \\(A_t\\) را انتخاب می‌کند.
3. Action را اجرا می‌کند.
4. Reward دریافت می‌کند.
5. به State بعدی \\(S\_{t+1}\\) منتقل می‌شود.
6. Action بعدی \\(A\_{t+1}\\) را انتخاب می‌کند.
7. Q-Function را Update می‌کند.

نکته مهم این است که SARSA از Action واقعی انتخاب‌شده در State بعدی برای محاسبه Target استفاده می‌کند.

### **۹.۳. فرمول SARSA**

فرمول به‌روزرسانی SARSA:

\\[ Q(S_t,A_t)\leftarrow Q(S_t,A_t) +\alpha[ R\_{t+1}+ \gamma Q(S\_{t+1},A\_{t+1}) -Q(S_t,A_t)] \\]

اجزای فرمول:

| نماد                       | مفهوم                  |
| -------------------------- | ---------------------- |
| \\(S_t\\)                  | State فعلی             |
| \\(A_t\\)                  | Action فعلی            |
| \\(R\_{t+1}\\)             | Reward دریافتی         |
| \\(S\_{t+1}\\)             | State بعدی             |
| \\(A\_{t+1}\\)             | Action بعدی            |
| \\(\alpha\\)               | Learning Rate          |
| \\(\gamma\\)               | Discount Factor        |
| \\(Q(S_t,A_t)\\)           | تخمین ارزش فعلی        |
| \\(Q(S\_{t+1},A\_{t+1})\\) | تخمین ارزش Action بعدی |

### **۹.۴. Temporal Difference Error در SARSA**

در SARSA ابتدا Target را محاسبه می‌کنیم:

\\[ Target= R\_{t+1}+ \gamma Q(S\_{t+1},A\_{t+1}) \\]

سپس اختلاف Target با تخمین فعلی را محاسبه می‌کنیم.

این اختلاف، Temporal Difference Error یا TD Error نام دارد:

\\[ \delta_t= R\_{t+1}+ \gamma Q(S\_{t+1},A\_{t+1}) -Q(S_t,A_t) \\]

در نهایت:

\\[ Q\_{\text{new}}=Q\_{\text{old}}+\alpha\delta_t \\]

**مفهوم TD Error:**

TD Error نشان می‌دهد تخمین فعلی Agent چقدر با تخمین جدید مبتنی بر تجربه و ارزش آینده تفاوت دارد.

اگر TD Error مثبت باشد، تخمین فعلی افزایش پیدا می‌کند.

اگر TD Error منفی باشد، تخمین فعلی کاهش پیدا می‌کند.

### **۹.۵. چرا SARSA یک On-Policy Algorithm است؟**

در SARSA، Agent با یک Policy در محیط عمل می‌کند و همان Policy مبنای یادگیری آن است.

برای مثال، اگر Agent از Epsilon-Greedy استفاده کند، ممکن است در State بعدی یک Action تصادفی انتخاب کند.

SARSA ارزش همان Action انتخاب‌شده را در Target قرار می‌دهد.

بنابراین یادگیری آن با رفتار واقعی Agent هماهنگ است.

### **۹.۶. SARSA در مقایسه با Monte Carlo**

| ویژگی         | Monte Carlo Control  | SARSA                |
| ------------- | -------------------- | -------------------- |
| نوع یادگیری   | Episode-Based        | Step-Based           |
| زمان Update   | پایان Episode        | بعد از هر Step       |
| روش           | Monte Carlo          | Temporal Difference  |
| Bootstrapping | ندارد                | دارد                 |
| Target        | Return واقعی         | Reward و تخمین آینده |
| On/Off-Policy | On-Policy در این روش | On-Policy            |

### **۹.۷. Bootstrapping در SARSA**

یکی از مفاهیم مهم این الگوریتم، Bootstrapping است.

Bootstrapping یعنی استفاده از تخمین فعلی برای به‌روزرسانی تخمین دیگر.

در SARSA، به جای اینکه منتظر Return واقعی تا پایان Episode بمانیم، از Q-Value تخمینی State و Action بعدی استفاده می‌کنیم.

\\[ R\_{t+1}+\gamma Q(S\_{t+1},A\_{t+1}) \\]

این ویژگی باعث می‌شود SARSA بتواند به‌صورت تدریجی یاد بگیرد.

### **۹.۸. چرخه SARSA**

```
       Observe State (S)
              |
              v
       Select Action (A)
              |
              v
        Execute Action
              |
              v
        Receive Reward
              |
              v
        Observe Next State
              |
              v
       Select Next Action
              |
              v
        Calculate TD Error
              |
              v
          Update Q
              |
              v
         Next Step
              |
              v
            Repeat
```

## **۱۰. Q-Learning: Learning to Act Optimally, Even If We Choose Not To**

Off-Policy و Temporal Difference

Q-Learning یکی از مهم‌ترین الگوریتم‌های Reinforcement Learning است.

ایده اصلی آن یادگیری Optimal Action-Value Function است؛ حتی اگر Agent هنگام جمع‌آوری تجربه‌ها همیشه از بهترین Action استفاده نکند.

### **۱۰.۱. ایده اصلی Q-Learning**

در SARSA، Agent از Action واقعی انتخاب‌شده در State بعدی برای Update استفاده می‌کرد.

اما در Q-Learning، Agent به جای استفاده از Action واقعی بعدی، بیشترین Q-Value تخمین‌زده‌شده در State بعدی را در نظر می‌گیرد.

یعنی:

\\[ \max\_{a'}Q(S\_{t+1},a') \\]

به عبارت دیگر، Q-Learning فرض می‌کند در State بعدی بهترین Action ممکن انتخاب خواهد شد.

### **۱۰.۲. فرمول Q-Learning**

\\[ Q(S_t,A_t)\leftarrow Q(S_t,A_t) +\alpha[ R\_{t+1}+ \gamma\max\_{a'}Q(S\_{t+1},a') -Q(S_t,A_t)] \\]

تفاوت اصلی آن با SARSA در قسمت Target است.

\\[ SARSA: R+\gamma Q(S',A') \\]

\\[ Q\text{-Learning}: R+\gamma\max\_{a'}Q(S',a') \\]

### **۱۰.۳. چرا Q-Learning یک Off-Policy Algorithm است؟**

در Q-Learning دو Policy را باید از یکدیگر متمایز کنیم:

**Behavior Policy**

Policy مورد استفاده برای انتخاب Action و تعامل با محیط.

**Target Policy**

Policy مورد استفاده برای یادگیری و تخمین ارزش Actionها.

در Q-Learning:

- Behavior Policy می‌تواند Epsilon-Greedy باشد.
- Target Policy به‌صورت Greedy و بر اساس بیشترین Q-Value تعریف می‌شود.

بنابراین Agent می‌تواند برای Exploration، Action تصادفی انتخاب کند؛ اما همچنان ارزش بهترین Action ممکن را یاد بگیرد.

### **۱۰.۴. تفاوت SARSA و Q-Learning**

این یکی از مهم‌ترین مقایسه‌های فصل است.

| ویژگی       | SARSA                  | Q-Learning               |
| ----------- | ---------------------- | ------------------------ |
| نوع         | On-Policy              | Off-Policy               |
| Target      | Action واقعی بعدی      | بهترین Action بعدی       |
| Exploration | در Target لحاظ می‌شود  | در Target لحاظ نمی‌شود   |
| یادگیری     | ارزش رفتار Policy فعلی | ارزش رفتار Greedy بهینه  |
| فرمول آینده | \\(Q(S',A')\\)         | \\(\max\_{a'}Q(S',a')\\) |

### **۱۰.۵. مثال ساده برای تفاوت SARSA و Q-Learning**

فرض کن Agent در یک Maze قرار دارد.

دو مسیر وجود دارد:

- مسیر اول کوتاه است، اما در نزدیکی یک منطقه خطرناک قرار دارد.
- مسیر دوم طولانی‌تر است، اما امنیت بیشتری دارد.

اگر Agent از Epsilon-Greedy استفاده کند، ممکن است هنگام حرکت در مسیر اول، به‌صورت تصادفی وارد منطقه خطرناک شود.

**SARSA:**

از Action واقعی انتخاب‌شده در State بعدی استفاده می‌کند.

بنابراین اگر Exploration باعث انتخاب یک Action نامناسب شود، این موضوع در Target و یادگیری آن لحاظ خواهد شد.

**Q-Learning:**

از بهترین Action تخمین‌زده‌شده در State بعدی استفاده می‌کند.

بنابراین ارزش بهترین مسیر را یاد می‌گیرد، حتی اگر Behavior Policy در عمل Action دیگری را انتخاب کرده باشد.

در نتیجه، SARSA به رفتار اکتشافی واقعی حساس است؛ اما Q-Learning ارزش Policy هدف Greedy را یاد می‌گیرد.

### **۱۰.۶. تفاوت در محیط‌های پرخطر**

این تفاوت در محیط‌هایی که Actionهای تصادفی می‌توانند پیامدهای منفی داشته باشند، اهمیت بیشتری پیدا می‌کند.

برای مثال:

- Robot Navigation
- مسیرهای نزدیک به موانع
- محیط‌های دارای خطر
- بازی‌هایی با جریمه‌های سنگین

در چنین محیط‌هایی SARSA ممکن است رفتار محافظه‌کارانه‌تری یاد بگیرد؛ چون اثر Exploration را در Update خود لحاظ می‌کند.

البته این یک نتیجه وابسته به محیط و تنظیمات الگوریتم است، نه یک قانون همیشگی.

### **۱۰.۷. چرخه Q-Learning**

```
       Observe State (S)
              |
              v
       Select Action (A)
         Epsilon-Greedy
              |
              v
        Execute Action
              |
              v
        Receive Reward
              |
              v
        Observe Next State
              |
              v
      Find Maximum Next Q
              |
              v
        Calculate TD Error
              |
              v
          Update Q
              |
              v
         Next Step
              |
              v
            Repeat
```

## **۱۱. On-Policy و Off-Policy**

این دو مفهوم از مهم‌ترین دسته‌بندی‌های الگوریتم‌های Reinforcement Learning هستند.

### **۱۱.۱. On-Policy**

در On-Policy، Agent درباره همان Policy یاد می‌گیرد که با آن در محیط تعامل می‌کند.

مثال:

- SARSA
- On-Policy Monte Carlo Control

### **۱۱.۲. Off-Policy**

در Off-Policy، Agent می‌تواند با یک Policy تجربه جمع‌آوری کند، اما درباره Policy دیگری یاد بگیرد.

مثال:

- Q-Learning
- Double Q-Learning

### **۱۱.۳. مقایسه مفهومی**

```
ON-POLICY

Behavior Policy
       |
       v
Interact with Environment
       |
       v
Collect Experience
       |
       v
Learn About Same Policy
```

```
OFF-POLICY

Behavior Policy
       |
       v
Interact with Environment
       |
       v
Collect Experience
       |
       v
Learn About Target Policy
```

### **۱۱.۴. مزایا و محدودیت‌ها**

| On-Policy                                 | Off-Policy                                    |
| ----------------------------------------- | --------------------------------------------- |
| یادگیری از رفتار واقعی Agent              | امکان یادگیری از رفتار متفاوت                 |
| Target با رفتار جاری هماهنگ است           | Target می‌تواند مستقل از رفتار باشد           |
| در SARSA اثر Exploration لحاظ می‌شود      | در Q-Learning هدف Greedy است                  |
| ممکن است از نظر نمونه‌برداری محدودتر باشد | امکان استفاده از تجربه‌های متنوع‌تر وجود دارد |

نکته: Off-Policy بودن به معنی سریع‌تر بودن قطعی الگوریتم نیست. سرعت همگرایی و پایداری به محیط، الگوریتم، Exploration و تنظیمات بستگی دارد.

## **۱۲. GLIE: Greedy in the Limit with Infinite Exploration**

مفهوم مهم تئوری

GLIE یکی از مفاهیم مهم برای درک شرایط همگرایی الگوریتم‌های مبتنی بر Exploration است.

GLIE مخفف عبارت زیر است:

**Greedy in the Limit with Infinite Exploration**

این مفهوم دو شرط اصلی دارد:

### **۱۲.۱. Infinite Exploration**

Agent باید در طول زمان تمام State-Action Pairهای قابل دسترس را به تعداد کافی و نامحدود بررسی کند.

یعنی نباید برخی Actionها را برای همیشه نادیده بگیرد.

هدف این است که Agent فرصت جمع‌آوری اطلاعات درباره تمام انتخاب‌های مهم را داشته باشد.

### **۱۲.۲. Greedy in the Limit**

با گذشت زمان، Policy باید به سمت انتخاب Action دارای بیشترین ارزش تخمینی حرکت کند.

به زبان ساده:

- در ابتدا Exploration بیشتر است.
- با افزایش تجربه، Exploration کاهش پیدا می‌کند.
- در حد نهایی، Agent به رفتار Greedy نزدیک می‌شود.

### **۱۲.۳. ارتباط GLIE با Epsilon-Greedy**

یکی از روش‌های پیاده‌سازی Exploration، استفاده از Epsilon-Greedy با Epsilon کاهشی است.

اما یک نکته بسیار مهم وجود دارد:

صرفاً کاهش Epsilon به صفر برای تضمین GLIE کافی نیست.

برای داشتن Infinite Exploration، کاهش آن باید به شکلی باشد که احتمال انتخاب Actionهای مختلف در طول آموزش همچنان فرصت کافی برای اکتشاف فراهم کند.

به‌طور نظری، شرایطی مانند موارد زیر برای همگرایی Q-Learning نیز اهمیت دارند:

- همه State-Action Pairهای مربوطه به تعداد کافی بازدید شوند.
- Learning Rate مناسب باشد.
- شرایط محیط و پاداش‌ها با فرضیات نظری الگوریتم سازگار باشند.

### **۱۲.۴. مقایسه GLIE و Epsilon-Greedy**

| مفهوم            | توضیح                                             |
| ---------------- | ------------------------------------------------- |
| Epsilon-Greedy   | یک روش انتخاب Action                              |
| Decaying Epsilon | کاهش تدریجی Exploration                           |
| GLIE             | مجموعه شرایط Exploration و Greedy شدن در حد نهایی |

نکته کلیدی:

GLIE یک الگوریتم انتخاب Action نیست؛ بلکه یک ویژگی یا شرط نظری برای رفتار Exploration است.

## **۱۳. Double Q-Learning**

Off-Policy

کاهش Maximization Bias

Double Q-Learning نسخه‌ای از Q-Learning است که برای کاهش مشکل Overestimation یا بیش‌برآورد ارزش Actionها طراحی شده است.

### **۱۳.۱. مشکل Q-Learning چیست؟**

در Q-Learning برای محاسبه Target از بیشترین Q-Value تخمین‌زده‌شده در State بعدی استفاده می‌کنیم:

\\[ \max\_{a'}Q(S',a') \\]

اما این مقادیر تخمینی هستند و ممکن است خطا داشته باشند.

مشکل این است که وقتی از میان چند تخمین، بیشترین مقدار را انتخاب می‌کنیم، احتمال انتخاب یک تخمین دارای خطای مثبت افزایش پیدا می‌کند.

این مشکل را Maximization Bias می‌نامیم.

### **۱۳.۲. مثال Maximization Bias**

فرض کن ارزش واقعی تمام Actionها برابر صفر باشد.

اما تخمین‌های Agent به دلیل خطای تخمین به شکل زیر باشند:

| Action | تخمین Q | ارزش واقعی |
| ------ | ------- | ---------- |
| A      | 0.11    | 0          |
| B      | 0.65    | 0          |
| C      | -0.44   | 0          |
| D      | -0.26   | 0          |

بیشترین تخمین:

\\[ \max(0.11,0.65,-0.44,-0.26)=0.65 \\]

در حالی که بیشترین ارزش واقعی برابر صفر است.

پس Agent به‌اشتباه فکر می‌کند بهترین Action ارزشی بیشتر از واقعیت دارد.

این اتفاق می‌تواند در به‌روزرسانی‌های متوالی ادامه پیدا کند و تخمین ارزش‌ها را بیش از حد افزایش دهد.

### **۱۳.۳. راه‌حل Double Q-Learning**

Double Q-Learning به جای یک Q-Function از دو Q-Function مستقل استفاده می‌کند:

\\[ Q_1(s,a) \\]

\\[ Q_2(s,a) \\]

ایده اصلی:

یکی از Q-Functionها Action را انتخاب می‌کند و دیگری ارزش آن Action را تخمین می‌زند.

این کار باعث می‌شود انتخاب Action و ارزیابی ارزش آن کاملاً بر اساس یک تخمین واحد انجام نشود.

### **۱۳.۴. نحوه عملکرد Double Q-Learning**

فرض کن می‌خواهیم \\(Q_1\\) را Update کنیم.

ابتدا با استفاده از \\(Q_1\\)، بهترین Action بعدی را پیدا می‌کنیم:

\\[ a^\*=\arg\max\_{a'}Q_1(S',a') \\]

سپس ارزش آن Action را با \\(Q_2\\) تخمین می‌زنیم:

\\[ Target= R+\gamma Q_2(S',a^\*) \\]

در نتیجه:

\\[ Q_1(S,A)\leftarrow Q_1(S,A) +\alpha[ R+\gamma Q_2(S',a^\*)-Q_1(S,A)] \\]

برای Update کردن \\(Q_2\\)، همین فرآیند را برعکس انجام می‌دهیم:

\\[ a^\*=\arg\max\_{a'}Q_2(S',a') \\]

\\[ Target=R+\gamma Q_1(S',a^\*) \\]

### **۱۳.۵. چرا دو Q-Function داریم؟**

در Q-Learning معمولی، یک تابع هم Action را انتخاب می‌کند و هم ارزش آن را تخمین می‌زند.

اما در Double Q-Learning این دو نقش میان دو تابع تقسیم می‌شوند.

```
             Q1 Function
                  |
                  v
          Select Best Action
                  |
                  v
             Action (a*)
                  |
                  v
             Q2 Function
                  |
                  v
          Estimate Action Value
                  |
                  v
             Calculate TD
                  |
                  v
              Update Q1
```

در Update بعدی می‌توان نقش دو تابع را معکوس کرد.

معمولاً با یک انتخاب تصادفی مشخص می‌شود که کدام Q-Function در آن Step به‌روزرسانی شود.

### **۱۳.۶. انتخاب Action برای تعامل با محیط**

برای انتخاب Action هنگام تعامل با محیط، می‌توان از مجموع یا میانگین دو Q-Function استفاده کرد:

\\[ \pi(s)= \arg\max_a[Q_1(s,a)+Q_2(s,a)] \\]

چون تقسیم بر دو ترتیب Actionها را تغییر نمی‌دهد، استفاده از میانگین یا مجموع در این انتخاب معادل است.

### **۱۳.۷. مزایا و محدودیت‌های Double Q-Learning**

**مزایا:**

- کاهش Maximization Bias
- کاهش تمایل به Overestimation
- تخمین‌های پایدارتر در بسیاری از محیط‌ها
- بهبود عملکرد نسبت به Q-Learning در شرایط مستعد بیش‌برآورد

**محدودیت‌ها:**

- نیاز به نگهداری دو Q-Function
- پیچیدگی محاسباتی بیشتر
- ممکن است سرعت یادگیری یا همگرایی در برخی محیط‌ها کمتر شود.

نکته مهم: Double Q-Learning مشکل Overestimation را به‌طور کامل حذف نمی‌کند؛ بلکه آن را کاهش می‌دهد.

### **۱۳.۸. تفاوت Q-Learning و Double Q-Learning**

| ویژگی             | Q-Learning       | Double Q-Learning |
| ----------------- | ---------------- | ----------------- |
| تعداد Q-Function  | یک               | دو                |
| Action Selection  | یک Q             | یکی از دو Q       |
| Action Evaluation | همان Q           | Q دیگر            |
| Maximization Bias | مستعد بیش‌برآورد | کاهش بیش‌برآورد   |
| پیچیدگی           | کمتر             | بیشتر             |
| نوع               | Off-Policy       | Off-Policy        |

### **۱۳.۹. ارتباط Double Q-Learning با DDQN**

در فصل‌های بعدی کتاب با Double Deep Q-Network یا DDQN آشنا می‌شویم.

DDQN از ایده مشابهی برای کاهش Overestimation در Deep Q-Learning استفاده می‌کند.

اما نباید Double Q-Learning کلاسیک را با DDQN یکی بدانیم؛ این دو الگوریتم در ساختار و نحوه استفاده از شبکه‌های عصبی تفاوت دارند.

## **۱۴. Hyperparameters و پارامترهای مهم الگوریتم‌ها**

در این فصل چند پارامتر مهم بارها استفاده می‌شوند.

### **۱۴.۱. Learning Rate یا Alpha**

\\[ \alpha \\]

Learning Rate مشخص می‌کند در هر Update چه مقدار از TD Error یا اختلاف Return با تخمین قبلی در Q-Value اعمال شود.

- Alpha بزرگ: تغییرات سریع‌تر
- Alpha کوچک: تغییرات تدریجی‌تر

### **۱۴.۲. Discount Factor یا Gamma**

\\[ \gamma \\]

Gamma میزان اهمیت Rewardهای آینده را مشخص می‌کند.

- Gamma نزدیک صفر: اهمیت بیشتر Rewardهای فوری
- Gamma نزدیک یک: اهمیت بیشتر Rewardهای بلندمدت

### **۱۴.۳. Exploration Rate یا Epsilon**

\\[ \epsilon \\]

Epsilon احتمال انتخاب Action تصادفی در Epsilon-Greedy را مشخص می‌کند.

- Epsilon بزرگ: Exploration بیشتر
- Epsilon کوچک: Exploitation بیشتر

### **۱۴.۴. Decay Schedule**

در این فصل از Decay Schedule برای کنترل تدریجی پارامترهای Alpha و Epsilon استفاده می‌شود.

یعنی مقادیر اولیه به‌مرور به سمت مقادیر حداقلی حرکت می‌کنند.

| پارامتر | هدف از Decay                              |
| ------- | ----------------------------------------- |
| Alpha   | کاهش شدت Updateها                         |
| Epsilon | کاهش Exploration و افزایش Greedy Behavior |

البته کاهش Learning Rate و Epsilon لزوماً باید با یک برنامه یکسان انجام نشود.

### **۱۴.۵. تفاوت Alpha و Epsilon**

این دو پارامتر نباید با یکدیگر اشتباه گرفته شوند.

- Alpha تعیین می‌کند Agent چقدر یاد بگیرد و Q-Value را تغییر دهد.
- Epsilon تعیین می‌کند Agent چقدر Exploration انجام دهد.

به زبان ساده:

```
Alpha
  |
  v
How much to learn?


Epsilon
  |
  v
How much to explore?
```

### **چرا این محیط اهمیت دارد؟**

با استفاده از این محیط می‌توان بررسی کرد:

- Agent چگونه از تجربه یاد می‌گیرد؟
- چگونه Policy خود را بهبود می‌دهد؟
- Exploration چه تأثیری بر رفتار Agent دارد؟
- SARSA و Q-Learning چه تفاوتی در یادگیری دارند؟
- Double Q-Learning چگونه با Maximization Bias مقابله می‌کند؟

هدف آزمایش، مقایسه عملکرد این الگوریتم‌ها در یک محیط تصادفی و بررسی نحوه یادگیری Policy بهینه است.

## **۱۷. Batch Learning و Online Learning**

در این فصل همچنین به Batch Learning نیز اشاره شده است.

این دو اصطلاح به نحوه استفاده از داده‌ها در فرآیند یادگیری اشاره دارند.

### **Online Learning**

در Online Learning، Agent با دریافت تجربه‌های جدید، به‌صورت تدریجی یادگیری خود را به‌روزرسانی می‌کند.

مثلاً SARSA بعد از هر Step می‌تواند Q-Value را Update کند.

### **Batch Learning**

در Batch Learning، مجموعه‌ای از داده‌ها جمع‌آوری می‌شوند و سپس برای انجام Updateهای یادگیری مورد استفاده قرار می‌گیرند.

این روش برای زمانی مناسب است که Dataset بزرگی از قبل در اختیار داریم.

| Online Learning            | Batch Learning                  |
| -------------------------- | ------------------------------- |
| یادگیری تدریجی             | یادگیری با مجموعه‌ای از داده‌ها |
| Updateهای پیوسته           | Update با Batch داده            |
| مناسب جریان تجربه‌های جدید | مناسب Datasetهای جمع‌آوری‌شده   |

نکته: Batch Learning و Offline RL دقیقاً یک مفهوم نیستند. Batch Learning به شیوه به‌روزرسانی مدل اشاره دارد، در حالی که Offline RL به یادگیری از Dataset ثابت بدون تعامل جدید با محیط اشاره می‌کند.

## **۱۸. Stochastic Approximation و شرایط همگرایی**

یکی از مفاهیم نظری مهمی که در جمع‌بندی کتاب مطرح می‌شود، Stochastic Approximation است.

الگوریتم‌های RL معمولاً از نمونه‌های تصادفی برای تخمین Value Function استفاده می‌کنند.

به همین دلیل تخمین‌ها ممکن است در هر مرحله تغییر کنند.

Stochastic Approximation به بررسی شرایطی می‌پردازد که تحت آن این تخمین‌های تدریجی می‌توانند به مقدار مورد انتظار یا مقدار بهینه همگرا شوند.

### **ارتباط آن با Learning Rate**

در الگوریتم‌های مبتنی بر TD، مقدار Alpha اهمیت زیادی دارد.

یکی از شرایط کلاسیک برای همگرایی در مسائل جدولی، تحت فرضیات مناسب، عبارت است از:

\\[ \sum\_{t=1}^{\infty}\alpha_t=\infty \\]

و:

\\[ \sum\_{t=1}^{\infty}\alpha_t^2<\infty \\]

این شرایط نشان می‌دهند:

- Learning Rate نباید آن‌قدر سریع کاهش پیدا کند که Agent فرصت یادگیری کافی نداشته باشد.
- Learning Rate باید به‌اندازه‌ای کاهش پیدا کند که تخمین‌ها به‌تدریج تثبیت شوند.

البته این شرایط به‌تنهایی برای تضمین همگرایی کافی نیستند و فرضیات دیگری مانند بازدید کافی از State-Action Pairها نیز اهمیت دارند.

| Maximization Bias | Overestimation     | منبع سوگیری ناشی از Max در برابر بیش‌برآورد ارزش      |

# **۲۱. نکات بسیار مهم برای یادگیری و امتحان**

این موارد را باید بتوان بدون نگاه کردن به خلاصه، توضیح داد.

**۱. هدف Control چیست؟**

پیدا کردن Policy بهینه با استفاده از Policy Evaluation و Policy Improvement.

**۲. چرا به Q-Function نیاز داریم؟**

چون برای بهبود Policy باید ارزش Actionهای مختلف را در هر State مقایسه کنیم.

**۳. GPI چیست؟**

تعامل مداوم Policy Evaluation و Policy Improvement برای حرکت به سمت Policy بهینه.

**۴. تفاوت Monte Carlo و SARSA چیست؟**

Monte Carlo بعد از پایان Episode به‌روزرسانی می‌کند؛ SARSA بعد از هر Step.

**۵. SARSA چرا On-Policy است؟**

چون از Action واقعی انتخاب‌شده توسط Policy رفتاری در Target استفاده می‌کند.

**۶. Q-Learning چرا Off-Policy است؟**

چون از بهترین Action تخمینی برای Update استفاده می‌کند، نه لزوماً Action واقعی انتخاب‌شده.

**۷. مهم‌ترین تفاوت SARSA و Q-Learning چیست؟**

تفاوت در Target آن‌ها است:

\\[ SARSA: Q(S',A') \\]

\\[ Q\text{-Learning}: \max\_{a'}Q(S',a') \\]

**۸. Maximization Bias چیست؟**

بیش‌برآورد ارزش Actionها به دلیل انتخاب بیشترین مقدار از میان تخمین‌های دارای خطا.

**۹. Double Q-Learning چه مشکلی را حل می‌کند؟**

با جدا کردن Action Selection از Action Evaluation، مشکل Maximization Bias را کاهش می‌دهد.

**۱۰. GLIE چیست؟**

تضمین Exploration نامحدود در کنار Greedy شدن Policy در حد نهایی، تحت شرایط مناسب.

# **۲۲. فرمول‌های ضروری فصل ششم**

برگه فرمول.

**۱. State-Value Function**

\\[ V^\pi(s)=\mathbb{E}\_\pi[G_t\mid S_t=s] \\]

**۲. Action-Value Function**

\\[ Q^\pi(s,a)=\mathbb{E}\_\pi[G_t\mid S_t=s,A_t=a] \\]

**۳. Greedy Policy**

\\[ \pi(s)=\arg\max_a Q(s,a) \\]

**۴. Epsilon-Greedy**

\\[ P(\text{Random Action})=\epsilon \\]

\\[ P(\text{Greedy Action})=1-\epsilon \\]

**۵. Monte Carlo Incremental Update**

\\[ Q\_{\text{new}}=Q\_{\text{old}}+\alpha(G_t-Q\_{\text{old}}) \\]

**۶. SARSA Target**

\\[ Target=R\_{t+1}+\gamma Q(S\_{t+1},A\_{t+1}) \\]

**۷. SARSA Update**

\\[ Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha\delta_t \\]

**۸. SARSA TD Error**

\\[ \delta_t=R\_{t+1}+\gamma Q(S\_{t+1},A\_{t+1})-Q(S_t,A_t) \\]

**۹. Q-Learning Target**

\\[ Target=R\_{t+1}+\gamma\max\_{a'}Q(S\_{t+1},a') \\]

**۱۰. Q-Learning Update**

\\[ Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha\delta_t \\]

**۱۱. Double Q-Learning Target**

\\[ a^\*=\arg\max\_{a'}Q_1(S',a') \\]

\\[ Target=R+\gamma Q_2(S',a^\*) \\]

# **۲۳. جمع‌بندی نهایی فصل ششم**

فصل ششم نقطه‌ای است که Reinforcement Learning از ارزیابی رفتار به سمت بهینه‌سازی رفتار حرکت می‌کند.

در ابتدای فصل یاد گرفتیم که یک RL Agent سه وظیفه اصلی دارد:

1. جمع‌آوری تجربه
2. تخمین ارزش‌ها
3. بهبود Policy

سپس با Generalized Policy Iteration آشنا شدیم که اساس بسیاری از الگوریتم‌های RL است. این چارچوب از تعامل میان Policy Evaluation و Policy Improvement تشکیل می‌شود.

بعد از آن سه خانواده مهم از روش‌های Control را بررسی کردیم:

- Monte Carlo Control: یادگیری از Return واقعی پس از پایان Episode.
- SARSA: یادگیری تدریجی و On-Policy با استفاده از Action واقعی بعدی.
- Q-Learning: یادگیری Off-Policy با استفاده از بهترین Action تخمینی.

در نهایت Double Q-Learning را بررسی کردیم که با استفاده از دو Q-Function مشکل Maximization Bias را کاهش می‌دهد.

**پیام اصلی فصل در یک جمله:**

Reinforcement Learning فقط یادگیری ارزش Stateها نیست؛ بلکه Agent باید با جمع‌آوری تجربه، تخمین ارزش Actionها و بهبود مداوم Policy یاد بگیرد چگونه بهترین تصمیم‌ها را بگیرد.

**پیشنهاد برای مطالعه:** مهم‌ترین بخش‌هایی که باید واقعاً درک شوند، GPI، تفاوت SARSA و Q-Learning، مفهوم Bootstrapping و Maximization Bias هستند. اگر این چهار موضوع تثبیت شوند، بخش بزرگی از منطق فصل ششم درک شده است..
