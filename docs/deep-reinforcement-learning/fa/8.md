نکته مهم این است که فصل فقط درباره شبکه‌های عصبی نیست؛ بلکه ارتباط چند مفهوم اساسی را توضیح می‌دهد:

3. Multi-Armed Bandit و تفاوت آن با Reinforcement Learning ترتیبی
4. Generalization و Function Approximation
5. تخمین State Value، Action Value و Advantage

7. معماری شبکه عصبی و تخمین Q-Values

12. مشکلات ناپایداری در یادگیری Deep RL

## **۱. تفاوت Tabular Reinforcement Learning و Deep Reinforcement Learning**

در فصل‌های قبلی، با روش‌هایی مثل Monte Carlo، TD Learning، SARSA و Q-Learning آشنا شدیم. این روش‌ها در حالت جدولی، مقادیر مربوط به Stateها یا State-Actionها را مستقیماً ذخیره و به‌روزرسانی می‌کنند.

اما این رویکرد در محیط‌های پیچیده با مشکل مواجه می‌شود.

### **۱.۱. محدودیت Tabular RL**

در Tabular RL برای هر State یا هر جفت State-Action یک مقدار جداگانه نگهداری می‌شود.

برای مثال، فرض کن یک Agent در یک محیط ساده با ۱۰۰ حالت و ۴ عمل ممکن فعالیت می‌کند.

در این حالت، می‌توان جدولی با ۴۰۰ مقدار Q ایجاد کرد.

اما اگر محیط شامل تصاویر، صداها یا داده‌های حسگر باشد، تعداد حالت‌های ممکن به‌شدت افزایش پیدا می‌کند.

مشکلات اصلی:

- **Large State Space:** تعداد بسیار زیاد Stateهای ممکن.
- **Continuous State Space:** حالت‌ها می‌توانند مقادیر پیوسته داشته باشند.
- **High-Dimensional State Space:** هر State ممکن است شامل هزاران ویژگی باشد.
- **Memory Complexity:** ذخیره‌سازی تمام Stateها و مقادیر مربوط به آن‌ها دشوار می‌شود.
- **Poor Generalization:** دانستن ارزش یک State لزوماً کمکی به تخمین ارزش Stateهای مشابه نمی‌کند.

### **۱.۲. راه‌حل: Function Approximation**

به‌جای ذخیره‌سازی جداگانه مقدار هر State، یک تابع برای تخمین مقادیر موردنیاز یاد می‌گیریم.

این تابع می‌تواند یک Neural Network باشد.

به‌جای داشتن جدول:

```
State 1  -> Q Values
State 2  -> Q Values
State 3  -> Q Values
...
State N  -> Q Values
```

یک مدل داریم:

```
State
  |
  v
Neural Network
  |
  v
Estimated Q Values
```

شبکه عصبی روابط و الگوهای موجود در داده‌ها را یاد می‌گیرد و می‌تواند برای Stateهایی که قبلاً دقیقاً مشاهده نکرده است نیز تخمین ارائه دهد.

به این قابلیت **Generalization** گفته می‌شود.

### **۱.۳. Deep Reinforcement Learning چیست؟**

Deep Reinforcement Learning ترکیبی از Reinforcement Learning و Deep Learning است.

در این رویکرد:

- Reinforcement Learning مشخص می‌کند Agent چگونه از طریق تعامل با Environment یاد بگیرد.
- Deep Learning امکان تقریب توابع پیچیده را با استفاده از Neural Network فراهم می‌کند.

برای مثال، در یک بازی ویدئویی:

```
Game Image
    |
    v
Neural Network
    |
    v
Q Values
    |
    v
Action Selection
    |
    v
Environment
    |
    v
Reward + Next State
    |
    v
Learning
```

به‌جای اینکه Agent مختصات ساده محیط را دریافت کند، می‌تواند مستقیماً از تصاویر بازی برای تصمیم‌گیری استفاده کند.

### **مقایسه Tabular RL و Deep RL**

| ویژگی              | Tabular RL             | Deep RL                         |
| ------------------ | ---------------------- | ------------------------------- |
| نمایش مقادیر       | جدول                   | تابع تقریبی                     |
| مدل یادگیری        | مقادیر مستقیم          | Neural Network                  |
| فضای کوچک و گسسته  | مناسب                  | ممکن است بیش‌ازحد پیچیده باشد   |
| فضای پیوسته        | محدود                  | مناسب‌تر                        |
| فضای با ابعاد بالا | نامناسب                | مناسب‌تر                        |
| Generalization     | محدود                  | امکان‌پذیر                      |
| هزینه محاسباتی     | معمولاً کمتر           | معمولاً بیشتر                   |
| نیاز به داده       | وابسته به پوشش Stateها | وابسته به کیفیت و تنوع نمونه‌ها |

نکته مهم: Deep RL الزاماً همیشه بهتر از Tabular RL نیست. برای محیط‌های کوچک و گسسته، روش‌های جدولی می‌توانند ساده‌تر، سریع‌تر و حتی قابل‌اعتمادتر باشند.

## **۲. انواع رویکردهای Deep Reinforcement Learning**

شبکه‌های عصبی را می‌توان به روش‌های مختلفی در Reinforcement Learning به کار برد.

چهار رویکرد اصلی عبارت‌اند از:

### **۲.۱. Value-Based Methods**

در روش‌های Value-Based، Agent ارزش Stateها یا State-Actionها را تخمین می‌زند.

هدف این است که مشخص کند کدام State یا Action ارزش بیشتری دارد.

برای مثال، در یک بازی شطرنج، مدل می‌تواند ارزش حرکت‌های مختلف را تخمین بزند و سپس حرکتی را انتخاب کند که بیشترین ارزش را دارد.

در این روش، Policy معمولاً به‌صورت غیرمستقیم از Value Function استخراج می‌شود.

مثلاً:

\\[ \pi(s)=\arg\max_a Q(s,a) \\]

یعنی در هر State، عملی انتخاب می‌شود که بیشترین Q-Value را دارد.

مثال‌ها:

- DQN
- NFQ
- DDQN

تمرکز اصلی فصل ۸

### **۲.۲. Policy-Based Methods**

در این روش، به‌جای تخمین مستقیم ارزش Actionها، خود Policy با استفاده از یک مدل یاد گرفته می‌شود.

شبکه عصبی مستقیماً نگاشت زیر را یاد می‌گیرد:

\\[ \pi(a|s) \\]

یعنی احتمال انتخاب هر Action در یک State مشخص.

برای مثال:

```
State
  |
  v
Neural Network
  |
  v
Action Probabilities
  |
  v
Action Selection
```

در این روش، Policy می‌تواند مستقیماً به‌روزرسانی شود.

مثال معروف:

\- REINFORCE

### **۲.۳. Actor-Critic Methods**

این روش ترکیبی از Value-Based و Policy-Based است.

دو بخش اصلی دارد:

**Actor**

مسئول انتخاب Action است و Policy را یاد می‌گیرد.

**Critic**

عملکرد Actor را ارزیابی می‌کند و ارزش State یا Action را تخمین می‌زند.

```
             State
               |
        +------+------+
        |             |
        v             v
      Actor         Critic
        |             |
        v             v
      Action      Value Estimate
        |             |
        +------+------+
               |
         Policy Update
```

در واقع Actor تصمیم می‌گیرد و Critic به ارزیابی کیفیت تصمیم کمک می‌کند.

مثال‌ها:

- A2C
- A3C
- DDPG
- PPO
- SAC

### **۲.۴. Model-Based Methods**

در Model-Based RL، Agent تلاش می‌کند مدلی از Environment یاد بگیرد یا از مدل موجود استفاده کند.

این مدل معمولاً شامل موارد زیر است:

- Transition Model: پیش‌بینی State بعدی.
- Reward Model: پیش‌بینی Reward.

به کمک این مدل، Agent می‌تواند پیامد Actionهای مختلف را پیش‌بینی و برای آینده برنامه‌ریزی کند.

```
Current State
      |
      v
Environment Model
      |
      v
Predicted Next State
      |
      v
Predicted Reward
      |
      v
Planning
      |
      v
Action Selection
```

مثلاً یک خودروی خودران می‌تواند با پیش‌بینی حرکت خودروهای اطراف، پیامد تصمیم‌های مختلف را بررسی کند.

نکته: Model-Based و Model-Free یک دسته‌بندی مستقل از Value-Based و Policy-Based هستند. بنابراین این دسته‌بندی‌ها الزاماً چهار گزینه کاملاً هم‌سطح و ناسازگار با یکدیگر نیستند.

### **۲.۵. Gradient-Free Methods**

در برخی روش‌های بهینه‌سازی، برای بهبود Policy یا پارامترهای مدل از Gradient Descent استفاده نمی‌شود.

به این روش‌ها Gradient-Free Optimization گفته می‌شود.

این روش‌ها به‌جای محاسبه مشتق تابع هدف، از تکنیک‌هایی مانند جست‌وجوی جمعیتی یا تکامل برای پیدا کردن راه‌حل بهتر استفاده می‌کنند.

مثال:

- Evolution Strategies
- Genetic Algorithms
- CMA-ES

این روش‌ها در دسته‌بندی روش‌های یادگیری RL قرار می‌گیرند، اما لزوماً روش‌های Value-Based نیستند.

## **۳. سه ویژگی اصلی Feedback در Reinforcement Learning**

یکی از مفاهیم بسیار مهم فصل ۸، بررسی نوع Feedback مورد استفاده در Deep Reinforcement Learning است.

بر اساس کتاب، Agentهای Deep RL با سه ویژگی اصلی Feedback مواجه هستند:

1. Sequential Feedback
2. Evaluative Feedback
3. Sampled Feedback

این سه ویژگی را باید از یکدیگر تفکیک کنیم.

### **۳.۱. Sequential Feedback**

Sequential Feedback یعنی تصمیم‌های Agent روی وضعیت آینده و نتایج تصمیم‌های بعدی تأثیر می‌گذارند.

برای مثال، در یک بازی:

- حرکت اول ممکن است موقعیت Agent را تغییر دهد.
- موقعیت جدید روی انتخاب حرکت دوم تأثیر می‌گذارد.
- حرکت دوم می‌تواند Reward نهایی را تغییر دهد.

بنابراین ارزش یک Action فقط به Reward فوری آن وابسته نیست.

\\[ G_t=R\_{t+1}+\gamma R\_{t+2}+\gamma^2R\_{t+3}+\cdots \\]

این مفهوم را در MDPها و Reinforcement Learning قبلی بررسی کردیم.

### **۳.۲. Evaluative Feedback**

Evaluative Feedback یعنی Agent به‌جای دریافت پاسخ صحیح، فقط بازخوردی درباره کیفیت تصمیم خود دریافت می‌کند.

مثلاً:

یک Agent در یک بازی حرکتی انجام می‌دهد و ۱۰ امتیاز دریافت می‌کند.

اما کسی به او نمی‌گوید:

- آیا Action انتخاب‌شده صحیح بود؟
- آیا Action دیگری بهتر بود؟
- اگر Action متفاوتی انتخاب می‌کرد، چه اتفاقی می‌افتاد؟

Agent فقط نتیجه تصمیم خود را مشاهده می‌کند و باید کیفیت تصمیم را از روی آن یاد بگیرد.

### **مقایسه Evaluative و Instructive Feedback**

| Evaluative Feedback               | Instructive Feedback               |
| --------------------------------- | ---------------------------------- |
| ارزیابی تصمیم                     | ارائه پاسخ صحیح                    |
| دریافت Reward                     | دریافت Label                       |
| مشخص نمی‌کند کدام Action بهتر بود | پاسخ مطلوب را مشخص می‌کند          |
| نیازمند Exploration               | معمولاً نیازمند کشف پاسخ صحیح نیست |

در Supervised Learning، برای مثال در Classification، مدل Label صحیح را دریافت می‌کند.

مثلاً:

```
Input: Image of a Cat
Correct Label: Cat
Model Prediction: Dog
Feedback: Wrong
```

اما در Reinforcement Learning:

```
State
  |
  v
Agent selects Action
  |
  v
Environment returns Reward
  |
  v
Agent evaluates the outcome
```

نکته: Reward بالا یا پایین لزوماً به معنی درست یا غلط بودن یک Action نیست؛ زیرا ممکن است پیامد واقعی آن در بلندمدت مشخص شود.

### **۳.۳. Sampled Feedback**

Sampled Feedback یعنی Agent تنها بخشی از تجربه‌ها و داده‌های ممکن را مشاهده می‌کند.

در محیط‌های پیچیده، نمی‌توان تمام Stateها، Actionها و پیامدهای ممکن را بررسی کرد.

برای مثال، یک Agent که با تصاویر یک بازی آموزش می‌بیند، فقط تصاویر و تجربه‌هایی را مشاهده می‌کند که در جریان تعامل یا نمونه‌گیری به دست آورده است.

بنابراین:

- تمام Stateهای ممکن مشاهده نمی‌شوند.
- تمام Actionهای ممکن آزمایش نمی‌شوند.
- تمام پیامدهای ممکن در دسترس نیستند.

Agent باید از نمونه‌های محدود، الگوهای کلی را یاد بگیرد.

### **۳.۴. مقایسه سه نوع Feedback**

| روش یادگیری               | Sequential   | Evaluative       | Sampled |
| ------------------------- | ------------ | ---------------- | ------- |
| Supervised Classification | خیر، معمولاً | خیر، دارای Label | بله     |
| Multi-Armed Bandit        | خیر          | بله              | بله     |
| Tabular RL                | بله          | بله              | بله     |
| Deep RL                   | بله          | بله              | بله     |

این جدول یک مقایسه مفهومی است؛ منظور از Sequential در Classification این است که نمونه‌های مستقل معمولاً وابستگی تصمیم‌گیری زمانی ندارند.

**نکته کلیدی فصل:**

Deep Reinforcement Learning با مسئله‌ای مواجه است که هم‌زمان Sequential، Evaluative و Sampled است.

به همین دلیل یادگیری در آن نسبت به Supervised Learning دشوارتر است.

## **۴. Multi-Armed Bandit و ارتباط آن با Deep RL**

در فصل‌های قبلی با Multi-Armed Bandit آشنا شدیم.

در فصل ۸ نیز از این مسئله برای توضیح تفاوت Feedback در مسائل یادگیری استفاده می‌شود.

### **۴.۱. Multi-Armed Bandit چیست؟**

فرض کن در یک Casino چند Slot Machine وجود دارد.

هر دستگاه یک Arm محسوب می‌شود.

Agent باید تصمیم بگیرد کدام دستگاه را انتخاب کند تا مجموع Reward دریافتی را افزایش دهد.

فرض کنیم سه دستگاه داریم:

```
Arm A -> Reward
Arm B -> Reward
Arm C -> Reward
```

هر بار که یک Arm انتخاب می‌شود، یک Reward دریافت می‌کنیم.

هدف، پیدا کردن Arm با بیشترین Expected Reward است.

\\[ a^\*=\arg\max_a \mathbb{E}[R|a] \\]

### **۴.۲. چرا Bandit یک مسئله One-Step است؟**

در مدل کلاسیک Bandit، انتخاب یک Arm فقط Reward همان مرحله را تعیین می‌کند و State آینده‌ای وجود ندارد که تحت تأثیر Action فعلی قرار بگیرد.

یعنی:

```
Select Arm
    |
    v
Receive Reward
    |
    v
Next Independent Decision
```

البته تجربه قبلی می‌تواند دانش Agent را درباره Armها تغییر دهد؛ اما خود انتخاب قبلی، وضعیت آینده Environment را تغییر نمی‌دهد.

### **۴.۳. تفاوت Bandit و RL ترتیبی**

| ویژگی                           | Bandit                | Reinforcement Learning |
| ------------------------------- | --------------------- | ---------------------- |
| State                           | معمولاً یک State ثابت | Stateهای مختلف         |
| Action                          | انتخاب Arm            | Actionهای مختلف        |
| Reward                          | فوری                  | فوری و بلندمدت         |
| اثر Action بر آینده Environment | ندارد                 | دارد                   |
| Sequential Feedback             | ندارد                 | دارد                   |
| Evaluative Feedback             | دارد                  | دارد                   |

### **۴.۴. مثال کاربردی Bandit**

فرض کن یک فروشگاه اینترنتی سه نسخه مختلف از یک تبلیغ دارد.

هدف این است که مشخص کنیم کدام تبلیغ بیشترین نرخ کلیک را دارد.

هر بار نمایش تبلیغ، یک تصمیم مستقل در مدل ساده Bandit است و کلیک یا عدم کلیک به‌عنوان Reward در نظر گرفته می‌شود.

این مسئله می‌تواند برای موارد زیر استفاده شود:

- تبلیغات آنلاین
- A/B Testing
- پیشنهاد محصولات
- انتخاب محتوای مناسب
- تخصیص منابع

### **نکته مهم**

در Bandit کلاسیک فرض می‌کنیم توزیع Reward هر Arm ثابت است.

اگر احتمال Reward در طول زمان تغییر کند، با یک مسئله Non-Stationary Bandit مواجه هستیم.

در این حالت، Agent باید خود را با تغییرات محیط تطبیق دهد.

## **۵. Generalization و اهمیت آن در Deep RL**

یکی از مهم‌ترین دلایل استفاده از Neural Network در Reinforcement Learning، قابلیت Generalization است.

### **۵.۱. Generalization چیست؟**

Generalization یعنی مدل بتواند از تجربه‌های قبلی خود برای تصمیم‌گیری درباره ورودی‌های جدید یا کمتر مشاهده‌شده استفاده کند.

برای مثال، فرض کن Agent برای حرکت در یک Maze آموزش می‌بیند.

اگر از روش Tabular RL استفاده کند، باید مقدار Stateهای مختلف را جداگانه یاد بگیرد.

اما یک شبکه عصبی می‌تواند الگوهایی مانند موارد زیر را یاد بگیرد:

- وجود دیوار در مسیر
- فاصله تا هدف
- مسیرهای بن‌بست
- موقعیت موانع

بنابراین می‌تواند در Stateهایی که دقیقاً قبلاً مشاهده نکرده است نیز عملکرد مناسبی داشته باشد.

### **۵.۲. مثال فضای حالت Go**

در بازی Go تعداد حالت‌های ممکن تقریباً برابر است با:

\\[ 10^{170} \\]

این تعداد آن‌قدر بزرگ است که ذخیره‌سازی تمام حالت‌ها در یک جدول عملی نیست.

شبکه عصبی به‌جای ذخیره‌سازی تمام حالت‌ها، ویژگی‌ها و الگوهای مرتبط را یاد می‌گیرد.

### **۵.۳. Sample Data و Generalization**

در Deep RL، Agent از نمونه‌های تجربه‌شده یاد می‌گیرد.

کیفیت این نمونه‌ها اهمیت زیادی دارد.

اگر نمونه‌های آموزشی نماینده مناسبی از محیط نباشند، مدل ممکن است الگوهای اشتباه یاد بگیرد.

برای مثال:

اگر یک Robot فقط در مسیرهای مستقیم آموزش ببیند، ممکن است هنگام مواجهه با پیچ‌های ناگهانی عملکرد ضعیفی داشته باشد.

بنابراین:

```
Sampled Experience
       |
       v
Neural Network
       |
       v
Learned Patterns
       |
       v
Generalization
       |
       v
Decision in New States
```

### **۵.۴. محدودیت Generalization**

Generalization همیشه موفق نیست.

مدل ممکن است:

- الگوهای اشتباه یاد بگیرد.
- در Stateهای خارج از توزیع داده‌های آموزشی ضعیف عمل کند.
- بیش‌ازحد به نمونه‌های مشاهده‌شده وابسته شود.
- برای یادگیری به داده‌های بسیار زیادی نیاز داشته باشد.

این موضوع یکی از چالش‌های مهم Deep RL است.

## **۶. Function Approximation در Reinforcement Learning**

پس از درک اهمیت Generalization، باید ببینیم دقیقاً چه چیزی را با Neural Network تخمین می‌زنیم.

به این کار Function Approximation گفته می‌شود.

### **۶.۱. Function Approximation چیست؟**

در روش جدولی، مقادیر مستقیماً ذخیره می‌شوند.

اما در Function Approximation، یک تابع پارامتری داریم که مقادیر را تخمین می‌زند.

به‌صورت کلی:

\\[ \hat{f}(x;\theta)\approx f(x) \\]

که در آن:

- \\(x\\): ورودی تابع
- \\(\theta\\): پارامترهای قابل یادگیری
- \\(\hat{f}\\): تابع تقریبی
- \\(f\\): تابع واقعی موردنظر

در Deep RL، پارامترهای این تابع می‌توانند وزن‌ها و Biasهای یک Neural Network باشند.

### **۶.۲. انواع Function Approximation**

چند روش مهم برای تقریب توابع وجود دارد:

| روش                           | توضیح                           |
| ----------------------------- | ------------------------------- |
| Tabular Representation        | ذخیره مستقیم مقادیر             |
| Linear Function Approximation | تقریب با ترکیب خطی ویژگی‌ها     |
| Tile Coding                   | تقسیم فضای State به نواحی مختلف |
| Neural Network Approximation  | تقریب با شبکه عصبی              |

در این فصل تمرکز روی Neural Network Function Approximation است.

### **۶.۳. چرا Function Approximation مهم است؟**

سه مزیت اصلی دارد:

1. امکان کار با State Spaceهای بزرگ.
2. امکان تخمین مقادیر در فضاهای پیوسته.
3. امکان Generalization به Stateهای مشاهده‌نشده.

اما یک مشکل اساسی نیز ایجاد می‌کند:

**یادگیری با Non-linear Function Approximation می‌تواند ناپایدار باشد و تضمین همگرایی روش‌های جدولی را از دست می‌دهیم.**

## **۷. Value Functions در Deep RL**

در NFQ باید تصمیم بگیریم که کدام Value Function را با Neural Network تخمین بزنیم.

سه مفهوم اصلی وجود دارند:

1. State-Value Function
2. Action-Value Function
3. Action-Advantage Function

### **۷.۱. State-Value Function**

State-Value Function ارزش یک State را نشان می‌دهد.

یعنی اگر Agent در State مشخصی قرار بگیرد و از Policy موردنظر پیروی کند، انتظار دریافت چه مقدار Return را خواهیم داشت؟

فرمول:

\\[ V^\pi(s)=\mathbb{E}\_\pi[G_t|S_t=s] \\]

مثلاً در CartPole:

اگر میله تقریباً عمودی باشد و گاری در موقعیت مناسبی قرار داشته باشد، ممکن است State ارزش بالایی داشته باشد.

اما State-Value به‌تنهایی مشخص نمی‌کند که در آن State کدام Action بهتر است.

### **۷.۲. Action-Value Function**

Action-Value Function ارزش انتخاب یک Action مشخص در یک State را نشان می‌دهد.

فرمول:

\\[ Q^\pi(s,a)=\mathbb{E}\_\pi[G_t|S_t=s,A_t=a] \\]

مثلاً در CartPole:

```
Current State
    |
    +---- Move Left  -> Q(s, Left)
    |
    +---- Move Right -> Q(s, Right)
```

اگر:

\\[ Q(s,\text{Left})=8 \\]

و:

\\[ Q(s,\text{Right})=12 \\]

آنگاه Action سمت راست از نظر تخمین مدل بهتر است.

برای انتخاب Action بهینه:

\\[ \pi(s)=\arg\max_a Q(s,a) \\]

### **۷.۳. Action-Advantage Function**

Advantage نشان می‌دهد یک Action نسبت به میانگین عملکرد Actionها در همان State چقدر بهتر یا بدتر است.

فرمول:

\\[ A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s) \\]

تفسیر:

- Advantage مثبت: Action بهتر از میانگین عملکرد Policy است.
- Advantage منفی: Action ضعیف‌تر از میانگین عملکرد Policy است.
- Advantage صفر: Action تقریباً مطابق میانگین عملکرد Policy است.

### **۷.۴. تفاوت سه تابع**

| Function | چه چیزی را اندازه می‌گیرد؟       |
| -------- | -------------------------------- |
| V(s)     | ارزش یک State                    |
| Q(s,a)   | ارزش یک Action در یک State       |
| A(s,a)   | برتری نسبی یک Action در یک State |

### **۷.۵. چرا NFQ از Action-Value Function استفاده می‌کند؟**

در NFQ هدف تخمین Optimal Action-Value Function است.

چون مسئله مورد بررسی، انتخاب Action مناسب در هر State است.

صرفاً دانستن ارزش یک State کافی نیست؛ باید بتوانیم Actionهای مختلف را با یکدیگر مقایسه کنیم.

برای مثال، در CartPole باید بدانیم در وضعیت فعلی حرکت به چپ بهتر است یا راست.

بنابراین:

\\[ Q^\*(s,a) \\]

تابع هدف ما خواهد بود.

تعریف Optimal Action-Value Function:

\\[ Q^\*(s,a)=\max\_\pi \mathbb{E}\_\pi[G_t|S_t=s,A_t=a] \\]

یعنی بیشترین Expected Return ممکن، با شروع از State و Action مشخص.

## **۸. Neural Fitted Q-Iteration (NFQ)**

مهم‌ترین الگوریتم فصل ۸

NFQ مخفف عبارت Neural Fitted Q-Iteration است.

این الگوریتم یکی از روش‌های اولیه موفق برای استفاده از Neural Network در Value-Based Deep Reinforcement Learning محسوب می‌شود.

هدف NFQ این است که با استفاده از یک Neural Network، تابع Action-Value را تقریب بزند.

### **۸.۱. ایده اصلی NFQ**

در Q-Learning جدولی، برای هر State-Action یک مقدار Q ذخیره و به‌روزرسانی می‌کردیم.

اما در NFQ به‌جای جدول، از Neural Network استفاده می‌کنیم.

```
State
  |
  v
Neural Network
  |
  v
Q(s, a1), Q(s, a2), ..., Q(s, an)
  |
  v
Select Best Action
```

شبکه عصبی یاد می‌گیرد که در هر State، هر Action چه مقدار ارزش دارد.

### **۸.۲. تفاوت Q-Learning و NFQ**

| ویژگی          | Q-Learning        | NFQ                           |
| -------------- | ----------------- | ----------------------------- |
| نمایش Q-Values | جدول              | Neural Network                |
| فضای State     | عمدتاً گسسته      | بزرگ، پیوسته یا با ابعاد بالا |
| Generalization | محدود             | امکان‌پذیر                    |
| به‌روزرسانی    | مقادیر جدول       | پارامترهای شبکه               |
| محاسبه خطا     | TD Error          | Loss Function                 |
| Optimization   | به‌روزرسانی جدولی | Gradient-Based Optimization   |

در واقع NFQ ایده Q-Learning را با Function Approximation ترکیب می‌کند.

## **۹. هفت تصمیم اصلی در طراحی NFQ**

یکی از بخش‌های مهم فصل، بررسی تصمیم‌هایی است که هنگام طراحی یک Value-Based Deep RL Agent باید بگیریم.

این تصمیم‌ها مشخص می‌کنند شبکه عصبی چگونه طراحی و آموزش داده شود.

### **۹.۱. تصمیم اول: Selecting a Value Function to Approximate**

ابتدا باید مشخص کنیم چه تابعی را تخمین می‌زنیم.

گزینه‌ها:

- State-Value Function
- Action-Value Function
- Action-Advantage Function

در NFQ از Action-Value Function استفاده می‌کنیم:

\\[ \hat{Q}(s,a;\theta) \\]

هدف، تقریب زدن Optimal Action-Value Function است.

### **۹.۲. تصمیم دوم: Selecting a Neural Network Architecture**

باید معماری شبکه عصبی را مشخص کنیم.

دو روش اصلی برای طراحی ورودی و خروجی شبکه وجود دارد.

**روش اول: State-Action as Input**

در این روش هم State و هم Action وارد شبکه می‌شوند.

```
State + Action
      |
      v
Neural Network
      |
      v
One Q-Value
```

یعنی برای هر جفت State-Action یک بار شبکه اجرا می‌شود.

از نظر مفهومی:

\\[ Q(s,a)=NN(s,a) \\]

**روش دوم: State as Input, Values as Output**

در این روش فقط State به شبکه داده می‌شود و شبکه مقدار Q مربوط به تمام Actionهای ممکن را خروجی می‌دهد.

```
State
  |
  v
Neural Network
  |
  +---- Q(s, Action 1)
  |
  +---- Q(s, Action 2)
  |
  +---- Q(s, Action 3)
  |
  +---- Q(s, Action N)
```

فرمول:

\\[ NN(s)=[Q(s,a_1),...,Q(s,a_n)] \\]

معماری انتخابی در مثال NFQ کتاب

این معماری در محیط‌هایی با Actionهای گسسته بسیار مفید است؛ زیرا برای به دست آوردن Q-Value تمام Actionها، تنها یک بار Forward Pass انجام می‌شود.

برای مثال در CartPole دو Action داریم:

- حرکت به چپ
- حرکت به راست

بنابراین شبکه دو خروجی خواهد داشت.

### **۹.۳. Fully Connected Neural Network**

در مثال NFQ از یک Fully Connected Neural Network استفاده می‌شود.

در این معماری، Neuronهای هر لایه به Neuronهای لایه بعدی متصل هستند.

ساختار ساده:

```
Input Layer
     |
     v
Hidden Layer 1
     |
     v
Hidden Layer 2
     |
     v
Output Layer
```

هر لایه می‌تواند تعداد Neuronهای متفاوتی داشته باشد.

برای مثال:

```
State (4 features)
      |
      v
Dense Layer (64)
      |
      v
Activation Function
      |
      v
Dense Layer (64)
      |
      v
Activation Function
      |
      v
Output Layer (2)
      |
      v
Q(Left), Q(Right)
```

این فقط یک نمونه معماری است و تعداد لایه‌ها و Neuronها به مسئله بستگی دارد.

### **۹.۴. Forward Function چیست؟**

Forward Function مشخص می‌کند داده ورودی چگونه از لایه‌های شبکه عبور کند.

مراحل:

1. دریافت State
2. ورود داده به لایه اول
3. انجام محاسبات خطی
4. اعمال Activation Function
5. عبور از لایه‌های بعدی
6. تولید خروجی Q-Values

فرمول یک لایه Fully Connected:

\\[ h=f(Wx+b) \\]

که در آن:

- \\(x\\): ورودی
- \\(W\\): وزن‌ها
- \\(b\\): Bias
- \\(f\\): Activation Function
- \\(h\\): خروجی لایه

در نهایت شبکه Q-Value تمام Actionها را تخمین می‌زند.

### **۹.۵. تصمیم سوم: Selecting What to Optimize**

سؤال اصلی این است:

چه چیزی را باید بهینه کنیم؟

هدف ایده‌آل، پیدا کردن Optimal Action-Value Function است:

\\[ Q^\*(s,a) \\]

اما مشکل اینجاست که ما مقدار واقعی \\(Q^\*\\) را در اختیار نداریم.

حتی Policy بهینه را هم نمی‌شناسیم که بتوانیم از طریق آن داده‌های ایده‌آل تولید کنیم.

پس نمی‌توانیم مستقیماً شبکه را با مقادیر واقعی Q بهینه کنیم.

راه‌حل، استفاده از Generalized Policy Iteration است که در ادامه توضیح داده می‌شود.

## **۱۰. Generalized Policy Iteration (GPI)**

این مفهوم را در فصل ۶ مطالعه کردیم، اما در فصل ۸ دوباره برای آموزش NFQ استفاده می‌شود.

### **۱۰.۱. ایده اصلی GPI**

Generalized Policy Iteration از دو فرآیند اصلی تشکیل شده است:

1. Policy Evaluation
2. Policy Improvement

**Policy Evaluation**

در این مرحله، عملکرد Policy فعلی را ارزیابی می‌کنیم.

یعنی تلاش می‌کنیم Value Function مربوط به Policy فعلی را تخمین بزنیم.

**Policy Improvement**

در این مرحله، بر اساس تخمین‌های به‌دست‌آمده، Policy را بهتر می‌کنیم.

### **۱۰.۲. چرخه GPI**

```
Initial Policy
      |
      v
Policy Evaluation
      |
      v
Value Estimation
      |
      v
Policy Improvement
      |
      v
Improved Policy
      |
      +----------> Repeat
```

این فرآیند تکرار می‌شود تا Policy به عملکرد مطلوب برسد.

### **۱۰.۳. ارتباط GPI و NFQ**

در NFQ:

1. شبکه عصبی با پارامترهای اولیه مقداردهی می‌شود.
2. Agent با Policy فعلی در Environment تعامل می‌کند.
3. Experience Samples جمع‌آوری می‌شوند.
4. با استفاده از Targetها، Action-Value Function تخمین زده می‌شود.
5. Policy بر اساس Q-Values بهبود پیدا می‌کند.
6. این فرآیند تکرار می‌شود.

نکته مهم:

در روش‌های Tabular RL، برای بسیاری از الگوریتم‌ها می‌توان تضمین‌های همگرایی مشخصی داشت؛ اما در Deep RL با Non-linear Function Approximation چنین تضمین عمومی‌ای نداریم.

بنابراین GPI به معنی تضمین رسیدن به Policy بهینه نیست.

## **۱۱. Targetهای مختلف برای Policy Evaluation**

برای آموزش شبکه باید مشخص کنیم Target مورد استفاده برای تخمین Q-Values چگونه تولید شود.

در فصل، چند روش اصلی مرور می‌شوند:

1. Monte Carlo Targets
2. Temporal-Difference Targets
3. N-Step TD Targets
4. TD(λ) Targets

### **۱۱.۱. Monte Carlo Target**

در Monte Carlo، برای محاسبه Target از Return واقعی حاصل از ادامه Episode استفاده می‌کنیم.

\\[ G_t=\sum\_{k=0}^{T-t-1}\gamma^k R\_{t+k+1} \\]

یعنی باید منتظر بمانیم Episode به پایان برسد تا Return کامل مشخص شود.

مزایا:

- استفاده از Rewardهای واقعی.
- عدم نیاز به Bootstrap.
- Target مبتنی بر Return مشاهده‌شده.

معایب:

- نیاز به انتظار تا پایان Episode.
- امکان بالا بودن Variance.
- نامناسب بودن برای برخی محیط‌های دارای Episodeهای طولانی.

### **۱۱.۲. Temporal-Difference Target**

در TD از Reward فعلی و تخمین ارزش State بعدی استفاده می‌کنیم.

برای Action-Value Function:

\\[ Y_t=R\_{t+1}+\gamma Q(S\_{t+1},A\_{t+1}) \\]

در حالت Q-Learning:

\\[ Y_t=R\_{t+1}+\gamma\max\_{a'}Q(S\_{t+1},a') \\]

مزایا:

- نیاز نداشتن به انتظار برای پایان Episode.
- امکان یادگیری مرحله‌به‌مرحله.
- قابلیت استفاده از Bootstrapping.

### **۱۱.۳. N-Step TD Target**

در این روش، به‌جای نگاه کردن به یک Step آینده، چند Reward واقعی را در نظر می‌گیریم.

\\[ G_t^{(n)} = \sum\_{k=0}^{n-1}\gamma^k R\_{t+k+1} + \gamma^n Q(S\_{t+n},A\_{t+n}) \\]

این روش بین TD یک‌مرحله‌ای و Monte Carlo قرار می‌گیرد.

### **۱۱.۴. TD(λ) Target**

در TD(λ)، از ترکیبی از Returnهای چندمرحله‌ای استفاده می‌شود.

ایده این است که اطلاعات مربوط به N-Step Returnهای مختلف با وزن‌های متفاوت ترکیب شوند.

در Forward View:

\\[ G_t^\lambda = (1-\lambda) \sum\_{n=1}^{\infty} \lambda^{n-1}G_t^{(n)} \\]

برای Episodeهای محدود، این ترکیب متناسب با طول باقی‌مانده Episode تنظیم می‌شود.

### **۱۱.۵. مقایسه Targetها**

| روش         | میزان نگاه به آینده | Bootstrapping         |
| ----------- | ------------------- | --------------------- |
| Monte Carlo | تا پایان Episode    | خیر                   |
| 1-Step TD   | یک Step             | بله                   |
| N-Step TD   | چند Step            | بله                   |
| TD(λ)       | ترکیبی از چند طول   | بله، در روش‌های معمول |

### **۱۱.۶. چرا در NFQ از TD استفاده می‌کنیم؟**

در پیاده‌سازی NFQ کتاب از TD Target مبتنی بر Q-Learning استفاده می‌شود.

دلایل مهم:

- سریع‌تر از Monte Carlo است.
- نیازی به پایان Episode ندارد.
- امکان یادگیری Off-Policy دارد.
- با هدف یادگیری Optimal Action-Value Function سازگار است.

## **۱۲. On-Policy و Off-Policy Learning**

برای فهم انتخاب Q-Learning در NFQ باید تفاوت این دو مفهوم را بدانیم.

### **۱۲.۱. On-Policy**

در On-Policy، Policy مورد استفاده برای تولید Experience با Policy مورد ارزیابی و یادگیری یکسان است.

مثال:

SARSA

\\[ Q(S_t,A_t) \\]

با استفاده از Action بعدی که Policy رفتاری واقعاً انتخاب کرده است، به‌روزرسانی می‌شود.

### **۱۲.۲. Off-Policy**

در Off-Policy، Policy تولیدکننده تجربه و Policy هدف می‌توانند متفاوت باشند.

مثال:

Q-Learning

در Q-Learning، حتی اگر Agent برای Exploration یک Action تصادفی انتخاب کرده باشد، Target از بهترین Action تخمینی در State بعدی استفاده می‌کند.

\\[ Y_t=R\_{t+1}+\gamma\max\_{a'}Q(S\_{t+1},a') \\]

### **۱۲.۳. مقایسه**

| ویژگی                   | On-Policy                 | Off-Policy                      |
| ----------------------- | ------------------------- | ------------------------------- |
| Behavior Policy         | همان Policy هدف           | می‌تواند متفاوت باشد            |
| یادگیری از رفتار تصادفی | با درنظرگرفتن رفتار واقعی | امکان یادگیری Policy هدف متفاوت |
| مثال                    | SARSA                     | Q-Learning                      |

### **۱۲.۴. چرا Off-Policy در NFQ مهم است؟**

ما می‌خواهیم Policy بهتری نسبت به Policy فعلی یاد بگیریم.

بنابراین لازم نیست دقیقاً همان Policy که Experience تولید می‌کند، Policy هدف ما باشد.

این ویژگی به Agent اجازه می‌دهد با استفاده از Exploration تجربه جمع‌آوری کند، اما در عین حال Q-Values را به سمت رفتار Greedy و بهینه‌تر هدایت کند.

## **۱۳. Q-Learning Target در NFQ**

یکی از مهم‌ترین قسمت‌های فنی فصل، نحوه ساخت Target برای آموزش شبکه عصبی است.

### **۱۳.۱. فرمول Q-Learning Target**

\\[ Y_t= R\_{t+1} + \gamma\max\_{a'}Q(S\_{t+1},a') \\]

این فرمول شامل دو بخش است:

**بخش اول: Reward واقعی**

\\[ R\_{t+1} \\]

پاداشی که Agent پس از انجام Action دریافت کرده است.

**بخش دوم: تخمین ارزش آینده**

\\[ \gamma\max\_{a'}Q(S\_{t+1},a') \\]

بهترین Q-Value تخمینی در State بعدی، با اعمال Discount Factor.

بنابراین Target از Reward واقعی و تخمین ارزش آینده تشکیل می‌شود.

### **۱۳.۲. مثال عددی**

فرض کن:

- Reward برابر ۵ است.
- Discount Factor برابر ۰٫۹ است.
- بهترین Q-Value در State بعدی برابر ۱۰ است.

در این صورت:

\\[ Y=5+0.9(10) \\]

\\[ Y=14 \\]

پس Target شبکه برابر ۱۴ خواهد بود.

### **۱۳.۳. چرا Target باید از Gradient خارج باشد؟**

در آموزش شبکه، باید تفاوت میان Prediction و Target را محاسبه کنیم.

\\[ Loss=(Y-Q(s,a;\theta))^2 \\]

نکته مهم این است که Target نباید از طریق Backpropagation تغییر کند.

یعنی Gradient فقط نسبت به Prediction محاسبه می‌شود.

در PyTorch از `detach()` یا `torch.no_grad()` برای جدا کردن محاسبات Target از Gradient استفاده می‌شود.

شکل مفهومی:

```
Next State
    |
    v
Q Network
    |
    v
Max Q-Value
    |
    v
Detach
    |
    v
TD Target
    |
    v
Compare with Prediction
    |
    v
Loss
    |
    v
Backpropagation
```

اگر Target نیز در مسیر Gradient قرار بگیرد، خود هدف یادگیری هم‌زمان با Prediction تغییر می‌کند و محاسبه گرادیان دیگر همان هدف موردنظر را دنبال نمی‌کند.

نکته: در NFQ، Target با مقادیر فعلی شبکه محاسبه و برای همان مرحله به‌عنوان یک مقدار ثابت در نظر گرفته می‌شود. استفاده از Target Network یک تکنیک تثبیت‌کننده مهم است که در فصل ۹ به‌طور مشخص بررسی می‌شود.

### **۱۳.۴. Terminal State و Truncated Episode**

در محاسبه Target باید پایان Episode را به‌درستی مدیریت کنیم.

اگر Episode واقعاً به Terminal State برسد، دیگر آینده‌ای برای Bootstrap کردن وجود ندارد.

بنابراین:

\\[ Y_t=R\_{t+1} \\]

اما یک تفاوت مهم وجود دارد:

**Terminated**

Episode به دلیل رسیدن به وضعیت پایانی واقعی Environment خاتمه پیدا کرده است.

**Truncated**

Episode به دلایلی مانند رسیدن به Time Limit متوقف شده، در حالی که محیط از نظر مفهومی می‌توانسته ادامه پیدا کند.

در حالت Truncated، معمولاً باید ارزش State بعدی را در Target حفظ کنیم:

\\[ Y_t=R\_{t+1}+\gamma\max\_{a'}Q(S\_{t+1},a') \\]

پس:

| وضعیت      | Bootstrap   |
| ---------- | ----------- |
| Terminated | خیر         |
| Truncated  | معمولاً بله |

این موضوع در محیط‌هایی مثل CartPole مهم است؛ زیرا ممکن است Episode صرفاً به دلیل محدودیت زمانی متوقف شود.

## **۱۴. Exploration Strategy: Epsilon-Greedy**

بعد از انتخاب Target باید مشخص کنیم Agent چگونه Actionها را انتخاب کند.

در NFQ از Epsilon-Greedy استفاده می‌شود.

### **۱۴.۱. Epsilon-Greedy چیست؟**

یک روش Exploration است که در آن:

- با احتمال \\(1-\epsilon\\)، بهترین Action تخمینی انتخاب می‌شود.
- با احتمال \\(\epsilon\\)، یک Action تصادفی انتخاب می‌شود.

فرمول:

\\[ \pi(a|s)= \begin{cases} \text{Random Action} & \text{با احتمال }\epsilon\\\ \arg\max_a Q(s,a) & \text{با احتمال }1-\epsilon \end{cases} \\]

### **۱۴.۲. مفهوم Epsilon**

Epsilon احتمال Exploration را تعیین می‌کند.

| Epsilon | رفتار Agent     |
| ------- | --------------- |
| 0       | کاملاً Greedy   |
| 0.1     | ۱۰٪ Exploration |
| 0.5     | ۵۰٪ Exploration |
| 1       | کاملاً Random   |

### **۱۴.۳. چرا Exploration مهم است؟**

اگر Agent همیشه بهترین Action تخمینی خود را انتخاب کند، ممکن است هیچ‌وقت Actionهای بهتر را کشف نکند.

مثلاً در Maze:

Agent ممکن است یک مسیر نسبتاً خوب پیدا کند و همیشه از همان مسیر استفاده کند.

اما اگر گاهی مسیرهای دیگر را امتحان کند، ممکن است مسیر کوتاه‌تری پیدا کند.

### **۱۴.۴. Epsilon-Greedy در NFQ**

در مثال فصل، از مقدار Epsilon برابر ۰٫۵ استفاده می‌شود.

یعنی:

- ۵۰٪ احتمال انتخاب Action تصادفی.
- ۵۰٪ احتمال انتخاب Greedy Action.

این مقدار یک انتخاب آزمایشی برای پیاده‌سازی است و قانون عمومی نیست.

### **۱۴.۵. Exploration در برابر Exploitation**

```
          Action Selection
                 |
          +------+------+
          |             |
          v             v
      Exploration   Exploitation
          |             |
          v             v
      Discover       Use Current
      New Actions    Knowledge
```

### **۱۴.۶. Behavior Policy و Target Policy**

در Off-Policy Learning:

- Behavior Policy: برای تولید Experience استفاده می‌شود.
- Target Policy: Policy موردنظر برای یادگیری است.

در NFQ، Epsilon-Greedy به تولید Experience کمک می‌کند.

اما هنگام ارزیابی عملکرد Agent، از Greedy Policy استفاده می‌کنیم.

یعنی:

\\[ a=\arg\max_a Q(s,a) \\]

در Evaluation، دیگر نیازی به Exploration تصادفی نداریم؛ هدف اندازه‌گیری عملکرد Policy یادگرفته‌شده است.

## **۱۵. Loss Function در NFQ**

برای آموزش Neural Network باید میزان اختلاف بین Prediction و Target را محاسبه کنیم.

این کار با Loss Function انجام می‌شود.

### **۱۵.۱. Mean Squared Error (MSE)**

یکی از روش‌های رایج، Mean Squared Error است.

\\[ L(\theta)= \frac{1}{N} \sum\_{i=1}^{N} (Y_i-Q(s_i,a_i;\theta))^2 \\]

که در آن:

- \\(Y_i\\): Target
- \\(Q(s_i,a_i;\theta)\\): Prediction شبکه
- \\(N\\): تعداد نمونه‌ها
- \\(\theta\\): پارامترهای شبکه

هدف آموزش:

\\[ \theta^\*=\arg\min\_\theta L(\theta) \\]

یعنی پیدا کردن پارامترهایی که Loss را کاهش دهند.

### **۱۵.۲. TD Error**

اختلاف بین Target و Prediction را TD Error می‌نامیم.

\\[ \delta_t=Y_t-Q(s_t,a_t) \\]

در Q-Learning:

\\[ \delta_t= R\_{t+1} +\gamma\max\_{a'}Q(s\_{t+1},a') -Q(s_t,a_t) \\]

TD Error نشان می‌دهد تخمین فعلی چقدر با Target اختلاف دارد.

اگر TD Error مثبت باشد، Target از Prediction بیشتر است.

اگر منفی باشد، Target از Prediction کمتر است.

### **تفاوت TD Error و Loss**

| مفهوم    | معنی                       |
| -------- | -------------------------- |
| TD Error | اختلاف Target و Prediction |
| Loss     | تابعی برای اندازه‌گیری خطا |
| MSE      | میانگین مربع خطاها         |

در حالت MSE، خطای TD به توان دو می‌رسد و میانگین آن محاسبه می‌شود.

## **۱۶. Gradient Descent و Optimization**

پس از محاسبه Loss باید پارامترهای Neural Network را به‌روزرسانی کنیم.

این کار با Optimization انجام می‌شود.

### **۱۶.۱. Gradient Descent چیست؟**

Gradient Descent یک روش بهینه‌سازی است که با استفاده از مشتق تابع Loss، جهت کاهش آن را پیدا می‌کند.

فرمول:

\\[ \theta\_{t+1} = \theta_t-\alpha\nabla\_\theta L(\theta_t) \\]

که در آن:

- \\(\theta\\): پارامترهای شبکه
- \\(\alpha\\): Learning Rate
- \\(\nabla\_\theta L\\): Gradient تابع Loss

Gradient نشان می‌دهد تغییر پارامترها چه تأثیری بر Loss خواهد داشت.

با حرکت در خلاف جهت Gradient، تلاش می‌کنیم Loss را کاهش دهیم.

### **۱۶.۲. انواع Gradient Descent**

سه روش مهم داریم:

1. Batch Gradient Descent
2. Stochastic Gradient Descent
3. Mini-Batch Gradient Descent

### **Batch Gradient Descent**

در این روش برای هر Update از کل Dataset استفاده می‌شود.

```
Entire Dataset
      |
      v
Calculate Loss
      |
      v
Calculate Gradient
      |
      v
Update Parameters
```

مزایا:

- Gradient نسبتاً پایدار.
- استفاده از کل داده‌ها برای هر Update.

معایب:

- هزینه محاسباتی بالا.
- مصرف حافظه زیاد.
- سرعت پایین‌تر برای Datasetهای بزرگ.

### **Stochastic Gradient Descent (SGD)**

در این روش برای هر Update فقط یک نمونه استفاده می‌شود.

```
One Sample
    |
    v
Calculate Loss
    |
    v
Calculate Gradient
    |
    v
Update Parameters
```

مزایا:

- Updateهای سریع.
- نیاز به حافظه کمتر.
- امکان انجام Updateهای مکرر.

معایب:

- Gradient پرنوسان.
- حرکت نامنظم در مسیر بهینه‌سازی.
- احتمال Zig-Zag.

### **Mini-Batch Gradient Descent**

این روش ترکیبی از دو روش قبلی است.

به‌جای کل Dataset یا فقط یک نمونه، از یک Batch کوچک استفاده می‌کنیم.

```
Dataset
   |
   v
Mini-Batch Sampling
   |
   v
Calculate Loss
   |
   v
Calculate Gradient
   |
   v
Update Parameters
   |
   v
Next Mini-Batch
```

مزایا:

- سریع‌تر از Batch Gradient Descent در بسیاری از مسائل.
- پایدارتر از SGD تک‌نمونه‌ای.
- استفاده بهتر از پردازش موازی GPU.
- مناسب برای Datasetهای بزرگ.

در آموزش Neural Networkها معمولاً Mini-Batch Gradient Descent انتخاب مناسبی است.

### **۱۶.۳. مقایسه سه روش**

| ویژگی                 | Batch      | Stochastic         | Mini-Batch    |
| --------------------- | ---------- | ------------------ | ------------- |
| تعداد نمونه در Update | کل Dataset | یک نمونه           | چند نمونه     |
| سرعت هر Update        | کمتر       | بیشتر              | متوسط         |
| پایداری Gradient      | بالا       | پایین              | متوسط تا بالا |
| حافظه موردنیاز        | زیاد       | کم                 | متوسط         |
| استفاده از GPU        | مناسب      | معمولاً کمتر بهینه | مناسب         |

### **۱۶.۴. Batch Size**

Batch Size تعداد نمونه‌هایی است که در هر Update استفاده می‌شوند.

مثلاً اگر:

\\[ Batch\ Size=64 \\]

یعنی در هر مرحله ۶۴ نمونه برای محاسبه Loss و Gradient استفاده می‌شود.

اندازه Batch یک Hyperparameter است.

Batch بزرگ‌تر:

- تخمین Gradient معمولاً کم‌نوسان‌تر است.
- حافظه بیشتری نیاز دارد.
- تعداد Updateها در هر Epoch کمتر می‌شود.

Batch کوچک‌تر:

- Updateهای بیشتری ایجاد می‌کند.
- نوسانات Gradient بیشتر است.
- مصرف حافظه کمتر است.

در متن آموزشی، محدوده ۳۲ تا ۱۰۲۴ به‌عنوان نمونه مطرح می‌شود؛ اما هیچ Batch Size بهینه و عمومی برای تمام مسائل وجود ندارد.

## **۱۷. Zig-Zag Pattern و Momentum**

یکی از مشکلات Gradient Descent، مخصوصاً با Batchهای کوچک، نوسان در مسیر بهینه‌سازی است.

### **۱۷.۱. Zig-Zag Pattern چیست؟**

تصور کن می‌خواهیم به نقطه کمینه یک تابع برسیم.

به دلیل وجود نوسانات در Gradient، ممکن است مسیر حرکت به شکل زیگزاگ باشد.

```
       Start
         *
        / \
       /   \
      /     \
     /       \
    /         *
   /          |
  *           |
   \          |
    \         *
     \       /
      \     /
       \   /
        \ /
      Minimum
```

این شکل صرفاً نمایشی از نوسانات مسیر است.

### **۱۷.۲. Momentum چیست؟**

Momentum روشی برای بهبود روند Optimization است.

در این روش، فقط Gradient فعلی را در نظر نمی‌گیریم؛ بلکه از جهت Gradientهای قبلی نیز استفاده می‌کنیم.

فرمول ساده:

\\[ v_t=\beta v\_{t-1}+\nabla\_\theta L(\theta_t) \\]

\\[ \theta\_{t+1}=\theta_t-\alpha v_t \\]

که در آن:

- \\(v_t\\): سرعت یا مقدار Momentum
- \\(\beta\\): ضریب Momentum
- \\(\alpha\\): Learning Rate

### **۱۷.۳. مزایای Momentum**

- کاهش نوسانات.
- حرکت پایدارتر در جهت مناسب.
- عبور سریع‌تر از Plateauها.
- بهبود سرعت یادگیری در برخی مسیرهای Optimization.

Momentum مانند اینرسی در فیزیک عمل می‌کند.

اگر Gradientهای قبلی جهت مشخصی را نشان دهند، الگوریتم تمایل دارد حرکت خود را در همان جهت ادامه دهد.

### **۱۷.۴. ارتباط Momentum با Local Minima**

Momentum می‌تواند به حرکت در مناطق کم‌شیب یا عبور از برخی نقاط نامناسب کمک کند.

اما تضمین نمی‌کند که مدل از تمام Local Minima خارج شود یا به Global Minimum برسد.

## **۱۸. الگوریتم‌های بهینه‌سازی Adam و RMSprop**

در متن فصل به دو روش مهم دیگر اشاره می‌شود.

### **۱۸.۱. RMSprop**

RMSprop برای تنظیم تطبیقی اندازه Updateها از میانگین متحرک مربع Gradientها استفاده می‌کند.

ایده اصلی این است که برای پارامترهایی با Gradient بزرگ‌تر، اندازه گام را کاهش دهد و برای Gradientهای کوچک‌تر، امکان حرکت مناسب را حفظ کند.

این کار می‌تواند نوسانات را کاهش دهد.

### **۱۸.۲. Adam**

Adam مخفف Adaptive Moment Estimation است.

این الگوریتم از دو تخمین متحرک استفاده می‌کند:

- First Moment: میانگین متحرک Gradientها.
- Second Moment: میانگین متحرک مربع Gradientها.

به‌صورت ساده:

\\[ m_t=\beta_1m\_{t-1}+(1-\beta_1)g_t \\]

\\[ v_t=\beta_2v\_{t-1}+(1-\beta_2)g_t^2 \\]

پس از اصلاح Bias:

\\[ \theta\_{t+1} = \theta_t- \alpha\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon} \\]

Adam در بسیاری از مسائل Deep Learning انتخاب رایجی است.

### **۱۸.۳. مقایسه**

| Optimizer      | ویژگی اصلی                         |
| -------------- | ---------------------------------- |
| SGD            | استفاده از Gradient                |
| SGD + Momentum | استفاده از جهت Gradientهای قبلی    |
| RMSprop        | تنظیم تطبیقی بر اساس مربع Gradient |
| Adam           | ترکیب تخمین First و Second Moment  |

نکته: Adam و RMSprop روش‌های جایگزین برای بهینه‌سازی هستند؛ صرف استفاده از آن‌ها تضمین‌کننده پایداری Deep RL نیست.

## **۱۹. مشکلات اصلی Deep Reinforcement Learning**

یکی از مهم‌ترین پیام‌های فصل ۸ این است که استفاده از Neural Network در RL قدرت زیادی ایجاد می‌کند، اما مشکلات جدیدی نیز به وجود می‌آورد.

مهم‌ترین مشکل مورد بحث در فصل، ناپایداری یادگیری به دلیل تغییر دائمی Targetها و توزیع داده‌ها است.

### **۱۹.۱. Non-Stationary Targets**

در Supervised Learning معمولاً فرض می‌کنیم Targetهای Dataset ثابت هستند.

مثلاً:

```
Input: Image
Target: Cat
```

در طول آموزش، Label مربوط به تصویر تغییر نمی‌کند.

اما در Deep RL، Targetها معمولاً از Predictionهای خود شبکه ساخته می‌شوند.

برای مثال:

\\[ Y_t= R\_{t+1} + \gamma\max\_{a'}Q(S\_{t+1},a';\theta) \\]

دقت کن که Target به پارامترهای شبکه یعنی \\(\theta\\) وابسته است.

وقتی شبکه به‌روزرسانی می‌شود، تخمین Q-Value نیز تغییر می‌کند.

در نتیجه Target جدید ممکن است با Target قبلی متفاوت باشد.

### **۱۹.۲. Moving Target Problem**

این مشکل به این معناست که هنگام تلاش برای کاهش خطا، خود Target نیز تغییر می‌کند.

```
Current Prediction
        |
        v
Calculate Target
        |
        v
Update Network
        |
        v
Prediction Changes
        |
        v
Target Changes
        |
        v
Repeat
```

بنابراین مدل همیشه در حال یادگیری از هدفی است که ممکن است با به‌روزرسانی‌های بعدی تغییر کند.

این موضوع می‌تواند باعث ناپایداری شود.

### **۱۹.۳. Correlated Samples**

در بسیاری از مسائل Supervised Learning، نمونه‌های آموزشی را تقریباً مستقل فرض می‌کنیم.

اما در RL، Experienceها معمولاً از یک Trajectory به دست می‌آیند.

برای مثال:

```
S1 -> A1 -> S2 -> A2 -> S3 -> A3
```

نمونه‌های نزدیک به یکدیگر ممکن است بسیار شبیه باشند.

در نتیجه:

- Experienceها Independent نیستند.
- Mini-Batchها ممکن است Correlated باشند.
- نمونه‌های متوالی می‌توانند اطلاعات بسیار مشابهی داشته باشند.

این موضوع یادگیری شبکه را دشوار می‌کند.

### **۱۹.۴. IID Assumption**

IID مخفف:

**Independent and Identically Distributed**

دو بخش دارد:

**Independent**

نمونه‌ها از نظر آماری مستقل باشند.

**Identically Distributed**

نمونه‌ها از یک توزیع احتمالی یکسان تولید شده باشند.

در آموزش استاندارد شبکه‌های عصبی، معمولاً تلاش می‌شود Dataset تا حد امکان به این شرایط نزدیک باشد.

اما در RL، این فرض‌ها به‌سادگی برقرار نیستند.

### **۱۹.۵. Non-Stationary Data Distribution**

توزیع داده‌های Agent می‌تواند با تغییر Policy عوض شود.

برای مثال:

1. Agent ابتدا با Policy تصادفی حرکت می‌کند.
2. Experienceهای تصادفی تولید می‌شوند.
3. شبکه آموزش می‌بیند.
4. Policy بهتر می‌شود.
5. Agent وارد Stateهای متفاوتی می‌شود.
6. توزیع Experienceهای جدید تغییر می‌کند.

بنابراین:

```
Policy 1
   |
   v
Experience Distribution 1
   |
   v
Policy Update
   |
   v
Policy 2
   |
   v
Experience Distribution 2
```

در نتیجه داده‌هایی که شبکه در طول آموزش مشاهده می‌کند، لزوماً از یک توزیع ثابت نیستند.

### **۱۹.۶. چرا این مشکلات مهم هستند؟**

این عوامل می‌توانند باعث موارد زیر شوند:

- نوسانات شدید Loss
- ناپایداری Q-Valueها
- یادگیری ناقص
- عملکرد ضعیف Policy
- عدم همگرایی الگوریتم

### **۱۹.۷. راهکارهای کاهش ناپایداری**

در متن فصل به ایده‌هایی مانند موارد زیر اشاره می‌شود:

- استفاده از Targetهای پایدارتر.
- تنظیم مناسب Learning Rate.
- استفاده از روش‌های Optimization مناسب.
- استفاده از داده‌های نماینده و متنوع.

در فصل ۹ کتاب، راهکارهای مشخص‌تری مانند Target Network و Experience Replay بررسی می‌شوند.

نکته مهم: این دو تکنیک را نباید به‌عنوان اجزای اصلی پیاده‌سازی NFQ در فصل ۸ در نظر گرفت؛ آن‌ها موضوع محوری فصل بعد هستند.

## **۲۰. مزایا و معایب Value-Based Deep RL**

در پایان، باید بدانیم روش‌های Value-Based چه نقاط قوت و ضعفی دارند.

### **مزایا**

1. امکان استفاده از Neural Network برای تخمین Value Function.
2. مناسب برای State Spaceهای بزرگ و پیوسته.
3. امکان Generalization.
4. امکان انتخاب Greedy Action با استفاده از Q-Values.
5. استفاده از الگوریتم‌های شناخته‌شده‌ای مانند Q-Learning.

### **معایب**

1. مشکلات ناپایداری در Non-linear Function Approximation.
2. نیاز به داده و منابع محاسباتی قابل‌توجه.
3. وابستگی عملکرد به کیفیت Experience Samples.
4. حساسیت به Hyperparameterها.
5. دشواری یادگیری در محیط‌های پیچیده.
6. محدودیت روش‌های معمول Q-Value در محیط‌های دارای Action Space پیوسته یا بسیار بزرگ.

### **پنج نکته‌ بسیار مهم**

**۱. چرا Deep RL به Neural Network نیاز دارد؟**

چون Tabular RL برای State Spaceهای بزرگ، پیوسته و با ابعاد بالا مناسب نیست و Neural Network امکان Function Approximation و Generalization را فراهم می‌کند.

**۲. چرا NFQ از Q-Function استفاده می‌کند؟**

چون هدف آن تخمین ارزش Actionهای مختلف در هر State و انتخاب Action بهتر است.

**۳. چرا Q-Learning در NFQ استفاده می‌شود؟**

چون Q-Learning یک روش Off-Policy است و می‌تواند با استفاده از تجربه‌های حاصل از Exploration، ارزش Policy هدف را یاد بگیرد.

**۴. چرا Target از Gradient جدا می‌شود؟**

چون Target باید در هر مرحله به‌عنوان یک مقدار ثابت در نظر گرفته شود و Backpropagation فقط Prediction را اصلاح کند.

**۵. چرا Deep RL ناپایدار است؟**

چون Neural Network هم‌زمان با یادگیری، Targetها و توزیع Experienceهای مورد استفاده را نیز تحت تأثیر قرار می‌دهد.
