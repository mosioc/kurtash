# **خلاصه کامل فصل اول کتاب Deep Reinforcement Learning**

فصل اول بیشتر روی شناخت Deep Reinforcement Learning (DRL)، مبانی Reinforcement Learning، تاریخچه هوش مصنوعی، معماری شبکه‌های عصبی و چالش‌های یادگیری تقویتی تمرکز دارد.

# **بخش اول: مفاهیم پایه هوش مصنوعی و یادگیری تقویتی**

## **1. Artificial Intelligence (AI)**

**هوش مصنوعی** شاخه‌ای از علوم کامپیوتر است که هدف آن ساخت سیستم‌هایی است که بتوانند برخی قابلیت‌های شناختی انسان را شبیه‌سازی کنند.

از جمله:

- Learning: یادگیری از داده و تجربه
- Reasoning: استدلال
- Problem Solving: حل مسئله
- Planning: برنامه‌ریزی
- Decision Making: تصمیم‌گیری
- Perception: درک محیط

مثال‌ها:

- موتورهای جست‌وجو
- سیستم‌های GPS
- دستیارهای هوشمند
- تشخیص تصویر
- رباتیک

نکته مهم: هوش مصنوعی الزاماً به معنای ساخت ماشینی با هوش یا آگاهی انسانی نیست. تمرکز اصلی می‌تواند حل مسائل و انجام وظایف هوشمندانه باشد.

## **2. Machine Learning (ML)**

**یادگیری ماشین** زیرمجموعه‌ای از هوش مصنوعی است که در آن سیستم به‌جای اینکه تمام قوانین به‌صورت دستی برایش تعریف شوند، از داده‌ها و تجربه الگو یاد می‌گیرد.

سه رویکرد اصلی یادگیری ماشین:

| نوع                    | مفهوم                                |
| ---------------------- | ------------------------------------ |
| Supervised Learning    | یادگیری از داده‌های دارای برچسب      |
| Unsupervised Learning  | کشف الگو در داده‌های بدون برچسب      |
| Reinforcement Learning | یادگیری از طریق تعامل و دریافت پاداش |

## **3. Deep Learning (DL)**

**یادگیری عمیق** زیرمجموعه‌ای از Machine Learning است که از شبکه‌های عصبی چندلایه برای یادگیری روابط و الگوهای پیچیده استفاده می‌کند.

کاربردهای مهم:

- پردازش تصویر
- پردازش زبان طبیعی
- تشخیص صدا
- استخراج ویژگی از داده‌های پیچیده

تفاوت مهم:

- Machine Learning یک حوزه گسترده از روش‌های یادگیری است.
- Deep Learning از شبکه‌های عصبی عمیق برای یادگیری استفاده می‌کند.
- Reinforcement Learning یک روش یادگیری مبتنی بر تعامل و پاداش است.

## **4. Reinforcement Learning (RL)**

مفهوم بنیادی فصل

یادگیری تقویتی روشی در Machine Learning است که در آن یک سیستم از طریق تعامل با محیط، انجام اقدامات مختلف و دریافت بازخورد یاد می‌گیرد چگونه به اهداف خود برسد.

ایده اصلی:

**یادگیری از طریق آزمون و خطا (Trial and Error)**

فرض کن یک ربات قرار است راه رفتن را یاد بگیرد:

1. یک حرکت انجام می‌دهد.
2. نتیجه حرکت را مشاهده می‌کند.
3. برای نتیجه مطلوب پاداش دریافت می‌کند.
4. برای نتیجه نامطلوب پاداش کمتری دریافت می‌کند یا جریمه می‌شود.
5. بر اساس تجربه‌های قبلی، رفتار خود را تغییر می‌دهد.

هدف اصلی RL:

\\[ \max \text{Expected Cumulative Reward} \\]

یعنی بیشینه‌سازی مجموع مورد انتظار پاداش‌ها در طول زمان.

نکته مهم: هدف فقط دریافت بیشترین پاداش فوری نیست؛ سیستم باید پیامدهای بلندمدت تصمیم‌های خود را نیز در نظر بگیرد.

## **5. Deep Reinforcement Learning (DRL)**

یادگیری تقویتی عمیق ترکیبی از دو مفهوم است:

- Reinforcement Learning
- Deep Learning

در این روش از شبکه‌های عصبی عمیق برای حل مسائل پیچیده یادگیری تقویتی استفاده می‌شود.

**ساختار مفهومی DRL**

**Deep Learning**

پردازش داده‌های پیچیده و تقریب روابط

**Reinforcement Learning**

یادگیری از تعامل، اقدامات و پاداش

**Deep Reinforcement Learning**

یادگیری تصمیم‌گیری پیچیده با کمک شبکه‌های عصبی عمیق

مثال: یک عامل هوشمند برای بازی کردن یک بازی ویدیویی، تصاویر بازی را دریافت می‌کند، وضعیت بازی را تحلیل می‌کند، حرکت بعدی را انتخاب می‌کند و بر اساس نتیجه آن یاد می‌گیرد.

نکته مهم درباره رابطه این مفاهیم:

\\[ DRL \subset RL \subset ML \subset AI \\]

البته DL نیز زیرمجموعه ML است و با RL رابطه ترکیبی دارد؛ بنابراین DRL حاصل ترکیب DL و RL است، نه اینکه RL زیرمجموعه DRL باشد.

## **6. Sequential Decision Making**

**تصمیم‌گیری متوالی** یعنی سیستم باید مجموعه‌ای از تصمیم‌ها را در طول زمان اتخاذ کند؛ تصمیم‌هایی که بر وضعیت آینده و تصمیم‌های بعدی تأثیر می‌گذارند.

مثال:

- در شطرنج هر حرکت بر موقعیت بعدی تأثیر می‌گذارد.
- در رباتیک هر حرکت بازو، وضعیت حرکت بعدی را تغییر می‌دهد.
- در رانندگی خودکار هر تصمیم بر شرایط آینده رانندگی اثر می‌گذارد.

این مفهوم یکی از مهم‌ترین دلایل استفاده از RL است.

## **7. Uncertainty**

**عدم قطعیت** یعنی سیستم نمی‌تواند با اطمینان کامل نتیجه اقدامات خود یا وضعیت آینده محیط را پیش‌بینی کند.

مثال:

یک بازوی رباتیک می‌خواهد جسمی را بردارد؛ اما:

- جسم ممکن است جابه‌جا شده باشد.
- وزن جسم ممکن است متفاوت باشد.
- حسگرها ممکن است خطا داشته باشند.
- حرکت موتور ممکن است دقیق نباشد.

بنابراین DRL برای مسائل تصمیم‌گیری متوالی تحت عدم قطعیت مناسب است.

## **8. ارتباط RL با حوزه‌های دیگر**

فصل به ارتباط RL با چند حوزه اشاره می‌کند:

| حوزه                | مفهوم                                     |
| ------------------- | ----------------------------------------- |
| Control Theory      | کنترل سیستم‌ها با استفاده از مدل دینامیکی |
| Operations Research | بهینه‌سازی و تصمیم‌گیری در مسائل پیچیده   |
| Psychology          | مطالعه رفتار و یادگیری انسان              |
| Machine Learning    | روش‌های یادگیری از داده و تجربه           |

تفاوت کلی:

- Control Theory معمولاً روی کنترل سیستم‌هایی با دینامیک مشخص تمرکز دارد.
- Operations Research به مسائل بهینه‌سازی و فضای تصمیم‌گیری بزرگ می‌پردازد.
- RL بر یادگیری رفتار مناسب از طریق تعامل با محیط تأکید دارد.

# **بخش دوم: اجزای اصلی Reinforcement Learning**

این قسمت از مهم‌ترین بخش‌های فصل است؛ چون تقریباً تمام الگوریتم‌های RL بر پایه همین مفاهیم ساخته می‌شوند.

## **9. Agent**

**عامل (Agent)** بخش تصمیم‌گیرنده سیستم است.

وظایف Agent:

- دریافت اطلاعات از محیط
- انتخاب Action
- یادگیری از نتایج اقدامات
- بهبود تصمیم‌گیری در طول زمان

مثال: در یک ربات، نرم‌افزاری که تصمیم می‌گیرد بازوی ربات به کدام سمت حرکت کند، Agent محسوب می‌شود.

نکته مهم: Agent لزوماً خود ربات یا سخت‌افزار آن نیست؛ بلکه بخش تصمیم‌گیری است.

## **10. Environment**

**محیط (Environment)** تمام عواملی است که خارج از کنترل مستقیم Agent قرار دارند و Agent با آن‌ها تعامل می‌کند.

مثلاً در یک ربات:

- موقعیت اشیا
- سطح زمین
- شرایط محیطی
- نویز دوربین
- تأخیر شبکه
- خطاهای موتور

Agent تصمیم می‌گیرد، اما تمام اتفاقات محیط را کنترل نمی‌کند.

## **11. State**

**وضعیت (State)** نمایش کامل اطلاعات مرتبط با وضعیت فعلی محیط است.

مثال در بازوی رباتیک:

- موقعیت فعلی بازو
- سرعت حرکت
- موقعیت جسم
- وضعیت مفاصل
- اطلاعات مرتبط با شرایط محیط

State تمام اطلاعات مرتبطی را که برای تعریف وضعیت مسئله لازم است، در بر می‌گیرد.

## **12. State Space**

**فضای وضعیت (State Space)** مجموعه تمام وضعیت‌های ممکنی است که محیط می‌تواند داشته باشد.

مثلاً اگر موقعیت و سرعت یک بازو متغیر باشند، تمام ترکیب‌های ممکن این متغیرها فضای وضعیت را تشکیل می‌دهند.

\\[ S = \\{s_1,s_2,s_3,\ldots\\} \\]

هر \\(s\\) یک State مشخص است.

## **13. Observation**

**مشاهده (Observation)** اطلاعاتی است که Agent مستقیماً از محیط دریافت می‌کند.

تفاوت مهم State و Observation:

| State                            | Observation                      |
| -------------------------------- | -------------------------------- |
| وضعیت کامل محیط                  | اطلاعات قابل مشاهده برای Agent   |
| ممکن است شامل اطلاعات پنهان باشد | ممکن است ناقص یا همراه نویز باشد |
| توصیف وضعیت واقعی سیستم          | نمایش اطلاعات دریافتی            |

مثال:

یک ربات ممکن است از طریق دوربین فقط تصویر جسم را ببیند، اما اطلاعات دقیق وزن، موقعیت سه‌بعدی یا سرعت آن را در اختیار نداشته باشد.

در این شرایط:

- State: اطلاعات کامل وضعیت
- Observation: تصویر دریافت‌شده از دوربین

گاهی در مسائل ساده این دو اصطلاح به‌جای یکدیگر استفاده می‌شوند، اما از نظر مفهومی متفاوت‌اند.

## **14. Action**

**عمل (Action)** تصمیم یا حرکتی است که Agent برای تأثیرگذاری بر محیط انتخاب می‌کند.

مثال:

- حرکت به چپ یا راست
- افزایش سرعت
- حرکت دادن بازوی ربات
- انتخاب یک حرکت در بازی

مجموعه تمام اقدامات ممکن، Action Space نام دارد.

## **15. Action Space**

**فضای اقدامات** مجموعه تمام Actionهایی است که Agent می‌تواند انتخاب کند.

دو نوع کلی:

- Discrete Action Space: اقدامات محدود و گسسته؛ مانند بالا، پایین، چپ و راست.
- Continuous Action Space: اقدامات پیوسته؛ مانند تنظیم زاویه یا سرعت موتور در یک بازه عددی.

## **16. Reward**

**پاداش (Reward)** سیگنالی عددی است که نشان می‌دهد نتیجه یک تعامل تا چه اندازه مطلوب بوده است.

مثال:

- رسیدن به هدف: پاداش مثبت
- برخورد با مانع: پاداش منفی
- حرکت به سمت هدف: پاداش مثبت کوچک

هدف Agent یادگیری رفتاری است که مجموع مورد انتظار پاداش را بیشینه کند.

## **17. Reward Function**

تابع پاداش مشخص می‌کند که در وضعیت‌ها و شرایط مختلف چه مقدار پاداش به Agent تعلق بگیرد.

\\[ R(s,a,s') \\]

در این نمایش، پاداش به وضعیت فعلی، اقدام و وضعیت بعدی وابسته است.

نکته بسیار مهم: طراحی تابع پاداش یکی از حساس‌ترین قسمت‌های RL است. اگر تابع پاداش با هدف واقعی مسئله هماهنگ نباشد، Agent ممکن است رفتاری یاد بگیرد که از نظر عددی پاداش خوبی دارد، اما در عمل نامطلوب است.

## **18. Transition Function**

تابع انتقال مشخص می‌کند که با انجام یک Action در وضعیت فعلی، وضعیت بعدی چگونه تعیین می‌شود.

\\[ P(s'|s,a) \\]

این تابع احتمال انتقال از State فعلی \\(s\\) به State بعدی \\(s'\\) را در اثر Action انتخاب‌شده \\(a\\) توصیف می‌کند.

مثال:

ربات در موقعیت مشخصی قرار دارد و تصمیم می‌گیرد به سمت چپ حرکت کند. تابع انتقال، وضعیت احتمالی بعد از این حرکت را توصیف می‌کند.

## **19. Model of Environment**

مدل محیط توصیفی از رفتار محیط است که می‌تواند موارد زیر را شامل شود:

- Transition Model: پیش‌بینی وضعیت بعدی
- Reward Model: پیش‌بینی پاداش

به کمک مدل محیط می‌توان درباره پیامد اقدامات احتمالی پیش‌بینی انجام داد.

# **بخش سوم: چرخه یادگیری و نحوه عملکرد Agent**

## **20. Reinforcement Learning Cycle**

یادگیری تقویتی یک فرآیند تکرارشونده است که در آن Agent و Environment با یکدیگر تعامل دارند.

**1. Agent observes the environment**

دریافت Observation

**2. Agent selects an Action**

انتخاب اقدام بر اساس سیاست فعلی

**3. Environment responds**

تغییر وضعیت و تولید Reward

**4. Agent learns from feedback**

ارزیابی نتیجه و بهبود تصمیم‌گیری

تکرار چرخه در Time Step بعدی

این چرخه اساس یادگیری تقویتی است.

## **21. Time Step**

هر مرحله از تعامل Agent با Environment یک Time Step محسوب می‌شود.

در هر Time Step معمولاً:

1. Agent اطلاعات محیط را دریافت می‌کند.
2. یک Action انتخاب می‌کند.
3. محیط به Action پاسخ می‌دهد.
4. Reward و وضعیت جدید مشخص می‌شوند.

## **22. Experience**

هر تعامل Agent با محیط یک تجربه (Experience) تولید می‌کند.

ساختار رایج نمایش تجربه:

\\[ (s_t,a_t,r\_{t+1},s\_{t+1}) \\]

که در آن:

| نماد           | مفهوم            |
| -------------- | ---------------- |
| \\(s_t\\)      | وضعیت فعلی       |
| \\(a_t\\)      | اقدام انتخاب‌شده |
| \\(r\_{t+1}\\) | پاداش دریافت‌شده |
| \\(s\_{t+1}\\) | وضعیت بعدی       |

Agent از این تجربه‌ها برای بهبود رفتار خود استفاده می‌کند.

## **23. Episodic Tasks**

**وظایف اپیزودیک** وظایفی هستند که شروع و پایان مشخص دارند.

مثال:

- انجام یک بازی تا رسیدن به پایان
- حل یک مرحله از یک بازی
- حرکت ربات تا رسیدن به مقصد

هر اجرای کامل وظیفه یک Episode است.

یک Episode شامل مجموعه‌ای از Time Stepهاست.

\\[ Episode = (s_0,a_0,r_1,\ldots,s_T) \\]

## **24. Continuing Tasks**

**وظایف ادامه‌دار** وظایفی هستند که پایان طبیعی و مشخصی ندارند.

مثال:

- کنترل دائمی دمای یک سیستم
- حرکت پیوسته یک ربات
- مدیریت مداوم مصرف انرژی

تفاوت اصلی:

| Episodic          | Continuing              |
| ----------------- | ----------------------- |
| شروع و پایان مشخص | بدون پایان طبیعی        |
| دارای Episode     | جریان مداوم تعامل       |
| مثال: یک مسابقه   | مثال: کنترل دائمی سیستم |

## **25. Sequential Feedback**

در RL بازخورد به‌صورت متوالی و در طول زمان دریافت می‌شود.

مشکل اینجاست که نتیجه یک Action ممکن است بلافاصله مشخص نشود.

مثلاً در شطرنج، یک حرکت ممکن است چندین حرکت بعد باعث پیروزی شود.

این موضوع یکی از مهم‌ترین چالش‌های RL است.

## **26. Delayed Rewards**

**پاداش تأخیری** زمانی اتفاق می‌افتد که Agent برای دریافت Reward باید چندین Action انجام دهد.

مثال:

یک ربات باید از یک هزارتو عبور کند. در انتهای مسیر پاداش دریافت می‌کند، اما در طول مسیر ممکن است پاداشی دریافت نکند.

مشکل این است که Agent باید بفهمد کدام اقدامات قبلی به دریافت پاداش نهایی کمک کرده‌اند.

## **27. Temporal Credit Assignment Problem**

مفهوم بسیار مهم

مسئله تخصیص اعتبار زمانی یعنی تشخیص اینکه کدام Actionها در طول زمان باعث نتیجه مثبت یا منفی شده‌اند.

مثال:

یک ربات چندین حرکت انجام می‌دهد و در نهایت به هدف می‌رسد.

کدام حرکت‌ها واقعاً در موفقیت نقش داشته‌اند؟

یا برعکس، اگر ربات شکست بخورد، کدام Action مسئول این شکست بوده است؟

این مسئله به‌خصوص در شرایط زیر دشوار است:

- پاداش‌ها با تأخیر دریافت شوند.
- تعداد Actionها زیاد باشد.
- نتیجه یک Action به Actionهای بعدی وابسته باشد.
- عوامل محیطی نیز بر نتیجه تأثیر بگذارند.

نکته: Agent باید به‌جای تمرکز صرف بر پاداش فوری، ارتباط بین مجموعه اقدامات و نتیجه نهایی را یاد بگیرد.

# **بخش چهارم: روش‌های یادگیری Agent**

## **28. Policy**

**Policy** استراتژی یا سیاست تصمیم‌گیری Agent است.

Policy مشخص می‌کند که Agent در یک وضعیت یا با مشاهده اطلاعات مشخص، چه Actionی انتخاب کند.

\\[ \pi(a|s) \\]

این نمایش احتمال انتخاب Action برابر \\(a\\) در وضعیت \\(s\\) را نشان می‌دهد.

به زبان ساده:

Policy = نحوه تصمیم‌گیری Agent

مثال:

اگر ربات مانع را در سمت راست ببیند، Policy ممکن است به آن بگوید به سمت چپ حرکت کند.

## **29. Value Function**

تابع ارزش تخمین می‌زند که یک State یا Action در بلندمدت چقدر ارزشمند است.

به بیان دیگر، Value Function به Agent کمک می‌کند بفهمد کدام وضعیت یا اقدام می‌تواند در آینده پاداش بیشتری ایجاد کند.

دو مفهوم مهم:

- State Value: ارزش یک وضعیت
- Action Value: ارزش انجام یک اقدام در یک وضعیت مشخص

نمایش ریاضی رایج:

\\[ V^\pi(s) \\]

ارزش مورد انتظار بودن در وضعیت \\(s\\) تحت Policy مشخص.

و:

\\[ Q^\pi(s,a) \\]

ارزش مورد انتظار انتخاب Action برابر \\(a\\) در وضعیت \\(s\\) تحت Policy مشخص.

## **30. Environment Model**

مدل محیط تلاش می‌کند رفتار آینده Environment را پیش‌بینی کند.

برای مثال:

- اگر Agent به سمت چپ حرکت کند، چه اتفاقی می‌افتد؟
- چه State جدیدی ایجاد می‌شود؟
- چه Rewardی دریافت خواهد شد؟

این مدل می‌تواند در برنامه‌ریزی و انتخاب Actionهای بهتر به Agent کمک کند.

## **31. Actor-Critic Architecture**

معماری Actor-Critic از دو بخش اصلی تشکیل می‌شود:

**Actor**

# **Policy**

انتخاب Action و تعیین نحوه رفتار

**Critic**

# **Value Function**

ارزیابی کیفیت State یا Action

Critic به بهبود تصمیم‌گیری Actor کمک می‌کند.

- Actor مسئول انتخاب Action است.
- Critic مسئول ارزیابی کیفیت تصمیم‌هاست.

این معماری تلاش می‌کند از ترکیب تصمیم‌گیری و ارزیابی برای یادگیری مؤثرتر استفاده کند.

## **32. Artificial Neural Networks (ANN)**

شبکه عصبی مصنوعی ساختاری محاسباتی است که از مجموعه‌ای از واحدهای پردازشی و توابع ریاضی تشکیل شده است.

شبکه عصبی به‌صورت ساده از سه نوع لایه تشکیل می‌شود:

1. Input Layer: دریافت ورودی
2. Hidden Layers: پردازش و تبدیل اطلاعات
3. Output Layer: تولید خروجی

هر لایه خروجی لایه قبلی را دریافت کرده و با استفاده از تبدیل‌های ریاضی آن را پردازش می‌کند.

شبکه‌های عمیق با استفاده از لایه‌های متعدد می‌توانند روابط پیچیده‌تری را یاد بگیرند.

نکته: شبکه عصبی یک ساختار محاسباتی است، نه یک الگوریتم یادگیری تقویتی به‌تنهایی.

## **33. Deep Neural Networks**

شبکه‌های عصبی عمیق، شبکه‌های عصبی دارای چندین لایه پردازشی هستند.

کاربرد آن‌ها در DRL:

- پردازش ورودی‌های پیچیده
- استخراج ویژگی‌ها
- تقریب Policy
- تقریب Value Function
- یادگیری روابط پیچیده میان State، Action و Reward

مثال مهم: در بازی‌های ویدیویی، یک شبکه عصبی می‌تواند از تصاویر خام بازی ویژگی‌های موردنیاز برای تصمیم‌گیری را استخراج کند.

## **34. Function Approximation**

در مسائل پیچیده، ذخیره یا محاسبه جداگانه ارزش تمام Stateها و Actionها عملی نیست.

به همین دلیل از Function Approximation استفاده می‌شود.

یعنی به‌جای محاسبه دقیق تمام مقادیر، از یک تابع برای تخمین آن‌ها استفاده می‌کنیم.

شبکه‌های عصبی عمیق یکی از ابزارهای مهم این کار هستند.

## **35. Overfitting**

Overfitting زمانی اتفاق می‌افتد که مدل داده‌ها یا تجربه‌های آموزشی را بیش از حد یاد می‌گیرد، اما در موقعیت‌های جدید عملکرد مناسبی ندارد.

مثال:

Agent در یک محیط آموزشی عملکرد بسیار خوبی دارد، اما وقتی محیط کمی تغییر می‌کند، نمی‌تواند عملکرد خود را حفظ کند.

راهکارهای اشاره‌شده در فصل:

- Regularization
- استفاده از نمونه‌های بیشتر
- توجه به Generalization

## **36. Generalization**

تعمیم‌پذیری یعنی توانایی مدل برای عملکرد مناسب در شرایط و داده‌هایی که قبلاً با آن‌ها مواجه نشده است.

یک Agent خوب نباید فقط سناریوهای آموزشی را یاد بگیرد؛ باید بتواند آموخته‌های خود را به شرایط جدید نیز تعمیم دهد.

# **بخش پنجم: چالش‌های بنیادی یادگیری تقویتی**

## **37. Evaluative Feedback**

بازخورد ارزیابی‌کننده فقط به Agent می‌گوید عملکردش خوب بوده یا بد.

اما الزاماً توضیح نمی‌دهد که چرا یک تصمیم خوب یا بد بوده است.

مثال:

در یک بازی، Agent متوجه می‌شود که برنده شده است، اما صرفاً از نتیجه برد نمی‌تواند بفهمد دقیقاً کدام حرکت باعث موفقیت شده است.

این موضوع باعث می‌شود Agent نیاز به تجربه و آزمایش داشته باشد.

## **38. Exploration**

**اکتشاف** یعنی Agent اقدامات جدید را امتحان کند تا اطلاعات بیشتری درباره محیط و پیامدهای Actionها به دست آورد.

مثال:

یک ربات برای پیدا کردن مسیر بهتر، مسیرهای جدید را امتحان می‌کند.

## **39. Exploitation**

**بهره‌برداری** یعنی Agent از اطلاعات و تجربیات قبلی خود استفاده کند و Actionهایی را انتخاب کند که می‌داند احتمالاً پاداش خوبی دارند.

مثال:

اگر ربات قبلاً مسیری را پیدا کرده که به هدف می‌رسد، دوباره از همان مسیر استفاده می‌کند.

## **40. Exploration vs. Exploitation Trade-off**

از مفاهیم کلیدی RL

یکی از مهم‌ترین مسائل یادگیری تقویتی، ایجاد تعادل بین Exploration و Exploitation است.

| Exploration                | Exploitation                     |
| -------------------------- | -------------------------------- |
| امتحان کردن گزینه‌های جدید | استفاده از دانش قبلی             |
| کسب اطلاعات بیشتر          | استفاده از اطلاعات موجود         |
| امکان کشف راه بهتر         | دریافت پاداش بر اساس تجربه       |
| احتمال شکست بیشتر          | احتمال از دست دادن فرصت‌های جدید |

اگر Agent همیشه Exploration انجام دهد، ممکن است هیچ‌وقت از دانش قبلی خود به‌خوبی استفاده نکند.

اگر همیشه Exploitation انجام دهد، ممکن است هرگز راه‌حل بهتری پیدا نکند.

هدف پیدا کردن تعادل مناسب بین این دو است.

## **41. Sample Feedback**

در مسائل واقعی، Agent تمام اطلاعات ممکن را در اختیار ندارد.

بلکه فقط نمونه‌هایی از تجربه و بازخورد را دریافت می‌کند.

به همین دلیل باید از تجربه‌های محدود خود درباره رفتار کلی محیط یاد بگیرد.

این موضوع یادگیری را دشوارتر می‌کند؛ چون Agent باید از اطلاعات ناقص، روابط پیچیده را تخمین بزند.

## **42. Sample Efficiency**

**کارایی نمونه‌ای** یعنی یک الگوریتم با چه میزان تجربه یا تعداد نمونه می‌تواند به عملکرد مطلوب برسد.

در DRL یکی از مشکلات مهم این است که Agent ممکن است برای یادگیری یک وظیفه پیچیده به میلیون‌ها نمونه تعامل نیاز داشته باشد.

در مقایسه، انسان‌ها معمولاً بعضی مهارت‌ها را با تجربه‌های بسیار کمتری یاد می‌گیرند.

عوامل مؤثر:

- پیچیدگی محیط
- تعداد وضعیت‌های ممکن
- تعداد اقدامات ممکن
- دشواری پیش‌بینی نتایج
- کیفیت الگوریتم یادگیری

## **43. Transfer Learning**

**انتقال یادگیری** یعنی استفاده از دانش به‌دست‌آمده از یک وظیفه برای یادگیری وظیفه‌ای دیگر.

مثال:

رباتی که قبلاً یاد گرفته چگونه یک چکش را بردارد، می‌تواند از دانش قبلی خود برای یادگیری نحوه برداشتن پیچ‌گوشتی استفاده کند.

مزایا:

- کاهش نیاز به آموزش از صفر
- صرفه‌جویی در زمان
- کاهش هزینه یادگیری
- استفاده مجدد از دانش قبلی

## **44. Hierarchical Reinforcement Learning**

یادگیری تقویتی سلسله‌مراتبی تلاش می‌کند رفتارهای پیچیده را به مجموعه‌ای از وظایف یا مهارت‌های کوچک‌تر تقسیم کند.

مثلاً برای رسیدن یک ربات به مقصد:

1. حرکت کردن
2. تشخیص موانع
3. عبور از موانع
4. پیدا کردن مسیر
5. رسیدن به مقصد

این روش می‌تواند به سازمان‌دهی تصمیم‌ها و استفاده مجدد از مهارت‌های یادگرفته‌شده کمک کند.

آزمونی برای بررسی این موضوع که آیا یک ماشین می‌تواند در مکالمه، انسان را متقاعد کند که با یک انسان دیگر صحبت می‌کند یا خیر.

هدف این آزمون بررسی نوعی از رفتار هوشمندانه ماشین است.

ممکن است یک حوزه ابتدا با هیجان و سرمایه‌گذاری زیاد روبه‌رو شود، سپس به دلیل برآورده نشدن انتظارات وارد دوره رکود شود و بعد با روش‌ها و فناوری‌های بهتر دوباره پیشرفت کند.

## **48. AI Hype Cycle**

چرخه هیجان هوش مصنوعی به بالا و پایین شدن انتظارات عمومی و سرمایه‌گذاری در این حوزه اشاره دارد.

نکات مهم:

- Hype می‌تواند علاقه و سرمایه‌گذاری ایجاد کند.
- انتظارات غیرواقعی می‌توانند به ناامیدی منجر شوند.
- باید بین پیشرفت واقعی و تبلیغات تفاوت قائل شد.
- دستاوردهای علمی به زمان نیاز دارند.

## **49. TD-Gammon**

یکی از نمونه‌های تاریخی استفاده از یادگیری تقویتی و شبکه عصبی در بازی تخته‌نرد.

نکات مهم مطرح‌شده در فصل:

- از شبکه عصبی برای پیش‌بینی احتمال پیروزی استفاده می‌کرد.
- با بازی کردن و تجربه‌اندوزی عملکرد خود را بهبود می‌داد.
- از ایده Trial and Error استفاده می‌کرد.
- نمونه‌ای از تلاش‌های اولیه برای یادگیری استراتژی بازی با شبکه عصبی بود.

این سیستم نمونه‌ای از پیشرفت‌های پیش از دوران مدرن Deep Learning محسوب می‌شود.

## **50. Inverse Reinforcement Learning (IRL)**

یادگیری تقویتی معکوس روشی است که در آن سیستم تلاش می‌کند از رفتار یک عامل متخصص، هدف یا تابع پاداش پنهان او را استنباط کند.

تفاوت مهم:

| RL                               | IRL                                           |
| -------------------------------- | --------------------------------------------- |
| یادگیری رفتار از طریق پاداش      | استنباط پاداش از رفتار متخصص                  |
| پاداش مشخص است                   | پاداش موردنظر باید تخمین زده شود              |
| Agent رفتار مناسب را یاد می‌گیرد | Agent ابتدا هدف رفتار متخصص را استخراج می‌کند |

مثال فصل: هلیکوپترهای خودمختار که از رفتار و کنترل خلبانان متخصص برای یادگیری استفاده می‌کنند.

## **51. Policy Gradient Methods**

روش‌های Policy Gradient خانواده‌ای از الگوریتم‌های RL هستند که مستقیماً پارامترهای Policy را برای بهبود عملکرد آن بهینه می‌کنند.

ایده اصلی:

به‌جای اینکه فقط ارزش Actionها را تخمین بزنیم، مستقیماً Policy را تغییر می‌دهیم تا احتمال انتخاب اقدامات مطلوب افزایش پیدا کند.

در فصل به استفاده از این روش‌ها برای آموزش ربات فوتبال و افزایش سرعت حرکت آن اشاره شده است.

## **52. Deep Q-Network (DQN)**

یکی از مهم‌ترین نقاط عطف تاریخی DRL

**DQN**

الگوریتمی که از شبکه عصبی عمیق برای تخمین ارزش اقدامات استفاده می‌کند.

DQN که در پژوهش‌های DeepMind و به‌خصوص کارهای Volodymyr Mnih و همکاران در سال‌های ۲۰۱۳ و ۲۰۱۵ مطرح شد، نقطه عطف مهمی در DRL بود.

ویژگی‌های مهم:

- یادگیری از تصاویر خام بازی‌های Atari
- استفاده از CNN برای استخراج ویژگی از تصاویر
- تخمین ارزش Actionها
- یادگیری بدون نیاز به تعریف دستی ویژگی‌های تصویری بازی
- امکان یادگیری از یک مجموعه بازی‌های مختلف با معماری مشترک

### **CNN چیست؟**

Convolutional Neural Network نوعی شبکه عصبی است که به‌خصوص برای پردازش داده‌های ساختاریافته مکانی مانند تصاویر کاربرد دارد.

در DQN، CNN می‌تواند از تصویر بازی ویژگی‌هایی مانند موقعیت بازیکن، توپ و موانع را استخراج کند.

نکته مهم: DQN به Agent امکان داد از ورودی تصویری خام یاد بگیرد، به‌جای اینکه تمام اطلاعات بازی از قبل به شکل ویژگی‌های ساده و دستی در اختیارش قرار بگیرند.

## **53. Game of Go و پیچیدگی فضای حالت**

بازی Go نمونه‌ای از محیط‌هایی است که تعداد وضعیت‌ها و مسیرهای احتمالی آن بسیار زیاد است.

چرا؟

- تعداد حرکات ممکن در هر مرحله زیاد است.
- هر حرکت روی کل صفحه اثر می‌گذارد.
- ترکیب حرکت‌های متوالی تعداد بسیار زیادی بازی متفاوت ایجاد می‌کند.

این مسئله نشان می‌دهد چرا روش‌های سنتی جست‌وجو برای مسائل با فضای حالت بسیار بزرگ محدودیت دارند و روش‌های یادگیری عمیق می‌توانند مفید باشند.

## **54. AI Singularity**

**تکینگی هوش مصنوعی** یک مفهوم فرضی است که به نقطه‌ای در آینده اشاره دارد که در آن هوش مصنوعی از هوش انسان فراتر می‌رود.

یکی از ایده‌های مرتبط با آن:

### **Self-improving AI**

سیستمی که بتواند توانایی‌های خودش را بهبود دهد؛ برای مثال:

- الگوریتم‌های یادگیری بهتر بسازد.
- محاسبات خود را بهینه کند.
- نسخه‌های توانمندتری از خود ایجاد کند.

این موضوع در فصل به‌عنوان یک احتمال نظری و بلندمدت مطرح می‌شود، نه یک اتفاق قطعی با زمان مشخص.

## **55. AI Safety**

ایمنی هوش مصنوعی به طراحی و توسعه سیستم‌هایی اشاره دارد که رفتار آن‌ها قابل کنترل، قابل اعتماد و همسو با اهداف موردنظر باشد.

چالش‌های مطرح‌شده:

- Bias: سوگیری الگوریتمی
- Misuse: استفاده نادرست
- Unintended Consequences: پیامدهای ناخواسته
- Safety: ایمنی سیستم‌های خودمختار

فصل تأکید می‌کند که مسائل عملی مانند پایداری و تعمیم‌پذیری DRL نیز باید جدی گرفته شوند.

## **59. Stability**

پایداری در DRL به این موضوع اشاره دارد که فرآیند یادگیری و عملکرد Agent تا چه اندازه قابل اتکا و کنترل است.

یک الگوریتم ناپایدار ممکن است:

- عملکرد متغیری داشته باشد.
- در طول آموزش نوسانات زیادی نشان دهد.
- به تغییرات کوچک حساس باشد.
- به‌سختی به عملکرد مطلوب برسد.

## **60. Safety in Exploration**

در RL، Agent برای یادگیری باید Actionهای جدید را امتحان کند.

اما در محیط‌های واقعی، بعضی اشتباهات می‌توانند خطرناک باشند.

مثال:

یک خودروی خودران نمی‌تواند برای یادگیری نحوه رانندگی، هر Action اشتباهی را در خیابان واقعی امتحان کند.

بنابراین Exploration باید با در نظر گرفتن ایمنی انجام شود.

## **61. Transfer Learning و Hierarchical RL به‌عنوان راهکار**

فصل به این دو روش به‌عنوان رویکردهایی برای استفاده مؤثرتر از تجربه‌های قبلی اشاره می‌کند.

- Transfer Learning: انتقال دانش از وظیفه قبلی به وظیفه جدید.
- Hierarchical RL: ساخت رفتارهای پیچیده از مهارت‌ها و اقدامات سطح پایین‌تر.

این روش‌ها می‌توانند نیاز به شروع یادگیری از صفر را کاهش دهند.

# **بخش نهم: ساختار یادگیری و الگوریتم‌های کتاب**

## **69. Tabular Reinforcement Learning**

یادگیری تقویتی جدولی روشی است که در آن اطلاعات مربوط به Stateها و Actionها در قالب جدول ذخیره می‌شوند.

مثال:

یک ربات در محیطی شبیه Grid World حرکت می‌کند. اگر تعداد وضعیت‌ها و اقدامات محدود باشد، می‌توان اطلاعات مربوط به آن‌ها را در جدول نگهداری کرد.

ویژگی‌ها:

- مناسب برای مسائل کوچک
- امکان بررسی وضعیت‌ها و اقدامات مختلف
- درک ساده‌تر مفاهیم پایه RL
- محدودیت در محیط‌های بسیار پیچیده و بزرگ

## **70. Value-Based Methods**

روش‌های مبتنی بر ارزش، تلاش می‌کنند ارزش Stateها یا Actionها را یاد بگیرند.

هدف این است که Agent بتواند تشخیص دهد کدام Action در یک State مشخص، در بلندمدت ارزش بیشتری دارد.

مثال: Q-Learning و DQN.

## **71. Policy-Based Methods**

روش‌های مبتنی بر Policy مستقیماً سیاست تصمیم‌گیری Agent را یاد می‌گیرند.

به‌جای اینکه ابتدا ارزش تمام Actionها را تخمین بزنند، پارامترهای Policy را بهینه می‌کنند.

مثال: Policy Gradient.

## **72. Actor-Critic Methods**

این روش‌ها دو رویکرد Value-Based و Policy-Based را با هم ترکیب می‌کنند.

- Actor: انتخاب Action
- Critic: ارزیابی تصمیم

### ارتباط مهم‌ترین مفاهیم

**ساختار کلی یک مسئله RL:**

1. **Environment**
   - دارای `State` و `State Space` است.
   - وضعیت فعلی را از طریق `Observation` در اختیار Agent قرار می‌دهد.

2. **Agent**
   - با استفاده از `Policy` تصمیم می‌گیرد.
   - یک `Action` انتخاب می‌کند.

3. **Environment**
   - Action را دریافت می‌کند.
   - باعث تغییر `State` می‌شود.
   - یک `Reward` تولید می‌کند.

4. **Experience**
   - حاصل تعامل Agent با Environment است.
   - شامل State، Action، Reward و State بعدی است.

5. **Learning**
   - Agent از Experienceها یاد می‌گیرد.
   - با هدف بهبود `Policy` و `Value Function`.

6. **تکرار چرخه**
   - این فرایند برای Time Stepهای بعدی تکرار می‌شود.
