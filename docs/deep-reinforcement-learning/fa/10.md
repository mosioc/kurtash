# **خلاصه جامع فصل ۱۰ کتاب Grokking Deep Reinforcement Learning**

فصل دهم به معرفی روش‌هایی برای بهبود الگوریتم‌های مبتنی بر DQN می‌پردازد. تمرکز اصلی این فصل بر افزایش **Sample Efficiency**، بهبود معماری شبکه عصبی، انتخاب هوشمندانه‌تر تجربه‌ها برای آموزش و افزایش پایداری فرایند یادگیری است.

در فصل‌های قبلی با DQN و Double DQN آشنا شدیم. در این فصل، چند تکنیک تکمیلی معرفی می‌شوند که می‌توانند عملکرد این الگوریتم‌ها را بهبود دهند:

1. **Dueling Network Architecture**: تفکیک ارزش State از مزیت Action.
2. **Prioritized Experience Replay (PER)**: اولویت‌بندی تجربه‌ها بر اساس میزان اهمیت یادگیری.
3. **Polyak Averaging**: به‌روزرسانی تدریجی و نرم Target Network.
4. **Dueling DDQN**: ترکیب معماری Dueling با الگوریتم Double DQN.

نکته مهم این است که این روش‌ها الزاماً الگوریتم‌های مستقل و جایگزین DQN نیستند؛ بلکه تکنیک‌هایی برای بهبود معماری، نمونه‌برداری و پایداری آموزش آن محسوب می‌شوند.

## **۱. هدف اصلی فصل: Sample Efficiency**

**Sample Efficiency** یا بهره‌وری نمونه‌ای، به این معناست که عامل بتواند با تعداد کمتری از تعاملات با محیط، به عملکرد مطلوب برسد.

در Reinforcement Learning، هر تجربه معمولاً شامل اطلاعات زیر است:

```
Experience = (State, Action, Reward, Next State, Done)
```

عامل با جمع‌آوری این تجربه‌ها و استفاده از آن‌ها برای به‌روزرسانی شبکه عصبی، یاد می‌گیرد که چه Actionهایی در هر State ارزش بیشتری دارند.

اما دو مشکل وجود دارد:

- تمام تجربه‌ها به یک اندازه برای یادگیری مفید نیستند.
- شبکه عصبی ممکن است نتواند به‌خوبی اطلاعات مشترک میان Actionهای مختلف را یاد بگیرد.

فصل دهم برای حل این مشکلات، دو ایده اصلی را دنبال می‌کند:

- **بهبود نحوه نمایش و تخمین Q-Value:** با استفاده از Dueling Network.
- **بهبود نحوه استفاده از تجربه‌های ذخیره‌شده:** با استفاده از Prioritized Experience Replay.

همچنین از Polyak Averaging برای به‌روزرسانی تدریجی Target Network استفاده می‌شود.

## **۲. Dueling Network Architecture**

### **۲.۱. مشکل معماری معمولی DQN**

در DQN معمولی، شبکه عصبی مستقیماً مقدار Q را برای هر Action در یک State تخمین می‌زند.

تابع Q به شکل زیر است:

\\[ Q(s,a) \\]

یعنی:

- `s`: وضعیت فعلی محیط (State)
- `a`: عملی که عامل انتخاب می‌کند (Action)
- `Q(s,a)`: ارزش انجام آن Action در آن State

برای مثال، در بازی CartPole فرض کنیم عامل دو Action دارد:

- حرکت به چپ
- حرکت به راست

شبکه عصبی باید ارزش هر دو Action را تخمین بزند.

مشکل اینجاست که ممکن است ارزش کلی یک State بسیار مهم‌تر از تفاوت میان Actionهای موجود در آن State باشد.

مثلاً فرض کن عامل در وضعیتی قرار دارد که میله تقریباً در مرکز است و سرعت آن کم است. این State به‌طور کلی وضعیت مناسبی است. حتی اگر حرکت به چپ و راست ارزش‌های متفاوتی داشته باشند، هر دو از یک وضعیت پایه و مشترک برخوردارند.

در معماری معمولی، شبکه برای تخمین ارزش Actionها باید این اطلاعات مشترک را نیز یاد بگیرد.

**ایده Dueling Network این است که اطلاعات مشترک State را از اطلاعات اختصاصی هر Action جدا کنیم.**

### **۲.۲. تفکیک Q-Function به دو تابع V و A**

در Dueling Network، تابع Q به دو بخش تقسیم می‌شود:

**۱. State-Value Function یا V-Function**

ارزش قرار داشتن در یک State را نشان می‌دهد، بدون اینکه Action مشخصی را در نظر بگیریم.

\\[ V(s) \\]

**۲. Advantage Function یا A-Function**

نشان می‌دهد یک Action نسبت به میانگین ارزش Actionهای موجود در همان State چقدر بهتر یا بدتر است.

\\[ A(s,a) \\]

به عبارت دیگر:

- V نشان‌دهنده ارزش کلی State است.
- A نشان‌دهنده مزیت نسبی یک Action در آن State است.

برای مثال:

فرض کن در یک State خاص، ارزش کلی وضعیت ۱۰ باشد.

| Action       | Advantage |
| ------------ | --------- |
| حرکت به چپ   | +3        |
| حرکت به راست | -2        |

در این مثال، حرکت به چپ نسبت به وضعیت کلی مزیت بیشتری دارد و حرکت به راست نسبت به آن ضعیف‌تر است.

البته این اعداد صرفاً مثالی برای درک مفهوم هستند.

### **۲.۳. رابطه Q، V و A**

ایده اصلی Dueling Network را می‌توان به شکل زیر نمایش داد:

```
                 State (s)
                     |
              Shared Network
                     |
              Shared Features
                /         \
               /           \
              V             A
         State Value     Advantage
              |             |
              |       Advantage per
              |          Action
              |             |
               \           /
                \         /
                 Q-Values
```

شبکه ابتدا ویژگی‌های مشترک State را استخراج می‌کند و سپس آن‌ها را به دو Stream متفاوت می‌فرستد:

- Value Stream: تخمین V(s)
- Advantage Stream: تخمین A(s,a)

در نهایت، خروجی این دو Stream با یکدیگر ترکیب می‌شود تا Q-Value هر Action به دست آید.

### **۲.۴. چرا نمی‌توان مستقیماً V و A را جمع کرد؟**

رابطه مفهومی اولیه به این شکل است:

\\[ Q(s,a)=V(s)+A(s,a) \\]

اما یک مشکل ریاضی وجود دارد.

اگر فقط Q را داشته باشیم، نمی‌توانیم به‌صورت یکتا مشخص کنیم چه بخشی از آن متعلق به V و چه بخشی متعلق به A است.

برای مثال، ممکن است دو مجموعه مقدار متفاوت برای V و A داشته باشیم که مجموع آن‌ها Q یکسانی تولید کند.

این مسئله را **Identifiability Problem** می‌نامند.

برای حل این مشکل، معماری Dueling از یک عملیات Aggregation استفاده می‌کند.

### **۲.۵. Aggregating the Value and Advantage Streams**

فرمول استاندارد Dueling Network به شکل زیر است:

\\[ Q(s,a;\theta,\alpha,\beta) = V(s;\theta,\beta) + \left( A(s,a;\theta,\alpha) - \frac{1}{|\mathcal{A}|} \sum\_{a'} A(s,a';\theta,\alpha) \right) \\]

در این فرمول:

- \\(\theta\\): پارامترهای لایه‌های مشترک
- \\(\beta\\): پارامترهای Value Stream
- \\(\alpha\\): پارامترهای Advantage Stream
- \\(|\mathcal{A}|\\): تعداد Actionهای ممکن

در واقع، میانگین Advantage تمام Actionها از Advantage هر Action کم می‌شود.

این کار باعث می‌شود Advantageها حول میانگین صفر مرکزدهی شوند و مشکل عدم یکتایی تجزیه تا حد زیادی برطرف شود.

**نکته:** در بعضی پیاده‌سازی‌ها به‌جای میانگین Advantage از Max Advantage استفاده می‌شود، اما فرم استاندارد مقاله Dueling Network از میانگین استفاده می‌کند.

### **۲.۶. مزایای Dueling Network**

- **Better Generalization:** اطلاعات مشترک State میان تمام Actionها به اشتراک گذاشته می‌شود.
- **Faster Learning:** یادگیری ارزش کلی State می‌تواند به تخمین بهتر ارزش Actionهای مختلف کمک کند.
- **Better Action Comparison:** عامل می‌تواند تفاوت ارزش Actionهای مشابه را بهتر تشخیص دهد.
- **Sample Efficiency:** استفاده مؤثرتر از تجربه‌های موجود می‌تواند نیاز به تعاملات کمتری با محیط را ایجاد کند.

یک نکته مهم: Dueling Network تضمین نمی‌کند که هر تجربه به‌صورت مستقیم تمام Actionها را به‌روزرسانی کند. مزیت اصلی آن، اشتراک ویژگی‌ها و یادگیری مشترک Value Stream و Advantage Stream است.

### **۲.۷. چه زمانی Dueling Network مفیدتر است؟**

این معماری به‌خصوص زمانی مفید است که:

- تعداد زیادی Action وجود دارد.
- ارزش کلی State اطلاعات مهمی درباره تمام Actionها ارائه می‌دهد.
- تفاوت ارزش Actionها در بسیاری از Stateها کم است.
- بعضی Stateها ارزش بالایی دارند، اما انتخاب Action در آن‌ها اهمیت کمتری دارد.

## **۳. Continuously Updating the Target Network**

### **۳.۱. یادآوری Target Network**

در DQN از دو شبکه عصبی استفاده می‌کنیم:

**Online Network**

شبکه اصلی است که با استفاده از تجربه‌ها آموزش می‌بیند و پارامترهای آن در هر مرحله به‌روزرسانی می‌شوند.

**Target Network**

شبکه‌ای است که برای محاسبه Target Q-Value استفاده می‌شود و به پایداری آموزش کمک می‌کند.

در روش معمول DQN، پارامترهای Target Network برای مدتی ثابت می‌مانند و پس از تعداد مشخصی از مراحل، از Online Network کپی می‌شوند.

```
Online Network:
θ  →  θ₁  →  θ₂  →  θ₃  →  θ₄

Target Network:
θ' →  θ'  →  θ'  →  θ'  →  θ₄
```

این روش به نام Hard Target Update شناخته می‌شود.

### **۳.۲. مشکل Hard Update**

در این روش دو مشکل وجود دارد:

1. Target Network برای مدتی از تغییرات Online Network عقب می‌ماند.
2. هنگام کپی کردن پارامترها، تغییر ناگهانی و بزرگی در Target Network اتفاق می‌افتد.

این تغییرات ناگهانی ممکن است باعث ناپایداری در تخمین Target Q-Value شوند.

### **۳.۳. Polyak Averaging**

برای حل این مشکل، از Polyak Averaging استفاده می‌کنیم.

در این روش، به‌جای کپی کامل پارامترهای Online Network، هر بار فقط بخشی از آن‌ها وارد Target Network می‌شود.

فرمول:

\\[ \theta' \leftarrow \tau\theta+(1-\tau)\theta' \\]

در این فرمول:

- \\(\theta\\): پارامترهای Online Network
- \\(\theta'\\): پارامترهای Target Network
- \\(\tau\\): ضریب ترکیب یا Mixing Factor

### **۳.۴. عملکرد Tau**

پارامتر Tau تعیین می‌کند چه مقدار از وزن‌های Online Network وارد Target Network شوند.

```
Small Tau
   |
   +--> Small contribution from Online Network
   +--> Slow Target Network update
   +--> More gradual changes

Large Tau
   |
   +--> Large contribution from Online Network
   +--> Faster Target Network update
   +--> Less smoothing
```

برای مثال، اگر:

\\[ \tau=0.1 \\]

باشد، در هر مرحله:

- ۱۰ درصد از وزن‌های Online Network
- ۹۰ درصد از وزن‌های قبلی Target Network

در ساخت وزن‌های جدید Target Network مشارکت می‌کنند.

اگر Tau برابر یک باشد:

\\[ \theta'=\theta \\]

یعنی Target Network دقیقاً با Online Network برابر می‌شود.

اگر Tau برابر صفر باشد، Target Network هیچ تغییری نمی‌کند.

### **۳.۵. تفاوت Hard Update و Polyak Averaging**

| ویژگی                | Hard Update     | Polyak Averaging    |
| -------------------- | --------------- | ------------------- |
| نحوه به‌روزرسانی     | کپی کامل وزن‌ها | ترکیب تدریجی وزن‌ها |
| زمان به‌روزرسانی     | دوره‌ای         | در هر مرحله         |
| تغییرات              | ناگهانی         | تدریجی              |
| کنترل تغییرات        | با فاصله زمانی  | با Tau              |
| رفتار Target Network | ثابت و سپس جهشی | حرکت نرم و پیوسته   |

**نتیجه:** Polyak Averaging باعث می‌شود Target Network به‌صورت تدریجی تغییر کند و همواره با کمی تأخیر نسبت به Online Network حرکت کند.

البته این روش به‌تنهایی تضمین‌کننده پایداری کامل آموزش نیست.

## **۴. Prioritized Experience Replay (PER)**

### **۴.۱. یادآوری Experience Replay**

در DQN، تجربه‌های عامل در Replay Buffer ذخیره می‌شوند.

هر تجربه معمولاً به شکل زیر است:

\\[ (s_t,a_t,r\_{t+1},s\_{t+1},d\_{t+1}) \\]

که شامل State، Action، Reward، Next State و وضعیت پایان Episode است.

در آموزش، به‌جای استفاده مستقیم از آخرین تجربه، یک Batch از تجربه‌های ذخیره‌شده انتخاب می‌شود.

در روش معمول، این تجربه‌ها با احتمال یکسان انتخاب می‌شوند.

این روش را Uniform Random Sampling می‌نامیم.

### **۴.۲. مشکل Uniform Random Sampling**

مشکل اصلی این است که تمام تجربه‌ها ارزش یادگیری یکسانی ندارند.

برای مثال:

- بعضی تجربه‌ها اطلاعات جدید و مهمی ارائه می‌کنند.
- بعضی تجربه‌ها نتیجه‌ای کاملاً قابل پیش‌بینی دارند.
- بعضی تجربه‌ها تفاوت زیادی میان مقدار پیش‌بینی‌شده و نتیجه واقعی ایجاد می‌کنند.

اگر تمام تجربه‌ها با احتمال یکسان انتخاب شوند، ممکن است زمان زیادی صرف یادگیری از تجربه‌هایی شود که اطلاعات جدید چندانی ندارند.

**ایده PER:** تجربه‌هایی که پتانسیل یادگیری بیشتری دارند، باید با احتمال بیشتری وارد Batch آموزشی شوند.

### **۴.۳. معیار تشخیص تجربه مهم: TD Error**

سؤال اصلی این است:

چطور تشخیص دهیم کدام تجربه برای یادگیری مهم‌تر است؟

در فصل دهم، پاسخ اصلی استفاده از **Temporal Difference Error (TD Error)** است.

TD Error اختلاف میان مقدار پیش‌بینی‌شده و مقدار Target را نشان می‌دهد.

در حالت ساده:

\\[ \delta = Target-Q(s,a) \\]

برای یک Target یک‌مرحله‌ای در DQN:

\\[ \delta = r+\gamma\max\_{a'}Q(s',a';\theta') -Q(s,a;\theta) \\]

که در آن:

- \\(r\\): پاداش دریافت‌شده
- \\(\gamma\\): Discount Factor
- \\(s'\\): State بعدی
- \\(\theta\\): پارامترهای Online Network
- \\(\theta'\\): پارامترهای Target Network

هرچه قدر مطلق TD Error بزرگ‌تر باشد، اختلاف میان پیش‌بینی عامل و Target بیشتر است.

بنابراین تجربه می‌تواند اطلاعات جدیدتری برای یادگیری فراهم کند.

### **۴.۴. چرا از Absolute TD Error استفاده می‌کنیم؟**

TD Error می‌تواند مثبت یا منفی باشد:

- TD Error مثبت: Target از مقدار پیش‌بینی‌شده بیشتر است.
- TD Error منفی: Target از مقدار پیش‌بینی‌شده کمتر است.

اما در اولویت‌بندی، بزرگی اختلاف اهمیت دارد، نه جهت آن.

بنابراین از قدر مطلق استفاده می‌کنیم:

\\[ Priority \propto |\delta| \\]

**نکته:** TD Error بزرگ لزوماً به معنای Reward بزرگ نیست. ممکن است یک تجربه Reward منفی داشته باشد اما به دلیل اختلاف زیاد با پیش‌بینی عامل، بسیار آموزنده باشد.

این دقیقاً یکی از نکات مهم فصل است: نباید فقط تجربه‌های دارای Reward مثبت یا بزرگ را مهم تلقی کنیم.

## **۵. Stochastic Prioritization**

### **۵.۱. مشکل Greedy Prioritization**

یک راه ساده این است که همیشه تجربه‌ای با بیشترین TD Error را انتخاب کنیم.

اما این روش مشکلاتی دارد:

- ممکن است تجربه‌های خاص بیش‌ازحد تکرار شوند.
- تنوع تجربه‌های آموزشی کاهش پیدا کند.
- تجربه‌های دارای TD Error پایین فرصت کافی برای یادگیری پیدا نکنند.
- نویز یا Outlierها ممکن است فرایند آموزش را تحت تأثیر قرار دهند.

### **۵.۲. راه‌حل: Stochastic Prioritization**

به‌جای انتخاب قطعی مهم‌ترین تجربه، احتمال انتخاب هر تجربه را متناسب با اولویت آن تعیین می‌کنیم.

```
Experience A: High Priority   → High Probability
Experience B: Medium Priority → Medium Probability
Experience C: Low Priority    → Low Probability
```

در این روش:

- تجربه‌های مهم‌تر شانس بیشتری برای انتخاب شدن دارند.
- تجربه‌های کم‌اهمیت‌تر نیز همچنان امکان انتخاب شدن دارند.

بنابراین هم از اطلاعات ارزشمند بیشتر استفاده می‌کنیم و هم تنوع داده‌های آموزشی را حفظ می‌کنیم.

## **۶. دو روش اصلی Prioritization**

در PER دو روش اصلی برای تعیین Priority تجربه‌ها وجود دارد:

1. Proportional Prioritization
2. Rank-Based Prioritization

هر دو روش از TD Error استفاده می‌کنند، اما نحوه محاسبه Priority در آن‌ها متفاوت است.

### **۶.۱. Proportional Prioritization**

در این روش، Priority هر تجربه مستقیماً متناسب با قدر مطلق TD Error آن است.

فرمول:

\\[ p_i=|\delta_i|+\epsilon \\]

که در آن:

- \\(p_i\\): اولویت تجربه شماره i
- \\(\delta_i\\): TD Error تجربه
- \\(\epsilon\\): مقدار مثبت کوچکی برای جلوگیری از Priority صفر

سپس احتمال انتخاب هر تجربه محاسبه می‌شود:

\\[ P(i)=\frac{p_i^\alpha}{\sum_k p_k^\alpha} \\]

در این فرمول:

- \\(P(i)\\): احتمال انتخاب تجربه i
- \\(p_i\\): Priority تجربه
- \\(\alpha\\): میزان تأثیر Priority بر احتمال نمونه‌برداری

### **۶.۲. نقش Alpha**

پارامتر Alpha مشخص می‌کند که تا چه اندازه نمونه‌برداری باید بر اساس Priority انجام شود.

```
Alpha = 0
   |
   +--> Uniform Random Sampling
   +--> All experiences have equal probability

Alpha = 0.5
   |
   +--> Partial Prioritization
   +--> High-priority experiences are favored

Alpha = 1
   |
   +--> Full Prioritization
   +--> Sampling probability follows raw priorities
```

بنابراین:

- Alpha پایین: نمونه‌برداری به Uniform Sampling نزدیک‌تر است.
- Alpha بالا: تفاوت Priorityها تأثیر بیشتری بر احتمال انتخاب دارد.

**نکته:** Alpha برابر یک به معنای انتخاب قطعی تجربه دارای بیشترین TD Error نیست؛ همچنان از نمونه‌برداری احتمالاتی استفاده می‌شود.

### **۶.۳. Rank-Based Prioritization**

در Proportional Prioritization، ممکن است یک TD Error بسیار بزرگ باعث شود یک تجربه نسبت به بقیه اولویت بسیار زیادی پیدا کند.

برای کاهش حساسیت به Outlierها، از Rank-Based Prioritization استفاده می‌کنیم.

در این روش، به‌جای استفاده مستقیم از مقدار TD Error، تجربه‌ها را بر اساس قدر مطلق TD Error مرتب می‌کنیم.

سپس به هر تجربه یک Rank اختصاص می‌دهیم.

```
Experience       | Absolute TD Error | Rank
--------------------------------------------
Experience A     |       100         |  1
Experience B     |        50         |  2
Experience C     |        20         |  3
Experience D     |         5         |  4
Experience E     |         1         |  5
```

Priority هر تجربه از رابطه زیر به دست می‌آید:

\\[ p_i=\frac{1}{rank(i)} \\]

سپس احتمال انتخاب تجربه:

\\[ P(i)=\frac{p_i^\alpha}{\sum_k p_k^\alpha} \\]

### **۶.۴. مثال Rank-Based Prioritization**

با فرض Alpha برابر یک:

```
Rank 1  → Priority = 1.00
Rank 2  → Priority = 0.50
Rank 3  → Priority = 0.33
Rank 4  → Priority = 0.25
Rank 5  → Priority = 0.20
```

بنابراین تجربه دارای Rank یک بیشترین احتمال انتخاب را دارد.

### **۶.۵. مقایسه Proportional و Rank-Based**

| ویژگی                        | Proportional   | Rank-Based             |
| ---------------------------- | -------------- | ---------------------- |
| معیار Priority               | مقدار TD Error | رتبه TD Error          |
| حساسیت به Outlier            | بیشتر          | کمتر                   |
| توجه به بزرگی اختلاف‌ها      | مستقیم         | غیرمستقیم              |
| مقاومت در برابر نویزهای بزرگ | کمتر           | بیشتر                  |
| پیچیدگی مرتب‌سازی            | ندارد          | نیازمند مدیریت رتبه‌ها |

**مزیت Proportional:**

اگر اختلاف TD Errorها واقعاً معنادار باشد، این روش می‌تواند تفاوت اهمیت تجربه‌ها را بهتر منعکس کند.

**مزیت Rank-Based:**

اگر یک تجربه TD Error بسیار بزرگی داشته باشد، نمی‌تواند صرفاً به دلیل بزرگی عدد، فاصله بسیار زیادی با سایر تجربه‌ها ایجاد کند.

**محدودیت Rank-Based:**

این روش نسبت به بزرگی واقعی TD Error حساسیت کمتری دارد. برای مثال، تفاوت بین TD Errorهای ۱۰۰ و ۵۰ و تفاوت بین ۱۰۰۰ و ۵۰۰ از نظر رتبه یکسان است.

هیچ‌کدام از این دو روش در تمام مسائل Reinforcement Learning بهترین انتخاب نیستند.

## **۷. Prioritization Bias و Importance Sampling**

### **۷.۱. مشکل Bias در PER**

تا اینجا یاد گرفتیم که PER تجربه‌های مهم‌تر را با احتمال بیشتری انتخاب می‌کند.

اما این کار یک مشکل آماری ایجاد می‌کند.

در Uniform Random Sampling، تمام تجربه‌ها احتمال انتخاب یکسان دارند.

اما در Prioritized Sampling، احتمال انتخاب تجربه‌ها متفاوت است.

در نتیجه، توزیع نمونه‌های استفاده‌شده برای آموزش با توزیع نمونه‌برداری یکنواخت تفاوت پیدا می‌کند.

این مسئله می‌تواند باعث ایجاد Bias در به‌روزرسانی پارامترهای شبکه شود.

به بیان ساده:

**شبکه بیش‌ازحد تحت تأثیر تجربه‌هایی قرار می‌گیرد که Priority بیشتری دارند.**

### **۷.۲. راه‌حل: Importance Sampling**

برای کاهش این Bias از Importance Sampling استفاده می‌کنیم.

در این روش، به هر تجربه یک Weight اختصاص می‌دهیم تا اثر احتمال نمونه‌برداری غیر یکنواخت را اصلاح کنیم.

فرمول Importance Sampling Weight:

\\[ w_i= \left( \frac{1}{N\cdot P(i)} \right)^\beta \\]

که در آن:

- \\(w_i\\): وزن Importance Sampling تجربه i
- \\(N\\): تعداد کل تجربه‌های موجود در Replay Buffer
- \\(P(i)\\): احتمال انتخاب تجربه i
- \\(\beta\\): میزان اصلاح Bias

### **۷.۳. نقش Beta**

پارامتر Beta مشخص می‌کند که تا چه اندازه Bias ناشی از Prioritized Sampling اصلاح شود.

```
Beta = 0
   |
   +--> No importance-sampling correction
   +--> All weights are equal to 1

Beta = 0.5
   |
   +--> Partial bias correction

Beta = 1
   |
   +--> Full importance-sampling correction
```

در عمل معمولاً Beta از مقدار اولیه کوچک‌تری شروع می‌شود و به‌تدریج به یک می‌رسد.

به این فرایند **Beta Annealing** گفته می‌شود.

دلیل این کار آن است که در مراحل اولیه آموزش، Prioritization می‌تواند مفید باشد و در مراحل نزدیک به همگرایی، اصلاح Bias اهمیت بیشتری پیدا می‌کند.

### **۷.۴. چرا Importance Sampling Weight را Normalize می‌کنیم؟**

ممکن است بعضی Weightها بسیار بزرگ شوند و باعث ناپایداری در به‌روزرسانی شبکه شوند.

برای جلوگیری از این مسئله، Weightها را با بیشترین Weight موجود در Batch یا Buffer نرمال‌سازی می‌کنیم.

فرمول:

\\[ w_i^{norm}=\frac{w_i}{\max_j w_j} \\]

در نتیجه:

\\[ 0\<w_i^{norm}\leq 1 \\]

این کار باعث می‌شود وزن‌ها فقط مقدار به‌روزرسانی را کاهش دهند و از بزرگ شدن بیش‌ازحد آن جلوگیری شود.

### **۷.۵. Importance Sampling چگونه وارد آموزش می‌شود؟**

در آموزش معمولی، Loss هر تجربه بر اساس اختلاف Q-Value پیش‌بینی‌شده و Target محاسبه می‌شود.

در PER، Loss هر تجربه با Importance Sampling Weight آن تعدیل می‌شود.

برای مثال، اگر از Mean Squared Error استفاده کنیم:

\\[ L(\theta)= \frac{1}{B} \sum\_{i=1}^{B} w_i^{norm} \left( y_i-Q(s_i,a_i;\theta) \right)^2 \\]

که در آن:

- \\(B\\): اندازه Batch
- \\(w_i^{norm}\\): وزن Importance Sampling نرمال‌شده
- \\(y_i\\): مقدار Target Q
- \\(Q(s_i,a_i;\theta)\\): مقدار پیش‌بینی‌شده شبکه

بنابراین تجربه‌هایی که با احتمال بیشتری انتخاب شده‌اند، با استفاده از Weight مناسب تعدیل می‌شوند.

**تفاوت مهم:**

- Alpha میزان Prioritization را کنترل می‌کند.
- Beta میزان اصلاح Bias ناشی از Prioritization را کنترل می‌کند.

## **۸. ساختار کامل Prioritized Experience Replay**

حالا می‌توانیم تمام مراحل PER را کنار هم قرار دهیم.

### **۸.۱. چرخه کاری PER**

```
          Environment
               |
               v
       Collect Experience
               |
               v
        Prioritized Buffer
               |
               v
       Calculate Priorities
               |
               v
      Stochastic Sampling
               |
               v
       Sample a Mini-Batch
               |
               v
     Calculate Importance Weights
               |
               v
       Calculate TD Targets
               |
               v
        Calculate Weighted Loss
               |
               v
       Update Online Network
               |
               v
       Recalculate TD Errors
               |
               v
        Update Priorities
               |
               +----------> Repeat
```

### **۸.۲. مراحل الگوریتم**

1. عامل با محیط تعامل می‌کند.
2. تجربه جدید در Prioritized Replay Buffer ذخیره می‌شود.
3. برای تجربه‌های جدید معمولاً Priority اولیه بزرگی در نظر گرفته می‌شود تا فرصت انتخاب شدن داشته باشند.
4. با استفاده از Priorityها، احتمال انتخاب هر تجربه محاسبه می‌شود.
5. یک Mini-Batch از تجربه‌ها به‌صورت Stochastic Sampling انتخاب می‌شود.
6. Importance Sampling Weight هر تجربه محاسبه می‌شود.
7. TD Target و TD Error برای تجربه‌ها محاسبه می‌شوند.
8. Loss با استفاده از Importance Sampling Weight تعدیل می‌شود.
9. Online Network به‌روزرسانی می‌شود.
10. Priority تجربه‌های انتخاب‌شده با TD Error جدید به‌روزرسانی می‌شود.

نکته مهم این است که Priority تجربه‌ها ثابت نیست. با تغییر شبکه و بهتر شدن پیش‌بینی‌ها، TD Error نیز تغییر می‌کند و بنابراین Priority باید به‌روزرسانی شود.

### **۸.۳. ساختار داده Sum Tree**

برای پیاده‌سازی کارآمد Proportional Prioritization، می‌توان از ساختاری به نام Sum Tree استفاده کرد.

در این ساختار:

- هر Leaf Node دارای Priority یک تجربه است.
- هر Parent Node مجموع Priority فرزندان خود را نگه می‌دارد.
- Root Node مجموع Priority تمام تجربه‌ها را نگه می‌دارد.

مثال:

```
                  15
                /    \
               9      6
              / \    / \
             4   5  2   4
```

در این مثال:

- Root برابر ۱۵ است.
- Priority هر تجربه در Leaf Node قرار دارد.
- مجموع Priorityها در گره‌های بالاتر نگهداری می‌شود.

با استفاده از Sum Tree می‌توان تجربه‌ها را متناسب با Priority آن‌ها انتخاب کرد و به‌روزرسانی Priorityها را نیز کارآمد انجام داد.

## **۹. ترکیب Dueling Network و Double DQN**

### **۹.۱. Dueling DDQN چیست؟**

در این فصل از Dueling Network در کنار Double DQN استفاده می‌شود.

این ترکیب را **Dueling Double Deep Q-Network (Dueling DDQN)** می‌نامیم.

در واقع دو ایده متفاوت را ترکیب می‌کنیم:

**Double DQN:**

برای کاهش Overestimation Bias در تخمین Q-Value از دو شبکه برای انتخاب Action و ارزیابی آن استفاده می‌کند.

**Dueling Network:**

برای بهبود نمایش Q-Function، آن را به Value Stream و Advantage Stream تقسیم می‌کند.

بنابراین:

```
                 Dueling DDQN
                      |
          +-----------+-----------+
          |                       |
          v                       v
     Double DQN             Dueling Network
          |                       |
          v                       v
 Reduce Overestimation      Separate V and A
          |                       |
          +-----------+-----------+
                      |
                      v
             Improved Q-Learning
```

### **۹.۲. تفاوت DDQN و Dueling DDQN**

| ویژگی              | DDQN                | Dueling DDQN                |
| ------------------ | ------------------- | --------------------------- |
| Double Q-Learning  | دارد                | دارد                        |
| Target Network     | دارد                | دارد                        |
| Value Stream       | ندارد               | دارد                        |
| Advantage Stream   | ندارد               | دارد                        |
| Q-Value Estimation | مستقیم              | از ترکیب V و A              |
| هدف اصلی           | کاهش Overestimation | بهبود نمایش و تخمین ارزش‌ها |

Dueling DDQN از نظر الگوریتم انتخاب و ارزیابی Action همچنان از منطق Double DQN استفاده می‌کند؛ تفاوت اصلی در معماری شبکه عصبی است.

### **۹.۳. ترکیب Dueling DDQN با Polyak Averaging**

در این فصل Target Network نیز با استفاده از Polyak Averaging به‌روزرسانی می‌شود.

بنابراین به‌جای Hard Update، از Soft Update استفاده می‌کنیم:

\\[ \theta' \leftarrow \tau\theta+(1-\tau)\theta' \\]

این کار باعث می‌شود Target Network به‌صورت تدریجی با Online Network هماهنگ شود.

### **۹.۴. ترکیب Dueling DDQN با PER**

در ادامه، Prioritized Experience Replay نیز به الگوریتم اضافه می‌شود.

در این حالت:

- Dueling Network: معماری تخمین Q-Value را بهبود می‌دهد.
- Double DQN: Overestimation Bias را کاهش می‌دهد.
- Polyak Averaging: به‌روزرسانی Target Network را تدریجی می‌کند.
- PER: تجربه‌های آموزنده‌تر را بیشتر در آموزش استفاده می‌کند.
- Importance Sampling: Bias ناشی از نمونه‌برداری اولویت‌دار را تعدیل می‌کند.

این ترکیب از نظر مفهومی، بخش مهمی از دستاورد فصل دهم است.

## **۱۰. نتایج آزمایش Dueling DDQN**

در متن فصل به آزمایش‌هایی با استفاده از محیط CartPole اشاره می‌شود.

هدف آزمایش بررسی این موضوع است که آیا Dueling Network می‌تواند در مقایسه با DDQN معمولی، تخمین دقیق‌تری از ارزش Actionها ارائه دهد یا خیر.

### **۱۰.۱. مشاهده رفتار عامل‌ها**

در آزمایش مطرح‌شده، رفتار Agentهای آموزش‌دیده با DDQN و Dueling DDQN مقایسه می‌شود.

مشاهدات گزارش‌شده:

- عامل Dueling DDQN تمایل داشت در محدوده کوچک‌تری از Stateها باقی بماند.
- این عامل توانست تفاوت میان Actionهایی با ارزش نزدیک به یکدیگر را بهتر یاد بگیرد.
- در این آزمایش، سیاست پایدارتری با تعداد گام‌های آموزشی کمتر به دست آمد.

### **۱۰.۲. Trade-off میان Training Time و Sample Efficiency**

یکی از نکات جالب آزمایش‌ها، وجود یک Trade-off است.

| معیار                | DDQN           | Dueling DDQN    |
| -------------------- | -------------- | --------------- |
| Sample Efficiency    | کمتر در آزمایش | بیشتر در آزمایش |
| تعداد Steps موردنیاز | بیشتر          | کمتر            |
| زمان آموزش           | کمتر           | کمی بیشتر       |
| معماری               | معمولی         | Dueling         |

بنابراین Dueling DDQN ممکن است با وجود زمان محاسباتی بیشتر، برای رسیدن به عملکرد مطلوب به تعاملات کمتری با محیط نیاز داشته باشد.

**نکته:** این نتایج تضمین عمومی برای تمام محیط‌ها نیستند و نباید آن‌ها را به این معنا تفسیر کرد که Dueling DDQN همیشه بهتر از DDQN است.

## **۱۱. محدودیت‌ها و چالش‌های روش‌های فصل**

### **۱۱.۱. محدودیت‌های Dueling Network**

- در مسائل با رابطه بسیار پیچیده میان State و Action، جداسازی V و A ممکن است همیشه مزیت ایجاد نکند.
- افزایش پیچیدگی معماری می‌تواند زمان محاسباتی را افزایش دهد.
- بهبود عملکرد به نوع محیط و ساختار Action Space بستگی دارد.

### **۱۱.۲. محدودیت‌های Prioritized Experience Replay**

- محاسبه و به‌روزرسانی Priorityها هزینه محاسباتی اضافه ایجاد می‌کند.
- تجربه‌های دارای TD Error بزرگ ممکن است ناشی از نویز باشند.
- تمرکز بیش‌ازحد روی تجربه‌های خاص می‌تواند تنوع داده‌های آموزشی را کاهش دهد.
- تغییر توزیع نمونه‌برداری باعث ایجاد Bias می‌شود.
- برای کنترل رفتار الگوریتم باید Alpha و Beta به‌درستی تنظیم شوند.

### **۱۱.۳. محدودیت‌های Polyak Averaging**

- انتخاب Tau اهمیت زیادی دارد.
- Tau بسیار بزرگ باعث می‌شود Target Network سریع‌تر تغییر کند و خاصیت هموارسازی کاهش پیدا کند.
- Tau بسیار کوچک باعث می‌شود Target Network بیش‌ازحد از Online Network عقب بماند.

## **۱۳. فرمول‌های مهم فصل دهم**

این قسمت برای مرور و آمادگی امتحان اهمیت زیادی دارد.

**۱. Dueling Network**

تفکیک Q به Value و Advantage:

\\[ Q(s,a)=V(s)+A(s,a) \\]

فرم استاندارد با میانگین Advantage:

\\[ Q(s,a)=V(s)+ \left( A(s,a)-\frac{1}{|\mathcal A|} \sum\_{a'}A(s,a') \right) \\]

**۲. Polyak Averaging**

\\[ \theta' \leftarrow \tau\theta+(1-\tau)\theta' \\]

**۳. TD Error**

\\[ \delta = Target-Q(s,a) \\]

**۴. Proportional Priority**

\\[ p_i=|\delta_i|+\epsilon \\]

**۵. Stochastic Prioritization**

\\[ P(i)=\frac{p_i^\alpha}{\sum_k p_k^\alpha} \\]

**۶. Rank-Based Priority**

\\[ p_i=\frac{1}{rank(i)} \\]

**۷. Importance Sampling Weight**

\\[ w_i= \left(\frac{1}{N\cdot P(i)}\right)^\beta \\]

**۸. Normalized Importance Sampling Weight**

\\[ w_i^{norm}=\frac{w_i}{\max_j w_j} \\]

**۹. Weighted Loss**

\\[ L(\theta)= \frac{1}{B}\sum\_{i=1}^{B} w_i^{norm} \left(y_i-Q(s_i,a_i;\theta)\right)^2 \\]

### **مهم‌ترین تفاوت مفاهیم**

- **V(s):** ارزش قرار داشتن در یک State.
- **A(s,a):** مزیت یک Action نسبت به میانگین Actionهای همان State.
- **Q(s,a):** ارزش انجام یک Action در یک State.
- **TD Error:** اختلاف میان Target و مقدار پیش‌بینی‌شده.
- **Priority:** میزان اهمیت یک تجربه برای نمونه‌برداری.
- **Alpha:** شدت Prioritization.
- **Beta:** شدت اصلاح Bias.
- **Polyak Averaging:** ترکیب تدریجی وزن‌های Online و Target Network.
- **Importance Sampling:** اصلاح اثر نمونه‌برداری غیر یکنواخت.

## **۱۵. سؤالات مهم برای تسلط بر فصل**

1. چرا معماری معمولی DQN ممکن است در یادگیری اطلاعات مشترک میان Actionها ناکارآمد باشد؟
2. تفاوت Value Function و Advantage Function چیست؟
3. چرا در Dueling Network میانگین Advantageها را از هر Advantage کم می‌کنیم؟
4. چرا Polyak Averaging می‌تواند جایگزین مناسبی برای Hard Target Update باشد؟
5. تفاوت Online Network و Target Network چیست؟
6. چرا Uniform Random Sampling همیشه بهترین روش برای Replay Buffer نیست؟
7. چرا TD Error معیار مناسبی برای اولویت‌بندی تجربه‌ها محسوب می‌شود؟
8. چرا از قدر مطلق TD Error استفاده می‌کنیم؟
9. تفاوت Proportional Prioritization و Rank-Based Prioritization چیست؟
10. چرا Stochastic Prioritization از Greedy Prioritization مناسب‌تر است؟
11. پارامترهای Alpha و Beta چه تفاوتی دارند؟
12. چرا Prioritized Experience Replay باعث ایجاد Bias می‌شود؟
13. Importance Sampling چگونه این Bias را اصلاح می‌کند؟
14. چرا Beta معمولاً به‌تدریج به یک افزایش پیدا می‌کند؟
15. چگونه Dueling Network، Double DQN و PER می‌توانند با یکدیگر ترکیب شوند؟

## **جمع‌بندی**

هدف صرفاً افزایش Reward نیست؛ هدف این است که عامل بتواند از هر تجربه، اطلاعات بیشتری استخراج کند و با تعاملات کمتر با محیط به سیاست مطلوب برسد. این همان مفهوم Sample Efficiency است.
