## **۱. مرور کلی مباحث کتاب و خانواده‌های الگوریتمی**

نویسنده ابتدا تمام مسیر کتاب را مرور می‌کند تا ارتباط میان روش‌های مختلف Reinforcement Learning مشخص شود.

### **۱.۱. Markov Decision Processes (MDPs)**

فرایند تصمیم‌گیری مارکوف، چارچوب ریاضی اصلی برای مدل‌سازی مسائل Reinforcement Learning است.

یک MDP معمولاً با مؤلفه‌های زیر تعریف می‌شود:

\\[ MDP = (S,A,P,R,\gamma,\rho_0,\mathcal{T}) \\]

- **S (State Space):** مجموعه حالت‌های ممکن محیط.
- **A (Action Space):** مجموعه اقدامات قابل انجام توسط Agent.
- **P (Transition Function):** احتمال انتقال از یک حالت به حالت دیگر با انجام یک اقدام.
- **R (Reward Function):** تابع پاداش که میزان مطلوبیت نتیجه را مشخص می‌کند.
- **γ (Discount Factor):** میزان اهمیت پاداش‌های آینده نسبت به پاداش فعلی.
- **ρ₀ (Initial State Distribution):** توزیع احتمالی حالت‌های اولیه.
- **𝒯 (Terminal States):** مجموعه حالت‌های پایانی.

نکته اصلی MDP، خاصیت Markov Property است:

> آینده، با دانستن حالت فعلی و اقدام فعلی، به تاریخچه قبلی وابستگی مستقیمی ندارد.

به بیان ریاضی:

\\[ P(S\_{t+1}\mid S_t,A_t,S\_{t-1},\ldots) = P(S\_{t+1}\mid S_t,A_t) \\]

این خاصیت به معنای قطعی بودن آینده نیست؛ بلکه به این معناست که توزیع احتمالات آینده با دانستن State فعلی و Action فعلی مشخص می‌شود.

**مثال: رباتی در یک Maze**

- State: موقعیت فعلی ربات.
- Action: حرکت به چپ، راست، بالا یا پایین.
- Transition: احتمال رسیدن به خانه بعدی.
- Reward: پاداش رسیدن به خروجی و جریمه برخورد با مانع.
- Discount Factor: میزان اهمیت رسیدن سریع‌تر به هدف.

نکته مهم این است که در مسائل واقعی، ممکن است State به‌تنهایی اطلاعات کافی برای برقرار بودن خاصیت مارکوف نداشته باشد. در چنین شرایطی باید نمایش State را غنی‌تر کنیم یا از چارچوب‌هایی مانند POMDP استفاده کنیم.

### **۱.۲. Planning Methods**

روش‌های Planning از مدل محیط برای پیش‌بینی نتایج اقدامات و انتخاب تصمیم مناسب استفاده می‌کنند.

در Planning، Agent به‌جای اینکه صرفاً از طریق تجربه مستقیم یاد بگیرد، می‌تواند با استفاده از مدل انتقال و پاداش، پیامد اقدامات را محاسبه کند.

مثلاً:

- ابتدا مدل محیط را در اختیار داریم.
- پیامد احتمالی اقدامات را بررسی می‌کنیم.
- ارزش مسیرهای مختلف را تخمین می‌زنیم.
- بهترین تصمیم را انتخاب می‌کنیم.

تفاوت مهم:

- **Planning:** استفاده از مدل برای محاسبه و انتخاب تصمیم.
- **Learning:** یادگیری از تجربه یا داده.
- **Model-Based RL:** یادگیری یا استفاده از مدل محیط و ترکیب آن با Planning.

### **۱.۳. Bandit Methods**

مسائل Multi-Armed Bandit از ساده‌ترین شکل‌های تصمیم‌گیری تحت عدم قطعیت هستند.

Agent باید از میان چند Action یکی را انتخاب کند و با توجه به Reward دریافتی، درباره مطلوبیت آن Action یاد بگیرد.

دو مفهوم اساسی:

- **Exploration:** امتحان کردن اقدامات جدید برای کسب اطلاعات بیشتر.
- **Exploitation:** انتخاب اقداماتی که بر اساس اطلاعات فعلی، پاداش بیشتری دارند.

هدف، ایجاد تعادل میان این دو است.

برای مثال، یک سیستم پیشنهاددهنده می‌تواند چند نوع تبلیغ داشته باشد. باید هم تبلیغات شناخته‌شده و موفق را نمایش دهد و هم تبلیغات جدید را آزمایش کند.

تفاوت Bandit با MDP این است که در Bandit معمولاً انتقال میان Stateهای متوالی و اثر زنجیره‌ای اقدامات وجود ندارد؛ تمرکز اصلی روی انتخاب Action و دریافت Reward است.

### **۱.۴. Tabular Reinforcement Learning**

Tabular RL به روش‌هایی گفته می‌شود که مقادیر مربوط به Stateها یا State-Actionها را در جدول ذخیره می‌کنند.

برای مثال:

| State | Action | Q-Value |
| ----- | ------ | ------- |
| S1    | Left   | 2.4     |
| S1    | Right  | 4.1     |
| S2    | Left   | 1.8     |
| S2    | Right  | 3.2     |

این روش برای محیط‌هایی با State Space و Action Space کوچک و قابل گسسته‌سازی مناسب است.

الگوریتم‌های مهم این بخش عبارت‌اند از:

- Monte Carlo (First-Visit و Every-Visit)
- Temporal Difference Learning (TD)
- N-Step TD
- TD(λ)
- SARSA
- Q-Learning
- Double Q-Learning
- SARSA(λ)
- Q(λ)
- Dyna-Q

**ارتباط Tabular RL با Deep RL**

در Deep RL، به‌جای نگهداری یک جدول بزرگ، از Neural Network برای تقریب Value Function یا Policy استفاده می‌شود.

بنابراین Deep RL جایگزین اصول بنیادی RL نیست؛ بلکه راهی برای تعمیم این اصول به فضاهای بزرگ و پیچیده است.

مثلاً:

- Tabular RL: ذخیره Q-Value برای هر State-Action.
- Deep RL: تخمین Q-Value با استفاده از یک شبکه عصبی.

نکته آموزشی مهم: شروع با Tabular RL باعث می‌شود مفاهیمی مانند Bellman Equation، Policy Evaluation، Policy Improvement، Bootstrapping و Temporal Difference Error را بدون پیچیدگی شبکه‌های عصبی درک کنیم.

### **۱.۵. Value-Based Deep Reinforcement Learning**

در روش‌های Value-Based، Agent ابتدا ارزش اقدامات مختلف را تخمین می‌زند و سپس با استفاده از این تخمین‌ها تصمیم می‌گیرد.

تابع مهم این خانواده:

\\[ Q(s,a) \\]

که ارزش مورد انتظار انجام Action مشخص در State مشخص را نشان می‌دهد.

الگوریتم‌های مهم:

- **NFQ:** Neural Fitted Q-Iteration؛ استفاده از شبکه عصبی برای تقریب Q-Function.
- **DQN:** استفاده از Deep Neural Network برای تخمین Q-Values.
- **Double DQN (DDQN):** کاهش مشکل Overestimation در تخمین ارزش اقدامات.
- **Dueling DQN:** تفکیک تقریبی State Value و Advantage.
- **Prioritized Experience Replay (PER):** اولویت دادن به تجربه‌هایی که یادگیری از آن‌ها مفیدتر است.
- **Rainbow DQN:** ترکیب چندین بهبود مهم DQN در یک الگوریتم.

ساختار مفهومی:

```
State
  |
  v
Deep Neural Network
  |
  v
Q-Values for Available Actions
  |
  v
Action Selection
  |
  v
Environment
  |
  v
Reward + Next State
  |
  v
Learning and Updating Q-Function
```

این خانواده به‌خصوص برای Action Spaceهای گسسته کاربرد دارد.

### **۱.۶. Policy-Based و Actor-Critic Deep Reinforcement Learning**

در روش‌های Policy-Based، Agent مستقیماً Policy را یاد می‌گیرد.

به‌جای اینکه ابتدا ارزش تمام اقدامات را تخمین بزند، تابعی یاد می‌گیرد که State را به توزیع احتمال اقدامات یا Action موردنظر تبدیل می‌کند.

\\[ \pi\_\theta(a\mid s) \\]

الگوریتم‌های اصلی:

- REINFORCE
- VPG (Vanilla Policy Gradient)
- A3C (Asynchronous Advantage Actor-Critic)
- A2C (Advantage Actor-Critic)
- GAE (Generalized Advantage Estimation)
- PPO (Proximal Policy Optimization)

در Actor-Critic دو مؤلفه اصلی وجود دارد:

- **Actor:** Policy را یاد می‌گیرد و Action انتخاب می‌کند.
- **Critic:** عملکرد Actor را با تخمین Value یا Advantage ارزیابی می‌کند.

```
              State
                |
        +-------+-------+
        |               |
        v               v
      Actor           Critic
        |               |
        v               v
   Action/Policy    Value Estimate
        |               |
        +-------+-------+
                |
                v
          Environment
                |
                v
          Reward + State
                |
                v
          Update Actor
          Update Critic
```

تفاوت مهم REINFORCE و VPG با Actor-Critic:

- REINFORCE از Return واقعی Episode برای محاسبه Policy Gradient استفاده می‌کند.
- VPG از یک Baseline برای کاهش Variance استفاده می‌کند.
- Actor-Critic علاوه بر Policy، از Value Function برای تخمین و Bootstrapping استفاده می‌کند.

Baseline در VPG لزوماً Critic به معنای Actor-Critic نیست؛ زیرا نقش آن در اینجا کاهش Variance است، نه استفاده از تخمین ارزش برای Bootstrapping در به‌روزرسانی Policy.

### **۱.۷. Advanced Actor-Critic Methods**

در فصل ۱۲، روش‌های پیشرفته‌تر Actor-Critic بررسی شده‌اند:

| Algorithm | ایده اصلی                                                               |
| --------- | ----------------------------------------------------------------------- |
| DDPG      | یادگیری Policy قطعی برای Actionهای پیوسته                               |
| TD3       | بهبود DDPG با Double Critics، Target Policy Smoothing و Delayed Updates |
| SAC       | بهینه‌سازی Reward و Entropy برای حفظ Exploration                        |
| PPO       | محدود کردن تغییرات Policy برای بهبود پایداری آموزش                      |

نکته مهم درباره طبقه‌بندی:

DDPG و TD3 معمولاً در خانواده Deterministic Policy Gradient و Actor-Critic قرار می‌گیرند؛ اما در توضیح مفهومی کتاب، تأکید می‌شود که از ساختار Value-Based و Critic نیز استفاده می‌کنند. بنابراین نباید آن‌ها را با الگوریتم‌های Policy Gradient خالص یکسان دانست.

همچنین A3C و A2C الزاماً فقط برای Actionهای گسسته نیستند و با طراحی مناسب توزیع Policy می‌توانند Actionهای پیوسته را نیز پشتیبانی کنند.

## **۲. مقایسه سه خانواده اصلی الگوریتم‌های RL**

یکی از مهم‌ترین بخش‌های فصل، مقایسه سه رویکرد Value-Based، Policy-Based و Model-Based است.

### **۲.۱. Value-Based Methods**

در این روش‌ها، ابتدا Value Function یاد گرفته می‌شود و سپس Action مناسب بر اساس آن انتخاب می‌شود.

مثال: DQN

```
State
  |
  v
Value Function: Q(s,a)
  |
  v
Compare Action Values
  |
  v
Select Best Action
```

ویژگی‌ها:

- یادگیری غیرمستقیم Policy از طریق Value Function.
- مناسب برای Action Spaceهای گسسته.
- معمولاً محاسبات ساده‌تری نسبت به برخی روش‌های Policy-Based دارند.
- ممکن است برای یادگیری به تجربه‌های زیادی نیاز داشته باشند.

### **۲.۲. Policy-Based Methods**

در این روش‌ها، خود Policy مستقیماً یاد گرفته می‌شود.

مثال: REINFORCE و PPO

```
State
  |
  v
Policy Function: π(a|s)
  |
  v
Action Distribution
  |
  v
Select Action
```

ویژگی‌ها:

- یادگیری مستقیم تابع تصمیم‌گیری.
- پشتیبانی مناسب از Action Spaceهای پیوسته و گسسته.
- امکان یادگیری Policyهای Stochastic.
- احتمالاً نیازمند محاسبات و نمونه‌های آموزشی قابل توجه.
- روش‌های Policy Gradient ممکن است Variance بالایی داشته باشند.

### **۲.۳. Model-Based Methods**

در این روش‌ها، Agent از مدل محیط برای پیش‌بینی اتفاقات آینده استفاده می‌کند.

مدل معمولاً شامل موارد زیر است:

- Transition Model
- Reward Model

```
Current State
      |
      v
Environment Model
      |
      v
Predict Next States and Rewards
      |
      v
Planning
      |
      v
Select Action
```

ویژگی‌ها:

- امکان برنامه‌ریزی قبل از انجام Action در محیط واقعی.
- قابلیت استفاده از داده‌های شبیه‌سازی‌شده.
- امکان کاهش نیاز به تعامل واقعی با محیط.
- هزینه محاسباتی بیشتر برای یادگیری یا اجرای مدل.
- حساسیت به اشتباهات مدل.

### **۲.۴. جدول مقایسه**

| معیار              | Value-Based               | Policy-Based       | Model-Based            |
| ------------------ | ------------------------- | ------------------ | ---------------------- |
| هدف یادگیری        | Value Function            | Policy             | مدل محیط               |
| تصمیم‌گیری         | براساس ارزش اقدامات       | مستقیماً با Policy | با پیش‌بینی و Planning |
| Action Space       | معمولاً گسسته             | گسسته و پیوسته     | وابسته به روش          |
| Sample Efficiency  | وابسته به الگوریتم        | وابسته به الگوریتم | بالقوه بالا            |
| Computational Cost | معمولاً متوسط             | متغیر              | ممکن است بالا باشد     |
| نیاز به مدل محیط   | خیر                       | خیر                | بله                    |
| نقطه ضعف اصلی      | تخمین Value و مقیاس‌پذیری | Variance و پایداری | Model Error            |

**نکته مهم:** هیچ‌کدام از این سه خانواده همیشه بهترین نیستند. انتخاب الگوریتم به ساختار مسئله، نوع Action Space، هزینه تعامل با محیط، منابع محاسباتی و میزان دسترسی به مدل بستگی دارد.

همچنین این سه دسته کاملاً مستقل و انحصاری نیستند؛ الگوریتم‌های ترکیبی مانند Actor-Critic هم‌زمان از Policy و Value Function استفاده می‌کنند و Model-Based RL نیز می‌تواند از Policy یا Value Function بهره ببرد.

## **۳. Model-Based Deep Reinforcement Learning**

موضوع پیشرفته و خارج از پوشش عمیق کتاب

### **۳.۱. تعریف**

در Model-Based Deep Reinforcement Learning، Agent تلاش می‌کند یک مدل از محیط بسازد تا بتواند نتایج اقدامات خود را پیش‌بینی کند.

این مدل معمولاً دو بخش اصلی دارد:

**۱. Transition Model**

پیش‌بینی می‌کند که بعد از انجام یک Action در State فعلی، چه State جدیدی به وجود خواهد آمد.

\\[ \hat{P}(s'\mid s,a) \\]

**۲. Reward Model**

پاداش احتمالی حاصل از انتقال را تخمین می‌زند.

\\[ \hat{R}(s,a,s') \\]

در برخی روش‌ها مدل به‌صورت قطعی و در برخی دیگر به‌صورت احتمالاتی یاد گرفته می‌شود.

### **۳.۲. نحوه عملکرد**

```
Real Environment
       |
       v
Collect Experiences
       |
       v
Learn Environment Model
       |
       v
Simulate Possible Actions
       |
       v
Predict Future States and Rewards
       |
       v
Planning / Policy Optimization
       |
       v
Choose Better Actions
       |
       v
Real Environment
```

به این ترتیب، Agent می‌تواند قبل از اجرای Action در محیط واقعی، پیامد احتمالی آن را در مدل بررسی کند.

### **۳.۳. Sample Efficiency**

یکی از مهم‌ترین مزایای Model-Based RL، امکان استفاده مجدد از تجربه‌ها است.

در Model-Free RL، Agent معمولاً برای یادگیری به تعامل مستقیم و مکرر با محیط نیاز دارد.

اما در Model-Based RL:

1. Agent از محیط واقعی تجربه جمع‌آوری می‌کند.
2. مدل محیط را یاد می‌گیرد.
3. از مدل برای تولید تجربه‌های شبیه‌سازی‌شده استفاده می‌کند.
4. از تجربه‌های مصنوعی برای بهبود Policy یا Value Function بهره می‌گیرد.

این فرایند می‌تواند تعداد تعاملات موردنیاز با محیط واقعی را کاهش دهد.

به این ویژگی Sample Efficiency گفته می‌شود.

### **۳.۴. مزایای Model-Based RL**

- **Sample Efficiency:** استفاده بیشتر از هر تجربه.
- **Planning:** بررسی پیامد اقدامات قبل از اجرای آن‌ها.
- **Transfer Learning:** استفاده مجدد از دانش مربوط به Dynamics محیط در وظایف جدید.
- **Stability:** در شرایط مناسب، یادگیری و برنامه‌ریزی ساختارمندتر.
- **Reduced Real-World Risk:** آزمایش تصمیم‌ها در محیط شبیه‌سازی‌شده به‌جای محیط واقعی.

### **۳.۵. معایب و محدودیت‌ها**

**۱. Model Error**

مدل یادگرفته‌شده ممکن است با محیط واقعی تفاوت داشته باشد.

**۲. Compounding Error**

اشتباهات کوچک مدل در پیش‌بینی‌های متوالی می‌توانند بزرگ‌تر شوند.

```
Prediction 1: Small Error
        |
        v
Prediction 2: Larger Error
        |
        v
Prediction 3: Accumulated Error
        |
        v
Unreliable Long-Term Prediction
```

**۳. Computational Cost**

Agent باید علاوه بر Policy یا Value Function، مدل محیط را نیز یاد بگیرد و اجرا کند.

**۴. Uncertainty Estimation**

تشخیص اینکه مدل در چه شرایطی مطمئن یا نامطمئن است، دشوار است؛ مخصوصاً در مدل‌های Deep Learning.

**۵. Unnecessary Modeling**

گاهی یادگیری تمام Dynamics محیط ضرورتی ندارد.

برای مثال، اگر هدف ربات برداشتن یک فنجان باشد، شاید نیازی به یادگیری کامل فیزیک جریان مایعات نباشد.

**۶. Data Hunger**

مدل‌های عمیق ممکن است برای ساخت یک شبیه‌ساز قابل اعتماد به داده زیادی نیاز داشته باشند. در نتیجه، همیشه تضمینی وجود ندارد که Model-Based از Model-Free کم‌نمونه‌تر باشد.

### **۳.۶. Model-Based RL و Model-Free RL**

| ویژگی                 | Model-Based          | Model-Free                 |
| --------------------- | -------------------- | -------------------------- |
| مدل محیط              | دارد یا یاد می‌گیرد  | برای تصمیم‌گیری لازم ندارد |
| Planning              | معمولاً دارد         | معمولاً ندارد              |
| استفاده از Simulation | می‌تواند گسترده باشد | محدودتر به ساختار الگوریتم |
| Sample Efficiency     | بالقوه بهتر          | وابسته به الگوریتم         |
| پیچیدگی               | معمولاً بیشتر        | معمولاً کمتر               |
| حساسیت به Model Error | بله                  | خیر، به این شکل            |

**نکته:** Model-Free به معنی بدون مدل‌بودن شبکه عصبی نیست؛ منظور این است که Agent برای یادگیری Policy یا Value به مدل صریح Dynamics محیط وابسته نیست.

## **۴. Derivative-Free Optimization**

موضوع پیشرفته و خارج از پوشش عمیق کتاب

### **۴.۱. تعریف**

در Deep Learning معمولاً برای بهینه‌سازی پارامترهای شبکه عصبی از روش‌های مبتنی بر Gradient استفاده می‌کنیم.

مراحل متداول:

```
Neural Network
      |
      v
Calculate Loss
      |
      v
Backpropagation
      |
      v
Calculate Gradients
      |
      v
Gradient Descent
      |
      v
Update Parameters
```

اما همه توابع هدف دارای Gradient قابل استفاده نیستند.

Derivative-Free Optimization یا DFO روشی برای بهینه‌سازی است که به محاسبه مشتق تابع هدف وابسته نیست.

این روش‌ها با آزمایش تغییرات مختلف در پارامترها و ارزیابی نتایج، به دنبال پیدا کردن راه‌حل بهتر هستند.

نام‌های دیگر:

- Gradient-Free Optimization
- Black-Box Optimization
- Zeroth-Order Optimization

### **۴.۲. چه زمانی استفاده می‌شود؟**

وقتی تابع هدف دارای ویژگی‌های زیر باشد:

- Discrete: گسسته باشد.
- Discontinuous: ناپیوسته باشد.
- Multi-Modal: دارای چندین نقطه بهینه محلی باشد.
- Non-Differentiable: مشتق‌پذیر نباشد یا محاسبه مشتق آن دشوار باشد.

در چنین شرایطی ممکن است روش‌های Gradient-Based عملکرد مناسبی نداشته باشند.

### **۴.۳. Genetic Algorithms**

یکی از روش‌های Derivative-Free Optimization، الگوریتم ژنتیک است.

ایده اصلی آن از انتخاب طبیعی در زیست‌شناسی الهام گرفته شده است.

مراحل:

1. ایجاد Population اولیه از راه‌حل‌های احتمالی.
2. ارزیابی Fitness هر راه‌حل.
3. انتخاب راه‌حل‌های بهتر.
4. انجام Crossover و Mutation.
5. ایجاد نسل جدید.
6. تکرار فرایند تا رسیدن به نتیجه مناسب.

```
Initial Population
        |
        v
Fitness Evaluation
        |
        v
Selection
        |
        v
Crossover + Mutation
        |
        v
New Generation
        |
        v
Repeat
```

### **۴.۴. Evolution Strategies (ES)**

Evolution Strategies نیز از خانواده روش‌های تکاملی هستند.

در این روش‌ها، پارامترهای مدل به شکل تصادفی تغییر می‌کنند و عملکرد نسخه‌های مختلف مقایسه می‌شود.

به‌طور ساده:

- چند نسخه از پارامترها تولید می‌شود.
- هر نسخه در محیط آزمایش می‌شود.
- عملکرد آن‌ها اندازه‌گیری می‌شود.
- اطلاعات عملکرد برای بهبود پارامترها استفاده می‌شود.

### **۴.۵. مزایا**

- نیازی به Backpropagation ندارد.
- قابلیت بهینه‌سازی توابع پیچیده و Black-Box را دارد.
- پیاده‌سازی برخی نسخه‌های آن ساده است.
- قابلیت Parallelization بسیار خوبی دارد.
- می‌توان از صدها یا هزاران پردازنده برای ارزیابی هم‌زمان راه‌حل‌ها استفاده کرد.

### **۴.۶. معایب**

- Sample Inefficiency: معمولاً به ارزیابی‌های زیادی نیاز دارد.
- ممکن است از ساختار مسئله و اطلاعات مفید آن استفاده نکند.
- ساختار Sequential در Reinforcement Learning را نادیده می‌گیرد.
- در مسائل بزرگ، هزینه ارزیابی‌ها می‌تواند بسیار بالا باشد.

**نکته مهم:** Derivative-Free Optimization جایگزین همیشگی Gradient Descent نیست. این روش‌ها ابزار مکمل هستند و انتخاب میان آن‌ها به ساختار تابع هدف و مسئله بستگی دارد.

## **۵. حرکت به سمت Artificial General Intelligence (AGI)**

### **۵.۱. AGI چیست؟**

AGI مخفف Artificial General Intelligence یا هوش مصنوعی عمومی است.

هدف AGI ساخت سیستمی است که بتواند مانند انسان، در حوزه‌های مختلف یاد بگیرد، استدلال کند، با شرایط جدید سازگار شود و مسائل جدید را حل کند.

تفاوت اصلی AGI با Narrow AI در گستردگی توانایی‌ها و قابلیت تعمیم است.

**Narrow AI:**

- برای وظیفه مشخصی آموزش دیده است.
- ممکن است در همان وظیفه عملکرد فوق‌العاده‌ای داشته باشد.
- انتقال دانش به وظایف متفاوت برای آن دشوار است.

**AGI:**

- قابلیت حل مسائل متنوع را دارد.
- می‌تواند دانش آموخته‌شده را به وظایف جدید منتقل کند.
- توانایی استدلال و سازگاری با شرایط پیش‌بینی‌نشده دارد.
- می‌تواند از تجربه‌های جدید به‌صورت مستمر یاد بگیرد.

### **۵.۲. ویژگی‌های مورد انتظار AGI**

**۱. Generalization**

توانایی استفاده از دانش یادگرفته‌شده برای حل مسائل جدید.

**۲. Transfer Learning**

انتقال دانش از یک وظیفه به وظیفه دیگر.

**۳. Adaptability**

توانایی سازگاری با شرایطی که در زمان آموزش وجود نداشته‌اند.

**۴. Reasoning**

توانایی استدلال و استخراج نتیجه از شواهد و اطلاعات موجود.

**۵. Common Sense**

درک روابط و مفاهیم عمومی دنیای واقعی.

**۶. Continuous Learning**

توانایی یادگیری از تجربه‌های جدید در طول زمان، بدون وابستگی کامل به یک مرحله آموزش اولیه.

### **۵.۳. چرا الگوریتم‌های فعلی AGI نیستند؟**

مثال مهمی که در فصل مطرح می‌شود، تفاوت توانایی انسان و Agentهای آموزش‌دیده برای بازی‌های مختلف است.

فرض کنید:

- یک Agent برای بازی Pong آموزش دیده است.
- Agent دیگری برای بازی Breakout آموزش دیده است.

ممکن است Agent اول در Pong عملکرد فوق‌العاده‌ای داشته باشد، اما در Breakout تقریباً هیچ مهارتی نداشته باشد.

درحالی‌که انسان می‌تواند با استفاده از تجربه بازی‌های قبلی، بازی مشابه را سریع‌تر یاد بگیرد.

این مسئله نشان‌دهنده ضعف در Generalization و Transfer Learning است.

مثال دیگر:

AlphaZero در بازی‌های تخته‌ای عملکرد بسیار خوبی دارد، اما این به معنای توانایی حل مسائل عمومی زندگی یا انجام وظایف خانگی نیست.

نکته اصلی:

**عملکرد فوق‌العاده در یک وظیفه تخصصی، به‌معنای داشتن هوش عمومی نیست.**

همچنین AGI صرفاً به معنی داشتن قدرت پردازشی بیشتر یا داده آموزشی بیشتر نیست؛ توانایی تعمیم، سازگاری و حل مسائل جدید نیز اهمیت دارد.

## **۶. Advanced Exploration Strategies**

مبحث پیشرفته

یکی از مشکلات اساسی Reinforcement Learning، ایجاد تعادل مناسب بین Exploration و Exploitation است.

در روش‌های ساده مانند Epsilon-Greedy، Agent با احتمال مشخصی اقدام تصادفی انجام می‌دهد و در باقی مواقع از بهترین Action شناخته‌شده استفاده می‌کند.

اما در محیط‌های پیچیده، Exploration تصادفی همیشه کافی نیست.

### **۶.۱. مشکل Exploration در محیط‌های پیچیده**

فرض کنید Agent در یک بازی باید به یک منطقه مخفی برسد تا پاداش بزرگی دریافت کند.

اگر Agent برای مدت طولانی فقط پاداش‌های کوچک و نزدیک را تجربه کند، ممکن است هیچ‌وقت به منطقه مخفی نرسد.

این مسئله در محیط‌های دارای Sparse Rewards شدیدتر است.

**Sparse Reward:** محیط فقط در تعداد محدودی از شرایط پاداش می‌دهد.

### **۶.۲. Intrinsic Motivation**

در روش‌های Intrinsic Motivation، Agent علاوه بر پاداش خارجی محیط، از یک سیگنال انگیزشی داخلی نیز استفاده می‌کند.

دو نوع Reward:

- **Extrinsic Reward:** پاداشی که محیط ارائه می‌کند.
- **Intrinsic Reward:** پاداشی که از معیارهای داخلی Agent، مانند تازگی یا عدم قطعیت، تولید می‌شود.

تابع پاداش ترکیبی را می‌توان به‌صورت زیر نمایش داد:

\\[ R\_{\text{total}} = R\_{\text{extrinsic}} + \beta R\_{\text{intrinsic}} \\]

در این رابطه:

- \\(R\_{\text{extrinsic}}\\): پاداش اصلی محیط.
- \\(R\_{\text{intrinsic}}\\): پاداش انگیزشی داخلی.
- \\(\beta\\): ضریب اهمیت پاداش داخلی.

مثلاً Agent ممکن است برای بازدید از یک State جدید، پاداش داخلی دریافت کند؛ حتی اگر آن State در ابتدا پاداش خارجی نداشته باشد.

### **۶.۳. نمونه روش‌های Exploration پیشرفته**

- **Count-Based Exploration:** پاداش دادن به بازدید از Stateهایی که کمتر مشاهده شده‌اند.
- **Novelty-Based Exploration:** تشویق Agent به تجربه موقعیت‌های جدید.
- **Curiosity-Driven Exploration:** تشویق Agent به یادگیری و پیش‌بینی بخش‌هایی از محیط که هنوز برایش ناشناخته‌اند.
- **Uncertainty-Based Exploration:** استفاده از عدم قطعیت مدل یا تخمین‌ها برای انتخاب اقدامات اطلاعات‌ساز.
- **Random Network Distillation (RND):** استفاده از اختلاف پیش‌بینی یک شبکه آموزش‌دیده و یک شبکه ثابت تصادفی به‌عنوان سیگنال Novelty.

نکته مهم: Exploration پیشرفته فقط به معنی تصادفی‌تر عمل کردن نیست؛ هدف این است که Agent اطلاعات مفیدتری از محیط به دست آورد.

## **۷. Inverse Reinforcement Learning (IRL)**

مبحث پیشرفته

### **۷.۱. تعریف**

در Reinforcement Learning معمولی، تابع پاداش مشخص است و Agent تلاش می‌کند Policy مناسبی برای بیشینه‌سازی آن یاد بگیرد.

اما در Inverse Reinforcement Learning، تابع پاداش ناشناخته است و Agent باید با مشاهده رفتار یک عامل دیگر، آن را استنباط کند.

به بیان ساده:

- RL: تابع Reward را داریم و Policy را یاد می‌گیریم.
- IRL: رفتار یا Demonstration را داریم و تلاش می‌کنیم Reward را استخراج کنیم.

### **۷.۲. تفاوت RL و IRL**

```
Reinforcement Learning:

Reward Function
      |
      v
Agent Learning
      |
      v
Optimal Policy
```

```
Inverse Reinforcement Learning:

Expert Demonstrations
      |
      v
Infer Reward Function
      |
      v
Learn a Policy
```

### **۷.۳. مثال**

فرض کنید می‌خواهیم رفتار یک راننده حرفه‌ای را به یک Agent آموزش دهیم.

به‌جای اینکه دقیقاً به Agent بگوییم:

- در چه زمانی ترمز کند.
- چه زمانی سرعت را افزایش دهد.
- چه زمانی تغییر مسیر دهد.

رفتار راننده حرفه‌ای را مشاهده می‌کنیم.

Agent با بررسی رفتار او تلاش می‌کند بفهمد چه چیزی برای راننده اهمیت دارد:

- ایمنی؟
- سرعت؟
- مصرف سوخت؟
- راحتی سرنشینان؟
- رعایت فاصله با خودروهای دیگر؟

سپس از این اطلاعات برای تخمین Reward Function استفاده می‌کند.

### **۷.۴. Apprenticeship Learning**

Apprenticeship Learning به یادگیری از طریق Demonstration یک Expert گفته می‌شود.

در یک رویکرد رایج:

1. Expert رفتار خود را نشان می‌دهد.
2. IRL تابع پاداش احتمالی را استخراج می‌کند.
3. Agent با استفاده از Reward تخمین‌زده‌شده آموزش می‌بیند.
4. Policy به‌دست‌آمده ارزیابی و اصلاح می‌شود.

```
Expert Demonstrations
        |
        v
Inverse Reinforcement Learning
        |
        v
Inferred Reward Function
        |
        v
Reinforcement Learning
        |
        v
Learned Policy
```

### **۷.۵. مزایا**

- نیاز کمتر به طراحی دستی Reward Function.
- استفاده از دانش و رفتار Expert.
- امکان یادگیری وظایف پیچیده‌تر.
- مناسب برای Robotics و Autonomous Driving.
- امکان استفاده از رفتار سایر Agentها برای پیش‌بینی اهداف آن‌ها.

### **۷.۶. محدودیت‌ها**

- رفتار Expert ممکن است اشتباه یا ناقص باشد.
- Reward استخراج‌شده لزوماً همان هدف واقعی Expert نیست.
- ممکن است چندین Reward Function رفتار مشابهی تولید کنند.
- جمع‌آوری Demonstration باکیفیت دشوار است.
- سوگیری‌های موجود در رفتار Expert می‌توانند به Agent منتقل شوند.

**نکته مهم:** IRL با Imitation Learning یکسان نیست. در Imitation Learning ممکن است Agent مستقیماً رفتار Expert را تقلید کند؛ اما IRL تلاش می‌کند هدف یا Reward پنهان پشت رفتار را استخراج کند.

## **۸. Transfer Learning و Domain Randomization**

### **۸.۱. Transfer Learning چیست؟**

Transfer Learning یعنی استفاده از دانش به‌دست‌آمده از یک وظیفه برای یادگیری یا حل وظیفه‌ای دیگر.

در Reinforcement Learning، به‌جای اینکه Agent برای هر Task از ابتدا آموزش ببیند، می‌توان دانش قبلی آن را منتقل کرد.

مثال:

یک ربات ابتدا یاد می‌گیرد چگونه یک مکعب را بردارد.

سپس برای یادگیری برداشتن اجسام دیگر، از دانش قبلی خود درباره موارد زیر استفاده می‌کند:

- حرکت بازو.
- کنترل مفاصل.
- گرفتن اجسام.
- تشخیص موقعیت.
- تعامل با محیط.

در نتیجه، ممکن است برای یادگیری وظیفه جدید به تجربه کمتری نیاز داشته باشد.

### **۸.۲. چرا انتقال دانش دشوار است؟**

یکی از مشکلات اصلی، تفاوت میان محیط مبدأ و مقصد است.

ممکن است Agent در محیط شبیه‌سازی‌شده آموزش دیده باشد، اما هنگام انتقال به دنیای واقعی با شرایط متفاوتی روبه‌رو شود:

- اصطکاک متفاوت.
- وزن متفاوت اجسام.
- تأخیر در حسگرها.
- خطاهای کالیبراسیون.
- نورپردازی متفاوت.
- تغییرات فیزیکی محیط.

این تفاوت‌ها را می‌توان بخشی از Sim-to-Real Gap دانست.

### **۸.۳. Domain Randomization**

Domain Randomization یکی از روش‌های مهم برای کاهش Sim-to-Real Gap است.

ایده اصلی این است که Agent را به یک شبیه‌سازی کاملاً ثابت محدود نکنیم.

به‌جای آن، هنگام آموزش، پارامترهای مختلف محیط را به‌صورت تصادفی تغییر دهیم.

برای مثال:

- تغییر جرم اجسام.
- تغییر اصطکاک.
- تغییر نورپردازی.
- تغییر رنگ و بافت.
- تغییر موقعیت اشیا.
- تغییر پارامترهای Dynamics.
- اضافه کردن نویز به حسگرها.

ساختار:

```
             Simulator
                 |
       +---------+---------+
       |         |         |
       v         v         v
    Domain 1  Domain 2  Domain 3
       |         |         |
       v         v         v
    Training  Training  Training
       |         |         |
       +---------+---------+
                 |
                 v
           Generalized Agent
                 |
                 v
           Real Environment
```

### **۸.۴. چرا محیط تصادفی می‌تواند بهتر از محیط کاملاً دقیق باشد؟**

فرض کنید ربات را در یک محیط شبیه‌سازی‌شده کاملاً ثابت آموزش دهیم.

ممکن است Agent فقط با همان شرایط خاص سازگار شود.

اما اگر هنگام آموزش با شرایط متنوعی مواجه شود، احتمال بیشتری وجود دارد که یک Policy مقاوم و قابل تعمیم یاد بگیرد.

هدف Domain Randomization این است که Agent به‌جای حفظ کردن شرایط یک محیط مشخص، الگوهای عمومی‌تر را یاد بگیرد.

### **۸.۵. مزایا و محدودیت‌ها**

مزایا:

- افزایش Robustness.
- کاهش حساسیت به تغییرات محیط.
- بهبود Generalization.
- کمک به Sim-to-Real Transfer.

محدودیت‌ها:

- طراحی محدوده Randomization دشوار است.
- تنوع بیش از حد می‌تواند آموزش را سخت‌تر کند.
- ممکن است برخی شرایط تصادفی غیرواقعی باشند.
- افزایش تنوع می‌تواند هزینه آموزش را بالا ببرد.

نکته: Domain Randomization یک روش مهم برای Transfer Learning است، اما تنها روش موجود نیست.

## **۹. Multi-Task Learning**

مبحث پیشرفته

### **۹.۱. تعریف**

Multi-Task Learning یعنی آموزش یک مدل برای یادگیری چند وظیفه مرتبط، به‌جای آموزش مستقل برای هر وظیفه.

هدف این است که Agent از اطلاعات و تجربیات مشترک میان وظایف مختلف استفاده کند.

### **۹.۲. مثال ربات**

فرض کنید یک بازوی رباتیک باید چند وظیفه انجام دهد:

- برداشتن مکعب.
- برداشتن توپ.
- انتقال اجسام به مکان مشخص.
- قراردادن اجسام در جعبه.
- چرخاندن اجسام.

اگر ربات هر وظیفه را کاملاً مستقل یاد بگیرد، ممکن است بخش زیادی از دانش خود را چندین بار یاد بگیرد.

اما در Multi-Task Learning، مدل می‌تواند اصول مشترکی مانند موارد زیر را یاد بگیرد:

- حرکت بازو.
- کنترل مفاصل.
- تعامل با اجسام.
- تخمین موقعیت.
- اعمال نیرو.

این دانش می‌تواند میان Taskهای مختلف به اشتراک گذاشته شود.

### **۹.۳. ساختار مفهومی**

```
          Shared Neural Network
                   |
          Shared Representations
                   |
        +----------+----------+
        |          |          |
        v          v          v
      Task 1     Task 2     Task 3
        |          |          |
        v          v          v
      Policy     Policy     Policy
        1          2          3
```

### **۹.۴. مزایا**

- استفاده مجدد از دانش مشترک.
- افزایش Generalization.
- یادگیری سریع‌تر وظایف مرتبط.
- کاهش نیاز به آموزش مستقل برای هر Task.
- یادگیری ویژگی‌های عمومی محیط.

### **۹.۵. محدودیت‌ها**

**Negative Transfer:** گاهی یادگیری یک Task باعث افت عملکرد در Task دیگر می‌شود.

همچنین:

- وظایف ممکن است با یکدیگر تعارض داشته باشند.
- تخصیص ظرفیت شبکه به Taskهای مختلف دشوار است.
- طراحی Taskهای مرتبط اهمیت زیادی دارد.

**نکته مهم:** Multi-Task Learning الزاماً به معنای انجام هم‌زمان چند وظیفه توسط یک Agent نیست؛ وظایف می‌توانند به‌صورت هم‌زمان یا در توالی‌های آموزشی مختلف ارائه شوند.

## **۱۰. Curriculum Learning**

### **۱۰.۱. تعریف**

Curriculum Learning روشی برای سازمان‌دهی فرایند آموزش است که در آن Agent ابتدا با وظایف ساده‌تر مواجه می‌شود و به‌تدریج وارد وظایف پیچیده‌تر می‌شود.

ایده اصلی از فرایند یادگیری انسان الهام گرفته شده است.

برای مثال، فردی که می‌خواهد رانندگی یاد بگیرد، ابتدا کنترل خودرو را در محیط ساده تمرین می‌کند و بعد وارد ترافیک پیچیده می‌شود.

### **۱۰.۲. مثال در Reinforcement Learning**

فرض کنید می‌خواهیم Agent را برای بازی‌های پیچیده آموزش دهیم.

می‌توانیم آموزش را به این شکل طراحی کنیم:

1. ابتدا بازی ساده با قوانین محدود.
2. سپس افزایش تعداد موانع.
3. افزایش سرعت محیط.
4. اضافه کردن دشمنان.
5. افزایش پیچیدگی تصمیم‌گیری.
6. در نهایت اجرای بازی کامل.

### **۱۰.۳. نقش Reward Function**

در Curriculum Learning، طراحی Reward Function اهمیت زیادی دارد.

در وظایف ساده ممکن است پاداش موفقیت بسیار واضح باشد.

اما در وظایف پیچیده‌تر، دستیابی به هدف ممکن است نیازمند مجموعه‌ای از رفتارهای هماهنگ باشد.

به همین دلیل می‌توان آموزش را از شرایطی با Feedback ساده‌تر آغاز کرد و به‌تدریج شرایط دشوارتر را معرفی کرد.

### **۱۰.۴. ساختار مفهومی**

```
Simple Task
     |
     v
Intermediate Task
     |
     v
Advanced Task
     |
     v
Complex Task
     |
     v
Target Task
```

### **۱۰.۵. مزایا**

- کاهش دشواری اولیه آموزش.
- بهبود Sample Efficiency در برخی مسائل.
- یادگیری تدریجی مهارت‌ها.
- کمک به حل مسائل دارای Sparse Rewards.
- افزایش احتمال یادگیری موفق رفتارهای پیچیده.

### **۱۰.۶. معایب**

اگر Curriculum به‌درستی طراحی نشود، ممکن است:

- Agent به مهارت‌های ساده بیش از حد وابسته شود.
- مهارت‌های لازم برای Task نهایی را یاد نگیرد.
- انتقال میان مراحل دشوار شود.
- ترتیب وظایف باعث ایجاد Bias شود.

نکته مهم: Curriculum Learning و Multi-Task Learning متفاوت‌اند.

- Multi-Task Learning: یادگیری از چند وظیفه.
- Curriculum Learning: سازمان‌دهی ترتیب و دشواری وظایف آموزشی.

## **۱۱. Meta-Learning**

مبحث پیشرفته

### **۱۱.۱. تعریف**

Meta-Learning به معنای Learning to Learn است.

در یادگیری معمولی، Agent تلاش می‌کند یک Task مشخص را حل کند.

اما در Meta-Learning، هدف این است که Agent از تجربه یادگیری چند Task استفاده کند تا در آینده بتواند Taskهای جدید را سریع‌تر یاد بگیرد.

به بیان ساده:

**به‌جای اینکه فقط به Agent یاد بدهیم چه کاری انجام دهد، به او یاد می‌دهیم چگونه بهتر یاد بگیرد.**

### **۱۱.۲. مثال**

فرض کنید یک Agent باید چند بازی مختلف را یاد بگیرد.

در آموزش معمولی، هر بازی از ابتدا یاد گرفته می‌شود.

اما در Meta-Learning، Agent از تجربه یادگیری بازی‌های قبلی استفاده می‌کند تا در بازی جدید سریع‌تر سازگار شود.

### **۱۱.۳. اجزای مفهومی**

```
        Multiple Training Tasks
                  |
                  v
          Meta-Learning Process
                  |
                  v
       Learn How to Learn Efficiently
                  |
                  v
          New / Unseen Task
                  |
                  v
       Fast Adaptation with Few Samples
```

### **۱۱.۴. هدف Meta-Learning**

- یادگیری سریع‌تر Taskهای جدید.
- کاهش تعداد تجربه‌های موردنیاز برای Adaptation.
- استفاده از دانش مشترک میان Taskها.
- بهبود قابلیت Generalization.
- سازگاری با محیط‌های جدید.

### **۱۱.۵. ارتباط با Neural Architecture Search**

یکی از کاربردهای مرتبط با ایده‌های Meta-Learning، یادگیری روش‌های بهتر برای طراحی یا آموزش شبکه‌های عصبی است.

برای مثال، می‌توان به دنبال سیستم‌هایی بود که بتوانند:

- ساختار مناسب شبکه را پیدا کنند.
- Hyperparameterها را تنظیم کنند.
- روش بهینه‌سازی مناسب را انتخاب کنند.
- فرآیند آموزش را برای مسئله جدید تطبیق دهند.

البته Neural Architecture Search و Meta-Learning یک مفهوم واحد نیستند؛ آن‌ها می‌توانند در برخی رویکردها با یکدیگر ترکیب شوند.

### **۱۱.۶. محدودیت‌ها**

- طراحی مجموعه Taskهای آموزشی مناسب دشوار است.
- آموزش Meta-Learner ممکن است هزینه محاسباتی زیادی داشته باشد.
- ممکن است Agent در Taskهای خارج از توزیع آموزشی عملکرد ضعیفی داشته باشد.
- تضمینی برای جلوگیری از Local Optima وجود ندارد.

## **۱۲. Hierarchical Reinforcement Learning (HRL)**

مبحث پیشرفته

### **۱۲.۱. تعریف**

Hierarchical Reinforcement Learning روشی است که در آن مسئله تصمیم‌گیری به چند سطح از تصمیم‌ها تقسیم می‌شود.

در RL معمولی، Agent در هر مرحله یک Action انتخاب می‌کند.

اما در HRL، Agent می‌تواند ابتدا یک هدف یا مهارت سطح بالا انتخاب کند و سپس مجموعه‌ای از اقدامات سطح پایین را برای رسیدن به آن اجرا کند.

### **۱۲.۲. مثال**

فرض کنید یک ربات باید از اتاقی خارج شود.

در RL معمولی:

- حرکت به چپ.
- حرکت به راست.
- حرکت به جلو.
- چرخش.
- تکرار این اقدامات.

در HRL:

- سطح بالا: تصمیم به خروج از اتاق.
- سطح پایین: یافتن در، حرکت به سمت آن و عبور از آن.

بنابراین، Agent به‌جای انتخاب مستقیم تمام اقدامات جزئی، از مهارت‌های سطح بالاتر استفاده می‌کند.

### **۱۲.۳. ساختار**

```
          High-Level Policy
                  |
                  v
          Select Subgoal / Skill
                  |
                  v
          Low-Level Policy
                  |
                  v
          Primitive Actions
                  |
                  v
             Environment
```

### **۱۲.۴. Options Framework**

یکی از چارچوب‌های مهم HRL، Options Framework است.

در این چارچوب، Option یک Action معمولی نیست؛ بلکه یک رفتار توسعه‌یافته در طول زمان است.

هر Option سه مؤلفه دارد:

**۱. Initiation Set (I)**

مجموعه Stateهایی که Option می‌تواند از آن‌ها آغاز شود.

**۲. Intra-Option Policy (π)**

Policy داخلی که اقدامات لازم برای اجرای Option را تعیین می‌کند.

**۳. Termination Condition (β)**

شرط یا احتمال پایان یافتن Option.

مثال Option با عنوان Open Door:

- Initiation Set: قرار داشتن ربات در نزدیکی در.
- Intra-Option Policy: حرکت به سمت دستگیره و باز کردن در.
- Termination Condition: باز شدن در یا شکست در اجرای عملیات.

### **۱۲.۵. ارتباط با Semi-Markov Decision Process**

از آنجا که اجرای یک Option ممکن است چندین Time Step طول بکشد، HRL را می‌توان با چارچوب Semi-Markov Decision Process (SMDP) مدل‌سازی کرد.

در MDP معمولی، Actionها در هر Time Step انتخاب می‌شوند.

اما در SMDP، تصمیم‌ها ممکن است در فواصل زمانی متفاوتی اتفاق بیفتند.

### **۱۲.۶. مزایا**

- کاهش پیچیدگی تصمیم‌گیری.
- مدیریت وظایف طولانی‌مدت.
- امکان استفاده مجدد از مهارت‌ها.
- بهبود Exploration در مسائل پیچیده.
- تقسیم مسئله به Subtaskهای قابل مدیریت.

### **۱۲.۷. محدودیت‌ها**

- پیدا کردن Hierarchy مناسب دشوار است.
- یادگیری Optionهای مؤثر پیچیده است.
- وابستگی زیاد به مهارت‌های سطح پایین می‌تواند مشکل‌ساز شود.
- خطای سطح بالا ممکن است عملکرد تمام سطوح پایین را مختل کند.

## **۱۳. Multi-Agent Reinforcement Learning (MARL)**

### **۱۳.۱. تعریف**

Multi-Agent Reinforcement Learning به شرایطی گفته می‌شود که چند Agent به‌صورت هم‌زمان در یک محیط فعالیت می‌کنند و رفتار یکدیگر را تحت تأثیر قرار می‌دهند.

این Agentها ممکن است:

- با یکدیگر همکاری کنند.
- با یکدیگر رقابت کنند.
- ترکیبی از همکاری و رقابت داشته باشند.

### **۱۳.۲. مهم‌ترین چالش: Non-Stationarity**

در Single-Agent RL، معمولاً محیط از دید Agent ثابت فرض می‌شود.

اما در Multi-Agent RL، رفتار سایر Agentها نیز در حال تغییر است.

فرض کنید Agent اول در حال یادگیری است.

هم‌زمان Agent دوم نیز Policy خود را تغییر می‌دهد.

بنابراین، محیطی که Agent اول تجربه می‌کند، دائماً تغییر می‌کند.

این وضعیت را Non-Stationarity می‌نامند.

```
Agent A Learning
       |
       v
Changes Policy
       |
       v
Changes Environment for Agent B
       |
       v
Agent B Updates Policy
       |
       v
Changes Environment for Agent A
       |
       v
Continuous Adaptation
```

### **۱۳.۳. Cooperative Multi-Agent Learning**

در این حالت، چند Agent برای رسیدن به یک هدف مشترک همکاری می‌کنند.

مثال:

چند خودروی خودران باید جریان ترافیک را بهینه کنند.

هدف هر خودرو فقط رسیدن سریع به مقصد خودش نیست؛ بلکه ممکن است کاهش ترافیک و افزایش ایمنی کل سیستم نیز اهمیت داشته باشد.

### **۱۳.۴. Centralized Critic**

یکی از روش‌های یادگیری همکاری، استفاده از Centralized Critic است.

در این ساختار، Critic می‌تواند اطلاعات بیشتری از وضعیت کلی سیستم دریافت کند.

برای مثال:

- State تمام Agentها.
- Actionهای انجام‌شده.
- اطلاعات کلی محیط.
- Reward مشترک.

در مقابل، هر Actor می‌تواند بر اساس اطلاعات محلی خودش تصمیم‌گیری کند.

### **۱۳.۵. Centralized Training, Decentralized Execution (CTDE)**

یکی از الگوهای مهم Multi-Agent RL، روش CTDE است.

در این روش:

- هنگام Training، اطلاعات گسترده‌تری از Agentها در اختیار سیستم یادگیری قرار می‌گیرد.
- هنگام Execution، هر Agent می‌تواند با استفاده از Policy محلی خودش تصمیم بگیرد.

```
                 Training
                    |
          +---------+---------+
          |                   |
          v                   v
       Agent A             Agent B
          |                   |
          +---------+---------+
                    |
                    v
           Centralized Critic
                    |
                    v
             Policy Updates
                    |
                    v
                 Execution
                    |
          +---------+---------+
          |                   |
          v                   v
      Local Actor A       Local Actor B
          |                   |
          v                   v
      Local Action A     Local Action B
```

این روش به Agentها کمک می‌کند در مرحله آموزش از اطلاعات مشترک بهره ببرند، اما برای اجرای نهایی لزوماً به یک کنترل‌کننده مرکزی وابسته نباشند.

### **۱۳.۶. Hierarchical RL و Multi-Agent RL**

این دو مفهوم متفاوت‌اند، اما می‌توانند با یکدیگر ترکیب شوند.

در HRL، تصمیم‌گیری در سطوح مختلف انجام می‌شود.

در MARL، چند Agent مستقل یا هماهنگ با یکدیگر تعامل می‌کنند.

گاهی می‌توان یک سیستم چندعاملی طراحی کرد که هر Agent وظیفه مشخصی در یک سلسله‌مراتب داشته باشد.

### **۱۳.۷. Self-Play و Adversarial Learning**

یکی از روش‌های مهم در آموزش Agentها، Self-Play است.

در این روش، Agent با نسخه دیگری از خودش یا نسخه‌های قبلی خود رقابت می‌کند.

مثال:

- Agent A در مقابل Agent B.
- Agent B نسخه قبلی Agent A است.
- نسخه جدید با چالش‌های ایجادشده توسط نسخه قبلی بهبود پیدا می‌کند.

مزایا:

- ایجاد حریف‌های متنوع.
- بهبود استراتژی.
- افزایش Robustness.
- کاهش وابستگی به حریف‌های از پیش تعریف‌شده.

این روش در بازی‌های رقابتی بسیار کاربرد دارد.

### **۱۳.۸. کاربردهای MARL**

- خودروهای خودران.
- مدیریت ترافیک.
- ربات‌های گروهی.
- بازی‌های چندنفره.
- شبکه‌های ارتباطی.
- مدیریت منابع توزیع‌شده.
- سیستم‌های مالی و بازارهای چندعاملی.

### **۱۳.۹. محدودیت‌ها**

- Non-Stationarity.
- افزایش پیچیدگی State و Action Space.
- دشواری هماهنگی Agentها.
- مشکل Credit Assignment.
- نیاز به روش‌های مناسب برای ارتباط و اشتراک اطلاعات.

نکته مهم: با افزایش تعداد Agentها، فضای Joint Action و Joint State ممکن است به‌شدت بزرگ شود؛ بنابراین مقیاس‌پذیری یکی از چالش‌های اساسی MARL است.&#x20;

## **۱۴. Explainable AI، Safety، Fairness و Ethical Standards**

بخش مهم مسئولیت‌پذیری هوش مصنوعی

در سیستم‌های DRL، Agent ممکن است رفتارهایی پیچیده و غیرقابل پیش‌بینی نشان دهد.

این مسئله در کاربردهای حساس مانند خودروهای خودران، پزشکی و رباتیک اهمیت زیادی دارد.

### **۱۴.۱. Explainable AI (XAI)**

هدف Explainable AI این است که بتوانیم بفهمیم چرا یک مدل یا Agent تصمیم خاصی گرفته است.

برای مثال:

یک خودروی خودران ناگهان ترمز می‌کند.

سؤالات مهم:

- چرا ترمز کرد؟
- چه اطلاعاتی باعث این تصمیم شد؟
- آیا مانعی را تشخیص داد؟
- آیا تصمیم به دلیل خطای حسگر بود؟
- آیا Policy رفتار غیرمنتظره‌ای نشان داد؟

در DRL، تفسیر تصمیم‌ها به دلیل وجود شبکه‌های عصبی عمیق و Policyهای پیچیده می‌تواند دشوار باشد.

روش‌های XAI می‌توانند شامل موارد زیر باشند:

- تحلیل ویژگی‌های مؤثر بر تصمیم.
- Visualization.
- بررسی رفتار Agent در شرایط مختلف.
- تحلیل مسیر تصمیم‌گیری.
- استفاده از مدل‌های قابل تفسیر در کنار مدل‌های پیچیده.

### **۱۴.۲. AI Safety**

AI Safety به مجموعه روش‌هایی گفته می‌شود که برای جلوگیری از رفتارهای ناخواسته، خطرناک یا آسیب‌زا در سیستم‌های هوشمند استفاده می‌شوند.

در RL، تعریف نامناسب Reward Function می‌تواند رفتارهای ناخواسته ایجاد کند.

مثال:

فرض کنید هدف یک ربات، جابه‌جایی سریع یک جسم باشد.

اگر فقط سرعت را پاداش دهیم و ایمنی را نادیده بگیریم، ممکن است ربات رفتارهای خطرناکی انجام دهد.

بنابراین باید محدودیت‌ها و معیارهای ایمنی نیز در طراحی سیستم لحاظ شوند.

مفاهیم مرتبط:

- Safe Reinforcement Learning
- Constraint-Based RL
- Risk-Sensitive RL
- Reward Hacking
- Robustness

### **۱۴.۳. Fairness**

Fairness به معنای جلوگیری از رفتارهای تبعیض‌آمیز یا ناعادلانه در سیستم‌های هوشمند است.

مثلاً یک Agent در تخصیص منابع نباید به‌صورت سیستماتیک به گروهی خاص اولویت ناعادلانه بدهد.

در طراحی Reward Function و انتخاب داده‌های آموزشی باید اثر تصمیم‌ها بر گروه‌های مختلف بررسی شود.

### **۱۴.۴. Ethical Standards**

استفاده از DRL در دنیای واقعی باید با اصول اخلاقی و مسئولیت‌پذیری همراه باشد.

موضوعات مهم:

- حفظ حریم خصوصی.
- شفافیت تصمیم‌ها.
- پاسخ‌گویی.
- ایمنی کاربران.
- جلوگیری از آسیب.
- مدیریت ریسک.
- نظارت انسانی.

**جمع‌بندی:** عملکرد بالا به‌تنهایی معیار کافی برای موفقیت یک Agent نیست. یک سیستم هوشمند باید علاوه بر عملکرد، قابل اعتماد، ایمن و مسئولانه نیز باشد.

## **۱۵. طراحی محیط‌های سفارشی برای Reinforcement Learning**

یکی از بخش‌های کاملاً کاربردی فصل، نحوه استفاده از DRL برای حل مسائل واقعی و سفارشی است.

### **۱۵.۱. چرا به Custom Environment نیاز داریم؟**

بسیاری از مسائل واقعی محیط آماده‌ای مانند Atari یا MuJoCo ندارند.

برای مثال:

- پیش‌بینی و معامله در بازارهای مالی.
- مدیریت منابع.
- کنترل سیستم‌های صنعتی.
- بهینه‌سازی ترافیک.
- رباتیک.
- مدیریت انرژی.

برای استفاده از RL باید این مسائل را به یک محیط قابل تعامل تبدیل کنیم.

### **۱۵.۲. مراحل طراحی محیط**

**مرحله اول: تعریف MDP**

باید مسئله را به مؤلفه‌های MDP تبدیل کنیم:

- State
- Action
- Transition
- Reward
- Initial State
- Terminal Conditions
- Discount Factor

**مرحله دوم: طراحی State**

مشخص کنیم Agent چه اطلاعاتی دریافت می‌کند.

مثلاً در معامله سهام:

- قیمت فعلی.
- حجم معاملات.
- موجودی حساب.
- دارایی‌های فعلی.
- شاخص‌های بازار.

**مرحله سوم: طراحی Action Space**

مشخص کنیم Agent چه اقداماتی می‌تواند انجام دهد.

برای مثال:

- Buy
- Sell
- Hold

یا در حالت پیوسته، تعیین مقدار سرمایه‌ای که باید خرید یا فروش شود.

**مرحله چهارم: طراحی Reward Function**

مشخص کنیم چه رفتاری مطلوب است.

مثلاً:

- سود حاصل از معامله.
- جریمه ریسک.
- هزینه معاملات.
- جریمه افت سرمایه.

**مرحله پنجم: پیاده‌سازی Transition Function**

باید مشخص کنیم اجرای هر Action چگونه State محیط را تغییر می‌دهد.

**مرحله ششم: پیاده‌سازی و آزمایش**

محیط باید به شکلی طراحی شود که Agent بتواند با آن تعامل کند.

### **۱۵.۳. چرخه تعامل Agent و Environment**

```
          Environment
               |
               v
         Observation
               |
               v
             Agent
               |
               v
             Action
               |
               v
          Environment
               |
               v
       Reward + New State
               |
               v
        Agent Learning
```

### **۱۵.۴. استفاده از محیط‌های آماده به‌عنوان الگو**

نویسنده توصیه می‌کند ساختار محیط‌های آماده را بررسی کنیم.

برای مثال:

- Atari: تعامل با Emulator.
- MuJoCo: تعامل با Physics Engine.
- سایر Simulatorها: دریافت Observation و اجرای Action.

با بررسی این محیط‌ها می‌توانیم الگوی مناسبی برای طراحی محیط خودمان پیدا کنیم.

### **۱۵.۵. نکات مهم در طراحی Custom Environment**

- Observation باید اطلاعات کافی برای تصمیم‌گیری فراهم کند.
- Action Space باید با مسئله واقعی سازگار باشد.
- Reward Function نباید باعث Reward Hacking شود.
- Transitionها باید تا حد امکان واقع‌بینانه باشند.
- شرایط Terminal باید درست تعریف شوند.
- محیط باید قابل ارزیابی و تکرارپذیر باشد.
- بهتر است ابتدا یک نسخه ساده بسازیم و سپس پیچیدگی را افزایش دهیم.

**نکته مهم:** اگر State ناقص باشد، ممکن است مسئله واقعی دیگر یک MDP قابل مشاهده نباشد و به POMDP نزدیک شود. همچنین طراحی اشتباه Reward Function می‌تواند باعث شود Agent مسئله‌ای متفاوت از هدف واقعی ما را بهینه کند.

## **۱۶. توصیه‌های نویسنده برای یادگیری و پیشرفت در حوزه DRL**

فصل فقط به مباحث فنی محدود نمی‌شود؛ نویسنده درباره مسیر یادگیری و ورود به این حوزه نیز توصیه‌هایی دارد.

### **۱۶.۱. فقط DRL یاد نگیرید**

برای درک عمیق Reinforcement Learning باید مفاهیم پایه‌ای حوزه‌های مرتبط را نیز بشناسیم:

- Mathematics
- Probability and Statistics
- Optimization
- Machine Learning
- Deep Learning
- Control Theory
- Computer Science

DRL در تقاطع چندین حوزه علمی قرار دارد.

### **۱۶.۲. روی مبانی تمرکز کنید**

یادگیری الگوریتم‌های جدید بدون درک اصول بنیادی، درک عمیقی از حوزه ایجاد نمی‌کند.

باید مفاهیمی مانند موارد زیر را به‌خوبی بشناسیم:

- MDP
- Bellman Equations
- Value Functions
- Policy Optimization
- Exploration vs Exploitation
- Temporal Difference Learning
- Bootstrapping
- Function Approximation

### **۱۶.۳. فقط مطالعه نکنید؛ پیاده‌سازی کنید**

یادگیری زمانی عمیق‌تر می‌شود که مفاهیم را به سیستم واقعی تبدیل کنیم.

پیشنهاد مسیر عملی:

1. پیاده‌سازی Tabular Q-Learning.
2. پیاده‌سازی DQN.
3. اضافه کردن Double DQN.
4. پیاده‌سازی REINFORCE.
5. پیاده‌سازی Actor-Critic.
6. پیاده‌سازی PPO.
7. ساخت Custom Environment.
8. آزمایش الگوریتم‌ها در محیط‌های مختلف.

### **۱۶.۴. مطالعه انتقادی داشته باشید**

هر منبعی که مطالعه می‌کنیم لزوماً درست یا کامل نیست.

باید به موارد زیر توجه کنیم:

- اعتبار نویسنده.
- کیفیت پژوهش.
- روش ارزیابی.
- محدودیت‌های نتایج.
- قابلیت تکرار آزمایش‌ها.

### **۱۶.۵. تمرکز و استراحت**

یادگیری این حوزه نیازمند تمرکز طولانی‌مدت است.

نویسنده تأکید می‌کند:

- از پراکندگی در منابع مختلف جلوگیری کنید.
- برای مطالعه عمیق زمان اختصاص دهید.
- به ذهن فرصت پردازش اطلاعات بدهید.
- از یادگیری سطحی و صرفاً مصرف محتوا پرهیز کنید.

### **۱۶.۶. از سؤال پرسیدن نترسید**

پرسیدن سؤال، حتی سؤال‌های ساده، بخشی از فرایند یادگیری است.

وقتی در یک موضوع به مشکل می‌خورید:

- مسئله را به بخش‌های کوچک‌تر تقسیم کنید.
- سؤال دقیق مطرح کنید.
- آزمایش انجام دهید.
- فرضیه‌های خود را بررسی کنید.
- از تجربه دیگران استفاده کنید.

### **۱۶.۷. در جامعه علمی مشارکت کنید**

یکی از توصیه‌های پایانی نویسنده، مشارکت فعال در جامعه DRL است.

برای مثال:

- نوشتن Blog Post.
- انتشار نتایج آزمایش‌ها.
- پیاده‌سازی الگوریتم‌ها.
- مشارکت در Open Source.
- مطالعه و تحلیل مقالات.
- اشتراک‌گذاری تجربه‌ها.
- توسعه روش‌های جدید.

**نکته کلیدی:** صرفاً مصرف‌کننده دانش نباشید؛ چیزی بسازید و به جامعه علمی و فنی کمک کنید.

## **۱۷. یادگیری بدون Reward صریح (Reward-Free Learning)**

یکی از موضوعات جالبی که در گفت‌وگوی پایانی کتاب مطرح می‌شود، این است که آیا Agent می‌تواند بدون دریافت Reward صریح از محیط یاد بگیرد؟

### **۱۷.۱. مسئله اصلی**

در RL سنتی، معمولاً یک Reward Function طراحی می‌کنیم.

مثلاً:

- رسیدن به هدف: +10
- برخورد با مانع: -5
- انجام اقدام مطلوب: +1

اما در دنیای واقعی، همیشه نمی‌توان هدف را به‌صورت یک عدد دقیق تعریف کرد.

مثلاً انسان‌ها برای هر رفتار خود پاداش عددی دریافت نمی‌کنند، اما همچنان یاد می‌گیرند.

این موضوع انگیزه‌ای برای تحقیق درباره روش‌های یادگیری بدون Reward صریح است.

### **۱۷.۲. چالش‌های Reward-Free Learning**

- Agent چگونه باید هدف خود را تشخیص دهد؟
- چگونه رفتار مطلوب را از رفتار نامطلوب تفکیک کند؟
- چگونه از انجام اقدامات خطرناک جلوگیری شود؟
- چگونه اطمینان حاصل کنیم اهداف Agent با ارزش‌های انسانی سازگار هستند؟

### **۱۷.۳. ارتباط با AI Alignment**

یکی از نگرانی‌های مهم این است که اگر سیستم هوشمند اختیار زیادی داشته باشد اما اهداف و محدودیت‌های آن به‌درستی تعریف نشده باشند، ممکن است رفتارهایی غیرمنتظره نشان دهد.

بنابراین باید به موضوعاتی مانند موارد زیر توجه کنیم:

- Alignment
- Safety Constraints
- Human Oversight
- Reward Design
- Goal Specification

نکته مهم: Reward-Free Learning یک اصطلاح گسترده برای مجموعه‌ای از رویکردهای پژوهشی است و نباید آن را با حذف کامل هر نوع هدف، سیگنال آموزشی یا محدودیت اشتباه گرفت.

## **۱۸. ارتباط مفاهیم پیشرفته فصل با یکدیگر**

یکی از مهم‌ترین نکاتی که باید از فصل ۱۳ دریافت کنیم، این است که مفاهیم معرفی‌شده مستقل از یکدیگر نیستند.

بسیاری از آن‌ها می‌توانند با یکدیگر ترکیب شوند.

برای مثال، فرض کنید می‌خواهیم یک ربات عمومی طراحی کنیم که در محیط‌های مختلف فعالیت کند.

این سیستم می‌تواند از روش‌های زیر بهره ببرد:

```
                Multi-Task Learning
                        |
                        v
                  Learn Shared Skills
                        |
                        v
                  Meta-Learning
                        |
                        v
               Faster Task Adaptation
                        |
                        v
               Hierarchical RL
                        |
                        v
              High-Level Subgoals
                        |
                        v
                Low-Level Actions
                        |
                        v
               Multi-Agent Learning
                        |
                        v
               Team Coordination
                        |

                 Generalization
```

در کنار این ساختار:

- Domain Randomization به افزایش Robustness کمک می‌کند.
- Inverse Reinforcement Learning امکان استخراج Reward از رفتار Expert را فراهم می‌کند.
- Advanced Exploration باعث کشف اطلاعات و رفتارهای جدید می‌شود.
- Model-Based RL امکان Planning با استفاده از مدل محیط را فراهم می‌کند.
- Explainable AI و Safety به قابل اعتماد بودن سیستم کمک می‌کنند.

بنابراین، حرکت به سمت هوش عمومی صرفاً با توسعه یک الگوریتم قدرتمندتر اتفاق نمی‌افتد؛ بلکه به ترکیب روش‌های مختلف یادگیری، استدلال، سازگاری و تصمیم‌گیری نیاز دارد.

شناخت ارتباط میان این روش‌ها از حفظ کردن نام الگوریتم‌ها مهم‌تر است.
