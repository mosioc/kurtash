فصل ۹ به یکی از مهم‌ترین نقاط عطف در یادگیری تقویتی عمیق می‌پردازد: **Deep Q-Network (DQN)** و روش‌هایی که برای پایدارتر، دقیق‌تر و کارآمدتر کردن آن توسعه پیدا کرده‌اند.

ایده اصلی فصل این است که چگونه می‌توان از شبکه‌های عصبی برای تخمین تابع ارزش در محیط‌های پیچیده استفاده کرد؛ به‌خصوص محیط‌هایی که ورودی آن‌ها داده‌های خامی مانند تصاویر هستند.

در این فصل فقط با DQN آشنا نمی‌شویم، بلکه مشکلات بنیادی استفاده از شبکه‌های عصبی در RL و راه‌حل‌هایی مانند Experience Replay، Target Network، Double DQN، Dueling Network و Prioritized Experience Replay را بررسی می‌کنیم.

نکته مهم: این فصل ارتباط مستقیمی با مباحث فصل‌های قبلی دارد:

- Q-Learning: یادگیری ارزش اقدامات.

- Deep Learning: استفاده از شبکه عصبی برای تقریب Q-Function.
- Experience Replay و Target Network: پایدارسازی آموزش.
- Double DQN و Dueling DQN: بهبود تخمین Q-Value.
- Prioritized Experience Replay: بهبود نحوه انتخاب داده‌های آموزشی.

## **۲. مقدمه: چرا به DQN نیاز داریم؟**

در فصل ۸ با روش‌هایی مانند NFQ آشنا شدیم که از شبکه‌های عصبی برای تقریب تابع ارزش استفاده می‌کردند.

در روش‌های جدولی مانند Q-Learning، برای هر State و Action یک مقدار Q ذخیره می‌کنیم.

اما این روش در محیط‌های پیچیده مشکل دارد:

- تعداد Stateها می‌تواند بسیار زیاد باشد.
- فضای حالت ممکن است پیوسته باشد.
- ورودی محیط ممکن است تصاویر خام باشد.
- ذخیره‌سازی جداگانه مقدار Q برای تمام حالت‌ها عملی نیست.

راه‌حل، استفاده از Function Approximation است.

به‌جای ذخیره تمام مقادیر Q، یک شبکه عصبی یاد می‌گیرد که تابع Q را تقریب بزند.

### **DQN چیست؟**

**Deep Q-Network (DQN)** الگوریتمی است که از شبکه عصبی عمیق برای تخمین Action-Value Function استفاده می‌کند.

تابع Q به‌صورت زیر تقریب زده می‌شود:

\\[ Q(s,a;\theta) \\]

که در آن:

- \\(s\\): وضعیت فعلی محیط (State)
- \\(a\\): اقدام انتخاب‌شده (Action)
- \\(\theta\\): پارامترهای شبکه عصبی
- \\(Q(s,a;\theta)\\): ارزش تخمینی انجام Action در State مشخص

شبکه عصبی به‌جای اینکه فقط یک مقدار Q را برای یک جفت State و Action محاسبه کند، معمولاً مقادیر Q تمام Actionهای ممکن را برای یک State خروجی می‌دهد.

### **۱. ساختار مفهومی DQN**

```
State (ورودی محیط)
    |
    | مثال: تصویر یک بازی Atari
    v
Deep Neural Network
    |
    | استخراج ویژگی‌ها و تخمین Q-Value
    v
Q-Values
    |
    |-- Left  = 2.1
    |-- Right = 5.8
    |-- Jump  = 3.4
    |
    v
Action Selection
    |
    v
Right (بالاترین Q-Value)
```

در حالت Greedy، عامل اقدامی را انتخاب می‌کند که بیشترین Q-Value را دارد:

\\[ a^\*=\arg\max_a Q(s,a;\theta) \\]

البته در عمل برای Exploration ممکن است از Epsilon-Greedy یا روش‌های دیگر استفاده شود.

### **اهمیت تاریخی DQN**

DQN نشان داد که می‌توان از شبکه عصبی برای یادگیری مستقیم از ورودی‌های تصویری خام استفاده کرد.

این الگوریتم در بازی‌های Atari به موفقیت چشمگیری رسید و نشان داد که عامل می‌تواند بدون طراحی دستی ویژگی‌های تصویری، از تجربه خود الگوهای مفیدی استخراج کند.

نکته: DQN اولین الگوریتم Deep RL نبود، اما یکی از مهم‌ترین دستاوردهای اولیه در ترکیب Deep Learning و Q-Learning محسوب می‌شود.

## **۳. چالش‌های اصلی Value-Based Deep Reinforcement Learning**

یکی از مهم‌ترین موضوعات فصل، دلیل ناپایداری آموزش شبکه‌های عصبی در RL است.

در یادگیری نظارت‌شده معمولاً داده‌ها از یک Dataset مشخص دریافت می‌شوند و مدل روی آن‌ها آموزش می‌بیند.

اما در Reinforcement Learning، عامل خودش داده تولید می‌کند و رفتار آن روی داده‌های آینده تأثیر می‌گذارد.

دو مشکل اصلی مطرح می‌شود:

1. Violation of IID Assumption
2. Non-Stationarity of Targets

### **۳.۱. فرض IID چیست؟**

IID مخفف عبارت زیر است:

**Independent and Identically Distributed**

یعنی داده‌ها باید دو ویژگی داشته باشند:

**Independent (مستقل):**

نمونه‌های آموزشی نباید به یکدیگر وابسته باشند.

**Identically Distributed (توزیع یکسان):**

نمونه‌ها باید از یک توزیع احتمالی یکسان تولید شده باشند.

برای مثال، فرض کن یک سکه سالم را چندین بار پرتاب می‌کنیم:

- نتیجه هر پرتاب مستقل از پرتاب قبلی است.
- احتمال شیر و خط در هر پرتاب ثابت است.

بنابراین داده‌ها تقریباً IID هستند.

### **۳.۲. چرا داده‌های RL مستقل نیستند؟**

در RL، داده‌ها به‌صورت دنباله‌ای تولید می‌شوند.

\\[ S_t \rightarrow A_t \rightarrow R\_{t+1} \rightarrow S\_{t+1} \\]

State بعدی به State قبلی و Action انتخاب‌شده وابسته است.

در نتیجه:

- تجربه‌های متوالی به هم وابسته‌اند.
- نمونه‌های آموزشی کاملاً مستقل نیستند.
- عامل از تجربه‌های اخیر خود تأثیر می‌گیرد.

مثلاً در یک بازی، اگر عامل در یک مسیر مشخص حرکت کند، احتمالاً چندین تجربه متوالی از همان منطقه بازی جمع‌آوری خواهد کرد.

### **۳.۳. Non-Stationarity of Data**

مشکل فقط وابستگی نمونه‌ها نیست.

توزیع داده‌های آموزشی نیز با تغییر Policy تغییر می‌کند.

فرض کن:

1. عامل در ابتدا رفتار تصادفی دارد.
2. به‌تدریج یاد می‌گیرد از مسیرهای مشخصی عبور کند.
3. حالا بیشتر تجربه‌های آن از مسیرهای جدید جمع‌آوری می‌شوند.

بنابراین توزیع Stateهایی که عامل مشاهده می‌کند، با پیشرفت آموزش تغییر می‌کند.

\\[ \pi_1 \neq \pi_2 \\]

\\[ d^{\pi_1}(s) \neq d^{\pi_2}(s) \\]

در اینجا \\(d^\pi(s)\\) توزیع حالت‌هایی است که Policy موردنظر تولید می‌کند.

**نتیجه:** داده‌های آموزشی RL برخلاف بسیاری از مسائل Supervised Learning، الزاماً مستقل و دارای توزیع ثابت نیستند.

### **۳.۴. Non-Stationarity of Targets**

مشکل دوم، تغییر مداوم Targetهایی است که شبکه عصبی باید یاد بگیرد.

در Q-Learning هدف آموزشی به شکل زیر است:

\\[ y=r+\gamma\max\_{a'}Q(s',a';\theta) \\]

توجه کن که Target خودش به پارامترهای شبکه عصبی \\(\theta\\) وابسته است.

یعنی:

1. شبکه عصبی Q-Value را تخمین می‌زند.
2. از همان تخمین برای ساخت Target استفاده می‌شود.
3. شبکه با استفاده از Target به‌روزرسانی می‌شود.
4. با تغییر شبکه، Target نیز تغییر می‌کند.

در نتیجه، شبکه در حال یادگیری از هدفی است که خودش دائماً آن را تغییر می‌دهد.

این مسئله می‌تواند موجب ناپایداری و حتی Divergence شود.

### **۲. چرخه تغییر Target**

```
شبکه عصبی Q-Value را تخمین می‌زند
                |
                v
Target از تخمین Q ساخته می‌شود
                |
                v
شبکه برای نزدیک شدن به Target به‌روزرسانی می‌شود
                |
                v
Target تغییر می‌کند!
                |
                v
          تکرار چرخه
```

این دو مشکل، یعنی وابستگی و تغییر توزیع داده‌ها و همچنین تغییر Targetها، از مهم‌ترین دلایل نیاز به تکنیک‌های پایدارسازی DQN هستند.

## **۴. Target Network**

یکی از مهم‌ترین نوآوری‌های DQN، استفاده از Target Network است.

### **۴.۱. Target Network چیست؟**

در DQN به‌جای استفاده از یک شبکه برای تمام محاسبات، از دو شبکه عصبی استفاده می‌کنیم:

1. **Online Network (شبکه اصلی):** شبکه‌ای که دائماً آموزش می‌بیند.
2. **Target Network:** شبکه‌ای که برای محاسبه Target استفاده می‌شود.

پارامترهای این دو شبکه را به شکل زیر نمایش می‌دهیم:

\\[ Q(s,a;\theta) \\]

برای Online Network و:

\\[ Q(s,a;\theta^-) \\]

برای Target Network.

پارامترهای Target Network از Online Network کپی می‌شوند، اما برخلاف آن، در هر مرحله به‌روزرسانی نمی‌شوند.

### **۴.۲. نحوه عملکرد**

در DQN، Target به شکل زیر محاسبه می‌شود:

\\[ y=r+\gamma\max\_{a'}Q(s',a';\theta^-) \\]

در این فرمول:

- \\(r\\): پاداش دریافتی
- \\(\gamma\\): ضریب Discount
- \\(s'\\): State بعدی
- \\(\theta^-\\): پارامترهای Target Network

سپس Online Network تلاش می‌کند پیش‌بینی خود را به Target نزدیک کند.

\\[ L(\theta)= \left(y-Q(s,a;\theta)\right)^2 \\]

به این ترتیب، شبکه اصلی برای مدتی با Target نسبتاً ثابتی آموزش می‌بیند.

### **۴.۳. Target Network چگونه به‌روزرسانی می‌شود؟**

دو روش متداول وجود دارد:

**روش اول: Hard Update**

در فواصل مشخص، پارامترهای Online Network به Target Network کپی می‌شوند.

\\[ \theta^- \leftarrow \theta \\]

مثلاً هر ۱۰۰۰ یا ۱۰٬۰۰۰ مرحله.

**روش دوم: Soft Update**

پارامترهای Target Network به‌صورت تدریجی به پارامترهای Online Network نزدیک می‌شوند:

\\[ \theta^- \leftarrow \tau\theta+(1-\tau)\theta^- \\]

که در آن:

\\[ 0<\tau\leq 1 \\]

مقدار کوچک‌تر \\(\tau\\) باعث می‌شود Target Network آهسته‌تر تغییر کند.

### **۳. مقایسه دو شبکه در DQN**

```
DQN
 |
 +---- Online Network
 |       |
 |       +---- Trainable
 |       |
 |       +---- به‌روزرسانی با Gradient Descent
 |
 +---- Target Network
         |
         +---- Temporarily Frozen
         |
         +---- محاسبه Targetهای پایدارتر
```

**روش‌های به‌روزرسانی Target Network:**

```
Hard Update:
کپی دوره‌ای پارامترهای Online Network به Target Network

θ- ← θ

Soft Update:
انتقال تدریجی پارامترهای Online Network به Target Network

θ- ← τθ + (1 - τ)θ-
```

**Online Network**

Trainable

به‌روزرسانی با Gradient Descent

**Target Network**

Temporarily Frozen

محاسبه Targetهای پایدارتر

در Hard Update، پارامترهای Online به‌صورت دوره‌ای به Target کپی می‌شوند. در Soft Update، این انتقال تدریجی است.

**مزیت اصلی Target Network:** کاهش نوسانات Target و پایدارتر شدن فرآیند یادگیری.

**نکته:** ثابت نگه داشتن Target Network برای همیشه درست نیست؛ چون در آن صورت Targetها با پیشرفت یادگیری به‌روزرسانی نمی‌شوند. بنابراین باید هر از گاهی به‌روزرسانی شود.

### **۴.۴. استفاده از شبکه‌های بزرگ‌تر**

شبکه عصبی بزرگ‌تر می‌تواند ظرفیت بیشتری برای تقریب توابع پیچیده داشته باشد.

در محیط‌هایی مانند Atari، استفاده از شبکه‌های عمیق‌تر و معماری‌هایی مانند CNN امکان استخراج ویژگی از تصاویر را فراهم می‌کند.

اما بزرگ‌تر بودن شبکه همیشه بهتر نیست:

- محاسبات بیشتری نیاز دارد.
- ممکن است آموزش سخت‌تر شود.
- می‌تواند مستعد Overfitting باشد.
- به تنظیم دقیق Hyperparameterها نیاز دارد.

بنابراین معماری شبکه باید متناسب با پیچیدگی محیط انتخاب شود.

## **۵. Experience Replay**

مشکل دیگری که در RL وجود دارد، وابستگی تجربه‌های متوالی است.

برای حل این مشکل، DQN از تکنیکی به نام Experience Replay استفاده می‌کند.

### **۵.۱. Experience Replay چیست؟**

Experience Replay یک حافظه برای ذخیره تجربه‌های گذشته عامل است.

به‌جای اینکه شبکه عصبی فقط از آخرین تجربه عامل برای آموزش استفاده کند، تجربه‌های قبلی ذخیره می‌شوند و بعداً به‌صورت تصادفی از آن‌ها نمونه‌برداری می‌شود.

این حافظه معمولاً Replay Buffer نام دارد.

### **۵.۲. ساختار Replay Buffer**

هر تجربه به‌صورت یک Tuple ذخیره می‌شود:

\\[ e_t=(s_t,a_t,r\_{t+1},s\_{t+1},d\_{t+1}) \\]

اجزای آن:

| مؤلفه          | مفهوم                                   |
| -------------- | --------------------------------------- |
| \\(s_t\\)      | State فعلی                              |
| \\(a_t\\)      | Action انتخاب‌شده                       |
| \\(r\_{t+1}\\) | Reward دریافتی                          |
| \\(s\_{t+1}\\) | State بعدی                              |
| \\(d\_{t+1}\\) | مشخص می‌کند Episode تمام شده است یا خیر |

معمولاً Replay Buffer ظرفیت مشخصی دارد. هنگامی که ظرفیت پر می‌شود، تجربه‌های قدیمی با تجربه‌های جدید جایگزین می‌شوند.

این ساختار معمولاً به شکل Circular Buffer پیاده‌سازی می‌شود.

### **۵.۳. نحوه عملکرد Experience Replay**

فرآیند به شکل زیر است:

1. عامل با محیط تعامل می‌کند.
2. تجربه جدید در Replay Buffer ذخیره می‌شود.
3. تعدادی تجربه به‌صورت تصادفی انتخاب می‌شوند.
4. این تجربه‌ها یک Mini-Batch تشکیل می‌دهند.
5. شبکه عصبی با استفاده از Mini-Batch آموزش می‌بیند.
6. این فرآیند تکرار می‌شود.

### **۴. چرخه Experience Replay**

```
Agent interacts with Environment
                |
                v
        Store Experience
                |
                v
(State, Action, Reward, Next State, Done)
                |
                v
          Replay Buffer
                |
                +---- Experience 1
                +---- Experience 2
                +---- Experience 3
                +---- Experience 4
                +---- Experience 5
                |
                v
         Random Sampling
                |
                v
            Mini-Batch
                |
                v
       Train Online Network
                |
                v
              Repeat
```

### **۵.۴. چرا Random Sampling مهم است؟**

فرض کن عامل در یک بازی در حال حرکت در یک مسیر مشخص است.

اگر فقط از تجربه‌های اخیر برای آموزش استفاده کنیم، احتمالاً بیشتر نمونه‌ها مربوط به موقعیت‌های نزدیک به یکدیگر خواهند بود.

این مسئله باعث می‌شود:

- نمونه‌های آموزشی به یکدیگر وابسته باشند.
- شبکه بیش از حد تحت تأثیر تجربه‌های اخیر قرار بگیرد.
- آموزش نوسان بیشتری داشته باشد.

با Random Sampling، تجربه‌هایی از زمان‌ها و موقعیت‌های مختلف وارد Mini-Batch می‌شوند.

در نتیجه، وابستگی زمانی نمونه‌های یک Batch کاهش پیدا می‌کند و آموزش پایدارتر می‌شود.

### **۵.۵. مزایای Experience Replay**

1. **Reducing Correlation:** کاهش همبستگی بین نمونه‌های آموزشی.
2. **Better Data Efficiency:** استفاده مجدد از تجربه‌های قبلی.
3. **More Stable Training:** جلوگیری از وابستگی بیش از حد به تجربه‌های اخیر.
4. **Improved Generalization:** کمک به یادگیری از شرایط متنوع‌تر.

### **۵.۶. محدودیت‌های Experience Replay**

- به حافظه بیشتری نیاز دارد.
- اندازه Buffer باید متناسب با مسئله انتخاب شود.
- تجربه‌های بسیار قدیمی ممکن است با Policy فعلی ارتباط کمتری داشته باشند.
- نمونه‌برداری کاملاً تصادفی تضمین نمی‌کند که تجربه‌های مهم‌تر بیشتر استفاده شوند.

نکته مهم: Experience Replay داده‌ها را کاملاً IID نمی‌کند؛ بلکه وابستگی و همبستگی بین نمونه‌های انتخاب‌شده برای آموزش را کاهش می‌دهد.

## **۶. Exploration Strategies**

در فصل‌های قبلی با Exploration و Exploitation آشنا شدیم.

DQN نیز برای انتخاب Actionها به یک راهبرد Exploration نیاز دارد.

### **۶.۱. Epsilon-Greedy**

یکی از رایج‌ترین روش‌ها، Epsilon-Greedy است.

در این روش:

- با احتمال \\(\epsilon\\)، یک Action تصادفی انتخاب می‌شود.
- با احتمال \\(1-\epsilon\\)، بهترین Action فعلی انتخاب می‌شود.

\\[ a_t= \begin{cases} \text{Random Action} & \text{with probability }\epsilon\\\ \arg\max_a Q(s_t,a;\theta) & \text{with probability }1-\epsilon \end{cases} \\]

### **۶.۲. Decaying Epsilon**

معمولاً مقدار Epsilon در طول آموزش کاهش پیدا می‌کند.

در ابتدای آموزش:

- دانش عامل کم است.
- Exploration اهمیت بیشتری دارد.

در ادامه:

- عامل تجربه بیشتری کسب می‌کند.
- می‌تواند بیشتر از دانش فعلی خود استفاده کند.

بنابراین:

\\[ \epsilon\_{\text{initial}} > \epsilon\_{\text{final}} \\]

برای مثال:

```
Initial epsilon = 1.0
Final epsilon   = 0.01
```

این مقادیر صرفاً نمونه هستند و به مسئله بستگی دارند.

### **۶.۳. سایر روش‌های Exploration**

در متن فصل به استفاده از راهبردهای دیگر نیز اشاره می‌شود.

- **Softmax Exploration:** انتخاب Actionها با احتمال متناسب با ارزش تخمینی آن‌ها.
- **Optimistic Initialization:** شروع با تخمین‌های خوش‌بینانه برای تشویق عامل به بررسی Actionهای ناشناخته.

این راهبردها می‌توانند جایگزین یا مکمل Epsilon-Greedy باشند.

## **۷. Double DQN**

(مفهوم کلیدی فصل ۹)

یکی از مشکلات مهم Q-Learning و DQN، بیش‌برآوردی ارزش Actionها است.

این مشکل را Overestimation Bias می‌نامیم.

### **۷.۱. Overestimation چیست؟**

در Q-Learning برای محاسبه Target از رابطه زیر استفاده می‌کنیم:

\\[ y=r+\gamma\max\_{a'}Q(s',a') \\]

مشکل این است که ما از Maximum مقدارهای تخمینی استفاده می‌کنیم.

فرض کن Q-Valueهای واقعی سه Action به شکل زیر باشند:

| Action | Q واقعی | Q تخمینی |
| ------ | ------- | -------- |
| A      | 5       | 6        |
| B      | 4       | 8        |
| C      | 3       | 2        |

در این شرایط:

- بهترین Action واقعی A است.
- اما شبکه عصبی Action B را انتخاب می‌کند.
- مقدار تخمینی B برابر 8 است، در حالی که ارزش واقعی آن 4 است.

وقتی همیشه بیشترین مقدار تخمینی را انتخاب می‌کنیم، خطاهای مثبت می‌توانند بیشتر در انتخاب نهایی ظاهر شوند.

بنابراین Maximum تخمینی ممکن است به‌طور سیستماتیک از Maximum واقعی بیشتر باشد.

این مسئله را Overestimation Bias می‌نامیم.

### **۷.۲. تفاوت Max و Argmax**

برای درک Double DQN باید تفاوت این دو مفهوم را بدانیم.

**Argmax:**

Action دارای بالاترین مقدار را پیدا می‌کند.

\\[ \arg\max_a Q(s,a) \\]

خروجی: Action

**Max:**

بالاترین مقدار Q را پیدا می‌کند.

\\[ \max_a Q(s,a) \\]

خروجی: مقدار Q

مثال:

```
Q-values:

A = 5
B = 8
C = 3

argmax(Q) = B
max(Q)    = 8
```

این دو عملیات در Double DQN نقش متفاوتی دارند.

### **۷.۳. ایده اصلی Double DQN**

در DQN معمولی، یک شبکه هم Action را انتخاب می‌کند و هم ارزش آن را ارزیابی می‌کند.

Double DQN این دو مسئولیت را از هم جدا می‌کند.

- Online Network: انتخاب بهترین Action
- Target Network: ارزیابی ارزش Action انتخاب‌شده

به این ترتیب، شبکه‌ای که Action را انتخاب می‌کند، همان شبکه‌ای نیست که مقدار آن Action را ارزیابی می‌کند.

### **۷.۴. فرمول Double DQN**

در DQN معمولی:

\\[ y\_{\text{DQN}}= r+\gamma\max\_{a'} Q(s',a';\theta^-) \\]

در Double DQN:

\\[ y\_{\text{Double DQN}}= r+\gamma Q\left( s', \arg\max\_{a'}Q(s',a';\theta); \theta^- \right) \\]

تفاوت اصلی:

در Double DQN:

1. Online Network با پارامترهای \\(\theta\\)، بهترین Action را انتخاب می‌کند.
2. Target Network با پارامترهای \\(\theta^-\\)، ارزش همان Action را محاسبه می‌کند.

### **۷.۵. مثال عددی**

فرض کن خروجی دو شبکه به شکل زیر باشد:

| Action | Online Q | Target Q |
| ------ | -------- | -------- |
| A      | 5        | 4        |
| B      | 8        | 5        |
| C      | 3        | 7        |

در Double DQN:

**مرحله اول: انتخاب Action با Online Network**

\\[ a^\*=\arg\max_a Q(s',a;\theta) \\]

بنابراین:

\\[ a^\*=B \\]

**مرحله دوم: ارزیابی Action با Target Network**

\\[ Q(s',B;\theta^-)=5 \\]

پس مقدار Target:

\\[ y=r+\gamma(5) \\]

در مقابل، DQN معمولی از Maximum خروجی Target Network استفاده می‌کند:

\\[ \max(4,5,7)=7 \\]

در این مثال، Double DQN به‌جای مقدار ۷ از مقدار ۵ استفاده می‌کند.

این جداسازی می‌تواند اثر خطای بیش‌برآوردی را کاهش دهد.

### **۷.۶. آیا Double DQN به دو شبکه اضافی نیاز دارد؟**

خیر.

DQN از قبل دو شبکه دارد:

- Online Network
- Target Network

Double DQN از همین دو شبکه برای جداسازی Action Selection و Action Evaluation استفاده می‌کند.

بنابراین نیازی به اضافه کردن دو شبکه عصبی مستقل دیگر نیست.

### **۷.۷. ارتباط Double DQN با Double Q-Learning**

در فصل ۶ با Double Q-Learning آشنا شدیم.

ایده بنیادی هر دو روش مشابه است:

**جدا کردن انتخاب Action از ارزیابی ارزش آن برای کاهش Overestimation Bias.**

تفاوت این است که Double DQN این ایده را در معماری مبتنی بر شبکه عصبی و با استفاده از Online و Target Network پیاده‌سازی می‌کند.

## **۸. Loss Functions در DQN**

برای آموزش شبکه عصبی باید اختلاف بین Q-Value پیش‌بینی‌شده و Target را محاسبه کنیم.

به این اختلاف، TD Error می‌گوییم:

\\[ \delta=y-Q(s,a;\theta) \\]

برای بهینه‌سازی شبکه، از Loss Function استفاده می‌شود.

سه تابع مهم که در متن مطرح شده‌اند:

1. Mean Squared Error (MSE)
2. Mean Absolute Error (MAE)
3. Huber Loss

### **۸.۱. Mean Squared Error (MSE)**

MSE میانگین مربع اختلاف بین پیش‌بینی و مقدار هدف است.

\\[ L\_{\text{MSE}}= \frac{1}{N}\sum\_{i=1}^{N} (y_i-\hat y_i)^2 \\]

ویژگی‌ها:

- خطاهای بزرگ را به‌شدت جریمه می‌کند.
- نسبت به Outlierها حساس است.
- در نزدیکی خطای صفر، Gradient به‌تدریج کوچک می‌شود.
- تابعی هموار و قابل مشتق است.

مثال:

```
Error = 2  -> Squared Error = 4
Error = 5  -> Squared Error = 25
```

بنابراین خطای ۵ تأثیر بسیار بیشتری نسبت به خطای ۲ دارد.

### **۸.۲. Mean Absolute Error (MAE)**

MAE میانگین قدرمطلق اختلاف بین مقدار پیش‌بینی‌شده و مقدار هدف است.

\\[ L\_{\text{MAE}}= \frac{1}{N}\sum\_{i=1}^{N} |y_i-\hat y_i| \\]

ویژگی‌ها:

- خطاهای بزرگ را به اندازه متناسب با بزرگی آن‌ها جریمه می‌کند.
- نسبت به Outlierها مقاوم‌تر از MSE است.
- در نقطه صفر مشتق‌پذیر نیست.
- Gradient آن نسبت به اندازه خطا تقریباً ثابت است.

مثال:

```
Error = 2  -> Absolute Error = 2
Error = 5  -> Absolute Error = 5
```

### **۸.۳. Huber Loss**

Huber Loss ترکیبی از ویژگی‌های MSE و MAE است.

برای خطاهای کوچک مانند MSE رفتار می‌کند و برای خطاهای بزرگ مانند MAE.

\\[ L\_\delta(e)= \begin{cases} \frac{1}{2}e^2 & |e|\leq\delta\\\ \delta(|e|-\frac{1}{2}\delta) & |e|>\delta \end{cases} \\]

که در آن:

\\[ e=y-\hat y \\]

و \\(\delta\\) آستانه تغییر رفتار تابع است.

**اگر خطا کوچک باشد:**

\\[ |e|\leq\delta \\]

تابع مانند MSE عمل می‌کند.

**اگر خطا بزرگ باشد:**

\\[ |e|>\delta \\]

تابع مانند MAE رفتار می‌کند.

### **۸.۴. نقش Delta در Huber Loss**

پارامتر \\(\delta\\) تعیین می‌کند که از چه نقطه‌ای رفتار تابع از Quadratic به Linear تغییر کند.

- Delta کوچک: بخش خطی زودتر آغاز می‌شود.
- Delta بزرگ: رفتار Quadratic در محدوده بزرگ‌تری ادامه می‌یابد.

در حدهای مفهومی:

- با \\(\delta\\) بسیار کوچک، رفتار به MAE نزدیک می‌شود.
- با \\(\delta\\) بسیار بزرگ، رفتار به MSE نزدیک می‌شود.

### **۸.۵. مقایسه سه Loss Function**

| ویژگی                        | MSE    | MAE          | Huber  |
| ---------------------------- | ------ | ------------ | ------ |
| نوع جریمه                    | مربعی  | خطی          | ترکیبی |
| حساسیت به Outlier            | زیاد   | کمتر         | کمتر   |
| Gradient نزدیک صفر           | تدریجی | تقریباً ثابت | تدریجی |
| مشتق‌پذیری در صفر            | بله    | خیر          | بله    |
| پایداری در برابر خطاهای بزرگ | کمتر   | بیشتر        | بیشتر  |

### **۵. رفتار مفهومی Lossها**

نمودار زیر یک نمایش شماتیک از رفتار سه تابع Loss است:

- محور افقی (X): مقدار خطا (Error)
- محور عمودی (Y): مقدار تابع خطا (Loss)

```
Loss
 ^
 |
 |                                  MSE
 |                                 /
 |                               /
 |                            __/
 |                         __/       Huber
 |                      __/         /
 |                   __/           /
 |                __/             /
 |             __/               /
 |          __/                 /
 |       __/                   /  MAE
 |    __/                     /
 |___/_______________________/____________> Error
```

**توضیح رفتار توابع:**

```
MSE:
افزایش مربعی Loss با افزایش مقدار خطا
حساسیت زیاد به خطاهای بزرگ

MAE:
افزایش خطی Loss با افزایش مقدار خطا
مقاومت بیشتر در برابر Outlierها

Huber Loss:
برای خطاهای کوچک، رفتار Quadratic مانند MSE
برای خطاهای بزرگ، رفتار Linear مانند MAE
```

نکته: نمودار صرفاً شماتیک است و مقیاس عددی دقیق توابع را نمایش نمی‌دهد.

### **۸.۶. Gradient Clipping**

در آموزش شبکه‌های عصبی، گاهی Gradientها بسیار بزرگ می‌شوند.

این پدیده می‌تواند باعث ناپایداری آموزش شود و به آن Exploding Gradients می‌گوییم.

Gradient Clipping برای محدود کردن اندازه Gradient استفاده می‌شود.

یکی از روش‌های رایج، Clip by Norm است:

\\[ g\_{\text{clipped}}= g\cdot \min\left(1,\frac{c}{\\|g\\|}\right) \\]

که در آن:

- \\(g\\): Gradient اصلی
- \\(c\\): حداکثر Norm مجاز
- \\(g\_{\text{clipped}}\\): Gradient محدودشده

اگر Norm از آستانه بیشتر باشد، Gradient کوچک می‌شود.

**نکته مهم:** Gradient Clipping با Huber Loss متفاوت است. اولی اندازه Gradient را محدود می‌کند، اما دومی شکل تابع خطا را تغییر می‌دهد. همچنین استفاده از Gradient Clipping به معنی استفاده از MSE نیست؛ این‌ها دو تصمیم مستقل در طراحی آموزش هستند.

### **۸.۷. کدام Loss بهتر است؟**

هیچ تابعی در تمام شرایط بهترین نیست.

- MSE: زمانی که جریمه شدید خطاهای بزرگ مناسب باشد.
- MAE: زمانی که مقاومت در برابر Outlier اهمیت داشته باشد.
- Huber: زمانی که هم Gradient هموار و هم مقاومت در برابر خطاهای بزرگ لازم باشد.

در DQN و بسیاری از پیاده‌سازی‌های آن، Huber Loss انتخاب رایجی است.

## **۹. ارتباط اجزای DQN با یکدیگر**

تا اینجا با چند ابزار مهم آشنا شدیم. حالا باید بدانیم هرکدام دقیقاً کدام مشکل را هدف قرار می‌دهند.

| تکنیک                  | مشکل اصلی                         | راه‌حل                                 |
| ---------------------- | --------------------------------- | -------------------------------------- |
| Target Network         | Non-Stationary Targets            | ثابت نگه داشتن موقت Target             |
| Experience Replay      | Correlated Samples                | نمونه‌برداری تصادفی از تجربه‌های گذشته |
| Larger Networks        | محدودیت ظرفیت تقریب               | افزایش توان مدل‌سازی                   |
| Exploration Strategies | کمبود تجربه از بخش‌های مختلف محیط | بررسی Actionهای متفاوت                 |
| Double DQN             | Overestimation Bias               | جداسازی انتخاب و ارزیابی Action        |
| Huber Loss             | حساسیت به خطاهای بزرگ             | ترکیب جریمه مربعی و خطی                |
| Gradient Clipping      | Exploding Gradients               | محدود کردن اندازه Gradient             |

نکته کلیدی این است که هیچ‌کدام از این تکنیک‌ها به‌تنهایی تمام مشکلات DQN را حل نمی‌کنند. آن‌ها مکمل یکدیگر هستند.

## **۱۰. الگوریتم کامل DQN**

حالا می‌توانیم تمام مفاهیم را در یک الگوریتم ترکیب کنیم.

### **۱۰.۱. مراحل اجرای DQN**

1. ساخت Online Network و Target Network.
2. یکسان‌سازی اولیه پارامترهای دو شبکه.
3. ایجاد Replay Buffer.
4. دریافت State از محیط.
5. انتخاب Action با استفاده از Exploration Strategy.
6. اجرای Action و دریافت Reward و Next State.
7. ذخیره تجربه در Replay Buffer.
8. انتخاب یک Mini-Batch تصادفی از Buffer.
9. محاسبه Target با استفاده از Target Network.
10. محاسبه Loss بین Q پیش‌بینی‌شده و Target.
11. به‌روزرسانی Online Network با Gradient Descent.
12. به‌روزرسانی دوره‌ای Target Network.
13. تکرار فرآیند تا رسیدن به شرایط توقف.

### **۱۰.۲. شبه‌کد DQN**

```
Initialize Online Network Q(s, a; θ)
Initialize Target Network Q(s, a; θ-)

Set θ- = θ
Initialize Replay Buffer D

For each episode:

    Initialize state s

    While episode is not finished:

        # Action Selection
        With probability ε:
            Choose a random action
        Otherwise:
            Choose argmax_a Q(s, a; θ)

        # Environment Interaction
        Execute action a
        Observe reward r, next state s', done

        # Store Experience
        Store (s, a, r, s', done) in D

        # Random Sampling
        Sample a mini-batch from D

        # Compute Targets
        If done:
            y = r
        Otherwise:
            y = r + γ * max_a' Q(s', a'; θ-)

        # Update Online Network
        Compute loss between:
            Q(s, a; θ)
            and
            y

        Update θ using Gradient Descent

        # Update Target Network
        If target update interval is reached:
            θ- = θ

        s = s'

    Decay ε
```

توجه: در این شبه‌کد، Target برای وضعیت پایانی برابر Reward است و نباید مقدار آینده به آن اضافه شود.

### **۱۰.۳. فرمول نهایی Target در DQN**

برای نمایش دقیق‌تر، با در نظر گرفتن وضعیت پایانی:

\\[ y_t = \begin{cases} r\_{t+1} & \text{if terminal}\\\ r\_{t+1}+\gamma\max\_{a'}Q(s\_{t+1},a';\theta^-) & \text{otherwise} \end{cases} \\]

این فرمول، هسته اصلی یادگیری DQN است.

## **۱۱. محدودیت‌های DQN و مسیر توسعه آن**

DQN یک پیشرفت مهم بود، اما همچنان محدودیت‌هایی داشت.

در انتهای فصل و متن ارسالی، به دو مسیر مهم برای بهبود آن اشاره می‌شود.

این دو مفهوم در فصل ۱۰ به‌صورت کامل آموزش داده می‌شوند.

### **۱۱.۱. Dueling Network**

در معماری معمول DQN، شبکه مستقیماً Q-Value هر Action را تخمین می‌زند.

اما یک رابطه مهم بین State Value و Action Value وجود دارد.

\\[ Q(s,a)=V(s)+A(s,a) \\]

که در آن:

- \\(V(s)\\): ارزش کلی قرار گرفتن در State مشخص.
- \\(A(s,a)\\): میزان بهتر یا بدتر بودن یک Action نسبت به سایر Actionها در همان State.

معماری Dueling Network این دو مقدار را جداگانه تخمین می‌زند و سپس آن‌ها را ترکیب می‌کند.

ایده اصلی:

گاهی ارزش خود State مهم است، حتی زمانی که تفاوت بین Actionهای مختلف چندان زیاد نیست.

این معماری به شبکه اجازه می‌دهد State Value و Action Advantage را جداگانه یاد بگیرد.

آموزش اصلی در فصل ۱۰

### **۱۱.۲. Prioritized Experience Replay (PER)**

در Experience Replay معمولی، تجربه‌ها به‌صورت تصادفی انتخاب می‌شوند.

اما تمام تجربه‌ها لزوماً ارزش آموزشی یکسانی ندارند.

برای مثال:

- تجربه‌ای که نتیجه آن کاملاً قابل پیش‌بینی بوده، ممکن است اطلاعات جدید زیادی نداشته باشد.
- تجربه‌ای که اختلاف زیادی بین مقدار پیش‌بینی‌شده و Target داشته، ممکن است اطلاعات مهمی ارائه کند.

Prioritized Experience Replay تلاش می‌کند تجربه‌های مهم‌تر را با احتمال بیشتری برای آموزش انتخاب کند.

یکی از معیارهای مهم برای تعیین اولویت:

**TD Error**

\\[ \delta_i=y_i-Q(s_i,a_i;\theta) \\]

هرچه قدرمطلق TD Error بیشتر باشد، تجربه می‌تواند اولویت بیشتری برای Replay داشته باشد.

البته نمونه‌برداری اولویت‌دار ممکن است Bias ایجاد کند؛ به همین دلیل PER از Importance Sampling Weights برای اصلاح این Bias استفاده می‌کند.

(آموزش اصلی در فصل ۱۰)

### **۱۱.۳. مقایسه DQN و بهبودهای بعدی**

| الگوریتم / تکنیک              | بهبود اصلی                                 |
| ----------------------------- | ------------------------------------------ |
| DQN                           | استفاده از شبکه عصبی برای تخمین Q-Function |
| Double DQN                    | کاهش Overestimation Bias                   |
| Dueling DQN                   | جداسازی State Value و Advantage            |
| Prioritized Experience Replay | انتخاب هوشمندانه‌تر تجربه‌های آموزشی       |

نکته: Double DQN موضوع فصل ۹ است، اما Dueling DQN و PER از مباحث اصلی فصل ۱۰ هستند.

## **۱۲. جمع‌بندی مفهومی فصل ۹**

### **نقشه ارتباط مفاهیم**

```
                 Deep Q-Network (DQN)
                          |
          +---------------+---------------+
          |               |               |
     Online Network  Target Network  Replay Buffer
          |               |               |
     Q Prediction     Stable Targets   Random Sampling
          |               |               |
          +---------------+---------------+
                          |
                    DQN Training
                          |
              +-----------+-----------+
              |                       |
         Overestimation          Training Stability
              |                       |
          Double DQN           Target Network
                                      |
                                Experience Replay

Additional Improvements:
          |
          +---- Dueling Network
          |        |
          |   Value + Advantage
          |
          +---- Prioritized Experience Replay
                   |
              TD Error Priority
```

### **مهم‌ترین روابط ریاضی فصل**

| مفهوم       | فرمول                                                       |
| ----------- | ----------------------------------------------------------- |
| Q-Function  | \\(Q(s,a;\theta)\\)                                         |
| DQN Target  | \\(r+\gamma\max\_{a'}Q(s',a';\theta^-)\\)                   |
| DQN Loss    | \\((y-Q(s,a;\theta))^2\\)                                   |
| Double DQN  | \\(r+\gamma Q(s',\arg\max\_{a'}Q(s',a';\theta);\theta^-)\\) |
| TD Error    | \\(y-Q(s,a;\theta)\\)                                       |
| Hard Update | \\(\theta^- \leftarrow \theta\\)                            |
| Soft Update | \\(\theta^- \leftarrow \tau\theta+(1-\tau)\theta^-\\)       |

### **مفاهیم مهم**

1. DQN از شبکه عصبی برای تقریب Q-Function استفاده می‌کند.
2. IID فرضی است که نمونه‌ها مستقل و دارای توزیع یکسان باشند.
3. داده‌های RL به دلیل تعامل متوالی عامل با محیط، معمولاً IID نیستند.
4. Policy با پیشرفت آموزش تغییر می‌کند و توزیع داده‌ها نیز تغییر می‌کند.
5. Non-Stationary Targets به دلیل وابستگی Target به تخمین‌های در حال تغییر شبکه ایجاد می‌شود.
6. Target Network برای پایدارتر کردن Targetها استفاده می‌شود.
7. Online Network آموزش می‌بیند، اما Target Network برای مدتی ثابت می‌ماند.
8. Experience Replay تجربه‌های گذشته را ذخیره و به‌صورت تصادفی نمونه‌برداری می‌کند.
9. Replay Buffer وابستگی زمانی نمونه‌های آموزشی را کاهش می‌دهد.
10. Epsilon-Greedy بین Exploration و Exploitation تعادل ایجاد می‌کند.
11. DQN ممکن است دچار Overestimation Bias شود.
12. Double DQN انتخاب Action و ارزیابی آن را از یکدیگر جدا می‌کند.
13. Argmax یک Action را برمی‌گرداند، اما Max مقدار بیشینه را.
14. MSE خطاهای بزرگ را به‌صورت مربعی جریمه می‌کند.
15. MAE نسبت به Outlierها مقاوم‌تر است.
16. Huber Loss رفتار MSE و MAE را ترکیب می‌کند.
17. Gradient Clipping برای کنترل Exploding Gradients استفاده می‌شود.
18. Dueling Network و PER از بهبودهای مهم بعدی هستند که در فصل ۱۰ بررسی می‌شوند.

## **۱۳. تفاوت مفاهیم مشابه که نباید اشتباه گرفت**

| مفاهیم                                 | تفاوت                                                           |
| -------------------------------------- | --------------------------------------------------------------- |
| Online Network / Target Network        | اولی آموزش می‌بیند، دومی Target تولید می‌کند.                   |
| DQN / Double DQN                       | Double DQN انتخاب و ارزیابی Action را جدا می‌کند.               |
| Max / Argmax                           | یکی مقدار بیشینه و دیگری Action متناظر را برمی‌گرداند.          |
| Experience Replay / Prioritized Replay | اولی نمونه‌برداری تصادفی، دومی نمونه‌برداری بر اساس اولویت است. |
| MSE / MAE                              | جریمه مربعی در برابر جریمه خطی                                  |
| Huber / Gradient Clipping              | تغییر شکل Loss در برابر محدود کردن Gradient                     |
| Dueling DQN / Double DQN               | اولی معماری شبکه را تغییر می‌دهد، دومی روش محاسبه Target را.    |
| Target Network / Soft Update           | اولی یک شبکه است، دومی یکی از روش‌های به‌روزرسانی آن است.       |
