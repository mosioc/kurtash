# خلاصه جامع فصل پنجم کتاب Grokking Deep Reinforcement Learning

## ۱. بررسی کلی

عنوان رسمی فصل پنجم **Evaluating Agents' Behaviors** است؛ یعنی ارزیابی رفتار عامل‌ها.

هدف اصلی فصل این است که یاد بگیریم چگونه ارزش یک رفتار یا سیاست (Policy) را در محیطی که تابع انتقال (Transition Function) و تابع پاداش (Reward Function) آن را نمی‌شناسیم، تخمین بزنیم.

نکته مهم این است که در این فصل، تمرکز روی **ارزیابی یک Policy ثابت** است، نه بهبود مستقیم آن. بهبود Policy موضوع اصلی فصل ششم است.

# بخش اول: مبانی ارزیابی رفتار عامل‌ها

## ۲. مسئله اصلی فصل: Policy Evaluation

در Reinforcement Learning، عامل باید یاد بگیرد چه تصمیم‌هایی بگیرد تا در بلندمدت بیشترین پاداش را دریافت کند.

اما قبل از اینکه بتوانیم یک Policy را بهبود دهیم، باید بدانیم Policy فعلی چقدر خوب عمل می‌کند.

این مسئله را **Policy Evaluation** یا ارزیابی سیاست می‌نامیم.

فرض کن یک ربات برای حرکت در یک Maze از یک Policy مشخص استفاده می‌کند.

می‌خواهیم بدانیم:

- قرار گرفتن در هر موقعیت چقدر ارزشمند است؟
- اگر ربات در یک State مشخص باشد، در آینده انتظار چه مقدار پاداش دارد؟
- آیا رفتار فعلی ربات در بلندمدت عملکرد مناسبی دارد؟

برای پاسخ به این پرسش‌ها باید Value Function را تخمین بزنیم.

### ۲.۱. Prediction Problem چیست؟

در این فصل، Prediction Problem به معنی تخمین ارزش یک Policy مشخص است.

فرض کن Policy ما ثابت باشد:

\[
\pi(a|s)
\]

یعنی احتمال انتخاب Action مشخصی در State مشخص.

هدف، تخمین تابع ارزش State است:

\[
V^\pi(s) = \mathbb{E}_\pi[G_t|S_t=s]
\]

به زبان ساده:

**Value Function نشان می‌دهد اگر عامل از State مشخصی شروع کند و طبق Policy مشخصی رفتار کند، به‌طور متوسط چه مقدار Return دریافت خواهد کرد.**

در این تعریف سه نکته مهم وجود دارد:

1. Policy مشخص است.
2. محیط می‌تواند تصادفی باشد.
3. ارزش State برابر Expected Return است، نه پاداشی که در یک اجرای خاص دریافت شده است.

### ۲.۲. تفاوت Prediction و Control

| مفهوم | هدف |
| --- | --- |
| Prediction | ارزیابی Policy فعلی |
| Control | پیدا کردن و بهبود Policy برای رسیدن به عملکرد بهتر |

مثال:

- Prediction: آیا مسیر فعلی ربات در Maze مناسب است؟
- Control: چگونه مسیر ربات را تغییر دهیم تا بهتر عمل کند؟

در فصل پنجم عمدتاً با Prediction سروکار داریم.

در فصل ششم وارد Control و روش‌های بهبود Policy می‌شویم.

## ۳. Reward، Return و Value Function

این سه مفهوم از پایه‌های اصلی فصل هستند و نباید با یکدیگر اشتباه گرفته شوند.

### ۳.۱. Reward

Reward پاداشی است که عامل در یک Time Step مشخص از محیط دریافت می‌کند.

\[
R_{t+1}
\]

مثلاً ربات با رسیدن به مقصد ۱۰ امتیاز دریافت می‌کند.

این پاداش مربوط به یک مرحله مشخص است و لزوماً عملکرد بلندمدت عامل را نشان نمی‌دهد.

### ۳.۲. Return

Return مجموع پاداش‌های آینده با در نظر گرفتن Discount Factor است.

\[
G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2R_{t+3} + \cdots
\]

یا به شکل کلی:

\[
G_t=\sum_{k=0}^{\infty}\gamma^kR_{t+k+1}
\]

در این فرمول:

- \(G_t\): بازده از زمان \(t\)
- \(R_{t+k+1}\): پاداش آینده
- \(\gamma\): Discount Factor
- \(k\): فاصله زمانی از پاداش فعلی

در مسائل Episodic، مجموع Return تا پایان Episode محاسبه می‌شود.

### ۳.۳. Discount Factor

Discount Factor یا ضریب تنزیل با نماد Gamma مشخص می‌شود:

\[
0\leq\gamma\leq1
\]

این ضریب مشخص می‌کند پاداش‌های آینده چقدر نسبت به پاداش‌های نزدیک ارزش دارند.

مثلاً فرض کنیم:

- پاداش فعلی: ۱۰
- پاداش مرحله بعد: ۱۰
- Gamma: برابر ۰٫۹

بنابراین:

\[
G_t=10+0.9(10)=19
\]

اگر Gamma برابر ۰٫۵ باشد:

\[
G_t=10+0.5(10)=15
\]

پس هرچه Gamma کوچک‌تر باشد، اهمیت پاداش‌های دورتر کمتر می‌شود.

| Gamma | تفسیر |
| --- | --- |
| 0 | فقط پاداش فوری اهمیت دارد |
| نزدیک 0 | تأکید بر پاداش‌های کوتاه‌مدت |
| نزدیک 1 | اهمیت بیشتر پاداش‌های بلندمدت |
| 1 | بدون تنزیل پاداش‌ها |

در مسائل با افق نامحدود، وجود شرایط مناسب مانند محدود بودن پاداش‌ها و Gamma کمتر از یک برای تضمین همگرایی Return اهمیت دارد.

### ۳.۴. Value Function

Value Function میانگین یا دقیق‌تر، امید ریاضی Return برای یک State و Policy مشخص است.

\[
V^\pi(s)=\mathbb{E}_\pi[G_t|S_t=s]
\]

تفاوت مهم:

- Reward: پاداش یک مرحله.
- Return: مجموع پاداش‌های تنزیل‌شده یک مسیر.
- Value Function: امید ریاضی Return برای یک State تحت یک Policy.

مثال:

فرض کنیم عامل از State مشخصی سه بار شروع کند و Returnهای زیر را دریافت کند:

\[
G_1=10,\quad G_2=20,\quad G_3=30
\]

تخمین ساده Value Function:

\[
V(s)=\frac{10+20+30}{3}=20
\]

یعنی تخمین ارزش این State برابر ۲۰ است.

این مثال نشان می‌دهد چرا Value Function با Return یکسان نیست.

## ۴. Random Walk Environment

در این محیط:

- عامل در یک State قرار دارد.
- با هر حرکت به یکی از Stateهای مجاور می‌رود.
- انتخاب جهت حرکت می‌تواند تصادفی باشد.
- بعضی Stateها Terminal State هستند.
- عامل نمی‌تواند نتیجه دقیق حرکت بعدی را کنترل کند.

### هدف در Random Walk

هدف این نیست که عامل مسیر خاصی را انتخاب کند؛ بلکه باید ارزش Stateهای مختلف را تخمین بزند.

برای مثال، اگر عامل در State میانی قرار بگیرد، ممکن است در آینده به Terminal State سمت چپ یا راست برسد.

بنابراین Return می‌تواند متفاوت باشد.

عامل باید با مشاهده تعداد زیادی تجربه، Expected Return هر State را تخمین بزند.

**نکته کلیدی:** در این محیط، Policy می‌تواند ثابت باشد و حتی بدون انتخاب‌های کنترلی پیچیده، مسئله Policy Evaluation را بررسی کنیم.

# بخش دوم: روش‌های تخمین ارزش Policy

## ۵. Monte Carlo Methods

Monte Carlo (MC) یکی از روش‌های تخمین Value Function است که از تجربه‌های واقعی عامل برای محاسبه Return استفاده می‌کند.

ایده اصلی:

به‌جای اینکه تلاش کنیم تمام احتمالات و قوانین محیط را از قبل بدانیم، اجازه می‌دهیم عامل در محیط تجربه جمع‌آوری کند و سپس از نتایج واقعی برای تخمین ارزش Stateها استفاده کنیم.

### ۵.۱. نحوه عملکرد Monte Carlo

فرض کنیم عامل در یک Maze حرکت می‌کند.

یک Episode شامل مجموعه‌ای از تجربه‌هاست:

\[
S_0,A_0,R_1,S_1,A_1,R_2,\ldots,S_T
\]

عامل تا رسیدن به Terminal State حرکت می‌کند.

سپس Return مربوط به بازدیدهای Stateها را محاسبه می‌کنیم و تخمین Value Function را به‌روزرسانی می‌کنیم.

مراحل کلی:

1. اجرای Policy در محیط.
2. جمع‌آوری یک Episode کامل.
3. محاسبه Return برای Stateهای بازدیدشده.
4. به‌روزرسانی تخمین Value Function.
5. تکرار فرآیند با Episodeهای بیشتر.

ویژگی مهم MC:

Monte Carlo برای به‌روزرسانی معمول خود به پایان Episode نیاز دارد؛ یعنی بعد از مشاهده نتیجه واقعی مسیر، تخمین را اصلاح می‌کند.

### ۵.۲. First-Visit Monte Carlo (FVMC)

First-Visit Monte Carlo فقط اولین باری را در هر Episode در نظر می‌گیرد که عامل از یک State بازدید می‌کند.

فرض کنیم مسیر عامل به این شکل باشد:

\[
A\rightarrow B\rightarrow C\rightarrow B\rightarrow D
\]

در این Episode، عامل دو بار از State مربوط به B بازدید کرده است.

در First-Visit MC فقط Return مربوط به اولین بازدید B استفاده می‌شود.

فرمول تخمین:

\[
V(s)=\frac{1}{N(s)}\sum_{i=1}^{N(s)}G_i(s)
\]

که در آن:

- \(N(s)\): تعداد Episodeهایی که State در آن‌ها حداقل یک بار بازدید شده است.
- \(G_i(s)\): Return مربوط به اولین بازدید از State در Episode شماره \(i\).

مثال:

فرض کنیم در سه Episode، اولین Return مربوط به State برابر باشد با:

\[
10,\quad20,\quad30
\]

پس:

\[
V(s)=\frac{10+20+30}{3}=20
\]

**نکته:** اگر State چند بار در یک Episode بازدید شود، فقط اولین بازدید آن Episode در محاسبه وارد می‌شود.

### ۵.۳. Every-Visit Monte Carlo (EVMC)

Every-Visit Monte Carlo برخلاف First-Visit، تمام بازدیدهای یک State را در هر Episode در نظر می‌گیرد.

برای مثال:

\[
A\rightarrow B\rightarrow C\rightarrow B\rightarrow D
\]

در اینجا هر دو بازدید از B در تخمین ارزش B مشارکت می‌کنند.

فرمول:

\[
V(s)=\frac{1}{N(s)}\sum_{i=1}^{N(s)}G_i(s)
\]

تفاوت این فرمول با First-Visit در تعریف \(N(s)\) و مجموعه Returnهایی است که وارد میانگین می‌شوند:

- در First-Visit، هر Episode حداکثر یک نمونه برای هر State تولید می‌کند.
- در Every-Visit، هر بازدید از State یک نمونه تولید می‌کند.

مثال:

فرض کنیم در یک Episode دو بازدید از B داشته باشیم:

\[
G_1(B)=20
\]

\[
G_2(B)=10
\]

و در Episode بعدی:

\[
G_3(B)=30
\]

بنابراین:

\[
V(B)=\frac{20+10+30}{3}=20
\]

### ۵.۴. نمودار مقایسه First-Visit و Every-Visit

در این مثال، مسیر عامل شامل دو بازدید از B است:

```text
Episode:
A ---> B ---> C ---> B ---> D ---> Terminal
       |                   |
       |                   |
       v                   v
   First Visit         Second Visit
```

رفتار دو روش:

```text
First-Visit MC:
A ---> B ---> C ---> B ---> D
       |
       +---- فقط این بازدید از B استفاده می‌شود


Every-Visit MC:
A ---> B ---> C ---> B ---> D
       |                   |
       +-------------------+
               هر دو بازدید از B استفاده می‌شوند
```

### ۵.۵. تفاوت First-Visit و Every-Visit

| ویژگی | First-Visit MC | Every-Visit MC |
| --- | --- | --- |
| تعداد نمونه در هر Episode | حداکثر یک نمونه برای هر State | تمام بازدیدها |
| معیار انتخاب | اولین بازدید | همه بازدیدها |
| محاسبات | ساده‌تر | نیازمند ثبت تمام بازدیدها |
| همگرایی | دارد | دارد |
| استقلال نمونه‌ها | نمونه‌های هر Episode همچنان ممکن است وابسته باشند | بازدیدهای یک Episode ممکن است هم‌بستگی بیشتری داشته باشند |

یک اصلاح مهم:

اینکه First-Visit همیشه سریع‌تر یا دقیق‌تر از Every-Visit است، درست نیست. هر دو روش با شرایط مناسب و تجربه کافی می‌توانند به Value Function واقعی همگرا شوند. تفاوت اصلی آن‌ها در نحوه نمونه‌گیری و ویژگی‌های آماری تخمین‌هاست.

همچنین Every-Visit لزوماً دقیق‌تر نیست؛ استفاده از تعداد نمونه بیشتر به‌تنهایی تضمین‌کننده دقت بهتر نیست، چون بازدیدهای مختلف یک Episode می‌توانند هم‌بسته باشند.

## ۶. Temporal-Difference Learning (TD)

Temporal-Difference Learning یا یادگیری تفاضل زمانی یکی از مهم‌ترین روش‌های Reinforcement Learning است.

این روش تلاش می‌کند مزایای Monte Carlo و Dynamic Programming را ترکیب کند.

### ۶.۱. مشکل Monte Carlo

Monte Carlo باید تا پایان Episode منتظر بماند.

این موضوع می‌تواند مشکل‌ساز باشد:

- بعضی Episodeها بسیار طولانی هستند.
- گاهی دریافت پاداش زمان زیادی طول می‌کشد.
- عامل باید برای به‌روزرسانی منتظر پایان مسیر بماند.

برای حل این مشکل از Temporal-Difference Learning استفاده می‌کنیم.

### ۶.۲. ایده اصلی TD

در TD، عامل لازم نیست تا پایان Episode صبر کند.

به محض انجام یک گام و مشاهده State بعدی، می‌تواند Value Function را به‌روزرسانی کند.

در واقع TD از دو اطلاعات استفاده می‌کند:

1. Reward واقعی دریافت‌شده.
2. تخمین فعلی ارزش State بعدی.

فرمول به‌روزرسانی:

\[
V(S_t)\leftarrow V(S_t)+\alpha[R_{t+1}+\gamma V(S_{t+1})-V(S_t)]
\]

در این فرمول:

- \(V(S_t)\): ارزش تخمینی State فعلی.
- \(R_{t+1}\): پاداش واقعی مرحله بعد.
- \(V(S_{t+1})\): تخمین ارزش State بعدی.
- \(\gamma\): Discount Factor.
- \(\alpha\): Learning Rate.

### ۶.۳. TD Target

قسمت زیر را در نظر بگیر:

\[
R_{t+1}+\gamma V(S_{t+1})
\]

این مقدار را TD Target می‌نامیم.

یعنی هدف جدیدی که عامل برای تخمین ارزش State فعلی در نظر می‌گیرد.

### ۶.۴. TD Error

اختلاف بین TD Target و تخمین فعلی Value Function را TD Error می‌نامیم.

\[
\delta_t=R_{t+1}+\gamma V(S_{t+1})-V(S_t)
\]

بنابراین:

\[
V(S_t)\leftarrow V(S_t)+\alpha\delta_t
\]

TD Error نشان می‌دهد تخمین فعلی چقدر با هدف جدید اختلاف دارد.

- اگر TD Error مثبت باشد، تخمین ارزش State افزایش می‌یابد.
- اگر منفی باشد، تخمین کاهش می‌یابد.
- اگر صفر باشد، در آن مرحله نیازی به تغییر تخمین نیست.

### ۶.۵. مثال عددی TD

فرض کنیم:

\[
V(S_t)=5
\]

\[
R_{t+1}=2
\]

\[
V(S_{t+1})=8
\]

\[
\gamma=0.9
\]

\[
\alpha=0.1
\]

ابتدا TD Target:

\[
Target=2+0.9(8)=9.2
\]

سپس TD Error:

\[
\delta_t=9.2-5=4.2
\]

حالا Value Function را به‌روزرسانی می‌کنیم:

\[
V(S_t)=5+0.1(4.2)
\]

\[
\boxed{V(S_t)=5.42}
\]

یعنی تخمین ارزش State از ۵ به ۵٫۴۲ افزایش پیدا می‌کند.

### ۶.۶. Bootstrapping چیست؟

یکی از مفاهیم بسیار مهم این فصل Bootstrapping است.

Bootstrapping یعنی استفاده از تخمین‌های فعلی خود عامل برای محاسبه تخمین‌های جدید.

در TD، عامل برای محاسبه Target از ارزش تخمینی State بعدی استفاده می‌کند.

یعنی به‌جای انتظار برای Return واقعی کل Episode، بخشی از محاسبات را با تخمین خودش انجام می‌دهد.

تفاوت:

- Monte Carlo: استفاده از Return واقعی یک Episode کامل.
- TD: استفاده از Reward واقعی و Value Function تخمینی State بعدی.

این ویژگی باعث می‌شود TD بتواند به‌صورت Online و مرحله‌به‌مرحله یاد بگیرد.

## ۷. مقایسه Monte Carlo و Temporal-Difference

این دو روش دو رویکرد اصلی برای تخمین ارزش Policy هستند.

**Monte Carlo:**

1. اجرای Episode
2. انتظار تا پایان Episode
3. محاسبه Return واقعی
4. به‌روزرسانی Value Function

**Temporal-Difference:**

1. اجرای یک گام
2. دریافت Reward و State بعدی
3. محاسبه TD Target با Bootstrapping
4. به‌روزرسانی فوری Value Function

| ویژگی | Monte Carlo | TD |
| --- | --- | --- |
| زمان به‌روزرسانی | پایان Episode | بعد از هر گام |
| Target | Return واقعی | تخمین مبتنی بر Reward و Value |
| Bootstrapping | ندارد | دارد |
| Bias | Target نمونه‌ای Return تحت شرایط مناسب بدون Bias است | Target مبتنی بر تخمین ممکن است Bias داشته باشد |
| Variance | معمولاً بیشتر | معمولاً کمتر |
| Episode کامل | برای روش استاندارد لازم است | لازم نیست |

### ۷.۱. Bias و Variance

این دو مفهوم برای درک تفاوت الگوریتم‌ها ضروری هستند.

**Bias (سوگیری):**

یعنی تخمین الگوریتم به‌طور سیستماتیک از مقدار واقعی فاصله داشته باشد.

**Variance (واریانس):**

یعنی تخمین‌ها در تجربه‌های مختلف چقدر پراکندگی دارند.

برای مثال، فرض کن ارزش واقعی یک State برابر ۲۰ باشد.

الگوریتم اول این تخمین‌ها را تولید می‌کند:

\[
19,\quad21,\quad20,\quad20
\]

الگوریتم دوم:

\[
10,\quad30,\quad15,\quad25
\]

هر دو ممکن است میانگین مناسبی داشته باشند، اما الگوریتم دوم Variance بیشتری دارد.

به‌طور کلی:

- MC از Return واقعی استفاده می‌کند و در شرایط استاندارد Target آن بدون Bias است، اما Variance آن می‌تواند زیاد باشد.
- TD از تخمین‌های قبلی استفاده می‌کند؛ در نتیجه ممکن است Bias داشته باشد، اما معمولاً Variance کمتری دارد.

این همان Trade-off مهمی است که روش‌های بخش بعدی تلاش می‌کنند مدیریت کنند.

# بخش سوم: روش‌های ترکیبی و چندمرحله‌ای

## ۸. N-Step Temporal-Difference Learning

تا اینجا دو روش را بررسی کردیم:

- Monte Carlo: استفاده از کل Episode.
- TD: استفاده از یک گام.

اما آیا می‌توانیم به‌جای یک گام، چند گام آینده را بررسی کنیم؟

بله. این ایده اساس N-Step TD است.

### ۸.۱. مفهوم N-Step TD

در N-Step TD، عامل به‌جای استفاده از فقط یک Reward یا کل Episode، از N گام آینده استفاده می‌کند.

مثلاً:

- 1-Step TD: یک گام آینده.
- 2-Step TD: دو گام آینده.
- 3-Step TD: سه گام آینده.
- N-Step TD: تعداد مشخصی از گام‌های آینده.

بعد از N گام، عامل از Value Function تخمینی State بعدی برای ادامه محاسبه استفاده می‌کند.

### ۸.۲. ساختار N-Step TD

نمودار زیر نشان می‌دهد که N-Step TD چگونه چند پاداش واقعی را دریافت می‌کند و سپس با استفاده از Value Function تخمینی، محاسبه را ادامه می‌دهد:

```text
S_t
 |
 | R_(t+1)
 v
S_(t+1)
 |
 | R_(t+2)
 v
S_(t+2)
 |
 | ...
 v
S_(t+n)
 |
 +---- Bootstrap: gamma^n * V(S_(t+n))
```

ساختار Target:

```text
N-Step Target
     |
     +---- R_(t+1)
     |
     +---- gamma * R_(t+2)
     |
     +---- ...
     |
     +---- gamma^(n-1) * R_(t+n)
     |
     +---- gamma^n * V(S_(t+n))
```

### ۸.۳. فرمول N-Step Return

\[
G_{t:t+n}=
R_{t+1}+\gamma R_{t+2}
+\cdots+\gamma^{n-1}R_{t+n}
+\gamma^nV(S_{t+n})
\]

این فرمول از دو قسمت تشکیل شده است:

1. مجموع Rewardهای واقعی در N گام آینده.
2. تخمین ارزش State بعد از N گام.

قسمت دوم همان Bootstrapping است.

### ۸.۴. مثال عددی N-Step TD

فرض کنیم:

\[
R_{t+1}=2
\]

\[
R_{t+2}=3
\]

\[
R_{t+3}=4
\]

\[
V(S_{t+3})=10
\]

و:

\[
\gamma=0.9
\]

در این حالت N برابر ۳ است:

\[
G_{t:t+3}=2+0.9(3)+0.9^2(4)+0.9^3(10)
\]

\[
=2+2.7+3.24+7.29
\]

\[
\boxed{G_{t:t+3}=15.23}
\]

این مقدار Target جدید برای به‌روزرسانی ارزش State اولیه است.

### ۸.۵. رابطه N با Monte Carlo و TD

این رابطه یکی از مهم‌ترین مفاهیم فصل است.

```text
1-Step TD                  N-Step TD                 Monte Carlo
    |                          |                          |
    v                          v                          v
1 Reward واقعی          N Reward واقعی             تمام Rewardهای
+ تخمین آینده           + تخمین آینده               واقعی تا پایان Episode
    |                          |                          |
    v                          v                          v
Bootstrapping زیاد      روش میانی                  بدون Bootstrapping
    |                          |                          |
    +--------------------------+--------------------------+
                               |
                               v
                   Increasing N moves TD
                    closer to Monte Carlo
```

**طیف N-Step TD**

**1-Step TD**

- Bootstrapping زیاد
- استفاده از یک Reward واقعی و یک تخمین آینده

**N-Step TD**

- روش میانی
- استفاده از چند Reward واقعی و یک تخمین آینده

**Monte Carlo**

- بدون Bootstrapping
- استفاده از Return واقعی تا پایان Episode

**نتیجه:**

هرچه N افزایش پیدا کند، N-Step TD به Monte Carlo نزدیک‌تر می‌شود.

در مقابل، هرچه N کوچک‌تر باشد، روش به 1-Step TD نزدیک‌تر است.

هرچه N افزایش پیدا کند:

- Rewardهای واقعی بیشتری وارد Target می‌شوند.
- وابستگی به تخمین Value Function کمتر می‌شود.
- روش به Monte Carlo نزدیک‌تر می‌شود.
- برای دریافت اطلاعات لازم ممکن است انتظار بیشتری نیاز باشد.

در انتخاب N مقدار بهینه و ثابتی برای تمام محیط‌ها وجود ندارد و باید با توجه به مسئله آزمایش شود.

### ۸.۶. برخورد با Terminal State

اگر عامل قبل از رسیدن به N گام به Terminal State برسد، دیگر نمی‌توانیم از Value Function یک State بعدی استفاده کنیم.

در نتیجه Target به شکل زیر محاسبه می‌شود:

\[
G_{t:T}=\sum_{k=0}^{T-t-1}\gamma^kR_{t+k+1}
\]

یعنی مجموع Rewardهای باقی‌مانده تا پایان Episode.

بنابراین در Terminal State واقعی، مقدار آینده پس از پایان Episode صفر در نظر گرفته می‌شود و جمله Bootstrapping حذف می‌شود.

## ۹. Forward-View TD(λ)

این بخش یکی از موضوعات مهم فصل است.

تا اینجا دیدیم که N-Step TD با یک مقدار مشخص N کار می‌کند.

اما اگر بخواهیم از اطلاعات چندین N مختلف استفاده کنیم چه اتفاقی می‌افتد؟

اینجاست که Forward-View TD(λ) وارد می‌شود.

### ۹.۱. ایده اصلی

به‌جای انتخاب فقط یک N، می‌توانیم Returnهای حاصل از N-Step TD را با وزن‌های مختلف ترکیب کنیم.

برای مثال:

- 1-Step Return
- 2-Step Return
- 3-Step Return
- ...
- Monte Carlo Return

Forward-View TD(λ) این Returnها را ترکیب می‌کند تا تخمین جدیدی بسازد.

### ۹.۲. Lambda چیست؟

Lambda با نماد زیر نمایش داده می‌شود:

\[
0\leq\lambda\leq1
\]

این پارامتر مشخص می‌کند وزن Returnهای با افق زمانی مختلف چقدر باشد.

به زبان ساده:

- Lambda نزدیک صفر: تأکید بر Returnهای کوتاه‌مدت.
- Lambda نزدیک یک: تأکید بیشتر بر Returnهای بلندمدت.

### ۹.۳. Lambda-Return

فرمول Lambda-Return در حالت افق نامحدود به شکل زیر است:

\[
G_t^\lambda=(1-\lambda)\sum_{n=1}^{\infty}\lambda^{n-1}G_{t:t+n}
\]

این فرمول ترکیبی وزنی از N-Step Returnهاست.

در محیط‌هایی با Episode محدود، برای لحاظ کردن پایان Episode، تعریف دقیق به شکل زیر نوشته می‌شود:

\[
G_t^\lambda=
(1-\lambda)\sum_{n=1}^{T-t-1}\lambda^{n-1}G_{t:t+n}
+\lambda^{T-t-1}G_t
\]

که \(G_t\) همان Monte Carlo Return کامل است.

نکته مهم: مجموع وزن‌ها برابر یک است.

بنابراین Lambda-Return در واقع ترکیبی از تخمین‌های کوتاه‌مدت، میان‌مدت و بلندمدت است.

### ۹.۴. نقش Lambda در ترکیب روش‌ها

| مقدار Lambda | رفتار |
| --- | --- |
| 0 | معادل 1-Step TD |
| نزدیک 0 | تأکید بر TD کوتاه‌مدت |
| مقادیر میانی | ترکیب چند N-Step Return |
| نزدیک 1 | تأکید بر Returnهای بلندمدت |
| 1 | معادل Monte Carlo در تعریف Episodic مناسب |

این رابطه برای Forward View با شرایط و تعریف مناسب برقرار است.

## ۱۰. TD(λ) و Eligibility Traces

این بخش روش دیگری برای پیاده‌سازی ایده TD(λ) است.

در Forward View، ابتدا Returnهای مختلف را ترکیب می‌کنیم.

اما TD(λ) با استفاده از ساختاری به نام Eligibility Traces، امکان به‌روزرسانی Stateهای قبلی را در حین حرکت عامل فراهم می‌کند.

### ۱۰.۱. Eligibility Trace چیست؟

Eligibility Trace یا رد شایستگی را می‌توان نوعی حافظه کوتاه‌مدت برای Stateهای اخیراً بازدیدشده در نظر گرفت.

فرض کن یک ربات در Maze حرکت می‌کند:

\[
A\rightarrow B\rightarrow C\rightarrow D
\]

وقتی ربات در D قرار دارد، ممکن است بخشی از پاداشی که دریافت کرده، نتیجه تصمیم‌هایی باشد که در A، B و C گرفته است.

اگر فقط State فعلی را به‌روزرسانی کنیم، اطلاعات مربوط به Stateهای قبلی به‌صورت مستقیم در همان مرحله به آن‌ها منتقل نمی‌شود.

Eligibility Traces این مشکل را حل می‌کند.

یعنی به Stateهایی که اخیراً بازدید شده‌اند، میزان مشخصی اعتبار یا Eligibility اختصاص می‌دهد تا بتوانند از TD Error فعلی تأثیر بگیرند.

### ۱۰.۲. نحوه عملکرد Eligibility Traces

هر State یک Eligibility مقدار دارد.

وقتی عامل وارد State جدیدی می‌شود:

- Eligibility آن State افزایش پیدا می‌کند.
- Eligibility مربوط به Stateهای قبلی کاهش پیدا می‌کند.
- TD Error در به‌روزرسانی ارزش Stateها با Eligibility آن‌ها ترکیب می‌شود.

به این ترتیب، اثر تجربه‌های اخیر به Stateهای قبلی نیز منتقل می‌شود.

### ۱۰.۳. نمودار انتشار Eligibility Trace

نمودار زیر نشان می‌دهد که با گذشت زمان، Eligibility یک State بازدیدشده کاهش پیدا می‌کند:

```text
State visited
     |
     v
Eligibility = 1.0
     |
     | Multiply by gamma * lambda
     v
Eligibility = 0.72
     |
     | Multiply by gamma * lambda
     v
Eligibility = 0.52
     |
     | Multiply by gamma * lambda
     v
Eligibility = 0.37
```

نمایش زمانی:

```text
Time:       t       t+1      t+2      t+3
             |        |        |        |
Trace:      1.00     0.72     0.52     0.37
```

اعداد مثال فرضی‌اند و با فرض زیر محاسبه شده‌اند:

\[
\gamma\lambda=0.72
\]

### ۱۰.۴. فرمول Eligibility Trace

در نسخه Accumulating Traces، فرمول به‌روزرسانی به شکل زیر است:

\[
e_t(s)=\gamma\lambda e_{t-1}(s)+\mathbb{1}(S_t=s)
\]

که \(\mathbb{1}(S_t=s)\) تابع Indicator است:

- اگر State موردنظر همان State فعلی باشد، مقدار آن ۱ است.
- در غیر این صورت، مقدار آن صفر است.

دو پارامتر مهم در این فرمول:

- Gamma: Discount Factor
- Lambda: Trace-Decay Parameter

هرچه State از زمان بازدیدش فاصله بگیرد، Eligibility آن کمتر می‌شود؛ مگر اینکه دوباره بازدید شود و مقدار Trace آن افزایش پیدا کند.

### ۱۰.۵. فرمول به‌روزرسانی TD(λ)

\[
V(s)\leftarrow V(s)+\alpha\delta_t e_t(s)
\]

در این فرمول:

- \(\alpha\): Learning Rate
- \(\delta_t\): TD Error
- \(e_t(s)\): Eligibility Trace مربوط به State

این فرمول نشان می‌دهد TD Error فعلی چگونه روی Stateهای مختلف اثر می‌گذارد.

Stateهایی که Eligibility بیشتری دارند، تغییر بیشتری در Value Function تجربه می‌کنند.

### ۱۰.۶. مثال مفهومی

فرض کنیم عامل در چهار State حرکت کرده است:

\[
A\rightarrow B\rightarrow C\rightarrow D
\]

مقادیر Eligibility به‌صورت فرضی:

| State | Eligibility |
| --- | --- |
| A | 0.2 |
| B | 0.4 |
| C | 0.7 |
| D | 1.0 |

اگر TD Error برابر ۲ باشد و Learning Rate برابر ۰٫۱ باشد:

برای A:

\[
\Delta V(A)=0.1(2)(0.2)=0.04
\]

برای B:

\[
\Delta V(B)=0.1(2)(0.4)=0.08
\]

برای C:

\[
\Delta V(C)=0.1(2)(0.7)=0.14
\]

برای D:

\[
\Delta V(D)=0.1(2)(1)=0.2
\]

بنابراین Stateهای مختلف متناسب با Eligibility خود به‌روزرسانی می‌شوند.

اعداد این مثال صرفاً برای نمایش نحوه محاسبه هستند و خروجی یک اجرای واقعی از الگوریتم نیستند.

### ۱۰.۷. رابطه Lambda با TD و Monte Carlo در TD(λ)

این موضوع یکی از نکات مهم امتحانی فصل است.

**وقتی Lambda برابر صفر باشد:**

\[
\lambda=0
\]

در این حالت:

\[
e_t(s)=\mathbb{1}(S_t=s)
\]

بنابراین فقط State فعلی به‌روزرسانی می‌شود.

در نتیجه TD(λ) به 1-Step TD تبدیل می‌شود.

**وقتی Lambda برابر یک باشد:**

\[
\lambda=1
\]

ردهای شایستگی با سرعت کمتری محو می‌شوند و تأثیر Stateهای قبلی بیشتر حفظ می‌شود.

در روش‌های استاندارد با شرایط مناسب و به‌روزرسانی‌های Episodic، TD(1) با Monte Carlo از نظر Targetهای نهایی ارتباط پیدا می‌کند؛ اما این دو از نظر زمان‌بندی و نحوه به‌روزرسانی لزوماً یکسان نیستند.

### ۱۰.۸. Forward View و Backward View

این دو روش، دو شیوه متفاوت برای بیان و محاسبه ایده TD(λ) هستند.

```text
Forward View:
Current State
     |
     v
Calculate different N-Step Returns
     |
     v
Weighted Average using Lambda
     |
     v
Lambda-Return
     |
     v
Update Value Function


Backward View:
Current State
     |
     v
Update Eligibility Traces
     |
     v
Calculate TD Error
     |
     v
Update previously visited States
     |
     v
Update Value Function
```

| ویژگی | Forward View | Backward View |
| --- | --- | --- |
| روش محاسبه | ترکیب N-Step Returnها | استفاده از Eligibility Traces |
| اطلاعات | Returnهای آینده | TD Error و حافظه Stateهای قبلی |
| جهت نگاه | آینده | گذشته |
| کاربرد | توضیح Lambda-Return | به‌روزرسانی مرحله‌به‌مرحله |

نکته کلیدی این است که Forward View و Backward View دو روش متفاوت برای بیان ایده TD(λ) هستند.

در شرایط مناسب، از نظر محاسباتی معادل‌اند؛ اما Backward View برای یادگیری آنلاین بسیار کاربردی‌تر است.

# بخش چهارم: نکات تکمیلی و جزئیات الگوریتم‌ها

## ۱۱. Learning Rate و Decay Schedule

در الگوریتم‌های این فصل، پارامتر Learning Rate با نماد Alpha مشخص می‌شود.

\[
0<\alpha\leq1
\]

Learning Rate تعیین می‌کند تخمین فعلی با چه شدتی به سمت Target جدید حرکت کند.

برای مثال:

- Alpha بزرگ: تغییر سریع‌تر Value Function.
- Alpha کوچک: تغییر تدریجی‌تر Value Function.

### ۱۱.۱. Learning Rate Decay

در ابتدای آموزش، ممکن است تخمین‌های Value Function بسیار نادرست باشند؛ بنابراین Learning Rate بزرگ می‌تواند مفید باشد.

اما پس از جمع‌آوری تجربه بیشتر، کاهش Learning Rate به تثبیت تخمین‌ها کمک می‌کند.

یک نمونه از Decay Schedule:

\[
\alpha_k=\frac{1}{k}
\]

که در آن \(k\) تعداد به‌روزرسانی‌ها یا شاخص مرحله آموزش است.

البته این تنها یک نمونه است و انتخاب Schedule مناسب به الگوریتم و شرایط همگرایی بستگی دارد.

نکته: کاهش Learning Rate به‌تنهایی تضمین نمی‌کند الگوریتم حتماً همگرا شود.

## ۱۲. Time-Step Limit و Terminal State

در محیط‌های واقعی، گاهی عامل محدودیت زمانی یا محدودیت تعداد گام دارد.

برای مثال:

- ربات باید مأموریت را در ۱۰۰ گام تمام کند.
- عامل بازی فقط زمان محدودی برای تصمیم‌گیری دارد.
- یک Episode به دلیل محدودیت محاسباتی متوقف می‌شود.

این محدودیت‌ها روی محاسبه Return و Target تأثیر می‌گذارند.

### تفاوت Terminal و Truncation

این دو مفهوم نباید با هم اشتباه شوند.

**Terminal State:**

یعنی Episode واقعاً به پایان رسیده است.

در این حالت، مقدار آینده پس از پایان Episode برابر صفر است.

**Truncation:**

یعنی اجرای Episode به دلیل یک محدودیت خارجی متوقف شده است، اما محیط الزاماً به یک Terminal State واقعی نرسیده است.

در این حالت، اگر قرار باشد تخمین ارزش ادامه مسیر را حفظ کنیم، باید از Value Function حالت نهایی استفاده کنیم.

برای N-Step TD:

\[
G_{t:t+n}=
\sum_{k=0}^{n-1}\gamma^kR_{t+k+1}
+\gamma^nV(S_{t+n})
\]

اگر به Terminal State واقعی برسیم، جمله آخر حذف می‌شود.

اما در Truncation، حذف آن ممکن است باعث تخمین اشتباه Return شود.

## ۱۳. تفاوت الگوریتم‌های اصلی فصل

این جدول یکی از مهم‌ترین بخش‌های مرور فصل است.

| الگوریتم | تعداد گام | زمان به‌روزرسانی | Bootstrapping |
| --- | --- | --- | --- |
| First-Visit MC | کل Episode | پایان Episode | خیر |
| Every-Visit MC | کل Episode | پایان Episode | خیر |
| 1-Step TD | یک گام | بعد از هر گام | بله |
| N-Step TD | N گام | پس از فراهم شدن اطلاعات N گام | بله |
| Forward-View TD(λ) | ترکیبی از Nها | پس از محاسبه Lambda-Return | معمولاً بله |
| TD(λ) با Eligibility Traces | چندین State با Trace | بعد از هر گام | بله |

## ۱۴. ارتباط تمام مفاهیم فصل پنجم

این نقشه نشان می‌دهد تمام الگوریتم‌های فصل چگونه از یک مسئله اصلی به وجود می‌آیند.

```text
                    POLICY EVALUATION
               تخمین ارزش یک Policy ثابت
                           |
                           v
                  VALUE FUNCTION
              Vπ(s) = Eπ[G_t | S_t = s]
                           |
             +-------------+-------------+
             |                           |
             v                           v
       MONTE CARLO              TEMPORAL DIFFERENCE
       Return واقعی               Bootstrapping
             |                           |
       +-----+-----+                     v
       |           |                 1-Step TD
       v           v                     |
  First-Visit  Every-Visit               v
       |           |                 N-Step TD
       |           |                     |
       +-----+-----+                     |
             |                           |
             v                           v
       استفاده از تجربه            TD(λ)
          کامل Episode                 |
                              +--------+--------+
                              |                 |
                              v                 v
                         Forward View      Backward View
                              |                 |
                              v                 v
                        Lambda-Return    Eligibility Traces
                              |                 |
                              +--------+--------+
                                       |
                                       v
                              Value Function Update
```

```text
**Policy Evaluation**

- تخمین ارزش یک Policy ثابت

    ↓

**Value Function Estimation**

Vπ(s) = Eπ[G_t | S_t = s]

    ↓

**Monte Carlo**

- استفاده از Return واقعی
- First-Visit MC
- Every-Visit MC

    ↓

**Temporal Difference**

- استفاده از Bootstrapping
- 1-Step TD
- N-Step TD

    ↓

**TD(λ)**

- ترکیب N-Step Returnها با Lambda
- Forward View
- Eligibility Traces
```

**نتیجه:**

این الگوریتم‌ها روش‌های مختلفی برای تخمین Value Function هستند.

ارتباط منطقی آن‌ها:

1. ابتدا باید بتوانیم ارزش یک Policy را تخمین بزنیم.
2. Monte Carlo از Return واقعی برای تخمین استفاده می‌کند.
3. TD با استفاده از Bootstrapping امکان یادگیری مرحله‌به‌مرحله را فراهم می‌کند.
4. N-Step TD فاصله میان Monte Carlo و TD را پر می‌کند.
5. TD(λ) از ترکیب Returnهای مختلف یا Eligibility Traces برای استفاده از اطلاعات چندین گام بهره می‌برد.

## ۱۸. فرمول‌های اصلی فصل

این فرمول‌ها مهم‌ترین مواردی هستند که شخص باید توان توضیح و استفاده از آن‌ها را داشته باشد.

**۱. Return**

\[
G_t=\sum_{k=0}^{\infty}\gamma^kR_{t+k+1}
\]

**۲. Value Function**

\[
V^\pi(s)=\mathbb{E}_\pi[G_t|S_t=s]
\]

**۳. TD Target**

\[
R_{t+1}+\gamma V(S_{t+1})
\]

**۴. TD Error**

\[
\delta_t=R_{t+1}+\gamma V(S_{t+1})-V(S_t)
\]

**۵. TD Update**

\[
V(S_t)\leftarrow V(S_t)+\alpha\delta_t
\]

**۶. N-Step Return**

\[
G_{t:t+n}=
\sum_{k=0}^{n-1}\gamma^kR_{t+k+1}
+\gamma^nV(S_{t+n})
\]

**۷. Lambda-Return**

\[
G_t^\lambda=
(1-\lambda)\sum_{n=1}^{\infty}\lambda^{n-1}G_{t:t+n}
\]

**۸. Eligibility Trace**

\[
e_t(s)=\gamma\lambda e_{t-1}(s)+\mathbb{1}(S_t=s)
\]

**۹. TD(λ) Update**

\[
V(s)\leftarrow V(s)+\alpha\delta_te_t(s)
\]

## ۱۹. سوالات مهم

1. چرا قبل از بهبود یک Policy باید آن را ارزیابی کنیم؟
2. تفاوت Reward، Return و Value Function چیست؟
3. چرا Monte Carlo باید تا پایان Episode صبر کند؟
4. تفاوت First-Visit MC و Every-Visit MC چیست؟
5. چرا Every-Visit لزوماً از First-Visit دقیق‌تر نیست؟
6. Temporal-Difference چگونه بدون انتظار برای پایان Episode یاد می‌گیرد؟
7. Bootstrapping چیست و چه نقشی در TD دارد؟
8. TD Target و TD Error چه تفاوتی دارند؟
9. چرا TD معمولاً Variance کمتری نسبت به MC دارد؟
10. چگونه N-Step TD میان MC و TD قرار می‌گیرد؟
11. Lambda چه تأثیری بر Returnهای مختلف دارد؟
12. Forward-View TD(λ) چگونه از N-Step Returnها استفاده می‌کند؟
13. Eligibility Traces چه مشکلی را حل می‌کنند؟
14. چرا Lambda برابر صفر در TD(λ) به 1-Step TD منجر می‌شود؟
15. چرا Lambda برابر یک به Monte Carlo نزدیک می‌شود؟
16. تفاوت Forward View و Backward View چیست؟
17. تفاوت Terminal State و Truncation چیست؟

# ۲۰. جمع‌بندی نهایی فصل پنجم

## مهم‌ترین ایده فصل

مسئله اصلی فصل پنجم این است که چگونه ارزش رفتار یک عامل را بدون دانستن مدل کامل محیط تخمین بزنیم.

سه رویکرد اصلی داریم:

**Monte Carlo:** از نتایج واقعی Episode برای تخمین ارزش استفاده می‌کند.

**Temporal-Difference:** از Reward واقعی و تخمین ارزش State بعدی برای به‌روزرسانی استفاده می‌کند.

**TD(λ):** اطلاعات چندین گام را با کمک Lambda و Eligibility Traces ترکیب می‌کند.

در واقع، فصل پنجم به این سؤال پاسخ می‌دهد:

**How good is the agent's current behavior?**

یعنی رفتار فعلی عامل چقدر خوب است؟

و پاسخ آن را با تخمین Value Function و الگوریتم‌های مختلف Policy Evaluation به دست می‌آوریم.

**نکته نهایی:** فصل پنجم را می‌توان پایه ورود به الگوریتم‌های Control دانست. در این فصل یاد می‌گیریم ارزش رفتار فعلی را تخمین بزنیم؛ در فصل ششم از این تخمین‌ها برای بهتر کردن رفتار عامل استفاده خواهیم کرد.
