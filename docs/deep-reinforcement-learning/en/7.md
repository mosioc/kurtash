# Part One: Making Better Use of Experiences

## 2. Why Do We Need Better Methods for Policy Evaluation?

In previous chapters, we became familiar with the following algorithms:

- Monte Carlo
- TD Learning
- N-Step TD
- SARSA
- Q-Learning

One of the problems with common methods is that information related to a delayed reward may be transferred slowly to previous states and state-action pairs.

For example, suppose the agent makes 10 moves in a game and only reaches the goal and receives a reward on the tenth move.

```
S1 → S2 → S3 → S4 → ... → S10 → Goal
                                      |
                                   Reward +10
```

If we use the one-step TD method, the reward information is first transferred only to the previous state, and then in subsequent steps it reaches earlier states.

This process may require a large number of updates.

**Goal of the methods in this chapter:** Transfer reward information more effectively to previous states and actions, without having to wait until the end of the episode for each update.

## 3. On-Policy and Off-Policy

Before examining the algorithms in this chapter, we need to know the difference between these two concepts.

### 3.1. On-Policy Learning

In the on-policy method, the agent learns the behavior and value of the same policy that it uses to interact with the environment.

In other words:

- The policy used to select actions is the same policy being evaluated and improved.
- The agent learns from experiences produced by its own behavior policy.

Examples: SARSA and SARSA(λ).

### 3.2. Off-Policy Learning

In the off-policy method, the policy used to collect experience can be different from the policy used for learning.

We have two important policies:

- Behavior Policy: the policy with which the agent selects actions.
- Target Policy: the policy whose value the agent wants to learn or toward which it wants to improve.

Examples: Q-Learning and Watkins's Q(λ).

### Comparison

| Feature | On-Policy | Off-Policy |
| --- | --- | --- |
| Behavior Policy | Same as Target Policy | Can be different |
| Learning | From the current policy's behavior | More independent of current behavior |
| Example algorithm | SARSA | Q-Learning |
| Extended example | SARSA(λ) | Watkins's Q(λ) |

Important note: Off-policy does not mean the agent behaves without a policy. It means the behavior used to collect experience is distinct from the policy being learned.

## 4. λ-Return

Key concept of the chapter

λ-Return is a method for combining information from different multi-step returns.

To understand it, we must first know three concepts:

### 4.1. One-Step Return

In one-step TD, we consider only the reward of one future step and then use the value estimate in the next state.

$$
G_t^{(1)} = R_{t+1} + \gamma V(S_{t+1})
$$

Features:

- One real reward.
- One estimate of the future.
- Uses bootstrapping.
- Fast update, but dependent on the value estimate of the next step.

### 4.2. N-Step Return

In N-step TD, instead of one reward, we consider several consecutive rewards and then use the estimated value of the final state.

$$
G_t^{(n)} = \sum_{k=1}^{n} \gamma^{k-1} R_{t+k} + \gamma^n V(S_{t+n})
$$

Features:

- Uses several real rewards.
- Uses a value estimate at the end of the range.
- Transfers information in several steps.
- Reduces dependence on nearby estimates.

### 4.3. Monte Carlo Return

In Monte Carlo, the actual return is calculated until the end of the episode.

$$
G_t = \sum_{k=1}^{T-t} \gamma^{k-1} R_{t+k}
$$

Features:

- Uses real rewards until the end of the episode.
- No bootstrapping.
- Requires observing the rest of the episode until its end.
- Usually has more variance than TD methods.

### 4.4. Main Idea of λ-Return

Instead of choosing only one N-step return, we can combine different multi-step returns with specific weights.

$$
G_t^\lambda = (1-\lambda) \sum_{n=1}^{\infty} \lambda^{n-1} G_t^{(n)}
$$

This formula is a conceptual form for continuing episodes. In finite episodes, the appropriate version must be calculated by considering the end of the episode.

The parameter λ is between zero and one:

$$
0 \leq \lambda \leq 1
$$

- λ close to zero: more weight to short-term returns.
- λ close to one: more weight to long-term returns.

As a result, λ allows control over how much future information is used.

### Behavior of λ in the Two Limiting Cases

| Value of λ | Behavior |
| --- | --- |
| λ = 0 | Equivalent to one-step TD |
| λ → 1 | Approaching Monte Carlo |

**Conceptual spectrum of λ-Return**

```
λ = 0                                      λ = 1
  |------------------------------------------|
  v                                          v
One-Step TD                              Monte Carlo

       λ increases  →
       The share of longer multi-step returns increases.
```

**Note:**

- λ = 0 → equivalent to one-step TD
- λ = 1 → equivalent to Monte Carlo (in the episodic case and under appropriate conditions)

**Important note:** λ is not the same as the learning rate.

- α (Alpha): the amount of change in value at each update.
- γ (Gamma): the importance of future rewards.
- λ (Lambda): the importance of different multi-step returns.

## 5. Eligibility Traces

Key concept of the chapter

Eligibility traces are a mechanism for keeping information about states or state-action pairs that the agent has recently visited.

The purpose of this mechanism is to determine, when a TD Error is received, which previous states or actions should participate in updating the value function.

In simple terms, an eligibility trace is a kind of short-term memory of the agent's experiences.

### 5.1. Why Are Eligibility Traces Important?

Suppose the agent follows the path below in a game:

```
S1 → S2 → S3 → S4 → S5 → Goal
                                  |
                               Reward +10
```

When the agent reaches the goal, the reward information must be transferred to previous experiences.

Without eligibility traces, the one-step TD method transfers information gradually.

But with eligibility traces, previous states still have a trace of their presence and can be updated when the TD Error is received.

### 5.2. Two Types of Eligibility Traces

The two main types examined in this chapter:

1. Accumulating traces
2. Replacing traces

### 5.3. Accumulating Traces

In this method, each time the agent visits a state or state-action pair, its eligibility value increases.

$$
e_t(s,a) =
\begin{cases}
\gamma\lambda e_{t-1}(s,a) + 1 & (s,a) = (S_t,A_t) \\
\gamma\lambda e_{t-1}(s,a) & \text{otherwise}
\end{cases}
$$

That is:

- With each visit, the trace value increases.
- Old traces gradually decrease.
- Repeated visits increase the importance of that state-action pair.

**Example:**

Suppose the agent visits a specific state-action pair several times.

```
Visit 1 → Eligibility = 1
Visit 2 → Eligibility = 1 + γλ
Visit 3 → Eligibility = 1 + γλ + (γλ)²
```

As a result, the eligibility value can exceed 1.

Advantage: the number of visits also plays a role in the amount of influence of the experience.

Limitation: if the agent repeats a state-action pair many times in a loop, its eligibility value may increase excessively.

### 5.4. Replacing Traces

In this method, when a state-action pair is revisited, its trace value is set to 1 instead of being added to the previous value.

$$
e_t(s,a) =
\begin{cases}
1 & (s,a) = (S_t,A_t) \\
\gamma\lambda e_{t-1}(s,a) & \text{otherwise}
\end{cases}
$$

Features:

- The trace value of the current pair becomes 1.
- The traces of other pairs decrease.
- Repeated visits do not cause the trace value to accumulate.
- The trace value does not exceed 1.

### 5.5. Comparison of Accumulating and Replacing Traces

| Feature | Accumulating | Replacing |
| --- | --- | --- |
| Revisit | Value increases | Reset to 1 |
| Maximum value | May exceed 1 | At most 1 |
| Effect of repetition | Stronger | Does not accumulate |
| Behavior in a loop | Risk of excessive accumulation | More controlled |
| Importance of frequency | Greater | Lesser |

### Conceptual Example: Frequency versus Recency

Suppose the agent repeatedly follows a repeated path in an environment but eventually experiences a new state that leads to receiving a reward.

- Accumulating traces give more importance to repeated past visits.
- Replacing traces do not allow a state-action pair to become overly influential simply because of frequent repetition.

Therefore:

**Accumulating traces combine frequency and recency more, while replacing traces prevent the accumulation of the effect of repeated visits.**

Note: Replacing traces are not necessarily always better or more stable. Their choice depends on the algorithm, the environment, and the type of problem.

### 5.6. Effect of Eligibility Traces on the Q-Function

Eligibility traces are not just an independent memory. They directly participate in updating the value function.

In Q-Learning with eligibility traces, the update formula is as follows:

$$
Q(s,a) \leftarrow Q(s,a) + \alpha \delta_t e_t(s,a)
$$

where:

- $Q(s,a)$: current value of the state-action pair.
- $\alpha$: learning rate.
- $\delta_t$: TD Error.
- $e_t(s,a)$: eligibility trace.

Therefore, the amount of change in Q depends on two factors:

1. The amount of prediction error (TD Error).
2. The eligibility of that state-action pair.

For example, if a state-action pair has a high eligibility value, the TD Error can have a greater effect on its Q.

### 5.7. Difference Between Eligibility Trace and TD Error

These two concepts should not be confused with each other.

| Concept | Function |
| --- | --- |
| TD Error | Determines how wrong the value prediction was |
| Eligibility Trace | Determines which state or action should be affected by this error |

In simple terms:

- TD Error says how much we should learn.
- Eligibility Trace says where we should learn.

## 6. SARSA(λ)

On-Policy Control

SARSA(λ) is an extended version of SARSA that uses λ-Return and eligibility traces.

In ordinary SARSA, only one step of the future is considered for calculating the TD target each time.

But SARSA(λ) allows information from several future steps to be transferred to previous state-action pairs.

### 6.1. Review of Ordinary SARSA

SARSA is an acronym for the following five elements:

```
S → A → R → S' → A'
```

TD target formula:

$$
\text{Target} = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1})
$$

TD Error formula:

$$
\delta_t = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t)
$$

And the update:

$$
Q(S_t,A_t) \leftarrow Q(S_t,A_t) + \alpha \delta_t
$$

### 6.2. How Does SARSA(λ) Work?

Instead of updating only the current state-action pair, SARSA(λ) uses eligibility traces to update previous pairs as well.

At each time step:

1. The agent experiences a state and action.
2. It receives the reward and the next state.
3. The TD Error is calculated.
4. Eligibility traces are updated.
5. The Q-value of all state-action pairs with eligibility is updated.
6. The agent continues interacting with the environment.

Update formula:

$$
Q(s,a) \leftarrow Q(s,a) + \alpha \delta_t e_t(s,a)
$$

### 6.3. Features of SARSA(λ)

- It is on-policy.
- It uses eligibility traces.
- It can use experiences from several steps earlier.
- It is useful for problems with delayed rewards.
- Its updates can transfer reward information faster than ordinary SARSA.

### 6.4. Difference Between SARSA and SARSA(λ)

| Feature | SARSA | SARSA(λ) |
| --- | --- | --- |
| Learning type | On-Policy | On-Policy |
| TD Target | One-Step | λ-Return in Forward View |
| Eligibility Traces | No | Yes |
| Credit transfer | Mainly one step | Several steps |
| Delayed Rewards | More limited | More suitable |

Important note: SARSA(λ) with λ=0 becomes ordinary SARSA.

## 7. Watkins's Q(λ)

Off-Policy Control

Watkins's Q(λ) is an extended version of Q-Learning that uses eligibility traces to transfer reward information to previous experiences.

To understand it, we must first recall the difference between Q-Learning and SARSA.

### 7.1. Review of Q-Learning

Q-Learning is an off-policy algorithm.

TD target formula:

$$
\text{Target} = R_{t+1} + \gamma \max_a Q(S_{t+1}, a)
$$

TD Error formula:

$$
\delta_t = R_{t+1} + \gamma \max_a Q(S_{t+1}, a) - Q(S_t, A_t)
$$

Main point:

Q-Learning uses the best possible action according to the Q-function to calculate the target, not necessarily the action selected by the behavior policy.

### 7.2. Main Idea of Watkins's Q(λ)

Watkins's Q(λ) preserves this feature of Q-Learning and adds eligibility traces to it.

That is:

- It remains off-policy.
- It uses the TD Error to correct Q-values.
- It transfers information to previous state-action pairs.
- It uses eligibility traces to determine the amount of influence of previous experiences.

### 7.3. Important Difference Between Watkins's Q(λ) and SARSA(λ)

In SARSA(λ), the agent uses the action selected by the policy to calculate the TD target.

But Watkins's Q(λ) uses the maximum Q-value in the next state.

However, there is an important issue:

If the agent selects a non-greedy action in the next state, eligibility traces can no longer be maintained in the same way.

For this reason, Watkins's Q(λ) uses a special mechanism.

### 7.4. Clearing Eligibility Traces

In Watkins's Q(λ), if the action selected by the behavior policy in the new state is not greedy, the eligibility traces are cleared.

Why?

Because the algorithm is learning the value of the greedy policy, but the agent has actually selected a non-greedy action.

If the traces of previous experiences are preserved, information resulting from exploratory behavior may be improperly propagated into the target policy.

Therefore, in the case of selecting a non-greedy action:

```
Non-Greedy Action
       |
       v
Clear Eligibility Traces
       |
       v
Continue Learning
```

In the case of selecting a greedy action, previous traces decrease according to the usual rule.

### 7.5. Difference Between SARSA(λ) and Watkins's Q(λ)

| Feature | SARSA(λ) | Watkins's Q(λ) |
| --- | --- | --- |
| Type | On-Policy | Off-Policy |
| TD Target | Selected action | Max Q |
| Eligibility Traces | Yes | Yes |
| Handling of Non-Greedy Action | Continue traces | Clear traces |
| Goal | Improve behavior policy | Learn greedy policy |

### 7.6. Peng's Q(λ)

Alongside Watkins's Q(λ), there is another method called Peng's Q(λ).

The important difference between these two methods is in how they handle non-greedy experiences and preserve eligibility traces.

- Watkins's Q(λ): clears the traces after selecting a non-greedy action.
- Peng's Q(λ): uses a different method to combine on-policy and off-policy information and does not cut the traces in the same way as Watkins.

As a result, Peng's Q(λ) can preserve more information from the sequence of the agent's behavior.

Of course, these two algorithms should not be considered merely two different implementations of the same formula. The targets they use also differ.

## 8. Comparison of the Algorithms in Part One

| Algorithm | On/Off-Policy | Eligibility Traces | Important Feature |
| --- | --- | --- | --- |
| SARSA | On-Policy | No | One-Step Update |
| SARSA(λ) | On-Policy | Yes | Multi-Step Credit Assignment |
| Q-Learning | Off-Policy | No | Greedy TD Target |
| Watkins's Q(λ) | Off-Policy | Yes | Clears traces after non-greedy action |
| Peng's Q(λ) | Off-Policy | Yes | Preserves non-greedy experience information differently |

**Conceptual relationship:**

```
             TD Control
                 |
        +--------+--------+
        |                 |
     On-Policy         Off-Policy
        |                 |
      SARSA            Q-Learning
        |                 |
    SARSA(λ)       Watkins's Q(λ)

```

# Part Two: Model-Based Reinforcement Learning

## 9. Model-Free versus Model-Based RL

In the second part of the chapter, we go beyond improving algorithms based on direct experience.

Here, two main approaches to reinforcement learning are introduced.

### 9.1. Model-Free Reinforcement Learning

In model-free RL, the agent does not need to build an explicit model of the environment to learn a policy or value function.

The agent:

1. Interacts with the environment.
2. Selects an action.
3. Receives a reward.
4. Observes the new state.
5. Improves the value function or policy using experiences.

Examples:

- SARSA
- Q-Learning
- DQN

Advantages:

- No need for an explicit model of the environment.
- Relatively simpler implementation.
- Suitable for environments whose exact model is not available.

Disadvantages:

- May require many experiences.
- Dependence on direct interaction with the environment.
- Does not directly use model simulation for planning.

### 9.2. Model-Based Reinforcement Learning

In model-based RL, the agent learns a model of the environment's behavior or uses a model that is already available.

This model helps the agent understand:

- What states may result from choosing an action?
- What is the probability of each transition?
- What reward may be received?

Using this model, the agent can simulate the future without having to perform all interactions again in the real environment.

### Comparison

| Feature | Model-Free | Model-Based |
| --- | --- | --- |
| Environment model | Not needed | Has or learns one |
| Source of experience | Real interaction | Real interaction and simulation |
| Planning | Does not use a model | Uses a model for planning |
| Sample Efficiency | May be lower | Can be higher if the model is accurate |
| Main issue | Needs many experiences | Model error |

### Simple Example

Suppose you want to learn a game.

**Model-Free:**

```
Try Action
    |
    v
Observe Result
    |
    v
Update Q-Value
    |
    v
Try Again
```

**Model-Based:**

```
Interact with Environment
          |
          v
     Learn Model
          |
          v
  Simulate Possible Actions
          |
          v
        Planning
          |
          v
     Improve Policy
```

Important note: Model-based does not necessarily mean having a model in advance. The model can be learned from the agent's experiences.

## 10. Environment Model

For the agent to simulate the future, it needs an environment model.

In an MDP, the model usually has two important components:

### 10.1. Transition Model

The transition function determines the probability of reaching the next state when choosing an action in a state.

$$
P(s' \mid s, a)
$$

That is:

The probability that the agent, from the current state $s$, by choosing action $a$, reaches the next state $s'$.

### 10.2. Reward Model

The reward function determines what reward is received when a transition is made.

$$
R(s, a, s')
$$

Therefore, a complete environment model can include these two components:

```
Environment Model
       |
       +-------------------+
       |                   |
       v                   v
Transition Model      Reward Model
       |                   |
       v                   v
Next State          Expected Reward
       |                   |
       +---------+---------+
                 |
                 v
          Planning
```

## 11. Sampling Models and Distribution Models

The submitted text refers to two types of models whose difference we must know precisely.

### 11.1. Sampling Model

A sampling model, given a state and action, produces a sample of the possible outcome of the environment.

$$
(s', r) \sim \hat{P}(\cdot, \cdot \mid s, a)
$$

For example, if the agent takes an action, the model samples one possible outcome.

### 11.2. Distribution Model

Instead of producing only one outcome, a distribution model provides the probability distribution of possible outcomes.

For example:

```
Current State + Action
          |
          v
    Possible Outcomes
          |
      +---+---+
      |       |
      v       v
    Heads    Tails
      |       |
      0.5     0.5
```

### Comparison

| Feature | Sampling Model | Distribution Model |
| --- | --- | --- |
| Output | One sample | Probability distribution |
| Information | One possible outcome | All modeled outcomes |
| Application | Simulation | Distributional computation and planning |
| Uncertainty | Determined by sampling | Represented as a distribution |

Note: A distribution model is not necessarily more accurate in reality. It only provides more distributional information. Its quality still depends on the accuracy of the learned model.

## 12. Dyna-Q

Model-Based RL

Dyna-Q is one of the most important algorithms in this chapter.

Its main idea is to combine three activities in one agent:

1. Interaction: interacting with the real environment.
2. Learning: learning the environment model and updating the Q-function.
3. Planning: using the learned model to simulate new experiences.

In ordinary Q-Learning, the agent mainly depends on experiences received directly from the environment for learning.

But in Dyna-Q, in addition to real experience, the agent also uses experiences simulated by its own model.

### 12.1. Structure of Dyna-Q

```
                Real Environment
                       |
                       v
                  Interaction
                       |
                 (S, A, R, S')
                       |
             +---------+---------+
             |                   |
             v                   v
        Q-Learning          Model Learning
             |                   |
             v                   v
        Update Q-Table       Update Model
                                 |
                                 v
                              Planning
                                 |
                         Simulated Experience
                                 |
                                 v
                            Update Q-Table
```

The important point is that both paths, real experience and simulated experience, can improve the Q-function.

### 12.2. How Does Dyna-Q Work?

At each step, the agent first interacts with the real environment.

Steps:

**Step one: Select action**

The agent selects an action using its policy.

**Step two: Receive real experience**

The environment provides the following information:

$$
(S_t, A_t, R_{t+1}, S_{t+1})
$$

**Step three: Update Q-function**

Using Q-Learning:

$$
Q(S_t,A_t) \leftarrow Q(S_t,A_t) + \alpha \delta_t
$$

where:

$$
\delta_t = R_{t+1} + \gamma \max_a Q(S_{t+1}, a) - Q(S_t, A_t)
$$

**Step four: Learn the model**

The agent stores information about the transition in its model.

**Step five: Planning**

The agent selects several state-action pairs from the model and uses the model to generate simulated experiences.

**Step six: Update Q-function again**

The simulated experiences are also used to correct Q-values.

### 12.3. What Information Does the Model Keep in Dyna-Q?

In the implementation discussed in the book, the model uses information about transitions.

For example:

- Current state
- Selected action
- Next state
- Reward resulting from the transition

The model uses multidimensional data structures (tensors) to record observed transitions.

In the book's implementation, information about transition probability and average reward resulting from transitions is kept.

Conceptually:

```
Model
  |
  +-- Transition Probabilities
  |       P(s' | s, a)
  |
  +-- Expected Rewards
          R(s, a, s')
```

Why is average reward important?

Suppose the agent has experienced a specific transition several times and received a different reward each time.

The average of the observed rewards can be used to estimate the reward of that transition.

### 12.4. Planning in Dyna-Q

Planning means using the learned model to generate artificial experiences.

Suppose the agent has previously had this experience:

```
S1 --Action A--> S2
Reward = +5
```

The agent can retrieve this transition from its model and use it to update the Q-function without referring again to the real environment.

The update formula is still the same Q-Learning formula:

$$
Q(s,a) \leftarrow Q(s,a) + \alpha \left[ r + \gamma \max_{a'} Q(s',a') - Q(s,a) \right]
$$

The difference is that this time $s, a, r, s'$ are obtained from the model, not from a new interaction with the environment.

### 12.5. Planning Steps

One of the important parameters of Dyna-Q is the number of planning times per real interaction.

This number is usually called `n` or `planning_steps`.

For example:

```
One Real Interaction
        |
        v
   Update Model
        |
        v
   Planning Step 1
        |
        v
   Planning Step 2
        |
        v
   Planning Step 3
        |
        v
   Update Q-Function
```

The more planning steps there are, the more simulated experiences the agent can use.

But increasing it also has a higher computational cost.

### 12.6. Advantages of Dyna-Q

- Better use of real experiences.
- Faster learning in many environments.
- Reduced need for direct and repeated interaction with the environment.
- Possibility of improving the Q-function with simulated experience.
- Combining learning and planning in one algorithm.

### 12.7. Limitations of Dyna-Q

The most important problem with Dyna-Q is its dependence on the accuracy of the model.

If the model is wrong, the agent may learn from incorrect simulated experiences.

For example:

```
Real Environment:
S1 → S2 → Reward +5

Incorrect Model:
S1 → S3 → Reward +10
```

If the agent uses the wrong model many times, its Q-values may also deviate toward wrong results.

This issue is especially important in dynamic environments where rules or transitions change.

## 13. Trajectory Sampling

Model-Based Planning

Trajectory sampling is another method for planning in model-based RL introduced in this chapter.

Its main difference from Dyna-Q is in how it selects the states and actions used for planning.

### 13.1. Problem with the Planning Method in Dyna-Q

In Dyna-Q, planning is usually done by randomly selecting observed state-action pairs.

In other words, the agent may select a state for planning that has no direct connection to the current state or the possible path to the goal.

Example:

```
Dyna-Q Planning:

Random State-Action Pair
          |
          v
    Simulate Transition
          |
          v
       Update Q
```

This method creates learning opportunities from all parts of the model, but it does not necessarily focus on the experiences that are more important for the agent's current behavior.

### 13.2. Main Idea of Trajectory Sampling

In trajectory sampling, instead of randomly selecting states, the agent starts a simulated path from its current state.

Then, using the current policy, it selects an action and receives possible transitions from the model.

This process continues for several steps.

```
Current State
      |
      v
Select Action using Current Policy
      |
      v
Sample Next State from Model
      |
      v
Select Next Action
      |
      v
Sample Another Transition
      |
      v
Continue for a Limited Depth
```

In this way, the agent examines paths that are related to its current behavior and learned policy.

### 13.3. Example

Suppose the agent is in state number 3 in a game and the goal is to reach state number 8.

```
S3 → S4 → S5 → S6 → S7 → S8
                                  |
                               Reward +1
```

In trajectory sampling:

1. The agent starts from S3.
2. Using the current policy, it selects an appropriate action.
3. The environment model simulates the next state.
4. This process continues until the specified maximum depth is reached.
5. The simulated experiences are used to improve the value function.

Therefore, instead of random sampling from the entire model, the agent focuses on probable future paths.

### 13.4. Max Core Trajectory Depth

In the book's code, a parameter called `max_core_trajectory_depth` is introduced.

This parameter determines the maximum length of the simulated path.

In simple terms:

- Small depth: examining fewer future steps.
- Large depth: examining more future steps.

For example:

```
Depth = 2

S1 → S2 → S3

Depth = 5

S1 → S2 → S3 → S4 → S5 → S6
```

Increasing depth brings more future information into planning, but the computational cost also increases.

### 13.5. Advantages of Trajectory Sampling

- Focus on states related to the agent's current situation.
- More purposeful use of the environment model.
- Greater focus on paths leading to the goal.
- Possibility of reducing wasted planning on less relevant states.
- Effective use of current policy information.

### 13.6. Limitations of Trajectory Sampling

This method also has limitations:

- It may not examine all state-action pairs.
- Important paths that the current policy has not yet discovered may be ignored.
- It depends on the accuracy of the environment model.
- Its results depend on the current policy and the simulation depth.

Therefore, if the current policy does not have enough information, trajectory sampling may also miss valuable paths.

## 14. Difference Between Dyna-Q and Trajectory Sampling

Both methods are model-based and use the learned model for planning.

But their difference is in the strategy for selecting simulated experiences.

| Feature | Dyna-Q | Trajectory Sampling |
| --- | --- | --- |
| Type | Model-Based | Model-Based |
| Environment model | Has one | Has one |
| State selection | Random from observed states | Starts from the current state |
| Action selection | Random in planning | According to the current policy |
| Planning structure | Independent sampling | Simulating a path |
| Focus | Different experiences of the model | Probable future paths |
| Advantage | More general coverage of the model | Focus on relevant paths |
| Limitation | Wasted planning on unimportant pairs | Risk of ignoring undiscovered paths |

## 19. Important Points and Common Mistakes

1. λ is different from α. λ controls the combination of multi-step returns, but α determines the amount of change in the value function.
2. λ=0 in SARSA(λ) is equivalent to ordinary SARSA.
3. λ-Return is a combination of different N-step returns.
4. Eligibility traces determine how the TD Error affects previous experiences.
5. Accumulating traces increase with revisit and can exceed one.
6. Replacing traces set the trace value to one upon revisit.
7. SARSA(λ) is an on-policy method.
8. Watkins's Q(λ) is an off-policy method.
9. Watkins's Q(λ) clears eligibility traces when a non-greedy action is selected.
10. Model-free does not need an explicit model of the environment for learning.
11. Model-based uses the environment model for simulation and planning.
12. Dyna-Q uses both real experience and simulated experience.
13. Dyna-Q uses sampling of observed state-action pairs for planning.
14. Trajectory sampling starts from the current state and continues the path with the current policy.
15. Increasing planning steps or trajectory depth can increase computational cost.
16. An incorrect model can cause incorrect learning and improper updating of Q-values.
