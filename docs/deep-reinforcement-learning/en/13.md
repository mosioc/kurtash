## 1. Overview of the Book's Topics and Algorithm Families

The author first reviews the entire path of the book to clarify the connection among the different reinforcement learning methods.

### 1.1. Markov Decision Processes (MDPs)

The Markov decision process is the main mathematical framework for modeling reinforcement learning problems.

An MDP is usually defined with the following components:

$$
MDP = (S, A, P, R, \gamma, \rho_0, \mathcal{T})
$$

- **S (state space):** the set of possible environment states.
- **A (action space):** the set of actions the agent can take.
- **P (transition function):** the probability of transitioning from one state to another by taking an action.
- **R (reward function):** the reward function that specifies the desirability of an outcome.
- **γ (discount factor):** the importance of future rewards relative to the current reward.
- **ρ₀ (initial state distribution):** the probability distribution of initial states.
- **𝒯 (terminal states):** the set of terminal states.

The main point of an MDP is the Markov property:

> The future, given the current state and current action, does not depend directly on the previous history.

Mathematically:

$$
P(S_{t+1} \mid S_t, A_t, S_{t-1}, \ldots) = P(S_{t+1} \mid S_t, A_t)
$$

This property does not mean the future is deterministic. It means the probability distribution of the future is determined by knowing the current state and current action.

**Example: a robot in a maze**

- State: the robot's current position.
- Action: move left, right, up, or down.
- Transition: the probability of reaching the next cell.
- Reward: a reward for reaching the exit and a penalty for hitting an obstacle.
- Discount factor: the importance of reaching the goal faster.

The important point is that in real problems, the state alone may not contain enough information for the Markov property to hold. In such cases, we must enrich the state representation or use frameworks such as POMDP.

### 1.2. Planning Methods

Planning methods use a model of the environment to predict the results of actions and choose appropriate decisions.

In planning, instead of learning only through direct experience, the agent can use the transition and reward model to compute the consequences of actions.

For example:

- First, we have a model of the environment.
- We examine the possible consequences of actions.
- We estimate the value of different paths.
- We choose the best decision.

Important difference:

- **Planning:** using a model to compute and select a decision.
- **Learning:** learning from experience or data.
- **Model-based RL:** learning or using an environment model and combining it with planning.

### 1.3. Bandit Methods

Multi-armed bandit problems are one of the simplest forms of decision making under uncertainty.

The agent must choose one of several actions and, based on the received reward, learn about the desirability of that action.

Two basic concepts:

- **Exploration:** trying new actions to gain more information.
- **Exploitation:** choosing actions that, based on current information, have higher rewards.

The goal is to balance the two.

For example, a recommendation system can have several types of advertisements. It must both show known and successful advertisements and test new advertisements.

The difference between a bandit and an MDP is that in a bandit, there is usually no transition between consecutive states and no sequential effect of actions. The main focus is on action selection and receiving a reward.

### 1.4. Tabular Reinforcement Learning

Tabular RL refers to methods that store the values of states or state-action pairs in a table.

For example:

| State | Action | Q-Value |
| --- | --- | --- |
| S1 | Left | 2.4 |
| S1 | Right | 4.1 |
| S2 | Left | 1.8 |
| S2 | Right | 3.2 |

This method is suitable for environments with small state and action spaces that can be discretized.

Important algorithms in this section include:

- Monte Carlo (first-visit and every-visit)
- Temporal difference learning (TD)
- N-step TD
- TD(λ)
- SARSA
- Q-Learning
- Double Q-Learning
- SARSA(λ)
- Q(λ)
- Dyna-Q

**Relationship between tabular RL and deep RL**

In deep RL, instead of maintaining a large table, a neural network is used to approximate the value function or policy.

Therefore, deep RL does not replace the fundamental principles of RL. It is a way to generalize these principles to large and complex spaces.

For example:

- Tabular RL: storing the Q-value for each state-action.
- Deep RL: estimating the Q-value using a neural network.

Important educational note: Starting with tabular RL allows us to understand concepts such as the Bellman equation, policy evaluation, policy improvement, bootstrapping, and temporal difference error without the complexity of neural networks.

### 1.5. Value-Based Deep Reinforcement Learning

In value-based methods, the agent first estimates the value of different actions and then makes decisions using these estimates.

The important function of this family:

$$
Q(s,a)
$$

which shows the expected value of taking a specific action in a specific state.

Important algorithms:

- **NFQ:** Neural Fitted Q-Iteration, using a neural network to approximate the Q-function.
- **DQN:** using a deep neural network to estimate Q-values.
- **Double DQN (DDQN):** reducing the overestimation problem in action value estimation.
- **Dueling DQN:** decomposing the approximation of state value and advantage.
- **Prioritized Experience Replay (PER):** giving priority to experiences from which learning is more useful.
- **Rainbow DQN:** combining several important DQN improvements into one algorithm.

Conceptual structure:

```
State
  |
  v
Deep Neural Network
  |
  v
Q-Values for Available Actions
  |
  v
Action Selection
  |
  v
Environment
  |
  v
Reward + Next State
  |
  v
Learning and Updating Q-Function
```

This family is especially applicable to discrete action spaces.

### 1.6. Policy-Based and Actor-Critic Deep Reinforcement Learning

In policy-based methods, the agent directly learns the policy.

Instead of first estimating the value of all actions, it learns a function that maps a state to a probability distribution over actions or to a desired action.

$$
\pi_\theta(a \mid s)
$$

Main algorithms:

- REINFORCE
- VPG (Vanilla Policy Gradient)
- A3C (Asynchronous Advantage Actor-Critic)
- A2C (Advantage Actor-Critic)
- GAE (Generalized Advantage Estimation)
- PPO (Proximal Policy Optimization)

In actor-critic, there are two main components:

- **Actor:** learns the policy and selects actions.
- **Critic:** evaluates the actor's performance by estimating the value or advantage.

```
              State
                |
        +-------+-------+
        |               |
        v               v
      Actor           Critic
        |               |
        v               v
   Action/Policy    Value Estimate
        |               |
        +-------+-------+
                |
                v
          Environment
                |
                v
          Reward + State
                |
                v
          Update Actor
          Update Critic
```

Important difference between REINFORCE and VPG with actor-critic:

- REINFORCE uses the actual episode return to compute the policy gradient.
- VPG uses a baseline to reduce variance.
- Actor-critic, in addition to the policy, uses a value function for estimation and bootstrapping.

The baseline in VPG is not necessarily a critic in the actor-critic sense, because its role here is to reduce variance, not to use the value estimate for bootstrapping in the policy update.

### 1.7. Advanced Actor-Critic Methods

In chapter 12, more advanced actor-critic methods are examined:

| Algorithm | Main idea |
| --- | --- |
| DDPG | Learning a deterministic policy for continuous actions |
| TD3 | Improving DDPG with double critics, target policy smoothing, and delayed updates |
| SAC | Optimizing reward and entropy to maintain exploration |
| PPO | Limiting policy changes to improve training stability |

Important note about classification:

DDPG and TD3 are usually placed in the deterministic policy gradient and actor-critic family, but in the book's conceptual explanation, it is emphasized that they also use a value-based structure and a critic. Therefore, they should not be considered the same as pure policy gradient algorithms.

Also, A3C and A2C are not necessarily only for discrete actions. With an appropriate policy distribution design, they can also support continuous actions.

## 2. Comparison of the Three Main Families of RL Algorithms

One of the most important sections of the chapter is the comparison of the three approaches: value-based, policy-based, and model-based.

### 2.1. Value-Based Methods

In these methods, the value function is learned first, and then the appropriate action is selected based on it.

Example: DQN

```
State
  |
  v
Value Function: Q(s,a)
  |
  v
Compare Action Values
  |
  v
Select Best Action
```

Features:

- Indirect policy learning through the value function.
- Suitable for discrete action spaces.
- Usually simpler computation compared with some policy-based methods.
- May require many experiences to learn.

### 2.2. Policy-Based Methods

In these methods, the policy itself is learned directly.

Example: REINFORCE and PPO

```
State
  |
  v
Policy Function: π(a|s)
  |
  v
Action Distribution
  |
  v
Select Action
```

Features:

- Direct learning of the decision-making function.
- Good support for continuous and discrete action spaces.
- Ability to learn stochastic policies.
- Possibly requires significant computation and training samples.
- Policy gradient methods may have high variance.

### 2.3. Model-Based Methods

In these methods, the agent uses an environment model to predict future events.

The model usually includes the following:

- Transition model
- Reward model

```
Current State
      |
      v
Environment Model
      |
      v
Predict Next States and Rewards
      |
      v
Planning
      |
      v
Select Action
```

Features:

- Ability to plan before taking an action in the real environment.
- Ability to use simulated data.
- Ability to reduce the need for real interaction with the environment.
- Higher computational cost for learning or running the model.
- Sensitivity to model errors.

### 2.4. Comparison Table

| Criterion | Value-Based | Policy-Based | Model-Based |
| --- | --- | --- | --- |
| Learning goal | Value function | Policy | Environment model |
| Decision making | Based on action values | Directly with the policy | With prediction and planning |
| Action space | Usually discrete | Discrete and continuous | Depends on the method |
| Sample efficiency | Depends on the algorithm | Depends on the algorithm | Potentially high |
| Computational cost | Usually moderate | Variable | May be high |
| Need for an environment model | No | No | Yes |
| Main weakness | Value estimation and scalability | Variance and stability | Model error |

**Important note:** None of these three families is always the best. The choice of algorithm depends on the structure of the problem, the type of action space, the cost of interacting with the environment, computational resources, and the availability of a model.

Also, these three categories are not fully independent and mutually exclusive. Hybrid algorithms such as actor-critic use both a policy and a value function simultaneously, and model-based RL can also benefit from a policy or value function.

## 3. Model-Based Deep Reinforcement Learning

An advanced topic outside the book's deep coverage

### 3.1. Definition

In model-based deep reinforcement learning, the agent tries to build a model of the environment so that it can predict the results of its actions.

This model usually has two main parts:

**1. Transition model**

It predicts what new state will result after taking an action in the current state.

$$
\hat{P}(s' \mid s,a)
$$

**2. Reward model**

It estimates the possible reward resulting from the transition.

$$
\hat{R}(s,a,s')
$$

In some methods, the model is learned deterministically, and in others, probabilistically.

### 3.2. How It Works

```
Real Environment
       |
       v
Collect Experiences
       |
       v
Learn Environment Model
       |
       v
Simulate Possible Actions
       |
       v
Predict Future States and Rewards
       |
       v
Planning / Policy Optimization
       |
       v
Choose Better Actions
       |
       v
Real Environment
```

In this way, the agent can examine the possible consequences of an action in the model before executing it in the real environment.

### 3.3. Sample Efficiency

One of the most important advantages of model-based RL is the ability to reuse experiences.

In model-free RL, the agent usually needs direct and repeated interaction with the environment to learn.

But in model-based RL:

1. The agent collects experience from the real environment.
2. It learns an environment model.
3. It uses the model to generate simulated experiences.
4. It uses the artificial experiences to improve the policy or value function.

This process can reduce the number of interactions required with the real environment.

This feature is called sample efficiency.

### 3.4. Advantages of Model-Based RL

- **Sample efficiency:** using more of each experience.
- **Planning:** examining the consequences of actions before executing them.
- **Transfer learning:** reusing knowledge about environment dynamics in new tasks.
- **Stability:** under appropriate conditions, more structured learning and planning.
- **Reduced real-world risk:** testing decisions in a simulated environment instead of the real environment.

### 3.5. Disadvantages and Limitations

**1. Model error**

The learned model may differ from the real environment.

**2. Compounding error**

Small model errors in successive predictions can grow larger.

```
Prediction 1: Small Error
        |
        v
Prediction 2: Larger Error
        |
        v
Prediction 3: Accumulated Error
        |
        v
Unreliable Long-Term Prediction
```

**3. Computational cost**

The agent must learn and run the environment model in addition to the policy or value function.

**4. Uncertainty estimation**

Determining when the model is confident or uncertain is difficult, especially in deep learning models.

**5. Unnecessary modeling**

Sometimes learning all the dynamics of the environment is unnecessary.

For example, if the goal of the robot is to pick up a cup, it may not need to learn the complete physics of fluid flow.

**6. Data hunger**

Deep models may require a lot of data to build a reliable simulator. As a result, there is no guarantee that model-based is always more sample-efficient than model-free.

### 3.6. Model-Based RL and Model-Free RL

| Feature | Model-Based | Model-Free |
| --- | --- | --- |
| Environment model | Has or learns one | Not needed for decision making |
| Planning | Usually yes | Usually no |
| Use of simulation | Can be extensive | More limited by the algorithm structure |
| Sample efficiency | Potentially better | Depends on the algorithm |
| Complexity | Usually higher | Usually lower |
| Sensitivity to model error | Yes | No, in this sense |

**Note:** Model-free does not mean having no neural network model. It means the agent does not depend on an explicit model of the environment dynamics to learn the policy or value.

## 4. Derivative-Free Optimization

An advanced topic outside the book's deep coverage

### 4.1. Definition

In deep learning, we usually use gradient-based methods to optimize neural network parameters.

Common steps:

```
Neural Network
      |
      v
Calculate Loss
      |
      v
Backpropagation
      |
      v
Calculate Gradients
      |
      v
Gradient Descent
      |
      v
Update Parameters
```

But not all objective functions have usable gradients.

Derivative-free optimization, or DFO, is a method for optimization that does not depend on computing the derivative of the objective function.

These methods search for a better solution by testing different changes in the parameters and evaluating the results.

Other names:

- Gradient-free optimization
- Black-box optimization
- Zeroth-order optimization

### 4.2. When Is It Used?

When the objective function has the following characteristics:

- Discrete
- Discontinuous
- Multi-modal, with several local optima
- Non-differentiable, or its derivative is difficult to compute

In such situations, gradient-based methods may not perform well.

### 4.3. Genetic Algorithms

One of the derivative-free optimization methods is the genetic algorithm.

Its main idea is inspired by natural selection in biology.

Steps:

1. Create an initial population of possible solutions.
2. Evaluate the fitness of each solution.
3. Select the better solutions.
4. Perform crossover and mutation.
5. Create a new generation.
6. Repeat the process until a suitable result is reached.

```
Initial Population
        |
        v
Fitness Evaluation
        |
        v
Selection
        |
        v
Crossover + Mutation
        |
        v
New Generation
        |
        v
Repeat
```

### 4.4. Evolution Strategies (ES)

Evolution strategies are also from the family of evolutionary methods.

In these methods, the model parameters are randomly changed, and the performance of different versions is compared.

Simply:

- Several versions of the parameters are generated.
- Each version is tested in the environment.
- Their performance is measured.
- The performance information is used to improve the parameters.

### 4.5. Advantages

- No need for backpropagation.
- Ability to optimize complex and black-box functions.
- Simple implementation of some versions.
- Very good parallelization capability.
- Hundreds or thousands of processors can be used to evaluate solutions simultaneously.

### 4.6. Disadvantages

- Sample inefficiency: usually requires many evaluations.
- May not use the structure of the problem and its useful information.
- Ignores the sequential structure of reinforcement learning.
- In large problems, the cost of evaluations can be very high.

**Important note:** Derivative-free optimization is not a permanent replacement for gradient descent. These methods are complementary tools, and the choice between them depends on the structure of the objective function and the problem.

## 5. Moving Toward Artificial General Intelligence (AGI)

### 5.1. What Is AGI?

AGI stands for Artificial General Intelligence.

The goal of AGI is to build a system that can learn, reason, adapt to new conditions, and solve new problems in various domains like a human.

The main difference between AGI and narrow AI is the breadth of capabilities and the ability to generalize.

**Narrow AI:**

- Trained for a specific task.
- May perform exceptionally well on that task.
- Transferring knowledge to different tasks is difficult for it.

**AGI:**

- Has the ability to solve diverse problems.
- Can transfer learned knowledge to new tasks.
- Has the ability to reason and adapt to unforeseen conditions.
- Can continuously learn from new experiences.

### 5.2. Expected Features of AGI

**1. Generalization**

The ability to use learned knowledge to solve new problems.

**2. Transfer learning**

Transferring knowledge from one task to another.

**3. Adaptability**

The ability to adapt to conditions that did not exist during training.

**4. Reasoning**

The ability to reason and draw conclusions from available evidence and information.

**5. Common sense**

Understanding general relationships and concepts of the real world.

**6. Continuous learning**

The ability to learn from new experiences over time, without complete dependence on an initial training phase.

### 5.3. Why Are Current Algorithms Not AGI?

An important example mentioned in the chapter is the difference between human ability and trained agents for different games.

Suppose:

- One agent is trained for Pong.
- Another agent is trained for Breakout.

The first agent may perform exceptionally well in Pong but have almost no skill in Breakout.

Meanwhile, a human can learn a similar game faster using previous game experience.

This shows the weakness in generalization and transfer learning.

Another example:

AlphaZero performs very well in board games, but this does not mean it can solve general life problems or perform household tasks.

The main point:

**Outstanding performance in a specialized task does not mean having general intelligence.**

Also, AGI is not merely about having more processing power or more training data. The ability to generalize, adapt, and solve new problems also matters.

## 6. Advanced Exploration Strategies

An advanced topic

One of the fundamental problems of reinforcement learning is creating a proper balance between exploration and exploitation.

In simple methods such as epsilon-greedy, the agent takes a random action with a certain probability and uses the best known action the rest of the time.

But in complex environments, random exploration is not always enough.

### 6.1. The Exploration Problem in Complex Environments

Suppose the agent in a game must reach a hidden area to receive a large reward.

If the agent experiences only small and nearby rewards for a long time, it may never reach the hidden area.

This problem is more severe in environments with sparse rewards.

**Sparse reward:** the environment gives a reward only in a limited number of conditions.

### 6.2. Intrinsic Motivation

In intrinsic motivation methods, the agent uses an internal motivational signal in addition to the external environment reward.

Two types of reward:

- **Extrinsic reward:** the reward provided by the environment.
- **Intrinsic reward:** the reward generated from internal criteria of the agent, such as novelty or uncertainty.

The combined reward function can be represented as:

$$
R_{\text{total}} = R_{\text{extrinsic}} + \beta R_{\text{intrinsic}}
$$

In this relation:

- $R_{\text{extrinsic}}$: the main environment reward.
- $R_{\text{intrinsic}}$: the internal motivational reward.
- $\beta$: the coefficient of the importance of the internal reward.

For example, the agent may receive an internal reward for visiting a new state, even if that state initially has no external reward.

### 6.3. Examples of Advanced Exploration Methods

- **Count-based exploration:** rewarding visits to states that have been observed less often.
- **Novelty-based exploration:** encouraging the agent to experience new situations.
- **Curiosity-driven exploration:** encouraging the agent to learn and predict parts of the environment that are still unknown to it.
- **Uncertainty-based exploration:** using the uncertainty of the model or estimates to select informative actions.
- **Random Network Distillation (RND):** using the difference between the prediction of a trained network and a fixed random network as a novelty signal.

Important note: Advanced exploration does not simply mean acting more randomly. The goal is for the agent to obtain more useful information from the environment.

## 7. Inverse Reinforcement Learning (IRL)

An advanced topic

### 7.1. Definition

In ordinary reinforcement learning, the reward function is known and the agent tries to learn a suitable policy to maximize it.

But in inverse reinforcement learning, the reward function is unknown and the agent must infer it by observing the behavior of another agent.

Simply:

- RL: we have the reward function and learn the policy.
- IRL: we have the behavior or demonstration and try to extract the reward.

### 7.2. Difference Between RL and IRL

```
Reinforcement Learning:

Reward Function
      |
      v
Agent Learning
      |
      v
Optimal Policy
```

```
Inverse Reinforcement Learning:

Expert Demonstrations
      |
      v
Infer Reward Function
      |
      v
Learn a Policy
```

### 7.3. Example

Suppose we want to teach a professional driver's behavior to an agent.

Instead of telling the agent exactly:

- When to brake.
- When to increase speed.
- When to change lanes.

we observe the professional driver's behavior.

The agent examines the driver's behavior and tries to understand what matters to the driver:

- Safety?
- Speed?
- Fuel consumption?
- Passenger comfort?
- Maintaining distance from other vehicles?

It then uses this information to estimate the reward function.

### 7.4. Apprenticeship Learning

Apprenticeship learning refers to learning through the demonstration of an expert.

In a common approach:

1. The expert demonstrates its behavior.
2. IRL extracts the probable reward function.
3. The agent is trained using the estimated reward.
4. The resulting policy is evaluated and refined.

```
Expert Demonstrations
        |
        v
Inverse Reinforcement Learning
        |
        v
Inferred Reward Function
        |
        v
Reinforcement Learning
        |
        v
Learned Policy
```

### 7.5. Advantages

- Less need for manually designing the reward function.
- Using the expert's knowledge and behavior.
- Ability to learn more complex tasks.
- Suitable for robotics and autonomous driving.
- Ability to use the behavior of other agents to predict their goals.

### 7.6. Limitations

- The expert's behavior may be incorrect or incomplete.
- The extracted reward is not necessarily the expert's true goal.
- Several reward functions may produce similar behavior.
- Collecting high-quality demonstrations is difficult.
- Biases in the expert's behavior can be transferred to the agent.

**Important note:** IRL is not the same as imitation learning. In imitation learning, the agent may directly imitate the expert's behavior, but IRL tries to extract the hidden goal or reward behind the behavior.

## 8. Transfer Learning and Domain Randomization

### 8.1. What Is Transfer Learning?

Transfer learning means using knowledge obtained from one task to learn or solve another task.

In reinforcement learning, instead of training the agent from scratch for every task, the agent's previous knowledge can be transferred.

Example:

A robot first learns how to pick up a cube.

Then, to learn to pick up other objects, it uses its previous knowledge about the following:

- Arm movement.
- Joint control.
- Grasping objects.
- Position detection.
- Interaction with the environment.

As a result, it may require fewer experiences to learn the new task.

### 8.2. Why Is Transferring Knowledge Difficult?

One of the main problems is the difference between the source and target environments.

The agent may be trained in a simulated environment but face different conditions when transferred to the real world:

- Different friction.
- Different object weights.
- Sensor delays.
- Calibration errors.
- Different lighting.
- Physical changes in the environment.

These differences can be considered part of the Sim-to-Real Gap.

### 8.3. Domain Randomization

Domain randomization is one of the important methods for reducing the Sim-to-Real Gap.

The main idea is not to limit the agent to a completely fixed simulation.

Instead, during training, we randomly change various environment parameters.

For example:

- Changing object masses.
- Changing friction.
- Changing lighting.
- Changing colors and textures.
- Changing object positions.
- Changing dynamics parameters.
- Adding noise to sensors.

Structure:

```
             Simulator
                 |
       +---------+---------+
       |         |         |
       v         v         v
    Domain 1  Domain 2  Domain 3
       |         |         |
       v         v         v
    Training  Training  Training
       |         |         |
       +---------+---------+
                 |
                 v
           Generalized Agent
                 |
                 v
           Real Environment
```

### 8.4. Why Can a Randomized Environment Be Better Than a Completely Accurate One?

Suppose we train the robot in a completely fixed simulated environment.

The agent may become adapted only to those specific conditions.

But if it encounters diverse conditions during training, there is a higher probability that it will learn a robust and generalizable policy.

The goal of domain randomization is for the agent to learn more general patterns instead of memorizing the conditions of one specific environment.

### 8.5. Advantages and Limitations

Advantages:

- Increased robustness.
- Reduced sensitivity to environment changes.
- Improved generalization.
- Helps with Sim-to-Real transfer.

Limitations:

- Designing the randomization range is difficult.
- Too much diversity can make training harder.
- Some random conditions may be unrealistic.
- Increased diversity can raise training costs.

Note: Domain randomization is an important method for transfer learning, but it is not the only available method.

## 9. Multi-Task Learning

An advanced topic

### 9.1. Definition

Multi-task learning means training one model to learn several related tasks instead of training independently for each task.

The goal is for the agent to use the information and experiences shared among different tasks.

### 9.2. Robot Example

Suppose a robotic arm must perform several tasks:

- Pick up a cube.
- Pick up a ball.
- Move objects to a specific location.
- Place objects in a box.
- Rotate objects.

If the robot learns each task completely independently, it may learn a large part of its knowledge several times.

But in multi-task learning, the model can learn common principles such as the following:

- Arm movement.
- Joint control.
- Interaction with objects.
- Position estimation.
- Applying force.

This knowledge can be shared among different tasks.

### 9.3. Conceptual Structure

```
          Shared Neural Network
                   |
          Shared Representations
                   |
        +----------+----------+
        |          |          |
        v          v          v
      Task 1     Task 2     Task 3
        |          |          |
        v          v          v
      Policy     Policy     Policy
        1          2          3
```

### 9.4. Advantages

- Reuse of shared knowledge.
- Increased generalization.
- Faster learning of related tasks.
- Reduced need for independent training for each task.
- Learning general environment features.

### 9.5. Limitations

**Negative transfer:** sometimes learning one task causes a drop in performance on another task.

Also:

- Tasks may conflict with each other.
- Allocating network capacity to different tasks is difficult.
- Designing related tasks is very important.

**Important note:** Multi-task learning does not necessarily mean an agent performs several tasks simultaneously. Tasks can be presented simultaneously or in different training sequences.

## 10. Curriculum Learning

### 10.1. Definition

Curriculum learning is a method of organizing the training process in which the agent first encounters simpler tasks and gradually moves to more complex tasks.

The main idea is inspired by the human learning process.

For example, someone who wants to learn to drive first practices controlling the car in a simple environment and then enters complex traffic.

### 10.2. Example in Reinforcement Learning

Suppose we want to train an agent for complex games.

We can design the training as follows:

1. First, a simple game with limited rules.
2. Then increase the number of obstacles.
3. Increase the environment speed.
4. Add enemies.
5. Increase decision-making complexity.
6. Finally, run the full game.

### 10.3. The Role of the Reward Function

In curriculum learning, designing the reward function is very important.

In simple tasks, the reward for success may be very clear.

But in more complex tasks, reaching the goal may require a set of coordinated behaviors.

For this reason, training can begin with conditions that provide simpler feedback and gradually introduce more difficult conditions.

### 10.4. Conceptual Structure

```
Simple Task
     |
     v
Intermediate Task
     |
     v
Advanced Task
     |
     v
Complex Task
     |
     v
Target Task
```

### 10.5. Advantages

- Reduced initial training difficulty.
- Improved sample efficiency in some problems.
- Gradual learning of skills.
- Helps solve problems with sparse rewards.
- Increased probability of successfully learning complex behaviors.

### 10.6. Disadvantages

If the curriculum is not designed properly, it may cause:

- The agent to become overly dependent on simple skills.
- The agent not to learn the skills needed for the final task.
- Difficulty in transferring between stages.
- The order of tasks to introduce bias.

Important note: Curriculum learning and multi-task learning are different.

- Multi-task learning: learning from several tasks.
- Curriculum learning: organizing the order and difficulty of training tasks.

## 11. Meta-Learning

An advanced topic

### 11.1. Definition

Meta-learning means learning to learn.

In ordinary learning, the agent tries to solve a specific task.

But in meta-learning, the goal is for the agent to use the experience of learning several tasks so that it can learn new tasks faster in the future.

Simply:

**Instead of only teaching the agent what to do, we teach it how to learn better.**

### 11.2. Example

Suppose an agent must learn several different games.

In ordinary training, each game is learned from scratch.

But in meta-learning, the agent uses the experience of learning previous games to adapt faster to a new game.

### 11.3. Conceptual Components

```
        Multiple Training Tasks
                  |
                  v
          Meta-Learning Process
                  |
                  v
       Learn How to Learn Efficiently
                  |
                  v
          New / Unseen Task
                  |
                  v
       Fast Adaptation with Few Samples
```

### 11.4. Goal of Meta-Learning

- Faster learning of new tasks.
- Reduced number of experiences required for adaptation.
- Use of shared knowledge among tasks.
- Improved generalization capability.
- Adaptation to new environments.

### 11.5. Relationship to Neural Architecture Search

One application related to meta-learning ideas is learning better methods for designing or training neural networks.

For example, we can look for systems that can:

- Find the appropriate network structure.
- Tune hyperparameters.
- Choose the appropriate optimization method.
- Adapt the training process to a new problem.

Of course, neural architecture search and meta-learning are not the same concept. They can be combined in some approaches.

### 11.6. Limitations

- Designing an appropriate set of training tasks is difficult.
- Training the meta-learner may have a high computational cost.
- The agent may perform poorly on tasks outside the training distribution.
- There is no guarantee against local optima.

## 12. Hierarchical Reinforcement Learning (HRL)

An advanced topic

### 12.1. Definition

Hierarchical reinforcement learning is a method in which the decision-making problem is divided into several levels of decisions.

In ordinary RL, the agent selects one action at each step.

But in HRL, the agent can first select a high-level goal or skill and then execute a set of low-level actions to reach it.

### 12.2. Example

Suppose a robot must leave a room.

In ordinary RL:

- Move left.
- Move right.
- Move forward.
- Turn.
- Repeat these actions.

In HRL:

- High level: decide to leave the room.
- Low level: find the door, move toward it, and pass through it.

Therefore, instead of directly selecting all the detailed actions, the agent uses higher-level skills.

### 12.3. Structure

```
          High-Level Policy
                  |
                  v
          Select Subgoal / Skill
                  |
                  v
          Low-Level Policy
                  |
                  v
          Primitive Actions
                  |
                  v
             Environment
```

### 12.4. Options Framework

One of the important frameworks of HRL is the options framework.

In this framework, an option is not an ordinary action. It is a behavior extended over time.

Each option has three components:

**1. Initiation set (I)**

The set of states from which the option can begin.

**2. Intra-option policy (π)**

The internal policy that determines the actions needed to execute the option.

**3. Termination condition (β)**

The condition or probability of the option ending.

Example of an option called Open Door:

- Initiation set: the robot being near the door.
- Intra-option policy: moving toward the handle and opening the door.
- Termination condition: the door opening or the operation failing.

### 12.5. Relationship to Semi-Markov Decision Process

Since executing an option may take several time steps, HRL can be modeled with the Semi-Markov Decision Process (SMDP) framework.

In an ordinary MDP, actions are selected at every time step.

But in an SMDP, decisions may occur at different time intervals.

### 12.6. Advantages

- Reduced decision-making complexity.
- Management of long-horizon tasks.
- Ability to reuse skills.
- Improved exploration in complex problems.
- Dividing the problem into manageable subtasks.

### 12.7. Limitations

- Finding the appropriate hierarchy is difficult.
- Learning effective options is complex.
- Excessive dependence on low-level skills can be problematic.
- A high-level error may disrupt the performance of all lower levels.

## 13. Multi-Agent Reinforcement Learning (MARL)

### 13.1. Definition

Multi-agent reinforcement learning refers to situations in which several agents operate simultaneously in one environment and influence each other's behavior.

These agents may:

- Cooperate with each other.
- Compete with each other.
- Have a combination of cooperation and competition.

### 13.2. The Most Important Challenge: Non-Stationarity

In single-agent RL, the environment is usually assumed to be fixed from the agent's perspective.

But in multi-agent RL, the behavior of other agents is also changing.

Suppose the first agent is learning.

At the same time, the second agent is also changing its policy.

Therefore, the environment the first agent experiences is constantly changing.

This situation is called non-stationarity.

```
Agent A Learning
       |
       v
Changes Policy
       |
       v
Changes Environment for Agent B
       |
       v
Agent B Updates Policy
       |
       v
Changes Environment for Agent A
       |
       v
Continuous Adaptation
```

### 13.3. Cooperative Multi-Agent Learning

In this case, several agents cooperate to achieve a common goal.

Example:

Several self-driving cars must optimize traffic flow.

The goal of each car is not only to reach its destination quickly. Reducing traffic and increasing the safety of the whole system may also matter.

### 13.4. Centralized Critic

One method for cooperative learning is the use of a centralized critic.

In this structure, the critic can receive more information about the overall state of the system.

For example:

- The state of all agents.
- The actions taken.
- General environment information.
- A shared reward.

In contrast, each actor can make decisions based on its own local information.

### 13.5. Centralized Training, Decentralized Execution (CTDE)

One of the important patterns of multi-agent RL is the CTDE method.

In this method:

- During training, broader information about the agents is available to the learning system.
- During execution, each agent can make decisions using its own local policy.

```
                 Training
                    |
          +---------+---------+
          |                   |
          v                   v
       Agent A             Agent B
          |                   |
          +---------+---------+
                    |
                    v
           Centralized Critic
                    |
                    v
             Policy Updates
                    |
                    v
                 Execution
                    |
          +---------+---------+
          |                   |
          v                   v
      Local Actor A       Local Actor B
          |                   |
          v                   v
      Local Action A     Local Action B
```

This method helps agents benefit from shared information during training but does not necessarily depend on a central controller for final execution.

### 13.6. Hierarchical RL and Multi-Agent RL

These two concepts are different but can be combined.

In HRL, decision making is performed at different levels.

In MARL, several independent or coordinated agents interact with each other.

Sometimes a multi-agent system can be designed in which each agent has a specific role in a hierarchy.

### 13.7. Self-Play and Adversarial Learning

One of the important methods in agent training is self-play.

In this method, the agent competes with another version of itself or with previous versions of itself.

Example:

- Agent A versus Agent B.
- Agent B is a previous version of Agent A.
- The new version improves by facing the challenges created by the previous version.

Advantages:

- Creating diverse opponents.
- Improving strategy.
- Increasing robustness.
- Reducing dependence on predefined opponents.

This method is very useful in competitive games.

### 13.8. Applications of MARL

- Self-driving cars.
- Traffic management.
- Swarm robotics.
- Multiplayer games.
- Communication networks.
- Distributed resource management.
- Financial systems and multi-agent markets.

### 13.9. Limitations

- Non-stationarity.
- Increased complexity of state and action spaces.
- Difficulty in coordinating agents.
- The credit assignment problem.
- The need for appropriate methods for communication and information sharing.

Important note: As the number of agents increases, the joint action and joint state spaces may grow dramatically. Therefore, scalability is one of the fundamental challenges of MARL.

## 14. Explainable AI, Safety, Fairness, and Ethical Standards

An important section on AI responsibility

In DRL systems, the agent may exhibit complex and unpredictable behaviors.

This issue is very important in sensitive applications such as self-driving cars, medicine, and robotics.

### 14.1. Explainable AI (XAI)

The goal of explainable AI is to understand why a model or agent made a specific decision.

For example:

A self-driving car suddenly brakes.

Important questions:

- Why did it brake?
- What information caused this decision?
- Did it detect an obstacle?
- Was the decision due to a sensor error?
- Did the policy show unexpected behavior?

In DRL, interpreting decisions can be difficult due to deep neural networks and complex policies.

XAI methods can include the following:

- Analyzing the features that influenced the decision.
- Visualization.
- Examining the agent's behavior under different conditions.
- Analyzing the decision path.
- Using interpretable models alongside complex models.

### 14.2. AI Safety

AI safety refers to the set of methods used to prevent unwanted, dangerous, or harmful behavior in intelligent systems.

In RL, an improperly defined reward function can create unwanted behaviors.

Example:

Suppose the goal of a robot is to move an object quickly.

If we reward only speed and ignore safety, the robot may perform dangerous behaviors.

Therefore, safety constraints and criteria must also be considered in system design.

Related concepts:

- Safe reinforcement learning
- Constraint-based RL
- Risk-sensitive RL
- Reward hacking
- Robustness

### 14.3. Fairness

Fairness means preventing discriminatory or unfair behavior in intelligent systems.

For example, an agent allocating resources should not systematically give unfair priority to a specific group.

When designing the reward function and selecting training data, the effect of decisions on different groups must be examined.

### 14.4. Ethical Standards

The use of DRL in the real world must be accompanied by ethical principles and responsibility.

Important issues:

- Privacy protection.
- Transparency of decisions.
- Accountability.
- User safety.
- Prevention of harm.
- Risk management.
- Human oversight.

**Conclusion:** High performance alone is not a sufficient criterion for the success of an agent. In addition to performance, an intelligent system must also be reliable, safe, and responsible.

## 15. Designing Custom Environments for Reinforcement Learning

One of the fully practical sections of the chapter is how to use DRL to solve real and custom problems.

### 15.1. Why Do We Need a Custom Environment?

Many real problems do not have a ready environment such as Atari or MuJoCo.

For example:

- Prediction and trading in financial markets.
- Resource management.
- Control of industrial systems.
- Traffic optimization.
- Robotics.
- Energy management.

To use RL, we must turn these problems into an interactive environment.

### 15.2. Steps for Designing an Environment

**Step one: Define the MDP**

The problem must be converted into the components of an MDP:

- State
- Action
- Transition
- Reward
- Initial state
- Terminal conditions
- Discount factor

**Step two: Design the state**

We specify what information the agent receives.

For example, in stock trading:

- Current price.
- Trading volume.
- Account balance.
- Current assets.
- Market indicators.

**Step three: Design the action space**

We specify what actions the agent can take.

For example:

- Buy
- Sell
- Hold

Or in the continuous case, determining the amount of capital to buy or sell.

**Step four: Design the reward function**

We specify what behavior is desirable.

For example:

- Profit from trading.
- Risk penalty.
- Transaction costs.
- Penalty for capital loss.

**Step five: Implement the transition function**

We must specify how executing each action changes the environment state.

**Step six: Implementation and testing**

The environment must be designed so that the agent can interact with it.

### 15.3. Agent-Environment Interaction Cycle

```
          Environment
               |
               v
         Observation
               |
               v
             Agent
               |
               v
             Action
               |
               v
          Environment
               |
               v
       Reward + New State
               |
               v
        Agent Learning
```

### 15.4. Using Ready-Made Environments as Templates

The author recommends examining the structure of ready-made environments.

For example:

- Atari: interaction with an emulator.
- MuJoCo: interaction with a physics engine.
- Other simulators: receiving observations and executing actions.

By examining these environments, we can find a suitable pattern for designing our own environment.

### 15.5. Important Points in Designing a Custom Environment

- The observation must provide enough information for decision making.
- The action space must be compatible with the real problem.
- The reward function must not cause reward hacking.
- Transitions must be as realistic as possible.
- Terminal conditions must be defined correctly.
- The environment must be evaluable and reproducible.
- It is better to first build a simple version and then increase complexity.

**Important note:** If the state is incomplete, the real problem may no longer be a fully observable MDP and may approach a POMDP. Also, an incorrect design of the reward function can cause the agent to optimize a problem different from our real goal.

## 17. Learning Without Explicit Reward (Reward-Free Learning)

One of the interesting topics raised in the final discussion of the book is whether the agent can learn without receiving an explicit reward from the environment.

### 17.1. The Main Problem

In traditional RL, we usually design a reward function.

For example:

- Reaching the goal: +10
- Hitting an obstacle: -5
- Performing a desired action: +1

But in the real world, it is not always possible to define the goal as a precise number.

For example, humans do not receive a numerical reward for every behavior, but they still learn.

This topic is a motivation for research on methods of learning without explicit reward.

### 17.2. Challenges of Reward-Free Learning

- How should the agent determine its goal?
- How should it distinguish desirable behavior from undesirable behavior?
- How can dangerous actions be prevented?
- How can we ensure the agent's goals are compatible with human values?

### 17.3. Relationship to AI Alignment

One important concern is that if an intelligent system has great authority but its goals and constraints are not properly defined, it may exhibit unexpected behaviors.

Therefore, we must pay attention to topics such as the following:

- Alignment
- Safety constraints
- Human oversight
- Reward design
- Goal specification

Important note: Reward-free learning is a broad term for a set of research approaches and should not be confused with the complete removal of any goal, training signal, or constraint.
