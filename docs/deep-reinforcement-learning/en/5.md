# Comprehensive Summary of Chapter 5 of *Grokking Deep Reinforcement Learning*

## 1. Overview

The official title of Chapter 5 is **Evaluating Agents' Behaviors**.

The main goal of the chapter is to learn how to estimate the value of a behavior or policy in an environment whose transition function and reward function are unknown.

An important note is that this chapter focuses on **evaluating a fixed policy**, not directly improving it. Policy improvement is the main topic of Chapter 6.

# Part 1: Foundations of Evaluating Agent Behavior

## 2. The Main Problem of the Chapter: Policy Evaluation

In reinforcement learning, the agent must learn what decisions to make in order to receive the greatest reward in the long run.

But before we can improve a policy, we must know how well the current policy performs.

This problem is called **policy evaluation**.

Suppose a robot uses a specific policy to move through a maze.

We want to know:

- How valuable is being in each position?
- If the robot is in a specific state, how much reward does it expect in the future?
- Does the robot's current behavior perform well in the long run?

To answer these questions, we must estimate the value function.

### 2.1. What Is the Prediction Problem?

In this chapter, the prediction problem means estimating the value of a specific policy.

Suppose our policy is fixed:

```math
\pi(a \mid s)
```

That is, the probability of selecting a specific action in a specific state.

The goal is to estimate the state-value function:

```math
V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]
```

In simple terms:

**The value function shows how much return the agent will receive on average if it starts from a specific state and behaves according to a specific policy.**

There are three important points in this definition:

1. The policy is fixed.
2. The environment can be stochastic.
3. The value of a state is the expected return, not the reward received in one particular run.

### 2.2. Difference between Prediction and Control

| Concept | Goal |
| --- | --- |
| Prediction | Evaluating the current policy |
| Control | Finding and improving a policy to achieve better performance |

Example:

- Prediction: Is the robot's current path through the maze appropriate?
- Control: How should we change the robot's path so that it performs better?

Chapter 5 deals mainly with prediction.

Chapter 6 moves into control and policy improvement methods.

## 3. Reward, Return, and Value Function

These three concepts are among the main foundations of the chapter and should not be confused with each other.

### 3.1. Reward

A reward is the reward the agent receives from the environment at a specific time step.

```math
R_{t+1}
```

For example, the robot receives 10 points upon reaching the destination.

This reward belongs to one specific step and does not necessarily reflect the agent's long-term performance.

### 3.2. Return

The return is the sum of future rewards taking the discount factor into account.

```math
G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots
```

Or in general form:

```math
G_t = \sum_{k=0}^{\infty}\gamma^k R_{t+k+1}
```

In this formula:

- `G_t`: the return from time `t`
- `R_{t+k+1}`: the future reward
- `\gamma`: the discount factor
- `k`: the time distance from the current reward

In episodic problems, the return is computed up to the end of the episode.

### 3.3. Discount Factor

The discount factor is denoted by gamma:

```math
0 \leq \gamma \leq 1
```

This factor specifies how much future rewards are worth relative to nearby rewards.

For example, suppose:

- Current reward: 10
- Next step reward: 10
- Gamma: 0.9

Therefore:

```math
G_t = 10 + 0.9(10) = 19
```

If gamma is 0.5:

```math
G_t = 10 + 0.5(10) = 15
```

So the smaller gamma is, the less important more distant rewards become.

| Gamma | Interpretation |
| --- | --- |
| 0 | Only the immediate reward matters |
| Close to 0 | Emphasis on short-term rewards |
| Close to 1 | Greater importance of long-term rewards |
| 1 | No discounting of rewards |

In problems with an infinite horizon, suitable conditions such as bounded rewards and gamma less than one are important for guaranteeing the convergence of the return.

### 3.4. Value Function

The value function is the average, or more precisely the expected value, of the return for a specific state and policy.

```math
V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]
```

Important difference:

- Reward: the reward of one step.
- Return: the sum of discounted rewards along one trajectory.
- Value function: the expected return for a state under a policy.

Example:

Suppose the agent starts from a specific state three times and receives the following returns:

```math
G_1 = 10, \quad G_2 = 20, \quad G_3 = 30
```

A simple estimate of the value function:

```math
V(s) = \frac{10 + 20 + 30}{3} = 20
```

That is, the estimated value of this state is 20.

This example shows why the value function is not the same as the return.

## 4. Random Walk Environment

In this environment:

- The agent is in a state.
- With each move it goes to one of the neighboring states.
- The choice of movement direction can be random.
- Some states are terminal states.
- The agent cannot control the exact outcome of the next move.

### Goal in the Random Walk

The goal is not for the agent to select a specific path; rather, it must estimate the values of different states.

For example, if the agent is in the middle state, it may reach the left or right terminal state in the future.

Therefore, the return can differ.

The agent must estimate the expected return of each state by observing a large number of experiences.

**Key note:** In this environment, the policy can be fixed, and we can study the policy evaluation problem even without complex control choices.

# Part 2: Methods for Estimating Policy Value

## 5. Monte Carlo Methods

Monte Carlo (MC) is one of the methods for estimating the value function that uses the agent's actual experiences to compute the return.

Core idea:

Instead of trying to know all the probabilities and rules of the environment in advance, we let the agent gather experience in the environment and then use the actual outcomes to estimate the values of states.

### 5.1. How Monte Carlo Works

Suppose the agent moves through a maze.

An episode consists of a sequence of experiences:

```math
S_0, A_0, R_1, S_1, A_1, R_2, \ldots, S_T
```

The agent moves until it reaches a terminal state.

Then we compute the return associated with the visits to states and update the estimate of the value function.

General stages:

1. Execute the policy in the environment.
2. Collect a complete episode.
3. Compute the return for the visited states.
4. Update the estimate of the value function.
5. Repeat the process with more episodes.

Important feature of MC:

Monte Carlo, in its usual update form, requires the episode to end; that is, it corrects the estimate after observing the actual outcome of the trajectory.

### 5.2. First-Visit Monte Carlo (FVMC)

First-Visit Monte Carlo considers only the first time in each episode that the agent visits a state.

Suppose the agent's trajectory is:

```math
A \rightarrow B \rightarrow C \rightarrow B \rightarrow D
```

In this episode, the agent has visited the state corresponding to B twice.

In First-Visit MC, only the return associated with the first visit to B is used.

Estimation formula:

```math
V(s) = \frac{1}{N(s)}\sum_{i=1}^{N(s)}G_i(s)
```

where:

- `N(s)`: the number of episodes in which the state was visited at least once.
- `G_i(s)`: the return associated with the first visit to the state in episode number `i`.

Example:

Suppose in three episodes the first returns associated with the state are:

```math
10, \quad 20, \quad 30
```

Then:

```math
V(s) = \frac{10 + 20 + 30}{3} = 20
```

**Note:** If the state is visited several times in one episode, only the first visit in that episode is included in the computation.

### 5.3. Every-Visit Monte Carlo (EVMC)

Every-Visit Monte Carlo, unlike First-Visit, considers all visits to a state in each episode.

For example:

```math
A \rightarrow B \rightarrow C \rightarrow B \rightarrow D
```

Here both visits to B contribute to the estimate of the value of B.

Formula:

```math
V(s) = \frac{1}{N(s)}\sum_{i=1}^{N(s)}G_i(s)
```

The difference from First-Visit lies in the definition of `N(s)` and the set of returns that enter the average:

- In First-Visit, each episode produces at most one sample for each state.
- In Every-Visit, each visit to the state produces one sample.

Example:

Suppose in one episode we have two visits to B:

```math
G_1(B) = 20
```

```math
G_2(B) = 10
```

and in the next episode:

```math
G_3(B) = 30
```

Therefore:

```math
V(B) = \frac{20 + 10 + 30}{3} = 20
```

### 5.4. Diagram Comparing First-Visit and Every-Visit

In this example, the agent's trajectory includes two visits to B:

```text
Episode:
A ---> B ---> C ---> B ---> D ---> Terminal
       |                   |
       |                   |
       v                   v
   First Visit         Second Visit
```

Behavior of the two methods:

```text
First-Visit MC:
A ---> B ---> C ---> B ---> D
       |
       +---- only this visit to B is used


Every-Visit MC:
A ---> B ---> C ---> B ---> D
       |                   |
       +-------------------+
              both visits to B are used
```

### 5.5. Difference between First-Visit and Every-Visit

| Feature | First-Visit MC | Every-Visit MC |
| --- | --- | --- |
| Number of samples per episode | At most one sample per state | All visits |
| Selection criterion | First visit | All visits |
| Computation | Simpler | Requires recording all visits |
| Convergence | Yes | Yes |
| Independence of samples | Samples from each episode may still be dependent | Visits within one episode may be more correlated |

An important correction:

The claim that First-Visit is always faster or more accurate than Every-Visit is not true. Both methods, under suitable conditions and with sufficient experience, can converge to the true value function. Their main difference lies in the sampling method and the statistical properties of the estimates.

Also, Every-Visit is not necessarily more accurate; using more samples alone does not guarantee better accuracy, because different visits within one episode can be correlated.

## 6. Temporal-Difference Learning (TD)

Temporal-difference learning is one of the most important reinforcement learning methods.

This method attempts to combine the advantages of Monte Carlo and dynamic programming.

### 6.1. The Problem with Monte Carlo

Monte Carlo must wait until the end of the episode.

This can be problematic:

- Some episodes are very long.
- Sometimes receiving a reward takes a long time.
- The agent must wait for the end of the trajectory to update.

To solve this problem, temporal-difference learning is used.

### 6.2. Core Idea of TD

In TD, the agent does not need to wait until the end of the episode.

As soon as it takes one step and observes the next state, it can update the value function.

In fact, TD uses two pieces of information:

1. The actual reward received.
2. The current estimate of the value of the next state.

Update formula:

```math
V(S_t) \leftarrow V(S_t) + \alpha[R_{t+1} + \gamma V(S_{t+1}) - V(S_t)]
```

In this formula:

- `V(S_t)`: the estimated value of the current state.
- `R_{t+1}`: the actual reward of the next step.
- `V(S_{t+1})`: the estimated value of the next state.
- `\gamma`: the discount factor.
- `\alpha`: the learning rate.

### 6.3. TD Target

Consider the following part:

```math
R_{t+1} + \gamma V(S_{t+1})
```

This quantity is called the TD target.

That is, the new target the agent considers for estimating the value of the current state.

### 6.4. TD Error

The difference between the TD target and the current value function estimate is called the TD error.

```math
\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)
```

Therefore:

```math
V(S_t) \leftarrow V(S_t) + \alpha\delta_t
```

The TD error shows how much the current estimate differs from the new target.

- If the TD error is positive, the estimated value of the state increases.
- If it is negative, the estimate decreases.
- If it is zero, there is no need to change the estimate at that step.

### 6.5. Numerical TD Example

Suppose:

```math
V(S_t) = 5
```

```math
R_{t+1} = 2
```

```math
V(S_{t+1}) = 8
```

```math
\gamma = 0.9
```

```math
\alpha = 0.1
```

First the TD target:

```math
\text{Target} = 2 + 0.9(8) = 9.2
```

Then the TD error:

```math
\delta_t = 9.2 - 5 = 4.2
```

Now we update the value function:

```math
V(S_t) = 5 + 0.1(4.2)
```

```math
\boxed{V(S_t) = 5.42}
```

That is, the estimated value of the state increases from 5 to 5.42.

### 6.6. What Is Bootstrapping?

One of the very important concepts of this chapter is bootstrapping.

Bootstrapping means using the agent's own current estimates to compute new estimates.

In TD, the agent uses the estimated value of the next state to compute the target.

That is, instead of waiting for the actual return of the entire episode, it performs part of the computation with its own estimate.

Difference:

- Monte Carlo: uses the actual return of a complete episode.
- TD: uses the actual reward and the estimated value function of the next state.

This feature allows TD to learn online and step by step.

## 7. Comparison of Monte Carlo and Temporal-Difference

These two methods are the two main approaches to estimating policy value.

**Monte Carlo:**

1. Execute an episode
2. Wait until the end of the episode
3. Compute the actual return
4. Update the value function

**Temporal-Difference:**

1. Execute one step
2. Receive the reward and the next state
3. Compute the TD target with bootstrapping
4. Update the value function immediately

| Feature | Monte Carlo | TD |
| --- | --- | --- |
| Update time | End of episode | After each step |
| Target | Actual return | Estimate based on reward and value |
| Bootstrapping | No | Yes |
| Bias | The sampled return target is unbiased under suitable conditions | The estimate-based target may be biased |
| Variance | Usually higher | Usually lower |
| Complete episode | Required for the standard method | Not required |

### 7.1. Bias and Variance

These two concepts are essential for understanding the differences among algorithms.

**Bias:**

That is, the algorithm's estimate is systematically distant from the true value.

**Variance:**

That is, how much the estimates vary across different experiences.

For example, suppose the true value of a state is 20.

The first algorithm produces these estimates:

```math
19, \quad 21, \quad 20, \quad 20
```

The second algorithm:

```math
10, \quad 30, \quad 15, \quad 25
```

Both may have a reasonable average, but the second algorithm has greater variance.

In general:

- MC uses the actual return, and under standard conditions its target is unbiased, but its variance can be high.
- TD uses previous estimates; as a result, it may be biased, but it usually has lower variance.

This is the important trade-off that the methods in the next section attempt to manage.

# Part 3: Combined and Multi-Step Methods

## 8. N-Step Temporal-Difference Learning

So far we have examined two methods:

- Monte Carlo: using the entire episode.
- TD: using one step.

But can we examine several future steps instead of one step?

Yes. This idea is the basis of N-step TD.

### 8.1. Concept of N-Step TD

In N-step TD, instead of using only one reward or the entire episode, the agent uses the next N steps.

For example:

- 1-step TD: one future step.
- 2-step TD: two future steps.
- 3-step TD: three future steps.
- N-step TD: a specific number of future steps.

After N steps, the agent uses the estimated value function of the next state to continue the computation.

### 8.2. Structure of N-Step TD

The following diagram shows how N-step TD receives several actual rewards and then continues the computation using the estimated value function:

```text
S_t
 |
 | R_(t+1)
 v
S_(t+1)
 |
 | R_(t+2)
 v
S_(t+2)
 |
 | ...
 v
S_(t+n)
 |
 +---- Bootstrap: gamma^n * V(S_(t+n))
```

Target structure:

```text
N-Step Target
     |
     +---- R_(t+1)
     |
     +---- gamma * R_(t+2)
     |
     +---- ...
     |
     +---- gamma^(n-1) * R_(t+n)
     |
     +---- gamma^n * V(S_(t+n))
```

### 8.3. N-Step Return Formula

```math
G_{t:t+n} = R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1}R_{t+n} + \gamma^n V(S_{t+n})
```

This formula consists of two parts:

1. The sum of the actual rewards over the next N steps.
2. The estimated value of the state after N steps.

The second part is the bootstrapping.

### 8.4. Numerical N-Step TD Example

Suppose:

```math
R_{t+1} = 2
```

```math
R_{t+2} = 3
```

```math
R_{t+3} = 4
```

```math
V(S_{t+3}) = 10
```

and:

```math
\gamma = 0.9
```

In this case N is 3:

```math
G_{t:t+3} = 2 + 0.9(3) + 0.9^2(4) + 0.9^3(10)
```

```math
= 2 + 2.7 + 3.24 + 7.29
```

```math
\boxed{G_{t:t+3} = 15.23}
```

This value is the new target for updating the value of the initial state.

### 8.5. Relationship of N to Monte Carlo and TD

This relationship is one of the most important concepts of the chapter.

```text
1-Step TD                  N-Step TD                 Monte Carlo
    |                          |                          |
    v                          v                          v
1 actual reward         N actual rewards           all actual rewards
+ future estimate       + future estimate           up to the end of the episode
    |                          |                          |
    v                          v                          v
high bootstrapping      intermediate method         no bootstrapping
    |                          |                          |
    +--------------------------+--------------------------+
                               |
                               v
                   Increasing N moves TD
                    closer to Monte Carlo
```

**The N-step TD spectrum**

**1-Step TD**

- High bootstrapping
- Uses one actual reward and one future estimate

**N-Step TD**

- Intermediate method
- Uses several actual rewards and one future estimate

**Monte Carlo**

- No bootstrapping
- Uses the actual return up to the end of the episode

**Conclusion:**

The more N increases, the closer N-step TD gets to Monte Carlo.

Conversely, the smaller N is, the closer the method is to 1-step TD.

As N increases:

- More actual rewards enter the target.
- Dependence on the value function estimate decreases.
- The method approaches Monte Carlo.
- More waiting may be needed to obtain the necessary information.

There is no single optimal value of N that works for all environments, and it must be tested according to the problem.

### 8.6. Handling Terminal States

If the agent reaches a terminal state before N steps, we can no longer use the value function of a next state.

As a result, the target is computed as follows:

```math
G_{t:T} = \sum_{k=0}^{T-t-1}\gamma^k R_{t+k+1}
```

That is, the sum of the remaining rewards up to the end of the episode.

Therefore, in a true terminal state, the future value after the end of the episode is considered zero, and the bootstrapping term is removed.

## 9. Forward-View TD(λ)

This section is one of the important topics of the chapter.

So far we have seen that N-step TD works with a specific value of N.

But what happens if we want to use information from several different N values?

This is where forward-view TD(λ) comes in.

### 9.1. Core Idea

Instead of choosing only one N, we can combine the returns obtained from N-step TD with different weights.

For example:

- 1-step return
- 2-step return
- 3-step return
- ...
- Monte Carlo return

Forward-view TD(λ) combines these returns to build a new estimate.

### 9.2. What Is Lambda?

Lambda is denoted by:

```math
0 \leq \lambda \leq 1
```

This parameter specifies the weight of returns with different time horizons.

In simple terms:

- Lambda close to zero: emphasis on short-term returns.
- Lambda close to one: greater emphasis on long-term returns.

### 9.3. Lambda-Return

The lambda-return formula in the infinite-horizon case is:

```math
G_t^\lambda = (1-\lambda)\sum_{n=1}^{\infty}\lambda^{n-1}G_{t:t+n}
```

This formula is a weighted combination of N-step returns.

In environments with finite episodes, to account for the end of the episode, the precise definition is written as:

```math
G_t^\lambda = (1-\lambda)\sum_{n=1}^{T-t-1}\lambda^{n-1}G_{t:t+n} + \lambda^{T-t-1}G_t
```

where `G_t` is the full Monte Carlo return.

Important note: the sum of the weights equals one.

Therefore, the lambda-return is in fact a combination of short-term, medium-term, and long-term estimates.

### 9.4. Role of Lambda in Combining Methods

| Value of Lambda | Behavior |
| --- | --- |
| 0 | Equivalent to 1-step TD |
| Close to 0 | Emphasis on short-term TD |
| Intermediate values | Combination of several N-step returns |
| Close to 1 | Emphasis on long-term returns |
| 1 | Equivalent to Monte Carlo under a suitable episodic definition |

This relationship holds for the forward view under suitable conditions and definitions.

## 10. TD(λ) and Eligibility Traces

This section presents another way to implement the TD(λ) idea.

In the forward view, we first combine different returns.

But TD(λ), using a structure called eligibility traces, allows updating previous states while the agent is moving.

### 10.1. What Is an Eligibility Trace?

An eligibility trace can be thought of as a kind of short-term memory for recently visited states.

Suppose a robot moves through a maze:

```math
A \rightarrow B \rightarrow C \rightarrow D
```

When the robot is in D, part of the reward it has received may be the result of decisions made in A, B, and C.

If we update only the current state, the information related to previous states is not directly transferred to them at that step.

Eligibility traces solve this problem.

That is, they assign a certain amount of credit or eligibility to recently visited states so that they can be affected by the current TD error.

### 10.2. How Eligibility Traces Work

Each state has an eligibility value.

When the agent enters a new state:

- The eligibility of that state increases.
- The eligibility of previous states decreases.
- The TD error is combined with the eligibility of each state in updating the values of states.

In this way, the effect of recent experiences is also transferred to previous states.

### 10.3. Diagram of Eligibility Trace Propagation

The following diagram shows that over time, the eligibility of a visited state decreases:

```text
State visited
     |
     v
Eligibility = 1.0
     |
     | Multiply by gamma * lambda
     v
Eligibility = 0.72
     |
     | Multiply by gamma * lambda
     v
Eligibility = 0.52
     |
     | Multiply by gamma * lambda
     v
Eligibility = 0.37
```

Time representation:

```text
Time:       t       t+1      t+2      t+3
             |        |        |        |
Trace:      1.00     0.72     0.52     0.37
```

The numbers are hypothetical examples computed under the assumption:

```math
\gamma\lambda = 0.72
```

### 10.4. Eligibility Trace Formula

In the accumulating traces version, the update formula is:

```math
e_t(s) = \gamma\lambda e_{t-1}(s) + \mathbb{1}(S_t = s)
```

where `\mathbb{1}(S_t = s)` is the indicator function:

- If the given state is the current state, its value is 1.
- Otherwise, its value is 0.

Two important parameters in this formula:

- Gamma: the discount factor
- Lambda: the trace-decay parameter

The farther a state is from the time of its visit, the smaller its eligibility becomes, unless it is visited again and its trace value increases.

### 10.5. TD(λ) Update Formula

```math
V(s) \leftarrow V(s) + \alpha\delta_t e_t(s)
```

In this formula:

- `\alpha`: the learning rate
- `\delta_t`: the TD error
- `e_t(s)`: the eligibility trace associated with the state

This formula shows how the current TD error affects different states.

States with greater eligibility experience a greater change in the value function.

### 10.6. Conceptual Example

Suppose the agent has moved through four states:

```math
A \rightarrow B \rightarrow C \rightarrow D
```

Hypothetical eligibility values:

| State | Eligibility |
| --- | --- |
| A | 0.2 |
| B | 0.4 |
| C | 0.7 |
| D | 1.0 |

If the TD error is 2 and the learning rate is 0.1:

For A:

```math
\Delta V(A) = 0.1(2)(0.2) = 0.04
```

For B:

```math
\Delta V(B) = 0.1(2)(0.4) = 0.08
```

For C:

```math
\Delta V(C) = 0.1(2)(0.7) = 0.14
```

For D:

```math
\Delta V(D) = 0.1(2)(1) = 0.2
```

Therefore, different states are updated in proportion to their eligibility.

The numbers in this example are purely to show the computation method and are not the output of a real run of the algorithm.

### 10.7. Relationship of Lambda to TD and Monte Carlo in TD(λ)

This topic is one of the important exam-relevant notes of the chapter.

**When lambda is zero:**

```math
\lambda = 0
```

In this case:

```math
e_t(s) = \mathbb{1}(S_t = s)
```

Therefore, only the current state is updated.

As a result, TD(λ) becomes 1-step TD.

**When lambda is one:**

```math
\lambda = 1
```

Eligibility traces fade more slowly, and the influence of previous states is preserved more.

In standard methods under suitable conditions and episodic updates, TD(1) is related to Monte Carlo in terms of the final targets; however, the two are not necessarily identical in terms of timing and update mechanism.

### 10.8. Forward View and Backward View

These two methods are two different ways of expressing and computing the TD(λ) idea.

```text
Forward View:
Current State
     |
     v
Calculate different N-Step Returns
     |
     v
Weighted Average using Lambda
     |
     v
Lambda-Return
     |
     v
Update Value Function


Backward View:
Current State
     |
     v
Update Eligibility Traces
     |
     v
Calculate TD Error
     |
     v
Update previously visited States
     |
     v
Update Value Function
```

| Feature | Forward View | Backward View |
| --- | --- | --- |
| Computation method | Combining N-step returns | Using eligibility traces |
| Information | Future returns | TD error and memory of previous states |
| Direction of view | Future | Past |
| Use | Explaining the lambda-return | Step-by-step updating |

The key point is that forward view and backward view are two different ways of expressing the TD(λ) idea.

Under suitable conditions they are computationally equivalent; however, the backward view is much more practical for online learning.

# Part 4: Supplementary Notes and Algorithm Details

## 11. Learning Rate and Decay Schedule

In the algorithms of this chapter, the learning rate parameter is denoted by alpha.

```math
0 < \alpha \leq 1
```

The learning rate determines how strongly the current estimate moves toward the new target.

For example:

- Large alpha: faster change of the value function.
- Small alpha: more gradual change of the value function.

### 11.1. Learning Rate Decay

At the beginning of training, the value function estimates may be very inaccurate; therefore, a large learning rate can be useful.

But after gathering more experience, reducing the learning rate helps stabilize the estimates.

A sample decay schedule:

```math
\alpha_k = \frac{1}{k}
```

where `k` is the number of updates or the training step index.

Of course, this is only one example, and choosing an appropriate schedule depends on the algorithm and the convergence conditions.

Note: Reducing the learning rate alone does not guarantee that the algorithm will necessarily converge.

## 12. Time-Step Limit and Terminal State

In real environments, the agent sometimes has a time limit or a limit on the number of steps.

For example:

- The robot must complete the mission in 100 steps.
- The game agent has only limited time to make decisions.
- An episode is stopped due to a computational limit.

These limits affect the computation of the return and the target.

### Difference between Terminal and Truncation

These two concepts should not be confused.

**Terminal State:**

That is, the episode has truly ended.

In this case, the future value after the end of the episode is zero.

**Truncation:**

That is, the execution of the episode has been stopped due to an external limit, but the environment has not necessarily reached a true terminal state.

In this case, if the estimate of the value of the continuation is to be preserved, the value function of the final state must be used.

For N-step TD:

```math
G_{t:t+n} = \sum_{k=0}^{n-1}\gamma^k R_{t+k+1} + \gamma^n V(S_{t+n})
```

If a true terminal state is reached, the last term is removed.

But in truncation, removing it may cause an incorrect estimate of the return.

## 18. Main Formulas of the Chapter

These formulas are the most important ones that a person should be able to explain and use.

**1. Return**

```math
G_t = \sum_{k=0}^{\infty}\gamma^k R_{t+k+1}
```

**2. Value Function**

```math
V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]
```

**3. TD Target**

```math
R_{t+1} + \gamma V(S_{t+1})
```

**4. TD Error**

```math
\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)
```

**5. TD Update**

```math
V(S_t) \leftarrow V(S_t) + \alpha\delta_t
```

**6. N-Step Return**

```math
G_{t:t+n} = \sum_{k=0}^{n-1}\gamma^k R_{t+k+1} + \gamma^n V(S_{t+n})
```

**7. Lambda-Return**

```math
G_t^\lambda = (1-\lambda)\sum_{n=1}^{\infty}\lambda^{n-1}G_{t:t+n}
```

**8. Eligibility Trace**

```math
e_t(s) = \gamma\lambda e_{t-1}(s) + \mathbb{1}(S_t = s)
```

**9. TD(λ) Update**

```math
V(s) \leftarrow V(s) + \alpha\delta_t e_t(s)
```

# 20. Summary of Chapter 5

## The Most Important Idea of the Chapter

The main problem of Chapter 5 is how to estimate the value of an agent's behavior without knowing the complete model of the environment.

We have three main approaches:

**Monte Carlo:** uses the actual outcomes of episodes to estimate value.

**Temporal difference:** uses the actual reward and the estimated value of the next state to update.

**TD(λ):** combines information over several steps with the help of lambda and eligibility traces.

In fact, Chapter 5 answers this question:

**How good is the agent's current behavior?**

And it obtains the answer by estimating the value function and using various policy evaluation algorithms.

**Final note:** Chapter 5 can be considered the foundation for entering control algorithms. In this chapter we learn to estimate the value of the current behavior; in Chapter 6 we will use these estimates to improve the agent's behavior.
