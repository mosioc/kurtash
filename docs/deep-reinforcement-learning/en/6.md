## 2. The Difference Between Prediction and Control

One of the most important concepts in chapter 6 is the difference between the prediction and control problems.

In chapter 5, we mostly dealt with prediction, but in chapter 6 our goal is to solve the control problem.

### 2.1. Prediction Problem

The goal of prediction is to evaluate a specific policy.

That is, we want to know how well the agent will perform if it follows a specific policy.

In this problem, the goal is not to find a better policy. Instead, we want to estimate the value of the existing policy.

Main tools:

- State-Value Function: $V^\pi(s)$
- Action-Value Function: $Q^\pi(s,a)$

### 2.2. Control Problem

The goal of control is to find the best possible policy.

Here, we do not just want to know how good a policy is. We want to improve it to obtain the highest possible return.

For this purpose, we have two processes:

1. Policy Evaluation: evaluating the current policy
2. Policy Improvement: improving the policy based on the obtained information

### Comparison of Prediction and Control

| Feature | Prediction | Control |
| --- | --- | --- |
| Goal | Evaluate a policy | Optimize a policy |
| Focus | Estimate value | Find the best behavior |
| Policy | Fixed or given | Gradually improved |
| Output | Value function | Optimal policy and optimal value function |

**Conceptual relationship:**

```
Prediction Problem
       |
       v

       |
       v
Estimate Value Function

       |
       v
Policy Evaluation
       |
       v
Policy Improvement
       |
       v
Better Policy
       |
       v
Repeat
       |

Optimal Policy
```

Key point:

Prediction tells us how good a policy is. Control tries to find a better policy.

## 3. Why Do We Need the Action-Value Function or Q-Function?

In previous chapters, we became familiar with the state-value function.

But there is a problem: knowing the value of a state does not necessarily tell us which action to choose.

### 3.1. State-Value Function

The function $V^\pi(s)$ shows the expected return if we are in a specific state and follow a specific policy.

$$
V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]
$$

### 3.2. Action-Value Function

The function $Q^\pi(s,a)$ shows the value of choosing a specific action in a specific state.

$$
Q^\pi(s,a) = \mathbb{E}_\pi[G_t \mid S_t = s, A_t = a]
$$

Main difference:

- $V(s)$: the value of being in a state
- $Q(s,a)$: the value of choosing an action in a state

### Example: Chess

Suppose the agent is in a specific position on the chessboard.

- $V(s)$ shows how favorable this position is in general.
- $Q(s,a)$ shows how valuable making a specific move from that position is.

To choose the best move, knowing the value of actions is much more useful.

### 3.3. Why Is the Q-Function Important in Control?

To improve a policy, we must be able to compare different actions.

If we have the Q-function, we can choose the action with the highest estimated value:

$$
\pi(s) = \arg\max_a Q(s,a)
$$

We call this the greedy policy.

Important note:

To use the Q-function and select actions, we do not necessarily need a complete model of the MDP. We can learn Q-values directly from the agent's experiences.

This is why the Q-function is so important in model-free reinforcement learning.

## 4. The Anatomy of a Reinforcement Learning Agent

In section 6.1, the book divides the general structure of an RL agent into three main tasks.

Every agent usually performs three tasks:

1. Gather experience
2. Estimate something
3. Improve a policy

### 4.1. Gather Experience

The agent must collect experience from the environment.

Each experience usually contains the following information:

$$
(S_t, A_t, R_{t+1}, S_{t+1})
$$

That is:

- $S_t$: current state
- $A_t$: chosen action
- $R_{t+1}$: received reward
- $S_{t+1}$: next state

This information helps the agent understand what results its actions have produced.

Experience can be obtained in different ways:

- Direct interaction with the real environment
- Simulation of the environment
- Using a learned model of the environment

For example, to train a robot, we can first use simulation so that the agent learns without damaging the real robot.

### 4.2. Estimate Something

After collecting experience, the agent must estimate something.

This estimation can include the following:

- Value function
- Action-value function or Q-function
- Expected value of different decisions

In this chapter, the main focus is on estimating the Q-function because we need it to select and improve actions.

### 4.3. Improve a Policy

Finally, the agent uses the estimated information to improve the policy.

The policy determines which action the agent should choose in each state.

$$
\pi(a \mid s)
$$

A policy can be deterministic or stochastic.

In a deterministic policy, one specific action is chosen for each state.

In a stochastic policy, the probability of choosing different actions is specified.

### The Main Cycle of an RL Agent

```
       Environment
            |
            v
    Gather Experience
            |
            v
     Estimate Values
            |
            v
     Improve Policy
            |
            v
    Better Decisions
            |
            v
       Environment
            |
            v
          Repeat
```

These three tasks are connected to each other:

- Without experience, there is no information for learning.
- Without estimation, the agent cannot properly compare the value of its decisions.
- Without policy improvement, learning does not necessarily lead to better behavior.

### 4.4. Difference Between Reinforcement Learning and Supervised Learning

In supervised learning, we usually have a ready dataset containing inputs and targets.

The model learns to find the relationship between input and output.

But in reinforcement learning, the agent must also collect the experiences it needs during the learning process.

| Supervised Learning | Reinforcement Learning |
| --- | --- |
| Dataset is provided in advance | Agent collects experience |
| Data is usually fixed | Experiences depend on the agent's decisions |
| Target is known | Feedback is received through reward |
| Learning from samples | Learning from interaction and experience |

**Important note:**

In RL, gathering data (experience gathering) and learning from data (learning) are two different problems.

An agent may perform well in selecting useful experiences but be weak in learning from them, or vice versa.

### 4.5. Difference Between Reinforcement Learning and Dynamic Programming

Dynamic programming usually requires a model of the environment to solve the problem.

This model includes information such as:

- Transition probability
- Reward function

But in many model-free RL algorithms, the agent does not have a complete model of the environment and learns from sampled experiences.

Therefore:

- Dynamic programming: using the environment model for computation and planning
- Model-free RL: learning from experience without needing a complete model of the environment

Of course, RL does not always mean direct interaction with the real world. Simulation and experiences generated from a model can also be used.

## 5. Generalized Policy Iteration (GPI)

The central concept of chapter 6

Generalized Policy Iteration is one of the most important concepts in this chapter.

GPI is a general framework for understanding the structure of reinforcement learning algorithms.

Its main idea is the continuous interaction of two processes:

1. Policy evaluation
2. Policy improvement

### 5.1. Policy Evaluation

In this stage, we evaluate the performance of the current policy.

The goal is to estimate the value function corresponding to the policy.

$$
V^\pi(s)
$$

Or in algorithms based on action-value:

$$
Q^\pi(s,a)
$$

### 5.2. Policy Improvement

In this stage, we use the value function information to improve the policy.

For example, if an action in a specific state has a higher value, we can increase the probability of choosing it.

In the greedy case:

$$
\pi'(s) = \arg\max_a Q^\pi(s,a)
$$

### 5.3. The GPI Cycle

```
       Initial Policy
             |
             v
      Policy Evaluation
             |
             v
      Estimate Value Function
             |
             v
      Policy Improvement
             |
             v
        Better Policy
             |
             v
      Policy Evaluation
             |
             v
           Repeat
             |
             v
       Optimal Policy
```

### 5.4. Relationship of GPI to Policy Iteration and Value Iteration

GPI is a more general framework than a specific algorithm.

**Policy Iteration:**

- First evaluates the policy.
- Then improves the policy.
- Repeats this process.
- In the classic version, policy evaluation is performed completely.

**Value Iteration:**

- Uses an update based on Bellman optimality.
- Instead of fully evaluating the policy at each iteration, it gradually updates the value estimates.
- Policy improvement happens implicitly in this process.

### 5.5. Why Is Policy Evaluation Not Always Performed Completely?

In complex environments, computing the exact value function can be very costly.

Therefore, instead of full evaluation, we sometimes use partial evaluation.

In this method, the policy is evaluated only to some extent and then improved.

Advantages:

- Reduced computation
- Faster policy improvement
- Possibility of gradual learning
- Better suitability for complex environments

### 5.6. Balance Between Evaluation and Improvement

In GPI, two processes interact with each other:

- Evaluation tries to make the value function consistent with the current policy.
- Improvement uses the value function to produce a better policy.

Improving the policy may cause the previous value function to no longer be consistent with the new policy.

Therefore, evaluation must be performed again.

This continuous interaction is the foundation of GPI.

**Important note:** GPI does not necessarily mean performing complete evaluation and then improvement. These two processes can also proceed gradually and simultaneously.

## 6. Exploration and Exploitation in Control

In the control problem, the agent must, in addition to using current information, also examine unknown options.

This is the same exploration and exploitation problem.

### 6.1. Exploration

Exploration means trying different actions to gather more information.

The goal is to discover options that may have higher value.

### 6.2. Exploitation

Exploitation means using current information to choose the best known action.

The goal is to receive the highest reward based on existing knowledge.

### 6.3. Why Is Exploration Essential?

Suppose the agent is in a maze.

If it always chooses the shortest known path, it may never discover that another path exists that produces a higher reward.

So the agent should not always be greedy.

### 6.4. Epsilon-Greedy

One of the simple and widely used methods for balancing exploration and exploitation is the epsilon-greedy algorithm.

In this method:

- With probability $1-\epsilon$, the best known action is chosen.
- With probability $\epsilon$, an action is chosen randomly.

$$
a_t =
\begin{cases}
\text{Random Action} & \text{with probability } \epsilon \\
\arg\max_a Q(s_t, a) & \text{with probability } 1-\epsilon
\end{cases}
$$

For example, if:

$$
\epsilon = 0.2
$$

then:

- 20% probability of exploration
- 80% probability of exploitation

### 6.5. Decaying Epsilon

At the beginning of training, the agent has little information, so more exploration is useful.

As experience increases, the probability of exploration can be reduced.

We call this method decaying epsilon.

```
Training Progress
       |
       v
Early Training
High Epsilon
More Exploration
       |
       v
Middle Training
Lower Epsilon
Balanced Behavior
       |
       v
Late Training
Low Epsilon
More Exploitation
```

Of course, epsilon should not be reduced without considering the conditions of the environment, because reducing it too much can cause the agent to lose the opportunity to discover better actions.

## 7. Control Agents and Model-Free Learning

In this chapter, we become familiar with agents that can directly improve their policy from their own experiences.

### 7.1. Difference Between Model-Based and Model-Free

**Model-Based RL**

The agent uses a model of the environment to predict the results of actions.

This model can describe transitions and rewards.

**Model-Free RL**

The agent directly uses its own experiences to learn the value of actions or the policy.

It does not need to know the transition probability to all next states.

### 7.2. Why Is Model-Free Learning Important?

In many real-world problems, building an accurate model of the environment is very difficult.

For example:

- Robot navigation
- Game playing
- Resource management
- Traffic optimization

In such situations, the agent can be trained with experiences obtained from interaction or simulation.

### 7.3. Decoupling Learning from Behavior

One of the important ideas in this chapter is separating the learning process from the agent's behavior.

This becomes especially important in Q-Learning.

The agent can act with one policy to collect experience but use that experience to learn a different and better policy.

In contrast, on-policy methods such as SARSA use the agent's actual behavior to update estimates.

In the following sections, we will examine this difference more precisely.

## 8. Monte Carlo Control

On-Policy

Episode-Based

Monte Carlo Control is the first main algorithm for solving the control problem in this chapter.

Its goal is to improve the policy through experiences collected in episodes.

### 8.1. Main Idea of Monte Carlo Control

In Monte Carlo Control:

1. The agent moves in the environment using the current policy.
2. A complete episode is executed.
3. The actual return is calculated.
4. The Q-values of visited state-action pairs are updated.
5. The policy is improved.
6. The next episode begins.

The important difference from prediction is that here we use the Q-function estimate to improve the policy.

### 8.2. Why Do We Use the Q-Function?

As we said, to choose the best action, we must compare the value of different actions.

$$
\pi(s) = \arg\max_a Q(s,a)
$$

Therefore, Monte Carlo Control learns action values instead of only estimating state values.

### 8.3. First-Visit Monte Carlo Control

In First-Visit Monte Carlo, each state-action pair in each episode is considered for update only the first time it is visited.

That is:

$$
(S_t, A_t)
$$

is updated only when it is the first occurrence in the episode.

The purpose of this is to use the first visit of each state-action pair in calculating the return.

Note: Being first-visit does not by itself mean definitely preventing overestimation. It is one of the ways to define the Monte Carlo estimate.

### 8.4. Every-Visit Monte Carlo

In Every-Visit Monte Carlo, all visits of a state-action pair in the episode are used to calculate the estimate.

| First-Visit MC | Every-Visit MC |
| --- | --- |
| First visit in the episode | All visits |
| Each pair once per episode | Each pair may be updated multiple times |
| Uses the return of the first visit | Uses the returns of all visits |

### 8.5. Q-Function Update Formula

The Q-value can be estimated by averaging the observed returns:

$$
Q(s,a) = \frac{1}{N(s,a)} \sum_{i=1}^{N(s,a)} G_i
$$

where:

- $N(s,a)$: number of samples used
- $G_i$: observed return in sample number $i$

An incremental update can also be used:

$$
Q_{\text{new}}(s,a) = Q_{\text{old}}(s,a) + \alpha \left[ G_t - Q_{\text{old}}(s,a) \right]
$$

In this formula:

- $\alpha$: learning rate
- $G_t$: actual return
- The difference between the actual return and the previous estimate determines the amount of correction.

### 8.6. Policy Improvement in Monte Carlo Control

After estimating the Q-values, we improve the policy.

But to maintain exploration, we usually use epsilon-greedy.

That is, the agent does not always choose the best known action, and there is still a probability of choosing a random action.

### 8.7. Monte Carlo Control Cycle

```
        Initialize Q
             |
             v
      Initialize Policy
             |
             v
      Start New Episode
             |
             v
       Collect Experience
             |
             v
       Episode Finished?
             |
             v
       Calculate Returns
             |
             v
       Update Q-Values
             |
             v
       Improve Policy
             |
             v
         Next Episode
             |
             v
            Repeat
```

### 8.8. Limitation of Monte Carlo Control

The most important limitation of Monte Carlo is that to calculate the actual return, we must wait until the end of the episode.

This becomes problematic in environments with long episodes or no clear ending.

For example, in controlling a robot, we may want to correct our estimate after each action, rather than waiting until the end of a long path.

This issue motivates the use of Temporal Difference Learning and the SARSA algorithm.

## 9. SARSA: Improving Policies After Each Step

On-Policy

Temporal Difference

SARSA is one of the most important algorithms in chapter 6.

Unlike Monte Carlo, which waits until the end of the episode to update estimates, SARSA can update its learning after each time step.

### 9.1. What Is SARSA?

SARSA is an acronym for the following five components:

- S: State
- A: Action
- R: Reward
- S: Next State
- A: Next Action

These five components are exactly the information used to update the Q-function in SARSA.

### 9.2. How SARSA Works

Suppose the agent is in the current state.

The steps are:

1. Observe the current state $S_t$.
2. Choose the current action $A_t$.
3. Execute the action.
4. Receive the reward.
5. Move to the next state $S_{t+1}$.
6. Choose the next action $A_{t+1}$.
7. Update the Q-function.

The important point is that SARSA uses the actual action chosen in the next state to calculate the target.

### 9.3. SARSA Formula

The SARSA update formula:

$$
Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \left[ R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t) \right]
$$

Components of the formula:

| Symbol | Concept |
| --- | --- |
| $S_t$ | Current state |
| $A_t$ | Current action |
| $R_{t+1}$ | Received reward |
| $S_{t+1}$ | Next state |
| $A_{t+1}$ | Next action |
| $\alpha$ | Learning rate |
| $\gamma$ | Discount factor |
| $Q(S_t, A_t)$ | Current value estimate |
| $Q(S_{t+1}, A_{t+1})$ | Value estimate of the next action |

### 9.4. Temporal Difference Error in SARSA

In SARSA, we first calculate the target:

$$
\text{Target} = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1})
$$

Then we calculate the difference between the target and the current estimate.

This difference is called the Temporal Difference Error or TD Error:

$$
\delta_t = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t)
$$

Finally:

$$
Q_{\text{new}} = Q_{\text{old}} + \alpha \delta_t
$$

**Meaning of TD Error:**

TD Error shows how much the agent's current estimate differs from the new estimate based on experience and future value.

If TD Error is positive, the current estimate increases.

If TD Error is negative, the current estimate decreases.

### 9.5. Why Is SARSA an On-Policy Algorithm?

In SARSA, the agent acts in the environment with one policy, and the same policy is the basis of its learning.

For example, if the agent uses epsilon-greedy, it may choose a random action in the next state.

SARSA places the value of that chosen action in the target.

Therefore, its learning is consistent with the agent's actual behavior.

### 9.6. SARSA Compared with Monte Carlo

| Feature | Monte Carlo Control | SARSA |
| --- | --- | --- |
| Learning type | Episode-based | Step-based |
| Update time | End of episode | After each step |
| Method | Monte Carlo | Temporal Difference |
| Bootstrapping | No | Yes |
| Target | Actual return | Reward and future estimate |
| On/Off-Policy | On-Policy in this method | On-Policy |

### 9.7. Bootstrapping in SARSA

One of the important concepts in this algorithm is bootstrapping.

Bootstrapping means using the current estimate to update another estimate.

In SARSA, instead of waiting for the actual return until the end of the episode, we use the estimated Q-value of the next state and action.

$$
R_{t+1} + \gamma Q(S_{t+1}, A_{t+1})
$$

This feature allows SARSA to learn gradually.

### 9.8. SARSA Cycle

```
       Observe State (S)
              |
              v
       Select Action (A)
              |
              v
        Execute Action
              |
              v
        Receive Reward
              |
              v
        Observe Next State
              |
              v
       Select Next Action
              |
              v
        Calculate TD Error
              |
              v
          Update Q
              |
              v
         Next Step
              |
              v
            Repeat
```

## 10. Q-Learning: Learning to Act Optimally, Even If We Choose Not To

Off-Policy and Temporal Difference

Q-Learning is one of the most important reinforcement learning algorithms.

Its main idea is to learn the optimal action-value function, even if the agent does not always use the best action when collecting experiences.

### 10.1. Main Idea of Q-Learning

In SARSA, the agent used the actual action chosen in the next state for the update.

But in Q-Learning, instead of using the actual next action, the agent considers the maximum estimated Q-value in the next state.

That is:

$$
\max_{a'} Q(S_{t+1}, a')
$$

In other words, Q-Learning assumes that the best possible action will be chosen in the next state.

### 10.2. Q-Learning Formula

$$
Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \left[ R_{t+1} + \gamma \max_{a'} Q(S_{t+1}, a') - Q(S_t, A_t) \right]
$$

The main difference from SARSA is in the target part.

$$
\text{SARSA}: R + \gamma Q(S', A')
$$

$$
\text{Q-Learning}: R + \gamma \max_{a'} Q(S', a')
$$

### 10.3. Why Is Q-Learning an Off-Policy Algorithm?

In Q-Learning, we must distinguish between two policies:

**Behavior Policy**

The policy used to select actions and interact with the environment.

**Target Policy**

The policy used to learn and estimate the value of actions.

In Q-Learning:

- The behavior policy can be epsilon-greedy.
- The target policy is defined as greedy based on the highest Q-value.

Therefore, the agent can choose random actions for exploration but still learn the value of the best possible action.

### 10.4. Difference Between SARSA and Q-Learning

This is one of the most important comparisons in the chapter.

| Feature | SARSA | Q-Learning |
| --- | --- | --- |
| Type | On-Policy | Off-Policy |
| Target | Actual next action | Best next action |
| Exploration | Considered in the target | Not considered in the target |
| Learning | Value of the current policy's behavior | Value of optimal greedy behavior |
| Future formula | $Q(S', A')$ | $\max_{a'} Q(S', a')$ |

### 10.5. A Simple Example of the Difference Between SARSA and Q-Learning

Suppose the agent is in a maze.

There are two paths:

- The first path is short but near a dangerous area.
- The second path is longer but safer.

If the agent uses epsilon-greedy, it may randomly enter the dangerous area while moving along the first path.

**SARSA:**

Uses the actual action chosen in the next state.

Therefore, if exploration causes an inappropriate action to be chosen, this will be reflected in the target and in its learning.

**Q-Learning:**

Uses the best estimated action in the next state.

Therefore, it learns the value of the best path, even if the behavior policy actually chose another action.

As a result, SARSA is sensitive to the actual exploratory behavior, but Q-Learning learns the value of the greedy target policy.

### 10.6. Difference in High-Risk Environments

This difference becomes more important in environments where random actions can have negative consequences.

For example:

- Robot navigation
- Paths near obstacles
- Environments with danger
- Games with heavy penalties

In such environments, SARSA may learn more conservative behavior because it considers the effect of exploration in its update.

Of course, this is a result that depends on the environment and the algorithm's settings, not an absolute rule.

```
       Observe State (S)
              |
              v
       Select Action (A)
         Epsilon-Greedy
              |
              v
        Execute Action
              |
              v
        Receive Reward
              |
              v
        Observe Next State
              |
              v
      Find Maximum Next Q
              |
              v
        Calculate TD Error
              |
              v
          Update Q
              |
              v
         Next Step
              |
              v
            Repeat
```

## 11. On-Policy and Off-Policy

These two concepts are among the most important categories of reinforcement learning algorithms.

### 11.1. On-Policy

In on-policy, the agent learns about the same policy with which it interacts with the environment.

Examples:

- SARSA
- On-Policy Monte Carlo Control

### 11.2. Off-Policy

In off-policy, the agent can collect experience with one policy but learn about another policy.

Examples:

- Q-Learning
- Double Q-Learning

### 11.3. Conceptual Comparison

```
ON-POLICY

Behavior Policy
       |
       v
Interact with Environment
       |
       v
Collect Experience
       |
       v

```

```
OFF-POLICY

Behavior Policy
       |
       v

       |
       v

       |

```

### 11.4. Advantages and Limitations

| On-Policy | Off-Policy |
| --- | --- |
| Learns from the agent's actual behavior | Can learn from different behavior |
| Target is consistent with current behavior | Target can be independent of behavior |

| May be more limited in terms of sampling | Allows using more diverse experiences |

Note: Being off-policy does not mean the algorithm is definitely faster. Convergence speed and stability depend on the environment, the algorithm, exploration, and settings.

## 12. GLIE: Greedy in the Limit with Infinite Exploration

An important theoretical concept

GLIE is one of the important concepts for understanding the convergence conditions of algorithms based on exploration.

GLIE stands for:

**Greedy in the Limit with Infinite Exploration**

This concept has two main conditions:

### 12.1. Infinite Exploration

Over time, the agent must examine all reachable state-action pairs sufficiently and infinitely many times.

That is, it should not ignore some actions forever.

The goal is for the agent to have the opportunity to gather information about all important choices.

### 12.2. Greedy in the Limit

Over time, the policy should move toward choosing the action with the highest estimated value.

In simple terms:

- At first, exploration is greater.
- As experience increases, exploration decreases.
- In the limit, the agent approaches greedy behavior.

### 12.3. Relationship of GLIE to Epsilon-Greedy

One way to implement exploration is to use epsilon-greedy with a decaying epsilon.

But there is a very important point:

Simply reducing epsilon to zero is not sufficient to guarantee GLIE.

To have infinite exploration, the reduction must be such that the probability of choosing different actions still provides enough opportunity for exploration during training.

Theoretically, conditions such as the following are also important for the convergence of Q-Learning:

- All relevant state-action pairs are visited sufficiently.
- The learning rate is appropriate.
- The conditions of the environment and rewards are consistent with the theoretical assumptions of the algorithm.

### 12.4. Comparison of GLIE and Epsilon-Greedy

| Concept | Description |
| --- | --- |
| Epsilon-Greedy | An action selection method |
| Decaying Epsilon | Gradual reduction of exploration |
| GLIE | A set of conditions for exploration and becoming greedy in the limit |

Key point:

GLIE is not an action selection algorithm. It is a property or theoretical condition for exploration behavior.

## 13. Double Q-Learning

Off-Policy

Reducing Maximization Bias

Double Q-Learning is a version of Q-Learning designed to reduce the overestimation problem of action values.

### 13.1. What Is the Problem with Q-Learning?

In Q-Learning, to calculate the target, we use the maximum estimated Q-value in the next state:

$$
\max_{a'} Q(S', a')
$$

But these values are estimates and may contain errors.

The problem is that when we choose the maximum value among several estimates, the probability of selecting an estimate with a positive error increases.

We call this problem maximization bias.

### 13.2. Example of Maximization Bias

Suppose the true value of all actions is zero.

But the agent's estimates, due to estimation error, are as follows:

| Action | Q Estimate | True Value |
| --- | --- | --- |
| A | 0.11 | 0 |
| B | 0.65 | 0 |
| C | -0.44 | 0 |
| D | -0.26 | 0 |

The maximum estimate:

$$
\max(0.11, 0.65, -0.44, -0.26) = 0.65
$$

While the maximum true value is zero.

So the agent mistakenly thinks the best action has a higher value than reality.

This can continue in successive updates and increase value estimates excessively.

### 13.3. The Double Q-Learning Solution

Double Q-Learning uses two independent Q-functions instead of one:

$$
Q_1(s,a)
$$

$$
Q_2(s,a)
$$

Main idea:

One of the Q-functions selects the action, and the other estimates its value.

This prevents action selection and value evaluation from being performed entirely based on a single estimate.

### 13.4. How Double Q-Learning Works

Suppose we want to update $Q_1$.

First, using $Q_1$, we find the best next action:

$$
a^* = \arg\max_{a'} Q_1(S', a')
$$

Then we estimate the value of that action using $Q_2$:

$$
\text{Target} = R + \gamma Q_2(S', a^*)
$$

As a result:

$$
Q_1(S,A) \leftarrow Q_1(S,A) + \alpha \left[ R + \gamma Q_2(S', a^*) - Q_1(S,A) \right]
$$

To update $Q_2$, we perform the same process in reverse:

$$
a^* = \arg\max_{a'} Q_2(S', a')
$$

$$
\text{Target} = R + \gamma Q_1(S', a^*)
$$

### 13.5. Why Do We Have Two Q-Functions?

In ordinary Q-Learning, one function both selects the action and estimates its value.

But in Double Q-Learning, these two roles are divided between two functions.

```
             Q1 Function
                  |
                  v
          Select Best Action
                  |
                  v
             Action (a*)
                  |
                  v
             Q2 Function
                  |
                  v
          Estimate Action Value
                  |
                  v
             Calculate TD
                  |
                  v
              Update Q1
```

In the next update, the roles of the two functions can be reversed.

Usually, a random choice determines which Q-function is updated at each step.

### 13.6. Action Selection for Interaction with the Environment

To select an action when interacting with the environment, we can use the sum or average of the two Q-functions:

$$
\pi(s) = \arg\max_a \left[ Q_1(s,a) + Q_2(s,a) \right]
$$

Since dividing by two does not change the order of actions, using the average or the sum in this selection is equivalent.

### 13.7. Advantages and Limitations of Double Q-Learning

**Advantages:**

- Reduces maximization bias
- Reduces the tendency toward overestimation
- More stable estimates in many environments
- Improved performance compared with Q-Learning in conditions prone to overestimation

**Limitations:**

- Requires maintaining two Q-functions
- Greater computational complexity
- May reduce learning speed or convergence in some environments

Important note: Double Q-Learning does not completely eliminate the overestimation problem. It reduces it.

### 13.8. Difference Between Q-Learning and Double Q-Learning

| Feature | Q-Learning | Double Q-Learning |
| --- | --- | --- |
| Number of Q-functions | One | Two |
| Action selection | One Q | One of the two Qs |
| Action evaluation | The same Q | The other Q |
| Maximization bias | Prone to overestimation | Reduced overestimation |
| Complexity | Lower | Higher |
| Type | Off-Policy | Off-Policy |

### 13.9. Relationship of Double Q-Learning to DDQN

In later chapters of the book, we will become familiar with Double Deep Q-Network or DDQN.

DDQN uses a similar idea to reduce overestimation in deep Q-Learning.

But classic Double Q-Learning should not be considered the same as DDQN. These two algorithms differ in structure and in how they use neural networks.

## 14. Hyperparameters and Important Parameters of the Algorithms

In this chapter, several important parameters are used repeatedly.

### 14.1. Learning Rate or Alpha

$$
\alpha
$$

The learning rate determines how much of the TD Error or the difference between the return and the previous estimate is applied to the Q-value at each update.

- Large alpha: faster changes
- Small alpha: more gradual changes

### 14.2. Discount Factor or Gamma

$$
\gamma
$$

Gamma determines the importance of future rewards.

- Gamma close to zero: greater importance of immediate rewards
- Gamma close to one: greater importance of long-term rewards

### 14.3. Exploration Rate or Epsilon

$$
\epsilon
$$

Epsilon determines the probability of choosing a random action in epsilon-greedy.

- Large epsilon: more exploration
- Small epsilon: more exploitation

### 14.4. Decay Schedule

In this chapter, a decay schedule is used to gradually control the parameters alpha and epsilon.

That is, the initial values gradually move toward minimum values.

| Parameter | Purpose of Decay |
| --- | --- |
| Alpha | Reduce the intensity of updates |
| Epsilon | Reduce exploration and increase greedy behavior |

Of course, reducing the learning rate and epsilon does not necessarily have to follow the same schedule.

### 14.5. Difference Between Alpha and Epsilon

These two parameters should not be confused with each other.

- Alpha determines how much the agent learns and changes the Q-value.
- Epsilon determines how much exploration the agent performs.

In simple terms:

```
Alpha
  |
  v
How much to learn?


Epsilon
  |
  v
How much to explore?
```

## 15. Important Functions in Python Implementation

### 15.1. Decay Schedule Function

This function generates an array of decreasing values.

Its input parameters can include the following:

- Initial value
- Minimum value
- Decay rate
- Maximum steps

This function is used to build the reduction schedule for alpha and epsilon.

### 15.2. Generate Score Trajectory

This function simulates one episode in the environment.

Its output is a set of transitions.

The structure of each transition:

$$
(S_t, A_t, R_{t+1}, S_{t+1}, \text{Done})
$$

where:

- State: current state
- Action: action taken
- Reward: received reward
- Next State: next state
- Done: indicates whether the episode has ended

This function is used to collect experience.

### 15.3. Monte Carlo Control Function

This function executes the main steps of Monte Carlo Control:

1. Run the episode
2. Generate the trajectory
3. Calculate the returns
4. Update the Q-values
5. Apply first-visit or every-visit
6. Improve the policy

### 15.4. Select Action Function

This function decides based on epsilon-greedy:

- Should a random action be selected?
- Or should the best known action be selected?

As a result, it manages exploration and exploitation.

### 15.5. SARSA Control Function

This function at each step:

1. Selects an action.
2. Executes it.
3. Receives the reward.
4. Determines the next state and action.
5. Calculates the TD Error.
6. Updates the Q-function.

### 15.6. Q-Learning Function

The general structure is similar to SARSA, but it uses the maximum Q-value in the next state to calculate the target.

### 15.7. Double Q-Learning Function

This function maintains two Q-functions and at each update updates one of them with the help of the other.

## 17. Batch Learning and Online Learning

This chapter also refers to batch learning.

These two terms refer to how data is used in the learning process.

### Online Learning

In online learning, the agent gradually updates its learning as it receives new experiences.

For example, SARSA can update the Q-value after each step.

### Batch Learning

In batch learning, a set of data is collected and then used to perform learning updates.

This method is suitable when a large dataset is already available.

| Online Learning | Batch Learning |
| --- | --- |
| Gradual learning | Learning with a set of data |
| Continuous updates | Updates with a batch of data |
| Suitable for a stream of new experiences | Suitable for collected datasets |

Note: Batch learning and offline RL are not exactly the same concept. Batch learning refers to the method of updating the model, while offline RL refers to learning from a fixed dataset without new interaction with the environment.

## 18. Stochastic Approximation and Convergence Conditions

One of the important theoretical concepts mentioned in the book's summary is stochastic approximation.

RL algorithms usually use random samples to estimate the value function.

Therefore, the estimates may change at each step.

Stochastic approximation examines the conditions under which these gradual estimates can converge to the expected value or the optimal value.

### Relationship to Learning Rate

In TD-based algorithms, the value of alpha is very important.

One of the classic conditions for convergence in tabular problems, under appropriate assumptions, is:

$$
\sum_{t=1}^{\infty} \alpha_t = \infty
$$

and:

$$
\sum_{t=1}^{\infty} \alpha_t^2 < \infty
$$

These conditions show that:

- The learning rate should not decrease so quickly that the agent does not have enough opportunity to learn.
- The learning rate should decrease enough that the estimates gradually stabilize.

Of course, these conditions alone are not sufficient to guarantee convergence, and other assumptions, such as sufficient visits to state-action pairs, are also important.

# 21. Very Important Points for Learning and Exams

These are points that you should be able to explain without looking at the summary.

**1. What is the goal of control?**

Finding the optimal policy using policy evaluation and policy improvement.

**2. Why do we need the Q-function?**

Because to improve a policy, we must compare the value of different actions in each state.

**3. What is GPI?**

The continuous interaction of policy evaluation and policy improvement to move toward the optimal policy.

**4. What is the difference between Monte Carlo and SARSA?**

Monte Carlo updates after the end of the episode. SARSA updates after each step.

**5. Why is SARSA on-policy?**

Because it uses the actual action chosen by the behavior policy in the target.

**6. Why is Q-Learning off-policy?**

Because it uses the best estimated action for the update, not necessarily the actual chosen action.

**7. What is the most important difference between SARSA and Q-Learning?**

The difference is in their target:

$$
\text{SARSA}: Q(S', A')
$$

$$
\text{Q-Learning}: \max_{a'} Q(S', a')
$$

**8. What is maximization bias?**

Overestimation of action values due to selecting the maximum value among estimates that contain errors.

**9. What problem does Double Q-Learning solve?**

By separating action selection from action evaluation, it reduces the maximization bias problem.

**10. What is GLIE?**

A guarantee of infinite exploration along with the policy becoming greedy in the limit, under appropriate conditions.

# 22. Essential Formulas of Chapter 6

Formula sheet.

**1. State-Value Function**

$$
V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]
$$

**2. Action-Value Function**

$$
Q^\pi(s,a) = \mathbb{E}_\pi[G_t \mid S_t = s, A_t = a]
$$

**3. Greedy Policy**

$$
\pi(s) = \arg\max_a Q(s,a)
$$

**4. Epsilon-Greedy**

$$
P(\text{Random Action}) = \epsilon
$$

$$
P(\text{Greedy Action}) = 1 - \epsilon
$$

**5. Monte Carlo Incremental Update**

$$
Q_{\text{new}} = Q_{\text{old}} + \alpha (G_t - Q_{\text{old}})
$$

**6. SARSA Target**

$$
\text{Target} = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1})
$$

**7. SARSA Update**

$$
Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \delta_t
$$

**8. SARSA TD Error**

$$
\delta_t = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t)
$$

**9. Q-Learning Target**

$$
\text{Target} = R_{t+1} + \gamma \max_{a'} Q(S_{t+1}, a')
$$

**10. Q-Learning Update**

$$
Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \delta_t
$$

**11. Double Q-Learning Target**

$$
a^* = \arg\max_{a'} Q_1(S', a')
$$

$$
\text{Target} = R + \gamma Q_2(S', a^*)
$$

# 23. Final Summary of Chapter 6

Chapter 6 is the point where reinforcement learning moves from evaluating behavior toward optimizing behavior.

At the beginning of the chapter, we learned that an RL agent has three main tasks:

1. Collect experience
2. Estimate values
3. Improve the policy

Then we became familiar with Generalized Policy Iteration, which is the foundation of many RL algorithms. This framework consists of the interaction between policy evaluation and policy improvement.

After that, we examined three important families of control methods:

- Monte Carlo Control: learning from the actual return after the end of the episode.
- SARSA: gradual and on-policy learning using the actual next action.
- Q-Learning: off-policy learning using the best estimated action.

Finally, we examined Double Q-Learning, which reduces the maximization bias problem by using two Q-functions.

**The main message of the chapter in one sentence:**

Reinforcement learning is not just about learning the value of states. The agent must learn how to make the best decisions by collecting experience, estimating the value of actions, and continuously improving the policy.
