# Comprehensive Summary of Chapter 4 of *Grokking Deep Reinforcement Learning*

**Chapter 4: Balancing the Gathering and Use of Information**

The main topic of this chapter is one of the most important challenges in reinforcement learning: how should the agent balance between gathering new information (exploration) and using current knowledge to obtain reward (exploitation)?

To examine this problem, we first become familiar with the Multi-Armed Bandit, and then we examine various exploration algorithms, from simple methods such as Greedy and Epsilon-Greedy to more advanced methods such as Softmax, UCB, and Thompson Sampling.

## 1. The Main Problem of the Chapter: Exploration vs. Exploitation

One of the most fundamental challenges in reinforcement learning is that the agent must decide when to use its current knowledge and when to try actions about which it does not yet have sufficient information in order to obtain new information.

This problem is called the **Exploration-Exploitation Dilemma**.

### 1.1. Exploration

Exploration means the agent tries actions in order to gain more information about the environment.

For example, suppose an agent has three choices and does not yet know which one produces the greatest reward. If it always selects the option that has produced the best result so far, it may never realize that another option is actually better.

Goals of exploration:

- Discovering better options
- Reducing uncertainty about rewards
- Improving estimates of action values
- Gathering information for future decisions

### 1.2. Exploitation

Exploitation means the agent uses its prior information and experiences and selects an action that, according to the current estimate, has the greatest reward.

For example, if the agent has estimated:

| Action | Estimated Value |
| ------ | --------------- |
| A      | 2               |
| B      | 5               |
| C      | 3               |

then in exploitation mode it selects option B.

The goal of exploitation is to use existing knowledge to obtain the greatest reward.

### 1.3. The Conflict between Exploration and Exploitation

The problem is that these two goals are not always compatible with each other.

- If the agent explores too much, it spends a lot of time selecting actions that may have lower rewards.
- If it exploits too much, it may miss the opportunity to discover a better action.

Therefore, the agent must strike a balance between the two.

### Conceptual Relationship between Exploration and Exploitation

```text
                Agent
                  |
        Current Knowledge
                  |
          Decision Making
                  |
          +-------+-------+
          |               |
     Exploration      Exploitation
          |               |
    Try new Actions   Choose best-known
          |               |
    Gather Information  Obtain Reward
          |               |
    Reduce Uncertainty   Use Current Knowledge
          |               |
          +-------+-------+
                  |
          Better Decisions
```

### Exploration

- Goal: gaining new information
- Use: learning about unknown options
- Result: reducing uncertainty about the environment and actions

### Exploitation

- Goal: obtaining reward
- Use: using current knowledge and experience to select the best estimated action
- Result: using existing information to obtain greater reward

The goal is to create a balance between exploration and exploitation appropriate to the amount of information and the conditions of the environment.

**Everyday example:** Suppose you know your favorite dish at a restaurant. Ordering it again is exploitation; trying a new dish is exploration. The new dish might be better, but to find out you must take a risk and gather information.

Important note: Exploration is not the ultimate goal; its purpose is to provide the information needed for more effective exploitation.

## 2. The Challenge of Interpreting Evaluative Feedback

This title is the first section of the chapter.

### 2.1. What Is Evaluative Feedback?

In reinforcement learning, the agent usually does not know all the details of the environment and the consequences of every action from the start. Instead, it acts and then receives a reward from the environment.

This reward is a form of **evaluative feedback**, that is, feedback that tells the agent how good or bad the outcome of its action was.

But there is a fundamental problem:

Receiving a positive reward does not necessarily mean that we have selected the best possible action.

For example:

- Choosing A produced a reward of 5.
- Choosing B produced a reward of 3.

Is A definitely better than B? No. It is possible that the expected reward of B is greater, but the agent has not yet tried it enough.

Therefore, the agent cannot make a definitive judgment about the true quality of actions based solely on observed rewards.

### 2.2. Difference between Evaluative Feedback and a Complete Environment Model

If the agent knows the environment model from the start, it may be able to predict the consequences of actions using the transition function and the reward function.

But in experience-based learning, the agent does not have this information completely and must learn from interaction with the environment.

This situation creates uncertainty.

**Key note:** The agent learns from reward, but reward alone does not specify what the best possible action was.

## 3. Multi-Armed Bandits (MAB)

To examine exploration and exploitation, the book uses a problem called the Multi-Armed Bandit.

### 3.1. Definition of the Multi-Armed Bandit

The Multi-Armed Bandit is a decision-making problem in which the agent chooses among several actions, and each action has an unknown reward distribution.

The name of this problem comes from multi-lever gambling machines.

Imagine a machine with several levers. Each lever has a different probability of paying out a prize, but you do not know these probabilities.

Your task is to find the best option by trying the levers.

### Conceptual Structure of the Multi-Armed Bandit

```text
                   Agent
                     |
              Select an Action
                     |
          +----------+----------+
          |          |          |
       Action A   Action B   Action C
          |          |          |
          v          v          v
      Reward A   Reward B   Reward C
          |          |          |
          +----------+----------+
                     |
                Observe Reward
                     |
              Update Action Value
                     |
              Select Next Action
```

This diagram shows that the agent, by selecting an action, receiving a reward, and updating its estimate, gradually gathers information about the options.

### 3.2. Main Features of the MAB

A simple Multi-Armed Bandit has the following features:

- It has only one state.
- It has several different actions.
- At each step, the agent selects one of the actions.
- After the action is selected, the environment produces a reward.
- The agent uses the observed rewards to estimate the values of actions.

### 3.3. Difference between MAB and MDP

| Feature | Multi-Armed Bandit | MDP |
| ------------- | ------------------------------ | ----------------------------------- |
| Number of states | One state | One or more states |
| Actions | Several choices | Several choices in each state |
| Transition | Usually no state change | Transitions between states |
| Horizon | Usually one decision per episode | Can have multiple time steps |
| Main problem | Selecting the best action | Selecting a sequence of actions |

In the MAB, each decision usually consists of selecting one action and receiving one reward. Unlike typical MDPs, the main problem is not how the agent moves between different states; rather, it is how to estimate the value of the available options and find the best one.

### 3.4. Action Value in the MAB

For each action, we have an estimated value that indicates what reward we expect selecting that action to produce.

This value is called the action value.

```math
Q(a) = \mathbb{E}[R \mid A = a]
```

In this relationship:

- `Q(a)`: the expected value of the action
- `R`: the reward
- `A = a`: selecting the given action
- `\mathbb{E}`: the expected value

In practice, the agent does not know the true value of `Q(a)` and must estimate it from experience.

### 3.5. Estimating Action Value with the Sample Average

One simple method for estimating the value of an action is the average of the rewards received so far from selecting that action.

```math
Q_n(a) = \frac{1}{n} \sum_{i=1}^{n} R_i
```

In this relationship:

- `Q_n(a)`: the estimated value of the action after `n` selections
- `n`: the number of times the action has been selected
- `R_i`: the reward observed in the `i`-th experience

**Example:**

Suppose action A has been selected three times and has produced the following rewards:

```math
R = [2, 4, 6]
```

As a result:

```math
Q(A) = \frac{2 + 4 + 6}{3} = 4
```

Therefore, the agent's estimate of the value of action A is 4.

### 3.6. Incremental Update

Instead of recomputing all averages, the action value can be updated incrementally.

```math
Q_{n+1}(a) = Q_n(a) + \frac{1}{n+1}[R_{n+1} - Q_n(a)]
```

The more general form of this relationship:

```math
Q_{\text{new}} = Q_{\text{old}} + \alpha(R - Q_{\text{old}})
```

where:

- `\alpha`: the learning rate
- `R`: the new reward
- `Q_{\text{old}}`: the previous estimate

In the sample average, the learning rate depends on the number of times the action has been selected; that is, for the update after receiving reward number `n+1`, the learning rate is `1/(n+1)`.

## 4. Regret: The Cost of Exploration

One of the important concepts of this chapter is regret.

### 4.1. Definition of Regret

Regret is the cost or lost opportunity created by selecting a non-optimal action.

In simple terms, regret shows how much reward the agent has lost relative to always selecting the best action, as a result of the choices it has made.

If the best action has a true value `Q^*` and the agent at time `t` selects action `A_t`:

```math
r_t = Q^* - Q(A_t)
```

This value is the expected regret at that step.

Cumulative regret:

```math
R_T = \sum_{t=1}^{T}[Q^* - Q(A_t)]
```

In this relationship:

- `Q^*`: the true value of the best action
- `Q(A_t)`: the true value of the selected action
- `r_t`: the regret at one step
- `R_T`: the total cumulative regret up to time `T`

Note that in this formula, `Q(A_t)` means the true expected value of the selected action, not necessarily the random reward observed at that step.

### 4.2. Why Does Exploration Cause Regret?

Suppose the best action has an expected reward of 10.

To discover other options, the agent selects an action whose expected reward is 6.

At this step:

```math
\text{Regret} = 10 - 6 = 4
```

If the agent repeats this choice several times, the cumulative regret increases.

But this does not mean exploration is bad; because these experiences may lead to discovering a better action in the future.

### 4.3. The Goal of Exploration Algorithms

The goal is not for the agent to have no regret at all; rather, it should reduce regret as much as possible over time.

For this reason, exploration algorithms must balance two things:

1. Gaining new information (exploration)
2. Avoiding too many non-optimal choices (regret reduction)

### Conceptual Example of Regret

Suppose the best action always has an expected reward of 10.

| Action | Expected reward | Regret |
| ------ | ---------------- | ------ |
| A | 10 | 0 |
| B | 7 | 3 |
| C | 4 | 6 |

Formula:

```text
Regret = Optimal Expected Reward - Selected Action's Expected Reward
```

For example, for action B:

```text
Regret = 10 - 7 = 3
```

The numbers are purely for illustration; the best action in this example is A.

## 5. Approaches to Solving MAB Environments

There are several different approaches to solving the Multi-Armed Bandit.

In this chapter, simple methods are examined first, and then algorithms are introduced that manage exploration more intelligently.

Three basic approaches for understanding the problem:

1. Greedy: exploitation only
2. Random: exploration only
3. A combination of exploration and exploitation, such as Epsilon-Greedy

Then methods based on estimation and uncertainty are examined.

### 5.1. Greedy: Always Exploit

In the greedy method, the agent always selects the action with the highest estimated action value.

```math
A_t = \arg\max_a Q_t(a)
```

For example:

| Action | Estimated Value |
| ------ | --------------- |
| A | 4 |
| B | 7 |
| C | 5 |

The agent always selects action B.

**Advantages:**

- Simple and fast
- Uses the best available knowledge
- No need for an exploration parameter

**Disadvantages:**

- It may become attached to one action too early.
- It does not examine unknown options.
- It may get stuck in a non-optimal solution.

For example, if action B initially produces a good reward, the agent may keep selecting it even if action A is actually better.

This problem can be described with the concept of premature convergence.

### 5.2. Random: Always Explore

In the random method, the agent selects an action randomly without regard to the estimated action value.

```math
P(A_t = a) = \frac{1}{|\mathcal{A}|}
```

That is, the probability of selecting each action is the same.

For example, if we have three actions:

```math
P(A) = P(B) = P(C) = \frac{1}{3}
```

**Advantages:**

- All actions have a chance to be selected.
- It does not depend on initial estimates.
- There is a chance of discovering unknown options.

**Disadvantages:**

- It does not use prior knowledge.
- It selects randomly even after identifying the best action.
- It may produce a lot of regret.

**Conclusion:** Greedy and random are two opposite extremes; one uses only current knowledge, and the other almost ignores it.

## 6. Epsilon-Greedy

One of the most famous exploration methods in reinforcement learning.

### 6.1. Core Idea

Epsilon-Greedy is a combination of greedy and random.

Most of the time, the agent selects the best estimated action, but occasionally it selects an action randomly.

The main parameter of this algorithm:

```math
\epsilon \in [0, 1]
```

which is called epsilon.

The action selection rule:

- With probability `1 - \epsilon`: select the greedy action
- With probability `\epsilon`: select a random action

### Epsilon-Greedy Decision Structure

```text
                Start
                  |
           Generate Random
              Number
                  |
             Is random
             < epsilon?
              /     \
            Yes      No
             |        |
             v        v
        Random     Greedy
        Action     Action
             |        |
             +---+----+
                 |
             Observe
              Reward
                 |
          Update Q-Value
                 |
              Repeat
```

### 6.2. Epsilon-Greedy Formula

```math
A_t =
\begin{cases}
\text{Random Action} & \text{with probability } \epsilon \\
\arg\max_a Q_t(a) & \text{with probability } 1 - \epsilon
\end{cases}
```

**Example:**

Suppose:

```math
\epsilon = 0.1
```

As a result:

- 90% of the time the agent acts greedily.
- 10% of the time the agent enters the random selection stage.

### 6.3. Important Note about Epsilon

A common mistake is to think that if `\epsilon = 0.5`, the agent selects a non-optimal action exactly 50% of the time.

This interpretation is not correct.

In the exploration stage, the agent selects randomly from among all actions; therefore, the greedy action itself may also be selected.

If `k` is the number of actions and only one action is considered greedy, then in the no-tie case:

```math
P(\text{Non-greedy}) = \epsilon\left(1 - \frac{1}{k}\right)
```

For example, if we have two actions and `\epsilon = 0.5`:

```math
P(\text{Non-greedy}) = 0.5(1 - 0.5) = 0.25
```

So the probability of selecting a non-optimal action is 25%, not 50%.

### 6.4. Choosing an Appropriate Value of Epsilon

- Large epsilon: more exploration
- Small epsilon: more exploitation
- Epsilon equal to zero: greedy behavior
- Epsilon equal to one: random selection

The value of epsilon must be set in accordance with the problem and the amount of information the agent has.

## 7. Decaying Epsilon-Greedy

One problem with fixed Epsilon-Greedy is that the amount of exploration does not change over time.

But usually the agent has little information at the beginning of learning and should explore more. After gaining experience, it can exploit more.

This is where decaying Epsilon-Greedy comes in.

### 7.1. Core Idea

In this method, the value of epsilon gradually decreases.

```math
\epsilon_t \downarrow
```

At the beginning of training:

- Exploration is high.
- The agent tries different options.

Later:

- Exploration decreases.
- The agent makes more use of the gathered information.

### 7.2. Linear Decay

In linear decay, epsilon decreases at a constant rate.

A common formula:

```math
\epsilon_t = \max(\epsilon_{\min}, \epsilon_0 - kt)
```

where:

- `\epsilon_0`: the initial value
- `k`: the decay rate
- `\epsilon_{\min}`: the minimum allowed value
- `t`: time or episode number

**Example:**

Suppose:

```math
\epsilon_0 = 1
```

```math
\epsilon_{\min} = 0.1
```

Over time, the value of epsilon decreases linearly and remains at 0.1 after reaching it.

### 7.3. Exponential Decay

In exponential decay, the value of epsilon decreases exponentially.

```math
\epsilon_t = \max(\epsilon_{\min}, \epsilon_0 e^{-kt})
```

In this relationship:

- `e`: Euler's number
- `k`: the decay rate
- `t`: time

In this method, epsilon decreases faster at the beginning and then gradually more slowly.

### Comparison of Linear and Exponential Epsilon Decay

In linear decay, the value of epsilon decreases at a constant rate.

In exponential decay, the value of epsilon decreases faster at the beginning and then gradually more slowly.

**Linear Decay:**

```text
Epsilon
  1.0 |\
      | \
      |  \
      |   \
      |    \
      |     \
  0.1 |______\____________
      |
      +--------------------> Time
```

**Exponential Decay:**

```text
Epsilon
  1.0 |\
      | \
      |  \
      |   \__
      |      \____
      |           \____
  0.1 |____________________
      |
      +--------------------> Time
```

These diagrams are schematic, and the exact shape of the curve depends on the decay parameters.

### Formulas

Linear decay:

```text
ε(t) = max(ε_min, ε_0 - k × t)
```

Features:

- Constant rate of decrease
- Predictable decay trend
- Simple control of the amount of exploration

Exponential decay:

```text
ε(t) = max(ε_min, ε_0 × e^(-k × t))
```

Features:

- Faster decrease at the beginning of learning
- Slower decrease later
- Gradual approach to the minimum epsilon

### Sample Comparison

| Episode | Linear Decay | Exponential Decay |
| ------- | ------------ | ----------------- |
| 0 | 1.00 | 1.00 |
| 1 | 0.90 | 0.74 |
| 2 | 0.80 | 0.55 |
| 3 | 0.70 | 0.41 |
| 4 | 0.60 | 0.30 |
| 5 | 0.50 | 0.22 |
| 6 | 0.40 | 0.17 |
| 7 | 0.30 | 0.13 |
| 8 | 0.20 | 0.10 |
| 9 | 0.10 | 0.10 |

These numbers are a demonstration example, and the actual shape of the curve depends on the decay parameters.

### 7.4. Advantages and Limitations

**Advantages:**

- Exploration is greater at the beginning of training.
- Later, the agent moves toward exploitation.
- It has a simple implementation.

**Limitations:**

- Choosing an appropriate decay rate is very important.
- Fast decay may prevent the agent from discovering better options.
- Excessive reduction of epsilon may almost stop exploration.

Note: Reducing epsilon does not necessarily mean improving the estimates; it only changes the probability of random selection.

## 8. Optimistic Initialization

### 8.1. Core Idea

Optimistic initialization is a simple method for encouraging exploration.

In this method, at the beginning the agent initializes the action values with optimistic and relatively large values.

That is, it assumes that all actions initially have high potential.

Why does this encourage exploration?

Because the agent initially has no real information. If the estimated value of all actions is high, then after selecting an action and receiving a reward, the estimated value of that action may decrease.

As a result, other actions that have not yet been tried will still have high estimated values and will be more likely to be selected.

### 8.2. Example

Suppose we have three actions:

| Action | Initial Value |
| ------ | ------------- |
| A | 10 |
| B | 10 |
| C | 10 |

The agent first selects A and receives a reward of 3.

Assuming sample average updating with one observation, the estimate of A becomes 3:

```math
Q(A) = 3
```

But the estimates of B and C are still 10.

Therefore, the agent will most likely go for B or C.

### The Process of Optimistic Initialization

```text
Initial Q-Values
       |
       v
+------+------+------+
| Q(A) | Q(B) | Q(C) |
|  10  |  10  |  10  |
+------+------+------+
       |
       v
   Select A
       |
       v
   Observe R = 3
       |
       v
   Update Q(A)
       |
       v
+------+------+------+
| Q(A) | Q(B) | Q(C) |
|   3  |  10  |  10  |
+------+------+------+
       |
       v
 Select B or C
```

In this way, optimistic initialization can create exploration.

### 8.3. Advantages

- Simple and easy to implement
- No need for constant random exploration
- Encourages the agent to try different actions

### 8.4. Limitations

- It depends on the initial values.
- If the initial values are too large, learning may become unbalanced.
- In non-stationary environments or environments where action values change, it is not a complete solution on its own.

**Important note:** Optimistic initialization is a method based on optimism in initial estimates; it should not be equated with UCB. UCB dynamically takes uncertainty and the number of times an action has been selected into account in decision-making.

## 9. Strategic Exploration

So far, we have examined methods that mainly perform exploration through randomness.

But an important question remains:

Would it not be better for the agent to also pay attention to the quality of its estimates when selecting randomly?

For example, if action A has an estimate of 9 and action B has an estimate of 1, it is not logical for the probability of selecting both to be completely equal.

In the second part of the chapter, three more important methods for exploration are examined:

1. Softmax
2. Upper Confidence Bound (UCB)
3. Thompson Sampling

The important difference among these methods lies in how they use action value estimates and information about uncertainty.

### 9.1. Softmax: Select Actions Randomly in Proportion to Their Estimates

#### Core Idea

In Epsilon-Greedy, during the exploration stage the agent selects randomly from among the actions.

But Softmax determines the probability of selecting each action in proportion to its estimated value.

That is:

- An action with a higher estimate has a higher probability of being selected.
- An action with a lower estimate has a lower probability of being selected.
- Unlike greedy, other actions still have a chance of being selected.

#### Softmax Formula

```math
P(A_t = a) = \frac{\exp(Q_t(a)/\tau)}{\sum_{b \in \mathcal{A}} \exp(Q_t(b)/\tau)}
```

In this formula:

- `P(A_t = a)`: the probability of selecting the given action
- `Q_t(a)`: the estimated value of the action
- `\exp`: the exponential function
- `\tau`: temperature
- `\mathcal{A}`: the set of all actions

#### What Is Temperature?

Temperature is a parameter that controls the degree of randomness in action selection.

**High temperature:**

- The probabilities of selecting the actions become closer to each other.
- Exploration increases.
- The difference in estimated action values has less influence on selection.

**Low temperature:**

- The probability of selecting the action with the higher estimated value increases.
- Selections move more toward greedy.
- Exploitation increases.

### Effect of Temperature on Selection Probability in Softmax

Temperature is denoted by `τ` and controls the degree of randomness in action selection.

Softmax formula:

```text
P(A=a) = exp(Q(a)/τ) / Σ exp(Q(b)/τ)
```

Suppose we have three actions with the following values:

- Action A: Q = 1
- Action B: Q = 2
- Action C: Q = 3

With temperature equal to 1:

| Action | Action Value | Probability |
| ------ | ------------ | ----------- |
| A | 1 | 9.0% |
| B | 2 | 24.5% |
| C | 3 | 66.5% |

### Conceptual Illustration of the Effect of Temperature

```text
Low Temperature (small τ)
--------------------------------
Action A  | *
Action B  | ***
Action C  | ***************

More focus on the action with the higher Q


High Temperature (large τ)
--------------------------------
Action A  | ********
Action B  | **********
Action C  | ************

Probabilities closer to each other
```

This diagram is only schematic, and the lengths of the bars do not represent the actual probability values.

- Low temperature: the probability of selecting the action with the highest value increases, and behavior approaches greedy.
- High temperature: the probabilities of selecting the actions become closer to each other, and exploration increases.

In summary:

- `\tau \rightarrow 0`: selection approaches greedy.
- Small `\tau`: more focus on high-value actions.
- Large `\tau`: more random selection.
- `\tau \rightarrow \infty`: the probabilities of selecting the actions become almost equal.

#### Advantages

- Uses action values in random selection
- Allows non-optimal actions to be selected with a controlled probability
- Creates a balance between exploration and exploitation

#### Limitations

- Choosing an appropriate temperature is very important.
- Softmax by itself does not model uncertainty in the estimates.
- The magnitude of action values can affect the probabilistic behavior.

**Important note:** Softmax decides based on the estimated value of actions, not based on how confident the agent is in those estimates.

### 9.2. Upper Confidence Bound (UCB)

#### Core Idea

UCB is one of the important methods of strategic exploration.

In the previous methods, the agent mainly used the estimated action value. But the problem is that the estimate of an action may not yet be accurate.

For example:

- Action A: estimate 8, with 100 experiences
- Action B: estimate 7, with 2 experiences

If we look only at the estimated value, A seems better.

But we have much less information about B. Perhaps B is actually better than A.

To solve this problem, UCB takes into account not only the estimated value but also the degree of uncertainty.

#### What Is a Confidence Bound?

A confidence bound refers to a range in which, given the observed data, we expect the true value to lie.

In UCB, instead of selecting solely based on the current estimate, a bonus is added to the action's estimate.

This bonus is given to actions that have been tried less often.

#### UCB Formula

The common UCB1 formula:

```math
UCB_t(a) = Q_t(a) + c\sqrt{\frac{\ln t}{N_t(a)}}
```

In this relationship:

- `Q_t(a)`: the estimated value of the action
- `c`: the parameter controlling the amount of exploration
- `t`: the total number of selections up to the current time
- `N_t(a)`: the number of times the action has been selected
- `\ln`: the natural logarithm

There are two main parts:

```math
\underbrace{Q_t(a)}_{\text{Exploitation}} + \underbrace{c\sqrt{\frac{\ln t}{N_t(a)}}}_{\text{Exploration Bonus}}
```

#### UCB Decision Structure

```text
              For Each Action
                     |
          +----------+----------+
          |                     |
          v                     v
   Estimated Value        Exploration Bonus
       Q(a)               c × √(ln(t)/N(a))
          |                     |
          +----------+----------+
                     |
                     v
                  UCB Score
                     |
                     v
             Compare All Actions
                     |
                     v
             Select Highest UCB
                     |
                     v
              Observe Reward
                     |
                     v
               Update Q-Value
                     |
                     v
                   Repeat
```

This diagram shows how UCB combines the two components of exploitation and exploration.

#### How Does the Exploration Bonus Work?

Pay attention to the formula:

```math
c\sqrt{\frac{\ln t}{N_t(a)}}
```

If an action has been selected less often, `N_t(a)` is smaller and the exploration bonus becomes larger.

As a result:

- Less-tried actions become more attractive.
- More-tried actions receive a smaller bonus.
- The agent gradually gathers more information about the different options.

#### Example

Suppose we have two actions:

| Feature | Action A | Action B |
| ----------------- | -------- | -------- |
| Estimated Value | 8 | 7 |
| Number of selections | 100 | 2 |
| Exploration Bonus | 0.2 | 2 |
| UCB Score | 8.2 | 9 |

Although the estimated value of A is higher, the UCB score for B becomes higher.

So the agent may select B, because it does not yet have enough information about it.

These values are a simplified numerical example; the actual bonus must be computed using the formula and the algorithm's parameters.

The Upper Confidence Bound (UCB) algorithm uses two components for action selection:

### 1. Estimated Action Value

`Q(a)`

Represents the expected reward from selecting the action.

This part corresponds to exploitation, that is, using the agent's current knowledge.

### 2. Exploration Bonus

`Exploration Bonus`

An additional value assigned to less-examined actions.

This part corresponds to exploration, that is, encouraging the agent to examine options about which it has less information.

### 3. UCB Score

Formula:

`UCB(a) = Q(a) + Exploration Bonus`

Common UCB1 formula:

`UCB_t(a) = Q_t(a) + c × √(ln(t) / N_t(a))`

At each step, the agent selects the action with the highest UCB score.

Therefore:

- A higher estimated action value strengthens exploitation.
- A higher exploration bonus strengthens exploration.
- The sum of the two determines the final UCB score.

#### Difference between UCB and Optimistic Initialization

These two methods are conceptually similar, since both use optimism to encourage exploration.

But their difference is important:

| Optimistic Initialization | UCB |
| --------------------------------------- | -------------------------------------------------- |
| Sets the initial estimate optimistically. | Computes an exploration bonus at each step. |
| The optimism is in the initial values. | The optimism changes based on the number of selections and time. |
| It is a simpler method. | It uses experience information dynamically. |

**Advantages:**

- Uses both the estimated value and uncertainty
- Encourages selecting less-examined actions
- Creates a systematic balance between exploration and exploitation

**Limitations:**

- Requires tuning the parameter `c`
- Depends on mathematical assumptions and the conditions of the problem
- In non-stationary environments, the basic version may not be suitable.

### 9.3. Thompson Sampling: Balancing Reward and Risk

#### Core Idea

Thompson Sampling is a Bayesian method for exploration.

In this method, instead of having only a fixed estimate for the value of each action, the agent maintains a probability distribution of its belief about the value of that action.

It then samples from these distributions and selects the action whose sample has the greatest value.

In simple terms:

Instead of only asking "which action is the best?", the agent asks:

"If the true values of the actions were in accordance with my current belief, which action should I select?"

#### What Is Bayesian Inference?

In the Bayesian method, the agent has a prior belief about a parameter and updates its belief as it observes new data.

Two main concepts:

- Prior: the initial belief about the parameter
- Posterior: the updated belief after observing the data

Bayes' formula:

```math
P(\theta \mid D) = \frac{P(D \mid \theta)P(\theta)}{P(D)}
```

where:

- `\theta`: the unknown parameter
- `D`: the observed data
- `P(\theta)`: the prior
- `P(\theta \mid D)`: the posterior
- `P(D \mid \theta)`: the likelihood

#### Stages of Thompson Sampling

1. For each action, maintain a probability distribution about its reward.
2. Take a sample from the distribution of each action.
3. Select the action whose sample is larger.
4. Receive the actual reward from the environment.
5. Update the distribution of the selected action using the new data.
6. Repeat this process.

### Thompson Sampling Cycle

```text
        Maintain Beliefs
               |
               v
        Sample from Each
        Action Distribution
               |
               v
        Compare Samples
               |
               v
        Select Highest Sample
               |
               v
        Execute Selected Action
               |
               v
        Observe Reward
               |
               v
        Update Posterior
               |
               v
          Repeat Cycle
```

1. **Maintain Beliefs**

   Maintaining a belief distribution for each action
2. **Sample**

   Sampling from the distribution of each action
3. **Select**

   Selecting the action with the largest sample
4. **Observe Reward**

   Receiving the reward from the environment
5. **Update Posterior**

   Updating the belief using the new experience
6. **Repeat**

   Repeating the process

#### Simple Example

Suppose we have two actions:

- Action A: unknown probability of success
- Action B: unknown probability of success

The agent has a probability distribution for each action.

At one step, the sample for action A may be 0.8 and the sample for action B may be 0.6.

So A is selected.

But at the next step, with new sampling, B may take a higher value and be selected.

These changes in selection allow the agent to both make use of promising options and examine other options.

#### Gaussian Distribution

In the book's explanation, the Gaussian distribution is used for sampling in the Thompson Sampling examples.

```math
X \sim \mathcal{N}(\mu, \sigma^2)
```

In this relationship:

- `\mu`: the mean of the distribution
- `\sigma^2`: the variance
- `\sigma`: the standard deviation

If the uncertainty about an action is greater, its distribution can be wider.

As a result, it produces more varied samples, and the probability of selecting that action can also change.

#### Beta Distribution

The Beta distribution is a common choice for Bernoulli bandit problems.

```math
X \sim \text{Beta}(\alpha, \beta)
```

In this distribution:

- `\alpha`: the parameter associated with evidence of success
- `\beta`: the parameter associated with evidence of failure

In the simple Bernoulli bandit case, if the prior is `\text{Beta}(\alpha_0, \beta_0)` and we observe `s` successes and `f` failures:

```math
\alpha = \alpha_0 + s
```

```math
\beta = \beta_0 + f
```

This update causes the agent's belief distribution to change with new experiences.

**Important note about the book:** The author uses Gaussian in the educational example, but the Beta distribution is more common for many Bernoulli bandit problems. So we should not assume that Thompson Sampling only works with Gaussian.

#### Advantages

- Uses uncertainty in decision-making
- Creates exploration without the need for a fixed epsilon
- Updates beliefs with new experiences
- Ability to select unknown but promising options

#### Limitations

- Requires choosing an appropriate prior
- Requires maintaining and updating probability distributions
- More complex than Epsilon-Greedy
- Depends on the chosen probabilistic model

### 11.1. Two-Armed Bernoulli Bandit

In this environment there are two actions.

For example:

- Action A: probability of success 0.4

In this environment there are ten different actions, and the reward of each action is generated from a Gaussian distribution.

### 11.3. Evaluation Metrics

The following metrics can be used to examine the performance of the algorithms:

**Average Reward**

The average reward received by the agent:

```math
\bar{R} = \frac{1}{T}\sum_{t=1}^{T}R_t
```

The larger this value, the greater the average reward the agent has received.

**Cumulative Reward**

The sum of rewards over the run:

```math
G_T = \sum_{t=1}^{T}R_t
```

**Cumulative Regret**

The sum of lost opportunities compared to the best action:

```math
R_T = \sum_{t=1}^{T}[Q^* - Q(A_t)]
```

The smaller the regret, the better the agent has performed in terms of selecting near-optimal actions.

### 11.4. Important Note on the Experiment Results

One important result in the examinations of this chapter is that more complex algorithms are not always better than simpler methods.

For example, in some of the tested environments, Epsilon-Greedy with appropriate tuning can perform very well.

Therefore:

- Greater complexity does not necessarily mean better performance.
- The choice of algorithm depends on the type of environment.
- Hyperparameters play an important role in performance.
- An algorithm may be excellent in one environment and weak in another.

This is one of the reasons for the importance of empirical testing and evaluation in reinforcement learning.

## 12. Final Summary of the Chapter

The main message of Chapter 4 is that, to achieve better performance, the agent must learn when to gather new information and when to use its current information to obtain reward.

This problem arises because, in unknown environments, the agent does not know the complete model of the environment and the true values of actions.

Therefore, it must estimate the values of the options through interaction and receiving rewards.

The methods introduced in the chapter can be divided into three general groups:

**Group 1: Basic methods**

- Greedy
- Random
- Epsilon-Greedy

These methods are the foundation for understanding exploration and exploitation.

**Group 2: Methods for improving exploration**

- Decaying Epsilon-Greedy
- Optimistic Initialization

These methods attempt to manage exploration in accordance with the stage of learning or the initial estimates.

**Group 3: Strategic exploration**

- Softmax
- UCB
- Thompson Sampling

These methods use information about action values, uncertainty, or belief distributions to make better decisions.
