## 1. Difference Between Value-Based and Policy-Based Methods

To understand the chapter, we must first know the difference between the two main approaches in reinforcement learning.

### 1.1. Value-Based Methods

In these methods, the agent first learns the value of a state or action and then makes a decision based on it.

For example, in DQN:

- The neural network receives a state.
- It estimates a Q-value for each action.
- The agent usually selects the action with the highest Q-value.

```
State
  |
  v
Neural Network
  |
  v
Q-Values
  |
  v
Action Selection
  |
  v
Action
```

The main goal is to learn the value function:

$$
Q(s,a)
$$

That is, if we are in state $s$ and choose action $a$, what return do we expect to receive?

### 1.2. Policy-Based Methods

In these methods, the agent directly learns a policy.

Instead of first computing the value of all actions, it directly learns what action to take in each state.

```
State
  |
  v
Policy Network
  |
  v
Action Probabilities
  |
  v
Action Selection
  |
  v
Action
```

The policy function is represented as follows:

$$
\pi(a \mid s)
$$

This function specifies the probability of choosing action $a$ when in state $s$.

For example:

```
State: Robot is near an object

Policy Network:

Move Left   = 0.10
Move Right  = 0.65
Move Forward= 0.20
Stop        = 0.05

Selected Action: Move Right
```

Here, the agent has directly learned the probability distribution over actions.

### 1.3. Comparison of the Two Approaches

| Feature | Value-Based | Policy-Based |
| --- | --- | --- |
| Learning goal | Value function | Policy |
| Network output | Action values | Policy or action probability distribution |
| Action selection | Based on Q-value | Based on policy |
| Action space | Usually discrete | Discrete and continuous |
| Stochastic behavior | Usually with a separate exploration method | Can be inherent in the policy |
| Example algorithm | DQN | REINFORCE |

**Important note:** In value-based methods, the policy is usually derived from the value function, but in policy-based methods, the policy itself is directly parameterized and optimized.

## 2. Policy-Based Methods and Their Advantages

Policy-based methods are a family of algorithms that directly optimize the policy.

### 2.1. Why Do We Need Policy-Based Methods?

Suppose a robot must control its arm.

In this problem, the actions can include the following:

- The rotation angle of the joints
- The movement speed of the arm
- How much the gripper opens and closes
- The amount of force applied to the object

If the action space is continuous, the number of possible actions can be very large or even unlimited.

In value-based methods, finding the best action among all these possibilities is difficult.

But in policy-based methods, the network directly learns what action to take given the current state.

### 2.2. Advantages of Policy-Based Methods

**1. Support for continuous action spaces**

These methods can directly produce actions with continuous values.

For example:

```
Robot State
    |
    v
Policy Network
    |
    v
Continuous Action
    |
    +--> Joint Angle: 0.72
    +--> Movement Speed: 0.35
    +--> Grip Force: 0.81
```

**2. Learning stochastic policies**

The policy can learn the probability of different actions instead of deterministically selecting one action.

This feature is useful in problems with uncertainty and incomplete information.

**3. Direct learning of desired behavior**

It is not always necessary to first learn an accurate value function.

In some problems, directly learning the desired action is simpler than estimating the value of all states and actions.

**4. Ability to learn multimodal policies**

Sometimes several different actions can produce good results.

For example, a robot may be able to pass an obstacle from the left or the right.

A stochastic policy can learn both behaviors with appropriate probabilities.

### 2.3. Disadvantages of Policy-Based Methods

- They may have high variance in the gradients.
- Training them can require many samples.
- They are sensitive to the choice of learning rate and other hyperparameters.
- They may reach a local optimum during optimization.
- Evaluating the quality of a policy can be difficult.

Note: Policy-based methods are not always better than value-based methods. The choice of method depends on the type of environment, the action space, computational constraints, and the goal of the problem.

## 3. Parameterized Policy

One of the fundamental concepts of this chapter is the parameterized policy.

In this method, the policy is represented with a set of parameters.

Instead of defining all decisions manually, we use a parametric model, usually a neural network.

Mathematical representation:

$$
\pi_\theta(a \mid s)
$$

where:

- $\pi$: the policy function
- $\theta$: the model parameters
- $s$: the environment state
- $a$: the action
- $\pi_\theta(a \mid s)$: the probability of choosing action $a$ in state $s$

The goal is to find the parameters that maximize the expected return:

$$
\theta^* = \arg\max_\theta J(\theta)
$$

In this relation:

$$
J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}[G(\tau)]
$$

That is, we want to adjust the policy parameters so that the average return of the trajectories produced by the agent increases.

### 3.1. Types of Policy

Two important types of policy are:

**Deterministic policy**

It selects one specific action for each state.

$$
a = \pi_\theta(s)
$$

Example:

```
State A -> Move Left
State B -> Move Right
State C -> Move Forward
```

**Stochastic policy**

It defines a probability distribution over actions for each state.

$$
a \sim \pi_\theta(\cdot \mid s)
$$

Example:

```
State A:

Move Left  = 0.70
Move Right = 0.20
Move Up    = 0.10
```

The agent samples an action according to this probability distribution.

Exam note

In policy-based methods, the stochastic policy is very important because it provides the possibility of exploration and learning diverse behaviors.

## 4. Why Is a Stochastic Policy Important?

Suppose an agent operates in a game with incomplete information such as poker.

The agent cannot observe all the information of the environment. In such situations, always choosing a fixed action may be predictable and inappropriate.

A stochastic policy allows the agent to:

- Learn several suitable actions.
- Diversify its behavior.
- Avoid becoming predictable.
- Be more flexible against uncertainty.

For example:

```
Current Observation
        |
        v
  Policy Network
        |
        v
Action Distribution
        |
        +---- Action A: 0.60
        |
        +---- Action B: 0.30
        |
        +---- Action C: 0.10
        |
        v
 Sample an Action
```

**An important conceptual correction:** A stochastic policy alone does not solve the partial observability problem and does not guarantee the Markov assumption. If the current observation does not contain enough information, the agent may need a history of observations and actions or a belief state. A stochastic policy only provides more flexibility in action selection.

## 5. REINFORCE: Outcome-Based Policy Learning

(The first important algorithm of the chapter)

REINFORCE is one of the simplest policy gradient algorithms.

Its main idea is:

Instead of learning a value function and deriving the policy from it, we directly update the policy parameters using the results of experiences.

### 5.1. Main Idea of REINFORCE

Suppose an agent is playing in an environment.

During an episode:

1. It receives a state.
2. It selects an action based on the policy.
3. It receives a reward.
4. This process continues until the episode ends.
5. The return is calculated.
6. The policy is updated based on the final result.

If an action was selected in a trajectory with a high return, the probability of selecting that action again increases.

If the return is low, the probability of selecting that action decreases.

### 5.2. The Concept of Trajectory

A trajectory is the entire path of the agent's interaction with the environment.

Representation of a trajectory:

```
S0
 |
 v
A0
 |
 v
R1
 |
 v
S1
 |
 v
A1
 |
 v
R2
 |
 v
S2
 |
 v
...
 |
 v
Terminal State
```

Mathematically:

$$
\tau = (S_0, A_0, R_1, S_1, A_1, R_2, \ldots)
$$

A trajectory includes the states, actions, and rewards corresponding to a path.

### 5.3. Probability of a Trajectory

The probability of a trajectory is formed by the product of the probabilities of the different events along the path.

$$
\begin{aligned}
P_\theta(\tau) =&\ \rho_0(s_0) \\
&\times \pi_\theta(a_0 \mid s_0) \\
&\times P(s_1, r_1 \mid s_0, a_0) \\
&\times \pi_\theta(a_1 \mid s_1) \\
&\times P(s_2, r_2 \mid s_1, a_1) \\
&\times \cdots
\end{aligned}
$$

In this relation:

- $\rho_0(s_0)$: the initial state distribution
- $\pi_\theta(a_t \mid s_t)$: the probability of selecting an action
- $P(s_{t+1}, r_{t+1} \mid s_t, a_t)$: the probability of the environment transition and receiving a reward

The important point is that the policy parameters control the probability of selecting actions.

Therefore, by changing the policy parameters, we can change the probability of different trajectories.

### 5.4. Why Do We Use Log Probability?

Computing the probability of a trajectory involves multiplying many probabilities.

To simplify the calculations, we use the logarithm.

Important property:

$$
\log(ab) = \log(a) + \log(b)
$$

Therefore:

$$
\log P_\theta(\tau) = \log \rho_0(s_0) + \sum_t \log \pi_\theta(a_t \mid s_t) + \sum_t \log P(s_{t+1}, r_{t+1} \mid s_t, a_t)
$$

Since the environment dynamics and the initial state distribution are usually not dependent on the policy parameters, when taking the derivative with respect to $\theta$, the main part of the gradient will correspond to the policy:

$$
\nabla_\theta \log P_\theta(\tau) = \sum_t \nabla_\theta \log \pi_\theta(a_t \mid s_t)
$$

This is the important log-derivative trick.

### 5.5. Goal of REINFORCE

The goal is to maximize the expected return:

$$
J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}[G(\tau)]
$$

Using the policy gradient, we can estimate the gradient of the objective:

$$
\nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta} \left[ G(\tau) \sum_t \nabla_\theta \log \pi_\theta(A_t \mid S_t) \right]
$$

This relation shows that:

- If the return is positive and high, the probability of the actions in the trajectory increases.
- If the return is low, the probability of the actions in the trajectory decreases.

### 5.6. REINFORCE Update Rule

$$
\theta \leftarrow \theta + \alpha G_t \nabla_\theta \log \pi_\theta(A_t \mid S_t)
$$

where:

- $\theta$: the policy parameters
- $\alpha$: the learning rate
- $G_t$: the return from time $t$
- $\nabla_\theta \log \pi_\theta$: the gradient of the log probability of the selected action

This algorithm updates the policy parameters with gradient ascent.

Note: In implementations based on gradient descent, the sign of the loss function is usually reversed.

## 6. Return and Reward-to-Go

One of the problems with REINFORCE is using the total episode return to update all actions.

To reduce this problem, we use reward-to-go.

### 6.1. Full Return

The return from the beginning of the episode:

$$
G_0 = R_1 + \gamma R_2 + \gamma^2 R_3 + \cdots
$$

In this method, all future rewards play a role in calculating the return.

### 6.2. Reward-to-Go

In reward-to-go, only the future rewards from the time of the current action selection are considered.

$$
G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots
$$

For example:

```
Time:     0       1       2       3
          |       |       |       |
Action:   A0      A1      A2      A3
          |       |       |       |
Reward:   R1      R2      R3      R4

G0 = R1 + γR2 + γ²R3 + γ³R4

G1 = R2 + γR3 + γ²R4

G2 = R3 + γR4

G3 = R4
```

Advantages of this method:

- Irrelevant past information does not enter the return calculation for the current action.
- The variance of the policy gradient estimate can be reduced.
- Credit assignment to actions becomes more accurate.

**Note:** Reward-to-go is still a Monte Carlo estimate and requires the end of the episode. This method alone does not completely solve the variance problem.

## 7. Main Problem of REINFORCE: High Variance

One of the most important limitations of REINFORCE is the high variance of the policy gradient.

### 7.1. What Is Variance?

Suppose we want to get closer to a target by throwing darts.

If the result of each throw is very different, determining the correct direction of movement will be difficult.

A similar thing happens in REINFORCE.

Different trajectories may have different returns for the following reasons:

- Randomness of the environment
- Randomness of action selection
- Differences in initial states
- Differences in the paths taken
- Differences in the received rewards

As a result, the computed gradient may vary greatly between different episodes.

### 7.2. Why Is High Variance Problematic?

- Training becomes unstable.
- The policy may change too much.
- More samples are needed to estimate the gradient accurately.
- Convergence can become slower.

### 7.3. Strategies to Reduce Variance

Several main strategies are introduced in this chapter:

1. Using reward-to-go
2. Using a baseline
3. Learning a value function
4. Using an advantage function
5. Using N-step returns
6. Using multiple independent workers
7. Using Generalized Advantage Estimation

## 8. VPG: Vanilla Policy Gradient

In this book, VPG refers to a version of REINFORCE that uses a baseline to reduce variance.

In other words:

```
REINFORCE
    |
    v
REINFORCE + Baseline
    |
    v
Vanilla Policy Gradient (VPG)
```

In this method, in addition to the policy, a value function is also learned.

### 8.1. Why Do We Add a Value Function?

In REINFORCE, we use the return to evaluate actions.

But the return alone does not specify whether an action was truly good or simply taken in an easy state.

For example:

- In one state, the return is 100.
- In another state, the return is 20.

Was the first action necessarily better?

Not necessarily, because the first state may have been inherently much better than the second state.

To solve this problem, we compare the action's performance with the expected average return of the same state.

### 8.2. Baseline

A baseline is a reference value that is subtracted from the gradient estimate to reduce variance.

In VPG, we usually use the state-value function:

$$
V_\phi(s)
$$

This function estimates what expected return we have from state $s$ when following the current policy.

As a result:

$$
A_t = G_t - V_\phi(S_t)
$$

This relation is in fact an estimate of the advantage.

### 8.3. Why Does a Baseline Reduce Variance?

Suppose:

```
State A:

Expected Return = 50

Action 1 Return = 80
Action 2 Return = 40
```

Computing the advantage:

```
Action 1:
80 - 50 = +30

Action 2:
40 - 50 = -10
```

Result:

- Action 1 was better than the average performance in that state.
- Action 2 was worse than the average performance in that state.

Therefore, the agent can compare actions more accurately.

### 8.4. Important Property of the Baseline

For the policy gradient estimate to remain unbiased, the baseline must not depend on the selected action, conditioned on the state.

For this reason, we use $V(s)$, not an arbitrary baseline that depends on the action.

## 9. Advantage Function

The advantage function is one of the most important concepts of the entire chapter.

This function shows how much better or worse choosing a specific action is compared with the average performance of the policy in the same state.

Definition:

$$
A_\pi(s,a) = Q_\pi(s,a) - V_\pi(s)
$$

where:

- $Q_\pi(s,a)$: the value of taking a specific action in a state
- $V_\pi(s)$: the average value of the state under the current policy

### 9.1. Interpretation of Advantage

| Advantage value | Meaning |
| --- | --- |
| $A(s,a) > 0$ | The action is better than average |
| $A(s,a) < 0$ | The action is worse than average |
| $A(s,a) = 0$ | The action is approximately equal to average |

Example:

```
State: Robot near an obstacle

V(s) = 50

Action A: Q(s,A) = 80
Advantage = +30

Action B: Q(s,B) = 40
Advantage = -10

Action C: Q(s,C) = 50
Advantage = 0
```

In this example, action A is better than the average performance of the policy.

### 9.2. Relationship Between Advantage and Policy Gradient

By replacing the return with the advantage, the policy update rule becomes:

$$
\nabla_\theta J(\theta) \approx \mathbb{E} \left[ A_\pi(s,a) \nabla_\theta \log \pi_\theta(a \mid s) \right]
$$

This relation helps update the policy based on the relative quality of actions.

Very important note

Advantage is not the same as return.

- Return: the sum of future rewards
- Value: the expected return from a state
- Q-value: the expected return from a state-action
- Advantage: the difference between Q-value and value

## 10. Actor-Critic Methods

Actor-critic is an architecture or family of reinforcement learning algorithms that combines two main parts:

- Actor
- Critic

The main idea is that one network is responsible for decision making and another network evaluates the quality of the decisions.

### 10.1. What Is the Actor?

The actor is responsible for learning the policy.

That is, it determines which action to select in each state.

$$
\pi_\theta(a \mid s)
$$

### 10.2. What Is the Critic?

The critic is responsible for evaluating the state or action.

This part usually learns the value function:

$$
V_\phi(s)
$$

or in some algorithms:

$$
Q_\phi(s,a)
$$

### 10.3. Actor-Critic Structure

```
              Environment
                   |
                   v
                  State
                   |
          +--------+--------+
          |                 |
          v                 v
        Actor             Critic
          |                 |
          v                 v
    Policy π(a|s)        Value V(s)
          |                 |
          v                 v
    Select Action      Evaluate State
          |                 |
          v                 v
       Action          Advantage / TD Error
          |                 |
          +--------+--------+
                   |
                   v
             Update Networks
```

### 10.4. How the Actor and Critic Cooperate

The overall process:

1. The actor selects an action according to the state.
2. The environment receives the action.
3. The environment returns the reward and the new state.
4. The critic evaluates the state.
5. The advantage or TD Error is computed.
6. The actor is updated based on this information.
7. The critic also corrects its value function using the experience.

### 10.5. Advantages of Actor-Critic

- Reduced variance compared with pure policy gradient in many situations
- Possibility of using bootstrapping
- Simultaneous learning of policy and value function
- Suitable for complex problems
- Possibility of using parallel workers

**Fundamental difference:** The actor makes decisions. The critic evaluates the quality of the decisions.

## 11. A3C: Asynchronous Advantage Actor-Critic

Parallel policy updates

One of the most important algorithms of this chapter is A3C.

A3C stands for:

**Asynchronous Advantage Actor-Critic**

This algorithm makes actor-critic learning faster and more stable by using multiple parallel workers.

### 11.1. Problem with On-Policy Methods

In on-policy methods, the agent must collect experience using its current policy.

For example, in VPG:

1. The agent runs an episode with the current policy.
2. It collects experiences.
3. It updates the policy.
4. It again collects experience with the new policy.

This process can be time-consuming.

Also, the consecutive experiences of one worker are usually correlated with each other.

For example, the consecutive states of a game are very similar to each other.

### 11.2. The Idea of A3C

Instead of using one worker, A3C uses several independent workers.

Each worker interacts with the environment separately and produces its own experiences.

The workers then send their gradients to the shared model.

Conceptual structure:

```
                 Global Network
                       |
          +------------+------------+
          |            |            |
          v            v            v
       Worker 1     Worker 2     Worker 3
          |            |            |
          v            v            v
       Environment  Environment  Environment
          |            |            |
          v            v            v
       Experience   Experience   Experience
          |            |            |
          v            v            v
       Gradients    Gradients    Gradients
          |            |            |
          +------------+------------+
                       |
                       v
               Global Update
                       |
                       v
               Updated Network
```

In this architecture:

- Each worker collects independent experiences.
- Each worker works with a local copy of the model.
- The gradients are sent to the global model.
- The shared model parameters are updated.

### 11.3. Why Are Multiple Workers Useful?

**1. Reducing correlation**

Each worker operates in an independent environment.

Therefore, the experiences obtained from different workers are less dependent on each other.

This helps reduce the effect of data correlation.

**2. Increasing the speed of experience collection**

Instead of one agent waiting for the end of one episode, several workers produce experience simultaneously.

**3. Greater diversity of experiences**

Workers may experience different paths and situations.

This helps improve the quality of training data.

**4. Reducing variance in the gradient estimate**

Combining independent experiences can make the gradient estimate more stable.

Of course, A3C does not guarantee that variance always decreases. The result depends on the number of workers, the environment, and the training setup.

### 11.4. Difference Between A3C and Experience Replay

In algorithms such as DQN, we use experience replay.

Previous experiences are stored in a replay buffer and sampled randomly during training.

But A3C uses multiple workers to produce new experiences.

| Feature | DQN | A3C |
| --- | --- | --- |
| Learning type | Off-policy | On-policy |
| Experience collection | One or more environments | Multiple independent workers |
| Replay buffer | Yes | No |
| Reducing correlation | Random sampling | Parallel workers |
| Update | Usually with mini-batch | Asynchronously |
| Value function | Q-function | Usually state-value |

**Note:** Parallelization in A3C replaces the replay buffer. It does not do exactly the same thing. Also, parallel workers alone do not guarantee full statistical independence of the data.

## 12. N-Step Returns in A3C

One of the important techniques used in A3C is the N-step return.

In previous methods, we became familiar with two main types of target:

- Monte Carlo return
- One-step TD return

The N-step return falls between these two methods.

### 12.1. One-Step TD

In one-step TD, we use one real reward and the estimated future value.

$$
G_t^{(1)} = R_{t+1} + \gamma V(S_{t+1})
$$

### 12.2. N-Step Return

In the N-step return, we sum several real rewards and then use the value function to estimate the rest of the path.

$$
\begin{aligned}
G_t^{(n)} = &R_{t+1} \\
&+ \gamma R_{t+2} + \cdots \\
&+ \gamma^{n-1} R_{t+n} + \gamma^n V(S_{t+n})
\end{aligned}
$$

### 12.3. Spectrum of N-Step Return

```
1-Step TD
    |
    |  1 real reward
    |  High bootstrapping
    v
N-Step TD
    |
    |  Several real rewards
    |  Less bootstrapping
    v
Monte Carlo
       All rewards of the episode
       No bootstrapping
```

### 12.4. Why Does A3C Use N-Step Returns?

The N-step return allows A3C to use several steps of experience without waiting for the end of the episode.

For example, if a worker wants to compute the gradient after 5 steps, it can use 5 real rewards and the estimated value of the next state.

Advantages:

- Faster updates
- No need to wait for the end of the episode
- Use of bootstrapping
- Reduced dependence on the full Monte Carlo return

### 12.5. Bias and Variance in N-Step Return

| Method | Bias | Variance |
| --- | --- | --- |
| One-step TD | Usually higher | Usually lower |
| N-step TD | Intermediate | Intermediate |
| Monte Carlo | Usually lower | Usually higher |

Reason:

- TD depends on the value function estimate, so bias may be introduced.
- Monte Carlo uses real rewards but is affected by the randomness of the entire trajectory.

This is an important trade-off in designing RL algorithms.

## 13. Asynchronous Updates

Another key concept of A3C is asynchronous model updating.

### 13.1. Synchronous vs Asynchronous

In the synchronous method, we usually must wait for all workers to complete their tasks and then perform a shared update.

But in the asynchronous method, workers send their gradients to the shared model without waiting for each other.

**Synchronous:**

```
Worker 1 ----\
Worker 2 -----+---- Wait ---- Global Update
Worker 3 ----/
```

**Asynchronous:**

```
Worker 1 ---------> Global Update
Worker 2 -----> Global Update
Worker 3 ------------> Global Update
```

### 13.2. Advantages of Asynchronous Updates

- Reduced waiting time between workers
- Better use of computational resources
- Possibility of parallel experience collection
- Increased training speed in many environments

### 13.3. Problems with Asynchronous Updates

Simultaneous updating by several workers can create problems:

**Race condition**

Several workers may change a shared parameter almost at the same time.

**Stale gradients**

A worker may have computed a gradient based on an old version of the model.

In this case, the sent gradient is not fully consistent with the current state of the model.

**Synchronization complexity**

Managing shared parameters and the optimizer state requires careful design.

## 14. Hogwild! and Lock-Free Updates

The chapter text refers to a method called Hogwild.

Hogwild! is an approach for performing parallel updates without using traditional locks.

### 14.1. The Problem with Locks

Suppose several workers want to update a shared model.

In the lock-based method:

1. The first worker acquires the lock.
2. It updates the parameters.
3. It releases the lock.
4. The next worker is allowed to update.

This process can become a bottleneck.

### 14.2. The Idea of Hogwild

In Hogwild, workers perform their updates without waiting to acquire a lock.

```
Worker 1 --------\
Worker 2 ---------+---- Shared Parameters
Worker 3 --------/
```

This method tries to reduce the cost of synchronization.

### 14.3. Is Hogwild Always Problem-Free?

No.

Hogwild is a method without full synchronization, and collisions between simultaneous writes are possible.

As a result:

- Some updates may affect each other.
- Old information may be used.
- In some situations, training quality may decrease.

The performance of this method depends on the memory architecture, the rate of collisions on the parameters, and the conditions of the problem.

### 14.4. Shared Optimizer

In A3C, not only the neural network parameters are important.

The optimizer also has internal variables.

For example, Adam has variables such as:

- First moment
- Second moment
- Step counter

If each worker has a separate optimizer state, coordinating the updates becomes difficult.

For this reason, the optimizer state can also be placed in shared memory.

In the implementation discussed in the chapter, the Shared Optimizer class is used to manage the internal variables of the optimizer in shared memory.

**Important note:** Hogwild does not mean automatically averaging all changes at the end. In A3C, workers apply their gradients or updates asynchronously, and no specific mechanism for final averaging is guaranteed.

## 15. Weight Sharing in Actor-Critic Networks

Another important topic of the chapter is the use of a shared neural network for the actor and the critic.

In the usual case, we can have two separate networks:

- Actor network
- Critic network

But in weight sharing, part of the network is shared between the actor and the critic.

### 15.1. Why Is Weight Sharing Useful?

Suppose an agent must make decisions using images from an Atari game.

Extracting features from images requires a lot of computation.

If the actor and the critic are two independent networks, both must extract the image features separately.

But with weight sharing, one shared part can extract the features, and then we have two separate heads.

### 15.2. Shared Actor-Critic Architecture

```
             Input State
                  |
                  v
          Shared Neural Network
                  |
                  v
             Hidden Layers
                  |
             +----+----+
             |         |
             v         v
         Actor Head  Critic Head
             |         |
             v         v
          Policy     Value
          π(a|s)     V(s)
```

### 15.3. Explanation of the Architecture Parts

**Shared layers**

They extract the input features.

For example, in image input:

- Object detection
- Visual feature extraction
- Position recognition
- Environment pattern recognition

**Actor head**

It produces the outputs related to the policy.

For example:

$$
\pi_\theta(a \mid s)
$$

**Critic head**

It estimates the value:

$$
V_\phi(s)
$$

### 15.4. Advantages of Weight Sharing

- Reduced number of model parameters
- Reduced redundant computation
- Reuse of extracted features
- Reduced memory cost
- Increased efficiency in problems with complex input

### 15.5. Disadvantages of Weight Sharing

The actor and the critic have different training goals.

The actor seeks to improve the policy, but the critic seeks to estimate the value function accurately.

If both use shared layers, their gradients may conflict with each other.

This problem can cause:

- The learning of one part to be affected by the other.
- Convergence to become more difficult.
- The need for careful tuning of the loss and learning rate.

Therefore, weight sharing is not always the best choice.

## 16. GAE: Generalized Advantage Estimation

Robust advantage estimation

GAE is one of the very important concepts of the chapter.

It stands for:

**Generalized Advantage Estimation**

The main goal of GAE is to estimate the advantage better and control the trade-off between bias and variance.

### 16.1. Problem of Advantage Estimation

In actor-critic, we need the advantage to update the actor.

A simple estimate:

$$
A_t = G_t - V(S_t)
$$

But using the full return can have high variance.

On the other hand, using one-step TD can introduce bias.

Therefore, we need a method that balances the two.

### 16.2. TD Error

First, we must know the TD Error.

In one-step TD:

$$
\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)
$$

This relation shows how much the actual reward plus the estimated future differs from the current value.

### 16.3. N-Step Advantage

Using the N-step return, we can estimate the advantage:

$$
A_t^{(n)} = G_t^{(n)} - V(S_t)
$$

For different values of N, we have different estimates of the advantage.

GAE combines these estimates in a certain way.

### 16.4. GAE Formula

The main formula:

$$
\hat{A}_t^{GAE(\gamma,\lambda)} = \sum_{l=0}^{T-t-1} (\gamma\lambda)^l \delta_{t+l}
$$

where:

- $\gamma$: the discount factor
- $\lambda$: the parameter controlling bias and variance
- $\delta_t$: the TD Error
- $T$: the end of the episode or the boundary of the experience segment

In simple terms, GAE combines a sequence of future TD Errors with decreasing weights.

### 16.5. The Role of Lambda

Lambda determines how much long-term and short-term information is used in estimating the advantage.

**If lambda equals zero:**

$$
\lambda = 0
$$

we have:

$$
\hat{A}_t = \delta_t
$$

That is, only the one-step TD Error is used.

Features:

- High bootstrapping
- Lower variance
- Potentially higher bias

**If lambda equals one:**

$$
\lambda = 1
$$

In a complete episode and under appropriate conditions, GAE approaches the Monte Carlo advantage estimate:

$$
\hat{A}_t = G_t - V(S_t)
$$

Features:

- Less bootstrapping
- Higher variance
- Potentially lower bias

### 16.6. Conceptual Spectrum of GAE

```
λ = 0
  |
  v
One-Step TD
  |
  |  High bootstrapping
  |  Potentially higher bias
  |  Lower variance
  |
  v
Intermediate λ
  |
  |  Combination of multi-step TD Errors
  |
  v
λ = 1
  |
  v
Monte Carlo Advantage
     Less bootstrapping
     Potentially lower bias
     Higher variance
```

### 16.7. Why Is GAE Useful?

- Better variance control
- Ability to tune bias and variance
- Use of multi-step information
- More stable advantage estimation
- Improved actor-critic performance in many problems

Important note: GAE does not mean completely eliminating bias or variance. Lambda is a tool for controlling the trade-off between the two.

## 17. A2C: Advantage Actor-Critic

Synchronous policy updates

A2C stands for:

**Advantage Actor-Critic**

This algorithm is the synchronous version of the parallel actor-critic approach, which contrasts with A3C.

### 17.1. Difference Between A2C and A3C

In A3C, workers send gradients to the shared model asynchronously.

But in A2C, workers collect their experiences, and then the model update is performed after the data is ready.

### 17.2. Structure of A2C

```
                 Shared Policy
                       |
          +------------+------------+
          |            |            |
          v            v            v
       Worker 1     Worker 2     Worker 3
          |            |            |
          v            v            v
       Environment  Environment  Environment
          |            |            |
          v            v            v
       Experience   Experience   Experience
          |            |            |
          +------------+------------+
                       |
                       v
                Batch Collection
                       |
                       v
                 Calculate Loss
                       |
                       v
                 Synchronous Update
                       |
                       v
                Updated Policy
```

### 17.3. Advantages of A2C

- Simpler structure compared with A3C
- Better coordination among workers
- Proper use of batch processing
- Easier implementation in many modern environments
- Ability to use the GPU effectively

### 17.4. Disadvantages of A2C

- Must wait for the batch to be ready.
- Execution speed may be affected by the slowest worker.
- Effective use of resources requires choosing an appropriate number of workers and batch size.

### 17.5. Comparison of A2C and A3C

| Feature | A3C | A2C |
| --- | --- | --- |
| Update type | Asynchronous | Synchronous |
| Workers | Parallel | Parallel |
| Coordination | Less | More |
| Waiting for workers | Usually none | Yes |
| Complexity | Higher | Lower |
| Batch processing | Not necessarily the main focus | Usually the main focus |
| Algorithm type | Actor-critic | Actor-critic |

**Note:** Both A2C and A3C use parallel workers. Their main difference is in the coordination and timing of the updates, not in the presence or absence of parallelization.

## 18. Entropy and Encouraging Exploration

One of the topics of the chapter that also appears in the official table of contents of the book is encouraging exploration.

So far, we have seen that a stochastic policy can select different actions, but there is a problem.

The policy may quickly become dependent on a specific action and reduce the probability of other actions to almost zero.

This problem can cause premature convergence.

### 18.1. What Is Entropy?

Entropy is a measure of the uncertainty of a probability distribution.

For a discrete policy:

$$
H(\pi(\cdot \mid s)) = -\sum_a \pi(a \mid s) \log \pi(a \mid s)
$$

If the probabilities of selecting actions are almost equal, the entropy is higher.

If one action has a much higher probability than the others, the entropy is lower.

Example:

```
Policy A:

Action 1 = 0.33
Action 2 = 0.33
Action 3 = 0.34

Entropy: High


Policy B:

Action 1 = 0.98
Action 2 = 0.01
Action 3 = 0.01

Entropy: Low
```

### 18.2. Why Is Entropy Important?

High entropy means the agent is still examining different options.

Low entropy shows that the agent has become more inclined toward one or a few specific actions.

Therefore, by encouraging entropy, we can increase exploration.

### 18.3. Entropy Regularization

To encourage exploration, we can add entropy to the objective function:

$$
J(\theta) = J_{\text{return}}(\theta) + \beta H(\pi_\theta)
$$

where:

- $J_{\text{return}}$: the expected return
- $H(\pi_\theta)$: the entropy of the policy
- $\beta$: the coefficient of exploration importance

If $\beta$ is larger, the agent has a greater incentive to maintain action diversity.

Of course, if this coefficient is too large, the agent may act too randomly even after learning appropriate behavior.

**Note:** Entropy regularization does not mean random selection without purpose. The goal is to prevent premature narrowing of the search space.

## 20. Choosing the Right Algorithm for the Problem

No algorithm is best in all situations.

The choice depends on the type of environment and the constraints of the problem.

| Problem conditions | Suitable approach |
| --- | --- |
| Simple problem with a discrete action space | REINFORCE |
| Need to reduce variance in policy gradient | VPG |
| Need for parallel and asynchronous learning | A3C |
| Need for more stable advantage estimation | GAE |
| Need for parallel and synchronous learning | A2C |

For example:

**Scenario one: controlling a robot**

If the robot must perform continuous actions, policy-based methods are a suitable choice.

**Scenario two: training an agent in a complex game**

If experience collection is time-consuming and several independent environments are available, A3C or A2C can be useful.

**Scenario three: high fluctuation in training**

If the policy gradient has high variance, using a baseline and advantage estimation can help.

**Scenario four: limited computational resources**

A2C with batch processing and a more coordinated structure can be a suitable choice, although actual performance depends on the environment and hardware.

## 23. The Most Important Concepts You Must Remember from This Chapter

If we want to summarize the entire chapter into a few fundamental principles:

1. **Value-based:** first learns the value of actions and then makes a decision.
2. **Policy-based:** directly learns the decision-making policy.
3. **Parameterized policy:** the policy is represented with learnable parameters, usually the weights of a neural network.
4. **Stochastic policy:** assigns a probability to each action and uses the probability distribution to select an action.
5. **REINFORCE:** directly optimizes the policy using the return.
6. **Reward-to-go:** considers only the future rewards from the time of the current action.
7. **VPG:** uses a value function as a baseline to reduce variance.
8. **Advantage:** specifies how much better or worse an action is compared with the average performance of the policy in the same state.
9. **Actor-critic:** the actor learns the policy, and the critic evaluates it.
10. **A3C:** uses parallel workers and asynchronous updates to increase learning speed.
11. **N-step return:** falls between one-step TD and Monte Carlo.
12. **Hogwild:** enables parallel updates without traditional locks.
13. **Weight sharing:** the actor and the critic can use shared layers for feature extraction.
14. **GAE:** improves advantage estimation by combining multi-step TD Errors.
15. **A2C:** uses parallel workers but performs updates synchronously.

The most important conceptual chain of this chapter for deep learning is:

**REINFORCE → Baseline → Advantage → Actor-Critic → A3C / GAE / A2C**

If this chain and the reason for introducing each stage are well understood, the main logic of policy gradient and actor-critic in this chapter will be understandable.
