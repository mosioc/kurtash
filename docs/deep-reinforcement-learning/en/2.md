# Complete Summary of Chapter 2 of *Grokking Deep Reinforcement Learning*

Chapter 2 deals with the fundamental concepts of the environment in reinforcement learning (RL), how the agent interacts with the environment, and the mathematical modeling of this interaction using **Markov Decision Processes (MDPs)**.

The main goal of the chapter is to learn how to convert a real problem into a set of states, actions, transitions, and rewards so that it can be solved with reinforcement learning algorithms.

## 1. What Is Reinforcement Learning?

Reinforcement learning is a machine learning method in which an agent learns, through interaction with an environment, what actions to take in order to obtain the greatest reward over the long term.

Unlike rule-based methods with predefined rules, in RL the agent learns through experience, trial and error, and received feedback.

**Examples:**

- Training a dog to follow commands.
- Training a robot to walk.
- Training a self-driving car to drive.
- Learning an appropriate strategy in games.
- Making buy and sell decisions in the stock market.

## Core Components of RL

| Concept | Definition |
| --- | --- |
| Agent | The decision-making component |
| Environment | The environment the agent interacts with |
| Action | An action the agent performs |
| Observation | Information the agent receives from the environment |
| Reward | Numeric feedback from the environment to the agent |
| Goal | The objective the agent tries to achieve |

## The Main Agent Cycle

The interaction of the agent with the environment can be summarized in three main stages:

**1. Observe**

Receiving information from the environment.

**2. Act**

Selecting and executing an action.

**3. Evaluate**

Evaluating the outcome and receiving the reward.

This cycle repeats continuously and enables the agent to improve its future behavior based on the outcomes of previous actions.

**Diagram of the agent-environment interaction cycle:**

```text
                 Action (a_t)
        +---------------------------+
        |                           |
        v                           |
   +---------+                 +-------------+
   |  Agent  |                 | Environment |
   +---------+                 +-------------+
        ^                           |
        |                           |
        +---------------------------+
             Observation (o_t)
                Reward (r_t)
```

In this cycle:

- The agent receives information from the environment.
- Based on the received information, it selects an action.
- The environment responds to the action.
- The environment produces a new state and the corresponding reward.
- This information is provided to the agent for the next decision.

# 2. What Is the Environment?

The environment is everything and all variables outside the agent that influence the outcome of its decisions.

For example, in a game:

- The player's current position
- The positions of enemies
- Obstacles
- The game state
- Movement rules

All of these are part of the environment.

In RL, the environment is modeled using several mathematical components.

## State Space

The state space is the set of all possible states of the environment.

**State:** a specific condition of the environment at a moment in time.

Example: In the game of Checkers, every possible arrangement of pieces on the board can be a state.

If we consider the set of all possible states, we arrive at the state space.

Important note: The number of variables describing each state can be fixed and limited, but the number of possible combinations of these variables can be very large.

## Observation Space

The observation space is the set of all information the agent may observe from the environment.

Difference between state and observation:

- State: the true condition of the environment.
- Observation: the information the agent receives about that condition.

These two are not always the same.

For example, in a game, the agent may see the positions of the pieces but may not be aware of hidden information in the game.

## Action Space

The action space is the set of all actions the agent can perform.

Example in Frozen Lake:

- Up
- Down
- Left
- Right

Important note: The available actions may depend on the current state. For example, in the corner of a grid, the number of possible moves is more limited.

## Transition Function

The transition function specifies how the environment moves from the current state to the next state after an action is executed.

Formula:

```math
P(s' \mid s, a)
```

where:

- `s`: the current state
- `a`: the executed action
- `s'`: the next state

This function can be deterministic or probabilistic.

## Reward Function

The reward function specifies what reward the agent receives after performing an action and causing a transition.

General form:

```math
R(s, a, s')
```

That is, the reward depends on the current state, the action, and the next state.

The reward can be positive, negative, or zero.

# 3. Deterministic vs Stochastic Environments

One of the most important differences among environments in RL is the degree of determinism in the outcome of actions.

## Deterministic Environment

The environment is deterministic, meaning every action in a given state always has the same outcome.

Example:

If the agent is in cell number 2 and moves right, it always goes to cell number 3.

For the intended next state:

```math
P(s' \mid s, a) = 1
```

## Stochastic Environment

The environment is probabilistic, meaning an action can have different outcomes.

For example, in a slippery environment:

- 80% probability of moving in the intended direction
- 20% probability of slipping and moving backward

For the intended move:

```math
P(s' \mid s, a) = 0.8
```

and the remaining probability corresponds to other possible outcomes.

| Feature | Deterministic | Stochastic |
| --- | --- | --- |
| Outcome of action | Certain | Probabilistic |
| Uncertainty | None | Present |
| Transition | One specific outcome | Several possible outcomes |
| Example | Movement in a simple grid | Movement on an icy surface |

Note: In a stochastic environment, even if the agent selects a specific action, the outcome is not necessarily predictable.

# 4. Types of Reward

A reward is a signal the environment gives the agent to indicate the quality of the outcome of its actions.

## Positive Reward

A positive reward encourages desirable behavior.

Example: Reaching the goal in a game.

## Negative Reward

A negative reward penalizes undesirable behavior.

Example: A robot colliding with an obstacle or taking too much time.

## Zero Reward

A zero reward occurs when the executed action has no particular reward or penalty.

## Dense vs Sparse Rewards

| Type | Description |
| --- | --- |
| Dense Reward | The agent receives feedback at various stages. |
| Sparse Reward | The agent receives a reward only in limited situations. |

**Dense Reward:**

- More feedback
- Faster learning is possible
- More guidance of the agent by the reward

**Sparse Reward:**

- Less feedback
- Greater need for exploration
- Possibility of discovering unexpected solutions

Example: In a game, if we give points for every move we have a dense reward; if we give points only for winning we have a sparse reward.

# 5. Time Steps, Experiences, and Episodes

## Time Step

A time step is the unit of time in the interaction between the agent and the environment.

At each time step, the agent receives information, performs an action, and receives feedback.

This unit can be a millisecond, a second, or even a day.

## Experience

An experience records the information related to one stage of interaction between the agent and the environment.

```math
(s_t, a_t, r_{t+1}, s_{t+1})
```

That is:

- The current state
- The selected action
- The received reward
- The next state

## Episode

An episode is a sequence of time steps from the beginning to the end of a task.

### Episodic Tasks

Tasks that have a defined beginning and end.

Examples:

- Finishing a game
- Solving a maze
- Reaching the goal in Frozen Lake

### Continuing Tasks

Tasks that do not have a natural, defined end.

Examples:

- Continuously controlling a vehicle
- Controlling industrial systems

Note: By setting a time step limit for a continuing task, it can be converted into a bounded, episodic task.

# 6. Return

The return is the sum of the rewards the agent receives during an episode.

The main goal of the agent in RL is to maximize the return.

In the simplest case:

```math
G_t = \sum_{k=0}^{T-t-1} r_{t+k+1}
```

That is, the sum of future rewards from the current time to the end of the episode.

Later in the chapter, the discounted return version is also introduced.

# 7. Three Main Concepts in the Agent

Three important tools for the agent's decision-making and learning are:

| Concept | Function |
| --- | --- |
| Policy | Selecting an action |
| Model | Predicting future states and rewards |
| Value Function | Estimating future reward |

## Policy

The policy specifies what action the agent takes in a given state.

```math
\pi(a \mid s)
```

The policy can be:

- Deterministic: selects one specific action for each state.
- Stochastic: has a probability distribution over actions for each state.

## Model

The model predicts the behavior of the environment.

In other words, it specifies what probable state and reward will be created in the future if the agent performs an action.

## Value Function

The value function estimates the desirability of a state or situation based on expected future rewards.

Note: These three concepts are introduced in this chapter; their computational details and algorithms are the subject of later discussions.

# 8. Markov Decision Process (MDP)

The most important concept of the chapter

MDP, or Markov Decision Process, is a mathematical model for describing decision-making environments in reinforcement learning.

Using an MDP, we can specify:

1. What states exist in the environment?
2. What actions can the agent perform?
3. What effect does each action have on the environment?
4. What reward does the agent receive?
5. How are future rewards valued?

## Main Components of an MDP

In this chapter, an MDP is introduced with the following components:

| Component | Concept |
| --- | --- |
| State Space | All possible states |
| Action Space | Possible actions |
| Transition Function | Probability of transitioning between states |
| Reward Function | Reward resulting from actions and transitions |
| Initial State Distribution | Probability distribution of starting states |
| Discount Factor | The degree of importance of future rewards |
| Planning Horizon | The planning time frame |

Common notation for an MDP:

```math
\text{MDP} = (S, A, P, R, \gamma)
```

This notation shows the main components; the initial state distribution and the horizon are also characteristics of the problem that must be considered in complete modeling.

## Markov Property

The Markov property is one of the most important features of an MDP.

According to this property, the future state depends only on the current state and the current action, not on the entire previous history.

```math
P(S_{t+1} \mid S_t, A_t, \ldots, S_0, A_0) = P(S_{t+1} \mid S_t, A_t)
```

**Example:**

Suppose a robot is in a grid environment.

If the current state of the robot is its position, then to predict the next position it is enough to know the current position and the action.

However, if the robot's movement also depends on its velocity, then velocity must also be added to the state.

Therefore, choosing the appropriate variables for defining the state is very important.

## Stationary Environment

A stationary environment is one whose transition and reward rules do not change during the learning process.

That is:

- Transition probabilities remain fixed.
- Reward rules remain fixed.

If the environment changes during training, the learned policy may no longer be suitable.

# 9. Terminal States

A terminal state is the final state of an episode; that is, when the agent reaches it, the current interaction ends.

Examples:

- Winning a game
- Losing a game
- Reaching the destination
- Falling into a hole in Frozen Lake

In an MDP, for a terminal state a transition to itself with probability 1 is usually defined:

```math
P(s' = s \mid s, a) = 1
```

and its reward in this transition is considered to be zero.

This is a modeling convention that makes the definition of transitions complete.

Important note: A terminal state is different from an initial state. The starting state and the terminal states are part of the definition of the environment and the MDP, not features that the agent determines arbitrarily during training.

# 10. Action Space and Types of Policy

The action space is not necessarily the same in all states.

For example, in a grid environment:

- In the center of the grid there may be four moves.
- In the corner of the grid the number of allowed moves is smaller.
- In a terminal state, there is no effective move to exit.

Therefore, the set of allowed actions can be considered a function of the state:

```math
A(s)
```

## No-op Action

No-op stands for no operation.

That is, an action that causes no effective change in the environment.

This action can be used to represent situations in which the agent effectively does nothing.

## Deterministic Policy

In this type of policy, one specific action is selected for each state.

```math
a = \pi(s)
```

For example:

If the agent is in cell number 2, it always chooses to move right.

## Stochastic Policy

In this type of policy, the agent uses a probability distribution to select an action.

```math
\pi(a \mid s) = P(A_t = a \mid S_t = s)
```

For example:

| Action | Probability |
| --- | --- |
| Up | 0.5 |
| Down | 0.2 |
| Left | 0.2 |
| Right | 0.1 |

Important difference:

- Deterministic and stochastic here concern how the agent selects an action.
- Deterministic and stochastic environment concern how the environment responds to an action.

These two topics are independent of each other.

# 11. Planning Horizon

The planning horizon specifies how far into the future the agent looks and considers future rewards and actions.

## Finite Horizon

The agent knows that the task ends after a specific number of time steps.

Example: Solving a puzzle in at most 15 moves.

## Greedy Horizon

This is a special type of finite horizon in which the agent considers only one step ahead.

That is, decisions are made based on immediate reward, and rewards from later stages are not considered.

This concept is important in bandit problems.

## Infinite Horizon

The agent assumes that interaction with the environment can continue indefinitely.

Example: Continuously controlling a robot in a warehouse.

Of course, the environment may in practice stop at any time.

## Hard Time Step Limit

Sometimes, to prevent an episode from continuing indefinitely, a specific time limit is defined.

In this case, after reaching a certain number of time steps, the episode terminates.

This is used in environments such as CartPole.

Important difference: An artificial time limit is not the same as naturally reaching a terminal state.

# 12. Discount Factor (γ)

A very important concept

The discount factor specifies how much future rewards are worth compared to current rewards.

It is denoted by the Greek letter gamma, `\gamma`.

```math
0 \leq \gamma \leq 1
```

Core idea:

The farther a reward is in the future, the less its value can be considered.

## Values of Gamma

| Value | Concept |
| --- | --- |
| `\gamma = 0` | Only the immediate reward matters. |
| `\gamma = 0.5` | Future rewards are discounted more heavily. |
| `\gamma = 0.99` | Future rewards are very important. |
| `\gamma = 1` | No discounting is performed. |

## Discounted Return

The formula for computing the return taking the discount factor into account:

```math
G_t = \sum_{k=0}^{T-t-1} \gamma^k r_{t+k+1}
```

In this formula:

- `G_t`: the return from the current time
- `\gamma`: the discount factor
- `k`: the time distance of the reward from the current time
- `r_{t+k+1}`: the future reward

### Example

Suppose the agent receives the following rewards over the next three stages:

```math
r_1 = 10, \quad r_2 = 10, \quad r_3 = 10
```

If:

```math
\gamma = 0.5
```

then:

```math
G = 10 + (0.5)(10) + (0.5^2)(10)
```

```math
G = 17.5
```

But if:

```math
\gamma = 1
```

then:

```math
G = 10 + 10 + 10 = 30
```

Therefore, gamma determines how much the agent cares about more distant rewards.

## Why Is the Discount Factor Important?

1. Reducing the influence of very distant and uncertain rewards.
2. Helping to control and stabilize return computations.
3. Adjusting the balance between immediate reward and future reward.
4. Influencing the agent's long-term strategy.

**Important note:** The appropriate value of gamma is not the same for all environments. This value depends on the structure of the environment, the rewards, and the length of the path to success.

In the chapter's examples:

- Bandit Walk and Bandit Slippery Walk can use gamma equal to 1.
- Frozen Lake is usually examined with gamma equal to 0.99.

Gamma is part of the definition of the MDP and, in some settings, is also tuned as a hyperparameter.

# 13. Types of MDP and Its Extensions

The basic MDP is suitable for modeling many problems; however, not all real environments have the same structure.

For this reason, extended versions of the MDP have been introduced.

| Type | Full Name | Application |
| --- | --- | --- |
| MDP | Markov Decision Process | Environment with observable state |
| POMDP | Partially Observable Markov Decision Process | Environment with incomplete information |
| FMDP | Factored Markov Decision Process | Compact representation of large environments |
| Continuous MDP | Continuous Markov Decision Process | Continuous state or action |
| Relational MDP | Relational Markov Decision Process | Modeling relationships between objects |
| SMDP | Semi-Markov Decision Process | Actions with different durations |
| MMDP | Multi-Agent Markov Decision Process | Interaction of multiple agents |
| Decentralized MDP | Decentralized Markov Decision Process | Collaboration of distributed agents |

## POMDP

In a regular MDP, it is assumed that the agent has access to the true state of the environment.

However, in a POMDP, the agent only receives observations and does not necessarily know the true state.

Example: A robot that observes only part of a room with its sensors.

Difference:

- MDP: access to the state
- POMDP: access to incomplete observations

In a POMDP, in addition to the observation space, the concept of emission probability is also introduced:

```math
P(o \mid s)
```

This probability indicates how likely a particular observation is given that the environment is in a specific state.

## FMDP

Factored MDP is used for the compact representation of environments with a very large number of states.

Instead of representing all states separately, it uses the structure of the variables and the relationships among them.

## Continuous MDP

In this type of MDP, the state or action variables can take continuous values.

Example: Controlling a robotic arm in three-dimensional space.

The position and angle of the arm can take continuous values.

## Relational MDP

Used for modeling objects and the relationships among them.

Example: The agent must understand where one object is located relative to another and how actions change these relationships.

## SMDP

Semi-Markov Decision Process allows the modeling of actions that may take several time steps.

Example: A multi-stage process for assembling a part.

## MMDP

Multi-Agent MDP is used for environments in which multiple agents interact simultaneously.

Example: Several robots collaborating to carry out a joint mission.

## Decentralized MDP

In this model, multiple agents can collaborate to achieve a shared reward without necessarily having access to the entire state of the environment.

# 14. How to Define MDPs and POMDPs in Practice

In the real world, we are not always given all the components of an MDP completely.

We may have only these two:

- Transition function
- Reward function

and other information such as the following may not be specified:

- Initial state distribution
- Discount factor
- Planning horizon

In such situations, we must specify what assumptions we have made for the environment.

In the educational examples of this chapter, for simplicity, the main focus is on the transition function and the reward function, and some parameters are predefined or specified.

## Difference between MDP and POMDP in Terms of Modeling

| Feature | MDP | POMDP |
| --- | --- | --- |
| State Space | Has it | Has it |
| Action Space | Has it | Has it |
| Transition Function | Has it | Has it |
| Reward Function | Has it | Has it |
| Observation Space | In the complete case, the same as the state | Defined separately |
| Emission Probability | Not needed | Has it |
| Observing the true state | Yes | Not necessarily |

# 15. Sample Environments in Chapter 2

Chapter 2 introduces several simple environments to explain the concepts.

## 15.1. Bandit Walk (BW)

A very simple environment with three states, only one of which is non-terminal.

Features:

- The agent starts from the middle state.
- It can move left or right.
- Reaching the right end has a reward of +1.
- Other transitions have a reward of zero.
- The transitions are deterministic.

**Diagram of Bandit Walk:**

```text
          Left                 Right
     +-------------+       +-------------+
     |             |       |             |
     v             |       v             |
+----------+   +----------+   +----------+
|    S0    |<->|    S1    |<->|    S2    |
| Terminal |   |  Start   |   | Terminal |
| Reward 0 |   |          |   | Reward +1|
+----------+   +----------+   +----------+
```

In this representation:

- `S_1` is the starting state and the only non-terminal state.
- `S_0` and `S_2` are terminal states.
- Reaching the right side has a reward of +1.
- Reaching the left side produces no reward.

Goal: A simple examination of how the agent learns in an environment with limited options.

## 15.2. Bandit Slippery Walk (BSW)

This environment is the stochastic version of the previous environment.

Features:

- The agent is in an environment similar to BW.
- The movement does not always match the selected action.
- The probability of moving in the intended direction is 80%.
- The probability of slipping backward is 20%.
- Reaching the goal has a reward of +1.
- Other transitions have a reward of zero.

**Diagram of the probabilistic transitions:**

Suppose the agent is in `S_1` and selects the action of moving right:

```text
                         Action: Right
                              |
                              v
                         +----------+
                         |    S1    |
                         +----------+
                           /      \
                          /        \
                    20%  /          \  80%
                        v            v
                  +----------+  +----------+
                  |    S0    |  |    S2    |
                  | Terminal |  | Terminal |
                  | Reward 0 |  | Reward +1|
                  +----------+  +----------+
```

In this example:

- With 80% probability the intended move is performed.
- With 20% probability the move backward occurs.

Goal: Examining the effect of uncertainty in transitions.

## 15.3. Frozen Lake (FL)

Frozen Lake is a 4x4 grid world environment.

The agent must reach the destination and avoid falling into holes.

Features:

- There are 16 cells in the grid.
- It has four main actions: up, down, left, and right.
- The moves are stochastic.
- The probability of moving in the intended direction is one third.
- The probability of moving in either of the two lateral directions is also one third.
- Reaching the goal has a reward of +1.
- Other states have a reward of zero.
- Falling into a hole ends the episode.

**Frozen Lake map:**

```text
+---+---+---+---+
| S | F | F | F |
+---+---+---+---+
| F | H | F | H |
+---+---+---+---+
| F | F | F | H |
+---+---+---+---+
| H | F | F | G |
+---+---+---+---+
```

Map legend:

```text
S = Start
F = Frozen / Safe tile
H = Hole (Terminal state)
G = Goal (Reward = +1)
```

**Movement in Frozen Lake:**

The agent has four possible actions:

```text
              Up
               ^
               |
               |
      Left <-- S --> Right
               |
               |
               v
             Down
```

However, because the environment is stochastic, choosing a direction does not necessarily lead to movement in that direction.

For example, if the agent chooses to move right:

```text
                 Intended: Right
                     1/3
                      |
                      v
                 +---------+
                 | Current |
                 |  State  |
                 +---------+
                   /     \
                  /       \
             1/3 /         \ 1/3
                v           v
              Up           Down
```

Therefore:

- Probability of moving in the selected direction: `1/3`
- Probability of moving in one lateral direction: `1/3`
- Probability of moving in the other lateral direction: `1/3`

This environment is used to learn how to model probabilistic environments and design MDPs.

## 15.4. CartPole

CartPole is an environment in which the agent must keep a pole attached to a cart balanced by moving the cart.

In the chapter, this environment is mentioned to explain the hard time step limit and the episode length constraint.

A simple conceptual representation:

```text
             |
             |   Pole
             |
             |
        _____|_____
       |           |
       |   Cart    |
       +-----------+
   =====================
          Track
```

The agent tries to keep the pole balanced by moving the cart left or right.

# 16. Important Details of State Space

One of the important points of the chapter is the difference between the number of variables in a state and the number of possible states.

For example, in the game of Checkers:

- The number of pieces and the variables describing the board is limited.
- However, different combinations of piece placements can create a very large number of states.

Therefore:

**The number of variables in each state does not necessarily indicate the number of possible states.**

A state can be described with a limited number of variables but have a very large state space.

This is very important in designing RL algorithms, because increasing the number of possible states makes computation and learning more difficult.

## Finite vs Infinite State Space

- Finite state space: the number of possible states is limited.
- Infinite state space: the number of possible states is unlimited.

In continuous environments, for example the position of a robot in three-dimensional space, the state space can be infinite.

However, each state may be described with only a limited number of variables.

# 17. Corner States

A corner state refers to states in a grid world that are located in the corners of the environment.

In these states, the number of allowed actions is smaller.

For example, in a grid:

- Center cell: four possible moves.
- Side cell: three possible moves.
- Corner cell: two possible moves.

**Conceptual representation of movement constraints in a grid:**

```text
+-----+-----+-----+
|     |     |     |
+-----+-----+-----+
|     |  C  |     |
+-----+-----+-----+
|     |     |     |
+-----+-----+-----+
```

In the center cell `C`, there are four directions of movement:

```text
              Up
               ^
               |
       Left <--C--> Right
               |
               v
             Down
```

But in the corner of the grid:

```text
+-----+-----+
|  C  |     |
+-----+-----+
|     |     |
+-----+-----+
```

Only two directions of movement remain inside the grid:

```text
              Down
               |
               v
       Right -> C
```

If the agent tries to leave the environment, it may hit a wall and remain in the same position.

Therefore, the transition function must take into account the movement constraints at the corners and edges.

# 18. Reward Expectation

Reward expectation, or expected reward, refers to the average expected reward computed by considering all possible outcomes of an action.

In a stochastic environment, an action may have several different outcomes.

Therefore, one cannot consider only a single outcome when computing the reward.

General formula:

```math
\mathbb{E}[R] = \sum_{s'} P(s' \mid s, a) R(s, a, s')
```

Example:

Suppose a robot has three paths to reach the goal and each path has a different probability of success.

To compute the expected reward, we multiply the reward of each outcome by its probability of occurrence and sum the results.

This concept is very important in probabilistic environments.

# 19. Environment Feedback and Filtering

After receiving an action from the agent, the environment updates its internal state.

**Interaction cycle:**

```text
       +------------------+
       |      Agent       |
       +------------------+
                |
                | Action
                v
       +------------------+
       |   Environment    |
       +------------------+
                |
                | Transition
                v
       +------------------+
       |    New State     |
       +------------------+
                |
                | Reward + Observation
                v
       +------------------+
       |      Agent       |
       +------------------+
                |
                v
         Next Time Step
```

Stages of interaction:

1. The agent selects an action.
2. The environment receives the action.
3. A transition occurs.
4. A new state is created.
5. The environment provides a reward.
6. The necessary information is passed to the agent.

## Filtering

In some environments, not all internal information of the environment is provided to the agent.

As a result, the information the agent receives can be a limited or filtered version of the true state of the environment.

Example: A self-driving car cannot know all information about the road and the behavior of other drivers, but it can receive important information about its surroundings from sensors.

This is one of the reasons for the importance of observations and POMDPs.

# 22. The Most Important Points of Chapter 2

If we were to reduce the entire chapter to its key concepts, these are its most important points:

1. **Reinforcement Learning:** The agent learns through interaction with the environment and receiving rewards.
2. **Agent and Environment:** The agent makes decisions and the environment responds to its decisions.
3. **State:** The current condition of the environment.
4. **Observation:** The information the agent receives from the environment.
5. **Action:** An action the agent can perform.
6. **Transition Function:** Specifies how to move from the current state to the next state.
7. **Reward Function:** Specifies the quality of the outcome of actions numerically.
8. **Deterministic and Stochastic:** Specify whether the outcomes of actions are certain or probabilistic.
9. **Episode and Time Step:** The basic units for describing the agent's interaction with the environment.
10. **Return:** The sum of rewards received during a task.
11. **Policy:** Specifies what action the agent selects.
12. **Model:** Predicts the future behavior of the environment.
13. **Value Function:** Estimates the long-term value of a state.
14. **MDP:** A mathematical framework for modeling decision-making environments.
15. **Markov Property:** The future depends on the current state and action, not the entire history.
16. **Terminal State:** The state at the end of an episode.
17. **Planning Horizon:** Specifies the time frame of the agent's decision-making.
18. **Discount Factor:** Determines the importance of future rewards.
19. **POMDP:** Used for environments in which the agent does not have complete information about the state.
20. **Reward Expectation:** Computes the average expected reward taking probabilities into account.

**Important note:** Understanding the differences between MDP and POMDP, state and observation, policy and value function, as well as transition and reward function, is very important before studying Chapter 3. These concepts are the foundation for understanding deep reinforcement learning algorithms.
