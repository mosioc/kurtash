# Comprehensive Summary of Chapter 10 of Grokking Deep Reinforcement Learning

Chapter 10 introduces methods for improving DQN-based algorithms. The main focus of this chapter is on increasing **sample efficiency**, improving the neural network architecture, selecting training experiences more intelligently, and increasing the stability of the learning process.

In previous chapters, we became familiar with DQN and Double DQN. In this chapter, several complementary techniques are introduced that can improve the performance of these algorithms:

1. **Dueling Network Architecture**: separating the value of a state from the advantage of an action.
2. **Prioritized Experience Replay (PER)**: prioritizing experiences based on their learning importance.
3. **Polyak Averaging**: gradual and smooth updating of the target network.
4. **Dueling DDQN**: combining the Dueling architecture with the Double DQN algorithm.

The important point is that these methods are not necessarily independent algorithms that replace DQN. They are techniques for improving its architecture, sampling, and training stability.

## 1. Main Goal of the Chapter: Sample Efficiency

**Sample efficiency** means that the agent can reach desirable performance with fewer interactions with the environment.

In reinforcement learning, each experience usually contains the following information:

```
Experience = (State, Action, Reward, Next State, Done)
```

By collecting these experiences and using them to update the neural network, the agent learns which actions have higher value in each state.

But there are two problems:

- Not all experiences are equally useful for learning.
- The neural network may not be able to learn the information shared among different actions well.

Chapter 10 follows two main ideas to solve these problems:

- **Improving how Q-values are represented and estimated:** using a Dueling Network.
- **Improving how stored experiences are used:** using Prioritized Experience Replay.

Polyak Averaging is also used to gradually update the target network.

## 2. Dueling Network Architecture

### 2.1. Problem with the Ordinary DQN Architecture

In ordinary DQN, the neural network directly estimates the Q-value for each action in a state.

The Q-function is:

$$
Q(s,a)
$$

That is:

- `s`: the current state of the environment
- `a`: the action the agent selects
- `Q(s,a)`: the value of taking that action in that state

For example, in CartPole, suppose the agent has two actions:

- Move left
- Move right

The neural network must estimate the value of both actions.

The problem is that the overall value of a state may be much more important than the differences among the actions available in that state.

For example, suppose the agent is in a situation where the pole is almost centered and its velocity is low. This state is generally a good situation. Even if moving left and moving right have different values, both share the same underlying state value.

In the ordinary architecture, the network must also learn this shared information to estimate action values.

**The idea of the Dueling Network is to separate the shared state information from the action-specific information.**

### 2.2. Decomposing the Q-Function into V and A

In the Dueling Network, the Q-function is divided into two parts:

**1. State-Value Function or V-Function**

It shows the value of being in a state, without considering a specific action.

$$
V(s)
$$

**2. Advantage Function or A-Function**

It shows how much better or worse an action is compared with the average value of the actions available in the same state.

$$
A(s,a)
$$

In other words:

- V represents the overall value of the state.
- A represents the relative advantage of an action in that state.

For example:

Suppose in a specific state, the overall value of the situation is 10.

| Action | Advantage |
| --- | --- |
| Move left | +3 |
| Move right | -2 |

In this example, moving left has more advantage than the overall situation, and moving right is weaker than it.

Of course, these numbers are only examples for understanding the concept.

### 2.3. Relationship Among Q, V, and A

The main idea of the Dueling Network can be shown as follows:

```
                 State (s)
                     |
              Shared Network
                     |
              Shared Features
                /         \
               /           \
              V             A
         State Value     Advantage
              |             |
              |       Advantage per
              |          Action
              |             |
               \           /
                \         /
                 Q-Values
```

The network first extracts the shared features of the state and then sends them to two different streams:

- Value stream: estimates V(s)
- Advantage stream: estimates A(s,a)

Finally, the outputs of these two streams are combined to obtain the Q-value of each action.

### 2.4. Why Can't We Simply Add V and A?

The initial conceptual relationship is:

$$
Q(s,a) = V(s) + A(s,a)
$$

But there is a mathematical problem.

If we only have Q, we cannot uniquely determine which part belongs to V and which part belongs to A.

For example, two different sets of values for V and A could produce the same Q.

This problem is called the **identifiability problem**.

To solve this problem, the Dueling architecture uses an aggregation operation.

### 2.5. Aggregating the Value and Advantage Streams

The standard Dueling Network formula is:

$$
Q(s,a;\theta,\alpha,\beta) = V(s;\theta,\beta) + \left( A(s,a;\theta,\alpha) - \frac{1}{|\mathcal{A}|} \sum_{a'} A(s,a';\theta,\alpha) \right)
$$

In this formula:

- $\theta$: the parameters of the shared layers
- $\beta$: the parameters of the value stream
- $\alpha$: the parameters of the advantage stream
- $|\mathcal{A}|$: the number of possible actions

In fact, the average advantage of all actions is subtracted from the advantage of each action.

This centers the advantages around zero and largely resolves the non-uniqueness of the decomposition.

**Note:** In some implementations, the maximum advantage is used instead of the average advantage, but the standard formula from the Dueling Network paper uses the average.

### 2.6. Advantages of the Dueling Network

- **Better generalization:** shared state information is shared among all actions.
- **Faster learning:** learning the overall value of the state can help estimate the value of different actions better.
- **Better action comparison:** the agent can better distinguish the value differences among similar actions.
- **Sample efficiency:** more effective use of existing experiences can reduce the need for fewer interactions with the environment.

An important note: the Dueling Network does not guarantee that each experience directly updates all actions. Its main advantage is sharing features and jointly learning the value stream and the advantage stream.

### 2.7. When Is the Dueling Network More Useful?

This architecture is especially useful when:

- There are many actions.
- The overall value of the state provides important information about all actions.
- The value differences among actions are small in many states.
- Some states have high value, but the choice of action in them is less important.

## 3. Continuously Updating the Target Network

### 3.1. Review of the Target Network

In DQN, we use two neural networks:

**Online Network**

This is the main network that is trained using experiences, and its parameters are updated at every step.

**Target Network**

This is the network used to compute the target Q-value and helps stabilize training.

In the usual DQN method, the parameters of the target network remain fixed for a while and are then copied from the online network after a certain number of steps.

```
Online Network:
θ  →  θ₁  →  θ₂  →  θ₃  →  θ₄

Target Network:
θ' →  θ'  →  θ'  →  θ'  →  θ₄
```

This method is known as hard target update.

### 3.2. Problem with Hard Update

This method has two problems:

1. The target network lags behind the changes of the online network for a while.
2. When the parameters are copied, a sudden and large change occurs in the target network.

These sudden changes can cause instability in the target Q-value estimates.

### 3.3. Polyak Averaging

To solve this problem, we use Polyak Averaging.

In this method, instead of fully copying the parameters of the online network, only a part of them enters the target network each time.

Formula:

$$
\theta' \leftarrow \tau\theta + (1-\tau)\theta'
$$

In this formula:

- $\theta$: the parameters of the online network
- $\theta'$: the parameters of the target network
- $\tau$: the mixing factor

### 3.4. Behavior of Tau

The parameter tau determines how much of the online network weights enter the target network.

```
Small Tau
   |
   +--> Small contribution from Online Network
   +--> Slow Target Network update
   +--> More gradual changes

Large Tau
   |
   +--> Large contribution from Online Network
   +--> Faster Target Network update
   +--> Less smoothing
```

For example, if:

$$
\tau = 0.1
$$

then at each step:

- 10 percent of the online network weights
- 90 percent of the previous target network weights

participate in forming the new target network weights.

If tau equals one:

$$
\theta' = \theta
$$

That is, the target network becomes exactly equal to the online network.

If tau equals zero, the target network does not change at all.

### 3.5. Difference Between Hard Update and Polyak Averaging

| Feature | Hard Update | Polyak Averaging |
| --- | --- | --- |
| Update method | Full copy of weights | Gradual combination of weights |
| Update time | Periodically | At every step |
| Changes | Sudden | Gradual |
| Control of changes | By time interval | By tau |
| Target network behavior | Fixed and then jumps | Smooth and continuous movement |

**Conclusion:** Polyak Averaging makes the target network change gradually and always move with a slight delay relative to the online network.

Of course, this method alone does not guarantee complete training stability.

## 4. Prioritized Experience Replay (PER)

### 4.1. Review of Experience Replay

In DQN, the agent's experiences are stored in a replay buffer.

Each experience is usually of the following form:

$$
(s_t, a_t, r_{t+1}, s_{t+1}, d_{t+1})
$$

which includes the state, action, reward, next state, and whether the episode has ended.

During training, instead of directly using the latest experience, a batch of stored experiences is selected.

In the usual method, these experiences are selected with equal probability.

We call this method uniform random sampling.

### 4.2. Problem with Uniform Random Sampling

The main problem is that not all experiences have the same learning value.

For example:

- Some experiences provide new and important information.
- Some experiences have a completely predictable outcome.
- Some experiences create a large difference between the predicted value and the actual outcome.

If all experiences are selected with equal probability, a lot of time may be spent learning from experiences that do not contain much new information.

**The idea of PER:** experiences with greater learning potential should enter the training batch with higher probability.

### 4.3. Criterion for Identifying Important Experiences: TD Error

The main question is:

How do we determine which experience is more important for learning?

In chapter 10, the main answer is to use the **temporal difference error (TD Error)**.

The TD Error shows the difference between the predicted value and the target value.

In the simple case:

$$
\delta = \text{Target} - Q(s,a)
$$

For a one-step target in DQN:

$$
\delta = r + \gamma \max_{a'} Q(s',a';\theta') - Q(s,a;\theta)
$$

where:

- $r$: the received reward
- $\gamma$: the discount factor
- $s'$: the next state
- $\theta$: the parameters of the online network
- $\theta'$: the parameters of the target network

The larger the absolute value of the TD Error, the greater the difference between the agent's prediction and the target.

Therefore, the experience can provide newer information for learning.

### 4.4. Why Do We Use Absolute TD Error?

The TD Error can be positive or negative:

- Positive TD Error: the target is greater than the predicted value.
- Negative TD Error: the target is less than the predicted value.

But in prioritization, the magnitude of the difference matters, not its direction.

Therefore, we use the absolute value:

$$
\text{Priority} \propto |\delta|
$$

**Note:** A large TD Error does not necessarily mean a large reward. An experience may have a negative reward but be very informative because of the large difference from the agent's prediction.

This is exactly one of the important points of the chapter: we should not consider only experiences with positive or large rewards as important.

## 5. Stochastic Prioritization

### 5.1. Problem with Greedy Prioritization

One simple approach is to always select the experience with the largest TD Error.

But this method has problems:

- Certain experiences may be repeated too much.
- The diversity of training experiences decreases.
- Experiences with low TD Error do not get enough opportunity to be learned from.
- Noise or outliers may affect the training process.

### 5.2. Solution: Stochastic Prioritization

Instead of deterministically selecting the most important experience, we determine the probability of selecting each experience according to its priority.

```
Experience A: High Priority   → High Probability
Experience B: Medium Priority → Medium Probability
Experience C: Low Priority    → Low Probability
```

In this method:

- More important experiences have a higher chance of being selected.
- Less important experiences still have a chance of being selected.

Therefore, we both use valuable information more and preserve the diversity of training data.

## 6. Two Main Prioritization Methods

In PER, there are two main methods for determining the priority of experiences:

1. Proportional prioritization
2. Rank-based prioritization

Both methods use the TD Error, but the way they compute priority is different.

### 6.1. Proportional Prioritization

In this method, the priority of each experience is directly proportional to the absolute value of its TD Error.

Formula:

$$
p_i = |\delta_i| + \epsilon
$$

where:

- $p_i$: the priority of experience number $i$
- $\delta_i$: the TD Error of the experience
- $\epsilon$: a small positive value to prevent zero priority

The probability of selecting each experience is then computed:

$$
P(i) = \frac{p_i^\alpha}{\sum_k p_k^\alpha}
$$

In this formula:

- $P(i)$: the probability of selecting experience $i$
- $p_i$: the priority of the experience
- $\alpha$: the degree to which priority affects the sampling probability

### 6.2. The Role of Alpha

The parameter alpha determines how much the sampling should be based on priority.

```
Alpha = 0
   |
   +--> Uniform Random Sampling
   +--> All experiences have equal probability

Alpha = 0.5
   |
   +--> Partial Prioritization
   +--> High-priority experiences are favored

Alpha = 1
   |
   +--> Full Prioritization
   +--> Sampling probability follows raw priorities
```

Therefore:

- Low alpha: sampling is closer to uniform sampling.
- High alpha: differences in priority have a greater effect on selection probability.

**Note:** Alpha equal to one does not mean deterministic selection of the experience with the largest TD Error. Probabilistic sampling is still used.

### 6.3. Rank-Based Prioritization

In proportional prioritization, a very large TD Error may cause one experience to have a much higher priority than the rest.

To reduce sensitivity to outliers, we use rank-based prioritization.

In this method, instead of directly using the TD Error value, we sort the experiences based on the absolute value of the TD Error.

Then we assign a rank to each experience.

```
Experience       | Absolute TD Error | Rank
--------------------------------------------
Experience A     |       100         |  1
Experience B     |        50         |  2
Experience C     |        20         |  3
Experience D     |         5         |  4
Experience E     |         1         |  5
```

The priority of each experience is obtained from the following relation:

$$
p_i = \frac{1}{\text{rank}(i)}
$$

The probability of selecting an experience is then:

$$
P(i) = \frac{p_i^\alpha}{\sum_k p_k^\alpha}
$$

### 6.4. Example of Rank-Based Prioritization

Assuming alpha equals one:

```
Rank 1  → Priority = 1.00
Rank 2  → Priority = 0.50
Rank 3  → Priority = 0.33
Rank 4  → Priority = 0.25
Rank 5  → Priority = 0.20
```

Therefore, the experience with rank one has the highest selection probability.

### 6.5. Comparison of Proportional and Rank-Based

| Feature | Proportional | Rank-Based |
| --- | --- | --- |
| Priority criterion | TD Error value | TD Error rank |
| Sensitivity to outliers | Higher | Lower |
| Attention to the magnitude of differences | Direct | Indirect |
| Resistance to large noise | Lower | Higher |
| Sorting complexity | None | Requires rank management |

**Advantage of proportional:**

If the differences in TD Errors are truly meaningful, this method can better reflect the importance differences among experiences.

**Advantage of rank-based:**

If one experience has a very large TD Error, it cannot create a very large gap with other experiences simply because of the size of the number.

**Limitation of rank-based:**

This method is less sensitive to the actual magnitude of the TD Error. For example, the difference between TD Errors of 100 and 50 and the difference between 1000 and 500 are the same in terms of rank.

Neither of these two methods is the best choice in all reinforcement learning problems.

## 7. Prioritization Bias and Importance Sampling

### 7.1. Problem of Bias in PER

So far, we have learned that PER selects more important experiences with higher probability.

But this creates a statistical problem.

In uniform random sampling, all experiences have the same selection probability.

But in prioritized sampling, the selection probabilities of experiences are different.

As a result, the distribution of samples used for training differs from the uniform sampling distribution.

This problem can introduce bias into the updates of the network parameters.

In simple terms:

**The network is overly influenced by experiences that have higher priority.**

### 7.2. Solution: Importance Sampling

To reduce this bias, we use importance sampling.

In this method, we assign a weight to each experience to correct the effect of the non-uniform sampling probability.

Importance sampling weight formula:

$$
w_i = \left( \frac{1}{N \cdot P(i)} \right)^\beta
$$

where:

- $w_i$: the importance sampling weight of experience $i$
- $N$: the total number of experiences in the replay buffer
- $P(i)$: the probability of selecting experience $i$
- $\beta$: the degree of bias correction

### 7.3. The Role of Beta

The parameter beta determines how much the bias caused by prioritized sampling is corrected.

```
Beta = 0
   |
   +--> No importance-sampling correction
   +--> All weights are equal to 1

Beta = 0.5
   |
   +--> Partial bias correction

Beta = 1
   |
   +--> Full importance-sampling correction
```

In practice, beta usually starts from a smaller initial value and gradually reaches one.

This process is called **beta annealing**.

The reason is that in the early stages of training, prioritization can be useful, and in the stages near convergence, bias correction becomes more important.

### 7.4. Why Do We Normalize the Importance Sampling Weights?

Some weights may become very large and cause instability in the network updates.

To prevent this problem, we normalize the weights by the largest weight in the batch or buffer.

Formula:

$$
w_i^{norm} = \frac{w_i}{\max_j w_j}
$$

As a result:

$$
0 < w_i^{norm} \leq 1
$$

This ensures that the weights only reduce the update magnitude and prevent it from becoming excessively large.

### 7.5. How Does Importance Sampling Enter Training?

In ordinary training, the loss of each experience is computed based on the difference between the predicted Q-value and the target.

In PER, the loss of each experience is adjusted by its importance sampling weight.

For example, if we use mean squared error:

$$
L(\theta) = \frac{1}{B} \sum_{i=1}^{B} w_i^{norm} \left( y_i - Q(s_i, a_i; \theta) \right)^2
$$

where:

- $B$: the batch size
- $w_i^{norm}$: the normalized importance sampling weight
- $y_i$: the target Q-value
- $Q(s_i, a_i; \theta)$: the network's predicted value

Therefore, experiences that have been selected with higher probability are adjusted using the appropriate weight.

**Important difference:**

- Alpha controls the degree of prioritization.
- Beta controls the degree of bias correction caused by prioritization.

## 8. Complete Structure of Prioritized Experience Replay

Now we can put all the steps of PER together.

### 8.1. PER Workflow

```
          Environment
               |
               v
       Collect Experience
               |
               v
        Prioritized Buffer
               |
               v
       Calculate Priorities
               |
               v
      Stochastic Sampling
               |
               v
       Sample a Mini-Batch
               |
               v
     Calculate Importance Weights
               |
               v
       Calculate TD Targets
               |
               v
        Calculate Weighted Loss
               |
               v
       Update Online Network
               |
               v
       Recalculate TD Errors
               |
               v
        Update Priorities
               |
               +----------> Repeat
```

### 8.2. Algorithm Steps

1. The agent interacts with the environment.
2. The new experience is stored in the prioritized replay buffer.
3. For new experiences, a large initial priority is usually assigned so that they have a chance to be selected.
4. Using the priorities, the selection probability of each experience is computed.
5. A mini-batch of experiences is selected using stochastic sampling.
6. The importance sampling weight of each experience is computed.
7. The TD target and TD Error are computed for the experiences.
8. The loss is adjusted using the importance sampling weights.
9. The online network is updated.
10. The priority of the selected experiences is updated with the new TD Error.

The important point is that the priority of experiences is not fixed. As the network changes and the predictions improve, the TD Error also changes, and therefore the priority must be updated.

### 8.3. Sum Tree Data Structure

To implement proportional prioritization efficiently, a structure called a sum tree can be used.

In this structure:

- Each leaf node contains the priority of one experience.
- Each parent node keeps the sum of the priorities of its children.
- The root node keeps the sum of the priorities of all experiences.

Example:

```
                  15
                /    \
               9      6
              / \    / \
             4   5  2   4
```

In this example:

- The root is 15.
- The priority of each experience is in a leaf node.
- The sum of priorities is kept in the higher nodes.

Using a sum tree, experiences can be selected in proportion to their priorities, and priority updates can also be performed efficiently.

## 9. Combining the Dueling Network and Double DQN

### 9.1. What Is Dueling DDQN?

In this chapter, the Dueling Network is used alongside Double DQN.

This combination is called **Dueling Double Deep Q-Network (Dueling DDQN)**.

In fact, we combine two different ideas:

**Double DQN:**

Uses two networks for action selection and evaluation to reduce overestimation bias in Q-value estimation.

**Dueling Network:**

Improves the representation of the Q-function by dividing it into a value stream and an advantage stream.

Therefore:

```
                 Dueling DDQN
                      |
          +-----------+-----------+
          |                       |
          v                       v
     Double DQN             Dueling Network
          |                       |
          v                       v
 Reduce Overestimation      Separate V and A
          |                       |
          +-----------+-----------+
                      |
                      v
             Improved Q-Learning
```

### 9.2. Difference Between DDQN and Dueling DDQN

| Feature | DDQN | Dueling DDQN |
| --- | --- | --- |
| Double Q-Learning | Yes | Yes |
| Target network | Yes | Yes |
| Value stream | No | Yes |
| Advantage stream | No | Yes |
| Q-value estimation | Direct | From combining V and A |
| Main goal | Reducing overestimation | Improving representation and value estimation |

Dueling DDQN still uses the logic of Double DQN for action selection and evaluation. The main difference is in the neural network architecture.

### 9.3. Combining Dueling DDQN with Polyak Averaging

In this chapter, the target network is also updated using Polyak Averaging.

Therefore, instead of hard update, we use soft update:

$$
\theta' \leftarrow \tau\theta + (1-\tau)\theta'
$$

This makes the target network gradually align with the online network.

### 9.4. Combining Dueling DDQN with PER

Next, Prioritized Experience Replay is also added to the algorithm.

In this case:

- Dueling Network: improves the Q-value estimation architecture.
- Double DQN: reduces overestimation bias.
- Polyak Averaging: makes the target network update gradual.
- PER: uses more informative experiences more often in training.
- Importance sampling: adjusts the bias caused by prioritized sampling.

This combination is conceptually an important achievement of chapter 10.

## 10. Results of the Dueling DDQN Experiment

The chapter text refers to experiments using the CartPole environment.

The purpose of the experiment is to examine whether the Dueling Network can provide more accurate action value estimates compared with ordinary DDQN.

### 10.1. Observing Agent Behavior

In the experiment described, the behavior of agents trained with DDQN and Dueling DDQN is compared.

Reported observations:

- The Dueling DDQN agent tended to stay within a smaller range of states.
- This agent was able to better learn the difference between actions with values close to each other.
- In this experiment, a more stable policy was obtained with fewer training steps.

### 10.2. Trade-off Between Training Time and Sample Efficiency

One of the interesting points of the experiments is the existence of a trade-off.

| Measure | DDQN | Dueling DDQN |
| --- | --- | --- |
| Sample efficiency | Lower in the experiment | Higher in the experiment |
| Required number of steps | More | Fewer |
| Training time | Lower | Slightly higher |

Therefore, Dueling DDQN may require fewer interactions with the environment to reach desirable performance, despite having a higher computational time.

**Note:** These results are not a general guarantee for all environments and should not be interpreted to mean that Dueling DDQN is always better than DDQN.

## 11. Limitations and Challenges of the Methods in the Chapter

### 11.1. Limitations of the Dueling Network

- In problems with a very complex relationship between state and action, separating V and A may not always provide an advantage.
- Increasing the complexity of the architecture can increase computation time.
- Performance improvement depends on the type of environment and the structure of the action space.

### 11.2. Limitations of Prioritized Experience Replay

- Computing and updating priorities adds computational cost.
- Experiences with large TD Errors may be caused by noise.
- Excessive focus on specific experiences can reduce the diversity of training data.
- Changing the sampling distribution introduces bias.
- The algorithm's behavior must be tuned correctly through alpha and beta.

### 11.3. Limitations of Polyak Averaging

- The choice of tau is very important.
- A very large tau makes the target network change faster and reduces the smoothing effect.
- A very small tau makes the target network lag too far behind the online network.

## 12. Final Comparison of the Methods in Chapter 10

| Method | Problem addressed | Solution |
| --- | --- | --- |
| Dueling Network | Learning action values separately without effectively using the shared state value | Separating V and A |
| Polyak Averaging | Sudden changes in the target network | Gradual weight update |
| Prioritized Experience Replay | Inefficient use of replay buffer experiences | Prioritizing experiences |
| Stochastic Prioritization | Excessive focus on specific experiences | Probabilistic sampling |
| Proportional Prioritization | Determining importance based on TD Error | Direct use of absolute TD Error |
| Rank-Based Prioritization | Sensitivity to outliers | Using TD Error rank |
| Importance Sampling | Bias caused by prioritized sampling | Weighting the loss |
| Beta Annealing | Need for gradual bias correction | Gradually increasing beta |

### Most Important Concept Differences

- **V(s):** the value of being in a state.
- **A(s,a):** the advantage of an action relative to the average of actions in the same state.
- **Q(s,a):** the value of taking an action in a state.
- **TD Error:** the difference between the target and the predicted value.
- **Priority:** the importance of an experience for sampling.
- **Alpha:** the intensity of prioritization.
- **Beta:** the intensity of bias correction.
- **Polyak Averaging:** gradual combination of online and target network weights.
- **Importance Sampling:** correcting the effect of non-uniform sampling.
