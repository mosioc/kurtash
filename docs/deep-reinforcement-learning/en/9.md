## 2. Introduction: Why Do We Need DQN?

In chapter 8, we became familiar with methods such as NFQ that used neural networks to approximate the value function.

In tabular methods such as Q-Learning, we store a Q-value for each state and action.

But this method has problems in complex environments:

- The number of states can be very large.
- The state space may be continuous.
- The environment input may be raw images.
- Storing a separate Q-value for all states is not practical.

The solution is to use function approximation.

Instead of storing all Q-values, a neural network learns to approximate the Q-function.

### What Is DQN?

**Deep Q-Network (DQN)** is an algorithm that uses a deep neural network to estimate the action-value function.

The Q-function is approximated as follows:

$$
Q(s,a;\theta)
$$

where:

- $s$: the current state of the environment
- $a$: the chosen action
- $\theta$: the neural network parameters
- $Q(s,a;\theta)$: the estimated value of taking action $a$ in state $s$

Instead of computing only one Q-value for one state-action pair, the neural network usually outputs the Q-values of all possible actions for a given state.

### 1. Conceptual Structure of DQN

```
State (environment input)
    |
    | Example: an Atari game image
    v
Deep Neural Network
    |
    | Feature extraction and Q-value estimation
    v
Q-Values
    |
    |-- Left  = 2.1
    |-- Right = 5.8
    |-- Jump  = 3.4
    |
    v
Action Selection
    |
    v
Right (highest Q-value)
```

In the greedy case, the agent selects the action with the highest Q-value:

$$
a^* = \arg\max_a Q(s,a;\theta)
$$

Of course, in practice, epsilon-greedy or other methods may be used for exploration.

### Historical Importance of DQN

DQN showed that a neural network can be used to learn directly from raw image input.

This algorithm achieved remarkable success in Atari games and showed that an agent can extract useful patterns from its own experience without hand-designed visual features.

Note: DQN was not the first deep RL algorithm, but it is considered one of the most important early achievements in combining deep learning and Q-Learning.

## 3. Main Challenges of Value-Based Deep Reinforcement Learning

One of the most important topics of the chapter is why training neural networks in RL is unstable.

In supervised learning, data usually comes from a fixed dataset and the model is trained on it.

But in reinforcement learning, the agent generates its own data, and its behavior affects future data.

Two main problems are discussed:

1. Violation of the IID assumption
2. Non-stationarity of targets

### 3.1. What Is the IID Assumption?

IID stands for:

**Independent and Identically Distributed**

That is, the data must have two properties:

**Independent:**

Training samples must not depend on each other.

**Identically distributed:**

Samples must be generated from the same probability distribution.

For example, suppose we flip a fair coin several times:

- The result of each flip is independent of the previous flip.
- The probability of heads and tails is constant on each flip.

Therefore, the data is approximately IID.

### 3.2. Why Are RL Data Not Independent?

In RL, data is generated sequentially.

$$
S_t \rightarrow A_t \rightarrow R_{t+1} \rightarrow S_{t+1}
$$

The next state depends on the previous state and the chosen action.

As a result:

- Consecutive experiences are dependent.
- Training samples are not fully independent.
- The agent is influenced by its recent experiences.

For example, in a game, if the agent moves along a specific path, it will likely collect several consecutive experiences from the same region of the game.

### 3.3. Non-Stationarity of Data

The problem is not only the dependence of samples.

The distribution of training data also changes as the policy changes.

Suppose:

1. The agent initially behaves randomly.
2. It gradually learns to pass through specific paths.
3. Now most of its experiences are collected from new paths.

Therefore, the distribution of states the agent observes changes as training progresses.

$$
\pi_1 \neq \pi_2
$$

$$
d^{\pi_1}(s) \neq d^{\pi_2}(s)
$$

Here $d^\pi(s)$ is the distribution of states produced by the given policy.

**Conclusion:** Unlike many supervised learning problems, RL training data is not necessarily independent and does not necessarily have a fixed distribution.

### 3.4. Non-Stationarity of Targets

The second problem is the constant change of the targets the neural network must learn.

In Q-Learning, the learning target is:

$$
y = r + \gamma \max_{a'} Q(s',a';\theta)
$$

Note that the target itself depends on the neural network parameters $\theta$.

That is:

1. The neural network estimates the Q-value.
2. The same estimate is used to build the target.
3. The network is updated using the target.
4. As the network changes, the target also changes.

As a result, the network is learning from a goal that it is constantly changing itself.

This problem can cause instability and even divergence.

### 2. The Cycle of Target Change

```
Neural network estimates Q-value
                |
                v
Target is built from the Q estimate
                |
                v
Network is updated to move closer to the target
                |
                v
The target changes!
                |
                v
          Repeat the cycle
```

These two problems, namely the dependence and changing distribution of data and the changing targets, are among the most important reasons why DQN needs stabilization techniques.

## 4. Target Network

One of the most important innovations of DQN is the use of a target network.

### 4.1. What Is a Target Network?

In DQN, instead of using one network for all computations, we use two neural networks:

1. **Online Network (main network):** the network that is continuously trained.
2. **Target Network:** the network used to compute the target.

We denote the parameters of these two networks as follows:

$$
Q(s,a;\theta)
$$

for the online network and:

$$
Q(s,a;\theta^-)
$$

for the target network.

The parameters of the target network are copied from the online network, but unlike it, they are not updated at every step.

### 4.2. How It Works

In DQN, the target is computed as follows:

$$
y = r + \gamma \max_{a'} Q(s',a';\theta^-)
$$

In this formula:

- $r$: the received reward
- $\gamma$: the discount factor
- $s'$: the next state
- $\theta^-$: the target network parameters

The online network then tries to bring its prediction closer to the target.

$$
L(\theta) = \left( y - Q(s,a;\theta) \right)^2
$$

In this way, the main network is trained for a while with a relatively fixed target.

### 4.3. How Is the Target Network Updated?

There are two common methods:

**Method one: Hard Update**

At specified intervals, the parameters of the online network are copied to the target network.

$$
\theta^- \leftarrow \theta
$$

For example, every 1000 or 10,000 steps.

**Method two: Soft Update**

The parameters of the target network gradually move toward the parameters of the online network:

$$
\theta^- \leftarrow \tau \theta + (1-\tau)\theta^-
$$

where:

$$
0 < \tau \leq 1
$$

A smaller value of $\tau$ makes the target network change more slowly.

### 3. Comparison of the Two Networks in DQN

```
DQN
 |
 +---- Online Network
 |       |
 |       +---- Trainable
 |       |
 |       +---- Updated with gradient descent
 |
 +---- Target Network
         |
         +---- Temporarily frozen
         |
         +---- Computes more stable targets
```

**Target Network update methods:**

```
Hard Update:
Periodically copy the online network parameters to the target network

θ- ← θ

Soft Update:
Gradually transfer the online network parameters to the target network

θ- ← τθ + (1 - τ)θ-
```

**Online Network**

Trainable

Updated with gradient descent

**Target Network**

Temporarily frozen

Computes more stable targets

In hard update, the online parameters are periodically copied to the target. In soft update, this transfer is gradual.

**Main advantage of the target network:** reducing target fluctuations and making the learning process more stable.

**Note:** Keeping the target network fixed forever is not correct, because then the targets would not be updated as learning progresses. Therefore, it must be updated from time to time.

### 4.4. Using Larger Networks

A larger neural network can have greater capacity to approximate complex functions.

In environments such as Atari, using deeper networks and architectures such as CNNs makes it possible to extract features from images.

But a larger network is not always better:

- It requires more computation.
- Training may become more difficult.
- It can be prone to overfitting.
- It requires careful tuning of hyperparameters.

Therefore, the network architecture should be chosen according to the complexity of the environment.

## 5. Experience Replay

Another problem in RL is the dependence of consecutive experiences.

To solve this problem, DQN uses a technique called Experience Replay.

### 5.1. What Is Experience Replay?

Experience Replay is a memory for storing the agent's past experiences.

Instead of using only the agent's latest experience for training, previous experiences are stored and later sampled randomly from.

This memory is usually called the Replay Buffer.

### 5.2. Structure of the Replay Buffer

Each experience is stored as a tuple:

$$
e_t = (s_t, a_t, r_{t+1}, s_{t+1}, d_{t+1})
$$

Its components:

| Component | Meaning |
| --- | --- |
| $s_t$ | Current state |
| $a_t$ | Chosen action |
| $r_{t+1}$ | Received reward |
| $s_{t+1}$ | Next state |
| $d_{t+1}$ | Indicates whether the episode has ended |

Usually, the replay buffer has a fixed capacity. When the capacity is full, old experiences are replaced by new ones.

This structure is usually implemented as a circular buffer.

### 5.3. How Experience Replay Works

The process is as follows:

1. The agent interacts with the environment.
2. The new experience is stored in the replay buffer.
3. A number of experiences are selected randomly.
4. These experiences form a mini-batch.
5. The neural network is trained using the mini-batch.
6. This process is repeated.

### 4. Experience Replay Cycle

```
Agent interacts with Environment
                |
                v
        Store Experience
                |
                v
(State, Action, Reward, Next State, Done)
                |
                v
          Replay Buffer
                |
                +---- Experience 1
                +---- Experience 2
                +---- Experience 3
                +---- Experience 4
                +---- Experience 5
                |
                v
         Random Sampling
                |
                v
            Mini-Batch
                |
                v
       Train Online Network
                |
                v
              Repeat
```

### 5.4. Why Is Random Sampling Important?

Suppose the agent is moving along a specific path in a game.

If we use only recent experiences for training, most samples will likely correspond to situations close to each other.

This problem causes:

- Training samples to be dependent on each other.
- The network to be overly influenced by recent experiences.
- Training to fluctuate more.

With random sampling, experiences from different times and situations enter the mini-batch.

As a result, the temporal dependence of the samples in a batch is reduced and training becomes more stable.

### 5.5. Advantages of Experience Replay

1. **Reducing correlation:** reducing the correlation between training samples.
2. **Better data efficiency:** reusing previous experiences.
3. **More stable training:** preventing excessive dependence on recent experiences.
4. **Improved generalization:** helping to learn from more diverse situations.

### 5.6. Limitations of Experience Replay

- It requires more memory.
- The buffer size must be chosen according to the problem.
- Very old experiences may be less relevant to the current policy.
- Purely random sampling does not guarantee that more important experiences are used more often.

Important note: Experience Replay does not make data fully IID. It reduces the dependence and correlation between the samples selected for training.

## 6. Exploration Strategies

In previous chapters, we became familiar with exploration and exploitation.

DQN also needs an exploration strategy to select actions.

### 6.1. Epsilon-Greedy

One of the most common methods is epsilon-greedy.

In this method:

- With probability $\epsilon$, a random action is chosen.
- With probability $1-\epsilon$, the current best action is chosen.

$$
a_t =
\begin{cases}
\text{Random Action} & \text{with probability } \epsilon \\
\arg\max_a Q(s_t, a; \theta) & \text{with probability } 1-\epsilon
\end{cases}
$$

### 6.2. Decaying Epsilon

Usually, the value of epsilon decreases during training.

At the beginning of training:

- The agent has little knowledge.
- Exploration is more important.

Later:

- The agent gains more experience.
- It can make more use of its current knowledge.

Therefore:

$$
\epsilon_{\text{initial}} > \epsilon_{\text{final}}
$$

For example:

```
Initial epsilon = 1.0
Final epsilon   = 0.01
```

These values are only examples and depend on the problem.

### 6.3. Other Exploration Methods

The chapter text also refers to the use of other strategies.

- **Softmax exploration:** selecting actions with probability proportional to their estimated value.
- **Optimistic initialization:** starting with optimistic estimates to encourage the agent to try unknown actions.

These strategies can replace or complement epsilon-greedy.

## 7. Double DQN

(Key concept of chapter 9)

One of the important problems with Q-Learning and DQN is the overestimation of action values.

We call this problem overestimation bias.

### 7.1. What Is Overestimation?

In Q-Learning, we use the following relation to compute the target:

$$
y = r + \gamma \max_{a'} Q(s',a')
$$

The problem is that we use the maximum of the estimated values.

Suppose the true Q-values of three actions are as follows:

| Action | True Q | Estimated Q |
| --- | --- | --- |
| A | 5 | 6 |
| B | 4 | 8 |
| C | 3 | 2 |

In this situation:

- The true best action is A.
- But the neural network selects action B.
- The estimated value of B is 8, while its true value is 4.

When we always select the maximum estimated value, positive errors can appear more often in the final selection.

Therefore, the estimated maximum may be systematically greater than the true maximum.

We call this problem overestimation bias.

### 7.2. Difference Between Max and Argmax

To understand Double DQN, we must know the difference between these two concepts.

**Argmax:**

Finds the action with the highest value.

$$
\arg\max_a Q(s,a)
$$

Output: an action

**Max:**

Finds the highest Q-value.

$$
\max_a Q(s,a)
$$

Output: a Q-value

Example:

```
Q-values:

A = 5
B = 8
C = 3

argmax(Q) = B
max(Q)    = 8
```

These two operations play different roles in Double DQN.

### 7.3. Main Idea of Double DQN

In ordinary DQN, one network both selects the action and evaluates its value.

Double DQN separates these two responsibilities.

- Online network: selects the best action
- Target network: evaluates the value of the selected action

In this way, the network that selects the action is not the same network that evaluates the value of that action.

### 7.4. Double DQN Formula

In ordinary DQN:

$$
y_{\text{DQN}} = r + \gamma \max_{a'} Q(s',a';\theta^-)
$$

In Double DQN:

$$
y_{\text{Double DQN}} = r + \gamma Q\left( s', \arg\max_{a'} Q(s',a';\theta); \theta^- \right)
$$

Main difference:

In Double DQN:

1. The online network with parameters $\theta$ selects the best action.
2. The target network with parameters $\theta^-$ computes the value of that same action.

### 7.5. Numerical Example

Suppose the outputs of the two networks are as follows:

| Action | Online Q | Target Q |
| --- | --- | --- |
| A | 5 | 4 |
| B | 8 | 5 |
| C | 3 | 7 |

In Double DQN:

**Step one: select the action with the online network**

$$
a^* = \arg\max_a Q(s',a;\theta)
$$

Therefore:

$$
a^* = B
$$

**Step two: evaluate the action with the target network**

$$
Q(s',B;\theta^-) = 5
$$

So the target value is:

$$
y = r + \gamma(5)
$$

In contrast, ordinary DQN uses the maximum output of the target network:

$$
\max(4,5,7) = 7
$$

In this example, Double DQN uses the value 5 instead of 7.

This separation can reduce the effect of overestimation error.

### 7.6. Does Double DQN Need Two Additional Networks?

No.

DQN already has two networks:

- Online network
- Target network

Double DQN uses these same two networks to separate action selection and action evaluation.

Therefore, there is no need to add two more independent neural networks.

### 7.7. Relationship of Double DQN to Double Q-Learning

In chapter 6, we became familiar with Double Q-Learning.

The fundamental idea of both methods is similar:

**Separating action selection from evaluating its value to reduce overestimation bias.**

The difference is that Double DQN implements this idea in a neural network based architecture using the online and target networks.

## 8. Loss Functions in DQN

To train the neural network, we must calculate the difference between the predicted Q-value and the target.

We call this difference the TD Error:

$$
\delta = y - Q(s,a;\theta)
$$

To optimize the network, a loss function is used.

Three important functions are mentioned in the text:

1. Mean squared error (MSE)
2. Mean absolute error (MAE)
3. Huber loss

### 8.1. Mean Squared Error (MSE)

MSE is the average of the squared difference between the prediction and the target value.

$$
L_{\text{MSE}} = \frac{1}{N} \sum_{i=1}^{N} (y_i - \hat{y}_i)^2
$$

Features:

- It penalizes large errors heavily.
- It is sensitive to outliers.
- Near zero error, the gradient gradually becomes small.
- It is a smooth and differentiable function.

Example:

```
Error = 2  -> Squared Error = 4
Error = 5  -> Squared Error = 25
```

Therefore, an error of 5 has a much greater effect than an error of 2.

### 8.2. Mean Absolute Error (MAE)

MAE is the average of the absolute difference between the predicted value and the target value.

$$
L_{\text{MAE}} = \frac{1}{N} \sum_{i=1}^{N} |y_i - \hat{y}_i|
$$

Features:

- It penalizes large errors in proportion to their size.
- It is more resistant to outliers than MSE.
- It is not differentiable at zero.
- Its gradient is approximately constant with respect to the size of the error.

Example:

```
Error = 2  -> Absolute Error = 2
Error = 5  -> Absolute Error = 5
```

### 8.3. Huber Loss

Huber loss combines the features of MSE and MAE.

For small errors it behaves like MSE, and for large errors it behaves like MAE.

$$
L_\delta(e) =
\begin{cases}
\frac{1}{2}e^2 & |e| \leq \delta \\
\delta(|e| - \frac{1}{2}\delta) & |e| > \delta
\end{cases}
$$

where:

$$
e = y - \hat{y}
$$

and $\delta$ is the threshold at which the function changes behavior.

**If the error is small:**

$$
|e| \leq \delta
$$

the function behaves like MSE.

**If the error is large:**

$$
|e| > \delta
$$

the function behaves like MAE.

### 8.4. The Role of Delta in Huber Loss

The parameter $\delta$ determines the point at which the function's behavior changes from quadratic to linear.

- Small delta: the linear part begins earlier.
- Large delta: the quadratic behavior continues over a larger range.

In the conceptual limits:

- With a very small $\delta$, the behavior approaches MAE.
- With a very large $\delta$, the behavior approaches MSE.

### 8.5. Comparison of the Three Loss Functions

| Feature | MSE | MAE | Huber |
| --- | --- | --- | --- |
| Type of penalty | Quadratic | Linear | Combined |
| Sensitivity to outliers | High | Lower | Lower |
| Gradient near zero | Gradual | Approximately constant | Gradual |
| Differentiability at zero | Yes | No | Yes |
| Stability against large errors | Lower | Higher | Higher |

### 8.6. Gradient Clipping

In training neural networks, gradients sometimes become very large.

This phenomenon can cause training instability and is called exploding gradients.

Gradient clipping is used to limit the size of the gradient.

One common method is clip by norm:

$$
g_{\text{clipped}} = g \cdot \min\left(1, \frac{c}{\|g\|}\right)
$$

where:

- $g$: the original gradient
- $c$: the maximum allowed norm
- $g_{\text{clipped}}$: the clipped gradient

If the norm is greater than the threshold, the gradient is scaled down.

**Important note:** Gradient clipping is different from Huber loss. The former limits the size of the gradient, while the latter changes the shape of the error function. Also, using gradient clipping does not mean using MSE. These are two independent decisions in designing the training process.

### 8.7. Which Loss Is Better?

No function is best in all situations.

- MSE: when heavily penalizing large errors is appropriate.
- MAE: when resistance to outliers matters.
- Huber: when both a smooth gradient and resistance to large errors are needed.

In DQN and many of its implementations, Huber loss is a common choice.

## 9. How the Components of DQN Relate to Each Other

So far, we have become familiar with several important tools. Now we must know exactly which problem each one targets.

| Technique | Main problem | Solution |
| --- | --- | --- |
| Target network | Non-stationary targets | Temporarily fixing the target |
| Experience replay | Correlated samples | Random sampling from past experiences |
| Larger networks | Limited approximation capacity | Increasing the modeling power |
| Exploration strategies | Lack of experience from different parts of the environment | Trying different actions |
| Double DQN | Overestimation bias | Separating action selection and evaluation |
| Huber loss | Sensitivity to large errors | Combining quadratic and linear penalties |
| Gradient clipping | Exploding gradients | Limiting the size of the gradient |

The key point is that none of these techniques alone solves all the problems of DQN. They complement each other.

## 10. The Complete DQN Algorithm

Now we can combine all the concepts into one algorithm.

### 10.1. Steps for Running DQN

1. Create the online network and the target network.
2. Initially make the parameters of the two networks identical.
3. Create the replay buffer.
4. Receive the state from the environment.
5. Select an action using the exploration strategy.
6. Execute the action and receive the reward and next state.
7. Store the experience in the replay buffer.
8. Select a random mini-batch from the buffer.
9. Compute the target using the target network.
10. Compute the loss between the predicted Q-value and the target.
11. Update the online network with gradient descent.
12. Periodically update the target network.
13. Repeat the process until the stopping condition is reached.

### 10.2. DQN Pseudocode

```
Initialize Online Network Q(s, a; θ)
Initialize Target Network Q(s, a; θ-)

Set θ- = θ
Initialize Replay Buffer D

For each episode:

    Initialize state s

    While episode is not finished:

        # Action Selection
        With probability ε:
            Choose a random action
        Otherwise:
            Choose argmax_a Q(s, a; θ)

        # Environment Interaction
        Execute action a
        Observe reward r, next state s', done

        # Store Experience
        Store (s, a, r, s', done) in D

        # Random Sampling
        Sample a mini-batch from D

        # Compute Targets
        If done:
            y = r
        Otherwise:
            y = r + γ * max_a' Q(s', a'; θ-)

        # Update Online Network
        Compute loss between:
            Q(s, a; θ)
            and
            y

        Update θ using Gradient Descent

        # Update Target Network
        If target update interval is reached:
            θ- = θ

        s = s'

    Decay ε
```

Note: In this pseudocode, the target for a terminal state is equal to the reward, and the future value should not be added to it.

### 10.3. Final Target Formula in DQN

To express it more precisely, taking the terminal state into account:

$$
y_t =
\begin{cases}
r_{t+1} & \text{if terminal} \\
r_{t+1} + \gamma \max_{a'} Q(s_{t+1}, a'; \theta^-) & \text{otherwise}
\end{cases}
$$

This formula is the core of DQN learning.

## 11. Limitations of DQN and Its Development Path

DQN was an important advance, but it still had limitations.

At the end of the chapter and in the submitted text, two important paths for improving it are mentioned.

These two concepts are taught in full in chapter 10.

### 11.1. Dueling Network

In the usual DQN architecture, the network directly estimates the Q-value of each action.

But there is an important relationship between the state value and the action value.

$$
Q(s,a) = V(s) + A(s,a)
$$

where:

- $V(s)$: the overall value of being in a specific state.
- $A(s,a)$: how much better or worse an action is compared with other actions in the same state.

The Dueling Network architecture estimates these two quantities separately and then combines them.

Main idea:

Sometimes the value of the state itself is important, even when the difference between different actions is not very large.

This architecture allows the network to learn the state value and the action advantage separately.

Main training in chapter 10

### 11.2. Prioritized Experience Replay (PER)

In ordinary experience replay, experiences are selected randomly.

But not all experiences necessarily have the same training value.

For example:

- An experience whose outcome was completely predictable may not contain much new information.
- An experience with a large difference between the predicted value and the target may provide important information.

Prioritized Experience Replay tries to select more important experiences with higher probability for training.

One important criterion for determining priority:

**TD Error**

$$
\delta_i = y_i - Q(s_i, a_i; \theta)
$$

The larger the absolute value of the TD Error, the higher the priority the experience can have for replay.

Of course, prioritized sampling may introduce bias. For this reason, PER uses importance sampling weights to correct this bias.

(Main training in chapter 10)

### 11.3. Comparison of DQN and Later Improvements

| Algorithm / Technique | Main improvement |
| --- | --- |
| DQN | Using a neural network to estimate the Q-function |
| Double DQN | Reducing overestimation bias |
| Dueling DQN | Separating state value and advantage |
| Prioritized Experience Replay | Smarter selection of training experiences |

Note: Double DQN is the topic of chapter 9, but Dueling DQN and PER are main topics of chapter 10.

### The Most Important Mathematical Relationships of the Chapter

| Concept | Formula |
| --- | --- |
| Q-function | $Q(s,a;\theta)$ |
| DQN target | $r + \gamma \max_{a'} Q(s',a';\theta^-)$ |
| DQN loss | $(y - Q(s,a;\theta))^2$ |
| Double DQN | $r + \gamma Q(s', \arg\max_{a'} Q(s',a';\theta); \theta^-)$ |
| TD Error | $y - Q(s,a;\theta)$ |
| Hard update | $\theta^- \leftarrow \theta$ |
| Soft update | $\theta^- \leftarrow \tau\theta + (1-\tau)\theta^-$ |

### Important Concepts

1. DQN uses a neural network to approximate the Q-function.
2. IID is an assumption that samples are independent and identically distributed.
3. RL data is usually not IID because the agent interacts with the environment sequentially.
4. The policy changes as training progresses, and the data distribution changes as well.
5. Non-stationary targets arise because the target depends on the changing estimates of the network.
6. The target network is used to make the targets more stable.
7. The online network is trained, but the target network remains fixed for a while.
8. Experience replay stores past experiences and samples them randomly.
9. The replay buffer reduces the temporal dependence of training samples.
10. Epsilon-greedy balances exploration and exploitation.
11. DQN may suffer from overestimation bias.
12. Double DQN separates action selection from its evaluation.
13. Argmax returns an action, but max returns the maximum value.
14. MSE penalizes large errors quadratically.
15. MAE is more resistant to outliers.
16. Huber loss combines the behavior of MSE and MAE.
17. Gradient clipping is used to control exploding gradients.
18. Dueling Network and PER are important later improvements that are examined in chapter 10.

## 13. Differences Between Similar Concepts That Should Not Be Confused

| Concepts | Difference |
| --- | --- |
| Online network / target network | The first is trained; the second produces targets. |
| DQN / Double DQN | Double DQN separates action selection and evaluation. |
| Max / argmax | One returns the maximum value; the other returns the corresponding action. |
| Experience replay / prioritized replay | The first samples randomly; the second samples based on priority. |
| MSE / MAE | Quadratic penalty versus linear penalty |
| Huber / gradient clipping | Changing the shape of the loss versus limiting the gradient |
| Dueling DQN / Double DQN | The first changes the network architecture; the second changes the method of computing the target. |
| Target network / soft update | The first is a network; the second is one of the methods for updating it. |
