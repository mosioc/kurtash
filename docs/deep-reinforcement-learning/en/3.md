# Comprehensive Summary of Chapter 3 of *Grokking Deep Reinforcement Learning*

**Main topic of the chapter: Solving Markov Decision Processes (MDPs) using Dynamic Programming**

This chapter is one of the most fundamental chapters in reinforcement learning. Its goal is to introduce how to evaluate policies, compute the value of states and actions, and find the optimal policy in environments whose rules and dynamics are known in advance.

In this chapter, concepts are introduced that form the foundation of many later reinforcement learning algorithms, especially Deep Reinforcement Learning.

# 1. Foundations and Prerequisites of the Chapter

## 1.1. Markov Decision Process (MDP)

**Fundamental concept**

A Markov Decision Process (MDP) is a mathematical framework for modeling sequential decision-making problems in reinforcement learning.

In an MDP, an agent is situated in an environment and, by selecting different actions, changes the state of the environment and receives rewards.

The MDP specifies the main rules of the environment, namely:

- What states exist.
- What actions are available.
- What the probability of transitioning from one state to another is.
- What reward each transition carries.

### Agent-Environment Interaction Cycle

At each step, the agent receives the current state, selects an action, and the environment in response returns the next state and the reward.

```text
             Action (A_t)
       +----------------------+
       |                      v
+-------------+         +-------------+
|    Agent    |         | Environment |
+-------------+         +-------------+
       ^                      |
       |                      |
       +----------------------+
          State (S_t+1)
          Reward (R_t+1)
```

**Main problem:** Algorithms such as Value Iteration and Policy Iteration require complete knowledge of the environment model for their computations.

That is, they must have access to information about:

- Transition probabilities
- Reward function

In the real world, such information is not always available, and the environment may be complex or changing.

## 1.2. Dynamic Programming (DP)

Dynamic programming is a set of computational methods for solving decision-making problems by decomposing the problem into smaller subproblems.

In reinforcement learning, dynamic programming is used to evaluate and optimize policies in MDPs.

Two important algorithms in this area are:

1. Policy Iteration
2. Value Iteration

An important feature of dynamic programming is that it uses a known model of the environment.

**Note:** These methods are very important for understanding the principles of RL, even if they cannot be used directly in many real environments.

## 1.3. Difference between Dynamic Programming and Real Reinforcement Learning

In the simple examples of this chapter, we assume the agent has access to complete information about the environment.

Therefore:

- There is no need for exploration to discover the rules of the environment.
- It knows the transition probabilities between states.
- It knows the rewards associated with transitions.
- It can find an appropriate policy through mathematical computation.

These conditions differ from real environments, because in real problems the agent usually must obtain the necessary information through interaction with the environment.

# 2. Reward and Return

## 2.1. Reward

A reward is a numeric value the agent receives from the environment after performing an action or after a transition occurs.

The agent's goal in reinforcement learning is to maximize the expected reward over time.

For example, in a game:

- Reaching the goal: positive reward
- Colliding with an obstacle: negative reward
- Performing an inappropriate action: possibly a negative reward

Rewards specify which behaviors are desirable from the perspective of the environment design.

## 2.2. Return

**Important concept**

The return is the sum of the rewards the agent receives from a point in time to the end of the trajectory.

In other words, unlike the reward, which indicates the reward of a single step, the return considers the sum of future rewards.

The return formula taking the discount factor into account:

```math
G_t = \sum_{k=0}^{T-t-1} \gamma^k R_{t+k+1}
```

In this formula:

- `G_t`: the return from time `t`
- `R_{t+k+1}`: the reward received in the future
- `\gamma`: the discount factor
- `T`: the end time of an episode

## 2.3. Discount Factor or Gamma

**Important concept**

The discount factor specifies how much future rewards matter compared to nearby rewards.

The value of gamma is usually between zero and one:

```math
0 \leq \gamma \leq 1
```

Interpretation of different values:

| Value of gamma | Concept |
| --- | --- |
| Close to 0 | Greater importance of immediate rewards |
| Close to 1 | Greater importance of future rewards |
| Equal to 1 | No discounting of future rewards |

For example, if:

```math
\gamma = 0.5
```

then the weight of the first step's reward is 1, the second step's is 0.5, and the third step's is 0.25.

Therefore, the farther a reward is in the future, the smaller its contribution to the return.

### Illustration of the effect of the discount factor on return

```text
Time:       t        t+1        t+2        t+3
            |          |          |          |
Reward:     R1         R2         R3         R4
            |          |          |          |
Weight:     1          γ          γ²         γ³
            |          |          |          |
            +----------+----------+----------+
                       |
                       v
              Discounted Return

G_t = R1 + γR2 + γ²R3 + γ³R4 + ...
```

## 2.4. Reward-to-Go

Reward-to-go refers to the sum of rewards the agent can receive from the current time onward.

This concept looks forward and specifies how much reward is attainable from the current state onward.

Important difference:

- Reward: the reward of a single step
- Return: the sum of future rewards taking discounting into account
- Reward-to-go: the sum of remaining rewards from the current time onward

# 3. Stochastic Environment

## 3.1. Stochastic Environment

A stochastic environment is one in which the outcome of an action is not always predictable.

For example, suppose the agent intends to move right in a grid environment.

It may:

- Move right.
- Deviate to the left.
- Receive a different outcome because the environment is stochastic.

Therefore, a specific action does not necessarily always lead to a specific state.

This feature causes the agent to consider the probabilities of different outcomes rather than simply choosing a path.

## 3.2. Frozen Lake Example

Frozen Lake is a simple environment for studying decision-making under uncertainty.

In this environment:

- Some tiles are safe.
- Some tiles contain holes.
- One tile is the starting point.
- One tile is designated as the goal.

The agent's goal is to reach the goal without falling into the holes.

But the problem is that the agent's actions may not have the expected outcome due to the stochastic nature of the environment.

Therefore, the agent must have a policy that takes the probabilities of different outcomes into account.

## 3.3. Slippery Walk 5 Example

Slippery Walk 5 is another example of stochastic environments introduced in the chapter.

In this environment, moving in a specific direction does not always mean reaching that direction; the agent may move in another direction due to slipping.

This example is used to understand the effect of stochasticity on return computation and the selection of an appropriate policy.

# 4. Policy

**Fundamental concept**

A policy is a strategy or rule that specifies what action the agent takes in each state.

In simple terms, a policy specifies:

"If you are in this state, what action should you take."

A policy can be defined in different ways:

- Deterministic policy: selects one specific action for each state.
- Stochastic policy: specifies the probability of selecting different actions for each state.

In an environment, there may be several different policies.

There may even be several different policies with the same optimal performance.

For example, in a grid environment, two different paths may both reach the goal and produce the same return.

# 5. Value Functions

Value functions are one of the most important concepts of Chapter 3.

Their purpose is to estimate the amount of reward the agent can obtain from a state or action.

In this chapter, three main concepts are examined:

1. State-Value Function
2. Action-Value Function
3. Action-Advantage Function

## 5.1. State-Value Function (V Function)

**Important concept**

The state-value function shows how much expected return being in a state will bring the agent, given a specific policy.

Formula:

```math
V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]
```

In this formula:

- `V^\pi(s)`: the value of state `s` under policy `\pi`
- `G_t`: the return
- `\mathbb{E}`: the expected value
- `\pi`: the agent's policy

In simple terms, this function tells us:

"If the agent is in this state and acts according to its current policy, how much reward do we expect it to receive in the future?"

Example:

In Frozen Lake, we may have two different states:

- State A: close to the goal and far from the holes
- State B: close to a hole and far from the goal

State A will probably have greater value.

**Note:** The value of a state depends on the policy used. A state may be valuable under one policy and less valuable under another.

## 5.2. Action-Value Function (Q Function)

**Very important concept**

The action-value function specifies how much expected return performing a specific action in a specific state produces.

Formula:

```math
Q^\pi(s, a) = \mathbb{E}_\pi[G_t \mid S_t = s, A_t = a]
```

Unlike the V function, this function does not only examine the value of a state; it also takes a specific action into account.

For example, suppose the agent is in a state and has two choices:

- Move left
- Move right

The V function shows the overall value of being in that state, but the Q function specifies what the outcome of choosing to move left or right will be.

Therefore, the Q function is a more precise tool for comparing different actions.

### Difference between V and Q Functions

| Feature | V Function | Q Function |
| --- | --- | --- |
| Input | State | State and action |
| Purpose | Evaluating a state | Evaluating an action in a state |
| Output | Expected value of the state | Expected value of the action |
| Use | Assessing a situation | Comparing actions |

## 5.3. Bellman Equation

**Fundamental concept**

The Bellman equation is one of the most important mathematical foundations of reinforcement learning.

This equation computes the value of a state or action based on the immediate reward and the expected value of future states.

Core idea:

The value of a decision does not depend only on the reward we receive right now; we must also consider the value of the states we will transition to in the future.

The Bellman formula for the Q function:

```math
Q^\pi(s, a) = \sum_{s', r} p(s', r \mid s, a) \left[ r + \gamma \sum_{a'} \pi(a' \mid s') Q^\pi(s', a') \right]
```

Components of the formula:

- `s`: the current state
- `a`: the current action
- `s'`: the next state
- `r`: the transition reward
- `p(s', r \mid s, a)`: the probability of transition and reward
- `\gamma`: the discount factor
- `\pi`: the agent's policy

The meaning of this equation:

The value of an action equals the immediate reward plus the discounted future value, taking the probabilities of different outcomes into account.

**Use:** The Bellman equation is the computational foundation of many reinforcement learning algorithms.

## 5.4. Action-Advantage Function (A Function)

**Important concept**

The action-advantage function specifies how much better or worse a specific action is compared to the expected value of the state itself.

Formula:

```math
A^\pi(s, a) = Q^\pi(s, a) - V^\pi(s)
```

Interpretation:

- Positive advantage: the action is better than the policy's expected performance in that state.
- Negative advantage: the action is worse than the policy's expected performance.
- Zero advantage: the action is worth as much as the policy's expected performance.

Example:

Suppose the agent's current policy usually selects moving left, but in a specific situation moving right is better.

The advantage function specifies how much better moving right is compared to the overall expected value of that state.

### Difference between Q and Advantage

The Q function shows the value of performing a specific action.

The advantage function shows how much better or worse that action is compared to the overall value of the state.

### Relationship among V Function, Q Function, and Advantage

```text
             State (s)
                 |
          +------+------+
          |             |
          v             v
       V(s)           Q(s,a)
    State Value     Action Value
                        |
                        |
              A(s,a) = Q(s,a) - V(s)
                        |
                        v
                  Advantage
```

# 6. Optimality in Reinforcement Learning

**Fundamental concept**

Optimality means finding the best possible behavior to maximize the expected return.

In this section, the difference between the optimal policy and the optimal value function is examined.

## 6.1. Optimal Policy

The optimal policy is the policy that provides the agent with the greatest expected return.

Notation:

```math
\pi^*
```

An environment may have several optimal policies.

That is, several different policies may achieve exactly the same optimal performance.

## 6.2. Optimal State-Value Function

The optimal state-value function is denoted by:

```math
V^*(s)
```

This function shows the greatest attainable value for each state.

Formula:

```math
V^*(s) = \max_\pi V^\pi(s)
```

That is, among all possible policies, the one with the greatest attainable value for that state is selected.

## 6.3. Optimal Action-Value Function

The optimal action-value function is denoted by:

```math
Q^*(s, a)
```

This function shows the greatest expected return for a state-action pair, assuming that after the current action the agent acts optimally.

Important relationship:

```math
V^*(s) = \max_a Q^*(s, a)
```

That is, to compute the optimal value of a state, it is enough to find the largest Q value among the possible actions in that state.

## 6.4. Optimal Advantage Function

The optimal advantage function specifies the position of an action relative to the best attainable value in the same state.

Formula:

```math
A^*(s, a) = Q^*(s, a) - V^*(s)
```

Since:

```math
V^*(s) = \max_a Q^*(s, a)
```

therefore:

```math
A^*(s, a) \leq 0
```

That is, under optimality, the advantage cannot be positive.

If the advantage of an action is positive, it indicates that the value of that action is greater than the optimal value of the state, which contradicts the definition of optimality.

## 6.5. Relationship among V, Q, and the Optimal Policy

These three concepts are directly related to each other:

**Optimal Q Function**

```math
Q^*(s, a)
```

Shows the optimal value of each state-action pair.

**Optimal V Function**

```math
V^*(s) = \max_a Q^*(s, a)
```

Shows the greatest attainable value in each state.

**Optimal Policy**

```math
\pi^*(s) \in \arg\max_a Q^*(s, a)
```

Selects the action with the greatest value. If several actions have the same optimal value, any of them can be selected in an optimal policy.

### Relationship among Optimal Q, Optimal V, and Optimal Policy

```text
             Optimal Q Function
                  Q*(s,a)
                     |
          +----------+----------+
          |                     |
          v                     v
    max over actions       argmax over actions
          |                     |
          v                     v
    Optimal V Function    Optimal Policy
         V*(s)               π*(s)
```

Important notes:

- If we have the optimal Q function, we can extract the optimal policy.
- If we have the optimal V function, using the environment model and examining one step ahead we can compute the optimal Q function.
- There may be several optimal policies, but in the MDPs discussed, the optimal V and optimal Q are unique.

# 7. Iterative Policy Evaluation

**Very important concept**

Iterative policy evaluation is a method for estimating the value of different states under a specific policy.

The goal of this method is not to find the best policy; rather, we first want to understand how well the current policy performs.

## 7.1. Why Do We Need Iterative Policy Evaluation?

In environments with a large state space, directly computing the value of all states can be difficult.

Therefore, instead of direct computation, we use initial estimates and improve them iteratively.

## 7.2. How It Works

The process is carried out as follows:

1. An initial value is considered for all states.
2. The desired policy is specified.
3. The value of each state is updated based on the expected reward and the value of the next states.
4. This process is repeated many times.
5. When the changes in the values become very small, the process stops.

The main formula for a deterministic policy:

```math
V_{k+1}(s) = \sum_{s', r} p(s', r \mid s, \pi(s)) \left[ r + \gamma V_k(s') \right]
```

For a stochastic policy, we must also average over the possible actions weighted by their selection probabilities.

In this formula:

- `V_k(s)`: the estimated value of the state in the current iteration
- `V_{k+1}(s)`: the estimated value in the next iteration
- `r`: the reward
- `\gamma`: the discount factor
- `p`: the probability of transitioning to the next state

## 7.3. Convergence

Convergence means that the estimated values approach stable values.

In iterative policy evaluation, with repeated computation, the values of the states gradually approach their true values under the given policy.

To detect convergence, the changes in the state values can be examined.

For example:

```math
\Delta = \max_s |V_{k+1}(s) - V_k(s)|
```

If:

```math
\Delta < \theta
```

then the computation can be stopped.

Here `\theta` is a threshold or tolerance value.

Important note: We do not always need to reach full mathematical precision; sometimes an approximation that is accurate enough for our purpose is sufficient.

## 7.4. Effect of Gamma in Policy Evaluation

The value of gamma affects how the values of states are evaluated.

- Low gamma: immediate rewards are more important.
- High gamma: future rewards are more important.

In the chapter's example, a value of:

```math
\gamma = 0.99
```

is examined.

This value indicates that future rewards are also very important.

## 7.5. Example of Policy Evaluation

In the book's example, the values of different states in an environment are computed using iterative policy evaluation.

In this example:

- A random policy is examined.
- The initial values of the states are estimated.
- With repeated computation, the values are updated.
- After about eight iterations, good estimates are obtained.

Another policy called GoGetIt is also examined, which contrary to expectation does not perform very well and reaches the goal only a small percentage of the time.

**Important conclusion:** The performance of a policy depends on the characteristics of the environment and its reward structure. A policy does not necessarily perform well in all environments.

# 8. Multiple Optimal Policies and Tie-Breaking

An environment may have several optimal policies.

For example, in a grid environment, two different paths may have exactly the same return.

In the chapter, the example of state number 6 is mentioned, where two actions, moving left and moving right, have the same value.

This situation is called a tie.

## 8.1. The Tie-Breaking Problem

If two actions have the same Q value, the algorithm must determine which one to select.

Random and unmanaged selection among ties may cause the algorithm to oscillate between several different policies and make no clear progress.

## 8.2. Tie-Breaking Strategy

To avoid this problem, when selecting actions of equal value, a specific and consistent selection method must be used.

The goal is to prevent the algorithm from getting stuck in unnecessary cycles and to enable it to reach a stable optimal policy.

# 9. Policy Iteration

**Main algorithm of the chapter**

Policy iteration is an algorithm for finding the optimal policy in an MDP by repeating two main stages:

1. Policy Evaluation
2. Policy Improvement

The core idea is to first evaluate the performance of the current policy and then use the obtained information to improve it.

## 9.1. Policy Evaluation

In this stage, the values of different states under the current policy are computed.

That is, we want to know how much expected return the current policy produces in each situation.

This is done using iterative policy evaluation.

## 9.2. Policy Improvement

After evaluating the policy, it is time to improve it.

In this stage, using the value function or Q function, better actions are selected for each state.

In other words, the new policy tries to select the action with greater value in each state.

The general policy improvement formula:

```math
\pi'(s) = \arg\max_a \sum_{s', r} p(s', r \mid s, a) \left[ r + \gamma V^\pi(s') \right]
```

## 9.3. The Policy Iteration Cycle

```text
       +------------------+
       |  Initial Policy  |
       +------------------+
                |
                v
       +------------------+
       | Policy Evaluation|
       +------------------+
                |
                v
       +-------------------+
       | Policy Improvement|
       +-------------------+
                |
                v
       +------------------+
       | Policy Changed?  |
       +------------------+
           |          |
          Yes         No
           |          |
           |          v
           |    +----------------+
           |    | Optimal Policy |
           |    +----------------+
           |
           +------> Repeat
```

Stages of the algorithm:

1. **Initial Policy**
   - Start with an initial policy

2. **Policy Evaluation**
   - Compute the values of states under the current policy

3. **Policy Improvement**
   - Select better actions and update the policy

4. **Convergence Check**
   - Does the policy no longer change?
   - **No:** repeat the policy evaluation and policy improvement stages
   - **Yes:** the optimal policy has been reached

## 9.4. Properties of Policy Iteration

- Directly improves the policy.
- Uses policy evaluation to estimate the values of states.
- Uses policy improvement to select better actions.
- In finite MDPs under standard conditions, it converges to the optimal policy.
- There may be several optimal policies.

# 10. Value Iteration

Value iteration is another important dynamic programming algorithm for finding the optimal value function and optimal policy.

This algorithm is introduced at the beginning of the chapter as one of the two fundamental methods for solving MDPs.

Its general difference from policy iteration lies in how the computations are performed:

- Policy iteration repeats the two stages of evaluation and policy improvement.
- Value iteration updates the values of states using maximization over the possible actions.

The standard value iteration formula:

```math
V_{k+1}(s) = \max_a \sum_{s', r} p(s', r \mid s, a) \left[ r + \gamma V_k(s') \right]
```

### Comparison of the Structure of Policy Iteration and Value Iteration

```text
       Dynamic Programming
                |
        +-------+-------+
        |               |
        v               v
 Policy Iteration   Value Iteration
        |               |
        v               v
 Policy Evaluation  Value Update
        |               |
        v               v
 Policy Improvement  Max over Actions
        |               |
        v               v
 Optimal Policy     Optimal Value
```
